# UI surface language study brief

**Status:** prepared brief; no candidate generation, production selection or S3 publication is
claimed by this document. The inputs are Mike's 17 UI reference images supplied on 2026-10-24.
The executing run must obtain the actual images from the supplied attachments or an exact
archived reference collection and preserve them under the asset workflow. Filenames below
identify the examples; they are not download links or proof that this checkout contains them.

## Request

Explore an original OpenLegend UI surface language: borders, textured panels, corners,
inset frames, title rails, dividers, tabs, brackets, medallions and scaffolding-like elements
that connect interface parts. Study material, construction and ornament before designing
whole screens.

Use the [reusable art flow](../../../docs/production-workflows/art-flows/README.md) with
purpose **UI style** and finish **study**. Select Standard, Higgsfield or both from Mike's
request. A useful initial comparison is three coherent directions per requested flow,
adjustable to the actual request and budget.

Keep OpenLegend's [current direction](../../decisions.md#current-visual-requirements--october-16-2026)
and [creative brief](../../final-board/creative-brief.md) as context. These references support
exploring richer interface craftsmanship; they do not choose a final palette, require a
parchment-book interface, or change the world's rendering style.

## Deliverable

Follow the [UI-style profile](../../../docs/production-workflows/art-flows/profiles.md#ui-style).
Show each candidate's materials and parts separately, then assemble them in the same small
neutral specimen. Include a clear connective-framework example, quiet text regions,
size variation and bright/dark background comparisons.

Possible exploratory hypotheses are worn ink-and-paper construction, dark tactile panels
with fine metal rails, or restrained etched frames with connective ornaments. These are
starting hypotheses, not mandatory directions or owner-approved themes. Prefer original,
coherent alternatives based on what the actual references and project context support.

Do not redesign inventories or every screen, generate every item icon, choose permanent
product tokens, implement runtime UI or promote assets as part of this study. Preserve the
contenders and actual sources, explain strengths/tradeoffs, and end with exact archive
references. Production slicing, seamless texture checks and implementation follow only
when that later output is requested.
