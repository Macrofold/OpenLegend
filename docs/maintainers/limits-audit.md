## What the ratings mean

The ratings describe **how restrictive a setting is**, not whether it is correct for gameplay. They are judgments based on the implementation, not proof from stress testing.

- **Very safe:** strongly restricts resource use, often by excluding substantial information or valid world content.
- **Safe:** uses a conservative allowance or short history window.
- **Medium:** uses a moderate allowance, or enforces a correctness rule that cannot meaningfully be called generous or restrictive.
- **Liberal:** permits substantial work or information but still imposes a finite limit; the supported workload needs verification.
- **Too liberal:** does not actually stop the resource from growing, or leaves an identified growth problem unresolved.

A limit rated “Very safe” can still break gameplay by withholding necessary information. A “Medium” rule can still be essential, such as preventing an action from spending the same materials twice. Where an entry groups multiple related limits, its rating reflects the most consequential restriction; its recommendation explains which parts should change.

Entries are grouped first by recommended action, then by their main purpose: model input, simulation performance, storage, network reliability, spending, correctness, game behavior, player-facing display or debugging.

## Protections that still need to exist

Keep checks that protect permissions and private memories, apply an action completely or not at all, reject invalid numbers, prevent a repeated request from applying the same effect twice, and prevent spending beyond the authorized amount. Generated inventions must still use mechanics the engine actually supports.

Keep finite network timeouts, manageable processing batches, bounded temporary caches and model requests that fit the provider's limits. A page or batch should limit work done at once while leaving the remaining valid records accessible.

Jev documents **64,000 tokens per request**, with a separate **32,000-token limit for the shared state plus the longest question**. Here, shared state means the information supplied for all questions in that request. The code estimates usage at four characters per token and targets 55,000 and 28,000 tokens respectively. Those margins are local choices, and character counting is only an estimate. Keep request-size protection and improve size accounting or split requests when necessary. [Jev model limits](https://docs.typesafe.ai/models).

A Jev multiple-choice question can offer at most **255 answer options**. That is not a limit of 255 questions per request. [Jev API documentation](https://docs.typesafe.ai/api).

The earlier audit's “Arbitrary” assessment meant that the exact number had no demonstrated technical basis; it did not mean every such rule should be deleted. Weapon damage, forgetting periods and dialogue length can be intentional game-design choices. Movement search and geometry processing also have real costs even when their particular limits were chosen without measurements.

## All 238 entries, grouped by recommendation and purpose

- **Remove:** delete the particular count ceiling or redundant declaration; retain relevant validation and request-size checks.
- **Replace:** change how the code selects or restricts information so it avoids unnecessary omissions or gameplay failures.
- **Expand:** allow more information or work while retaining a meaningful upper limit.
- **Review:** keep provisionally until the stated behavior, dependency or performance question is checked.
- **Keep:** preserve a necessary protection or a limit whose removal would offer little benefit.

## Places where removing limits could create a real problem

- **Unprocessed memory growth:** the 8,192-record threshold only signals that memory summarization is needed; it does not cap storage. If summarization stays unavailable, retained experiences can continue growing. Keep the simulation running while using durable storage and selective reads, rather than stopping all characters or silently deleting their memories.
- **Total private knowledge:** a size limit on each subject note does not limit how many notes a character can accumulate. Retrieve relevant notes instead of copying or sending the entire collection every time the character makes a decision.
- **More world definitions and sensory contacts:** allowing more attributes, senses or contacts can increase simulation work. Avoid reevaluating unchanged definitions unnecessarily, and measure perception performance with many nearby beings and objects before claiming it scales.
- **Large editor and remote-execution requests:** two requests of the same byte size can require very different processing work. Deeply nested data or instructions containing many operations still need complexity checks.

## How to prevent another silent Jev failure

1. For each limit, document which component enforces it, what it measures, why it exists and what happens when exceeded.
2. Distinguish selecting a subset from failing to process a request. “Selected 300 of 900 available actions” and “Jev rejected the request” must not produce the same diagnostic result.
3. Measure the complete model request, including response-format instructions and other required overhead. Avoid an unrelated record-count cutoff that rejects a request which would fit.
4. When useful, split relevance questions across requests that each fit Jev's limits and the authorized spending allowance. Preserve the association between each answer and its action or information record. Do not automatically purchase retries after failures.
5. Keep essential current facts in a character's input when optional relevance filtering fails. A failed relevance check does not mean nothing was relevant.
6. Keep movement and other ordinary world simulation independent of optional AI decisions and memory summarization. Continue to stop unsafe operations when saving fails or state would become inconsistent.
7. Show how many records or actions were available, considered, selected and omitted, why omissions occurred, and which fallback information was used. Clearly report when essential information could not fit.
