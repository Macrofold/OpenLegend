## Sequencing and completion discipline

1. Reconcile branch-specific state and semantic owners through DF02 before extending conflicting paths. Read current work and branch handoffs; preserve main-thread changes and existing source receipts/permission limits.
2. Establish contributions/resource claims and the two-human authority proof first. Implement the object/containment and invalidation seams through concrete supported consumers, not speculative empty tables or a universal engine rewrite.
3. Continue the existing invention, hearing, action and cadence lines. Join each stateful consumer to SL00 and measure the combined running world, including dense recipients and aged/cold history. Preserve the agreed first/growth workload; no isolated benchmark closes it.
4. Gate advanced emotional/social work on ACT07/ACT08, public mortality on BW14/BW15 decisions, and broad law editing on INV-5.6/MP02. Implementing storage support is not implementing the full semantic memory/emotion system.
5. Keep distributed databases, seamless-region execution, arbitrary generated scripts, marketplace, full physics and detailed emotion taxonomies out of the immediate prerequisite list. Retain them with their existing owners and enable only when their actual consumer/growth gate requires them.

Update this index when branch work integrates or evidence changes; update task completion only in its canonical tracker. [Open decisions](../../archive/05-project/open-decisions.md) holds unresolved product choices, not missing code disguised as a new question.
