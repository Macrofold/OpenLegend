## Sequencing and completion discipline

1. Reconcile new or changed state owners through DF02 before extending conflicting paths. Use current integrated code and applicable handoffs, not the old branch snapshot as a merge queue; preserve existing receipts and permission limits.
2. Build on the delivered contribution/claim, authority, object/containment and dependency/work owners. New consumers must retain their exact identity, scope, bounded execution and lifecycle contracts.
3. Continue the remaining capabilities and qualification in the integrated invention, hearing, action and cadence owners. Join each new stateful consumer to SL00 and measure the combined running world, including dense recipients and aged/cold history. Preserve the agreed first/growth workload; no isolated benchmark closes it.
4. Build advanced emotional/social work on completed ACT07/ACT08; gate public mortality on BW14/BW15 decisions and broad law editing on INV-5.6/MP02. Implementing storage support is not implementing the full semantic memory/emotion system.
5. Keep distributed databases, seamless-region execution, arbitrary generated scripts, marketplace, full physics and detailed emotion taxonomies out of the immediate prerequisite list. Retain them with their existing owners and enable only when their actual consumer/growth gate requires them.

Update this index when branch work integrates or evidence changes; update task completion only in its canonical tracker. [Open decisions](../../archive/05-project/open-decisions.md) holds unresolved product choices, not missing code disguised as a new question.
