## Delivery order

- [ ] **VW01 — Atomic ownership and bounded lifecycle.** Implement one controller/coordination table, registered pool slots, aggregate cost admission, fenced claims, supervisor, deadlines and independent recovery. Use the technical state machine and current project access. **Required pass:** simultaneous claim has one winner; duplicate dispatch does not replay; stale heartbeat/release cannot affect a new run; laptop/controller loss, pending commands and stop/claim races either recover cleanly or quarantine; no unaccounted slot or budget reset. Use controlled disposable fault scenarios; do not modify active temporary workers.
- [ ] **VW02 — Reusable prepared machines.** Depends on VW01. Deliver the pinned bootstrap, one initial worker and bounded second-slot allocation, stop/start, isolated databases/workspaces, exact cache keys/pruning and evidence-aware retirement. **Required pass:** warm reuse retains compatible tool/download caches and no prior game state; changed lockfile/toolchain rebuilds the affected preparation; foreign processes, failed cleanup and insufficient disk prevent reuse. Verify actual stop plus retained EBS and eventual retirement accounting. No legacy environment adapter is required.
- [ ] **VW03 — One runner and complete evidence.** Depends on VW01–VW02. Implement plan/run/status/cancel/collect/release, immutable compressed source transfer, current profiler manifest integration, source/workspace-link refusal, stage timeline, logs/artifact manifests and actual-work samples. Reuse existing game tools and replace task-specific wrapper dependencies. **Required pass:** success, startup failure, interrupted transfer/run and lost client preserve truthful outcomes and retrievable artifacts; collection/release are idempotent. **Required measurement:** one fresh-machine and one stopped/restarted cached-worker experiment using the same standard opening, one controlled player, native actor activity, no paid AI, normal speed, five-second game warm-up and 300-second measured window. Both use fresh databases; machine-cache warmth is distinct from game warm-up. Include packaging/upload/dependencies/startup/measured work/drain/cleanup, cache hits, total time and cost. Poor overhead requires attribution, not a claimed speedup. Repeated trials only for a concrete variance/failure question.
- [ ] **VW04 — Rendered play and operational adoption.** Depends on VW03. Connect the existing browser profiler to a privately reached worker backend, retain device/network provenance and verify actual player controls/rendered movement. **Required pass:** one representative-device input-to-rendered-response journey; no hardware-FPS claim from software rendering. **Required measurement:** frame pacing/stalls, responsiveness and backend progression in the same run; identify host/network limits. Promote implemented operation instructions, publish exact runnable commands and measured cold/warm overhead, remove temporary-script requirements, and close only demonstrated scope. GPU fleet/multi-device capacity remain excluded. Use CG05 for installed-agent routing, not another dispatch tracker.

No game-runtime changes, new automated test suite, paid model calls, GitHub CI, shared-host job mode or deployment of the game to production is part of these tasks. Authorizing implementation must include its actual bounded infrastructure/storage cost under the existing spending policy.
