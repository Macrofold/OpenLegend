# Production deployment delivery

**Status: open planning, 1 October 2026.** Start with the [technical recommendation](../projects/production-deployment-tech-design.md) and [player/operator specification](../projects/production-deployment-feature-spec.md). Auth0 is selected; infrastructure is proposed. This documentation does not deploy the game or authorize paid execution.

This is the cross-functional release checklist under [D5/D6](production-data.md), not a replacement for MP/PF/SL/MW/INV/V3D or the scaling branch's SC/SF/LT work. Each PD item coordinates the named owners; close their existing acceptance there and link the evidence here rather than copying task bodies. Limits live in the [deployment inventory](../limits/production-deployment.md).

## Fastest path

**PD01 → PD02/PD03/PD05 in parallel → PD04/PD06 → PD07/PD08 → invitation pilot → PD09 public gate.** Complete PD10 before enabling the corresponding optional feature. PD11/PD12 are expansion, not reasons to delay a correctly scoped pilot. Native-only staging precedes paid AI qualification.

- [ ] **PD01 — Release contract and operating budget.** Record first audience/region, workload, admission policy, availability/latency objectives, failure-class RPO/RTO, monthly spend ceiling and responsible operator. Preserve the selected 100-player mixed workload and later shared-world target; choose a smaller pilot honestly rather than relabeling it a capacity pass. Obtain explicit post-launch save/retention policy approval before making continuity promises; do not change the development policy incidentally. **Owner:** D5/product. **Exit:** one signed-off release profile, including unattended-world behavior and excluded features.

- [ ] **PD02 — Reproducible AWS environment.** Add reviewed CDK, ECR/container build, nonproduction/production separation, VPC/ALB/TLS/WAF, RDS/pgvector, EFS access point, S3/CloudFront, secrets and Actions OIDC. Check regional versions, quotas, runtime/startup permissions, costs and origin restrictions. **Dependency:** PD01. **Exit:** deploy the same digest to a clean staging environment; no public database, embedded secret or reliance on ephemeral save storage.

- [ ] **PD03 — Auth0 and player onboarding.** Reuse MP01, then qualify actual Auth0 callbacks, replay/expiry/logout/recovery, issuer/subject mapping, invitation/provisioning, two real accounts, revoked access and creator/operator separation. Configure production SES mail and provider quotas. Replace process-local pending-login storage before replicated auth frontends. **Owners:** MP01/MP04 and D5; **dependency:** PD01. **Exit:** real browsers cannot cross private scopes, seize another identity or obtain privilege through signup; clear failures during provider outage and restart.

- [ ] **PD04 — Stateful owner deployment.** Integrate storage-enforced ownership generations, readiness, drain/reconnect and bounded termination with the current commit/receipt owner. Do not autoscale identical active copies of one world. **Owners:** D1/D5, MP/SL; **dependencies:** PD02/PD03. **Exit:** overlapping replacement, killed owner, lost acknowledgement and delayed old result produce one authoritative history; no duplicate inventory, control or paid dispatch.

- [ ] **PD05 — First production asset consumer.** Publish the rights-approved mercenary through immutable S3 objects, PostgreSQL metadata and CloudFront; add bounded loader/cache/fallback and pinned conversion/validation tools. Exercise unavailable/corrupt/unauthorized/version-replaced assets and a fresh checkout/browser. **Owners:** INV/V3D, D4/D5; **dependency:** PD01. **Exit:** runtime bytes are delivered independently of Git/application releases; prior valid art survives failure; saves pin usable dependencies. No repository history rewrite is included.

- [ ] **PD06 — Coherent backup and recovery.** Qualify existing operational export with PostgreSQL plus retained EFS files and content pins; add protected copies and recovery manifest. Exercise fresh-environment restore, file-copy/process-death gaps, database failover and current privacy/accounting overlays. **Owners:** D1/D2/D5, SL/SB18; **dependency:** PD02/PD04/PD05. **Exit:** measured usable-world recovery within PD01's objectives with verified state, not merely a successful snapshot job.

- [ ] **PD07 — AI production admission and economics.** Complete MW deployment gates, verify selected Worker authorization/isolation and upstream model quotas, and install global/world/account concurrency, queue-age and monetary controls around existing reservations/receipts. Separate shared Worker allocation from per-call expense. **Owners:** MW, cognition/INV and D5; **dependencies:** PD03/PD04. **Exit:** separately authorized live qualification covers quality, latency, cancellation, quota outage and uncertain completion; no automatic paid retry or native-game stall. Keep paid features disabled until this passes.

- [ ] **PD08 — Operability and abuse response.** Add journey metrics, bounded logs/traces, actionable alerts, cost alarms, audited operator access, support/report/mute/block/ban tools and status communication. Write and rehearse runbooks for owner/database loss, failed rollout/restore, provider outage, runaway spend, asset takedown and reconnect storms. **Owners:** D5/MP, existing observability owners; **dependencies:** PD02–PD07 as applicable. **Exit:** another authorized operator can detect, contain and recover the exercised incident without accessing unnecessary private content.

- [ ] **PD09 — Public release qualification.** Run the agreed mixed workload, dense scene, growing/aged history, sustained activity and reconnect/failure cases on actual hosted infrastructure and representative browsers/devices. Include genuine Auth0 separately from bulk synthetic sessions, private payload inspection, asset bytes/VRAM, database tails and full AI/compute costs. **Owners:** PF11/D5, MP/SL/MW/V3D. **Exit:** report p50/p95/p99, errors, queue age, headroom, hardware, duration, state sizes and cost against preselected objectives; CI and subsystem gates remain satisfied. Native microbenchmarks or the existing 100-account burst do not close this item.

## Conditional launch and expansion

- [ ] **PD10 — Features that need an explicit release gate.** Before each relevant feature ships: approve unattended-world time/absence semantics; enforce personal/guild-domain building/access rights; implement scoped discovery/friends/invitations; review account/data/UGC retention, age/territory and licensing policies. Payments additionally need verified fulfillment, non-rewinding ledger, refunds and fraud handling; marketplace payouts and voice add their own review. **Owners:** existing world/MP/D/INV/product owners. **Exit:** implement and qualify only the enabled feature; disabled features have truthful UI/product claims. This is not authorization to build the entire list now.

- [ ] **PD11 — Many-world fleet and measured hosting comparison.** Add consumed world directory/provisioning/admission, placement generations, bounded database cohorts and per-world cost/load accounting. Benchmark ECS Fargate versus EC2 and GameLift on the same real workload, including SDK/routing integration, eligible bandwidth treatment, reliability and operator cost. **Owner:** D6; **dependency:** PD09 plus actual demand. **Exit:** world moves and one-cell failure preserve identity/permissions/receipts and meet the expanded profile. Reuse the scaling research's fleet/operations work rather than duplicating it.

- [ ] **PD12 — Shared-world and global expansion.** Follow D6's working sets → regional CPU ownership → storage distribution sequence, with explicit crossing/time/perception/resource protocols. Add geography, specialized search, rented vLLM capacity or bare-metal baseload only on measured triggers. **Owners:** D6/PF/EPR/SW/CR and existing scaling LT tasks; **dependency:** named bottleneck and authorized scope. **Exit:** stage-specific load/fault/quality/cost evidence; independent-world throughput never certifies a single hot scene or millions of concurrent participants.
