## Fastest path

**PD01 → PD02/PD03/PD05 in parallel → PD04 → PD06 and PD07 → PD08 → invitation pilot → PD09 public gate.** PD08 observability/security starts alongside infrastructure; its final rehearsal uses the completed deployment. Native-only staging precedes paid AI qualification. A native-only pilot may leave paid features explicitly disabled; it must not claim NPC dialogue qualification. Complete PD10 before enabling the corresponding optional feature. PD11/PD12 are expansion, not reasons to delay a correctly scoped pilot.

- [ ] **PD01 — Release contract and operating budget.** Record first audience/region, workload, admission policy, availability/latency objectives, failure-class RPO/RTO, monthly spend ceiling and responsible operator. Preserve the selected 100-player mixed workload and later shared-world target; choose a smaller pilot honestly rather than relabeling it a capacity pass. Obtain explicit post-launch save/retention policy approval before making continuity promises; do not change the development policy incidentally. **Owner:** D5/product. **Exit:** one signed-off release profile, including unattended-world behavior, maintenance expectations, enabled features and excluded features.

- [ ] **PD02 — Reproducible AWS environment and release artifacts.** Add reviewed CDK, ECR/container build, nonproduction/production separation, VPC/ALB/TLS/WAF, RDS/pgvector, EFS access point, S3/CloudFront, secrets and Actions OIDC. Follow the playbook's actual Node/tsx entrypoint and build-time configuration requirements; do not assume `dist/` contains a compiled server. Keep production source generation, workspace dependencies, runtime data/WASM and image architecture explicit. Implement immutable image promotion, protected environment approval, restricted IAM, release input ownership, scan/provenance and retained rollback artifacts. Check regional versions, quotas, runtime/startup permissions, costs and origin restrictions. **Dependency:** PD01. **Exit:** deploy the same digest to a clean staging environment; no public database, embedded secret, obsolete Copilot dependency or reliance on ephemeral save storage. The selected production PostgreSQL/pgvector pair is exercised, not inferred from current PG16 CI.

- [ ] **PD03 — Auth0 and player onboarding.** Reuse MP01, then qualify actual Auth0 callbacks, replay/expiry/logout/recovery, issuer/subject mapping, invitation/provisioning, two real accounts, revoked access and creator/operator separation. Configure production SES mail and provider quotas; exercise actual delivery and account recovery. Replace process-local pending-login storage before replicated auth frontends. **Owners:** MP01/MP04 and D5; **dependency:** PD01. **Exit:** real browsers cannot cross private scopes, seize another identity or obtain privilege through signup; clear failures during provider outage and restart; no authentication shortcut from a trusted-looking gateway or email match.

- [ ] **PD04 — Stateful owner deployment and CI/CD promotion.** Integrate storage-enforced ownership generations, readiness/liveness, durable maintenance/release phases, drain/reconnect and bounded termination with the current commit/receipt owner. Use the playbook's stop/verify/capture/install/start procedure; fence EFS writers as well as database writes, including automatic task replacement. Never autoscale identical active copies of one world or use Express Mode's canary request split for its authority. Serialize and reconcile interrupted deployment jobs; verify running image/task definition and application state rather than only service stability. **Owners:** D1/D5, MP/SL; **dependencies:** PD02/PD03. **Exit:** overlapping replacement, killed owner, lost acknowledgement, interrupted workflow, failed rollback, ALB fail-open and delayed old result preserve one authoritative history; no duplicate inventory, control or paid dispatch. Maintenance remains closed when safety cannot be verified.

- [ ] **PD05 — First production asset consumer.** Publish the rights-approved mercenary through immutable S3 objects, PostgreSQL metadata and CloudFront; add bounded loader/cache/fallback and pinned conversion/validation tools. Implement conditional upload/checksum verification and expected-version publication, independently of application releases. Exercise unavailable/corrupt/unauthorized/version-replaced assets, a fresh checkout/browser, interrupted loads, low-memory devices and decoder/WASM compatibility. **Owners:** INV/V3D, D4/D5; **dependency:** PD01. **Exit:** runtime bytes are delivered independently of Git/application releases; prior valid art survives failure; saves pin usable dependencies; CDN/private metadata and CORS/CSP boundaries are correct. Runtime generation adds quarantine, isolated conversion, rights/quality review and durable paid-attempt handling only after this curated path. No repository history rewrite is included.

- [ ] **PD06 — Coherent backup and recovery.** Qualify existing offline operational export with PostgreSQL plus retained EFS files and content pins; add a separate authorized operator task, protected copies and recovery manifest. Exercise fresh-environment restore, file-copy/process-death gaps, database failover and current privacy/accounting overlays. Distinguish whole-database disaster restore from gameplay rewind: reconcile current authority, erasure and financial/provider records before reopening, and block uncertain state. **Owners:** D1/D2/D5, SL/SB18; **dependency:** PD02/PD04/PD05. **Exit:** measured usable-world recovery within PD01's objectives with verified state and latest required operational restrictions, not merely a successful snapshot job.

- [ ] **PD07 — AI production admission and economics.** Complete MW deployment gates, verify selected Worker authorization/isolation and upstream model quotas, and install global/world/account concurrency, queue-age and monetary controls around existing reservations/receipts. Separate shared Worker allocation from per-call expense and distinguish admission stop, known-attempt cancellation and operator-managed idle capacity. Version model/prompt policies; measure preparation, queue, first useful output, completion, quality, stale outcomes and full cost. **Owners:** MW, cognition/INV and D5; **dependencies:** PD03/PD04. **Exit:** separately authorized live qualification covers quality, latency, cancellation, quota outage and uncertain completion; no automatic paid retry or native-game stall. Keep paid features disabled until this passes; rented serving is a later measured comparison, not required GPU ownership.

- [ ] **PD08 — Operability and abuse response.** Add journey metrics, bounded logs/traces, actionable alerts, cost alarms, audited operator access, support/report/mute/block/ban tools and status communication. Write and rehearse runbooks for owner/database loss, failed rollout/restore, provider outage, runaway spend, costly-authoring abuse, credential rotation, asset takedown, bad client/model/content release and reconnect storms. **Owners:** D5/MP, existing observability owners; **dependencies:** PD02–PD07 as applicable to enabled features. **Exit:** another authorized operator can detect, contain and recover the exercised incident without accessing unnecessary private content; WAF and a green health check are not used as substitutes for application security.

- [ ] **PD09 — Public release qualification.** Run the agreed mixed workload, dense scene, growing/aged history, sustained activity and reconnect/failure cases on actual hosted infrastructure and representative browsers/devices. Include genuine Auth0 separately from bulk synthetic sessions, private payload inspection, asset bytes/VRAM, database tails and full AI/compute costs. Qualify the production database/extension and exact release artifacts. **Owners:** PF11/D5, MP/SL/MW/V3D. **Exit:** report p50/p95/p99, errors, queue age, headroom, hardware, duration, state sizes and cost against preselected objectives; CI and subsystem gates remain satisfied. Native microbenchmarks, service waiters or the existing 100-account burst do not close this item.

The [DG08 community participation proposal](../projects/community-entry-and-participation-feature-spec.md) supplies the selected discovery/entry/reporting journey for MP19, PD08 and PD10. Its [CP bounds](../limits/community-participation.md) require explicit audience, staffing, evidence/retention and operating adoption before public use; it does not complete the invited pilot or hosted qualification.

## Conditional launch and expansion

- [ ] **PD10 — Features that need an explicit release gate.** Before each relevant feature ships: approve unattended-world time/absence semantics; enforce personal/guild-domain building/access rights; implement scoped discovery/friends/invitations; review account/data/UGC retention, age/territory, licensing/attribution and deletion/export policies. Payments additionally need verified fulfillment, non-rewinding ledger, refunds and fraud handling; marketplace payouts and voice add their own review. **Owners:** existing world/MP/D/INV/product owners. **Exit:** implement and qualify only the enabled feature; disabled features have truthful UI/product claims. This is not authorization to build the entire list now.

- [ ] **PD11 — Many-world fleet and measured hosting comparison.** Add consumed world directory/provisioning/admission, placement generations, capacity reservation/prewarming, bounded database cohorts and per-world cost/load accounting. Promote cell gateways/worker pools before a service/target group per world exhausts quotas or idle budgets; include task-launch, subnet/ENI, load-balancer and connection limits. Benchmark ECS Fargate, Managed Instances, EC2 and GameLift on the same real workload, including wrapper/SDK/routing integration, eligible bandwidth treatment, maintenance/recovery and operator cost. Include GCP when expertise, offer or regional measurements warrant it. **Owner:** D6; **dependency:** PD09 plus actual demand. **Exit:** world moves and one-cell failure preserve identity/permissions/receipts and meet the expanded profile. Reuse the scaling research's fleet/operations work rather than duplicating it.

- [ ] **PD12 — Shared-world and global expansion.** Follow D6's working sets → regional CPU ownership → storage distribution sequence, with explicit crossing/time/perception/resource protocols. Add geography, specialized search, rented vLLM capacity or bare-metal baseload only on measured triggers. **Owners:** D6/PF/EPR/SW/CR and existing scaling LT tasks; **dependency:** named bottleneck and authorized scope. **Exit:** stage-specific load/fault/quality/cost evidence, including the busiest shared scene and failure reserve; independent-world throughput never certifies a single hot scene or millions of concurrent participants.
