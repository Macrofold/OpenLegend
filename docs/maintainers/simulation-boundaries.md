# Simulation boundary catalogue

This is a running design inventory for [simulation time](../simulation-time.md), not a second task tracker. PF13 owns the current delivery; PF/SW/EPR and feature owners retain future implementation tasks. Add a row when a mechanic gains a useful exact deadline, validity bound or unresolved coupling. A deadline predicts when work may matter; it never authorizes an effect or proves that an arbitrary larger interval is safe.

## How to extend the catalogue

For each scenario record: authoritative inputs; what remains constant; earliest deadline or conservative bound; invalidators; required boundary work; implementation/evidence status; and its existing owner. Use game-time deadlines for mechanics, monotonic real time for host/network/reading budgets, and rendering time for appearance. Never turn a timer unit into a universal update frequency. Inputs with unknown evolution need a bounded fallback rather than a speculative certificate.

**Status key:** integrated = current finite adapter contributes a bound or exact elapsed calculation; bounded = a deliberate approximation with known limits; candidate = not implemented. Current runtime evidence belongs in Verification; these entries are not universal mathematical or scale certification.

A bound is conditional on unchanged inputs, not an assertion that its event will actually occur. Recompute at an earlier command, geometry/status transition or changed participant. Do not cache an Infinity bound as permanently impossible: another committed mutation can change its premises. Predicate evaluation and the eventual effect must use the same subject/source/target bindings. Rate comparisons at equality may need one bounded strict-side departure; arbitrary clock nudges are not a remedy for a stuck state.

Current-format restoration retains progress toward an already chosen mechanical sampling boundary, then rebuilds all current bounds and uses the earlier end. The [native interval owner](../simulation-time.md#native-interval-contract) discards that progress on a semantic mutation; no-op load validation preserves it. [Independent review evidence](../verification/perception-reaction-intake.md#independent-review-follow-through) covers exact contact/wall/flight continuation and current PostgreSQL/checkpoint persistence. This does not date sampled onsets exactly or qualify dense capacity.

## Scaling direction, not a prerequisite framework

Start with the few implemented rate/deadline families. Dirty object regions, per-mover sensing envelopes and private motion schedules now reuse mechanical predictions and can share a publication. A slice that only moves bodies now leaves captured rates pending until a shared boundary, command, re-prediction or publication, and mid-air turns stay private to the flyer ([evidence](../verification/regional-time-and-navigation.md)). Perception sampling and publication still run world-wide per slice and are the next measured limit. The proposed [proportional step work plan](../projects/proportional-step-work.md) makes every stop declare its reach (private, local or shared) so this work follows what a stop can change. The [cadence evidence](../verification/simulation-cadence.md#failed-staggered-flight-scaling-probe) now triggers RP06: global work was a demonstrated bottleneck; the [current follow-through](../verification/spatial-cadence-main-integration.md#performance-follow-through) measures the bounded private-slice implementation. Neither enlarging the displacement bound nor deleting the timers is an accepted fix.

Later consider a deadline heap, spatial dependency index, kinetic bounds and analytic dormant systems only when their inputs/invalidation are explicit and measurements justify them. A heap alone makes deadline selection faster; it does not eliminate integrating the whole world for each selected deadline. Local integration needs a dependency/occurrence boundary and stable ordering when participants interact. Preserve one authoritative ordering/commit owner. An exact mechanical integrator plus approximate sampled perception must be described as such, not advertised as exact continuous reality.
