# Produce music and sound

**Designed procedure; automation and provider qualification remain open in [AUD](../maintainers/audio-production.md).** Use existing authorized tools for supported steps. Future `pnpm audio` commands in the [technical design](../projects/audio-production-tech-design.md#4-minimal-command-contract) are implementation targets, not installed capabilities.

Read the relevant [shared process](production-process.md) sections (Brief/Operation for prompt-only work; the remaining sections for execution/resumption), then the matching provider section in [audio tools](audio-tools.md). Read [asset workflow](../asset-workflow.md) before creating, transferring or publishing files. This page owns audio-specific execution; world musical choices come from the selected world's direction, including the [bundled world](../worlds/base/audio-direction.md). A music study does not authorize game integration or a musician gameplay mechanic.

## 1. Establish the exact starting point

1. Identify the new request or resumed study and its requested stopping point: explore, finish, publish for a named audience, or integrate.
2. For an existing candidate, locate its exact retained revision and read its accepted/rejected status and feedback. If Mike rejected its direction, do not quietly use it as the basis for another version. Offer repair or replacement when the distinction is unresolved.
3. Recover any submitted/uncertain provider jobs before creating replacements. Read settled and outstanding task spending, including delegated work. Follow the shared recovery/spending owners rather than creating an allowance per candidate.
4. Locate the collection vocabulary, related accepted music/effect families, reference permissions and current actual tool capabilities. Do not load all repertoire catalogues or research into every request.
5. Set a deliberately named external workspace and record where the next meaningful batch will be preserved. Do not create media inside Git or use an expiring provider URL as the archive.

**Exit:** the source, scope, budget, available tools and next human decision are understood. Resolve a missing consequential input before its dependent work; independent preparation may continue.

## 2. Resolve the brief and batch

Translate ordinary language into a short brief. Most requests need only the wanted sound, intended use and a few creative constraints. Infer routine values and state them; do not make Mike fill out a questionnaire.

| Field      | What to resolve                                                                                                                        |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Role/use   | Music cue, full song, accent, impact/effect, source loop or ambience; study, game background, physical source or performance candidate |
| Character  | The experience and acoustic qualities wanted, including mixed emotions; not just “epic” or “high quality”                              |
| References | Link/file/candidate, exact passage, role, inspected extent and permitted use                                                           |
| Identity   | Existing theme/arrangement/source to preserve, protected passages, permissible changes and direction to avoid                          |
| Shape      | Duration/range, structure, onset/tail, loop behavior, mono/positional versus stereo/background use                                     |
| Voice      | Instrumental by default for ordinary background cues; deliberate vocals/lyrics/language only when requested or already selected        |
| Batch      | Number of new alternatives, exact parent(s), group membership, selected provider/route and cost bound                                  |
| Finish     | Reviewable candidates, finished exports, approved library publication or explicit integration                                          |

### Starting defaults

Defaults are reversible convenience choices, not artistic laws or per-provider guarantees:

- New music exploration: **three candidates**, normally **60 seconds** each when duration is absent. A requested complete song defaults to **120 seconds** only if no other context supplies its form. State that extending a short candidate may change the composition; generate a complete piece upfront when its structure is the decision.
- A focused edit/finish: **one result per selected source**. Changed audio creates a child; metadata or encoding-only updates retain the candidate alias with an exact new asset revision. “Three variations of A and B” means six children. “All” means the explicitly resolved current group, not the entire library.
- A new one-shot effect family: **five related takes**, with duration inferred from the event and enough natural tail. If duration cannot be inferred, start at **three seconds**; do not stretch a short impact to fill the request.
- Source-loop/ambience exploration: **three candidates**, normally **20 seconds** each, with loop intent stated. Musical accents use their actual brief, with **five seconds** as an absent-duration starting point.
- Use the [required Suno/Eleven Music comparison](audio-tools.md#qualify-the-operation-before-scaling) before selecting an initial music default; ask Mike after presenting results. Keep the default unresolved until his explicit answer. Outside that audition, normally use one approved route per batch unless a comparison or another operation is useful. A default does not make the workflow exclusive to that provider.
- Two concurrent generation jobs at most initially, subject to provider limits and spending admission. The requested batch can be larger and runs in bounded waves.
- Draft means unapproved/exploratory, not low-bitrate or deliberately damaged. Use a cheaper model only when its output answers the question and its later refinement limitations are understood.

If the provider's fixed lengths/output count cannot match the brief, show the nearest useful operation and its actual cost. Trim only when that produces the intended result; do not report a provider limitation as Mike's artistic choice.

Before paid work, give one plan line, for example: “Three 60-second instrumental exploration ideas, using A for sparse percussion and B for warmth; no uploaded reference audio; cost estimate from the selected route; next decision is which ideas to develop.” State real costs/uncertainties, not an invented example dollar amount.

## 3. Handle references and write the operation

1. Record each reference's distinct job. Identify source ownership separately from aesthetic admiration.
2. For Spotify/YouTube, preserve link, title where verified, timestamps and notes. Do not claim to have heard inaccessible content. Use authorized listening where available; request the missing quality description if it changes the brief.
3. For audio conditioning, establish that the exact file can be supplied to the exact provider under its input/onward-use terms. A purchased album, streaming link or possession of a file is not enough by itself. Avoid automatic downloads or audio extraction from streaming platforms.
4. Write concrete sonic instructions in importance order: musical/acoustic subject, instrumentation or source, progression, rhythm/energy, texture, duration/structure, protected elements and consequential exclusions.
5. Translate the brief into the selected provider's actual supported fields. Keep the original request, interpreted brief and submitted payload distinct. Provider prompts cannot read a repository path or infer an unavailable reference file.
6. Do not put artist/song names into providers that forbid them. Describe the relevant properties. Do not ask for a recognizable copy of another composition or an unpermitted voice.

Example music direction: “An intimate instrumental exploration cue with a memorable short phrase, open pauses and a steady light pulse. Begin curious and warm, add a little unresolved tension halfway through, then leave a clean resting ending. Preserve the supplied owned melody; vary its accompaniment. No sung or spoken voice.” This is an adaptable example, not the game's mandatory instrumentation or emotional arc.

Example effect direction: “One close, dry impact of a steel blade against plate armor, firm metallic contact with a short natural ring. One strike only; no voice, music, whoosh sequence or environment bed.” Material/source wording belongs to the chosen world and actual event, not generic engine enums.

## 4. Generate or acquire a finite batch

1. Admit the exact batch, provider account and conservative cost commitment under the task ceiling. Record source permissions and requested outputs.
2. Submit each operation once, save its receipt promptly, and observe that operation to completion. An interrupted wait goes to recovery, not automatic retry.
3. Retrieve actual files into the external workspace. Preserve original downloads and meaningful provenance; decode/inspect the files rather than trusting a success response.
4. Assign stable candidate aliases and exact parent/revision relationships. Keep extra outputs from a provider batch visible and accounted for.
5. Check obvious unusable output: missing/truncated file, wrong acoustic event, unintended speech, clipping or an absent requested passage. Repair only within the admitted operation/scope; further generation needs another explicit finite operation and remaining budget.
6. Preserve the meaningful batch through existing private/library/study storage as permitted. Report publication gaps accurately and retain working files until preservation succeeds.

Reusing a licensed recording, recording Foley, editing a source or commissioning help can replace generation when it is a better route. Human outreach, purchases and private uploads retain their actual authorization requirements. Quality preference does not itself authorize someone else's account or a new subscription.

## 5. Present and collect feedback

Present a stable listening list/page with exact candidate labels, full playback, duration, concise differences, parentage, proposed tags and material technical issues. Match preview level where useful and retain original-level playback. Avoid automatic playback and unsolicited simultaneous tracks.

Say which output best fits the brief and why, with an explicit distinction between listening judgments, measurements and provider claims. Mike may choose any candidate, combine directions, reject all, delegate the selection or keep several. A technically clean export is not aesthetic approval.

Record feedback against the exact target. A useful feedback record includes the timestamp/range when relevant, what is wrong, what must stay, and the desired operation. “I like A's melody but B's percussion” is a new arrangement request, not a promise that the service can splice two mixes cleanly.

## 6. Revise the right thing

| Feedback                       | First operation to consider                                                                                  | What must be checked afterward                                               |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| “More bass”                    | Gain/EQ or bass-part mix if available; clarify only if the intended part/character is materially ambiguous   | Balance, distortion and masking; melody/pacing preserved                     |
| “Happier”                      | A changed arrangement/harmony/rhythm with named identity locks                                               | The intended mood and whether recognizable material survived                 |
| “Fix this passage”             | Supported time-range edit or local edit with preserved surrounding audio                                     | Both boundaries, timing, tonal continuity and unchanged neighboring passages |
| “More like A”                  | Variations from the exact permitted A source where supported; otherwise a clearly labeled new interpretation | Similarity by listening; no promise from a seed or prompt alone              |
| “Make it longer”               | Supported extension/arrangement development; retain original                                                 | Whole-piece form, repetition, transition and ending                          |
| “Make it higher quality”       | Diagnose artifacts, balance, performance and export first; select finishing or a new performance accordingly | A/B against the favorite, not just file size/sample rate                     |
| “These hits need more variety” | Additional coherent takes or restrained editing of the same event family                                     | Material/action remains recognizable and perceived level is compatible       |
| “Add melancholy”               | Metadata correction                                                                                          | Approved vocabulary/use meaning; no generation                               |

Preserve the original and apply the [candidate/revision rules](../projects/audio-production-tech-design.md#record-contract). Batch operations list their exact targets and partial outcomes. Wait when the next creative decision belongs to Mike; otherwise continue delegated selection or already-authorized finishing/publication within the stated scope. There is no automatic aesthetic retry loop or fixed maximum number of user-directed rounds.

## 7. Finish the selected recording

Apply the [audio finishing recipe](art-flows/production.md#audio) and produce only what the chosen use needs:

1. Preserve the original/master and create a working derivative. Retain the actual best source format; conversion cannot recover missing detail.
2. Repair clicks, unintended silence/noise/layers and cut tails; keep intentional transients and dynamics. If the unwanted layer is inseparable, seek a replacement source instead of constructing a complicated runtime workaround.
3. Establish the intended entry, ending and loop points in the actual export's units. Listen through repeated wraps and transitions. Do not require loops for every complete song.
4. Balance family members and create supported playback encodings. Record actual format/rate/channels/duration, gain guidance and measured issues. No one loudness target applies to every song, impact and ambience.
5. Export stems only when useful and actually available. Label original composition stems versus estimated separation. Neither is required by the fixed-recording musician idea.
6. Inspect/listen to the final encodings, not just the source project. Keep an honest checklist of technical pass, artistic acceptance and intended-use evidence. Unperformed listening is an open result.

“Finished” means ready for its named consumer, not automatically integrated or suitable for every scene. Specialist finishing can be chosen when likely to improve an important favorite; record the deliverable, source permissions and cost before dispatch.

## 8. Propose and approve catalogue metadata

Analyze the actual final audio and show suggested facets alongside the existing vocabulary and relevant accepted examples. For each uncertain property, retain unknown/tentative status. Distinguish acoustic facts from interpreted mood and editorial use.

Confirm family/composition/arrangement relationships from actual authorship/listening, not shared genre alone. Record approved uses/exclusions, vocal presence, energy/prominence, loop behavior, provenance and optional performance-role notes. Present tag additions/changes plainly; “also melancholy” should be a small edit, not a taxonomy redesign. Manual corrections survive reanalysis.

Compare against the relevant library subset: nearby moods/roles, already-used themes and coverage gaps. Do not fetch every recording or send the complete catalogue to a model. “No matching approved track” is useful evidence for a new production brief; it does not authorize unattended generation.

## 9. Publish and optionally bind

1. Confirm the exact selected revisions, audience and intended uses. Recover any previous publication operation before creating another.
2. Prepare masters/sources for restricted storage and approved previews/runtime files for their separate audiences. Retain license/entitlement and attributable human changes; exclude secrets and unrelated private files.
3. Use the existing asset CLI/authority to prepare, approve under current authorization, publish, verify and retain permanent exact references. Check the final consumer file's hash after processing.
4. Update the selected library/catalogue release deliberately. A study remains reproducible against its older selection; do not overwrite published versions.
5. If integration is requested, show the world-owned binding or context-pool change, supported trigger, material/source assumptions, fallback and affected existing selection. Explain an unavailable event/semantic capability before promising the binding.
6. Implement through the ordinary authorized code workflow and qualify the real action/scene under [audio and feedback](audio-and-feedback.md). Do not mark integration done after copying a file to S3.

A creator export or independent host must not receive restricted raw assets merely because official playback is allowed. Preserve optional distribution rights as metadata for future selection; broader product work is not a prerequisite to this first library.

## 10. Handoff and resume

Return playable previews/exact labels, accepted/rejected/deferred choices, important differences, verified permanent study/asset references, actual or best-supported costs, and the next requested decision or completed boundary. State any unavailable listening, export, rights, publication or integration evidence. Link one durable study record from which another session can recover the exact candidates and outstanding jobs.

Do not claim a production route is qualified because a command returned success, a provider advertises an editor or a file has a large sample rate. No genre choice, provider, tag set or generated song becomes an engine law. The [feature spec](../projects/audio-production-feature-spec.md) and [technical design](../projects/audio-production-tech-design.md) define the full target; [AUD](../maintainers/audio-production.md) owns unfinished implementation and qualification.
