# Higgsfield art flow

Apply the [shared procedure](README.md) and requested [profile](profiles.md). Higgsfield
supplies generation and editing; OpenLegend's coordinator owns scope, inspection, file
preservation and the final result.

## Access and setup

1. **Inspect available integrations first.** Prefer an already authorized official
   Higgsfield connector/MCP or an approved installed CLI when it supports the task. Use
   the browser when explicitly requested or permitted by the host's tool/fallback rules.
   Do not assume this repository installs or authenticates any of them.

2. **Reuse the account.** If sign-in is needed, open the official site or integration
   authorization and hand the required login/verification step to Mike through the
   supported mechanism. For a new account, the official signup offers social sign-in
   or email verification. Resume after access is available. Never request passwords
   or verification codes in a study record.

3. **Check capability and cost once.** Inspect current image/editing models, reference
   inputs, output formats, credit balance and charge per operation. A paid subscription
   may be required for an integration. Do not purchase plans or change billing products
   without the corresponding authorization. The MCP/CLI route uses plan credits;
   the developer API has a separate prepaid USD balance and catalog. Automated generation
   is not entitled to the website's manual Unlimited/free allowance. Apply the shared
   task budget to actual generation, editing and upscaling.

4. **Create a named run.** Use the study ID in the provider folder/project where supported.
   Keep a local external working area and study record as well. A provider workspace URL
   is useful navigation but is not the durable archive.

Current official guidance documents MCP at `https://mcp.higgsfield.ai/mcp`, account
authorization, the official ChatGPT plugin and CLI options. Use the executing host's
current supported setup, not copied button coordinates or an unreviewed install command.
Review/pin any [first-party skill](https://github.com/higgsfield-ai/skills) before installing;
load only capabilities needed for the art task. If the CLI is the appropriate route, follow
its [official setup and command reference](https://github.com/higgsfield-ai/cli): inspect the
installer/version, authenticate in the actual execution environment, inspect account status,
and read current model schemas/help before constructing commands. A browser login elsewhere
does not authenticate that runtime; a working integration does not require a second one.

## Produce a coherent result

1. **Map reference roles.** Upload the images needed for the selected purpose and explicitly
   identify identity, material, palette, frame/connector construction and composition roles.
   A screenshot can guide its border while its screen layout is excluded. Do not upload
   an undifferentiated pile of references or unrelated private project material.

2. **Run a representative specimen.** Use an available model/mode that actually supports
   the required instructions and references. For UI style, test a panel, frame corner and
   connector together. Check whether the tool interprets a reference as style, identity,
   source image or start frame. For example, the current Soul help describes direct-reference
   and prompt controls differently from its Moodboard controls; do not assume every mode
   accepts the same prompt-plus-reference operation. If model choice is unresolved, audition
   credible options on this same useful specimen within the budget. Select model/mode,
   quality, resolution and aspect explicitly; catalog labels and defaults can differ from
   website marketing names. Inspect current schemas rather than copy an old model ID.

3. **Create distinct direction anchors.** Use the shared brief and requested number of
   candidates. Record actual model, mode, prompt, reference inputs and available settings.
   Inspect the original output before expanding a contender. Keep each contender's accepted
   internal anchor separate from the others; this is not permanent project-style approval.

4. **Expand using references and targeted editing.** Reuse that anchor through the supported
   reference, Element, Moodboard or editing mechanism. Preserve palette, material, edge
   language and texture scale across the required specimens. Give a correction a specific
   target: simplify a noisy center, repair an edge, retain a face, or adjust a connector.
   Do not regenerate a complete family to repair one local defect.

5. **Inspect actual outputs and finish selectively.** Review at intended display scale on
   the same specimen/backgrounds as other candidates. Upscale only useful outputs and
   inspect again for altered ornament or invented detail. If layer separation or background
   removal is available, inspect the result and actual export format. A Layers operation
   does not by itself prove a native editable document, clean alpha or production-ready parts.

6. **Compose when the deliverable needs it.** Use the shared
   [editable UI-composition procedure](profiles.md#editable-composition) for typography,
   layout and design-system work. Feed actual Higgsfield artwork into the composition and
   return precise art defects to this route. A separate design tool does not turn an image
   study into implementation.

7. **Download and preserve.** Retrieve originals and meaningful revisions from the completed
   operation or Assets, with available generation details. Distinguish flattened images,
   transparent exports, reconstructed layers and editable originals. Keep private operational
   receipts separate from public provenance. Save through the shared S3 procedure before
   provider links expire. Publishing to a public Higgsfield profile is a separate action
   and is not required to archive the study. After timeouts, use the current operation
   status/wait controls to recover the same submitted work before any replacement request.

If the required production format is not supported, retain the concept and use an authorized
finishing tool with that limitation recorded. Label a mixed route honestly in comparisons;
do not quietly substitute another image generator and call the result Higgsfield-only.
A character image is not a 3D mesh; a generated video is not a rig or skeletal animation.

## Optional reusable Canvas template

Use Canvas when a saved graph helps repeated work and the available controls support the
task. It is optional, not an extra manual setup ritual for every request.

- Create a named canvas from the common study ID.
- Add the brief/prompt and reference inputs with explicit roles.
- Connect independent direction-generation nodes for the requested candidates.
- Connect each candidate's selected anchor to its own related specimen/edit nodes.
- Add finishing/upscale nodes only where needed.
- Run only the required nodes, inspect their outputs, and save the arrangement as a reusable
  template when available. Record its provider link and a portable textual recipe in the
  study record.

Parameterize the subject, references, output profile and invariant style anchor. Keep each
new request's output in a new run; preserve earlier candidates. Confirm how the chosen nodes
consume their references before executing dependent generations. A saved graph does not
guarantee deterministic regeneration or exportable native source.
