## Scope and reading this inventory

**Current runtime mapping reviewed: October 8, 2026.** This file covers player, creator and operator interfaces. Inventory was an example in the original request, not the boundary of the requested redesign. The whole-interface candidate now changes the broader HUD, actions, Character, readers, settings, lifecycle, operations and creator/inspection workspaces. The [current mapping](#current-runtime-candidate) distinguishes those changes from reused capabilities and conditional features. The 58-group [October 4 source audit](#historical-source-audit) is preserved below at its original revision.

This file owns the surface-to-source, coverage and evidence map. It does not duplicate implementation tasks, native contracts or acceptance checklists. The project pair owns the full redesign scope; the [UI/UX tracker](../maintainers/ui-ux.md) and linked subsystem trackers own work and completion. A field-based creator editor can be appropriate for deliberate authoring even when routine play should require direct game actions. Source inspection, actual interaction and human usability evidence remain distinct.

**Source review: October 4, 2026.** The 58 rows in the six surface sections below describe runtime `f39cec41d84a9192417b0bf2b306c642e9c3e084`, with subsequent documentation checkpoint `1ba77e8`. Their source links lead to the maintained files, whose implementations may since have changed.

The audit was an inventory of source and recorded evidence, **not a new running-game inspection**. The separate [inventory diagnosis](current-interface-audit.md) remains pinned to `b50ec6c` and must not be read as a description of today's paired inventory. Questions below record concrete design or research gaps at the audit revision; they do not assert that every existing control was defective. The current tracker records which work subsequently changed.

- **Source reviewed (S):** the entry and relevant rendering/state code were read. This establishes what exists and how the code routes the task; it does not establish usability, visual fit, accessibility or native integration success.
- **Recorded interaction evidence (I):** an existing report describes actual interaction with its stated revision and environment. Component fixtures, historical native browser runs and final-runtime checks remain distinct. No whole row is certified by a link to one exercised control.
- **Design gap (P):** a proposed or unresolved design question. It is not shipped behavior, a new authorization, or an observed runtime failure.
- **Prior slice:** “changed” means the earlier inventory/task/conversation effort directly changed this surface; “retained” means it remained an existing surface; “shared only” means it reused or received a narrow shared change without an end-to-end redesign.

All 58 historical surface rows below are **S**. Their I evidence, where available, is bounded in [Recorded evidence and untested coverage](#recorded-evidence-and-untested-coverage). Existing source owners continue to control privacy, authority, cost, world mechanics and persistence.

## Boundaries: a source inventory is not a feature catalogue

The current source does not establish that Open Legend ships a general vendor/auction economy, bulk loot automation, equipment loadouts, quest-map search, controller navigation or an arbitrary-world interface merely because a reference game has them. The future guidance in [Inventory](inventory.md), the original [wireframes](wireframes/README.md) and individual game dossiers remains qualified. Likewise, creator-only family data, private minds and operational grants are not ordinary-player knowledge or controls. Research may recommend a new pattern, but its world semantics, authority and implementation scope require their own accepted owner.
