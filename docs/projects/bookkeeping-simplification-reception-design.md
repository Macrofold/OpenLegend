**BK17–BK19 source and connected storage integration are complete; normal-speed and cleanup operating qualification remain unmet. Architecture used November 3, 2026, 22:05 UTC; connected current-format checks November 4, 2026.** This companion specifies the current [feature](bookkeeping-simplification-feature-spec.md#10-compact-received-state-and-chronology) and [technical](bookkeeping-simplification-tech-design.md#13-compact-representation) contracts. ## 1. Outcome, evidence and alternatives

The subsequent [received-batch proposal](bookkeeping-simplification-batch-design.md) addresses the remaining per-partition append and storage-lifetime work exposed by the completed-source measurement. It is not installed; the BK17–BK19 contracts below still describe current execution.

A person should receive their surroundings, notice a changing situation and remember a useful sequence without rebuilding thousands of proof objects merely to keep looking. An ordinary route can fade; a particular favor, learned name or promise can remain. Witnesses can disagree honestly because neither acquires the other's private knowledge. Responsive movement and remembered consequence are the payoff; a more elaborate memory simulation is not itself a feature.

The completed-source diagnostic attributed substantial work to immutable graph preparation, current-field proof construction, history dictionaries and repeated retention reads. It recorded 158,901 expanded current fields, 1,239,908 encoded temporal slots and 316,836 account-header rows returned by 356 maintenance queries. These counters describe different work and cannot be added. The retired history sampled afterward contained 73,565,067 bytes of dictionary content and 38,813,344 bytes of JSON lookup indexes. Repeated indexes and baselines are not meaningful memories.

The earlier **228,718,313-byte cleanup debt** was retired personal history header/payload accounting, not active memories or measured disk space. That database was removed; its exact decomposition is unavailable. The later diagnostic measured 134,855,424 bytes of equivalent retired payload after less game progress, not a demonstrated improvement. Its 0.420374 normal speed was instrumented on a heavily contended host and had two background work-lane deadline failures. The cleaner prior run was 0.632342 normal with no runtime failure. Neither meets the unchanged gate. The evidence report owns workload, CPU versus elapsed-time qualifications, query counts and artifact references; this design does not infer a speedup by subtracting overlapping timings.

## 2. Boundaries and one authority per meaning

The engine owns exact reception, causal order, bounded selection, private access, correction, storage and coherent cuts. The selected world owns senses and their timing, Perception/Focus, attention allocation and familiarity influence, recording admission, memory importance and retention allowances. Extend existing world hooks where policy is presently repeated in a server helper; do not embed base-world reason names or ranking literals in SQL. No new daughter, cliff, kitchen, profession, movement-episode or destination handler is needed.

Keep existing defaults: broad current awareness outside detailed slots, automatic recent capture for attended subjects, separate required evidence, current native reactions and async cognition. Selection means the existing attention owner grants detailed attention, not a player clicking a subject or an NPC executing a follow action. A familiar person may receive higher priority without being liked. A room category may be inferred from acquired furnishings and activity; it needs neither a hidden map label nor a prior spoken name. There is no new sixteen-item background sampler, recurring AI call, compiled personality-to-object taxonomy or automatic expiry summary.

The current, recent and lasting representations have different meanings. Removing duplicate _storage_ does not merge them into an omniscient database view. A neutral value can be shared across compatible recipients; observer, local identity, grant, times, received frame and admission cannot be shared merely because the value matches.

## 3. Native data model and mutation sequence

Names below specify current contracts; reuse/refactor the existing exported types rather than retain old APIs beside these. Source identities use the existing structured reference helpers and preserve revision types, including opaque strings. Never concatenate arbitrary IDs with delimiters or introduce a lifetime identity registry.

### 3.1 Stable content, clocks and member identity

A current contact contains bounded **content groups**, not a rich independent proof object per field. Each group holds immutable received values, original source/provenance, grant/channel/life and local subject association. Separate metadata holds exact measurement and successful-support clocks, availability and optional recording annotation. A successful check or attention cursor change must not replace the content object or rebuild neutral-value ownership.

Refactor `CurrentReceivedGroup` in place to `{ received: { grant, fields }, metadata: PartPartition[] }`. Each partition contains an exact mask of owned member/part addresses, their homogeneous clocks, check class, availability and optional open-recording binding. Every held part belongs to exactly one metadata partition; different clocks, admission or opening origins require separate partitions. The contact retains its group array, field order and shared originals. Normalize saved **content** by stable field/member/part identity with immutable grant/original/value descriptors; saved **metadata** contains these partitions. Metadata also preserves the actual received time/order, successful-check revision and receiver frame. Attention admission borrows those dates rather than inventing a new check. Clock-only splitting/merging changes metadata only; actual received-part/value/grant changes update content and affected masks atomically. This is one codec projection of the existing contact, not another table or native catalogue.

The current mutation owner certifies content-unchanged intent for confirmation, unchecked and recording changes. The codec reuses the prior payload without flattening, comparing or serializing every field merely to prove equality. Metadata-only changes replace small wrappers while reusing immutable `received`, values and originals. Remove `fieldView`'s content-keyed proof cache rather than replace it with another invalidation scheme; immutable publication must reuse already immutable received content.

Fields remain independently meaningful. A partial sample splits/narrows only affected members; members with identical content/grant/clocks can share group metadata. Splitting to represent different clocks preserves existing member identity and interval origin. It does not close unchanged values or accumulate historical splits in current state. Group count is bounded by currently held members.

Use a stable **member track**: observer life/temporal epoch, observer-local source/contact identity, exposure/grant lifetime, exact channel pin and typed member/part key. It identifies a line of actual received state, not a particular value or physical page. Reuse the current actor/life/epoch/ordinal allocator for logical interval identity; preserve original member ordinals through grouping, narrowing and packing. Two members may originate in one grouped acquisition but close at different times. A logical evidence reference identifies interval plus member and selected check/order, never an array offset in a SQL page.

Respect existing composite received values: field kind alone is too coarse for a body containing independently fresh detail, pose and description. The received-value owner resolves typed parts using `splitObservedBody`, `effectiveReceivedFacetDescriptor`, `composeReceivedFacetValue` and existing detail/pose/description support. The separately acquired location remains the owner of newer pose; a body view borrows it rather than creating another writable pose or recorded interval. Its raw acquisition pose remains original evidence where the existing composition rules permit it. Independently received description similarly keeps its own owner. Receiver frame belongs to the sample/check, not a replacement body value. Plain facets have one `value` part. Compose permitted views only when consumed. Equal coordinates/neutral values alone cannot merge grants or clocks. This is trusted-family decomposition, not arbitrary JSON diffing or world-specific movement logic; parts retain their original logical facet identity for accounting.

Reuse `receivedTrackKey(exposure, channel)` under its observer/life/epoch owner; extend with member/part identity for indexed selection. A logical fact address is `{ actorId, physicalLife, epoch, openingOrdinal, memberOrdinal, part }`. Split entries preserve disjoint member/part addresses and original source ordinals. Do not merge groups if that discards distinct recording origins, and do not allocate a SQL row merely to allocate this address.

References also carry validated stable-track and original admitted-time/order **lookup hints**, produced by the same reference helper. These locate a bounded page with the existing member/time index; exact logical identity is checked after lookup. Hints grant no authority and do not change when the interval is packed, split or clipped by eligibility. Update all reference consumers/current-format validation together; no lifetime logical-ID-to-page catalogue is needed.

An **open annotation** holds interval identity, member identity, recording admission class, admitted start `(game time, causal order)` and the original measurement/support clocks. Its value/provenance remain in current content; do not duplicate a start baseline. Its end is implicit at the captured current cut. Historical eligibility can begin later than admission after expiry, without pretending that the value was measured at the cutoff.

A **closed interval** stores the outgoing value (inline or neutral shared reference), minimum direct provenance/frame/grant, original clocks, admitted start/end, terminal clocks and closing reason. It carries a finite range of coverage order, not a growing list of declaration bindings. Its identity survives physical repacking or sparse edits. It means “this received value applied at these recorded checks,” not continuous observation between checks. Its terminal clock seeds retain the last actual received support and measurement independently; a later closure cannot serve as another observation. No predecessor interval/page is required to decode it.

Keep the existing hybrid received-value owner, with one explicit representation correction: validated `body-pose`, `location` (point/bearing/region), `observation-frame` and `observation-header` fragments stay inline regardless of crossing the current small-fragment byte threshold. A long surface ID or full-precision coordinates must not allocate a pooled row on every movement. Preserve existing validation/payload bounds; suitable rich/stable bodies and larger non-coordinate content still use the pool, and other small fragments retain the existing threshold. Do not instead allocate a fresh observation-header/proof payload for each otherwise-inline coordinate sample: retain its minimum changing provenance inline and share only suitable stable rich content. No global deduplication scan, per-coordinate value ID or SQL row is introduced. [BKS-L09](../limits/persistence.md#bks-l09--span-and-check-representation) records the representation change.

### 3.2 Exact successful checks

Before preparing historical check data, intersect actual successful coverage with existing recording admission. An unattended broad check updates current clocks only. Required/optional admission must come through its existing owner, not a new bypass from the check writer.

A **coverage declaration** contains immutable compatible observer/life/channel/grant scope, stable member identities and operation class: support confirmation or actual measurement. Its member set is exact. Equal-value remeasurement advances measurement time for only measured members; support-only confirmation cannot do that. Different subsets or operation classes require distinct declarations (or equivalent homogeneous groups), not one ambiguous shared clock. Changing coordinates does not replace an otherwise compatible declaration. Membership changes replace the declaration without closing survivors' value intervals; later checks cannot refresh departed members.

An admitted check is an exact `(time, causal order, declaration, source-check/frame data when meaningful)` stamp. Encode ordered stamp runs compactly, including irregular and equal-time checks. Delta encoding is allowed; interpolated/fabricated checks are not. Cache declaration cardinality for logical-work accounting. Avoid a new declaration object for every unchanged check by reusing the current compatible coverage identity; retire obsolete declarations with their retained pages, not in a permanent scope catalogue.

The typed payloads preserve the existing clock contract:

| Stamp kind                | Required data beyond received time/order and declaration                                                                                                                                                                                                                                                    |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Support confirmation      | Exact confirming source reference/revision, `confirmedFrom`, `confirmedThrough`, and receiver-frame data when supplied. Original fact/role binding comes from the declaration's selected part; value measurement/acquisition clocks are unchanged.                                                          |
| Same-original measurement | The support tuple above plus `measuredFrom`, `measuredThrough`, `acquiredAt` and the exact measurement proof/frame. Different tuples use different homogeneous masks. The selected projection derives `asOf = measuredThrough`, matching `temporalFacetProofInput`; received time never substitutes for it. |

An omitted clock means unchanged from that selected part's prior state, not zero/current time. Encode full clock tuples first; later delta packing must round-trip those same tuples. Seeds carry the latest applicable support tuple and measurement tuple separately, with their original received order and direct proof. Common tuples/proofs can be shared by a mask; do not rebuild a full proof per member per stamp. For example, a sample received/acquired at 100 describing measurement `[90,94]` projects `asOf:94`; a support-only check received at 104 advances support only, leaving measurement `[90,94]` and acquisition 100.

Page-local predecessor seeds preserve **support and measurement separately for each applicable member**. Seed lazily on a member's first use, from the actual predecessor of that operation at the captured cut. Reuse the seed within the page across declarations. A seed copies old clock evidence; it is not a new observation and cannot advance freshness. Values/full proof baselines are not copied at page boundaries. Necessary seed provenance belongs in the page's actual ownership closure.

### 3.3 One receiving mutation

Contact changes use the following ordering inside `receiveCurrentChange` and its existing batch owner. Current geometry uses its own hooks below and the same temporal transition helpers; neither uses a later frame recorder to recover overwritten values.

```text
validate the actual incoming channel/grant and supported change once
select affected current groups/members and current recording admission
for each affected admitted member whose value, grant/provenance or availability meaning changes:
    append outgoing self-contained interval BEFORE replacing/removing its value
apply the received content/clock/availability change through the current owner
for changed still-admitted members, open their new interval at this causal boundary
for successful admitted coverage, append exact compact check stamp(s)
update correspondence, dependent native cues and owned invalidations
publish compact immutable deltas through the existing transition
```

Every received intermediate change inside one native batch follows this sequence. End-of-batch capture cannot recover overwritten states. Attention newly granted at batch end starts from the then-current acquired value, retaining its original measured time; it gains none of the earlier batch's unrecorded travel. A genuine occurrence such as received speech or an action result keeps its separate ordered occurrence record and required support.

Allocate one monotonic causal order for each received transition; close/open/check products of that transition share its order. Attention/availability transitions have their own order without becoming sensory samples. Value intervals are **half-open `[openOrder, closeOrder)`**: install the replacement/open interval before attaching its check. An outgoing terminal clock is its last earlier support, not a check at closure. At one game time, `108: p0→p1`, `110: p1→p2`, `112: attention exit`, `114: reentry`, `116: confirmation` produces p1 `[108,110)`, p2 `[110,112)`, and a new p2 interval from 114. Orders 108/110 check only their new values; 112/114 add no observations; the reentry baseline retains its earlier measurement and 116 belongs only to the new interval. Inclusive SQL time ranges are candidate filters; exact order applies these endpoint rules.

Advancing a support-confirmation clock or remeasuring the same value under the same binding is **not** a closing boundary. A fresh receipt/check ID or newer measurement-source revision belongs to its check, rather than automatically replacing the interval's original acquisition. Close the value interval only if its granted received value, original source binding/role or supported availability meaning actually changes. This distinction prevents the replacement from becoming one copied interval per unchanged sighting.

Distinguish same-original remeasurement from a genuinely independent acquisition with an equal value. Existing eligibility requires both original and confirming support, and confirmation keeps the same original. Independent acquisition B therefore closes A's binding and opens B's interval, reusing the equal neutral value. Withdrawing A leaves B intact under its own provenance. Do not treat B as an alternative support edge on A's interval or let an ordinary confirmation manufacture independence; no new support graph is needed.

Native consumers use a synchronous read scope that validates current observer/channel support once, selects members and borrows immutable group data. The scope cannot survive mutation or an `await`. It does not expose writable backing maps. Rich field/proof materialization is a deliberate projection for a selected external consumer or retained support, not the implementation of group iteration. Existing guards still protect untrusted input, changed authority and current-format restoration; do not repeatedly validate owned unchanged content to assert internal conventions.

**Current feature integration.** `ReceivedGeometryState.fragments/boundaries` remains the authority for acquired patches and physical boundaries. Give each existing keyed feature a bounded metadata/recording annotation using the same part-partition contract; keep its observation value in that owner, never a fabricated contact or second open-history map. On acquisition, open only existing admitted feature history. On a successful held-geometry check, update only actually covered feature clocks and admitted check stamps. Before replacement/removal in `received-geometry.ts`, close outgoing admitted parts using their prior support; unchanged retained features keep their annotations. `endReceivedGeometry`/`finalizeGeometry` close before removing current features. Convert `captureReceivedFeatureHistory` and `finalizeTemporalGeometrySupport` to these shared operations, removing `geometryCaptures` rebaseline bookkeeping. Near/far-plane dependencies of a received physical boundary retain their exact acquired support. Attention rotation, page rollover and ordinary history expiry cannot duplicate terrain, acquire more ground or erase current cliff geometry.

This is an operational history boundary, not a new measurement, narrative event or loss of sight. Never discard the restored open history or append new events to a sealed old epoch.

## 4. Selected reads, ordering and async boundaries

### 4.1 Capture only what can be consumed

Native current readers select contact/channel/member before projection. `captureCurrentSources` must not freeze the entire actor current map and value closure for a small request. `captureTemporalHistoryReadContext` must take an explicit actor-local selection/window and freeze only selected open annotations, their immutable values/provenance, independent terminal measurement/support clocks and pending suffix references. Current-open capture stores a receipt plus its terminal seeds, so retirement of old check pages cannot discard a still-eligible successful check. A revision number alone cannot reconstruct a prior open value after it changes. Hold that small immutable selected closure, not a live view across an await.

The selection includes the existing bounded **permitted expansion envelope**, not only facts printed in the initial prompt. Later scene/detail queries at that cut may select from that captured envelope; they cannot silently substitute newer live facts or treat an uncaptured source as nonexistent. A genuinely different query requires the existing fresh-cut preparation path with its actual date and privacy checks. Do not reduce broad surroundings to the ten detailed slots to make capture smaller.

Player projection, native targeting/reactions, descriptions, model current context and recent recall use the same receiving authority with different selections. Current scene construction remains bounded by its existing candidate/row/byte budgets. Historical selection intersects subject/member/time/order/eligibility before field expansion. Count expanded logical observations using declaration cardinality before allowing compressed runs into a context budget. Decode/materialize only the selected prefix within actual work and output byte ceilings.

### 4.2 Exact cut example

At revision R, an admitted position interval P holds value p0 with checks at orders 100 and 104. A reader captures P and its selected clocks at R. At R+1, an actually received p1 at order 108 closes P and opens Q. A reader at R still sees p0 through its captured cut. A reader at R+1 merges the closed P and open Q exactly once. Saving R+1 atomically transfers P from current ownership to history ownership; it must neither disappear between tables nor occur twice. p2 received later in that same native batch still closes Q before replacement.

A history query for an earlier time must select a span by **when its value applied**, not only when it closed or was written. A span closed today may describe a retained earlier interval. Selected scopes never grant travel before detailed admission or after loss. An old observation timestamp can be reported as stale evidence without granting an expired movement sequence.

Reuse `LiveReadCuts` for the durable cut plus pending native suffix. Add a typed temporal selection path to `LiveReadOverlay`; do not encode pending history into SQL CTE page rows merely to read it. Merge durable selected entries and pending selected entries by stable logical identity/order, applying exact pending deletions/replacements and eligibility at that cut. Generic SQL overlays remain for ordinary current/account rows. Read retries stay within existing preparation/admission; no new replay service.

### 4.3 Current privacy after waiting

`temporal-source-fence.ts` must watch stable logical interval/member and selected check identity, plus existing observer life, privacy, source revision and retention fences. A routine open-to-closed transfer is not source revocation just because its physical row changes. Conversely, watching only the interval's old start ordinal would wrongly reject a long unchanged value with a recent eligible check. A true correction, forgotten support or changed permission invalidates the captured result before publication/execution; new content is never substituted into the old cut.

Physical advance must complete actual reception, native supported reactions, exact admission/order and compact recording intent for that boundary. SQL encoding, index preparation, optional descriptions/consolidation and physical deletion can follow later. Existing async cognition uses its selected captured evidence and rechecks action preconditions at application. Moving a large loop to a worker is not a reduction and is not selected here. There is no requirement for each actor to call an LLM every few seconds; interpretation remains trigger/funding/work-budget driven.

## 5. Physical pages and indexed cold reads

The old logical chunk → dictionary/checkpoint → physical segment hierarchy is replaced, not retained as empty wrappers. Use one actor-owned **history page** table for packed closed intervals, checks and occurrences, with chronological-page indexes and a derived **span/member range** relation. Pack across native frames. A page boundary has no sensory or memory meaning.

Mixed pages avoid one payload row per field or coordinate. Only closed spans need the narrow member-range relation: independently changing members share pages, while a long interval can close much later than other entries. A whole-page span envelope alone would select many irrelevant pages. Checks/occurrences instead arrive chronologically and use their page's received-time range plus compact exact member/subject indexes. Do not create a SQL row per unchanged field per save. Never duplicate these projections inside JSON or retain separate `references` and `sourceRefs` arrays with the same meaning.

### 5.1 Canonical payload and derived selection

Use three page kinds, `span`, `check`, `occurrence`, under one codec/table lifecycle. Payload contains its kind, observer/life/epoch and ordered native operations. Check pages additionally contain only used declarations and lazy clock seeds. Value/provenance references are direct; no full predecessor page or replay dictionary is permitted. Existing required retention classes remain distinguishable within operations and their charging/eligibility projections; required support is independently retained by its actual owner.

Canonical columns (ordinary world-record identity and revision columns omitted):

  last_received_at, first_measured_at, last_supported_at
  encoded_bytes, logical_bytes, receipt_count, retired_revision, payload
  subjects[], member_keys[], source_ids[], individual_ids[], value_refs[]
  lookup_buckets[]
  PRIMARY KEY (world_id, id)

### 5.2 Cold selection algorithm

1. Capture actor/life/epoch, exact cut, eligibility frontiers, query members/subjects/window and preparation budget. Apply current privacy and pending withdrawal before treating anything as eligible.
2. Query span ranges overlapping the requested admitted interval, scoped to that actor and selected subjects where present. Select check/occurrence pages by received time/order and their exact member/subject array predicates. Include a bounded lookahead row and deterministic cursor. Do not enumerate every track the character has encountered, or select all page-wide envelopes and decode them to find members.
3. Deduplicate selected page IDs within row/byte/work bounds; fetch only those bodies and their selected direct value/proof closure. A metadata page truncated by member rows is incomplete even if several rows refer to the same payload. Continue from the cursor when more coverage is required and allowance remains.
4. Merge selected pending operations and captured current-open intervals by logical identity/order, applying replacement/withdrawal before final limits. A span can have closed after the requested historical time; use its admitted overlap and clip to the query/captured cut.
5. Find support and measurement independently: overlapping check pages and their seeds first; for a gap, indexed predecessor member page or the first later member page's **old seed only**. Terminal clocks on the selected span/current value may answer only when no later than the requested cut. Never consume later stamps. If required later clock evidence says a retained check must exist but its page/dependency is absent, return the existing incomplete/integrity failure, not guessed freshness.
6. Count logical covered operations before expanding rich proofs; project only selected permitted results. Retain explicit uncertainty/coverage gaps. Release prepared page/value closures after consumption or invalidation.

Illustrative range query (the existing typed SQL builder supplies scoped predicates and bounded parameters):

```sql
SELECT page_id, track_id, first_at, last_at, first_order, last_order
FROM mind_temporal_span_ranges
WHERE world_id = :world AND actor_id = :actor
  AND numrange(first_at::numeric, last_at::numeric, '[]')
      && numrange(:from, :through, '[]')
  -- exact life/epoch, selected subjects, captured cut and eligibility predicates
ORDER BY last_at DESC, last_order DESC, track_id, page_id
LIMIT :metadata_limit_plus_one;
```

For a particular member's as-of clock, clip the cut to the selected interval/admission. Query actor/life/epoch/live checks with `(first_at, first_order) <= cut`, the member's bucket and **exact** `member_keys @> [member]` before `LIMIT`. Order by `(first_at, first_order, id)` descending; the reverse tuple selects a successor, and the same tuple is the keyset cursor. Decode the last applicable stamp through the cut or its old member seed. A page can straddle the cut while that member's first stamp/seed belongs to later admission: reject that seed and inspect the preceding exact matching page or the old interval's terminal clock. If no predecessor remains, a first later exact matching page can provide only an eligible old seed. Colliding buckets never grant or suppress membership. These select a bounded number of exact neighbor **results**; rows examined inside PostgreSQL remain plan-dependent. Exhausted preparation/database time returns incomplete preparation, not absence; timeout does not promise a resumable cursor. A source correction removes indexed membership only when the last actual covered stamp there is removed.

All comparisons to a captured cut use actual received causal position; the displayed measurement/support dates remain separate. A caller's measured/effective-time filter applies to selected stamps, not predecessor ordering. Do not add another measurement-time index without an actual supported selective-query consumer.

Verify plans for present, absent, sparse-old and deliberately colliding member keys on small and retained-history-heavy data. A B-tree plus a GIN predicate does not establish an ordered constant-cost seek, and `LIMIT` does not bound examined rows. Keep existing metadata/decoded-byte/work/time guards and exact predicate-before-limit behavior; a completed empty query proves absence only in its captured eligible scope. The numerical time range is a broad phase; scalar order and sparse member eligibility remain exact. Do not introduce an extension, separate per-member payload table, lifetime track list or recurring reindex job merely to simplify selection.

## 9. Work growth and pressure cases

Let R be legitimate receiver/source checks, F selected members, Δ actual received value/support boundaries, K admitted exact checks, M coverage membership changes, O occurrences, B save cuts, and A selected account candidates with D affected dependencies. Useful sensory work still scales with recipients. History construction follows Δ + K + M + O; proof expansion follows selected F, encoding follows new operations, and account **body/dependency preparation** follows A + D. Database filtering/sorting may examine more retained rows and needs qualification. Do not construct rich proofs for F × unchanged native reads, repeat value baselines at F × rollover, enumerate lifetime encounters or rebuild complete actor version sets. Span-range rows follow changed members per page; exact masks, bounded-bucket postings and seeds still have a member × page term, without one SQL record/full proof per unchanged member/save. Group seeds only when exact clocks/proof/frame semantics agree.

A paper comparison illustrates the distinction, not measured throughput: seven observers × ten admitted subjects × three co-covered members × 300 one-second save cuts would create **63,000 check lookup rows** in a per-member-row scheme. If each observer's suffix fits one page per cut, the target creates **2,100 check-page rows**, with up to 63,000 member-bucket postings before bucket deduplication, plus actual stamps/masks/seeds. Subject/source projections add their own keys. Actual page fullness, index cost and query scans remain unknown. Independently timed coverage also increases seed preparation; checks are not constant-cost.

Dense first exposure necessarily establishes each observer's actually received current content and correspondence. Compatible target-independent geometry/rich bodies can share existing preparation and immutable values. Distinct grants/precision/frames cannot. Only admitted details open historical intervals; first exposure does not create baseline dictionaries for all fields of all visible subjects. Current/member metadata and attention selection still cost work, and the next source profile must show their remaining multiplication honestly. This design is not a constant-cost crowd algorithm.

Long-lived characters retain bounded current/admitted working sets and policy-bounded recent checks/closed history; meaningful accounts follow existing quotas/required support. A logical ID counter may grow without a lifetime resident ID catalogue. World-event archives have separate policy and no new indefinite cap here. Cold history work follows selected retained pages and affected dependencies, not character age. Byte/accounting ceilings do not by themselves prove heap convergence; measure captured closures, open annotations, declarations, page directories and pending buffers too.

## 10. Implementation stages and acceptance

Do all source/caller conversion and review fixes before complete-game profiling. Each stage is independently reviewable; later stages may remain unfinished in an honest intermediate commit, but no dual production format is shipped as a completed stage.

### BK17 — Native grouped state and reads

1. Refactor current group content/part-partition metadata and its current-format codec together. Preserve independent composition owners, clocks and recording origins; never add a second writable pose.
2. Introduce the single synchronous selected read scope by extending the existing body/current owner. Convert value-only, correspondence, native body, recognition and attention callers; make selected proof projection explicit.
3. Remove facade caches and rich proof allocation from native confirmation/recording/group iteration. Reuse immutable received content through publication.
4. Inspect every remaining proof-producing caller for a real external/support consumer. Prepare selected closure once, not on each native getter.

Exit: independent freshness and partial coverage preserved; unavailable bodies cannot be targeted; no rich field facade constructed for unchanged native checks/recording membership; alternating partial clock masks do not encode unchanged content. Current codec/validation/export agree. This is the minimal practical conversion, not complete operating acceptance.

### BK18 — Compact chronology, selected reads and save-cut encoding

1. Add current recording annotations and typed span/check/occurrence operations inside the existing temporal owner. Reuse typed received-value parts for independent detail/pose; close only changed parts before replacement. Preserve intra-batch order and exact member addresses. Convert required/optional producers and familiarity support admission.
2. Convert feature-owned geometry recording and historical selection, retained minimal support, correction/forgetting, bounded current/expansion-envelope capture and async source fences. Exercise R/R+1 and late-closed intervals on paper/code paths before storage conversion.
3. Replace chunk/segment/dictionary models with canonical pages and kind-appropriate indexes. Introduce typed pending suffix selection, conservative admission charges, bounded native-tail residency and the save-cut encoder under the existing writer.
4. Convert cold queries, sparse edits, ownership, exports/current-format validation, ordinary reopen and explicit restore. Remove old shape/readers, encoding fallback and duplicate index/reference arrays.

Exit: no baseline/full-value copy on physical rollover, no per-sample table row or pooled coordinate ID even for valid poses/frames exceeding the old small-fragment threshold, exact clock tuples and half-open equal-time close/open/check order, with no pre-attention route; selected cold reads need no predecessor-page replay; open/closed transfer is atomic; current privacy applies before expansion/publication. Buffered checks seed from their actual predecessor, never the latest current clock; received time never replaces measurement/acquisition dates. Acquired terrain retains its one current owner and exact dependencies. Ordinary save encodes each new suffix once; pending reads do not serialize it into SQL. Exact logical/reservation totals agree after close, expiry, correction, failed save and restore.

### BK19 — Selected maintenance and complete integration

1. Add world-owned selection projections to account writes; query due/pressure candidates in the unchanged policy order. Overlay pending candidates before limiting. Replace whole-actor metadata preparation in ordinary maintenance.
2. Replace complete source-version plans with sparse affected-key plans through existing reverse dependencies. Convert pending reads, accounting and replacement guards together.
3. Convert recent frontiers, selected identity repair and physical cleanup; reuse prepared prefixes until affected. Preserve writer fairness, dirty work during service, exact age eligibility and protected support.
4. Complete the caller inventory and affected-diff review. Reconcile current semantic/save/limits contracts only when installed; retain future physical sensing, full PP07/SAI-A and unrelated semantic-memory scopes as open.

Exit: account preparation reads bounded selected candidate/dependency closure; complete flattened dependency projections cover summaries and non-impression memories in pending and durable state. Pressure-only selection stops when that class recovers rather than removing 64 by quota. One changed account does not rebuild all actor source versions; replacing an account with no outgoing dependencies still archives its old revision if another account needs it, including a nested manifest case. Unrelated append does not invalidate a selected retirement prefix. No dropped pending save/optional dirty intent under the observed admission-pressure failure. Required facts and current reception remain independent of recent cleanup. No duplicate authority, fallback format or superseded runtime path remains.

### Verification and smallest measurements

Use existing disposable scenario/verification tooling; no maintained unit-suite campaign or new test framework. Static/type/build checks and connected current-format PostgreSQL/player/NPC checks apply after full implementation. Preserve any already-required integration/human gates; design review alone supplies none of them.

First run the smallest structural comparison: unchanged attended subject across multiple page boundaries; changing attended member with independently stale siblings; crowded first exposure at two small cardinalities; same-cut pending correction and cold restoration after early check-page expiry. Count actual fields projected, acquired values, closed intervals, stamps, declarations/seeds, encoded suffixes/bytes, lookup/owner-use rows and account/dependency rows. Assert removal targets, not an invented percentage speedup. Inspect SQL plans for present/absent/sparse-old/colliding history keys and many-due/many-not-due account sets, reporting examined as well as returned rows. Verify collision postchecks and explicit incomplete preparation, and pressure relieved by a single account despite a 64-account ceiling. If any ordinary path can still encode a prefix, record its exact reason and fix the missed conversion before profiling.

Then run the existing standard opening once on a suitably uncontended environment with its same warmup, active movement/speech, population, nominal clock, provider policy and **uninstrumented ≥0.98 normal-speed required pass**. Record actual advancement, command tails, failures, optional gaps, pending age/bytes and exact start/end cleanup debt. A failed startup/warmup is not a completed measured run. If it fails, take one bounded attribution capture and stop for diagnosis; do not churn through small encoding tweaks or expand into crowds. Host contention is an environment limitation, not a capacity result or reason to lower the gate.

If the standard gate passes, retain existing BK12/BK16/SR07 substantial-scene passes and wider scale/mature-history measurement obligations. The smallest additional uncertainty checks are several retention cycles with produced/reclaimed bytes and rows, one retained-heap comparison outside timed work, and small/large local arrival cardinalities. Include index/TOAST/WAL, lookup rows, clock seeds, open/captured closures and pending buffers. Stop and redesign if live/retired bytes or queues do not converge at ordinary load, cold reads scale with lifetime history, a long interval pins expired pages, or compressed data bypasses context bounds. Do not infer hundreds of active characters from the tiny opening.

## 11. Decisions, risks and extension seams

No product question remains unresolved for this design. Consequential choices are explicit: current-owned open intervals rather than a second timeline store; compact exact checks rather than continuous-visibility inference; kind-specific physical pages under one codec plus chronological-page and span-range indexes rather than per-field SQL rows; native pending suffix reads rather than repeated early encoding; sparse dependency deltas rather than complete actor archive replacement. Optional memory ranking and all sensory/gameplay defaults remain unchanged. The accounting/granularity change in BKS-L09 intentionally stops charging accidental dictionary duplication.

The main risks are missed supported callers, independent clock/member mistakes, pending-cut double inclusion and selecting late-closed spans incorrectly. The algorithms and acceptance above address these directly. Physical packing density, query plans, retained heap and sustainable cleanup are empirical uncertainties, not missing product decisions. Exact observation opportunities still cost stamps; derived member indexes still cost rows; selected correction still costs dependency work. No percentage speedup or population capacity is promised.

Extensions use the same narrow seams: a new supported channel supplies exact received values/check semantics; a new world supplies admission/retention policy; a new consumer supplies its selection and materializes permitted evidence. None must invent a private recording store, global event replay, extra writer or situation-specific observer rule. Additional infrastructure requires a demonstrated remaining need after this conversion, not anticipated future richness.
