## Scope

This is SAD-G's implementation specification for the [feature](stealth-player-experience-feature-spec.md), covering the selected [ND13](../maintainers/needs-design.md#nd13--stable-action-recommendations-and-complete-control-customization) control/presentation slice. It changes documentation only. All type/field names introduced below describe proposed current-format contracts to implement through existing owners; they are not claims that those APIs exist.

Implementation spans domain movement amendments, server authorization/projection, protocol, React interaction and PlayCanvas rendering, so privacy and action continuity are material risks. The plan and exit criteria belong to [SPX](../maintainers/stealth-player-experience.md). Implementation and runtime qualification remain separate work; this specification makes no execution or usability claim.

## Authorized projection contract

### Envelope and field freshness

Reuse the existing world ID, save timeline, access scope, history/privacy epoch, current view revision and patch predecessor. Add the **evaluation cut** to the ordinary projection: the simulation time through which the included physical/observer facts are complete. The exact name can align with current protocol conventions; the meaning is mandatory.

An audience is explicit: ordinary embodied perspective versus authorized creator inspection. Resolve it server-side from an explicit mode selection and current grants, never from a query's requested Boolean. Merely possessing inspect/create rights must not promote an ordinary embodied view. Existing creator-tool, detailed-work and detached-inspector reads must check this selected audience as well as their individual grants; hiding the toolbar is insufficient. View scope includes exact controlled life/generation server-side, even when those internal values are not serialized. Do not add a new general identity service.

Each independently changeable facet carries:

| Proposed public field | Meaning and use                                                                                                                                     |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| display value         | The narrow currently permitted description, representation, point/region/bearing or own condition.                                                  |
| measurementAt         | Original observation/measurement time for that facet.                                                                                               |
| confirmedThrough      | Last completed provider-defined availability support for this facet; it never refreshes the value’s measurement time or supplies a newer transform. |
| temporalRole          | Current at the evaluation cut, historical, or explicitly inferred.                                                                                  |
| quality               | The A-owned possible/supported/ambiguous distinction when applicable; omit invented confidence percentages.                                         |
| precision             | Only the admitted spatial/detail precision.                                                                                                         |
| sourceReference       | An opaque permitted reference for personal inspection when available; not native evidence/support tuples.                                           |
| observationContinuity | Opaque scope-local continuity binding only when A supports it; it authorizes no extra fact.                                                         |

A's concrete fact families remain canonical. For `CapturedCurrentFacet`, public `measurementAt` comes from `valueMeasuredThrough`; `confirmedThrough` retains its separate availability meaning. Preserve a meaningful measurement interval when the facet supplies one. Native `valueAcquiredAt` determines when the value entered the captured evidence and cannot be backdated by its original fact key or publication. G does not require every field on a facet where it has no meaning, and may compose these semantics into existing structures rather than wrapping every scalar. A missing field is absent, not zero/false. Explicit patch removal must remove the old field; omitted unchanged fields in a patch are different from revoked fields.

Live display means the latest admitted sample remains eligible at the published cut, not that its coordinates were measured at that cut. B evaluates active-scope visual samples on its canonical **50 ms normal-play grid** and actual physical discontinuities, supplying frozen values with their original measurement times. Publication can reuse those values but cannot refresh their age, read a newer hidden transform or extrapolate between measurements. The evaluation cut states completed native work separately from each facet’s measurement time. The client cannot know an undelivered observation loss; it holds only the last authorized sample until a new sample or explicit loss arrives.

**Exposed part is not whole body.** A head above a wall can provide a head patch/region, without exact feet, body transform, carried weapon or body-target permission. Rendering a complete avatar at a guessed anchor is forbidden. Use the admitted patch/region cue or a non-identifying representation. A physically targetable anonymous body is valid; recognition is not a prerequisite when the action's body-binding contract is satisfied.

**Continuity is earned.** If indistinguishable bodies overlap and lose every unique observation witness, retire the old physical contact binding and selection lock. Reacquisition can create new contacts. Do not preserve identity through hidden canonical IDs, asset reuse, list ordering or guessed closest-position matches.

### Asset and metadata restrictions

A contact's asset selection must itself be permitted. A UUID or hash identifying a hidden character-specific model, portrait, equipment texture, voice bank or animation can leak identity even if its rendered node is hidden. Use common neutral assets for weak contacts; resolve detailed assets only from admitted appearance facets.

Express B's received distinguishing appearance features at the earned detail. When art cannot make a supported distinction legible, supply its permitted qualitative description through the same inspection/cue surface. Do not substitute an ID-coded portrait, expose raw recognition vectors or depict observably different faces identically without that alternative. Matching received features remain legitimately ambiguous.

Strip hidden subject information from URL paths, accessibility labels, data attributes, React keys, tooltip titles, selection order, browser logs, notifications, sound source groups, command errors and download/preload requests. Share static asset caches where lawful, but no current entity association survives authorization loss. Do not claim that destroying a renderer texture removes bytes a previously authorized creator has already learned; the obligation is correct future publication and no automatic transfer to character knowledge.

### Geometry and light

The server separates immutable public navigation scenery, retained known geometry and currently observed changing geometry before serialization. Reuse existing map/surface types for the allowed subset; do not send a collision-ready copy of secret world geometry merely because the renderer currently accepts SpatialMap.

A hidden obstacle may block real motion. The client can show the known route proposal, but only server physics decides admission/progress and safe blockage wording. A stale remembered door is labeled historical when relevant; it cannot keep animating. Public geometry does not imply a secret room's name, contents or occupants.

The renderer consumes B's observer-safe current appearance. Its selected light count/quality is an aesthetic approximation; it cannot change detection or remove the authoritative readability of an already acquired cue. Historical fire records have no light emitter. A visible bright wall around a corner may remain lit from a source-free field without revealing the lamp's position or holder.

Dynamic shadow/reflection/particle geometry cannot encode a hidden body. Use only separately permitted phenomena; no hidden skeleton is uploaded to generate its shadow. B's initial optics omit reflected vision, refraction, bounce, volumetric smoke and dark adaptation. Decorative effects must not install those senses.

### Projection algorithm and revocation

1. Resolve the current server audience/control scope. Prepare only its required current observation and exact requested history; never hydrate a world-wide entity/knowledge list for later browser filtering.
2. Acquire one coherent complete native observation cut and the permitted retained source revisions. Incomplete required work remains under existing native hold/continuation; no missing source is treated as absent, safe or neutral.
3. Construct the allowlisted records from A/B/C facts, own D/E/F feedback and installed descriptors. Resolve public references/asset choices only after role/detail authorization.
4. After any awaited preparation, recheck current scope, history/privacy revisions and exact required sources immediately before publication. A cache hit grants no authority.
5. Produce full baseline or an ordered patch. A scope/timeline/audience discontinuity requires a new baseline. Per-contact and per-facet removals are explicit, applied atomically before additions/animation updates.
6. On the client, reject a patch with the wrong scope or predecessor. Request a fresh baseline without replaying commands. Clear affected render/input bindings at the same revision; old async results cannot revive them.
7. Derive historical display only from an explicit currently eligible history record. Ordinary live-list omission is not sufficient to create memory: it can mean revocation, forgetting, removal, changed scope or failed preparation.

A visual live-to-history transition is one coherent update: retire the body target and unsupported visual facets, animation and body-anchored audio/light; optionally install independently allowed history. Independently current acoustic evidence or source-free environmental glow survives only under its own continuing support and precision. Losing sight does not silence an actually heard voice. A forgotten/corrected/revoked facet invalidates its old detail and dependent render objects even while paused. A correction's new eligible account may be shown with attribution, never silently substituted as an original witnessed fact.

## Input routing and ordinary movement

### One input owner

Extend ui/keyboard.ts with a shared semantic binding map and a focused held-input controller invoked by main.tsx/WorldRenderer. Keep React responsible for UI/focus and plain intentions; PlayCanvas supplies pointer rays/camera basis and renders accepted state. No domain world object is imported into client control logic.

Priority is modal scope → child popup/text/IME → captured UI/construction/target-selection gesture → eligible focused world controls → ordinary panel shortcuts. A focused control consumes its activation/navigation keys before world shortcuts; those events never enter the held-direction set. A key event is consumed once. Modifier chords suppress plain movement keys; entering Shift+S releases any held plain S before opening speech. Browser/OS shortcuts remain available.

The canvas/game surface and immediate movement/posture/pace HUD controls form one world-input scope. Focus changes within it preserve held movement and renewals; native admission still decides whether the requested action preserves or replaces that movement.

Held movement/gaze state clears on leaving that focus scope for text entry, menus, selectors or unrelated panels, opening a blocking overlay, window blur, page hiding, pointer cancellation where relevant, suspension, disconnect/stale transport, manual pause, control/body/world/timeline/audience change and controller disposal. Send neutral/release best effort; server freshness expiry is independent protection. Returning focus never resumes held movement until a fresh press. Stop remains a reachable button while panels cover the world.

The selected bindings and exact pointer semantics are in the feature. Rendering preferences and remapping are local/account UI preferences, not rewindable world state; keep them in the existing preference owner. Persist semantic control IDs and scoped key/chord values, not physical target IDs or private world data.

### Direction movement: missing narrow capability

The base only admits point movement. Implement a **direction-driven variant of ordinary move work**, not a client path loop, new physical lane or special stealth mode. Extend the existing move command/action owner with a destination-versus-direction discriminant, updating current callers together. Preserve the present destination route and native action family.

The public held-input message is carried through the existing authenticated command transport. It contains only:

| Field                                   | Requirement                                                                                                                                                                                                                                                                                                                    |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Current access scope / command identity | Existing server-issued control scope plus unique request identity for a discrete start/end; supplied actor/body authority is ignored.                                                                                                                                                                                          |
| Gesture and input session               | Start carries a monotonically increasing gesture number and original command identity within the current server-issued control scope. Admission returns an opaque binding to its exact native action/controller/life. Pending-start cancel can address the original gesture before that reply; updates never create an action. |
| Sequence                                | Strictly increasing for this movement gesture/input binding, allocated when sent. Gaze retains B's separate command/directive ordering and cannot supersede a movement packet. An old movement sequence cannot renew freshness or supersede Stop.                                                                              |
| Direction                               | Latest complete finite normalized desired direction, including on a positive renewal, or explicit neutral. No speed, elapsed simulation time, current coordinate, path, velocity or target truth from the client.                                                                                                              |
| Expected work                           | Exact current work binding for starting/replacing; optional exact B orientation/E attention amendment references when actually applicable.                                                                                                                                                                                     |
| Requested mode                          | Destination move remains its ordinary point/support request; direction mode means direct steering, not auto-detouring toward an unseen destination.                                                                                                                                                                            |

For a start, preflight the body's ordinary movement and actual work relationship. A supported standalone manually controlled destination walk may amend to direction steering within the same admitted move: settle earned motion/costs, discard its remaining destination and arrival goal, create the exact current direction-input binding, and preserve action identity, contact-distance progress and compatible E/B directives with their original deadlines. Never report arrival at the discarded destination or resume its route later. Re-evaluate actual travel direction and coverage through B/E. This amendment is not available to plan-, activity-, cooperation-, follow- or attack-approach-owned travel merely because its current action is a move; those use their existing explicit continuation/replacement rules.

Other starts atomically replace old work only after successful native admission, creating one ordinary move and input binding. While held, compatible steering amendments settle earned motion and update only the requested direction, preserving action identity, costs, distance progress and compatible E/B facets. Neither mode handoff nor steering emits another action-start effect, resets footstep cadence, rerolls a check or renews a watch deadline. Current work states the handoff or replacement consequence.

The current control owner retains one cancelled/superseded-gesture high-water mark for its scope. Release, blur or supersession sends cancellation against the original gesture/command immediately, without waiting for Start's response or the replaceable-update slot. A cancelled older Start cannot admit if it arrives later. If Start already committed, cancellation resolves its original receipt and ends only its still-current direction-input binding; matching the action ID alone is insufficient. It cannot stop a later input binding, destination walk or replacement work. A late response cannot reinstall client held state. A lost response is recovered through the same command identity, never by submitting another Start. Unknown/expired session updates refuse without creating work or renewing liveness. A fresh press uses a new gesture; server-controlled scope change invalidates the entire old sequence space.

If the player selects a click destination while a Start is unresolved, immediately cancel the held gesture and submit the destination through ordinary exact-work admission. If its expected work no longer matches, show the ordinary changed-work refusal and retain the selected destination preview for explicit resubmission; never retry silently or let a late Start replace the click walk. This explicit movement takeover is separate from posture admission. Do not cancel first for a posture or other replacement whose refusal must preserve old work; use the pending-request rule below to establish its exact binding.

The server forms the short physical continuation from actual position, installed speed/pace/posture and the existing native motion boundaries, using shared straight steering/support-edge/clearance helpers. Direction mode stops at a blockage and reports the permitted reason; it does not pathfind around a wall or choose another floor. Valid actual support seams/slopes are crossed through the existing native query. Renderer geometry and same-surface guessing cannot decide motion. If an admitted body cannot safely steer under its installed movement family, refuse explicitly and retain click-to-move.

Use B's installed ordinary-locomotion orientation policy: a new ordinary move sets a body-heading goal toward the actual admitted travel tangent and applies that family's head/eye default at real turn rates, unless an explicit compatible look is admitted with it. A same-action steering amendment changes the body-heading goal through that physical pose owner while preserving compatible head/eye directives and earned turn progress. Translation never writes or snaps heading. Sideways/backward travel with an independently maintained body direction requires the explicitly admitted B/C composition and its actual speed boundaries; keyboard direction alone does not create that capability.

Direction is normalized once; opposed keys cancel that axis and diagonals have no extra speed. No keyboard-derived sprint or fear modifier is permitted. Standing/quiet/crouched speeds and body-assisted turning costs come from reconciled B/C rules. The UI shows available pace names/actual consequences from installed descriptors.

Neutral input ends only the exact direction action/session it owns, using ordinary termination. Terminal blockage or successful stationary work replacement retires that gesture too. Suppress each direction key still down at that ending until its keyup; autorepeat does not rearm it. A fresh keydown of another direction can start a new gesture, excluding suppressed keys. Toggle movement becomes inactive. This permits deliberate sideways escape from a wall without later restarting a held forward key. Refused replacement and compatible pace/gaze/watch amendments do not retire or rearm movement. A neutral request cannot stop a subsequent click-walk, guard or newly controlled actor. An action-only stop and **Stop all work** remain distinct: the latter ends queued/waiting plan continuation through the current full-cancellation owner. Space invokes the visible full Stop choice when present; releasing WASD ends only held movement. Do not let a waiting plan immediately restart movement after the user selected Stop all work.

### Input timing and limits

Selected operational defaults are inventoried in [SPX-L](../limits/stealth-player-experience.md). They are transport/control safety choices, not simulation rules:

- Send start, direction change and release promptly; coalesce replaceable intermediate directional/gaze updates to at most 20 per real second. Do not coalesce discrete posture, attack, cancellation or committed outcomes.
- Keep one in-flight replaceable update and two fixed pending slots: the latest movement direction and the latest gaze request, each with its own exact binding. A change replaces only its own slot. Alternate eligible slots when both remain pending so continuous pointer gaze cannot starve steering. This is one existing dispatch owner, not per-key queues. Neutral/release bypasses the replaceable gate, closes its exact movement binding and cannot be superseded by a renewal.
- Renew eligible held movement every 100 ms, with at most 10 priority renewals per real second in addition to the shared 20/s replaceable-change allowance; valid direction updates also renew it. Every positive movement packet carries the latest complete desired direction sampled when sent and a newly allocated movement sequence. Thus an overtaking renewal applies the current intention before rejecting older movement packets; it cannot leave obsolete travel in force. Gaze uses B's independent ordering. An unchanged renewal updates only transient liveness, without another physical amendment. Permit only one outstanding renewal; retain the latest desired direction in the existing controller, not an accumulating renewal queue. Renewal and neutral/cancel bypass the replaceable-update gate, and cancellation also bypasses an outstanding renewal. After 300 ms without a fresh valid renewal, stop that held movement at the next native input boundary. Check expiry before another positive native advance after a server stall/catch-up; settle already committed/required coherent progress, but do not replay the stalled wall interval as held travel. ## Integrated dependencies and remaining decision

The [shared technical contract](stealth-awareness-tech-design.md) owns evidence revisions, publication ordering and module boundaries. A owns exact evidence/reference roles; B/C own physical sensing and movement composition; E owns the actual maintained-method start and finite attention; F consumes that timing and actually acquired warning facts. G consumes those canonical values without converting source revisions, deriving readiness from action age, or adding client sensing rules. Implementation must replace unsafe full-entity/map/animation producers together with their consumers; the source audit and acceptance table identify those concrete gaps.

**SA-D01 remains open in full:** controlled-player appraisal production, retained-appraisal mechanical applicability, disclosure, revocation and control transfer. The recommended initial policy is native-body-only during direct control, preserving interpreted records/lifetimes while masking their mechanics. This is a recommendation, not an adopted rule. Native startle and NPC interpretation have independent specified behavior; no implementation may silently select the player policy.

Input, historical-marker and feedback defaults remain subject to measured tuning in [SPX](../maintainers/stealth-player-experience.md) and [SPX-L](../limits/stealth-player-experience.md). Design integration does not establish runtime correctness, accessibility, latency or fun.
