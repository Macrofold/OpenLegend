# People built from parts — technical design

| Status      | Current progress                                                                       | Last updated |
| ----------- | -------------------------------------------------------------------------------------- | ------------ |
| In progress | The creator builds, with broader body controls, artwork and family qualification open. | 2026-11-11   |

The [feature specification](people-from-parts-feature-spec.md) describes Mike's path from a description to a dressed, animated person. The [artist's procedure](../production-workflows/art-flows/people.md) describes how to make each piece. This design covers the data and deformation needed to make the _same_ body settings work in Blender, the private draggable preview and an authorized game character.

The [family authoring contract](people-from-parts-authoring-contract.md) owns the [control model](people-from-parts-authoring-contract.md#character-control-model), exact source package, recipe resolution, sculpt/material evaluation, reusable baker, ordered checks and isolated experiments. Read it with the [world-owned control definitions](../worlds/base/people-appearance.md#control-definitions) before implementing. These contracts finish the ND39–ND42 design; actual approved sculpts, texture pixels and measured qualification remain production deliverables. No endpoint asset or live slider is delivered by documentation.

## Existing consumers and implementation impact

`scripts/art/art-tool.py assemble-person` consumes the exact external family package and one or more recipes through `scripts/art/people.py`. The shared fixed operations evaluate bodies, fit parts, bake materials and fit maintained motion before checked GLB export. The browser uses the corresponding numerical family evaluator through `PersonActor` for both preview and admitted wearers. Construction-source checks establish these mechanisms; a qualified finished family is still required. Generated-head intake alone supplies neither common facial topology nor removable hair, and SAM's exported keypoint markers are not a usable rig.

`LibraryActors` in `apps/client/src/library-actors.ts` shares loaded geometry/material preparation per source and evaluates each admitted wearer's pose. Its display scaling uses source height versus the projected body height. The new source must supply anatomical stature, not the top of its hair. Keep the existing load, fallback, visibility and disposal owners; no new per-frame body fitting is needed for a baked character. The current helper's 40,000-triangle character check applies to the assembled GLB, not independently to each new garment.

`world-presentation.ts` borrows `skinInstance`/`morphInstance` for reveal geometry and clears borrowed references on removal. That code requires an actual mutable-morph lifetime check before live targets enter play; sharing an immutable mesh is not permission to share two people's morph weights. `perception-frame.ts` includes `entity.appearance` in sensory fingerprints, and `apps/server/src/context.ts` spreads the observed actor into self context. Slider fields added to those records can leak into decisions even if no prompt was edited. The sparse separate recipe/projection contract below is therefore required, not an optional cleanup. [Native input evidence](../verification/people-from-parts.md#cosmetic-data-and-character-decisions).

Existing fixed character art is the cost baseline. Better anatomy/textures add authoring work; common controls, age samples and reusable wardrobe require upfront qualification. The design does not claim equal implementation effort. Amortize that work across later characters, count repairs as well as generation, and keep every performance-sensitive addition under the [isolated experiments](people-from-parts-authoring-contract.md#isolated-experiments). New libraries, a general fitting server, migration/version adapters, runtime AI generation and unrestricted cloth are unnecessary for this delivery.

For scale, the inspected 18,439-vertex SAM body needs 221,268 bytes for one dense float32 position-delta array. Eleven bipolar body axes with separate positive/negative targets at two frames would need 44 arrays, **9,735,792 bytes (about 9.3 MiB)** before normals, heads, correctives and UV/export splits. This is a storage calculation, not a measured runtime allocation. Share identical targets, keep this authoring data out of fixed exports and load live-family data only for an admitted consumer. A new scalar itself is cheap; its sculpting, validation, dependent fitting and buffers are not free. Texture pixels and separate material/shadow draws also cost more than their compressed file sizes suggest. E1–E4 measure the actual accepted result before widening the kit or enabling the live path.

## What the model has to know

A 3D model arrives with points and triangles. It cannot infer which points are a collar, how broad a shoulder may become, what fits inside a sleeve or how a knee should bend. The family author supplies those meanings once. A **shape target** records the displacement of each point from a neutral shape. A slider sets how much of that displacement to use. A **skeleton** places joints inside the shaped person. **Skin weights** say how strongly each point follows each joint during movement. **Fit surfaces** carry separately modelled garments to the shaped body in its resting pose. These solve different problems. [Primary sources and project evidence](../../art-direction/research/3d-pixel-worlds/adjustable-people-and-wardrobe.md).

## Family manufacture and slider evaluation

1. **Build one good template.** For the paused Wayfarer pilot use the [selected SAM/MHR construction surface](people-from-parts-authoring-contract.md#source-choice-and-quality-boundary) and approved concept references. Preserve the mercenary as a quality benchmark. Source comparison for a separately requested new family follows the [art decision](../../art-direction/decisions.md#how-the-current-look-changes-production), inspecting exact meshes, terms and exportable sources before selecting a donor. Suitable licensed topology can save rebuilding joint loops; it does not qualify visible stock anatomy, a rig or control endpoints. Hidden MPFB use still needs a deliberate source choice. The rejected visible MPFB bodies and fused proof dresses remain excluded.
2. **Keep correspondence.** Align neutral front and side views to the scale, place eye corners, nostrils, lips, chin, neck ring, major joints and silhouette landmarks. Align the donor to the template and preserve its proportions through registration. Transfer usable broad volumes, feature placement and relief. Fix demonstrated defects in the affected regions, such as concealed anatomy, recessed features, fingers, armpits or joint folds. Keep index order, anatomical edge loops, UV correspondence and material alignment. An automatic rig on a new mesh supplies none of this correspondence. Rebuild or reject a candidate with a closed mouth painted over missing lips or geometry fused through the clothing. Bake sculpt detail to the compatible surface where justified.
3. **Author endpoints and correctives.** On the same body topology, sculpt corresponding structural and local targets, independent mass, fullness and definition responses, and qualified age anchors. Store each face preset on the shared head with matching eye/lid, mouth and neck topology. For example, give the widest shoulders and fullest chest an extra _combined_ deltoid correction where adding the two independent shapes pinches the armpit. Store a continuous driver for it, such as a product of the two normalized excursions that grows smoothly away from neutral. Define any mutual constraints under the family and show them in the creator. The procedure supports continuous positions inside the admitted range. No extrapolation or arbitrary extrapolated blend is promised.
4. **Solve proportions once in the rest pose.** Evaluate surface controls in canonical space, solve the rest joint positions from shaped anatomical landmarks, then resolve final stature around the soles. A neck edit changes the head pivot, collar anchors and head placement. A leg-share edit moves hips/knees at fixed stature. Keep the stated height fixed while redistributing proportions. For simple overall height, scale the whole fitted body/rig consistently; for a local length change, rebuild the affected joint offsets and inverse bind matrices. If segment length is already represented on the surface, do not apply it again as a pose-scale track.
5. **Fit eyes, face and hair.** A face blend supplies coarse shape. Local controls refine it within bounds. Move the eyeball centres with eye spacing, shape lids around the globes and verify the closure pose. Place pupils/iris pigment in eye materials. Place brows and beards on the shaped forehead/jaw. Constrain the separate head's neck ring to the same boundary positions, weights and normals as the body or weld the matching ring at offline bake. Keep skin materials continuous across the join. Use a scalp cap to fit hair roots, deform lengths within the style's reviewed range, then attach long sections to the reserved family joints. Test hats with the approved compressed style, exposing fringe as appropriate.
6. **Fit wardrobe, then pose.** Transfer garment shape and fit the rigid attachments on this rest body (below). Bind all to the same evaluated joint hierarchy for this one wearer. Animate local rotations on top. Pose-induced corrections such as an elbow fold are separate from rest-shape controls. Blender constraints, drivers, fit cages and IK are authoring inputs. Bake them into supported mesh or clip data, or add an explicit bounded runtime evaluator and qualify it before depending on it. A correct Blender viewport alone cannot establish a correct GLB. [glTF morph targets and skins](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#morph-targets).

**Example evaluation.** For a linear control with neutral .5, let `u = 2s − 1`. Add `max(u, 0) × (broad − neutral) + max(−u, 0) × (narrow − neutral)` to the neutral points. At .25 the result is halfway toward narrow; at .75 it is halfway toward broad. A qualified pair of corresponding frame anchors uses a direct 0–1 blend. Stature uses metres. Read the fixed mappings and locks from the pinned family for every input method. [Bundled examples](../worlds/base/people-appearance.md).

### One recipe, two ways to author it

For a worked example, suppose the selected family has the range and presets in the bundled profile. The sheet calls for a 1.95 m adult with a long neck, a close braid, green eyes and a short quilted coat over a shirt. An artist entering 1.95 m and another dragging to 75% should produce the same canonical stature value. Store metres for stature and normalized values for sculpt controls. Derive the displayed percentage from the pinned mapping. Resolve preset defaults into explicit values at save so editing a preset cannot alter an existing character.

```yaml
# Authoring-input excerpt; substitute the exact installed descriptor reference.
family:
  owner: { kind: world, id: base }
  assetId: wayfarer-adult-people
  revisionId: <published revision>
  manifestSha256: <published descriptor checksum>
controls:
  {
    statureMetres: 1.95,
    frame: 0.35,
    breadth: 0.63,
    muscle: 0.45,
    fullness: 0.55,
    neckLength: 0.70,
    adultAgeYears: 55,
    eyeAperture: 0.46,
    eyeSpacing: 0.54,
    hairLength: 0.40,
    greying: 0,
  }
selections:
  face: face-b
  iris: green-umber
  skin: warm-neutral
  hair: tied-braid
  hairPigment: dark-brown
  coverage: bra-and-briefs
```

The separate outfit request can select a linen shirt, trousers, quilted coat, paired boots and ear studs when those parts are qualified. To dress a second person in the same coat, supply that person's recipe and the same coat definition to the assembler. The coat receives new fit and bind data. Its fabric, colour regions, item instance (if exchanged in play) and attachment construction follow their existing owners. For NPC batches, draw from the selected world’s authored distributions with a deterministic seed and preserve the resolved result. Compare a bounded batch’s silhouette, head, hair and outer-layer choices so a change in iris colour alone does not count as a visibly distinct crowd member. If a kit-only batch cannot meet its requested variety, report which visible combinations repeat and where a new part would help. Missing control values in the example come from the pinned definition during authoring. A final asset receipt includes the complete resolved recipe and actual references.

## Matching a concept to a recipe

A marked scale and undeformed front/profile views make matching repeatable. Separate known dimensions from estimates. Record locked traits (a stated height, the face outline or signature nose) and reliable measurements such as shoulder and hip width, crotch height, neck length and trunk depth in the relevant view. Put their points on the corresponding family landmarks. When the sheet supplies only a stylized three-quarter view, request a construction view or record an artistic interpretation. An obscured waist supplies no reliable girth.

For the first proof an artist can fit the sheet with Blender controls. Align the feet and vertical centreline in orthographic views and compare in metres. When ranking presets, use equal weight for each supplied, reliable measurement unless the brief explicitly prioritizes one. Normalize each residual by reference stature and rank by weighted mean square. Start from the best candidate, honour locks, adjust within bounds, and overlay front and profile at the same scale. Break an equal score by artist judgment. Missing measurements contribute neither a zero error nor a weight. Automated inference from images is outside the build.

Apply the [pilot tolerances](../limits/3d-pixel-art.md#adult-family-and-garment-fit) separately to the stated height and each reliable silhouette landmark used in the match. A measured but unlocked feature still has to pass. Aggregate score only orders candidates. The artist and Mike still inspect distinctive identity features, particularly eyes and profiles where this tolerance is too coarse. Separate inferred dimensions and uncertain style from a numerical pass. If no supported shape matches, return the nearest attempt with the failing dimensions, the reference and the cost of a correction or proposed extension. Mike decides whether to extend the family, commission another, or revise the target. A better garment fit never justifies silently changing a locked body. [Scope and limits](../limits/3d-pixel-art.md#adult-family-and-garment-fit).

## How the same item fits different bodies

**A close shirt.** Bind each vertex once to a triangle on the appropriate helper region, with three interpolation weights and an offset in its surface frame. Weights .2, .3 and .5 follow `.2A + .3B + .5C` on the shaped triangle. Carry the local offset for ease and thickness. Keep sleeves on the arm side of the armpit. For a fixed export, evaluate the fitted garment directly on the requested rest body and include artist corrections where the surface fails. Preserve the binding for the next wearer.

**Experiment for repeated fits.** Prepared endpoint targets can amortize repeated fitting but interpolating a moving surface normal is approximate. Compare direct fitting with reused targets for the actual batch or drag workload; keep the direct fit as the reference. Check interior control values as well as endpoints, especially cuffs, collars and openings. Promote prepared targets only where their correction effort, clearance and measured cost justify them. [Isolated fitting results](../verification/people-from-parts.md#fitting-one-garment).

**Loose clothing, layers and hard parts.** A skirt or coat hem binds to a simple cage spanning both thighs. Mapping down the nearest leg would split it. Inner/outer fit envelopes provide clearance between a shirt, padding and the upper coat. Process inner to outer. Use a tucked cuff, a different boot opening or a qualified thin inner variant when an overlap is intentional. Rigid armour can select an authored shell size, adjust the spacing or overlap of plates and skin flexible straps separately. A rigid stud follows an oriented landmark at the shaped lobe. Fit the neckline of a necklace across neck/clavicle supports, then attach the pendant rigidly. A helmet uses a fitted head attachment and a matched hair variant. All can belong to one item instance even when they have several mesh pieces. [Garment-by-garment production example](../production-workflows/art-flows/people.md).

**Complete body and coverage.** Preserve a closed, shaped torso, pelvis and limbs beneath the separate [world-selected coverage pieces](../worlds/base/people-appearance.md#baseline-coverage) in the editable master. Inspect the body without outfit geometry in the authoring tool, then show the covered figure for review. Garments have outer and inner surfaces joined around the thickness at necklines, cuffs and hems, with usable openings. Qualify the fitted complete body before deriving hidden faces for a dressed export. Author masks on the canonical source faces for each body or garment. Use the [target-specific mask contract](people-from-parts-authoring-contract.md#external-family-package) to union masks separately for each exact underlying mesh, preserving openings, linings and the family's coverage set. Apply this to a copy before triangulation/export of a fixed outfit; retain the intact master. Export can split geometry into primitives and vertices at material or UV seams. For a future live piece, export and verify its explicit region-to-primitive/face mapping at each supported detail level. Never reuse Blender face indices as GLB indices. Taking off a coat over a vest must restore both arms regardless of equip order.

**Fit guarantee.** Every released item in the common wardrobe must pass the supported adult envelope and its declared layer combinations. Require additional authored fits or correctives when a rigid piece, heavy overlap or distant measurement fails. A specialist prototype can carry narrower supported ranges in a study. It cannot silently enter the common wardrobe or create a gender restriction. Distinct cuts can use discrete authored topology even though body controls remain continuous. Blend between compatible fit samples or switch cuts at a qualified overlap when a private draft edit finishes, installing the matching geometry and masks together. Never interpolate vertices between different cut topologies. Handle an unsolved change with the supported body and an explicit fit failure. Never generate an item or run a general cloth simulation during a drag.

## Animation on a family

Use a single named humanoid joint hierarchy, conventions for local axes and attachment landmarks, and a documented neutral pose. Include the deforming joints required for face/hair/gear in the budget. Pieces can use subsets of that palette. Bodies share the rig **contract**. Two different people need their own evaluated rest offsets, inverse binds and independent pose playback. Clothing on the same person follows that person's already evaluated pose. Never animate a second, independently ticking copy of the skeleton per garment.

Treat 64 exported joints as the proposed ceiling. One feasible allocation is 7 central + 8 arm + 8 leg + 30 finger + 3 jaw/eyes + 6 braid + 2 hem joints. Use only what the approved poses and garments need. Keep nondeforming sockets and authoring helpers out of that palette. Record the pelvis used for motion and the bilateral stance/foot joints in the rig map. A ground-level root cannot supply pelvis height for the current clip helper's translation ratio. Retarget in Blender if the helper cannot represent the rig.

Start with the current upright Idle, in-place Walk/Run and applicable attack clips. Same-rig copying needs matching rest transforms, hierarchy, units, axes and clip channels. When leg/arm proportions or the bind pose change, retarget rotations into the corrected bases, handle pelvis/root translation separately, discard inappropriate source scale and joint translation tracks, and bake corrected contacts on the target. Recheck planted feet and hand-to-tool alignment. Measure stride on the final target and supply the consumer's stride metadata for its actual display scale. A different rest height by itself is insufficient to derive stride after relative leg lengths or poses change. World motion determines position and action results.

Use [the merged animation workflow](../production-workflows/art-flows/animation.md) for source choice, admission, rights and receipts. New or replacement human motion starts with Kimodo under its source/target qualification; accepted compatible library clips remain reusable for this proof and other characters. MotionBricks is an optional offline transition tool with separate data rights. Neither generates fitted clothes or supplies a new game action. Bake or skin secondary motion for hems, braids and necklaces, with simple weighted motion as the baseline. Introduce a local cloth solver only for a selected article such as an existing supported cape and measure the complete use. Avoid multiple systems driving the same joints or vertices.

## Height and gameplay

Keep two measurements. **Stature** is bare soles to anatomical crown in the upright reference pose. **Dressed bounds** include footwear, hair, helmet and moving cloth; use them for framing and culling. The [model report](../../scripts/art/art-tool.py) measures all meshes. When populating the standing source height for [library actors](../../apps/client/src/library-actors.ts), use anatomical stature. Applying the current body-height scale to a helmet-inclusive measurement shrinks the person. Register the support contact of the shod sole separately so exchanging footwear preserves ground contact. [Isolated measurement](../verification/people-from-parts.md#stature-and-dressed-bounds).

Today play fits a person to the common standing extent. For individual stature at creation, the [bundled spatial profile](../../packages/domain/src/worlds/base/spatial-definitions.ts) supplies the standing dimensions and anchors. Apply its [world-owned stature rule](../worlds/base/people-appearance.md#height-in-play) to the candidate profile **before** spawn admission checks clearance. Initialize the exact same profile in the authorized creation transaction. The saved spatial body is authoritative afterwards. Reuse [effectiveBodyProfile](../../packages/domain/src/spatial-state.ts) for posture and the projected body size for display. During an existing-person edit, preview a different stature only. Applying it requires an authorized physical resize with prospective clearance and normal spatial invalidation. No second size authority in the character creator.

Muscle mass, fullness and definition are visual. A world can explicitly connect physique to gameplay, but this proposal adds no strength, social knowledge, skills, mass or speed effects. A different world could fit saddle bags to its own four-legged rig and anchors without installing the human kit.

## Assembly, storage and the renderer

**Offline first.** Keep the body, source garments and recipe. Normalize static sources before binding; the [current tool](../../scripts/art/art-tool.py) rejects rigged input. Evaluate the requested recipe in Blender, export covered and dressed animated GLBs, reimport them, and run the existing report and [study preview](../production-workflows/art-flows/3d-models.md#consumer-contract-and-budgets). Check actual units, facing, bind and root transforms, materials, masks, bounds, clip names and stride metadata. A baked outfit proves the one assembly. Its controls and interchangeable sources remain editable outside the game.

For the first accepted baked character, use the current asset-selection/presentation mapping for the chosen art key. Do not rewrite `entity.appearance` to a recipe ID or install a new whole-world recipe system merely to show that fixed model. This preserves the ordinary renderer path while the later mutable appearance collection is implemented and qualified.

**Live assembly experiment.** A creator controller holds one private draft. Completing a gesture, numeric edit or preset choice updates that draft, records one undo step and schedules its local fit/motion setup. Only **Save** requests an authorized world mutation. These are distinct boundaries; local setup never waits for or triggers a server commit. On pointer-down bind the selected handle, front/profile view, starting value and allowed axis. Convert displacement using the displayed reference extent and family mapping. Coalesce moves to the newest draft per display frame. Update only what the control drives. Iris pigment updates a material. Neck length updates the head pivot, nearby fitted surfaces and attachments on that draft. Do not bake/export, reload all assets, commit network state or pay for generation per move. Pointer-up completes the draft edit; pointer cancellation restores the gesture’s starting values without an undo entry. Cancel closes the editor with no world write. Save carries the reviewed recipe and expected revision through the authorized creation/edit owner. Refit once on an accepted equipment/shape revision. A private draft may retain the previous authorized preview during loading. In play immediately detach stale or revoked parts on committed removal, loss of permission or identity change. Restore newly exposed underlying regions immediately with that removal; a missing outer part cannot retain its hide mask. Show a current authorized covered fallback if one is available, then install the complete matching part-and-mask result. Reject stale load completions after outfit replacement, permission loss, scene teardown or actor reuse.

**Preview implementation.** Add one `PersonPreview` adapter behind the existing `WorldRenderer` boundary and one private editor draft using the shared React Aria controls. It receives admitted family data and resolved values, not an entire world or Blender object. Extract the fixed numerical evaluator into a small renderer-free TypeScript module when this second consumer is built; use the offline evaluator's exact samples as its reference. Do not introduce a family framework/package in advance. Build a dependency list once from each control's affected objects/landmarks; a pigment change cannot invalidate body buffers, and a head edit cannot refit boots. Draft editing uses the upright rest pose; resume the selected motion only after the new rest/bind and motion setup are ready. Active movement choices and Play wait during editing/preparation; Rest remains accepted, including while a feature-selection gesture is pending. Update the visible selection only when the preview accepts that request. All gesture, keyboard and numeric paths call one `setControl` owner. A numerical rejection leaves the requested input visible and the last valid preview intact; a drag stops at the declared envelope boundary. No global world-key handler receives the gesture.

The baseline live evaluator updates the one selected preview's position/normal buffers and affected fit surfaces at most once per displayed frame, then does no fitting work while idle. This avoids shipping every author's shape key as a permanently active GPU target on every actor. One read-only family buffer set may be shared; evaluated arrays, inverse binds, pose and mutable material parameters belong to the wearer. Prepared garment targets or GPU morphs are alternatives under E3/E4, not prerequisites. Evaluate only active controls and their explicit corrections; no searches over all people, presets or wardrobe combinations occur during a drag. Shape change cost is bounded by the selected body's affected vertices/parts; ordinary play stays on fixed evaluated buffers plus animation.

**Motion after a proportion edit — E7 experiment.** Retain admitted source rotations, canonical root/foot guides, contact intervals and bend directions during compilation. Follow the [motion contract](people-from-parts-authoring-contract.md#external-family-package) for actual skin probes and fixed support times: original-grid planting precedes bounded ankle correction, using the original source knee plane even for near-straight targets. The browser uses the offline owner's two-bone/source-plane math, never incompatible rest translations or a second limb scale. After a private edit completes, bake only the selected clip against the new rest; build other clips on demand at selection/setup. Keep one current and one pending setup per preview, discard stale results and release replaced arrays. Fit before installing visible geometry/materials, so a rejected motion retains the last valid presentation. Cloth response consumes that final fitted clip. Geometry/proportion evaluation and clip baking stay at setup; the bounded contact correction below is the only pose-time fit.

Compare offline/browser endpoint and intermediate recipes for joint transforms, foot/toe contact, knee hemisphere, stride timing and cloth coverage, plus setup latency, CPU and memory. A failed live gate leaves the creator unqualified; an independently accepted offline baked person can still enter play. This does not authorize cloth simulation. The separately approved contact experiment below corrects only the final blended articulation.

**Correction after blending — runtime experiment.** After the actual animation component evaluates a modular wearer, apply the same admitted source-plane/sole solver to its final blended pose before skinning. Source guides mirror actual clip instances, times, weights and evaluation order, including reentrant transition history; do not infer them from a stride parameter or merge equal clip names. Share immutable original-source guide tracks per family, sample only the leg-ancestor rotations/root, and keep numerical buffers, snapshots and lifetimes private to the wearer. Clear retired instances, reset at Rest, and replace preparation when rest/sole inputs change; same-rest equipment edits retain the active gait clocks. Skip source-guide evaluation when the current soles already clear the existing local support datum. The correction changes leg articulation only, preserving root/local translations and foot/toe orientation. It performs no world movement, terrain queries, slope-foot alignment or cloth simulation. An unresolved pose retains the bounded best depiction and an explicit diagnostic result rather than crashing the world frame; it still fails qualification. Adoption requires actual animation/skin before/after contact and source-plane evidence, reentrant/pause/replacement/teardown checks, CPU/allocation measurements and representative in-game graphics review. A labelled local in-Scene diagnostic may qualify this mechanism without installing unaccepted art; it does not qualify the ordinary published-family/asset-authority journey.

**Secondary rotation bake — E7 experiment.** The braid uses three cosmetic attachment joints, keeping the pilot at 55 joints. Family `secondaryMotion` rows declare `{part, joint, driver, lagSeconds, maxAngleRadians}`; parameters and rest landmarks belong to the asset. A target joint must carry the matching `secondaryPart` tag, with no core/unrelated-part descendants. After leg/contact fitting, derive its desired world orientation from the actual fitted driver turn and its own rest orientation. Smooth toward it by shortest quaternion interpolation with `1-exp(-dt/lagSeconds)`, clamp angular lag to `maxAngleRadians`, then write the parent-relative keys. Process parents before children from immutable fitted inputs. Loops use eight bounded warm-up cycles over unique samples and repeat the initial secondary orientation at the end; nonloops start at the first desired pose. Apply only active parts. Covered and dressed companions share core/contact fitting, then bake separately for each distinct active-rule set; another garment's secondary joint may drive visible hair. This is an authored visual follow-through rule, not physical cloth simulation. Source compilation may expand only explicitly declared, rest-only attachment joints; unknown ordinary source joints remain failures. Compare the Python/browser bake and actual braid coverage before promotion. Motion setup invalidates on actual sole-probe coordinates and active secondary parts as well as rest changes; playback remains ordinary skinning.

**Age/material preview — E2/E4 experiment.** Baked exports carry one resolved skin finish. The later preview may blend only the two bracketing age samples at a time, with linear colour and renormalized tangent normals, applying the same palette/mark masks as the baker. Use shared immutable maps and private uniforms. Compile preview-resolution maps inside the existing texture/residency budget; compare against the baked reference at matching resolution and then against the full accepted export. Load an adjacent age pair on crossing a knot, retaining only current/pending references; stale loads cannot overwrite a newer age. Count pending maps and other resident textures in the same budget; release obsolete maps before loading if overlap would exceed it. Do not preload every face × age × skin combination. Keep the preview in a preparing state until the requested pair/geometry is ready; Save requires the exact requested appearance, not a previous-age texture. If this measured route cannot preserve quality/cost, do not silently replace age with a few fixed presets: retain offline recipe authoring and report the live gate unmet.

PlayCanvas 2.22.2 is pinned here. Mesh definitions, textures and clip data can be shared. Per-person joint palettes, morph weights, fitted bind data and reveal/hover replicas require explicit lifetimes. The existing hover and reveal paths assign morph instances between meshes. The [V3D05 gate](../maintainers/3d-pixel-art.md#v3d05--rigged-character-and-equipment-family) requires independent morph-instance ownership through replacement and teardown before morphing GLBs enter play. Baked proof exports can omit morph targets. Reuse the existing renderer resource/permission lifecycle. Check a dressed and a distinct neighboring body through hover, reveal, replacement, cancelled loads, permission revocation mid-load and destruction. One shared pose does not merge a draw call per material or remove shadow passes. Compare actual device work before choosing batching. [Current world presentation](../world-presentation.md#animated-characters).

Same-rest equipment fitting replaces animation tracks within the existing gait graph when its stride names, speeds, durations and available strike clips agree. Preserve clip clocks, blend weights and an active crossfade; evaluate replacement snapshots at the same time even while paused. The pinned engine patch addresses individual animation leaves and their fading history, rather than replacing the containing Move state. Synchronized stride speeds update throughout crossfades; zero-weight synchronized clips advance only their clocks, without evaluating curves or dispatching hidden events. Align the event cursor once when such a clip becomes visible. Held actions keep their existing clock semantics. Reassignment must restore the manually driven animation clock. A new rest/skeleton and the creator's deliberate upright fitting pose retain their existing reset boundary. Qualify mixed strides and start/stop transitions separately: individual floor-safe clips do not guarantee floor-safe quaternion blends.

**Saved appearance.** For playable assembly add a sparse wearer-to-recipe collection to [WorldState](../../packages/domain/src/types.ts), outside both observed entities and the shared presentation definitions. Register it as a keyed collection in the [current save record layout](../../apps/server/src/world-record-schema.ts) so editing one person writes one entry. Store only resolved body/face/hair/coverage/material choices and their exact source references there. Consume `initialOutfit` during authorized creation; omit it and private `concept`/generation provenance from the saved visual recipe. Worn garment definitions come from actual equipment placement. Keep private provenance in the asset library. The existing [sensory fingerprint](../../packages/domain/src/perception-frame.ts) uses `entity.appearance`, and [character context](../../apps/server/src/context.ts) copies observed self data. Never put recipe IDs, slider values or revision tokens in that string, on the observed entity or in model input. Use a separate cosmetic seed when drawing a population so appearance does not advance the simulation's random sequence. Preserve appearance across a normal reconnect or load. Use the current physical-life reference when installing a late visual result. The existing death/return owner decides which body and equipment survive; never run starting-outfit provisioning on return.

**Equipment and visibility.** At authorized creation resolve the initial-outfit entries through installed item definitions, check the requested ports together, then create and equip the actual lots in the same successful transition. Reject conflicting starters without partial grants. [Lot placement](../../packages/domain/src/objects.ts) owns equip/unequip, transfers and revisions; [equippedItems](../../packages/domain/src/equipment.ts) reads that wearer's direct attachments. Store no second list of worn items. In [projectView](../../apps/server/src/view.ts), resolve visible parts only after subject visibility is granted. Use the existing per-viewer entity cache with dependencies for that person's appearance and visible outfit. Send an optional display payload through [EntityView and GamePatch](../../packages/protocol/src/index.ts). Include only the controls or resolved geometry/material refs needed to draw visible parts, and omit hidden equipment identities, source recipes and inventory. The renderer accepts these views; it never supplies equipment authority.

**Commit and restore.** The player creator edits a new person the world permits that player to create. Editing an established resident uses an explicit creator grant; taking control of an existing body grants no power to redesign it. On submission the server checks the subject, expected current revision, installed family/parts and supported bounds and commits the complete recipe once. Resolve the current-format save with the existing save/load owners and exact release pins. Reject incompatible state. A temporary render failure gets an authorized visual fallback. The [asset authority](../asset-workflow.md) owns access to restricted sources and publication. The pilot needs no new game save format, migration, remote fitting service or paid inference in play.

For integration, add the narrow trusted recipe contract in `packages/domain/src/appearance.ts`, exporting its public types through the package entry point, rather than adding fields on `Entity` or `Actor`. The world-selected profile chooses the family/presets; generic validation checks its declared controls, not a hard-coded human slider enum. Add `appearanceRecipes` as a sparse world collection keyed by wearer identity, with the owning physical-life reference, recipe revision and resolved recipe; register it with the current record codec and validation. The creation/edit mutation owns recipe changes, expected revision, dependent physical stature admission where requested and projection invalidation together. The server view resolves only the current permitted wearer and visible equipped parts by exact identity. Add that wearer's appearance revision and visible outfit dependencies to its existing view-cache key; a cosmetic edit does not invalidate every person or schedule cognition. Client assets/materials remain derived and disposable. Follow the current no-compatibility development policy; no migrations, old recipe aliases or parallel schema formats.

Appearance age never rewrites birth/history or grants age knowledge to observers. Hair/face/build controls do not change the existing sensory description, perception events, personal memories or AI candidates. A later intentional visible-description feature needs its own perception/cognition design and evidence; it cannot be smuggled into a renderer patch. For E5 use the same actor/observer context builders and perception owner, comparing complete permitted inputs and native events, not just fixture summaries. Native input parity is not evidence of identical stochastic model responses.
