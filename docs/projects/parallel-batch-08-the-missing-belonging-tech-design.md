## MY02 — Precise personal evidence through existing records

### Recording and interpretation

`EncounterExposure` already stores exact item ID, definition pin, label and description; its owning `Awareness` supplies observer, event/source, acquisition, time and sequence. Use these existing authoritative snapshots rather than a new `clue`, `case`, `truth`, `solved` or `witnessAnswer` store. Current live item facts still belong to object/placement owners.

The concrete missing fact is where the inspected item was encountered when that place is permitted and relevant. Extend the existing inventory-item exposure with an optional typed **observed location** only when inspection genuinely establishes it: exact supported world point and source-safe label for the inspected accessible ground container/site, or an explicit carried-possession description without a hidden holder's location. Snapshot this at the admitted inspection boundary from current placement/access, not from a later live lookup. A nested bag inspection refers to the accessible containing site only when the complete ancestor path is currently permitted. Do not resolve unseen ancestors or infer an actor's live position from custody. Point units and surface identity follow the spatial owner.

For reading a note, preserve the exact admitted inscription as attributed document text inside the existing inspected-description snapshot. The observation establishes that those words were read. It does not establish that their asserted relocation occurred. The base-world description must retain that attribution; common rendering must not strip it. No NLP extraction into authoritative assertions, automatic theorem checker or typed universal fact graph is needed.

Record only actual admitted observations. History browsing and comparison do not inspect an object again. `recordInspectedItems` already records each admitted page; introduction keys separately identify narration novelty. Preserve that distinction: a repeated observation may be truthful while needing no new introduction. Carry the newly recorded location through the existing path without making narration novelty suppress a materially changed item or location. Preserve immutable earlier evidence and normal admission/retention. A changed clue must not silently rewrite a prior observation.

Speech already has listener-specific perceived wording and attribution. A resident's account is a heard experience for the listener, even when it describes a past observation. Ordinary knowledge notes may contain inference, uncertainty or false belief; their text and source links are not native world facts. Do not convert a listener's canonical source IDs into recognition, add a private witness pad to a shared event, or copy one observer's evidence to another.

### Exact detail and source comparison

Extend the existing scoped perceived-history read/projection with an exact detail request for an eligible retained encounter or utterance. References carry the complete owning key and current source revision: world/timeline, actor, record family and source ID. Application-issued references are opaque to the client; a globally unique-looking event ID alone never proves permission. Two selected sources are fetched together under one consistent actor-scoped read, with indexed exact lookup and shared authorization/preparation.

The result contains only permitted recorded text, acquisition, event-time source label/recognition, time/order, and any permitted recorded observed location. Include correction/unavailable coverage from existing owners. Never include raw world-event payloads, authored solution data, current hidden location, another actor's mind, current name learned after the old observation, or an actionable hidden entity reference. A currently recognized visible subject may have separate ordinary controls through current inspection; the historical reference itself cannot target a command.

Fences include authenticated control, world/restore generation and evidence/privacy revision. Recheck them after each awaited/cached result and immediately before disclosure. Correction, forgetting, access loss or restore invalidates held selections and late reads. A removed live object does not invalidate an otherwise retained historical account; a revoked source does. No raw-event fallback is permitted when a perspective is unavailable.

**Acceptance:** two observers read different source details; a document's claim stays attributed; a moved bag retains its old observed location but reveals no new one; second inspection can record a new permitted location; same-name/separator-containing IDs cannot collide; source correction/forgetting races refuse stale reads. A materially different ordinary case—inspecting a cooking ingredient, moving it, and later comparing that observation with heard speech—uses the same path without mystery content or actor-name checks.

## MY04 — Compare sources without receiving a hidden answer

World Events remains the entrypoint. Add a source-detail affordance to eligible encounter/speech rows and **Compare sources** to select a first and second record, including records from different search pages. Use a two-slot local selection of full server-issued references. This is presentation state, not saved actor knowledge or a new journal. Leaving the panel may retain the selection within the mounted scoped panel; changing actor/world/timeline clears it. No private text or selection reference goes into a shareable URL.

Each selected record shows its acquisition/source/time and full permitted account. Two columns when readable, stacked sections on narrow/short layouts; the same source and action order persists. Show explicit **Choose another source**, **Remove**, **Back to source** and **Close comparison** controls. Reuse existing history pagination/search and shared React Aria controls; do not fork World Events into a mystery-only evidence browser. Preserve its query, scroll anchor, prior reading position and ordinary Talk drafts.

Comparison does no model work and records no new awareness. It draws no conclusion. Source labels distinguish an inspection of a written account from witnessing its claimed event. A historical point is labeled **Observed here then**, with time, and is not a tracker or hidden-location action. Known places continues to require the ordinary actual place observation.

Pending detail requests preserve safe visible content with truthful loading. A source correction refreshes/qualifies the account; revocation replaces it with an unavailable state without repeating removed text. Reject late detail results after scope or evidence changes. Keyboard/focus, enlarged text, selection/copy, IME typing and Escape cannot trigger movement, inventory changes or message submission. Existing maximum history page/search windows apply; two comparison slots limit only simultaneous display, not retained evidence or accessible search results.

**Acceptance:** complete investigation through ordinary controls at desktop and narrow/short enlarged layouts; compare exact inspected note with heard suspicion; choose a source on an older page; recover from correction, access loss, partial search and failed detail load; resume the same conversation draft. No god mode, developer tools, hidden map labels or extra AI service is required for the player journey.

### Performance design

The recurring costs already come from ordinary residents, perception and conversation. No new simulation tick scans the incident, clues, all characters or their histories. Inspection runs only for the selected accessible object and actual container ancestry. Comparison runs only on explicit opening/source change or relevant invalidation; indexed exact source selection precedes hydration. Existing actor-scoped search windows and continuation remain the only broad discovery route.

Record the four planning answers before runtime changes:

| Question                             | Selected design                                                                                                                                                                                                                                                           |

| What grows?                          | Actor-perceived history, documents/subjects, inspection occurrences, visible nearby people, incoming conversation, nested container ancestry and pending reads; two displayed records do not bound all upstream work.                                                     |

There is no new count cap or permanent copy of selected history. Use existing page/request/native-work admission and return explicit incomplete/unavailable results.
