## 1. Selected architecture and current baseline

Use one authoritative in-memory world and one ordered direct PostgreSQL writer. Record only admitted experience. Keep immutable shared **substantial/stable** received values, inline small changing values, append personal history in explicit batches, and delete obsolete storage asynchronously. Keep existing semantic owners, command receipts, snapshot isolation, private-read fencing and paid-operation records. Remove the custom second durable application stage and storage layout state hidden on domain objects.

The installed [contact/group model](attention-and-scenes-runtime-design.md#13-proposed-structural-replacement-contacts-and-grouped-receipts) supplies native contact ownership, grouped checks and derived attention preparation. Adopt that model, not its minimal bulk-only or log-only alternatives. SR08/SR09 own those native conversions and SR10 their derived-state removal; BK integrates their storage once. The earlier segmented shared-value store, journal and accepted/applied fences are removed; the current writer and captured read projection are the sole persistence path. Its reception, selection, correction and current-default guarantees remain unchanged.

```mermaid
flowchart LR
  I[Client intentions / native due work] --> W[Server world mutation owner]
  W --> V[Permitted live client updates]
  W --> D[Dirty current records + admitted history suffix]
  D --> T[One direct SQL transaction]
  T --> DB[Canonical tables and receipts]
  DB --> C[Bounded cold reads and checkpoints]
  DB --> G[Small background deletion batches]
  W --> K[Finite permitted cognition input]
  K --> R[Optional model work]
  R --> W
```

Ordinary native/player/NPC gameplay publishes its complete in-memory transition before the scheduled save. Protected effects retain their durable barrier. Cognition runs outside mutation ownership, waits for the fixed evidence cut required by paid dispatch and returns a proposal.

The preview defect was an internal incomplete-save inspection, not a player-facing preview: preparing candidate records could bind physical segment boundaries or positions to live objects before completeness was refused. For example, a previously saved two-entry prefix plus one appended entry could be regrouped as a single three-entry segment; the later real save reused that dry-run layout. The existing narrow fix makes that path read-only. The target removes the underlying hidden placement dependency, so an inspection has nothing to install. This describes a demonstrated coupling, not evidence that players lost data.

## 3. Runtime representation

### 3.1 Current truth and current personal state

[PP08’s common receiving procedure](perspective-perception-runtime-design.md) owns channel-neutral sample/confirmation/availability/occurrence mutation through these contacts. BK executes the same SR08/SR09 representation and lifecycle conversion; it does not add a parallel sensor or receipt store.

The actual entity owns its latest physical position. A personal contact owns the last actually received pose, original measurement times, current availability and sparse field exceptions. The existing two compatible samples suffice for immediate motion queries; longer paths belong only to admitted recent history. An appearance observation can remain older than pose. Availability can change without changing the last measured value. One support change can affect several fields without writing separate loss events.

Use contact-owned received groups with immutable `received` content and typed part-partition metadata. Successful checks, recording and availability change metadata without replacing content. Partial coverage splits only affected metadata; a body's original acquisition pose remains evidence while independently acquired location owns its newer pose. The current codec saves content independently of clock partitions. Native correspondence, body, recognition and attention borrow selected values synchronously; explicit evidence consumers materialize proof through that same owner. [BK17 mechanics](bookkeeping-simplification-reception-design.md#31-stable-content-clocks-and-member-identity) define identity, masks and codec guarantees.

Keep minimal meaningful attention state—selection order, discovery progress, acknowledged versions, displacement anchors, cue expiry and partial scan cursors—but rebuild scores, candidate views, formatted descriptions and relation-dirty work at activation. Optional descriptive novelty uses a compact non-security content label; exact evidence, identity, permissions and correction never use that label. Producers supply actually received geometry changes to relation invalidation, so a numeric detail update need not restart spatial work. Those derived candidates are not persisted mirrors. Recovery preserves the same selection without taking a new sample or crediting familiarity again. Existing changed-key persistent collections prevent one contact update from copying every contact of an observer.

Continue existing isolated native drafts and structural sharing. Change only touched contact/feature records and seal completed values once at the owning transition. Do not copy every actor’s field map, iterate old history, or rebuild root entity lists to discover these changes. Exact maintained membership/count queries and established dirty-key lineage remain useful derived tooling. This project removes hidden **storage placement** caches, not every immutable memoization or spatial index.

### 3.2 Inline values and shared values

The native value owner supplies the representation for supported facets:

- **Inline:** pose/location scalars, small support/availability states and small numeric/categorical changes; one receiver frame in the personal frame header. Keep exact representation/precision, not rounded text. A differently received uncertain location remains different from an exact pose.
- **Shared immutable value:** stable body/detail bundles, descriptions, larger received geometry and similarly substantial typed values. Different clipping, field availability or precision creates a distinct variant. Reuse only a compatible value still owned by current or retained evidence; a process cache of old addresses is insufficient.
- **Existing occurrence source:** exact received speech, interactions and action-result families continue using their existing event/account source owners. Do not copy them into a second universal event store or replace a personal account with the global event.

Replace block-plus-slot addresses with stable value IDs in the shared-value owner. No mutable array of mixed live/dead payload slots, reused ordinal, per-slot reclamation generation or compaction address rewrite remains. A new variant allocates a new immutable value; an unchanged stable variant can be shared for as long as some real owner retains it. Preparation may cache a neutral value, but an unowned cached value gets a new ID when legitimately acquired again.

Sharing is an optimization of **values**, not occurrences. Two independent observations of an equal body can share bytes while preserving separate actual acquisition/confirmation times. Later recognition does not rename formerly anonymous evidence as if the observer knew the name then. Pose history stays in personal frames even though the same pose can also occur in current state; those have different lifetimes and purposes.

The native value owner always inlines validated body-pose, location, observation-frame and observation-header fragments, even above the ordinary 192-byte small-fragment threshold. Suitable rich stable content remains shared. This single representation policy prevents a valid coordinate sample or its changing proof header from allocating a pooled SQL row; it does not grant reception or retention permission.

### 3.3 Personal frames and chunks

The temporal owner stores ordered **received batches** containing sparse baselines, actual samples, availability/admission boundaries and discrete occurrences. Observer/life/epoch, batch order, entry and stable member indices identify evidence independently of physical placement. Current freshness partitions remain separate from recording admission. Attention entry dates an acquired baseline; subsequent actual changes retain their own clocks and frames. Equal checks update current freshness only. Bounded admission reserves coverage-terminal space; no late-closed value span or predecessor proof chain is stored.

A detached save packs only its new mixed actor suffix into immutable preferred 64 KiB physical blocks. Complete bounded native blocks remain indivisible; compact owner/clock/source/frame metadata makes each received record independently decodable without predecessor seeds. Packing and sparse correction preserve logical addresses and physical predecessor checks. Shared substantial values grant neither another observer's receipt nor private knowledge.

The pending save owns native suffix intent and one immutable in-flight cut. Failure preserves that cut and newer accepted work. Acknowledgement rebases placement onto the existing native tail without rebuilding logical eligibility. Ordered tuple bounds select candidate raw receipts; the actual owned entry/member proves source existence. Current state and finite permitted captures have their separate owners; historical readers do not replay expired events or reconstruct arbitrary old scenes. [Section 15](#15-compact-native-evidence-and-change-history) owns the current layout and lifetimes.

### 3.4 Lasting accounts and exact support

Promoting knowledge or retaining an account creates an independent minimal support record through the existing owner. Examples: the actually understood introduction supporting a learned name; the received position/extent and permitted label supporting a Known place; exact terms of an unresolved promise. Copy small necessary facts and their original provenance, or reference an already shared substantial value. Do not retain the entire recent chunk merely because one fact mattered.

An impression copies its selected claims and bounded provenance spans, explicitly without exact-coordinate/quotation authority. Existing exact summaries retain the complete exact sources they actually need, including transitive correction dependencies; this project does not quietly turn them into impressions. Existing native learned-method/identity rules still decide what constitutes sufficient support. No promotion occurs merely because a chunk is about to expire.

Correction metadata identifies source kind/ID/revision, observer scope and covered acquisition/claim ranges; it need not preserve every discarded raw body. Source-version bodies remain only for real exact consumers. Active obligations retain their admitted support until their owning completion/cancellation rules permit retirement. Required support is not an unlimited pool, and arbitrary `remember` output cannot claim its protection.

## 4. Direct transactional saving

### 4.1 One pending change buffer and one writer

Extend the existing dirty-record and append-intent owners. Keep one accumulating buffer and at most one immutable in-flight batch. A buffer holds changed current records keyed by canonical row identity, explicit removals, ordered admitted history suffixes and required operation receipts. It holds compact record values/changes, not a sequence of complete world roots.

For current state, a later unsaved update to the same row replaces its prior pending value. For history and discrete effects, preserve every admitted occurrence/order; only explicitly supersedable operational input may coalesce under its existing contract. A transient current value that was never durable and has no admitted receipt need not be inserted. Deleting a row that exists in the durable baseline remains an explicit delete. Required source corrections and receipt-dependent operations keep their barrier; do not treat them as an ordinary last-write-wins overwrite.

Capture swaps the accumulating buffer, so later changes enter the next buffer. A successful commit advances the durable mark and releases only the captured buffer. Failure never clears newer dirty work. If a newly captured baseline does not match the writer’s predecessor, refuse rather than rediscovering it from arbitrary latest rows. These are ordinary ordered saves, not a second durable journal.

Use one-second save opportunities, one accumulating live prefix and one immutable in-flight save. Five seconds since the oldest unsaved acceptance stops further ordinary admission. The combined pending-work ceiling is 64 MiB, with a 64 KiB emergency-Pause margin inside it; these are operational limits, not world retention policy. The former journal’s 32 MiB debt threshold is removed with that queue, rather than introducing another per-step encoded-debt census. SQL groups retain their encoded byte/row bounds, and an operation that cannot fit its finite pending allowance is refused before ordinary publication or uses its existing explicit durable path. Measure actual prepared bytes and decoded retained buffers separately; one in-flight save is not a universal heap bound. Do not queue multiple full captures or let pending history grow silently.

### 4.2 Routine native progress

1. Apply a coherent native transition and record its actual received evidence through existing semantic owners.
2. Publish its permitted state from server memory at the existing delivery cadence. Queue exact changed records and admitted history for the next save.
3. At the due save opportunity, capture the finite change buffer and release mutation ownership.
4. The ordered writer inserts new shared values, writes current records, appends frame batches/accounts and their reference projections, updates derived durable counters, and advances the single database head in one transaction.
5. After commit, publish the durable mark to existing paid-work/cold-read/checkpoint consumers. Evict only committed inactive records; the in-flight buffer retains unsaved evidence even if it leaves the hot simulation tail.

No ownership query, value cleanup, whole-world record walk or complete retention scan runs before ordinary movement admission. Validation of a newly received value happens at its producer/owner boundary; formatting and SQL preparation use that trusted result.

### 4.3 Ordinary commands and protected results

1. Admit current authority/request identity and recover an identical accepted or durable outcome before preparing another action. Active receipt-reader pins prevent a concurrent cold miss from losing an accepted result to cache eviction.
2. Prepare required cold evidence outside mutation, then recheck exact sources, control and native preconditions in one short turn.
3. Accept and publish the complete ordinary transition and receipt in memory. Fold changed current rows into the pending buffer while retaining ordered admitted occurrences and exact source-version plans.
4. Save one detached prefix with the existing writer. Its final storage checks concern expected revision, writer ownership and current-format integrity; an expired originating session cannot undo already accepted gameplay.

Spending, access/control, explicit privacy settlement, authoring/installation, checkpoints and restore retain their own durable barriers, ordering after preceding accepted play. Correction/editor factories prepare cold dependency/source-version closure outside mutation, then rerun the native operation against the current world; they merge only selected cold residency, reject changed dependencies and commit the complete privacy result. Ordinary publication and protected success are distinct. No automatic paid retry or new model cadence is introduced.

### 4.4 Database authority and recovery

Keep one database world head with current timeline/generation and revision, updated by compare-and-swap in the same transaction as its rows and receipts. Remove accepted/applied dual heads, journal table classification, replay eligibility proofs, journal-alignment overlays, application workers and alignment drains. Captured live reads project RAM deltas onto a recognized durable snapshot; that projection is ephemeral and cannot mutate authority. Derived search coverage has its own legitimate source/index revision and is not removed merely because it also uses revisions.

Use normal durable PostgreSQL commits; do not disable `synchronous_commit`, WAL or filesystem durability to improve timing. If a connection fails around COMMIT, do not execute gameplay again. Stop further writes, establish that the previous writer can no longer commit, then inspect the existing head and exact receipt using the normal store owner. A proved committed batch adopts its recorded outcome; a proved rollback preserves the earlier baseline; uncertainty stays a storage hold. This small recovery distinction prevents duplicate effects and is still needed with zero players. Reuse existing receipt/connection ownership, not a new replay service.

Paid reservations, uncertain provider attempts, authentication/control grants and operational restore records retain their existing durability and non-rewindable owners. A background save or manual gameplay restore cannot refund real spending or restore revoked authority. PostgreSQL handles interrupted **database** transactions; filesystem checkpoint publication and external paid outcomes still require their existing explicit protocols.

## 5. Physical rows, indexes and queries

Reuse current canonical table families and the typed record writer; names below specify required row meanings, not a new generic repository layer. A current-format cutover may rename obsolete tables coherently. No old reader or dual schema remains.

| Row meaning                       | Identity / essential fields                                                                                          | Required access path                                                          |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Shared received value             | World/timeline + immutable value ID; typed payload; encoded bytes; nullable GC-candidate sequence                    | Primary key; partial candidate index                                          |
| Current contact/feature           | Observer/life + local subject/feature; compact current fields and inline pose; shared IDs; independent times/support | Exact actor/local key; actor owner scan at restore                            |
| Immutable recent block            | Actor/life/epoch + physical ID; mixed batches, used-part seeds and exact charge directory                            | Actor/received tuple, actor/time and bounded-bucket GIN with exact postchecks |
| Shared-value use                  | World/timeline + owner kind/ID + value ID                                                                            | Unique owner/value key; reverse value-ID index; FK to value                   |
| Personal lasting/required account | Existing source/account identity, permitted body and minimum support                                                 | Existing actor/source, eligibility and correction indexes                     |
| Source dependency                 | Existing exact source/derived owner relationship                                                                     | Source-kind/ID/revision + actor-scoped reverse lookup                         |

The shared-value use table is a **derived transactional projection of real owner fields**, not separately writable knowledge. Closed owner kinds are current contact/feature, recent page and retained exact-support/account owners. Reuse the canonical reference extractor for writes, current-format validation and capture. A polymorphic owner link needs exact owner-kind validation; do not pretend a foreign key to the value proves the owner exists. Delete owner links in the same transaction as owner removal. Startup/capture integrity verifies both directions once, not on every tick.

For a current contact, update use rows only when its shared IDs change; pose/freshness-only updates leave them alone. A recent page owns each distinct direct value once, inserted in bounded bulk with a unique owner/value key. Independently retained support owns its own closure, so retiring a page releases only that page's uses. Keep the selected/resident reference closure rather than mirroring cold ownership into JavaScript. Occurrence-survival queries reuse the 16,384-bucket GIN candidate index and exact source/person postchecks under actor/live-parent/removal fences; hash collisions grant no survival proof.

New values and their first owners commit together. Writes insert values before uses; removes delete/repoint uses before deleting a value. Ordinary updates use the existing bounded typed SQL grouping, parameter limits and one atomic transaction, not one statement per observer. Stable explicit keys eliminate list renumbering where order has no meaning. Ordered personal evidence retains its original order.

Cold queries select actor, lifetime, time/order, subject and eligible source metadata **before** loading JSON or expanding reference arrays. Existing candidate filters may be reused if their exact postcheck and measured plans remain sound; do not add redundant full-value GIN indexes. A page containing one desired source must not expand all unrelated sources before filtering. Query projections need only fields consumed by the caller. Current truth uses active indexes/counts rather than rebuilding entity arrays merely to count them.

Do not require every observation to be a SQL row. Immutable pages amortize exact samples across each save suffix without rewriting prior pages. Scalar and selection projections come from the same encoder; canonical payloads omit duplicate derived membership/reference arrays. SQL row/index/TOAST costs are measured separately from personal logical charges.

## 6. Expiry, forgetting and physical cleanup

### 6.1 Logical eligibility and accounting

The native temporal actor enforces world-owned age/count/byte rules by retiring whole optional native blocks at their oldest-record age boundary or prefix pressure. Its bounded directory holds block totals and derived individual membership, rebuilt from complete eligible metadata at activation/restore. No per-member closure ledger remains. Ordinary expiry reads no SQL, writes no per-page retirement marker and never expires current knowledge. Increasing an allowance cannot revive retired blocks; younger optional neighbors can disappear early.

Raw, pending, story, player/model, editor and cold readers apply eligibility before disclosure. A block-range or dependency-alias match only selects candidates; exact source existence requires its actual owned entry/member. Sparse correction/forgetting may remove individual fields without renumbering unrelated acquisitions, independently of whole-block expiry. Save/load compare complete current-format counters. Finite already permitted copies survive ordinary expiry, while explicit source/privacy withdrawal still fences affected output and current actions recheck current authority.

Expiry releases block charges and returns only affected local-individual candidates for pruning. Wholly ineligible physical blocks are collected behind the durable frontier with their value-use and story-access projections; a partly live physical block retains bounded inaccessible slack. Pending/in-flight references remain protected. Lasting-account maintenance stays separate: one query family per account table batches selected actors, deduplicates before hydration and preserves each actor's 64-account/4 MiB preparation limits and world-owned ranking. [Section 15](#bounded-saving-and-ownership) owns current accounting and failure handling.

### 6.2 One background collector

Reuse the existing maintenance scheduler and ordered database writer. There is no collector on command admission, no per-field database check, and no second writer allowed to race canonical ownership.

1. Wake when expiry is due or an owner releases values. Coalesce ordinary notifications over five real seconds; after a nonempty bounded slice, wait at least 250 ms before another opportunity while debt remains. One SQL transaction handles both candidate kinds, alternating priority so oversized pages cannot starve values. Startup can reconstruct outstanding work from persisted cutoffs and candidate rows.
2. Select the oldest wholly ineligible block/account rows using durable frontier metadata. Delete a bounded group and its use rows in one short transaction. Retain currently eligible partial pages.
3. When use rows disappear, mark their distinct value IDs with a nullable **candidate sequence**, in the same transaction. This is only an indexed hint that a whole value might now be unowned, not a pending-delete state machine or reference count. Repeated hints coalesce.
4. Select a bounded set of marked values. One indexed `NOT EXISTS` check against the reverse use index determines which have no owner. Delete those whole rows; clear the hint on still-owned values. No payload decode, slot compaction or traversal of every containing page is needed.
5. Release committed cold payloads from process caches independently of physical deletion. Only actual resident current/tail owners and in-flight writes require RAM; cold SQL ownership does not require resident bodies.

Examine at most 128 candidates of each kind; select at most 256 combined owner/value candidates and 256 KiB of selected encoded bodies per slice, reusing smaller applicable repository/statement limits. Count dependent use-row work too. Whole oversized admitted records/pages are processed alone. Never load a huge body just to decide whether its ID has a use. At most one cleanup slice is queued; give overdue cleanup one turn between foreground write batches through the existing fair scheduler, rather than waiting for complete idleness or draining an unlimited backlog ahead of a command. End each slice before scheduling another.

Keep physical storage/backlog metrics and existing operational storage-failure/backpressure controls. There is no separate gameplay admission check over all candidate bytes per movement command. These bounds limit each pass, not total physical debt: if cleanup cannot keep up, disk can grow despite bounded logical memory. Sustained debt and physical/index reuse are required operating acceptance, and failure blocks release; it is not permission to hide the growth by deleting required records. Storage exhaustion/failure stops authority explicitly. Do not claim a universal disk bound from an age window.

### 6.3 Why unsaved work and reads are safe without pins

The required invariant is: **every reference admitted after a durable cut either names a newly allocated value retained by that pending write, or derives from a still-eligible real owner.** Payload-address caches alone are never owners. This removes the need for a second pending/cold ownership census.

- If the owner exists in the durable cut, its use row protects the value while new pending owners are created. If a captured save releases that last durable use before a newer accepted owner reaches disk, the collector excludes live/pending legitimate owners until their own ordered settlement. No payload cache gains ownership from this exclusion.
- If the value was created after the durable cut, it has a new ID and is held in the pending buffer; cleanup cannot select an uncommitted row. Its first database insertion includes its real owners.
- If the last owner has actually expired/been removed, neither a held ID nor a weak cache can create a new reference. A new physical acquisition creates a new value/owner; a stale recall or promotion fails current eligibility.
- A cold reader selects the owner and its values in one bounded repeatable-read transaction, then copies the permitted finite closure and releases the transaction. PostgreSQL preserves that snapshot while concurrent deletion completes. There is no later fetch by naked payload ID outside the read scope. Publication still rechecks current expiry, correction and authority.

A temporary model/capture copy is independent bytes, not a storage pin or a retention extension. Future code must use the existing owning read/receipt admission API, never a raw `getValue(id)` that grants evidence or a cleanup exemption. Verify release/reacquisition, delayed cold read and in-flight save cases explicitly before removing the old guards.

### 6.4 Correction, explicit forgetting and source versions

Semantic correction/forgetting keeps the existing strict atomic owner. Select affected owner IDs through the source dependency index, load only their bounded records, and revoke/rewrite actual affected facts and derived sources together. For rare edits inside a page, replace that bounded page while preserving stable surviving acquisition identities; recompute its uses from the selected contents. Do not repack the entire history or weaken source-specific deletion into “drop everything nearby.” The correction owner’s existing whole affected-operation admission remains controlling when the transitive dependency set is large.

The existing operational privacy ledger retains actor-scoped forgotten IDs and correction links across gameplay and operational restoration. Reapply exclusions through the native experience owner without importing unavailable later correcting text; ordinary expiry is not explicit erasure. Old source-version bodies and derived vectors/text leave access immediately, then physical cleanup follows their current privacy obligations. For a shared value still needed by another observer, remove the requesting observer’s uses/accounts rather than deleting the other person’s evidence. Correction of the source itself reaches all actually affected owners through existing exact dependencies. Current operational privacy overlays continue to constrain checkpoints and provider-context reuse.

## 7. Reads, cognition, capture and restore

### Live and cold reads

Current gameplay/projection reads use the captured server state and existing permitted selectors. Ordinary display does not force persistence. For a history request spanning hot and cold evidence, select the bounded pending/hot suffix at the request’s acquisition cut, read eligible durable history up to that same cut, and merge by stable actor/life/acquisition identity. Duplicate overlap is removed; no generic whole-database pending overlay is introduced. Correction/forgetting and timeline/authority changes fence the entire read after waits. Expiry is checked again at publication, not only when selecting rows.

A request requiring a fully durable cut uses the existing `WorldService.whenDurable()`/durable-mark boundary, outside the mutation turn where possible. A paid decision may wait for its required trigger to be durable without delaying native movement or requiring a private evidence save of its own. Optional indexes can lag; their existing source/coverage checks remain. Search index coverage is distinct from the removed query-table application stage.

### Finite model inputs

Build context from selected current facts, relevant chronological changes, independent physical context, required evidence and selected memories. Reuse the existing materializer and `experience-context` projection; no internal artwork ID, storage use row, physical batch position or full raw body goes into the prompt merely because it exists in SQL. Labels, exact understood words, relative geometry and useful appearance remain when selected and permitted.

Keep current broad/static/discovery allowances and legitimate familiarity, rather than sorting an unbounded whole-world set first. No background sixteen-source sampler, personality/object whitelist, per-step semantic call or hidden global trajectory query is introduced. Source-fragment sharing does not replace exact observer receipts. A request holds a bounded selected copy, no old world root or database transaction during provider work. Late acceptance follows existing source, authority, spending and action-precondition owners.

### Pure capture and validation

Separate three operations: **describe/capture** returns explicit records from a selected complete cut; **validate** returns a result without mutation; **commit** installs rows and advances durable state. Reuse field codecs and validators across them, not a mutating save planner with flags such as “don’t bind this time.” Pure memoization is allowed only where it cannot change later write placement or authority.

A manual checkpoint first saves the required live prefix, then establishes one read-only database snapshot and streams all current/cold canonical owners plus exact dependencies through the existing checkpoint owner. This is an occasional complete operation, not a per-step full scan. Invalid/incomplete candidates fail without touching the live world, cursor, dirty buffer, cache layout or baseline. Check both refusal and subsequent ordinary save.

Same-format loading reconstructs IDs before links, validates references and complete counters once at the owning boundary, rebuilds transient indexes and resumes under existing pause/control policy. It never regenerates past model outcomes. Restore preserves current operational permissions/accounting/erasure, abandons stale work and gives clients a new baseline. Restoration replaces the complete recent-history rows, including physically retained retired chunks, inside its atomic transaction; it cannot leave newer batches attached to a restored prefix. Manual save files retain atomic publication and their existing catalog/retention; a checkpoint is self-contained, so deleting active database history does not break an existing complete file. Existing privacy transforms still govern loading that file.

## 8. Performance model and extension rules

The important dimensions are active entities, actual observer/source pairs, acquired changes, unique shared variants, retained personal history, and concurrent readers/commands. Hundreds of real observers receiving a changed source entails real receiver work; no index makes their distinct receipts free. Ten years of encounters must not become a ten-year hot ownership map or a per-tick scan.

An object existing or moving does not require a new autobiographical/world-history row for every possible observer. Preserve the existing common recording admission before constructing optional occurrence wrappers. Shared received history contains only real retained uses, not a permanent objective trajectory archive. Independently retained world events, checkpoint files, exact command receipts and operational accounting have their own retention owners; bounded personal memory does not prove those totals bounded. Remove obsolete optional sensory source closure through those owners, but never delete required receipts/accounting or silently reduce their retention to make this project look small.

| Path                 | Work allowed                                                                                   | Work removed                                                                                   |
| -------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Native update        | Changed/due physical scopes and real recipients; cheap current updates; admitted frame appends | SQL ownership reads, all-history traversal, eager rich materialization and layout planning     |
| Routine save         | Distinct dirty current rows + new retained frames/values/uses; one direct commit               | Journal encode/write/apply, duplicate heads, full-prefix rewrite, separate ownership mirrors   |
| Cold recall          | Actor/source/time-index selection, bounded chosen batches and closure                          | Payload-first filtering, per-source sequential queries, global source-history reconstruction   |
| Expiry               | Due actor/chunk metadata and bounded deletion slices                                           | Per-facet loss/retirement records, command-path cleanup, partial shared-block compaction       |
| Full checkpoint/load | Complete canonical state streamed or validated once                                            | Codec mutation by preview, replay of effects, duplicate validation of unchanged installed data |

Keep only indexes with real readers: exact identity, actor/time/order, source correction and reverse shared-value uses. Measure their write cost and repeated delete/vacuum reuse. Batching reduces statement and row overhead but does not remove bytes, WAL, CPU or database contention. Native and SQL work are asynchronous only where the ownership contract permits; `async` syntax does not offload CPU. No extra worker or service is selected. Reconsider CPU offload only after measurements isolate substantial remaining encoding work and account for transfer/queue cost.

New sense/mechanic adapters provide exact typed value, original source/reception metadata, stable facet equality and required support through existing owners. The common value owner supplies its inline/shared representation rule. New retained record owners expose reference/metadata extraction once to the same writer and validator. They do not add a parallel retention service, branch on named game situations or expand raw shared values directly into prompts.

## 16. Proposed native execution and current-read reduction

### Diagnosis and candidate selection

Removing encounters and animal actions together cuts main CPU/game by roughly two-thirds in two groups, with changed animal/alarm state. This is a coupled upper bound, not an achievable optimization forecast. Native ordinary-reception suppression, optional-history removal, current-row SQL suppression and slower sight do not independently reproduce it. The valid trace identifies proxy traversal, current-field navigation and publication alongside actual native work. A broad history/SQL rewrite or another cadence change is therefore not the first response.

### A1 — keep controller wake-ups separate from physical invalidation

`AnimalWorkQueue.nextChoiceAt` and `advanceWorldNative` already limit execution through `privateReviewAt`, independently of the cached mechanical forecast. `nativeInterval` nevertheless inserts `animal.foraging.reviewAt` as a forecast-ending `foraging-review`; the foraging review path then unconditionally calls `discardMechanics('foraging-review')`. The baseline has 1,040 foraging-review ending causes and 1,540 endpoint discards in 2,162 forecasts. Animal-action suppression leaves only 300 forecasts. These are work counts, not CPU shares; a standalone status-rule removal has only a small uncertain effect.

Reuse that existing private wake path. Remove only the duplicate foraging-review **mechanical expiration**, retaining actual work end, movement/collision, attribute/status thresholds, acoustic/danger expiry and every other physical/effect boundary. At the exact due review, capture the change cursor, events, allocations and manifest **before settling earned pending values**, then settle through the existing owner and run the review against reacquired actor references. The guard spans both settlement and review: rate settlement can itself emit a body/status effect even if the review returns no intention. Reuse the existing observation-materialization proof where applicable; do not compare only the review’s writes. A deadline-only renewal leaves the unrelated forecast valid. Actual local body/action/attribute changes use the existing `localizeState` classification; events, allocation, foreign/coupled/reactive effects, unknown coverage or manifest changes retain conservative invalidation. Reacquire actor references after an actual successor. Do not use controller metadata equality to certify physical truth, skip an action effect, delay the review or predict an unreceived target.

Continue using `nextChoiceAt`’s strictly-future result: a declined feed review can leave its clock already due, so re-inserting that past deadline would create a zero-duration spin. `choiceIds` and actual work/arrival boundaries still select supported active work; pending navigation retains its current suspension behavior. No new calendar, cached eligibility witness or saved deadline field is needed. Saved review clocks and existing continuation rules remain canonical; cold restoration rebuilds preparation and lands on the same due instants. The E2 broad animal-eligibility witness remains rejected. This experiment instead removes duplicate scheduling authority over the same due review.

### A2 — complete one visual acquisition once

`updateEncounters` calls `reconcileVisualEvidence` for broad and detail with `deferCompletion`, then `finishVisualReception`. Each reconciliation still opens/closes `withCurrentPerceptionBatch`; its finalizer can run attended reconciliation and seal contacts despite deferred inner completion. Thus broad and detail can repeatedly prepare entry tracks/sets, close/seal current state and reconcile temporal state in one unchanged physical cut.

Extend the existing receiving/current batch owner with a lazy scoped lifetime spanning **broad reception → final selection → selected detail → finish**. Use the same pending-contact overlay and existing temporal acquisition, not another current store. The scope opens only when actual current work begins. Reads during selection see the accepted broad prefix through that overlay; detail cannot retroactively affect that selection. Distinct received transitions still carry actual time/order and independently changed parts. Coalesce publication work, never erase a change followed by its reversal or merge independent occurrences.

Open after contact-episode updates and place `acquireExposure` events; close before changed-being notices, `reconcileCombatSight` and `encounter.flush`, which can create actual effects/occurrences. The current `confirm` handler can call `captureTemporalCurrent` immediately: an outer wrapper alone does not remove that work. Move only duplicate same-cut capture into the existing accumulated delta while preserving real source order, outgoing/incoming selected tracks and terminal reservations.

For siblings acquired together, add a subject patch to the same receiving owner: one admitted observer/channel/exposure and complete ordered changed-field/checked-scope set. Resolve channel/correspondence once, apply actual parts through existing setters, and union dirty keys once. Independent channels, times and occurrences remain separate. Delete the per-field re-entry into channel/address/history hooks for that patch; do not keep both paths as writable authorities.

Finalize once at the observer's actual end: reconcile affected derived attention membership and finish actual attended capture/terminal/recording-mark updates **against the pending contact overlay**, then seal/install changed contacts once and publish the owner. Installing contacts before recording marks would reopen and reseal them, defeating the removal. Do not restore global reranking during history recording. A technical cooperative yield is not a new sensory sample. Retain the private native batch across such a yield only under the existing exclusive mutation lane; borrowed read handles do not survive a mutation. Before a physical/rate/required-occurrence effect changes the relevant cut, or before an actual snapshot/publication, flush the accepted prefix and end the scope. Cancellation/error releases preparation and preserves the existing all-or-nothing transition behavior; no half-open batch may escape. A native acoustic/own-effect occurrence keeps its independent causal reception and immediate supported reaction, even while optional visual work is deferred.

If a generator-safe lifetime requires a second transaction manager or can only work by holding a mutable scope across independent mutations, reject that implementation. The fallback is narrower: let broad/detail share existing owned preparation and defer only provably redundant finalization, retaining current prefix flush boundaries.

### A3 — join current reads before rich projection

Extend `prepareCurrentBodyReadScope`, `currentContactNativeFacet` and their current-address owners into one explicit synchronous subject/channel/exposure read handle. It resolves contact identity, eligible channel/life and field-to-group/partition addresses once, memoizing each requested typed value or unavailable/ambiguous result. Known typed addresses do not parse display keys. Scoring/description reads borrow received values; selected geometry asks for its actual independent clock; a proof/support/export request alone resolves acquired originals and expands its required provenance. Keep zero/one/multiple eligible matches unavailable/value/ambiguous. Never choose a hidden identity to resolve ambiguity.

Use the handle in `receivedAttentionSource`, candidate description/location/association preparation, relation anchors and compatible selected presentation. The existing contact/partition indexes and immutable fragment caches remain useful; replace their repeated caller preparation rather than adding a global cache around every accessor. Description-cache reuse currently happens after fetching several sibling fields: test unchanged semantic inputs before rebuilding that input list. Position-only changes must not freshen description, recognition or names. One body scope ending after broad cannot silently be reused after detail mutation.

For player projection, move a complete unchanged-row decision **before** `currentObservedFacetValues` and body/grant preparation, using the actual encoded dependency tuple: body/detail/availability, acquired identity, source/privacy/life, observer frame and represented check times/references. `visualConfirmation.completeThrough` may give meaning to omitted per-field times, and actual confirmation changes may legitimately alter proof references. Do not remove these dependencies. The existing GamePatch/context-action memoization already exists; this is earlier permitted-row reuse, not new transport or lazy action enumeration. Permission/captured-history/asset authorization still rechecks at its existing egress boundary. D's held-view ceiling is about 6.7% conditional, not a promised reuse gain.

Scopes and row caches are derived, bounded by active requested subjects/fields, never persisted. Mutation, yield into independently changing work, permission change or incompatible cut ends reuse. Captured AI input remains a finite immutable permitted copy with current correction/privacy fences; the read handle grants no later action authority.

### A4 — prepare and commit qualified native actions without whole-world forks

The single-route pure-wander fast path already admits in place; do not implement it again. The sampled fork path is generic native admission, including `nativeForagingIntention → executeCommand → executeCommandNative → draftWorld`, followed by another `workingNativeWorld` fork after completion. Multi-route escape has additional tentative-randomness/metadata forks, but `nativeMovementTransition` itself is rare in this trace. Snapshot work is real but bounded: `draftWorld` appears in 2,344 of 83,618 samples inclusive; that is not proof it explains the full interaction.

Split qualified supported admission inside the **existing command owner** into read-only preparation and bounded commit. Preparation returns the affected actor/action/target dependencies, resolved route and all possible refusal decisions; it changes no IDs, events, stock, receipts or RNG. Commit rechecks dependencies and all effect-time permissions/preconditions, settles only actual participants, then applies the validated action through the existing mutation/effect owners in the already-owned native draft. Use it first for the actual foraging movement path. Shared player/NPC command callers consume the same preparation logic; no native-only validation bypass.

An interrupt, transfer, effectful cancellation or other operation that can still refuse after partial mutation is not eligible until its preparation covers that effect. This includes exception-based `WorkBudgetError` / `ResourceReservationError`: admit or bound fallible work/reservation charges before commit, or retain the isolated path. Returning the original pointer cannot undo writes to an in-place draft. Unqualified operations retain their existing isolated draft. For multi-route selection, evaluate admissible routes through the same preparation, calculate a prospective saved RNG successor locally, and commit the draw/selected action together only on success. A failed final admission must preserve IDs/RNG/state/events exactly. Do not add general rollback logs, a second command implementation or a blanket `nativeController` in-place shortcut. After a qualified commit, reconcile its semantic changes once; do not seal/fork the world between consecutive private actions just to report an internal success. Final outward publication, real previews/forks and explicit capture keep isolation.

### B — conditional canonical representation experiment

If joined reads still spend material time navigating mutable group/mask structures, prototype replacing the runtime contact content with **exposure → typed field part → value/source/check-scope reference** directly. Keep original acquired source identities, observer-local correspondence and independent value/check/availability dates. Share immutable received rich values only when acquired content is compatible; observers never share attention, recognition, names or personal receipt authority. Co-checked fields share an actual check stamp; a partial check splits only affected membership. Do not save a mirror group graph or add another authority index. Derived underspecified-field addresses rebuild once after restore.

Acquisition installs the direct fields; unchanged confirmation updates only its existing check scope; change replaces the actual parts and supplies ordered receiving deltas; loss ends only matching exposures and prunes dependent attention. Attention entry captures only then-available baseline, exit ends detailed recording, correction/forgetting revoke matching sources and pending output, and ordinary expiry leaves independent current/learned support alone. Save uses one canonical current codec plus the existing compact recent blocks; restore validates that current format and rebuilds derived addresses. All supported producers/consumers, minimal support, correction and cold restoration must convert together. No legacy reader or incremental dual-format rollout is needed.

Expected work is proportional to requested/changed parts, plus genuine affected observer/subject acquisition; it cannot remove necessary observer × visible-subject work. Dense first exposure still acquires legitimate facts for each observer, but no repeated group discovery or historical proof per native read. Unchanged reads allocate no new field wrapper after their first scoped request. Current space remains proportional to live personal contacts/parts; recent storage remains admitted sparse changes under existing bounds, and lasting support remains independent. Ten years of memory cannot become a lifetime index of transient read handles. These are algorithmic targets, **not measured capacity**. Compare total resident/native/encoded size and finalization cost: duplicating scalar direct slots can outweigh avoided navigation.
