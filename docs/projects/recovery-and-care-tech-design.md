## 1. Deliverable and architecture

A damaging occurrence can create a separately identifiable injury. Its current stage supplies particular mechanical consequences and permitted descriptions until an actual recovery or treatment transition changes it. A kidney injury is a named condition, not the contents of a required torso slot. A torso impact can select it through authored eligibility rules; later precise organ contact can select the same definition without replacing the saved injury model.

Use the existing independent status contribution as the authoritative injury instance. Extend that owner to evaluate the selected numeric consequences and instance-specific stages. Do not create a second writable wound collection and synchronize it with status effects. The domain's current health owner remains responsible for health; current geometry owns impacts; current actions own treatment work; current persistence stores the records. A derived modifier summary is never saved authority.

The reusable runtime owns identity, explicit transitions, supported operations, deterministic selection, current-format validation, time integration, evidence, privacy and exact claims. The selected world owns which bodies can suffer which conditions, what impact descriptions mean, how damage selects severity, how consequences combine, what care does, and every name and explanation. A contrasting world can use a damaged actuator that slows movement until a material repair completes. It must not acquire human organs, medical supplies, bleeding or human mortality by installing the mechanism.

The implementation adds focused modules within `packages/domain`; it needs no new package, ECS, external medical service, actor framework, provider loop, host-time scheduler or generated executable language. A saved participation-time anchor derives injury progress from the existing simulation clock. Installed data selects trusted operation families. Character speech, a model's diagnosis and a renderer's mesh cannot directly create a condition.

## 3. Installed definitions and instance ownership

### 3.1 Definition representation

Extend `StatusEffectDefinition` with optional typed `injury` metadata. An injury definition remains one status definition: its exact definition identity supplies its name, disclosure, stages, effect operations and transition rules. An installed trauma/care policy references these definitions and owns selection tables, compatible body profiles, region mappings and care-method definitions. Keep that policy under the installed body-service boundary rather than a process-global registry. Author the bundled contents once under `packages/domain/src/worlds/base/`; expose them through existing selected-world consumers.

The proposed concrete attachment is `BodyPolicy.injuryCare: InjuryCarePolicy | null`, with `LivingBody.injuryProfileId: string | null` identifying one profile within that installed policy. Null means this family is not installed/applicable, never a fallback human profile. The body initializer supplies the explicit binding; `body.plan`, species spelling and renderer appearance do not select it. Reuse the installed body-policy pin plus existing status definition ID/digest and policy-revision ownership. Do not introduce a second version scheme merely for injuries. Policy/profile replacement updates the body's existing revision/dependencies and checks retained instances and active care before admission.

An injury stage has an ID, severity label, supported operations, treatment compatibility and either no natural transition or one finite transition to another stage/resolution after an authored amount of active simulation time. Make the definition shape a checked union: ordinary status definitions retain their top-level `whileActive`; injury definitions supply their operations within stages instead, and cannot also supply a competing top-level list. One `activeStatusOperations` reader resolves the current instance's actual list. A stage cannot select an arbitrary script. Definition validation rejects unknown operation channels, missing next stages, cyclic natural transitions, contradictory requirements and a selected catalogue entry with no meaningful supported consequence. Permanence means an explicit-removal stage without a natural deadline, not a missing or invalid timer.

The trauma policy defines ordered body-profile/region/damage-kind selection rows and damage bands. Each candidate references an exact injury definition and starting stage plus an authored nonnegative weight. Regions and damage-kind names are selected-world IDs, not universal engine anatomy enums. Candidate rows may require anatomy/applicability tags supplied by the body's installed injury profile. A clockwork body without the kidney tag cannot receive a kidney injury merely because its visual hull resembles a human torso.

The body profile's anatomical tags are applicability data, not independently damageable slots. The profile may map several impact regions to the same condition, and an injury may have no region. Do not introduce per-organ hit points, required limbs, duplicate body coordinates, a global pain meter or a graph of organs to support this slice.

### 3.2 One saved injury instance

The existing `entity.statusEffects[episodeId]` independent contribution gains typed injury metadata. Retain the current contribution definition digest/revision and lifetime owner. The following is a field contract, not a parallel public wire type:

| Field                                  | Meaning                                                                                                                                                                                               |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Existing episode/contribution identity | Unique native identity allocated once through the current ID owner; two injuries with the same definition remain distinct.                                                                            |
| `injury.physicalLife`                  | The injured person's exact physical life at acquisition; it is immutable and checked whenever mechanics or care consume the record.                                                                   |
| `injury.acquiredAt`                    | Simulation time of acquisition, retained for causal history.                                                                                                                                          |
| `injury.stageId`                       | The one current stage within the pinned injury definition.                                                                                                                                            |
| Existing `elapsedSeconds`              | Credited stage progress at the saved `stageClockAt` anchor; current progress is a pure read under §3.4, not a field rewritten every interval.                                                         |
| `injury.stageClockAt`                  | Coordinate in this physical life's shared participation-time basis when the stage/credited progress was installed.                                                                                    |
| `injury.origin`                        | Immutable occurrence/cause ID, initial stage, target-at-impact identity/life, available native source identity/life, impact region if supplied, damage kind, effective damage and actual health loss. |
| Terminal outcome                       | Existing inactive contribution plus resolution/end reason and time; cold history preserves the original identity and cause.                                                                           |

The operative `$subject`, `$source` and `$actionTarget` bindings are the patient for subject-local injury effects. The attacker is historical provenance in `origin`, never an effect-maintaining source. An arrow injury survives the shooter leaving, dying or being removed. A missing historical source is valid; it does not make the patient healthy. Source-sustained lifetimes remain available for their existing mechanics but are not ordinary wounds.

Stage identity already records fresh, stabilized, dressed, supported or convalescing state where the catalogue uses those distinctions. Do not add competing booleans or a copied treatment-history array. Contribution revision changes on semantic stage/stabilization/resolution/lifecycle mutation, not on every elapsed-time increment. Ordinary ticking therefore does not make a just-offered treatment stale. Exact elapsed progress remains saved and current independently of that semantic revision.

Injury definitions are non-occupying, have explicit-removal contribution lifetime and no ordinary activate/deactivate action, automatic activation or voluntary interruption hook. Starting another action, sleeping, Stop or ending the originating attack cannot remove them. Trauma admission creates them; natural/treatment/lifecycle transitions change or end them. Owner editing remains its separately granted operation and goes through the same current-state validator.

No gameplay injury-count cap is added. New damage does not overwrite the last injury of a given type, evict an older condition, or silently merge causes. Grouping identical entries in a panel is presentation only. Stable exact instance IDs support treatment of one particular condition and preserve repeated hits as distinct events.

### 3.3 Reuse without duplicate authority

Factor the existing singleton/contribution lookup into one prepared active-instance reader. Its entries carry instance ID, exact definition, bindings and selected stage operations; read current elapsed progress only when the consumer needs it. Ordinary singleton sleep and existing independent capability restrictions retain their current semantics; injury instances use shared validation, operations, transitions and disclosure where those meanings agree. Injury modifiers and stage timers are not entries in the every-interval numeric rate loop. The selected extension supports subject-local injury modifiers, stage progress and the aggregate symptom consumer. It does not implicitly enable arbitrary independently stacked foreign-target rates, new attribute selectors or a generic effect scripting language.

Trace every consumer of `definition.whileActive`, not only the rate executor: definition/condition validation, native work costing, capability preparation, operation dependency extraction, retained arithmetic validation, stage/pulse boundaries, authoring schemas/metadata and projection all use the checked definition/stage reader. Installation can prepare the maximum supported per-instance stage demand from immutable definitions; actual ongoing accounting distinguishes static modifiers from timed work. A static injury cannot be charged and reevaluated like a numeric rate every interval merely because it shares storage with Sleep.

Do not implement this by making one new status definition per received wound. Definitions are shared immutable content; instances contain the particular stage and origin. Do not attach a second status per injury modifier or bleeding symptom. Operations derive from the one active instance, and ending it removes its own contributions without restoring a historical health/speed snapshot.

The shared refactor is required CARE06 scope: change `statusEffects` to the existing `OrderedRecord<StatusEffectInstance>` representation, updating every current singleton/contribution caller through shared exact lookup/set/update/iteration helpers. Updates replace the exact immutable record through the collection owner so changed-key persistence can observe them. This remains one canonical collection, not a separate injury table. The existing plain map is copied when a singleton changes, and its persistence diff enumerates every member; merely stopping wound timer writes would still visit all wounds during unrelated energy/sleep updates. Use `world-record-schema.ts`'s existing `indexed-map` changed-key path, with `unordered: true` only after establishing the explicit execution order below. Update current-format decoding, historical residency/materialization, validation, cloning and fixtures together, with no old-format adapter. Reuse the existing record structure and database table; do not create another collection implementation.

Storage key order must not change effect/event order. Current singleton arithmetic follows installed-definition order; preserve it. Current independent contribution reconciliation/interruption follows creation/insertion order and can emit ordered events. Retain that meaning with one immutable creation ordinal on each status episode, assigned through the existing shared identity-sequence owner at creation, never a second counter or reconstructed lexical ID order. Validate nonnegative safe integer ordinals, uniqueness within the status owner and reservation below the saved next sequence; current-format restore retains them verbatim. Expose the same ordinal as a column/index in the existing status-row owner when an ordered history query needs it, rather than reusing arbitrary database return order. Prepare/reuse its ordered contribution roster on membership changes; sorting is not repeated for singleton clock writes. Injury boundaries order first by due time, then the defined pulse-before-stage priority, then stable creation ordinal. Verify unchanged ordinary singleton, capability, interruption and same-endpoint outcome ordering across save/reopen before enabling unordered row persistence. UI sorting remains its own explicit presentation choice.

### 3.4 Progress without per-injury ticking

The current numeric status integrator increments each participating singleton's `elapsedSeconds` per interval. Its lazy `native-values.ts` path explicitly excludes contributions and coupled/periodic effects. Do not claim that existing path already solves injury timing or force wounds into the continuous-attribute window. The selected injury stages and shared bleed phase use a small participation-time anchor instead:

- A body with injury timing stores `injuryTime: { value, atSimTime }`. It is a coordinate basis, not an injury severity, timer queue or duplicate wound collection. Define `running` from that same living physical life being alive and actively participating. Current time is `value + (running ? world.simTime - atSimTime : 0)`.
- Create the basis lazily at acquisition. Immediately **before** a transition changes running eligibility, settle earned due body work in the existing native order, then reanchor it to its current value and `world.simTime`. Cover actual protected departure/return, placement/retirement and death owners, not browser presence. The current kernel settles elapsed body exposure before `finishSimulatedExits`, then protects against discrete attacks at that instant; ongoing injury pulses belong to that earned-body-work phase. Preserve that ordering instead of replaying an unpaid old pulse on return. The vulnerable departure interval remains running. Global pause needs no write because simulation time does not advance. End/reset the basis at physical-life replacement after retaining terminal evidence.
- At stage entry, set `stageClockAt` to current participation time and `elapsedSeconds` to zero or the earned recovery credit specified by treatment. Current stage progress is `elapsedSeconds + currentParticipationTime - stageClockAt`. Ordinary interval advance writes neither field. On a real stage transition, write the new stage/anchor once. On resolution/end, materialize its final progress once if retained history needs it.
- A finite stage's due coordinate is `stageClockAt + duration - elapsedSeconds`. Keep a derived per-patient ordered index of timed instance IDs and those coordinates; the next due lookup uses its minimum, not a scan of every wound. Maintain/rebuild it on injury semantic changes, current-definition changes and load. When running, convert its next coordinate to a simulation deadline by subtracting current participation time. When protected, publish no deadline. Permanent stages have no entry.
- The one bleeding singleton uses the same coordinate basis for its episode phase, with a saved last-settled pulse ordinal. Its episode anchor is fixed until bleeding ends; only an actual pulse advances that ordinal. Adding or stabilizing a nonfinal wound changes the amount source, not phase. At a due endpoint, apply each owed pulse once in native order; a budget yield preserves the next unsettled pulse. This replaces per-interval elapsed writes for this aggregate episode only, not unrelated status clocks.

These anchors preserve exact current-format save/load without checkpoint-time materialization of every wound. Validation checks finite representable coordinates, valid same-life basis, stage credit bounds and the last-settled pulse against the current coordinate. Pure elapsed/detail reads never mutate anchors, charge work or advance a stage. Due transitions remain the existing native interval owner's work; an overdue external/public state must be reconciled before publishing current effects rather than silently treated as healed by a UI reader.

The modifier summary and timed membership must depend on injury **semantics**, not the whole `statusEffects` object identity, current simulation time or the bleeding pulse ordinal. Add one safe integer `injuryRevision` under the body's injury-state metadata, incremented by the sole owner for acquisition, stage/treatment/resolution and relevant live profile changes. It is a freshness token, not effect authority. Key the retained summary by patient identity/life, this revision, exact installed definition/policy pins and relevant eligibility. Rebuild it from canonical instances on a cold load or unknown mutation; ordinary singleton ticks and harmless clock reads preserve it. Existing per-instance revisions still fence exact treatment selections.

Audit the existing broad contribution consumers rather than merely adding a new helper: `NativeStatusPreparation.signature` currently disables reuse for any contribution; `advanceCapabilityContributions` scans/charges every contribution; `statusBoundary`, `crossStatusReferences`, source-dependency capture, contribution indexing and terminal-residency checks also enumerate the shared map. Recognize this validated subject-local injury family in their prepared semantic membership so an unrelated singleton tick does not traverse all injuries or treat the historical attacker as a sustained source. Preserve conservative handling for existing foreign/generic contributions. Ordinary auto-status rule preparation must not scan all injury instances to prove that none is an automatic singleton.

`statusWork` / `initializeNativeWork` distinguish interval-rate work, scheduled injury transitions and static contributions. Charge injury acquisition/edit preparation and each actual due transition, plus selected pulse aggregation/output, through existing complete-operation admission. A permanent static injury owns no recurring interval charge; a timed stage retains only the admitted scheduled continuation and is charged when due. Switching to/from a timed stage acquires/releases that continuation through the semantic owner. Do not call `chargeStatusWork` once per injury merely because a physics sample elapsed. This is a required extension of the current work owner, not a claim about current behavior.

## 4. From a physical hit to an injury

### 4.1 Explicit trauma evidence

The native damage caller supplies a typed trauma descriptor only after an actual eligible external occurrence. It contains the damage-kind/profile pin, contact body/life, actual contact point and incoming direction when available, coarse region selection when that is all the mechanic supports, and the causal occurrence identity. The descriptor distinguishes measured point, authored coarse selection and unavailable location. A client may supply aiming intention; the server/domain supplies accepted physical facts and installed profile references.

Keep the exact contact occurrence distinct from its parent action. A projectile contact binds the flight/contact identity; a strike binds its actual strike occurrence. Future multiple contacts from one action require distinct occurrence ordinals through the existing identity owner, not repeated injury creation under a shared action label. The current completed-flight/action-stage/receipt owner prevents replay; do not add a growing per-body seen-hit set. Generate the injury ID and consume RNG only inside the candidate draft, so rejected work discards both.

Allocate a native episode with the saved `nextId` owner, and commit its counter, RNG, status row, health and causal result together. Do not call the externally keyed `attachCapabilityContribution` command from contact: that current entry point requires complete contribution history before accepting a caller-chosen ID, which would hydrate every resolved wound on a fresh hit. Factor its internal validated attach mutation for native allocated IDs. Protect the allocator universally: supplied native-looking contribution IDs reserve the shared sequence through the same reservation semantics already used for supplied entity IDs, and current-format validation/initialization checks that contract. Update the shared helper/callers rather than adding a wound-only allocator, collision scan or compatibility fallback. External arbitrary-ID commands retain their exact-history checks where required; native generated acquisition needs no terminal-history fetch.

Projectile contact already resolves a swept hit and `flight.position`; use that contact rather than the original intended target or current mouse position. Released flight stores its accepted trauma definition pin with its other committed properties. A later weapon edit, unequip, shooter death or forgotten target cannot change its already released damage kind. Defense and susceptibility use the actual struck body's current valid state.

Current melee checks target, reach and hit outcome; it does not calculate an anatomical blade path. Its installed strike profile therefore supplies an explicit coarse region/distribution. The first injury implementation must not claim a measured kidney stab from this path. Both ordinary and windup/recovery strikes use the same descriptor builder and commit owner.

General health loss, starvation, exhaustion, injury bleeding pulses, health editor writes and arbitrary negative deltas do not manufacture trauma descriptors. A periodic bleed cannot generate another laceration or recursively create wounds. A future fall, fire or poison family must explicitly supply its own supported exposure/trauma contract; a damage label alone grants no such behavior.

### 4.2 Deterministic selection algorithm

For one eligible contact, in the existing authoritative draft:

1. Resolve the actual target and physical life. Prepare guard/armor reduction, execution contribution, body susceptibility and existing applicable incoming modifiers through their current owners. Keep their ordering; do not apply any multiplier twice.
2. Compute nonnegative **effective trauma damage before clamping to remaining health**. Compute the ordinary health owner's rounded/clamped actual loss separately. The selected severity ratio is effective trauma damage divided by the struck body's valid positive maximum health. A severe blow against a nearly dead character does not become mild because only a little health remained.
3. Resolve the allowed coarse region and damage kind through the installed target profile. Filter definition/stage candidates by that profile, region, kind and severity band before preparing their effects. An explicitly authored broad fallback is an ordinary compatible candidate; never invent a human organ for an incompatible body. No match means actual damage still occurs without an injury. Installation rejects a selected table that promises an injury but has neither a compatible candidate nor an explicit supported no-injury rule.
4. Use only the saved domain RNG. A probability of zero needs no draw and produces no injury; one needs no probability draw. Otherwise consume one chance draw, succeeding when it is less than the selected probability. After success, sort eligible candidates by exact definition ID then stage ID; a single positive-weight candidate needs no draw, and several use one draw against their total weight with half-open cumulative intervals. Skip zero weights. Do not redraw on a retry, load, projection or diagnosis.
5. Prepare the chosen instance, resulting stage operations, required work reservation, causal events and ordinary damage/lifecycle result before publishing any of them. Failed computational admission cannot publish health loss while silently omitting its selected injury. A projectile with already committed release remains pending at its valid contact boundary until the complete native outcome can commit; budget exhaustion is not a miss or immunity.
6. Commit actual damage and the selected instance atomically through one body/trauma owner, then perform dependent interruption/lifecycle reconciliation and permitted evidence. A lethal hit retains its chosen injury as historical old-life evidence even though no living-body modifier survives death. Finalize death once.
7. Record effective damage, actual health loss, chosen definition/stage, region certainty and causal identity in native history. Ordinary projections disclose only permitted portions. Retry returns the recorded outcome and never advances RNG or adds another injury.

Selection uses one pre-contact state. The injury acquired from the hit does not modify that same hit retroactively. A preexisting injury may modify it only through an explicitly supported authored channel. Stable body-before-action endpoint ordering remains authoritative; do not batch distinct hits into one aggregate wound or reinterpret the existing sequential combat order as simultaneous damage.

### 4.3 Coarse location now, precise contact later

Keep center-target ranged aiming, release-time repicking and actual projectile collision unchanged. An aimed target moving away before button-up is not retained. A point shot follows the selected point without target lead; a target shot uses the current target center and the existing permitted motion lead. This project adds consequences to actual contact, not headshot controls.

The initial region resolver is world-owned profile data evaluated from supported physical evidence; the profile defines its fallback when only a coarse strike location is available. For the selected coarse projectile classifier, normalize contact height within the actual effective occupied body's bottom/top interval, clamp numerical endpoint residue to that interval, then apply the profile's ordered half-open bands. Reuse the effective-body/anchor reader so crouching, flight and altered numeric profiles cannot silently reuse standing dimensions. The world profile owns different humanoid, quadruped and avian bands. A current melee contact lacking a measured point uses its authored coarse region, not a reconstructed camera or aiming point. Generic spatial code performs geometry and returns measurements, never kidney/rib selection. Region membership and classification are distinct from injury identity and treatment.

The later precision seam can supply body-local contact point, trajectory, motion class and admitted anatomical volumes to the same selector. It requires authoritative pose transforms/hit volumes, mappings for applicable bodies and deterministic closest/penetration contact rules; a renderer's visual head is insufficient. Broad phase first selects physically possible bodies, then only those bodies' relevant regional volumes receive exact tests. Future precise inputs can deterministically select an organ injury without changing existing injury instances, recovery or care contracts. Slashing, stabbing and blunt impact must remain materially distinct authored evidence; no claim that a slash breaks bone is inferred from its English name.

## 5. Mechanical effects and stacking

### 5.1 Finite supported operations

Extend status operations only for the channels actually consumed by the selected injury catalogue. Reuse existing capability restrictions and periodic numeric changes; add a small typed modifier operation for the following channels. A modifier cannot write an arbitrary attribute path, change permissions or install callbacks. The [world profile](../worlds/base/recovery-and-care.md) owns the selected caps and per-stage contributions.

| Channel                   | Shared interpretation and consumer                                                                                                                                                                                 |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `movementSpeed`           | Sum applicable penalty fractions, cap by the world rule, and multiply the ordinary speed by `1 - penalty`; compose the existing scar factor once. Consume in all supported movement and matching forecasts.        |
| `physicalWorkRate`        | Sum/cap work penalties, then multiply eligible finite physical-work throughput by `1 - penalty`. Apply to the exact phases below; exclude speech, real-time gestures, care, passive physiology and pure cooldowns. |
| `activeEnergyExpenditure` | Sum/cap extra expenditure fractions, then multiply the installed active energy drain by `1 + extra`. It does not introduce a new drain when the body/profile lacks that energy operation.                          |
| `recoveryWork`            | Sum/cap extra ordinary health-recovery work, then use throughput `1 / (1 + extra)` for Recover at camp. One completion still restores the promised health; this is not a reduced-health top-up loop.               |

Shared bleeding is the separate timed symptom channel below. No selected injury changes damage output, target damage multipliers or headshot damage.

A single `effectiveBodyEffects(world, entity)`-style pure reader combines current injury stage operations with applicable existing inputs for consumers. Its result uses the semantic cache contract in §3.4; changing a singleton's elapsed clock must not invalidate injury totals. The world supplies stacking laws and bounds; the engine supplies the deterministic evaluator. Retain each injury's individual consequences in detail even when a world-selected cap limits the combined penalty. The reader never edits the body or stores an independently writable effective speed.

Complete consumers matter: movement means ordinary travel, native travel/escape, flight/climb, attack movement, supported chosen evasion and the matching motion/deadline predictions. A work-rate change affects both offered duration and actual admitted progress. Existing `remainingSeconds`-style work records continue to mean remaining authored work; convert valid elapsed game time to consumed work at the interval-start throughput, and bound the next completion by remaining work divided by that rate. Reevaluate after an injury/stage change without resetting completed progress. Preserve resource reservations and already committed stages. The offered remaining time uses the current throughput and changes honestly when that throughput changes.

Pure combat recovery/guard expiry deadlines remain their existing absolute commitments; the new work channel does not rescale them. The one-real-second gesture ring is also unchanged. Pressure, dressing, splinting and Tend injuries at camp use their declared care work and are exempt from ordinary injury work penalties so care cannot create its own slowing trap. Only ordinary camp health recovery consumes `recoveryWork`. Its own increased work may still change as injuries change, using the same remaining-work contract. Expenditure modifiers affect only their explicitly selected drain family. If a consumer lacks a meaningful channel, do not include an inert effect in the catalogue.

The feature's body-effect fold must not multiply scar penalties twice. The existing scar source remains authoritative and is read through `scarFactor`; the new common consumer can compose its result with injury modifiers once. Existing death-scar wording and removal remain their separate contract.

Consequently an injured animal's selected energy consequence has an actual native consumer even though feeding clocks are exempt from W. The world profile owns the numeric rates and selected animal-specific consequences.

### 5.2 Periodic bleeding and exact health arithmetic

Whole-point health currently rounds every nonzero delta to at least one point. The selected shared bleeding law therefore uses one world-authored singleton status episode per patient as the **pulse clock**, with the pulse amount derived from all currently bleeding injury contributions and clamped by the world's law before one integer health write. The singleton stores no writable bleeding severity, wound list or mirrored treatment flags. Extend the finite status operation family with this named aggregate-channel consumer; do not execute several fractional per-wound writes or apply a tiny per-frame decrement.

The first bleeding injury starts the clock. Additional bleeding and treatment of a nonfinal wound retain its elapsed phase; stopping the last bleeding contribution ends it. Later new bleeding starts a new episode with a full first interval. Selecting an oldest wound as the clock owner is invalid because treating it would move the remaining wounds' deadline. Each pulse records its actual aggregate health change and the exact contributing injury IDs in stable order; the pulse does not choose a wound or invoke trauma selection.

The interval scheduler ends at the next real pulse or stage transition. At an endpoint, sample the bleeding contributions active immediately before that pulse, then resolve natural recovery or treatment completion. This is discrete sampling, not proportional integration: a new wound acquired shortly before an existing pulse contributes its full current amount to that next pulse, but never to an already completed pulse. There is no per-wound fractional accumulator or age adjustment. A completed stabilization prevents later pulses; it does not erase a pulse already due. No pulse is replayed after save/load. Treatment interruption distinguishes incoming external trauma from ongoing symptoms so an activity intended to stop bleeding is not cancelled by every bleed pulse. If a due pulse is lethal, death precedes any treatment completion.

## 6. Natural recovery and lifecycle

An injury stage advances only while its particular current-life body actively participates under the selected world law. Derive its current progress and the shared bleeding phase from the saved participation-time basis in §3.4, not host wall time or per-wound interval updates. Pause stops progress. Protected absence stops the body's injury progression and recovery consistently; another human resuming the shared world does not grant treatment or harm to an absent protected body. Unprotected/native participation follows its existing world policy.

An authored natural stage transition is an exact deadline derived from elapsed stage time. A permanent stage has none. Resolve due old-stage operations, change the stage/revision once, reset its stage elapsed time, rebuild affected contributions and emit the appropriate permitted transition. A transition to resolved ends the instance and releases its recurring work. No natural transition creates an arbitrary new injury or same-time chain. The selected catalogue's finite courses use at most two natural stages; the admission validator proves the supported acyclic graph and computes its finite resolution suffixes once.

Treatment changes a named stage or resolves a named instance through the same owner. It does not remove all conditions sharing the definition name, restore pre-injury health automatically or rewrite the originating event. If a method includes health restoration, that is a separately declared operation in the same committed care outcome.

Treatment must never postpone an already nearer natural resolution. Compute `oldRemaining` from the current stage's remaining time plus its compiled natural suffix to resolution, or infinity when the untreated course has no resolution. Each selected timed treatment destination goes directly to resolution after its authored duration `D`. On transition, set its `elapsedSeconds` to `D - min(D, oldRemaining)`; a formerly permanent course starts at zero. If `oldRemaining` is already zero, resolve through the normal due owner instead of installing an artificial delay. This elapsed field is credited recovery work, not a claim about time physically spent in the new stage; `acquiredAt` and events retain actual chronology. Pressure uses the same no-later-resolution rule when its stabilized stage has a finite course. A permanent stabilized stage retains no natural deadline. Reapplying a method whose destination/current stage gives no further supported benefit is unavailable.

On death, end live injury mechanics with an explicit death outcome and retain their old-life records. `separateDeadLife` currently creates a corpse while preserving the person's identity elsewhere; it does not copy status effects. Corpse inspection resolves retained injury records by the original person/physical-life link. Do not duplicate/rekey the same injury onto the corpse or leave it mechanically active on the retained person. Continue begins a new physical life without old-life injuries; its existing death scars remain. Creator revival retains its explicit privileged full-restoration policy below. Historical memory of the injury remains independent from physical recovery; death ending a mechanical effect is not treatment healing it.

Body/profile replacement, retirement, definition editing and timeline restore use the existing continuation/identity rules. Replacement cannot silently reinterpret an injury into another anatomy. A supported live edit must leave all retained exact definition/stage references valid; otherwise reject that edit with a specific dependency. No old-save migration, alias or previous-format reader is required. Rebuild derived indexes after load; never infer recovery from process downtime.

## 7. Care actions and exact completion

### 7.1 Method contract

Care methods are world-authored definitions of a finite trusted action family. Each specifies applicable bodies, target conditions/stages, actual prerequisites, work, material requirements, location requirements, permitted performer/patient relation and exact outcome operations. Operations may stabilize selected bleeding contributions, change selected injury stages, resolve selected injuries, or restore ordinary health through its existing owner. They cannot edit arbitrary bodily fields, infer a diagnosis or cure unselected conditions.

Keep the current ordinary action catalogue/availability owner, parser/family declarations, action details, NPC choices, command schema, plan records and execution caller in sync. A read-only preview selects exact supported options and explains known refusal; it does not reserve a patient, interrupt current work or charge material. Static method facts prepare once per compatible read. Known exact injury IDs use direct lookup; discovery selects that patient's eligible active records, never every wound in the world.

Offer only a condition for which that method can still produce its declared useful result at the quoted completion time under the currently known pinned natural course. A wound that will naturally resolve before completion, or clot before pressure finishes, is not a useful selectable target for that method. Use native known deadlines, not predictions of future attacks or hidden decisions. Recheck usefulness at admission; later natural change still follows the exact completion rules below. This avoids spending a long group activity on conditions already predicted to need no help.

An action saves the admitted method pin, performer and patient identities/lives, exact selected injury IDs and semantic revisions, selected camp/location where required, input claims, and remaining native work. New injuries acquired after admission do not silently join the selected cohort. The profile's group treatment is **one finite atomic activity** with flat quoted work and per-selected-injury materials, not a sequence of individually completed cures. Cancellation before completion changes no selected injury and spends no treatment supplies. Naturally resolved members reduce the material actually consumed and effects applied, but do not shorten the admitted work; disclose that rule with the quote.

At completion, accept the selected instance's expected stage or an explicitly known monotone natural successor from the same pinned definition, provided the method remains applicable without increased cost/materials or wider consent. A cut clotting while dressing is applied should not cancel useful treatment. This is a graph relation validated from the definition; it is not permission to accept arbitrary later revisions. Resolve/skip already cured members. A change from another treatment, creator edit, unsupported stage, definition replacement or physical-life change is stale and refuses the complete group before effects or supplies. If every selected member resolved naturally, complete honestly with no treatment benefit, no material consumption and no practice reward. No condition is substituted.

Prove that a successor was natural rather than accepting any later revision whose stage happens to be reachable. The injury transition owner can reach active care through the patient's exact current action: self-care is local; assisted participation points to its performer action. On a permitted natural transition, atomically advance that action's expected stage/revision for this selected instance; on natural resolution, mark that selection as no longer requiring effects or supplies. Non-natural stage changes use the same dependency owner to invalidate/end the bound care. No growing revision-history log or scan of every actor is necessary. At completion compare the exact updated expectations, not a guessed provenance inferred from the stage name.

Before start, admit the entire selected group's real work and representation through the existing native/action/resource envelope. If that envelope cannot hold a selection, offer an explicitly smaller user-selected cohort with its own quote. Never silently truncate the target set, turn the group into an autonomous queue, hide partial completion or make that operational bound an injury-count limit.

### 7.2 State machine

1. **Offer:** compute an actor-permitted exact choice with current method, patient life, injuries, location and supply. Keep private unmet patient prerequisites private from a helper.
2. **Consent where required:** retain agreement to that method, patient life, performer, exact material supplier and selected injury/cohort. Consent authorizes this care, not inventory access, future procedures, personal data access or a standing instruction. No human or NPC consent is inferred from silence.
3. **Start:** revalidate the current choice and consent, then acquire exact existing resource claims and participant action ownership atomically. Refuse unavailable work/material before interrupting another valid activity. A helper's actual action owns physical work; the new narrow patient participation action below references that owner and cannot survive it.
4. **Advance:** consume the valid native interval at the selected method's rate. Ordinary continuing needs and symptoms still act. Invalid commands, panel closure, speech and inspection do not cancel care; admitted incompatible work, movement/lost reach, actual external trauma, consent withdrawal, unavailable life/participation and method prerequisites use the selected interruption law.
5. **Complete:** settle due body effects first, then recheck patient/performer lives, method pin, exact selected injury state with the natural-successor rule, current consent/reach, required location and material claims. Commit only the declared useful care result and its actual material consumption together. Release claims for naturally resolved members without spending them and finish plan/experience evidence through the existing owner.
6. **End early:** stop remaining work, release unspent claims and patient participation, retain actual elapsed world time and independent world events. The selected methods grant no partial cure or material spend before group completion; no automatic retry or restart occurs.

Routine self-care needs no extra confirmation layer or model call. Apply Pressure must remain useful while bleeding continues, so its symptom pulse does not interrupt it. External trauma and lethal symptoms still can prevent completion. Recovery at camp restores health according to its separate selected eligibility and injury-related work requirement; it does not resolve injuries merely by reaching maximum health. Ordinary food/energy, scars and other conditions keep their own owners.

### 7.3 Helping and doctors

The first doctor is a person who willingly performs a supported known method with the necessary resources. There is no new doctor controller, profession permission, clinic queue, generated medical-success roll or compulsory helper. Ordinary NPC choice can accept, refuse or defer an offered interaction using its permitted evidence and goals; once chosen, treatment proceeds natively without repeated model approval.

Helpers and self-care use the same mechanism. The selected profile decides method availability, resources and any explicitly authored difference. Merely naming someone a doctor cannot create a potency bonus or hidden anatomical knowledge. A future trained method can bind a real qualification and different effect/work through this method definition; it does not require replacing injury records or the care executor.

### 7.4 Exact assisted-care integration

The existing `cooperation.ts` help tasks cover preparation, carrying and construction; none is currently a care contract. Add one typed `help.task.kind: 'care'` proposal/terms variant. It binds patient and helper physical lives, exact method pin, selected injury identities and semantic revisions, disclosed selected-condition evidence, maximum required resource types/amounts, selected site when required, and quoted work. `outings.ts` retains ownership of proposal admission, notices, accept/decline/withdrawal, current terms, deadlines, participant indexes and owned work. Do not build a parallel medical invitation system.

The patient initiates **Request care** by selecting method, exact conditions and a currently eligible nearby helper. The request states what will be shared and required. It acquires no action slot or supplies. A helper seeking to assist first can ask in ordinary speech; the patient then makes this same selection. No unsolicited offer grants private condition inspection or permission to start work.

The helper sees the exact event-time snapshot of selected condition names, stages and relevant effects supplied by the request. Pending or accepted cooperation retains that evidence; it is not a live medical read grant. Remote unseen recovery, new trauma and state changes cannot update its labels/counts through a hidden injury lookup. Current ordinary perception can supply additional permitted evidence. The native Start validator can generically report that an agreement is unavailable without revealing which private condition changed. A fresh request can explicitly share fresh facts.

For the care variant, the explicit **Accept and start** choice prepares acceptance and ordinary action start in one atomic transaction. Validate lives, current method/cohort consent, readiness/reach, location and the helper's selected eligible material lots before changing either actor. Failure leaves the pending request without acceptance, action ownership or material effects. Do not change generic cooperation Accept into an implicit work command. The ordinary separate Accept remains available when the helper wishes to agree without starting yet; its accepted state enables an explicit **Provide care** action that runs the same Start validator. Neither accepted state reserves a patient or silently queues treatment. Existing cooperation expiry remains an upper bound; admission proves the selected activity can finish before it rather than adding another medical deadline. At the inspected revision, `outings.ts` sets accepted `endAt` from the installed `cooperation.episodeSeconds`, authored as 14,400 in `worlds/base/config/first-playable/people.yaml`; this exceeds the longest selected 1,800-second care activity. A delayed start still checks its actual remaining window, and a different installed profile must provide a sufficient window or decline admission honestly.

At actual start the patient must still be idle and ready to participate. A prior request is not authority to cancel work the patient chose later. The helper can replace their own work only through the ordinary prospective-work preview and accepted transition. The helper supplies and authorizes their own exact accessible material lots; the patient's agreement binds requirement type/maximum amount, not private helper lot IDs. Patient-supplied materials require an ordinary accepted handover first. Treatment consent grants no access to either inventory.

`resource-claims.ts` currently reserves finite attributes, replenisher/gathering stock and item lots; it has no actor-body lock. Keep those real input claims and add a narrow patient-participation variant in the existing `actor.action` slot. It references the performer action ID, performer/patient lives and accepted cooperation identity/revision, with no independent timer, effects or material claims. Atomically install the performer's timed care action and the patient's marker, and attach both exact action identities through cooperation's existing owned-work relation. Self-care uses one ordinary care action and no marker.

Both ordinary action slots make their participants active for the installed energy-expenditure rule. Each participant therefore pays their own current applicable active expenditure, including their own injury modifier, while care runs. Preview costs/prerequisites use those actual separate rates; do not charge the helper's drain to the patient, exempt the marker by accident, or assume only one person expends energy.

Stop, withdrawal, admission of incompatible work, relevant damage, lost reach/participation, deadline or either physical-life change ends the linked operation through one owner. Release unspent material claims, close both exact action bindings and conclude the cooperation once. Cleanup compares action IDs and lives before clearing a slot, so a late completion/cancellation cannot erase newer work. Stop and withdrawal remain available while paused and require no provider call. Restore validation requires the marker and performer action to agree exactly; neither a stale marker nor an accepted social request can create care work after reload.

## 8. Death, revival and restoration details

Distinguish **healed/resolved**, **temporarily unavailable participation**, and **ended with a physical life**. Protected absence retains active injury instances and their exact earned progress while effective operation eligibility is false. It does not cure or expire them. Death sets their existing `active` flag false, records the death end reason and time, releases recurring work and ends the patient's shared bleeding episode. Do not announce those conditions as medically healed.

For a player whose body becomes a separate corpse, `physicalBodyForLife` resolves that old physical body. Ordinary current-person inspection does not treat its old-life records as current injuries. Continue starts its new physical life with no old-life injury effects, while exact historical records remain available under permitted corpse/history inspection.

The current creator **Revive** accepts an ordinary dead actor, rejects a player awaiting Continue and its separated corpse, and increments `physicalLife` to fence stale actions. Preserve that privileged full restoration: the revived life has full ordinary health and no active injuries from its previous life. Retain original injury/cause history with explicit lifecycle outcomes; do not rebind old instances, replay injury effects or label the transition ordinary treatment. The creator's preview/result states that restoration. This operation does not imply that changing a living character's health to maximum clears their injuries; only the explicit lifecycle/condition owner can do so.

Same-format save/load retains exact injury IDs, definition pins, current stages and credited progress, shared bleeding clock, participant lives, current care work, claims and resulting history. The ordinary world transaction commits them with health and events. Current-format validation checks complete fields, finite representable progress, exact stages/methods, lifecycle state, valid historical versus required live references and correspondence between active claims and current work. The next pulse/transition must remain representable. A missing historical attacker is legitimate; a missing active care patient is not.

Keep active/current injury records in the simulation working set; resolved and ended-life records use the existing terminal contribution storage/residency path. Extend `currentContributionsPredicate`, history pruning/materialization and full snapshot validation coherently without losing distinct terminal reasons. Complete save capture includes cold injury outcomes without eagerly hydrating them on every movement command.

Update the current database/checkpoint format owners and actual current callers together. Incompatible development data is disposable under the root policy. Reconcile useful starting content through the existing initializer; do not invent an injury migration, preserve an obsolete schema or change a marker to admit stale fields.

## 9. Evidence, projections and ordinary agency

Native state, permitted perception, a diagnosis and a remembered account are distinct. The owning player receives the selected world's honest condition/effect/treatment information. An observer receives only visible symptoms, permitted health and information actually shared or established by an admitted examination. A hidden kidney condition, exact private penalty, attacker identity or unobserved attack direction cannot leak through treatment availability, a disabled menu reason, generic status labels or story impact metadata.

Add injury-specific acquisition, stage-change, stabilization, resolution and care-result facts to the existing event/disclosure owner. Reuse the original contact/action causal identity. A public impact event can describe a hit or visible bleeding without exposing the internal injury selection. Health changes remain the actual committed numbers. Compact per-body pulse evidence may bind its contributing IDs internally; projections do not dump this list into every nearby person's context.

Normal context preparation selects current consequential effects and available responses from the same scoped projection. Character cognition chooses what to do; it never chooses which injury a hit caused, makes a diagnosis true by saying it, or supplies damage arithmetic. No new provider tick, guaranteed gratitude, trust/skill reward or automatic paid retry is part of injury processing. A treatment attempt and its result are actual action experience; the existing learning owner decides what that supports under the selected world rules.

Provide a compact ordinary injury summary and paged instance detail with effect, state and useful action. Grouped rows retain exact expandable members and actual selected treatment targets. A page limit bounds rendered output, not selection work; use active-patient indexes before preparing expensive detail. Reopening the panel or inspecting a distant person grants no treatment, timer progress, diagnosis or broader information.

Physical state and memory stay independent: forgetting the attack cannot heal the wound; resolving the wound cannot erase the event or compel forgiveness. A claimed injury unsupported by native state remains speech/belief. A healer may explain what a supported treatment does without needing a generated diagnosis system in the first delivery.

## 10. Performance and admitted work

### 10.1 Cost model

There is no injury-count gameplay cap and no permission to remove real wounds for performance. There is also no assertion that an unbounded number of actively simulated records has constant cost. Let `I` be a patient's active injuries, `T` the subset with timed transitions, `C` the selected candidate list for one impact, `S` the selected treatment cohort and `H` retained resolved history. The complete implementation must distinguish these dimensions from total world population.

| Path                          | Required preparation and reuse                                                                                                                                                                      |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| One hit                       | Exact body/profile lookup; compatible indexed selection rows; `O(C)` stable candidate filtering/selection, without scanning all world actors or every installed injury definition.                  |
| Static modifier read          | Reuse a body/life/definition/state-dependent aggregate. Rebuild for a changed patient's active contributions, not each movement frame, caller, observer or whole-world revision.                    |
| Natural recovery and bleeding | Register injury-bearing participants and their real next stage/pulse boundaries. Permanent static injuries supply no periodic callback. Reuse existing native scheduling and semantic invalidation. |
| One exact treatment           | Exact lookup of the requested instance(s), one shared method preparation and exact claim check; selected work follows `S` (canonical ordered lookups add `log I`), not all `H`.                     |
| List/detail                   | Select permitted active IDs first, then prepare one page. Historical injury detail is an explicit indexed read and does not enlarge hot movement state.                                             |
| Persistence                   | Write changed status/action/claim/history records through the current transaction; do not rewrite an actor-sized injury array or serialize all history per pulse.                                   |

An initial aggregate rebuild can be `O(I)` after an actual injury mutation; a cold ordered deadline index can cost `O(T log T)`. These costs do not recur merely because time, an ordinary meter or another actor changed. The required shared collection refactor removes the plain-map copying/persistence scan, and §3.4 separates semantic invalidation from earned clock time. Measure frequent real mutations on a heavily injured patient before claiming scale. If full rebuilds are material within the required workload, maintain derived channel totals/deadline membership from the existing changed-key path; never add parallel saved totals. Rebuild from canonical records after load/fork and invalidate on definition/stage/life changes. A bounded result list does not justify an unbounded preparation scan.

### 10.2 Scheduling and capacity

The shared pulse clock and injury stage boundaries join the existing native interval owner. Body changes occur before action completion at the endpoint. Current-rate capture uses interval-start state; an effect acquired or removed at the endpoint cannot retroactively change the completed interval. Local modifier changes invalidate that body's motion forecast, dependent action deadlines and relevant observation preparation through the semantic change owner, not by hoping an event happened to be emitted.

Native work admission covers candidate evaluation, an admitted ongoing timed process, transition effects and causal output before the irreversible outcome. Define the maximum supported definition complexity through the existing combined work validator. Do not substitute an arbitrary wound count or ignore the next real pulse when a budget expires. The server can yield between coherent prefixes and retain simulation debt under the current scheduling contract. A technical budget refusal is not an in-world miss, cure or completed care activity.

No geometry work runs merely because an old injury exists. Precise anatomy expansion keeps the existing conservative body broad phase and performs region/organ exact checks only on actual candidate bodies. Do not add world-wide body-part scans, one worker per injury or asynchronous wrappers around synchronous arithmetic. Post-commit optional presentation may coalesce replaceable summaries; distinct actual injuries, treatment results and required causal evidence remain retained.

## 12. Expansion seams and decisions

The selected implementation intentionally does not need per-organ health, anatomical slots, headshot controls, skeletal pose replication, penetration physics, surgery, diseases/infection, permanent universal pain, a medical skill tree or healer economy. The feature specification and world catalogue retain the valuable future examples with explicit scope. A new injury definition using supported operations is content; an unknown operation or precise physical selector requires a reviewed runtime extension.

Precise body contact adds measurements to trauma selection. More advanced recovery adds admitted stage transitions or methods. Diagnosis adds a permitted evidence acquisition action; it does not become a hidden prerequisite for knowing that a visibly supported treatment can help. Lasting consequences remain individual instances and causal history. A richer social care relationship is built from actual offers, decisions and remembered help, not an automatic relationship reward.

**Open technical decisions:** none required to begin the selected implementation once the paired feature/world contracts are approved. Balancing values remain reversible authored choices; verification results can justify a documented tuning change. A newly discovered conflicting owner or unsupported combination must be resolved in this pair and the tracker before dependent implementation, rather than silently weakening the specified behavior.
