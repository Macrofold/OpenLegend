## Owners and risk

Expect approximately 400–700 affected runtime logic lines, excluding tests, plus world content and maintained documentation. This is a cross-layer knowledge/authority change, so the existing batch spec/design is supplemented by this delivery plan. The main risks are granting a method without permitted inspection, disclosing private stock/provenance, stale record execution, falsely crediting authored discovery as live invention, and duplicating rewards on restore.

- Base-world content owns destinations, clue wording, finite stock, spear tuning and the field-sling proposal.
- The existing recipe compiler/admission owner installs an authored method with explicit world provenance, without crediting an actor with invention or teaching anyone on startup.
- Ordinary item definitions carry a typed exact method-record capability. The item-access owner checks reach, custody and container access before reading it; the learning command also checks the selected item's revisions and pinned meaning.
- The existing recipe-knowledge owner grants a method once and invalidates dependent choices. Native action receipts/private evidence record acquired versus already known; there is no per-site completion flag.
- Server inventory/action projections and the existing recipe/detail surfaces expose only permitted method facts. All command schemas/binders/consumers are updated together.
- Current-format validation and PostgreSQL persistence retain exact definitions, stock, knowledge and ordinary action receipts. Existing worlds are never reseeded or deleted.

AV02's future attachment owner remains responsible for enforcing two-hand equipment occupancy. This branch uses the current single-equipped-tool owner and does not introduce a competing equipment store. Shared AV02 integration remains separately tracked.
