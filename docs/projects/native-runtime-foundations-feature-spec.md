## 1. Purpose and scope

Make the current small game responsive while preserving an affordable route to a much larger persistent world. The desired return is useful invention, independent people, readable danger, cooperation and consequences worth returning to—not a count of idle entities. The [first-playable priorities](../repertoires/gameplay-priorities.md) remain the product scope.

This design refines the existing resident Rust architecture and keeps one native mutation authority. Its first four candidates address JSON preparation, scratch storage, compatible captures and ordered rate reads. Mike's November 13 continuation authorizes their remaining work and the later designed NSC conversion, parallelism, cell and distribution stages through their existing owners. Each numerical target guides its own candidate decision. An earlier profile failure does not block the other approved work. The [NSC tracker](../maintainers/native-simulation-core.md#remaining-proof-checklist) owns the repair checkpoint and review before porting more mechanics.

The source baseline is `Macrofold/OpenLegend`, `codex/native-simulation-proof`, `d9544ae5d017e697bfcfe2a38c71bb8569ad14f6`. That commit integrates the research; its runtime is the preceding `d1211430d65390957baf5b0094d2cf2057950f8f` runtime. The active implementation can advance independently. The [evidence record](native-runtime-foundations-evidence-and-repertoire.md) separates inspected code, the implementation owner's additional report, hypotheses and remaining measurements.

## 3. Player and world journeys

### A. A person can act while another person thinks

At the supported opening, a player moves, stops and talks while NPC replies are pending and native animals continue their actual reactions. Controls, current permitted views and ordinary saves remain usable. Optional model preparation must not pin unrelated full-world representations. A failed or canceled reply does not duplicate speech, erase accepted progress or release memory still owned by the transport.

The performance work preserves the same meaningful encounter. It does not improve a result by canceling the second conversation, skipping animal activity, reducing evidence, slowing the world or excluding failed runs. The actual cognition request and admitted reply effects must retain their meaning; fixed provider replies qualify deterministic continuity, not autonomous model quality.

### B. Two windows are not two copies of the world

Two eligible connections viewing the same embodied character can reuse identical captured facts within one accepted cut. They retain independent control tokens, connection state, transport buffers, reconnect baselines and final permission checks. Closing or blocking one window does not retire another window's valid data. A different observer does not acquire that character's private perspective. New accepted progress ends reuse rather than dressing old facts as a newer view.

The proposed reuse is below the complete player view. It grants no simultaneous-control feature and changes no account or multiplayer policy.

### C. A larger gathering still contains particular people

More participants should create possibilities for individual interaction rather than replace people with interchangeable crowd props. A player can approach a person, receive a real response and later encounter a consequence. Native reactions, actual hearing, identity uncertainty and ongoing actions keep their owners.

The present design adds no crowd fidelity switch, pushing law, automatic grouping of minds or population cap. Read-only parallel preparation may serve one crowded scene as well as dispersed activity. Physical crowding and geographical cells do not prove that all effects or audiences are independent.

### D. The world remains itself on return

Saving and reloading preserve actual current-format identities, accepted effects, remaining action progress, independent detail times and correction/forgetting. Independently evolving copies of a seed share immutable resources, not mutable consequences. A quiet place need not be rendered or repeatedly copied, but it cannot silently stop owed activity merely because nobody is looking.

Complete physical-region unloading is outside this implementation slice. Current cold-history support is not relabeled as that capability. The technical design specifies the access boundary that prevents future residency work from being confused with nonexistence.

## 4. Selected work

**J — One JSON shape preflight.** Combine two existing read-only shape traversals used by native JSON preparation. Preserve the exact size calculation, standard serializer, reservations and outgoing-only encoding. This is an isolated CPU experiment, not a new codec.

**S — One scratch owner for a synchronous encoding operation.** Compare reusing one explicitly resizable temporary reservation with constructing separate native wrapper objects for sequential measurement and serialization workspaces. Outputs and their consumers keep independent ownership. This is an isolated lifetime/CPU experiment, not a general arena, a higher allowance or permission to stop accounting for live headers.

**P — Equivalent-connection capture reuse.** Compare one actual immutable player capture for a bounded same-cut group of compatible periodic publications with independent captures. Build and authorize each complete view separately. This is an isolated multiplayer preparation experiment, not global view caching or shared personal knowledge; duplicate-tab savings do not establish distinct-player capacity.

**R — Ordered read-only rate preparation.** Complete a concrete NSC03/E2 candidate on the existing host pool. First serialize outer same-world bridge calls before they enter that pool (R0); then compare parallel status-rate selections (R1). This prevents a waiting worker from taking another call that blocks on its own world's held lock. Waiting requests keep existing admission and memory custody without occupying a compute worker. Results, reductions, mutations, random draws and identities retain native order. No parallel actor mutation or second scheduler service is introduced.

J and S's removed 128 MiB experiments have inconclusive complete-work CPU/RSS benefit. Their failures and the old stopping rule remain historical evidence; S's focused and complete held-consumer correctness passes remain scoped to their recorded identities. J/S reconsideration is now authorized at 2 GiB with fresh equal-profile controls and the complete recipes. P next needs accepted-cut compatible-capture attribution, then its designed sharing where actual callers justify it. R needs rate-phase benefit attribution, serial extraction, R0 safety and R1 ordered joins in that order. Resolve missing engineering prerequisites rather than leaving work pending because the old profile failed. Numerical targets guide repair or a specific candidate's disposition; a disproved premise does not require building an optimization or end the other work. The [technical sequence](native-runtime-foundations-tech-design.md#7-experiment-sequence-and-adoption) retains the exact ownership and evidence requirements.

## 5. Foundation contracts to preserve now

**Shared Rust–TypeScript work.** While someone walks and an NPC considers what to do, the server should spend its time on the actual physical queries, the NPC's permitted evidence and the changes that need saving. The [shared bridge design](native-runtime-foundations-bridge.md) covers local preparation answers, database reads, accepted rows, executable offers and NPC wakeups. Compare the same movements, private choices and saved consequences for each proposed reduction. Timing and memory benefits remain experimental.

**Existence, residency, activity and publication are different.** Internal calculation may assume a complete supported execution scope; every field access need not gain a new tri-state lookup. Loading/query boundaries must distinguish missing resident data from a proved absent entity, and prepare required data before entering mutation. Do not add a generic storage abstraction to all native operations.

**One mutation owner and actual lifetimes remain controlling.** Reuse immutable calculations and products; do not share a mutable candidate, replace its exact input cut, or retire an allocation merely because one reader finished. Dependent operation failure leaves existing rollback and accepted-output ownership intact.

**Order, precision and source meaning survive the port.** Keep current double-precision authoritative coordinates, world units, stable logical identities, native slot generations, exact source references, original sampling phase and saved randomness. A cell or process address is not durable identity. Body/query geometry supplies candidate facts, not character knowledge.

**Work must remain attributable and bounded.** Extend existing counters and finite admission, not per-actor tracing or a universal dependency graph. Distinguish actual CPU/RSS from reservation bounds. Required effects, optional cognition and replaceable presentation cannot be discarded under one generic overload policy.

These contracts are preservation requirements for affected consumers, not assertions that they are currently absent. The technical design names already-satisfied coverage and later extraction triggers.

## 6. What this design does not add

NRF introduces no legacy readers, old-save migrations, second database, world snapshot per observer, actor thread, cell-specific pool, universal ECS, global view cache, new model route, automatic paid retry, artificial gameplay room or independently advancing regional clock. The authorized later cell/distribution stages and their custody protocols retain the existing NSC05–NSC07 and PD11–PD12 designs; they are not a new NRF infrastructure design.

No complete physical-region streaming, new world-seed overlay engine or broad crowd-behavior design is claimed. Those need actual consumers and supported family closures. Their research questions remain discoverable without being smuggled into the current proof.

## 7. Acceptance and delivery

A candidate must preserve equivalent actual work and useful player behavior through ordinary callers, not merely identical small helper outputs. Correctness, responsiveness, resource stability, complete operating cost and human enjoyment are separate evidence. No measured population capacity follows from this document.

Proceed one coherent independent change at a time. Reuse current NSC attribution and valid correctness evidence. After actual-caller correctness and review, each candidate and prerequisite refactor receives an isolated AWS comparison before another optimization batch; include complete native/Node/database/network cost and preserve failed results. Include [the cognition-boundary comparison](native-runtime-foundations-tech-design.md#72-required-correctness), rather than infer response safety from unchanged final positions. Apply the revised [evaluation policy](../limits/native-runtime-foundations.md#nrf-l05--evidence-and-adoption): investigate regressions, repair or revert the specific unsuccessful mechanism, and continue remaining implementation. Neutral simpler correct code may remain; complexity requires justification. Do not retain a permanent experimental switch or both implementations for compatibility.

No unresolved product choice is needed to implement these experiments. Activation and adoption remain measured decisions. New pushing rules, lower-fidelity cognition, unattended-service promises or population-admission offers require their existing design owners; they are not unanswered prerequisites for this work.

## 8. Choosing whom to address and what a warning means

**Design complete, delivery open.** When the player opens Speak or Act, the composer should promptly answer whether this person can send now and, where permitted, whom they are addressing and whether to expect a reply. The world continues while the server consults the AI allowance. A listener can leave sight, become unaddressable or gain a different permitted name in that time. Show the answer licensed by the current player, target role, world and allowance. Seeing an enabled Send button makes no commitment on the player's behalf. The actual submission still checks permission, spending and execution. The [delivery recipe](native-runtime-foundations-tech-design.md#9-send-availability-and-installed-warning-interpretation) covers the advisory GET separately from command execution and view publication.

Imagine warning a companion before taking the riverside approach to the [toll tower](../repertoires/combinations.md#the-toll-tower-at-dawn). One listener knows the named place. A second heard the same words but has never visited it. The first can locate the reported danger with the precision of their own experience. The second still heard someone speak. Neither has seen the danger, learned a hidden position or agreed to follow. The player can investigate, explain further, trust the speaker or take another route. This difference between two honest witnesses is part of the reward for exploration and conversation. The tower is a play example. The deliverable exercises the supported place, actual utterance and listener in the smaller opening. It adds no scripted response, trust meter or quest.

### Player-visible acceptance

- Open the real composer for open speech, a currently perceived body, a remembered person and Act. When a listener leaves sight during the allowance check, a visible-body selection expires even if the speaker still remembers the person. A separately chosen remembered-person reference remains usable while its own evidence and addressability hold. Preserve the existing fields, refusal order, optional personally known name and routing. An unavailable or canceled check spends nothing and never speaks. Sending and deliberately retrying an NPC reply retain their own independent authority.
- Speak the supported clause at a uniquely learned place. A listener who heard it in full acquires one attributed, approximate claim of possible danger. An independently uninformed listener, missing word, ambiguity or expired interpretation yields the ordinary personal speech record alone. Reopening the world preserves what each listener learned, with correction and forgetting applied by their current owners. Incomplete access to required evidence follows the existing preparation path. The [bundled-world law](../worlds/base/perception-recognition.md#ordinary-spoken-warning-policy) owns wording and duration.
- Future mechanics can use the same evidence acquisition and journal while selecting a different interpretation at installation. A coherent world could treat these words as ordinary conversation, or use visual signs around loud machinery. The latter would need actual visible sign evidence and separately selected gameplay. The present proof accepts only the existing compiled profile. A contrasting disposable policy case checks the seam without shipping a new world.
- Keep the public packet, complete-permitted-view, model and storage contracts intact. Last-use release and allocation admission still apply when a scoped reader, a reply or a slow socket outlives the original request. Preserve the current human-visible detail. Compare each experiment independently. Actual play cost, sustained progress and human enjoyment require different evidence.

The warning seam completes the selected interpretation-design slice of [ND16](../maintainers/needs-design.md#nd16--hearing-and-communication-beyond-direct-path-speech). The wider hearing and media work has separate owners. This extends the four existing foundation experiments with two localized delivery tasks. ## 9. Seeing another player act

A companion steps out from cover. A player with sight of the companion should see the movement promptly enough to react. A bystander who heard a warning may know something different, and a player behind cover may learn nothing. In a festival the same rule lets witnesses remember different encounters. Each receives the current view earned by their character and allowed by their session. These scenarios exercise the [existing repertoires](native-runtime-foundations-evidence-and-repertoire.md#repertoire-review-all-28-catalogue-scopes). They introduce no shared omniscient audience, new sensing distance or combat rule.

Ordinary actions take effect in the live world. The acting player's command response, that player's first displayed movement, an observer's first displayed movement, and the database confirmation are distinct outcomes. The server pushes permitted changes over each connected client's HTTP event stream. A returning player gets their current permitted view. A slow reader can skip intermediate presentation frames and recover current state. Accepted actions, receipts and personally acquired history keep their existing owners and chronology.

**Designed, awaiting implementation and measurement.** Try overlapping independent players' view preparation within the current host resource budget. Preserve ordered delivery to each player, a responsive single-player session and an independent login/reconnect path. The initial evidence must cover two independently controlled players reacting to the same movement, then a bounded crowd including a slow reader. Record whether a human can actually follow and respond to the other player's motion separately from server timings.
