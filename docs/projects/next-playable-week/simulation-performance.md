# PW08 — Make repeated sight work follow the affected bodies

**Proposed implementation brief.** Engineer 1: **36 hours**, following 20 hours of reliability repairs. The engineer's separate 24-hour integration allowance is shared with those repairs, not an additional implementation budget for this brief. The [feature specification](../next-playable-week-feature-spec.md) and [technical design](../next-playable-week-tech-design.md) own the expanded week's scope; [PW08](../../maintainers/next-playable-week.md#pw08--proportional-simulation-work) owns completion. Creating this document does not authorize runtime implementation.

## Outcome and source evidence

When one bird takes off or one object leaves a person's view, the game should retain the unchanged sighting records and reusable calculations for other bodies. Brief glimpses and physical contact must still be noticed, and each character must retain exactly the evidence they were entitled to receive. This package removes three specific sources of repeated work; it does not redesign how world time advances.

Source inspection at local main `6664144a` establishes the following current paths. These are implementation observations, not new measurements.

| Current owner                                                                                     | Present repeated work                                                                                                                                                                                                                      | Deliverable                                                                                                                                       |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`kernel.ts`](../../../packages/domain/src/kernel.ts), `updateEncounters`                         | A changed member of `perceptionEpisodes[actorId]` causes `Object.fromEntries` to reconstruct the full mapping from visible subject to sighting identity. A continuing identity connects a character's observations of the same appearance. | Apply only additions and removals to that mapping, retaining continuing identities and the existing rule for a prompt return after disappearance. |
| [`motion-boundaries.ts`](../../../packages/domain/src/motion-boundaries.ts), `forgetCrossings`    | Invalidating a body's predicted path scans all cached observer/target pairs.                                                                                                                                                               | Maintain a reverse lookup from a body to its incident cached pairs, and delete only those pairs.                                                  |
| [`kernel.ts`](../../../packages/domain/src/kernel.ts), `advanceWorld` mechanical-forecast rebuild | `crossings = crossingCache()` discards every brief-sighting calculation when the shared mechanical forecast is rebuilt, even if some bodies' relevant paths, senses and geometry are unchanged.                                            | Reuse only certified certain-path pairs across such a rebuild. Every unproved dependency change takes the existing recomputation path.            |

The [proportional-step proposal](../proportional-step-work.md#where-the-time-goes-today) reported that full sighting-map reconstruction used about 18% of CPU and brief-sighting prediction about 20% in its historical staggered-flight experiment. It also reported map-reconstruction growth after adding static objects. Those measurements came from regional branch `563d0776`, before the later merged perception work, on a heavily contended host; the disposable scripts are not directly reproducible. They motivate these candidates but establish neither current percentages nor an expected speedup. The [merged perception evidence](../../verification/perception-reaction-intake.md) already records reductions in other sensory work; do not reimplement them.

## Implementation sequence and technical contracts

### 1. Attribute the current path before changing it — 5 hours

Pin the actual implementation base and record any change from `6664144a`. Reuse the native runner's setup/warm-up separation, CPU sampling, outcome tracing and actual simulated-time reporting. Count sighting bindings inserted/deleted, pair evaluations/cache hits, pairs visited during invalidation, retention hits/misses by reason, and cache sizes. Counter increments must be observational only. Reproduce the three operations above on current code before removing them. If the expected path is already absent, reconcile PW08 instead of duplicating a delivered optimization.

### 2. Update sighting identity mappings by difference — 6 hours

Keep the existing frozen-map membership certificate in `episodeMembership` for unchanged visible-person/object arrays. When membership differs, compare the current exposed IDs with the prior mapping and construct addition/removal lists. Obtain the draft mapping only when one list is nonempty. Delete departed IDs and assign new IDs in the existing exposed-array order, using the existing priority: continuing binding, recently departed sighting within the linger interval, then `perceptionEpisodeId`.

Do not replace the full mapping, rewrite unchanged values, or generate identities while merely comparing membership. Keep departures and new encounter events in their existing order. An empty resulting map has the same meaning as today; do not add a second serialized representation. Existing array/set comparison can remain linear in visible membership in this slice. Acceptance measures fewer assignments and reconstruction work, not an unsupported claim that membership detection or Immer finalization becomes constant time.

### 3. Index cached pairs by their bodies — 6 hours

Add `pairsByBody: Map<string, Set<string>>` beside `CrossingCache.pairs`. Put pair insertion/replacement/removal behind local helpers in `motion-boundaries.ts`: insertion records the key for both IDs; removal deletes the pair and both reverse memberships, removing empty sets. Replacing the same key first removes its previous membership. Invalidating several bodies deduplicates incident pair keys, deletes their tracks and removes those pairs even if one track was already absent. Do not preserve the current assumption that a missing track means no pair needs invalidating.

`copyCrossings` must copy each reverse set as well as the outer map. Immutable scalar pair/track values may be shared only while no consumer mutates them. Frozen-world forks must never share a mutable map/set or a draft entity. Removing/expiring a pair must leave no reverse entry behind; clearing the pair cache clears the reverse index. Prune expired pairs and missing/ineligible bodies during reconciliation; do not keep pairs from every past encounter merely because a global reset was removed. This derived lookup has exactly two memberships per live pair, not a second history of all past pairs. Measure pruning cost separately from incident-body invalidation.

### 4. Retain only dependency-certified certain pairs — 10 hours

A mechanical forecast predicts movement and changing needs until the next relevant moment. Rebuilding that forecast must no longer imply that every sight/contact calculation is invalid, but it also cannot establish validity. Replace the unconditional reset with a reconciliation call after current values are materialized and before the next sensory bound is used.

Store copied certificates with retained tracks/pairs. At a shared rebuild, rederive current eligible movement using the existing flight/walker/flee owners, without the early cached-track shortcut. Compare the newly derived certain path against the old path over the remaining absolute interval `[now, pair.until]`. Compare piecewise-linear paths at the union of their future breakpoints translated to that interval, with the existing motion tolerance, and require both paths to be certain throughout that interval. A matching position at the current instant is insufficient. Retain an old pair only while its covered interval contains the entire requested slice; never extend its expiry on the strength of a certificate. Recompute normally when the interval is exhausted.

Retain only the existing certain-path branch in this package. Clear uncertain-outcome memoization at shared rebuilds; it keeps its present exact-track-signature behavior within a forecast. Do not attempt to prove equivalent collections of possible flight outcomes. This provides a conservative fallback while removing expensive repeated exact pair work where ordinary fixed paths remain valid.

| Dependency                                     | Required certificate/check                                                                                                                          | Invalidation rule                                                                                                                                                                                                       |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Absolute simulated time and predicted movement | Original interval, actual pose and certain path over the retained interval; current route/flight/wait state is interpreted through existing owners. | Missing body, expired interval, changed/deviated path, uncertain prediction or unsupported movement invalidates the body's incident pairs. Hover transitions must not reuse the arriving movement as a stationary path. |
| Perception eligibility                         | Observer alive, remembering and actively participating; current perception capability; target eligibility; current participant membership.          | Death, removal, lost capability or changed participation removes affected tracks/pairs. Reentering bodies recompute.                                                                                                    |
| Senses and body geometry                       | Current sight radius, eye height, sample heights, contact capability, body height/radius/interaction heights and the relevant pair kind.            | Changed values invalidate incident pairs even if positions are identical. Resolve values through existing world/body/sense owners.                                                                                      |
| Occlusion/contact geometry                     | Existing immutable spatial-map/geometry identity or revision that covers every input read by `visionRuns` and `contactRuns`.                        | Map or barrier change clears affected calculations; use a full clear when existing ownership cannot safely localize it. Do not infer map stability from a world clock alone.                                            |
| World rules and definitions                    | Identity/revision of the currently resolved sight/contact policy and definitions, including sample geometry.                                        | Changed definitions/rules clear the cache. If no reliable existing revision is available, compare copied required values or recompute; do not introduce a writable policy authority.                                    |
| Fork, restore and command lifecycle            | Cache belongs to one native continuation; command/dependency changes must be revalidated before use.                                                | Copy on frozen continuation fork. Rebuild after load/restore; never serialize or restore the cache as authority. Unknown invalidation takes the full reset.                                                             |

The certificate must cover the functions actually called in the final diff. Document every input beside the helper and review new dependencies there. Pair retrieval still checks current eligibility and certificate validity; successful retention during a previous rebuild is not permission to skip subsequent changes. A cheap conservative rejection is acceptable; a missed glimpse is not. If all meaningful pairs fail certification, report that result and revise this substep before claiming it delivered a performance improvement.

### 5. Verify outcomes and full-server effect — 9 hours

Use the applicable existing checks in [`perception.test.ts`](../../../packages/domain/src/perception.test.ts) and [`kernel.test.ts`](../../../packages/domain/src/kernel.test.ts), plus the smallest additional operational scenarios needed for the cases below. The sight-boundary and JSON-restore checks cover only part of the contract; do not claim they exercise new cache retention. Do not reconstruct all eleven disposable regional experiments or author a broad new regression suite. Preserve required CI gates and perform TypeScript/build checks appropriate to the final touched files when implementation is authorized.

Compare baseline and candidate with the **same call schedule**. For each semantic scenario run 30-second offers, 1-second offers and a whole-span offer where the API permits it; compare each candidate to its corresponding baseline, not to a different call schedule. Existing call-size-dependent behavior is not silently repaired by this optimization. ## Acceptance, effort and remaining risks

PW08 requires all three implementations, passing relevant semantic rows, attributable reduction in their operation counts, and matched native plus real-server evidence. Publish exact observed improvements and regressions, not a promised percentage. A result within measurement noise may establish removed redundant work, but must not be described as a measured end-to-end speedup. Investigate material regression rather than hiding it in an average.

The allocation is **5 + 6 + 6 + 10 + 9 = 36 hours**. Expected runtime/profiler changes are approximately **350–600 logic lines**, excluding tests and documentation; reassess after the baseline. The largest risk is an incomplete certain-path certificate. Full recomputation remains the correctness fallback. If complete certification or required evidence exceeds the allocation, report the unfinished contract to the coordinating engineer; do not silently omit it or close PW08 from the two easier changes. Use the separate integration allowance for combined-branch review and checks, not a speculative scheduler expansion.

Cannot be committed as outcomes now: a numerical speedup, dense 8× capacity, constant-cost publication, full large-world locality, exact approach timing, or completion of proportional-step stages 2–3. This planning task ran no simulation or server benchmark.
