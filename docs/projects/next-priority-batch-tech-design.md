### One failure translation, with evidence about dispatch

Use a small internal classifier receiving the caught typed error or validated terminal inference, receipt, abort cause and verified execution stage. This is reusable transport/application meaning, not a new event system. Stage information stays local to execution and the existing durable operation/Run records; it is not a second stored authority.

Preserve separate caller and deadline signals before combining them, and retain the actual first abort cause. A timeout must not become user cancellation just because both signals are exposed as `signal.aborted`. Every exit finalizes timestamps/latency and keeps its original request/Run identity. Use stable bounded reason codes internally; show safe plain messages through existing job/diagnostic presentation. For a verified terminal timeout or cancellation, preserve the explicit timeout/cancellation meaning and the separately proven execution state. In particular a confirmed ended timeout is `failed` with `deadline_exceeded`, not an assertion that the caller cancelled; a confirmed ended caller cancellation is `cancelled` with `completionUncertain:false`. A malformed transport envelope that cannot establish final completion remains uncertain even if its local parse error is known. The director's current precedence—uncertain completion dominates other non-cancellation failures—remains intact.

`dispatched` is conservative evidence that this external attempt may have begun, not a model's assertion about itself. Do not set it false merely because an accepted Run reports `provider_outcome:not_invoked`: preserve any actual intermediary charge and its original Run identity. Known HTTP rejection rules remain route-specific. Existing explicit native worker-conflict allowlists remain explicit; generic 409, 5xx, read timeout, reset, or JavaScript `TypeError` does not prove non-dispatch. A refused connection can be classified as known non-dispatch only if the transport supplies trustworthy evidence that no request could have been accepted; otherwise retain uncertainty and state that limitation.

The durable `mutation` journal must not become a retry grant. On a rejected admission, preserve the recorded rejection and original fingerprint. On a possibly accepted operation, leave its unresolved identity intact. If rejection persistence itself fails, existing operational recovery remains conservative; do not manufacture a successful journal update.

### Cost evidence and exact settlement

Keep the ledger's integer microdollar unit. Add narrowly shared decoding/conversion helpers in the existing provider/accounting ownership path, with no dependency from `packages/ai` into server code. Provider decoding rejects malformed evidence; `store.settle` independently refuses to treat an invalid amount as a usable charge so a missed adapter check cannot break financial integrity.

1. **Microdollar strings:** accept only nonempty decimal digits representing a nonnegative integer. Reject whitespace-only/blank strings, signs, fractions, exponent notation, non-digits and unsafe magnitude. Parse/check with integer arithmetic before conversion. Leading zeros are harmless numeric representation; they are not missing data. Zero is valid only when explicitly present in otherwise valid evidence.
2. **USD numbers:** accept only finite nonnegative numbers whose conservatively rounded microdollar amount is safely representable. Retain the current round-up policy for fractional microdollars; never subtract an arbitrary epsilon to make charges smaller. Convert the reported numeric value through its decimal representation or an equivalent checked method so binary floating-point multiplication does not invent an extra fractional microdollar; apply upward rounding to the actual represented decimal amount. Centralize this conversion so admission, settlement and decision accounting use consistent arithmetic.
3. **Magnitude and aggregation:** every amount and each sum must fit the JavaScript safe-integer range used by application arithmetic as well as the database column. Check before conversion/addition; individually safe rows can overflow a total. For provider microdollar strings converted through the existing numeric USD receipt field, require lossless recovery of that integer amount by the same conversion helper. If the public number cannot represent the original amount reliably, keep it unpriced rather than silently round down or add a second receipt schema. This is arithmetic validity, not an operator spending cap.
4. **Source authority:** costs come from the configured route's validated provider/Run usage records bound to the original accepted request, never model prose, a client value, or an unrelated Run. Check the returned status/terminal result identity before interpreting its prices. For BYOK, a zero platform model charge is not a zero provider invoice. Preserve the existing separation of complete provider-model usage and other attributable charges; do not add provider-inclusive totals twice. Managed Run cost uses the verified Run's actual managed charge; lower-level token estimates are not permission to replace a contradictory or missing authoritative bill with a cheaper amount.
5. **Unusable evidence:** omit invalid cost from the normalized receipt and retain a safe diagnostic reason; do not write `NaN`, infinity, `null` masquerading as a price, or a negative amount. The original raw cost need not be copied into gameplay diagnostics. A validated final output may still be usable under existing caller policy while its price remains unknown.
6. **Settlement:** an undispatched request settles to zero; a dispatched request with uncertain completion or missing/unusable price retains the original conservative reserve under the existing uncertain status; a completed request with usable price settles to that price even when its output was invalid/refused/failed. A valid over-reserve actual charge remains recorded rather than clamped away. Reconciliation affects the same original attempt and cannot dispatch again. Existing repeated-final and later-authoritative-receipt semantics remain; an invalid late receipt must not overwrite a valid final charge.
7. **Consumer consistency:** normalize at the adapters and protect the authoritative ledger. The decision ledger, diagnostics and usage summaries must not display the rejected numeric value as an actual charge while SQL retains a hold. Reuse the same validity/conversion meaning without a second wallet or independent charge counter.

`captureRunUsage` currently checks each microdollar string before summing. This assignment also checks the sum and the complete-result requirement; it must not silently add a truncated usage page. Existing incomplete/paginated usage remains unpriced until the owner provides complete attributable evidence. This task does not add a general financial-history pager or import invoices.

### 1. Bind a disclosure grant to the original direct conversation

Create volatile preview state only for a live `chat` job submitted by an authorized player, after the existing native speech trigger and scoped decision preparation have succeeded. Capture original request ID, actual attempt number/generation, world/load identity, authority/account/actor/control identity, responding NPC, and the already established direct conversation or original player utterance. Use the actual existing conversation identity; do not invent a parallel relationship or history store.

No preview grant is created for a thought/reflection/invention/background job, Jev selection, unbound conversation, absent or revoked requester, or unsupported route. This restriction affects display only: existing response generation and final admission stay available.

The operation grant is narrower than the job grant. Release no string fragments. Buffer until the first operation object closes, reject duplicate keys, and strictly validate that complete object against the operation schema from this exact request. Release text only when all of these facts are established:

- Its safe unique `localId`, empty `requiresAccepted`, and the allowed speech variant; all other operation kinds are null.
- A `talk.addresseeEntityId` exactly equal to the requesting character, a valid supported `volume`, and a valid nullable `selfIntroduction` value. Self-introduction metadata is never applied during preview.
- It is the first operation, parsed as a complete closed object and validated against the exact request-scoped operation schema; there is no speculative prerequisite execution. Initial private thought/note or earlier speech means this first release stays final-only.

Verify authority and exact attempt currency before every publication. Both actors must still participate and remain alive/able to speak or perceive as applicable; reuse current restrictions. The same pure `speechPerception` query must return clear current hearing at the parsed volume. Require known/visible speaker attribution already permitted to the player's Talk interface; do not disclose a new identity from an acoustic bearing or a canonical name. Partial/none/unknown hearing stays final-only. A query failure or incomplete coverage is no grant.

Re-evaluate the gate on relevant world/control/access changes and immediately before emitting a queued snapshot. If it stops holding, retire this attempt's preview and clear the browser's provisional text; do not later resume the old prefix after the player returns. The final generated decision can still be admitted according to its ordinary rules. This is deliberately conservative; walking away is not cancellation of already funded provider work.

### 2. One bounded deterministic JSON decoder

The server schema owner declares the exact eligible path `operations[0].talk.text` and its required siblings; the generic decoder accepts an explicit path/metadata contract, not arbitrary dotted strings from a model or client. Private `think.text`, `note.text`, action descriptions, goal objectives, nested JSON-looking strings and additional operations are never eligible.

Do not parse with regular expressions, repeated `JSON.parse` of guessed prefixes, or substring searches for `text`. Use an incremental UTF-8 decoder and JSON lexical/structural state: object keys, arrays/indices, strings, escapes, numbers/literals and nesting. Decode escaped text exactly once. Retain incomplete UTF-8 sequences, `\\u` escapes and surrogate pairs until valid; never display half a code point. Unknown fields/duplicate keys/malformed structure retire preview eligibility; final whole-body validation still decides the request result.

The existing schema declares `talk.text` before recipient and volume. Reordering properties is not a disclosure guarantee: an untrusted provider can reorder or duplicate keys, or supply an incompatible operation field afterward. Do not change schema semantics, force the target, reorder properties as a claimed safety fix, or expose partial text based on metadata that arrived first. The safe unit in this task is the **complete closed and validated first operation**, not the text field or a JSON prefix. The parser rejects duplicate keys at every object level; a later duplicate root `operations` key invalidates the whole response rather than replacing an earlier operation. Later malformed content still invalidates final completion, but cannot reinterpret the already closed operation's recipient.

The validated operation can be published before subsequent operations, provider terminal reporting or complete-envelope validation arrive. This is a narrower latency opportunity than word-by-word streaming. Single-operation responses may offer no meaningful early text. Retain final-only operation in that case and measure the actual improvement. A separate public-output channel with server-fixed disclosure could support earlier fragments, but is not added here and would require a new accepted response contract.
Use existing response/schema limits as input bounds, including the active level's output byte/token envelope, 16-operation domain limit, speech's 1,200-character generation/admission bound and the adapter maximum response bytes. Stop preview on limit overflow; do not truncate a speech into a falsely valid final result or spend on a repair. Keep only bounded first-operation buffer, selected validated text, bounded parser metadata and the bounded raw final-output representation already needed by the adapter. Never retain every prefix or every network frame.

The outer structured response can become invalid after one closed, validated speech operation was shown. That possibility is the disclosed provisional behavior; complete operation validation, strict field allowlisting and current recipient authority remain prerequisites, while final envelope validation remains essential. The displayed operation is not claimed to be an admitted deed. No decoder claims an unfinished operation is safe merely because its text prefix parses.

### 3. Provider transport and receipt preservation

Extend `GenerateRequest` with an optional internal progress callback accepting normalized generated-text fragments or a replacement snapshot plus stable transport sequencing. Its callback is not serialized into prompts or supplied by clients. The generic AI layer knows about generated text and transport, not NPC audience, world policy or speech effects. It continues returning exactly one final `AiResult<T>` and one authoritative receipt.

For direct OpenAI, use documented response-stream events and obtain the terminal response and usage under the existing request ID, model, schema, deadline and cancellation. Ignore reasoning/tool/unknown-content channels. For the configured Macrofold direct-inference route, verify the deployed native streaming contract first, then consume only its documented model-output channel and final inference result. Do not treat the owner Run `output.delta` format as a direct-inference protocol. If full-harness or another configured route lacks a qualified structured-output stream, retain its existing final-only path; never change models or replay the request to manufacture a preview.

Upstream EOF, connection loss and an output fragment are not successful completion. Validate the complete final output with the same schema, run existing response parsing/reference binding, then native commit. Preserve usage, unknown charge exposure, terminal classification, cancellation and the original dispatch identity through the current receipt owner. Preview callback/slow-browser errors cannot make a successful paid request execute twice or turn unknown cost into zero. NP01's adapter classification work remains separate and is not replaced here.

Transport reconnect, where the current provider supports it, resumes the same existing call under its documented cursor/idempotency contract. A non-replayable direct stream is not automatically retried. The browser can reconnect to local snapshots without reopening a provider request.

### 4. Separate private preview projection and bounded transport

Add a typed private preview projection alongside existing job reads, with exact scope identity, original request, attempt/generation, sequence, speaker's observer-safe label, allowed text and state (`forming`, `withdrawn`, or `settled`). Stable correlation IDs are wire fields only, never visible prose. The server derives all identities from the authenticated job; caller parameters locate a job and grant no access.

Use a narrowly scoped read/stream endpoint under the existing authenticated HTTP/connection limit owner. It is private to the requesting principal with current character control and current world/timeline. Recheck before and after awaited snapshot reads and on each publication. Do not put draft words into global simulation SSE, public events, ordinary diagnostic job messages, PostgreSQL conversation rows or owner-session records. The requester can have multiple authorized browser connections, but those do not create more inference or more preview history.

Retain at most one current preview snapshot for the actual running generative attempt. Existing director concurrency bounds still apply; no preview queue that outlives jobs. Publish only actual preview lifecycle changes, not every provider chunk, and keep one replaceable queued snapshot per connection. This closed-operation slice needs no new per-token polling or durable-write cadence. Use the existing connection cap, heartbeat/backpressure closure and frame ceiling rather than a new unbounded token log. The selected text cannot exceed the existing speech limit. Snapshot notifications do not rebuild the whole `GameView` for each token.

The volatile preview is intentionally absent from saves and recovery checkpoints. A reconnect while the same process/attempt is active can fetch the latest permitted snapshot. A server restart drops previews and presents normal recorded job recovery/final history; it does not resurrect draft words or resume paid work. No new durable preview table, replay cursor archive or compatibility reader is needed.

### 5. Final admission and browser reconciliation

Before `commitActorResponse`, retire the producing callback so late frames cannot extend the prefix. Keep normal current-state and evidence validation. A final body matching the schema is not proof that the speech operation was accepted. Read the existing response component receipt and committed utterance identity to determine actual speech; remember that not-heard directed speech can fall back to an actual ambient utterance and still be unavailable in the requester's heard history.

At final commit, resolve the server-only native utterance identity `${responseId}:${localId}` to the actual emitted speech event(s), then to the requester's permitted heard-history entries. Include those existing public `ChatMessage.id` values in the private settlement notification. `PerceivedSpeech` has no utterance ID, and `replyRequestId` is attached to the player trigger; do not invent `speech.id` or match text. The client refreshes its permitted conversation history and replaces/removes the preview using the returned actual history IDs. This needs a small explicit server correlation seam, not a new stored speech schema or private event disclosure. It never manufactures `ChatMessage` text from the provider result. Until history catches up, show a non-text pending reconciliation state; do not leave provisional words looking final. Two final speech operations produce their genuine two history entries, not two plus a preview.

No-speech output, a different recipient, private-only decisions and native refusal do not become a fake message. Preserve the existing distinction between technical failure, silence, another chosen action and a player who could not hear. On stale/revoked/control/load changes, clear sensitive text immediately. A late settlement for an old request must not remove a newer attempt's preview or affect another NPC's conversation.
