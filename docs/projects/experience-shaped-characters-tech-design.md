## 1. Selected experience and boundary

A quiet travelling companion begins to enjoy taking a slightly longer route with a particular person, although they still decline an outing that would frustrate their own work. A precise rival gives useful criticism, then asks the person who beat them to watch a later attempt. Someone keeps an earlier refusal in memory but becomes less certain it meant dislike after hearing a later explanation. A resident decides that making something was enjoyable even when nobody praised it. These are possible developments through actual life, not predetermined rewards for the player's inputs.

The implementation must connect **permitted experience → revisable current understanding → a later real opportunity → independently selected and executed conduct**. Each arrow already has a semantic owner. A new state machine that tries to guarantee a transformation would weaken that ownership. The selected design therefore reuses existing memory, self-understanding, directional notes, native feelings, goals and action execution, and qualifies the complete connection.

EC selects no universal personality axes, numerical growth, new relationship meter, per-lesson record, new physical action, new daily maintenance pass or additional model allowance. It does not make the player a therapist or require a person to improve morally. A joyful habit, sharper taste, worthwhile rivalry, narrower expectation, different ambition or continued disagreement can all be a useful result. A person can finish an activity, remain grateful and leave for their own life.

Ordinary companionship, pleasure, initiative and delayed social consequences already belong to [compelling characters](compelling-characters-tech-design.md) and the [first-playable people](../worlds/base/first-playable-people.md). EC adds their selected longitudinal qualification and older reinterpretation; it does not postpone those earlier obligations. Dreams, a reviewable human reflection aid and deliberate coarsening remain independently deferred EC05/EC06 consumers. They are unnecessary for EC01–EC04.

The existing `InnerWorld` stores `text`, `revision`, `files`, `sourceSnapshot`, `publicationJobId`, optional `publicationBody`, `evidenceIds` and optional `reconsiderationRequired`. The current snapshot has publication-level provenance, not a separately validated citation for every sentence. This is adequate for the selected conservative invalidation policy. It cannot establish exact causal attribution for an arbitrary prose claim or justify selective retention after a source is removed. No per-claim dependency graph is selected merely to make that stronger claim.

The base-world author owns traits, protected origins, individual interests, actual starting knowledge and opportunities. Another world can select a different coherent person without changing the publication mechanism. The trusted reflection contract owns distinctions between self-understanding, testimony, inference and world effects. Native integrity does not hard-code a psychological response to an event type. These boundaries apply the existing [engine/world decision procedure](../engine-and-world-boundaries.md#5-a-repeatable-boundary-decision).

An accepted reflection with unchanged files can still have a valid publication identity, advance the existing revision/timing bookkeeping and append its permitted short thoughts. That is maintenance, not evidence of character development. The feature records no special growth event and does not schedule another inference merely because current self-understanding changed. A genuine typed goal or other semantic change retains its existing ordinary scheduling consequences.

## 4. Reflection input and proposal contract

### Preparation and source coverage

Reuse `prepareDecision` as called by the existing background reflection path. It flushes pending personal sources, captures the world generation, assembles current perception/body/agency, includes required outcome evidence, current general notepad and the complete accepted `aboutMe`, and uses existing actor-scoped recall and conversation preparation. Required context is checked before optional compaction/selection; overflow refuses explicitly. Optional selection must not replace the current self-understanding with a summary of selected old paragraphs.

**Inspected gap and selected EC03 repair:** current `ReflectionRequest` contains only `actorId`, `origin`, `reason` and `at`. Both semantic routing and significant-event intake in `ai-director.ts` can enqueue an opportunity, but `reflect()` passes only its reason and an empty required-ID array to `prepareDecision`. A later explanation can therefore lose the exact source that prompted it, and an older association selected during the initiating decision is not retained by that handoff. Current idle recall remains useful, but it does not establish the selected source-bearing case. Implement the following inside the existing queue, decision preparation, knowledge and recall owners; there is no new inference stage, reflective retrieval endpoint or memory store.

1. **Retain an actual initiating binding.** Extend the existing queued request with an optional metadata-only source bundle: current world timeline, the existing actor-scoped `MemoryScope`, an optional exact triggering `CurrentMemorySource`, the exact source-family/ID/revision references actually supplied to the initiating judgment, and the document ID/subject/revision of the subject notes actually supplied there. Expose this already-prepared metadata from `prepareDecision`; do not reconstruct it from prose or copy the prompt, note text or historical source bodies into another pad. Semantic routing passes its admitted bundle. Significant-event intake passes its actual observer-permitted triggering sources. A native-downtime opportunity carries no invented episode or older association and continues to use ordinary optional recall. No evaluator-selected event ID, target lesson or another person's private source may enter this bundle.
2. **Keep one current queued opportunity.** Preserve the existing per-actor queue and earliest waiting time. Coalesce by the complete source-bundle identity as well as the reason; equal text with different actual evidence is not a duplicate. The newest admitted bound opportunity in the actual serialized queue order replaces the pending bound bundle as one unit, with the replaced coverage recorded in the existing private diagnostic; do not accumulate an unbounded union. An unbound idle request does not replace a valid bound cue. Claim/remove only the bundle actually admitted, so an older start cannot erase a concurrently queued replacement. The existing attempt/day, admission, eligibility and spending rules still govern. Restore, forgetting or correction cannot turn this operational pointer into a fresh authorized source.
3. **Bind before reading and dispatch.** Flush pending sources and check the queued timeline, current actor scope, each source-family/ID/revision and selected subject-note revision through their existing owners. A stale or unavailable bound cause retires that targeted opportunity with its actual reason before provider dispatch; it neither reuses the stale reason as evidence nor buys an automatic replacement attempt. Pass the exact current trigger through `triggerEvidenceId` and the admitted source references through the existing required-recall preparation. Carry their complete source identity through `MemoryRepository` selection, `RecallService` candidates and final validation; reducing them to a raw ID and accepting another source family is invalid. The relevant existing CR05 source-identity correction remains at that owner. Refresh actual subject notes through the current knowledge path; a document-only reference permits revising remembered prose without making an unrecognized person's present body targetable.
4. **Resolve an already-retained older association once.** A current involved or otherwise actually selected subject note can already contain supporting `evidenceIds`. EC03 adds one indexed lookup of those IDs through the existing required-source/recall owner, sharing the same request-local read cache and allowance. Preserve the note's current revision, classify every returned source by its actual family and precision, and supply the admissible association through that same prepared context. Do not recursively expand the returned sources or every accepted-mind publication, enumerate the person's lifetime, infer new causal edges from wording, or treat the note's broad support set as proof of an individual sentence. If a stored raw ID is ambiguous across source families, record that association as unresolved until the existing owner supplies exact identity; never pick one silently. An old refusal present in this actual note's permitted supporting history can thus reach reflection even after leaving the recent tail. The actual later explanation stays a separate heard source.
5. **Preserve limited or absent recollection.** The one-hop lookup and the retained bundle share the current repository preparation envelope of 8,192 rows / 4 MiB and the final context allowance; they receive no extra per-consumer budget. Carry preparation accounting across these reads: the current request-local cache bounds its residency, which alone does not bound total rows examined or repeated hydration. A required association that cannot fit refuses or defers that targeted preparation explicitly instead of silently dropping part of its support. Missing historical support in an otherwise current note is reported as missing, rather than fabricated from a saved pointer. If only a retained summary or present assessment is available, supply it with that label: it supports qualifying the assessment without restoring unavailable scene detail, precise quotes or an unrecorded original reason. If no source-bearing association exists, the ordinary bounded query uses the actual stimulus, current goal and accepted self-understanding; optional selection can find relevant history, but no result is not a choice to ignore it. The broader ND20 retrieval work remains conditional on its own demonstrated need.
6. **Record coverage without manufacturing a memory.** Extend the existing private preparation diagnostic with initiating cue/scope, requested and actually admitted source identities/revisions, selected note revisions, the one-hop lookup's returned/missing/ambiguous sources, raw-event versus summary versus assessment-only precision, optional omission, overflow and stale status. Revalidate admitted sources and notes after awaited work and at publication. The log follows existing actor/privacy access and erasure; it is not a new witnessed event, growth record or public source browser. EC01/EC03 compare this coverage with the actual retained episode before classifying no change, interpretation or publication quality. They never buy repeated reflections to force recollection.

The semantic instructions and world-authored text below change only where their baseline exposes a gap. The source-bearing handoff above is explicitly selected missing runtime work. It chooses evidence already available to this person, never what that evidence must mean.

Current appraisal preparation offers at most 48 selected evidence sources and the active-appraisal page returned by the existing owner. That first page is not all retained feelings. A proposal can use only the actual supplied source/policy/feeling handles; it cannot invent an identifier for an omitted record. An otherwise useful reflection can keep existing feelings unchanged. If a selected case needs an omitted current feeling, the missing preparation is an explicit ACT/CR consumer issue, not permission to silently enlarge the limit or treat absence as emotional resolution.

### Selected meaning within the existing trusted task

Keep the existing complete reflection contract, protected-identity rule, workspace grants and output schema. Add or clarify the following meaning through that owner when implementation compares the baseline; these are full semantic requirements, not separate tools or mandatory output headings:

1. Consider what the supplied actual experience means for this particular person's present self-understanding. Joy, curiosity, accomplishment, companionship, disappointment and disagreement are all legitimate material. A useful reflection can change nothing.
2. Keep another person's current characterization in that person's permitted subject note. Keep a self-oriented tendency or value in mutable self-understanding. Do not reproduce the whole incident in both documents. A practical plan or goal uses its typed owner when genuinely intended; prose alone cannot create it.
3. Preserve the scope of the evidence. One respectful encounter can support a tentative exception with that person; it does not prove everybody is safe or that future help is wanted. Repeated real encounters may form a broader pattern. A consequential incident may support a larger change without an automatic event-to-trait formula.
4. Distinguish what happened, what was later said about it, and what is now inferred. Preserve uncertainty, mixed evidence, the possibility of misunderstanding and the meaningful consequence of the earlier event. Quoted dialogue requires supplied exact words; a summary supports only a summary.
5. Recalling the same source or its derivative again supplies no independent corroboration. A new utterance is nevertheless a real new social act: repeated pressure can be annoying, and a later sincere attempt can matter. Distinguish that new act from proof of its repeated claim.
6. Keep room for an independent life. Enjoying someone's company need not create a promise, permanent availability, confession, romantic wish or obligation. An earned change may be wanting a different challenge, keeping a private pleasure or deciding a completed project was enough.
7. Retain protected origins exactly, and write only permitted mutable files and typed changes. A current exception can qualify an authored tendency without rewriting childhood, installing a skill, enrolling a native feeling process or prescribing the next action.

These instructions describe permitted interpretation. They do not direct the model to produce a particular lesson, output “growth,” repeat a named future line or maximize transformation frequency. The world profile's illustrative later outcomes and evaluation rubric stay outside actor instructions. Ordinary players can communicate their own wishes through actual speech, with the usual untrusted-content treatment; those wishes do not become the trusted evaluator's expected answer.

### Native output and acceptance

The existing reflection harness edits only its actor-scoped `mind/*.md` workspace. The final response retains the existing 1–3 short thoughts and optional `knowledgeChanges`, `nameChanges`, `goalChanges` and `appraisalChanges`. This feature does not add an `outlookChanges` JSON family. The harness returns proposed files; native publication checks all existing protected documents exactly, file names/content bounds, thought shape and supporting source/permission restrictions.

`publishInnerWorld` receives the expected current inner-world revision, publication job identity, snapshot, files and admitted typed changes. Identical replay of the same job/body is a duplicate with no additional effect; the same job with a different body, changed prior revision or invalidated prior publication is rejected. Native note edits require the exact current note revision. Goal edits use existing revision/state transitions. Appraisal operations use the supplied policy, current record revision, allowed subject and actual cause binding. A failure in any of these reflection components rejects the proposed publication as a unit. This atomicity concerns reflection; it does not roll back previously heard conversation or already executed actions.

The server revalidates actor/body/controller eligibility, generation, current source bindings and live unresolved commitments at publication. `prepareDecision` also binds relevant action outcomes and remembered participant recognition; correction, newly relevant outcomes or lost exposure cannot be bypassed by a plausible old answer. Appraisal binding checks current source revisions, installed policy, appraisal state, knowledge revision and ownership. Publication runs through the existing serialized world transition and durable state owner; no additional writer or background queue is selected.

The current native schema cannot prove that arbitrary prose is psychologically convincing or factually proportionate. Supplying evidence and checking references establish access and freshness; they are not a semantic truth oracle. Unsupported or formulaic prose that passes those mechanical checks is a quality failure to diagnose through the existing instruction/context owner. Do not claim it is automatically rejected, and do not add a paid model checker merely to endorse it. EC04 qualifies the complete behavior before claiming this feature delivered.

## 5. Later use, observation and player interaction

Ordinary NPC decision and conversation preparation already include the complete current `aboutMe`, current native feelings, body, goals and current agency. The general notepad is included; required/currently involved subject notes and selected remembered material retain their existing knowledge/recall scope. Use the accepted current revision after an awaited preparation, then native execution rechecks its own current prerequisites. An old cached prompt cannot become the next character state.

No specific action is automatically promoted because the self-understanding text changed. The existing offered action/interaction set remains governed by the body, exact items, knowledge, geometry, participants and world law. The model can choose among those real opportunities and may propose a genuinely desired native goal. For example, a person who now values a rival's judgment can ask them to watch an actual next attempt; they cannot create a contest, seize the rival's time or acquire an unknown method by describing that wish.

The selected base-world scenes reuse actual walking, local conversation, observation, making and sling practice. Companionship may use the already selected outing/guidance owner where that interaction is available. A request can be meaningful even when declined. Actual arriving, waiting, shooting, hitting/missing, making or stopping remains with its native owner. PC04's delayed-shot observation repair remains a prerequisite for claiming completed coaching; EC's rivalry scene can compare actually witnessed independent practice without pretending the repair is delivered.

Players discover a difference through particular speech and visible choices in places and activities they already understand. There is no new friendship dashboard, growth badge, personality control, compulsory confession or prompt asking the player to optimize a resident. Existing action panels show actual practice/making/offer controls and accepted activity state; opening them performs no inference. A private thought or personal note appears only to its permitted audience through existing surfaces. Public narration may describe a seen smile, departure or spoken joke only when that expression/action actually occurred; it must not reveal a hidden motive because an inspector could read it.

For a later return, stable individual recognition is required where the scene depends on knowing it is the same person after lost exposure. Use the selected SPK recognition owner; a familiar-looking display name is not a substitute. Failure to recognize a person cannot be repaired by placing the hidden runtime ID or their undisclosed history into a model prompt. Report the actual availability/dependency in the episode evidence.

Human control remains meaningful. If the human inhabits Ada or another participant, automatic NPC reflection does not rewrite that human-authored account. The human chooses their own conduct and existing editable narrative. The counterpart NPC can still develop its own understanding from the encounter. Remote correspondence and its additional privacy scope are separately designed consumers, unnecessary for these in-person episodes.

Define acceptable alternatives before observing the result. Do not place the desired later line, change direction or evaluator rubric into character instructions. Counterfactual variants change one relevant experience while keeping comparable initial perspective and opportunities; they do not force later worlds to stay identical after different choices.

The selected minimum coverage is **all five profile families**: enjoyable company, useful rivalry, self-directed satisfaction, later explanation of an old refusal, and a mixed/contrary encounter. Include an unchanged-evidence control, a different-person control, unavailable reflection, and a long enough intervening activity to establish a real later opportunity. Predeclare repetitions, held-out group splits and any acceptable cost/quality threshold before paid evaluation, under the existing CE05/CR12/AG12 owner.

An individual unchanged outlook or refusal can be entirely convincing. At least the selected positive companionship and an independent/solitary or rival family must show recognizable, evidence-sensitive later conduct in observed episodes, with the contrary/control results retained. Review whether the player can recognize the person and enjoy their own activity without being taught to grind a transformation. Human judgment concerns the chronology, available choices and visible consequences, not recovered hidden reasoning. A privileged diagnostic can establish which accepted revision and sources the later decision actually received. It cannot prove the model's private causal process, and an eloquent explanation is not a substitute for the observed choice. No paid comparison, runtime trial, player study or performance benchmark was performed for this design.

## 10. Tradeoffs, extension seams and decisions

This design chooses a concise revisable account using existing owners. It avoids maintaining a trait vector alongside prose whose authority would be unclear, or a permanent lesson list that grows on every encounter. It accepts that freeform meaning needs empirical quality evidence and that current conservative erasure can lose useful unrelated interpretation. Those are explicit limitations, not unimplemented promises hidden in new schema fields.

A later exact-provenance feature needs a real selective-retention consumer before adding sentence-level links. A new activity requires its own native behavior before it can become a meaningful character opportunity. A later dream or human aid can reuse permitted state, but must preserve imagined versus remembered meaning and explicit human authorship; it cannot inherit an automatic publication permission from NPC reflection. Richer thought/familiarity presentation should be justified by players missing useful visible continuity, not by a wish to expose internal implementation.

There is **no unresolved product-owner decision for EC01–EC04**. The remaining work is implementation diagnosis and separately authorized qualification under existing spending and data policies. No operating promise, adult-content policy, human privacy boundary, audience choice, platform choice or retention policy is reopened by this selected design.
