This pair completes the selected design for **DG23**, the revisable-personality slice of **[ND04](../maintainers/needs-design.md#nd04--experience-shaped-personality-and-practical-skill-growth)** and the older-interpretation slice of **[ND19](../maintainers/needs-design.md#nd19--older-memory-transformation-and-dream-reinterpretation)**. ## 1. Selected experience and boundary

A quiet travelling companion begins to enjoy taking a slightly longer route with a particular person, although they still decline an outing that would frustrate their own work. A precise rival gives useful criticism, then asks the person who beat them to watch a later attempt. Someone keeps an earlier refusal in memory but becomes less certain it meant dislike after hearing a later explanation. A resident decides that making something was enjoyable even when nobody praised it. These are possible developments through actual life, not predetermined rewards for the player's inputs.

The implementation must connect **permitted experience → revisable current understanding → a later real opportunity → independently selected and executed conduct**. Each arrow already has a semantic owner. A new state machine that tries to guarantee a transformation would weaken that ownership. The selected design therefore reuses existing memory, self-understanding, directional notes, native feelings, goals and action execution, and qualifies the complete connection.

EC selects no universal personality axes, numerical growth, new relationship meter, per-lesson record, new physical action, new daily maintenance pass or additional model allowance. It does not make the player a therapist or require a person to improve morally. A joyful habit, sharper taste, worthwhile rivalry, narrower expectation, different ambition or continued disagreement can all be a useful result. A person can finish an activity, remain grateful and leave for their own life.

Ordinary companionship, pleasure, initiative and delayed social consequences already belong to [compelling characters](compelling-characters-tech-design.md) and the [first-playable people](../worlds/base/first-playable-people.md). EC adds their selected longitudinal qualification and older reinterpretation; it does not postpone those earlier obligations. Dreams, a reviewable human reflection aid and deliberate coarsening remain independently deferred EC05/EC06 consumers. They are unnecessary for EC01–EC04.

The existing `InnerWorld` stores `text`, `revision`, `files`, `sourceSnapshot`, `publicationJobId`, optional `publicationBody`, `evidenceIds` and optional `reconsiderationRequired`. Accepted files are mirrored through the current mind-document representation by their existing owner; this is not permission to add another mutable outlook table. `KnowledgeDocument` already carries origin, subject, text, revision and supporting evidence IDs. Keep these existing identities and typed references under [the identity contract](../identity-and-references.md#contract); names and authored roles are display/installation references, not runtime keys.

The current snapshot has publication-level provenance, not a separately validated citation for every sentence. This is adequate for the selected conservative invalidation policy. It cannot establish exact causal attribution for an arbitrary prose claim or justify selective retention after a source is removed. No per-claim dependency graph is selected merely to make that stronger claim.

The base-world author owns traits, protected origins, individual interests, actual starting knowledge and opportunities. Another world can select a different coherent person without changing the publication mechanism. The trusted reflection contract owns distinctions between self-understanding, testimony, inference and world effects. Native integrity does not hard-code a psychological response to an event type. These boundaries apply the existing [engine/world decision procedure](../engine-and-world-boundaries.md#5-a-repeatable-boundary-decision).

An accepted reflection with unchanged files can still have a valid publication identity, advance the existing revision/timing bookkeeping and append its permitted short thoughts. That is maintenance, not evidence of character development. The feature records no special growth event and does not schedule another inference merely because current self-understanding changed. A genuine typed goal or other semantic change retains its existing ordinary scheduling consequences.

## 4. Reflection input and proposal contract

### Preparation and source coverage

Use the existing `prepareDecision`, `RecallService`, `MemoryRepository` and knowledge preparation. Required current self-understanding, recent action outcomes, live obligations and the actual cause enter their shared admission before optional selection. A queued request carries references to permitted evidence, never copied history or a target personality change. The existing `ReflectionRequest`, its integration record and `CognitionMaintenance` remain the only reflection opportunity owner.

#### Capture the cause, retain useful pointers

`prepareDecision` returns a read-only metadata projection alongside its current context: world timeline, actor-scoped `MemoryScope`, the exact initiating `CurrentMemorySource` when one exists, the other actual coalesced cause sources, the historical source references actually supplied to that judgment, and the IDs/subjects/revisions of its selected subject notes. A source reference is the complete `(world, actor, repository generation, source family, raw ID, revision)` identity. Reuse the repository's source-key encoder; display names, candidate wording and a raw memory ID cannot stand in for it. Subject references use the knowledge owner's exact document key, not a guessed entity name.

The two existing producers supply only what they actually have:

- Semantic routing passes the metadata already prepared for the judgment that selected reflection. Its initiating and coalesced causes are required evidence; other selected historical sources and note references are association hints. Do not rerun retrieval to assemble the queued request.
- Significant-event intake passes the exact observer-permitted source references in its admitted event opportunity, preserving the one actual initiating cause separately. It has no later semantic selection or note-read proof to invent. Bind metadata through the existing source preparation after the relevant save ticket is durable; an unavailable read leaves intake unconsumed under its existing failure rule.

Native downtime and other source-free opportunities remain explicitly unbound. They use fresh current state and ordinary optional recall, with no invented event or historical association. An authored source, an accepted private thought and witnessed activity keep their own acquisition kind. Developer instructions, comparison manifests, role-play rehearsals, desired later lines and service notices are not personal sources. No evaluation helper may call enqueue with a chosen old-event ID or prewritten lesson and then count the result as autonomous development.

For progressive speech, use the common [terminal semantic-readiness owner](npc-speech-streaming-tech-design.md#terminal-semantic-readiness). Open or rejected text cannot enter this metadata, exact required reads, note support, embeddings or reflection. A terminal interrupted utterance supplies only its actually accepted, observer-permitted words and interruption status. A hidden completion or unaccepted remainder never fills it out. SPK's [structured experience and selected-summary attribution](speech-and-social-perception-tech-design.md#structural-attribution-in-every-selected-summary) supplies the same source meaning to reflection as to other consumers; EC adds no parallel speech capsule or readiness check in a prompt builder.

#### One pending opportunity, exact replacement

Keep at most one pending opportunity per actor in the existing integration record. At enqueue, the maintenance owner enters `publishRecall`, rechecks the current runtime generation and reads/replaces that exact record within the existing repository transaction. A current-format request has an application-allocated instance ID, its source-bundle digest and earliest waiting time. The instance ID distinguishes replacement even when an earlier bundle later recurs; it is not a world event, source identity or personality revision.

For a bound request, deduplicate the actual scope/source/note references, with canonical ordering for set-valued fields. Formatting, a new origin job ID or reading the same source again does not establish new evidence. The newest valid admitted bound bundle replaces the pending bound bundle as one unit while preserving the earliest waiting time. Its sources remain in ordinary memory after replacement. An unbound idle request cannot overwrite a valid bound request. A stale pending request is retired by its exact instance ID; storage unavailability is not proof of staleness. No full-history union, per-lesson list or second waiting queue is added.

The complete serialized request, including its reason and source metadata, must fit the existing **8,192 UTF-8 byte execution-descriptor allowance** owned by `DECISION_LIMITS.descriptorBytes`. Apply that same value before retaining the request and pass its actual encoded size to shared execution admission; the current fixed `+128` metadata estimate cannot represent a captured source bundle. Refuse an oversized replacement without truncating it, deleting the earlier pending request, consuming a daily attempt or deleting experience. Record the unavailable targeted opportunity in existing diagnostics. This selected use of the descriptor limit bounds each pending cue; it neither increases model context nor caps a person's lifetime memories. The integration-value cache keeps its own eviction policy, and total durable pending metadata can still grow with the number of people. [EC-L03/EC-L05](../limits/memory.md#ec-l03--existing-work-admission-and-evidence-limits) record that tradeoff.

#### Claim only current, admitted work

Scheduling first checks the queued timeline/scope, exact cause revisions and present NPC eligibility without a provider call. A cause that was forgotten, corrected, is semantically open, belongs to another timeline or is otherwise unavailable retires only that targeted instance with its reason. Do not reinterpret its saved reason as evidence or buy a replacement reflection. Age, a departed speaker or an unrelated world tick alone does not stale an accessible past experience. A storage/read failure retains the pending instance and uses the existing maintenance-read failure/backoff; it is not a fictional refusal or a consumed paid attempt.

A shared execution-slot refusal, expiry or cancellation before its start callback leaves the never-admitted pending opportunity intact. At the start callback, retain the original queued instance ID, recheck current eligibility/source metadata, then atomically compare that ID, check the actor's current daily attempt marker, record the admitted attempt/job identity and consume only that matching pending request. Add this narrow atomic operation to the existing repository/integration owner: the source baseline's separate `getIntegration`/`putIntegration` calls do not supply compare-and-consume or an atomic two-record claim. Do not introduce a generic durable queue framework or force a world save merely to mutate scheduling metadata.

Claim before any potentially paid embedding, relevance or harness work. If a replacement arrived, the stale callback exits without consuming it or the day's allowance. After the claim, cancellation, context overflow, unavailable funding, invalid output and uncertain completion retain the admitted attempt and actual receipts; no automatic requeue or retry follows, including when no provider was ultimately dispatched. A newer independent cue may remain pending for a future eligible day. New evidence does not cancel an already funded reflection unless the existing urgency, eligibility, source or authority rules invalidate it.

#### Refresh notes, then bind the complete attempt

An initiating response can legitimately revise its subject note before background reflection starts. A queued note revision is therefore an association hint, not a promise that the note will stay unchanged until idle time. After flushing pending personal sources, resolve each hinted note through its current owner. Record whether it is unchanged, changed, empty, missing or no longer permitted. Use the current permitted text and revision; never restore the queued text or discard an otherwise valid cause solely because its note changed. A document-only reference may revise remembered prose without making an unrecognized person or retired body targetable.

Preserve the exact current cause through the shared typed source preparation. An awareness trigger may supply the existing `triggerEvidenceId`; personal action-result or other source families must retain their typed identity rather than being coerced into an awareness ID. Extend the existing required-source interface and candidate binding together. [CR04](../maintainers/cognition-redesign.md#cr04--jev-attention-across-all-candidate-sources) owns the existing raw-ID collisions in recall candidate grouping/binding; EC consumes that correction, rather than maintaining a private source map that leaves ordinary recall inconsistent.

Resolve one hop of the current relevant subject notes' supporting `evidenceIds` through the existing indexed required-source owner, sharing the request's body cache and preparation accounting. Also consider the exact historical sources actually supplied to the initiating judgment. These are available associations, not per-sentence proof: current note publications can carry the whole admitted evidence set. Do not infer which source proves a particular claim from prose. A raw supporting ID that is ambiguous across source families remains unresolved until the owning source contract distinguishes it; never pick a family silently.

Deduplicate complete source identities before hydration and final context assembly. Supply the available selected association set through the same required evidence path for this reflection, so optional relevance failure cannot silently drop an admitted older association. Distinguish a missing, changed, ambiguous or forgotten requested source from an available record omitted by capacity. No longer-current historical references do not silently bind a new revision; current corrected evidence can enter separately through the ordinary owner. A current note can still be reconsidered at assessment-only precision when its old support is unavailable. If the available required set cannot fit, refuse/defer preparation explicitly. Do not recursively expand returned memories, every prior mind publication or a person's lifetime.

A retained summary is supplied at its actual precision through SPK's structured summary owner, including its bounded attribution support. This is not permission to hydrate every lifetime leaf or count an absent original twice. Without exact available words, motives, roles or sequence, reflection can qualify uncertainty but cannot reconstruct a scene. If no source-bearing association exists, ordinary bounded recall uses the actual stimulus, current goal and accepted self-understanding; no result remains incomplete recollection, not deliberate disregard.

#### One preparation budget and one publication fence

Cue, required current sources, current subject-note support and ordinary recall share the repository's **8,192-row / 4-MiB preparation envelope** and the final context allowance. Carry cumulative request accounting through those existing reads; a cache's bounded residency alone does not limit total hydration. Account for the deduplicated admitted union and actual bytes once, while recording repeated metadata validation and database rows visited separately. A small final result is not a bound on SQL work. No additional budget per note, helper, source family or pagination round is granted. The 8-KiB queued descriptor is a separate retained-metadata limit, not another source-reading allowance.

Extend existing private preparation diagnostics with queued instance/scope, requested and admitted exact sources, current note revisions, changed/missing/ambiguous support, original/summary/assessment-only precision, capacity refusal and dispatch/claim outcome. Keep metadata rather than copied source bodies where the diagnostic already links them. These records follow existing access, erasure and retention; they are not actor memories, a public source browser or permanent growth history.

After every awaited preparation and at publication, validate the actual admitted sources and current note revisions through the existing conversation/recall and knowledge owners, alongside current inner-world revision, control/body/generation, recognition, outcomes and live obligations. Do not fence publication against the obsolete queued note revision. Native source validity protects access and currentness; the model's interpretation remains subject to quality qualification. EC01/EC03 use this recorded coverage to distinguish absent input, no change, poor interpretation and rejected publication without repeating paid input until a preferred answer appears.

Current appraisal preparation offers at most 48 selected evidence sources and the active-appraisal page returned by the existing owner. That first page is not all retained feelings. A proposal can use only the actual supplied source/policy/feeling handles; it cannot invent an identifier for an omitted record. An otherwise useful reflection can keep existing feelings unchanged. If a selected case needs an omitted current feeling, the missing preparation is an explicit ACT/CR consumer issue, not permission to silently enlarge the limit or treat absence as emotional resolution.

### Selected meaning within the existing trusted task

Keep the existing complete reflection contract, protected-identity rule, workspace grants and output schema. Add or clarify the following meaning through that owner when implementation compares the baseline; these are full semantic requirements, not separate tools or mandatory output headings:

1. Consider what the supplied actual experience means for this particular person's present self-understanding. Joy, curiosity, accomplishment, companionship, disappointment and disagreement are all legitimate material. A useful reflection can change nothing.
2. Keep another person's current characterization in that person's permitted subject note. Keep a self-oriented tendency or value in mutable self-understanding. Do not reproduce the whole incident in both documents. A practical plan or goal uses its typed owner when genuinely intended; prose alone cannot create it.
3. Preserve the scope of the evidence. One respectful encounter can support a tentative exception with that person; it does not prove everybody is safe or that future help is wanted. Repeated real encounters may form a broader pattern. A consequential incident may support a larger change without an automatic event-to-trait formula.
4. Distinguish what happened, what was later said about it, and what is now inferred. Preserve uncertainty, mixed evidence, the possibility of misunderstanding and the meaningful consequence of the earlier event. Quoted dialogue requires supplied exact words; a summary supports only a summary.
5. Recalling the same source or its derivative again supplies no independent corroboration. A new utterance is nevertheless a real new social act: repeated pressure can be annoying, and a later sincere attempt can matter. Distinguish that new act from proof of its repeated claim.
6. Keep room for an independent life. Enjoying someone's company need not create a promise, permanent availability, confession, romantic wish or obligation. An earned change may be wanting a different challenge, keeping a private pleasure or deciding a completed project was enough.
7. Retain protected origins exactly, and write only permitted mutable files and typed changes. A current exception can qualify an authored tendency without rewriting childhood, installing a skill, enrolling a native feeling process or prescribing the next action.

These instructions describe permitted interpretation. They do not direct the model to produce a particular lesson, output “growth,” repeat a named future line or maximize transformation frequency. The world profile's illustrative later outcomes and evaluation rubric stay outside actor instructions. Ordinary players can communicate their own wishes through actual speech, with the usual untrusted-content treatment; those wishes do not become the trusted evaluator's expected answer.

### Native output and acceptance

The existing reflection harness edits only its actor-scoped `mind/*.md` workspace. The final response retains the existing 1–3 short thoughts and optional `knowledgeChanges`, `nameChanges`, `goalChanges` and `appraisalChanges`. This feature does not add an `outlookChanges` JSON family. The harness returns proposed files; native publication checks all existing protected documents exactly, file names/content bounds, thought shape and supporting source/permission restrictions.

`publishInnerWorld` receives the expected current inner-world revision, publication job identity, snapshot, files and admitted typed changes. Identical replay of the same job/body is a duplicate with no additional effect; the same job with a different body, changed prior revision or invalidated prior publication is rejected. Native note edits require the exact current note revision. Goal edits use existing revision/state transitions. Appraisal operations use the supplied policy, current record revision, allowed subject and actual cause binding. A failure in any of these reflection components rejects the proposed publication as a unit. This atomicity concerns reflection; it does not roll back previously heard conversation or already executed actions.

The server revalidates actor/body/controller eligibility, generation, current source and note bindings and live unresolved commitments at publication. `prepareDecision` also binds relevant action outcomes and remembered participant recognition; correction, newly relevant outcomes or lost exposure cannot be bypassed by a plausible old answer. Appraisal binding checks current source revisions, installed policy, appraisal state, knowledge revision and ownership. Publication runs through the existing serialized world transition and durable state owner; no additional writer or background queue is selected.

The current native schema cannot prove that arbitrary prose is psychologically convincing or factually proportionate. Supplying evidence and checking references establish access and freshness; they are not a semantic truth oracle. Unsupported or formulaic prose that passes those mechanical checks is a quality failure to diagnose through the existing instruction/context owner. Do not claim it is automatically rejected, and do not add a paid model checker merely to endorse it. EC04 qualifies the complete behavior before claiming this feature delivered.

## 5. Later use, observation and player interaction

Ordinary NPC decision and conversation preparation already include the complete current `aboutMe`, current native feelings, body, goals and current agency. The general notepad is included; required/currently involved subject notes and selected remembered material retain their existing knowledge/recall scope. Use the accepted current revision after an awaited preparation, then native execution rechecks its own current prerequisites. An old cached prompt cannot become the next character state.

No specific action is automatically promoted because the self-understanding text changed. The existing offered action/interaction set remains governed by the body, exact items, knowledge, geometry, participants and world law. The model can choose among those real opportunities and may propose a genuinely desired native goal. For example, a person who now values a rival's judgment can ask them to watch an actual next attempt; they cannot create a contest, seize the rival's time or acquire an unknown method by describing that wish.

The selected base-world scenes reuse actual walking, local conversation, observation, making and sling practice. Companionship may use the already selected outing/guidance owner where that interaction is available. A request can be meaningful even when declined. Actual arriving, waiting, shooting, hitting/missing, making or stopping remains with its native owner. PC04's delayed-shot observation repair remains a prerequisite for claiming completed coaching; EC's rivalry scene can compare actually witnessed independent practice without pretending the repair is delivered.

Players discover a difference through particular speech and visible choices in places and activities they already understand. There is no new friendship dashboard, growth badge, personality control, compulsory confession or prompt asking the player to optimize a resident. Existing action panels show actual practice/making/offer controls and accepted activity state; opening them performs no inference. A private thought or personal note appears only to its permitted audience through existing surfaces. Public narration may describe a seen smile, departure or spoken joke only when that expression/action actually occurred; it must not reveal a hidden motive because an inspector could read it.

For a later return, stable individual recognition is required where the scene depends on knowing it is the same person after lost exposure. Use the selected SPK recognition owner; a familiar-looking display name is not a substitute. Failure to recognize a person cannot be repaired by placing the hidden runtime ID or their undisclosed history into a model prompt. Report the actual availability/dependency in the episode evidence.

Human control remains meaningful. If the human inhabits Ada or another participant, automatic NPC reflection does not rewrite that human-authored account. The human chooses their own conduct and existing editable narrative. The counterpart NPC can still develop its own understanding from the encounter. Remote correspondence and its additional privacy scope are separately designed consumers, unnecessary for these in-person episodes.

Current `invalidateExperience` can clear all of an actor's mutable notes and nonprotected self-understanding when exact selective support cannot be proved. It increments revisions, clears the accepted publication body, keeps protected content, sets `reconsiderationRequired` and removes invalid dependents through their owners. That conservative loss can include a useful unrelated outlook. EC accepts this existing tradeoff and records it in [EC-L06](../limits/memory.md#ec-l06--dependency-closure-and-private-ownership); it does not claim a surgical memory repair.

The narrative domain state and its tables are unchanged. The existing durable reflection integration value gains the selected cue fields, and its reader validates that one current shape before use; no parallel format, migration or legacy reader is retained. A malformed or incompatible operational cue cannot authorize work, while accepted character state remains with ordinary save/load. A pending, unclaimed cue may survive ordinary restart only when its stored world timeline and repository scope still match and all current cause/authority checks pass. Bind any newly admitted execution to the new process generation. An already claimed attempt or uncertain/dispatched provider job is never resumed or automatically resubmitted. A gameplay restore retires abandoned-timeline cues; source correction/erasure cannot be undone by restoring their pointers. Current-format round trips preserve accepted state and later permitted choices, not a model's future answer. Existing CR13 monotonic revision work and SPK/source-preservation gaps remain owned prerequisites where a selected caller consumes them; EC must not create alternate revision counters or stringify exact facts around those owners.

### Longitudinal personal and player qualification

Run the [world profile](../worlds/base/experience-shaped-characters.md#qualification-opportunities) through the current ordinary director. Begin with one eligible resident and the human, then use a contrasting coherent profile in a matched run. Include a two-NPC case after its existing independent-life dependencies are available; neither actor receives the other's target transformation. Keep a later activity and a current-format return among the cases. Native feasibility replay and independent live model choices are different evidence.

Use the existing comparison manifest for initial authored state, permitted evidence, actual intervention, admitted opportunity, source/prompt/model revisions, accepted publication, real later conduct, stopping conditions, costs and uncertainty. Define acceptable alternatives before observing the result. Do not place the desired later line, change direction or evaluator rubric into character instructions. Counterfactual variants change one relevant experience while keeping comparable initial perspective and opportunities; they do not force later worlds to stay identical after different choices.

The selected minimum coverage is **all five profile families**: enjoyable company, useful rivalry, self-directed satisfaction, later explanation of an old refusal, and a mixed/contrary encounter. Include an unchanged-evidence control, a different-person control, unavailable reflection, and a long enough intervening activity to establish a real later opportunity. This is a coverage requirement, not a claim about sufficient statistical sample size. Predeclare repetitions, held-out group splits and any acceptable cost/quality threshold before paid evaluation, under the existing CE05/CR12/AG12 owner.

An individual unchanged outlook or refusal can be entirely convincing. The whole feature cannot pass if every run leaves understanding and later conduct unchanged, if all changes are declarations without execution, or if only the human-centered praise case works. At least the selected positive companionship and an independent/solitary or rival family must show recognizable, evidence-sensitive later conduct in observed episodes, with the contrary/control results retained. Review whether the player can recognize the person and enjoy their own activity without being taught to grind a transformation. Report insufficient opportunity, evaluator disagreement and inconclusive findings separately from success.

Human judgment concerns the chronology, available choices and visible consequences, not recovered hidden reasoning. A privileged diagnostic can establish which accepted revision and sources the later decision actually received. It cannot prove the model's private causal process, and an eloquent explanation is not a substitute for the observed choice. Runtime, live-model, player and performance acceptance remain open in EC01–EC04; source analysis does not satisfy them.

## 10. Tradeoffs, extension seams and decisions

This design chooses a concise revisable account using existing owners. It avoids maintaining a trait vector alongside prose whose authority would be unclear, or a permanent lesson list that grows on every encounter. It accepts that freeform meaning needs empirical quality evidence and that current conservative erasure can lose useful unrelated interpretation. Those are explicit limitations, not unimplemented promises hidden in new schema fields.

A later exact-provenance feature needs a real selective-retention consumer before adding sentence-level links. A new activity requires its own native behavior before it can become a meaningful character opportunity. A later dream or human aid can reuse permitted state, but must preserve imagined versus remembered meaning and explicit human authorship; it cannot inherit an automatic publication permission from NPC reflection. Richer thought/familiarity presentation should be justified by players missing useful visible continuity, not by a wish to expose internal implementation.

There is **no unresolved product-owner decision for EC01–EC04**. The remaining work is implementation diagnosis and separately authorized qualification under existing spending and data policies. No operating promise, adult-content policy, human privacy boundary, audience choice, platform choice or retention policy is reopened by this selected design.
