## 1. Diagnosis and evidence limits

The [final attribution](../verification/performance/2026-10/bookkeeping-simplification.md#final-bounded-attribution) measures 120.420 real seconds after 60 seconds of warmup: the standard opening has seven people, twenty animals, 74 root objects, one controlled moving player, native actions and speech, and no model calls. It advances 3,068 game seconds. Three background queue-deadline refusals and severe host contention make this an overloaded diagnostic, not a clean throughput comparison. The separate error-free five-minute run achieves 41.79% of requested normal speed. Failed earlier startup/warmup attempts contribute neither of the counts below.

**83,193 is the count of successful `appendHistoryOperation` calls**, not world events, memories, movement steps or database rows. There are five producers in `temporal-evidence.ts`: current-partition checks, closing current-partition spans, received occurrences, geometry-feature checks and closing geometry spans. The capture has no operation-kind/byte histogram. Their individual totals cannot be recovered from this counter.

At the measured source, an unchanged attended check constructed a one-stamp operation inside `captureTemporalCurrent`'s partition loop. Each append sizes the operation, resolves declarations/counts, checks admission, snapshots/appends, updates subject/source/reference lists, charges the actor and updates deadlines. Later saving encodes it and maintains database projections. That geometry path had a complete unchanged-set fast path, but `recordGeometryCheck` still visits every retained feature to append separate checks. Recording-object identity also prevented otherwise equal current freshness partitions from merging (`samePartition`). These are source-established multiplication paths, not measured percentages.

**7,157 is PostgreSQL adapter calls**, including reads, direct/grouped writes and transaction control. The writer already combines 5,590 logical statements into 1,650 calls. Those 1,650 are included in 7,157; the remaining 5,507 are unclassified, not all reads. Other measured counts are 71 save spans, 91 cleanup attempts, 682 read-lane admissions, 203 writer-lane admissions, and 34 lexical batches processing 813 changed searchable accounts. An admission can execute several queries; ordinary temporal checks are not all full-text-indexed accounts. No query-family frequency, affected-row histogram or PostgreSQL backend CPU was captured.

The normal collector route uses approximately four adapter calls per successful slice: begin, candidate selection, combined collection, commit. Even 91 full slices would account for about 364 calls, subject to phase/failure boundaries. Cleanup alone cannot explain most of 7,157. Ownership projection and canonical writes are already batched; do not diagnose them as one query per contact. SQL elapsed spans overlap save, cleanup and queue spans; they cannot be summed or called database CPU.

The clean run ends with 88,166,947 bytes of retired history payload, not 88 MB of active memories or physical disk. The diagnostic ends with 158,237,469 bytes of total raw history, including 21,900,722 retired, and 1,978,607 bytes of pooled values. Different run lengths/game progress preclude a cleanup improvement comparison. The small pooled-value total argues against replacing shared rich descriptions with copies in every observer's history.

Reconstructing personal experience from objective world history remains unsuitable: it cannot recover actual clipping, successful checks, attention, uncertainty or personal identity without retaining those receipts anyway. Adding a worker, slowing sight, enlarging save intervals or increasing cleanup budgets is not this design's fix. No new world rules, service, journal or model loop is introduced.

## 3. One receiving result, multiple consumers

Extend `withCurrentPerceptionBatch` / `withTemporalAcquisition`; do not create a second observation pipeline. A synchronous receiver-owned builder collects an ordered `ReceivedBatch` while the actual receiving owner mutates current knowledge. It borrows immutable values and exact owned bindings. Capture outgoing information before replacement, never by comparing end-of-tick worlds.

The canonical batch contains:

- Actor/physical-life/receipt-epoch identity, actual received boundary and local sequence. Reuse existing structured identities and causal allocation. Each subtransition retains its original order; equal game time is not equal causal order.
- A small dictionary of genuinely common receiver frames, channels and support clock tuples. Different frames/times/source revisions remain explicit exceptions. A shared observer frame is recorded once; it is never reconstructed from the observer's newer position.
- Immutable coverage bindings for the exact local subject, grant lifetime, original acquisition and typed member/part set. Reuse binding identity while membership/provenance is unchanged. Its cardinality and source projection are computed once, not by stringifying/set-building on every check.
- Ordered entries for admitted baseline, received value/measurement change, successful coverage check, admission/availability boundary and discrete occurrence. Entries reference exact bindings/masks and common clocks; changed scalar values are inline, substantial stable values keep existing shared references. Boundary entries are metadata, not invented sensory occurrences or lasting memories.

At each actual reception, append compact inputs for its already known affected members. Do not re-enumerate all selected contacts afterward merely to rediscover the change. Flush/account/append the builder once per receiving boundary, splitting only at existing work/byte admission limits. Large legal acquisitions may require multiple bounded pieces; preserve the original atomic transition and all required evidence. Do not keep an unbounded deferred builder or silently discard a suffix.

Admission still precedes retaining each contribution. In the existing deterministic transition/member order, reserve required evidence through its mandatory path, then check optional logical contributions against local remaining allowance before adding them. Preserve admitted contributions and exact rejected-coverage gaps; do not turn partial admission into all-or-nothing batching. Aggregate accepted charges into the owner once at flush. Rejected optional recording does not undo actual current perception, and final batching cannot bypass work/pending limits.

Unchanged checks carry their actual timestamps and precise masks; they do not become separate value/receipt/proof objects. Repeated identical coverage can use one immutable membership plus an ordered scalar array of exact check times/revisions. No arithmetic cadence inference, interpolation or new run-compression framework is needed. Common clock columns can be shared only when equal; successful support does not imply a fresh measurement. Missing checks remain missing. Necessary exact samples still consume data and logical count.

Separate current freshness masks from history-admission bindings **within the existing contact/geometry owners**. Equal current clocks can merge independently of different recording origins. Retain independent detail, pose, description, association and other typed parts. Recording refers to current-owned bindings; it does not duplicate their values or become a second writable map of knowledge. Remove reservations for a future full closing-span copy: admission now reserves/charges its actual baseline and subsequent exact entries before accepting them.

When geometry's current owner certifies an unchanged complete set, emit one check of that exact immutable feature-set membership. Membership changes produce a new binding or a precise subset. A feature not included in the successful check is not refreshed. This is a general set-coverage mechanism, not a special cliff/ground rule.

Attention consumes changed received inputs, not reconstructed field proofs. Keep discovery/stability/required-cause rules; resolve an unchanged selection before building candidate descriptions/groupings. The existing owner rebuilds derived candidate preparation on restore and calculates deadlines from compact scalar state under §3.3. Goal, focus, identity, familiarity, eligibility, expiry or relevant relation changes invalidate their actual dependencies. A deadline lookup does not build `attentionRelationAnchors`. Native reactions still consume the current permitted scene before physical advancement completes. Player/current/model projections borrow the same immutable received facts through existing scoped readers; later asynchronous use captures only its permitted selection and rechecks privacy.

### 3.1 Native contracts and identity

Replace the temporal operation types in their existing owner. These are serializable owned data, not a new service or plugin interface:

```ts
type ReceivedAddress = {
  actorId: string;
  physicalLife: number;
  epoch: string;
  batchOrder: number;
  entryIndex: number;
  memberIndex: number;
};
type ReceivedBatch = {
  actorId: string;
  physicalLife: number;
  epoch: string;
  batchOrder: number;
  frames: readonly ObservationFrame[];
  bindings: readonly ReceivedBinding[];
  entries: readonly ReceivedEntry[];
};
```

`ReceivedBinding` contains its allocated identity, original `EvidenceSource`/acquisition, local subject, exact exposure/channel/grant lifetime, and ordered typed parts. A part has a stable `partIndex`, logical facet identity and supported part kind, reusing the existing received-value decomposition. `ReceivedEntry` contains explicit `entryIndex`, actual transition `order`, `receivedAt` and one of the payloads below. Each entry has deterministic logical members with explicit `memberIndex`; a logical member is one counted facet, possibly covering several typed parts. Do not confuse a typed `partIndex` with a logical member. An exact part proof adds the selected typed part to the complete logical address.

These are complete logical addresses, not instructions to serialize actor/life/epoch on every member. Within a batch/block, inherit its owner header and use local binding/frame/entry/member indices; validate the fully resolved owner once at the boundary. Reuse the existing tuple/key helpers for indexed identities. Retained native values must already be immutable or copied as the small exact scalar/clock tuple before mutation; retaining a mutable draft pointer is not predecessor capture.

| Entry payload | Required data                                                                                                                                     |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `baseline`    | Exact admitted binding/part masks, original values and independent clocks/frame, admission time/order; no new sensor sample token.                |
| `sample`      | Actual sample token, exact binding/part coverage, common support/measurement clock tuples and subset exceptions, sparse changed value references. |
| `boundary`    | Exact then-affected binding/part mask, original cause and terminal availability/admission state; never a wildcard over future members.            |
| `occurrence`  | Existing permitted received occurrence/source and exact context/correspondence bindings; retain its existing indivisible units.                   |

Use the existing identity allocator for `batchOrder` and binding IDs. Allocate logical entry/member coordinates in deterministic producer order before optional filtering; store them explicitly. Removed/rejected members leave holes, and saving, partial expiry or correction never renumbers surviving references. Batch order identifies the append; actual transition order and entry/member order retain chronology within it. Epoch strings are identities, not sort keys. Restore preserves the existing global allocation floor before issuing new orders. Current owners retain active bindings; old blocks carry only descriptors they use. No lifetime binding registry is added.

The actual receiving adapter creates a receiver-local **sample token** when a successful detector result or acquired contribution exists. Current, detail and recording helpers consuming that same result reuse it. The builder unions their exact coverage into one sample entry. Timestamp/value equality alone is not deduplication: two genuine checks at the same game time have different tokens. Sight's existing confirmation revision remains proof metadata, not a universal token across producers. Both `confirmDetailed` passes over the same result reuse its token; a promoted subject's genuinely new detail measurement obtains another. One complete geometry-set check has one token across its features. Speech/inspection/outcome acquisitions preserve their real event/contribution identity and observer-specific token. Readers and attention changes mint none.

The token freezes the successful result's complete typed-part coverage, values/clocks, order and admission mask once, with the accepted/rejected logical-member decisions. Reserve each complete logical facet before helper consumption. Repeated helpers may mark already captured subsets consumed, but cannot retry rejected members, allocate another index, charge again, read newer current values or add a later attention promotion. A genuinely new result requires a new token.

Finalize observer-local body correspondence before freezing that token/binding. Currently `reconcileVisualEvidence` assigns unfamiliar bodies after both `confirmDetailed` passes and calls `receiveCurrentSample` again to attach `localSubject`; `selectedBodyIndividual`/the base world's `ensureBodyIndividual` requires the installed current body grant. Convert this path through the same receiving owner: its world adapter consumes the already validated body receipt, assigns/reuses the local subject, then the owner freezes the complete result. Resolve against the incoming exposure, body continuity and lives, not the pre-overwrite `currentBodySubject`. Only compatible continuity or independently received recognition permits reuse; a matching private routing ID alone does not. Do this for broad unattended bodies too. No reader, second sample or retroactive binding edit is needed. This grants neither a name nor recognition; later genuine recognition remains separately acquired association evidence. The world still owns who qualifies for a local individual; the engine owns the receiving order and exact grant.

Coverage unions only within the admission that applied at actual reception. A later attention promotion cannot add its earlier broad sample to detailed history: it gets a dated baseline, followed by any genuinely new sample. Within one actual sample, co-covered typed parts of one logical facet count once; a separately acquired location is another facet. Value change plus confirmation from that sample counts once, not twice. Boundaries have zero observation count but retain their byte/dependency cost. Required occurrence units remain intact.

### 3.2 Receiving algorithm

```text
enter receiver scope; nesting reuses its builder, admission and actual sample tokens
for each actual incoming transition in producer order:
    validate its channel/grant at the existing receiving boundary
    capture needed predecessor state before any overwrite
    finalize permitted local correspondence through the world adapter using that received grant
    intersect successful coverage with admission at that moment
    reserve mandatory support and admit optional members before retaining them
    freeze the complete result/binding/admission decision before helper consumption
    update all actually received current parts, even if optional recording is refused
    collect admitted sample/changes/boundaries and exact dirty keys
update attention from these dirty keys and actual due opportunities
    close outgoing admission; baseline newly selected current facts with their old dates
    route genuine additional sensing through the same procedure with a new sample token
apply existing native relational cues/reactions against permitted current state
flush one immutable batch and aggregate charges before publishing the native transition
```

A failed native transition discards its builder with the candidate state. No builder survives an `await`, immutable publication or save cut. Required evidence cannot fail silently; optional refusal marks only its actual coverage gap. Continue to bound builder bytes/work using the existing admission owner, even before flush. Store native suffixes through the existing append collection; no growing array is repeatedly copied merely to group checks.

Reserve the bounded admission/coverage-gap metadata before optional changed-value payload. If that payload is refused, terminate the old recorded state's valid range at the actual transition and preserve the exact gap while current knowledge still updates. The current admission owner keeps that gap open; repeated refusals append nothing and rewrite no saved boundary. A later admitted sample establishes a new dated baseline and closes the gap. Neither a repeated helper nor a successor seed can bridge the omitted change. Boundary metadata cannot itself be dropped to make a full payload fit.

In `perception-current.ts`, move active recording bindings out of `CurrentPartPartition` into the containing contact/feature's existing owned state. They reference current member identities without copying values. `samePartition` compares freshness/support/frame/availability only. `currentConfirmGroups` returns the exact successful/changed coverage to its caller; `currentGroupsSetRecording` becomes admission updates without splitting freshness partitions. Delete future-close reservations, start/terminal value copies and `reserveOpenReceipt` once consumers use baselines and samples. A selected proof is materialized only at an actual consuming boundary, not to iterate owned native data.

### 3.3 Attention and scheduling invalidation

Reuse the current candidate/description preparation and actor attention state. Apply dirty source inputs before testing selection reuse, but return before constructing the complete `candidateView`, representative grouping and sorting when no ranking input or due opportunity changed. Content/description, received position/geometry, association/familiarity, focus/action target, policy/capacity, presentation/discovery watermark, eligibility and real expiry update their own inputs. A successful unchanged check advances only support-dependent work; it does not automatically mean descriptive novelty or new relation geometry. A changed receiver frame still invalidates relationships that actually depend on it.

Extract one shared key/scalar helper for deadline queries: self, selected subjects, current work targets and still-live direct-involvement subjects outside the slots; urgency/direct expiry, dirty relation families, latch clear deadlines and `nextRelationAt`. It must not prepare descriptions, body proofs or geometry. Reuse existing key membership where available; a remaining scalar annotation walk must be reported as such, not called O(slots). No new cached deadline field or heap is required. Actual relation execution still validates current received eligibility, and existing discovery/stability opportunities keep their scheduling semantics. Restore rebuilds disposable preparation from saved semantic attention state without advancing discovery, granting familiarity or taking a sample.

## 4. Chronology and lifecycle

History records facts when received/admitted, not when a potentially long interval eventually closes. Native/read consumers may derive an interval from ordered samples and boundaries, but it is not another saved authority.

| Transition                    | Target behavior                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Broad acquisition             | Update current state and local correspondence. No detailed route for every visible subject. Compatible neutral value preparation can be shared across observers; grants, local identity and dates cannot.                                                                                                                                                                       |
| Attention entry               | Record a baseline of admitted current members with original measurement/support times and a distinct admission time. No earlier movement is acquired. Entry alone creates no lasting account or fresh measurement.                                                                                                                                                              |
| Unchanged successful check    | Add exact common clocks plus the checked binding/mask to the receiving batch; no copied value, closed span, independent operation envelope or stable-value ownership update.                                                                                                                                                                                                    |
| Received change               | Preserve each intermediate value in order, including p0→p1→p2 at one game time. Record only changed parts, while retaining a supported snapshot seed for selected reads. Same-original equal-value remeasurement updates only that member's explicitly supplied measurement/acquisition and support tuples; support-only confirmation leaves measurement/acquisition unchanged. |
| Independent equal acquisition | Preserve B's independent original even if its neutral value equals A. Withdrawing A cannot remove B.                                                                                                                                                                                                                                                                            |
| Unchecked/loss                | Update availability and append an admitted coverage boundary. Keep the last actual position/date; do not invent the moment/location of disappearance or treat loss as a new observation.                                                                                                                                                                                        |
| Attention exit                | End admission at its exact order. Current sight and learned knowledge continue independently. A later entry starts at then-current received state, without filling the gap.                                                                                                                                                                                                     |
| Required occurrence           | Retain exact speech/action/outcome through its existing source owner and one ordered batch reference. | Reopen/restore                | Restore exact current state, batches, clocks, eligibility and owned support, with no new observation. Logical references identify actor/life/epoch, received batch and member/entry, never SQL row offsets. Preserve original family/revision types and exact observation uncertainty. Epoch order uses the existing saved timeline ordering; do not compare opaque epoch strings or reset ordinals as if globally ordered. The save acknowledgement continues using committed causal cuts, so an old prefix cannot reappear as a new append. Format conversion updates every caller; no compatibility reader remains.

## 5. Save layout and cold reads

Reuse `mind_temporal_pages`, `WorldRecords`, `PendingWorldSave`, `LiveReadCuts` and the existing direct writer. Replace kind-specific payloads with mixed chronological blocks. At a detached save, gather the new suffix across all native containers **for each actor/life/epoch**, preserve entry/member order, and pack by the existing preferred 64 KiB physical target. Count the actual encoded payload, used descriptors/seeds, header and directory metadata, not its smaller logical memory charge. Start a new block for owner/epoch, actual size or the scheduled save-cut boundary, not operation kind/native-container identity. Saving ends its immutable blocks; a later save does not fill their unused space. No whole old tail is re-encoded; a refused save retains its immutable cut and newer pending data.

Multi-member samples, baselines and common boundaries may be physically sliced between complete logical facets. Preserve their batch/entry/token/member identities and keep all co-covered typed parts of a facet together. Discrete occurrences remain indivisible. Slices are disjoint coverage of one logical entry; repeated physical headers create neither new observations nor duplicate logical closure charges. One indivisible facet/occurrence may exceed the preferred target under the existing exception, but not the hard current [record/admission limits](../limits/persistence.md#sv05). Use the existing explicit failure path if it cannot fit; no truncation or larger limit. The native receiving transition and complete save transaction remain atomic.

Each block is independently decodable using its inline data and referenced immutable rich values, with no predecessor-page replay. Include a first-use descriptor/clock seed **only for bindings and their parts actually used in that block**, including the then-held state for a check without a value change. One changed member of a large binding must not copy its untouched siblings' baselines; retain original part indices and one common header for the used subset. Preserve original dates and separate the seed from eligible received entries. Do not baseline the entire broad scene, all ten attention subjects or untouched terrain at every save. The seed is codec context, not a new sample, retained fact or eligibility extension. Saving a block can repeat compact descriptors; it must not repeat full field-proof objects or copy pooled descriptions. This bounded repetition is an explicit tradeoff for selected cold reads, and its bytes must be measured.

One metadata projection supplies actor/life/epoch, chronological order/time bounds, exact logical charge totals and used subject/member/source/value keys. Keep the primary identity, actor/order/time selection and bounded candidate buckets with exact membership checks. Remove `mind_temporal_span_ranges` and its writers/readers: no span is inserted long after its observed time. Review each of the seven page indexes against actual converted queries; drop only those with no distinct caller. No duplicate JSON lookup arrays, per-check SQL rows or newly introduced per-field table. Keep one existing shared-value use per distinct block/value, generated in the already batched ownership projection. Inline position/frame/check changes add no pooled-value rows.

Cold readers first restrict actor, life, epoch and received time/order, then subject/member candidates and exact current eligibility. For an as-of member value, seek its latest eligible received entry at/before that cut **and applicable later admission, availability and grant boundaries**. Candidate membership includes common subject/set boundaries, even when they contain no value entry; do not copy the boundary per field. A face checked at 10 and contact lost at 20 is dated past knowledge at 30, not a current visible face. Attention exit/reentry cannot bridge an unrecorded route.

If no preceding entry remains, inspect the nearest following exact member block's **old predecessor seed**, or a captured current binding. A seed includes the actual predecessor's value, independent clocks, frame, grant, admission and last state/availability boundary; it is valid only over its certified unchanged-state range through the first real entry, clipped by recording and retention eligibility. All source references come from that predecessor, never the newer check or save-time world. No separate saved interval catalogue is added. The exact member/boundary indexes support bounded predecessor/successor selection; exhausted preparation returns incomplete, not absence.

For example, an unchanged admitted value measured at 50 and checked at 70 and 90 may have the exact predecessor state for the 90 check in a later block. At cut 75, provided 75 remains inside the actor's eligible history range, use the 70 entry or its eligible carried state with measurement 50/support 70; never report a check at 75 or use support 90. If the 70 event has expired, it cannot be returned as a retained occurrence, but the seed can still describe dated held state within its retained valid range. An age cutoff of 80 makes cut 75 unavailable regardless of that seed. If the range or its support is unavailable, report unknown. At cut 95 the actual 90 check remains usable even after its predecessor block is collected. Acquisition at 80 or an intervening loss prevents a successor seed from answering an earlier cut. This preserves the installed long-unchanged-state contract without inventing continuous visibility or reacquiring expired events.

For a sequence, traverse only bounded candidate blocks, merge exact pending batches and apply pending corrections/deletions before limits. First-use seeds are selected decoding context, not independently searchable occurrences. Historical late closures no longer require separate span-range joins.

Keep existing preparation limits, exact source fences and explicit incomplete outcomes. A hash collision can cause extra candidates, never false access or silent truncation. Test sparse/absent/member selections and cold old cuts; a smaller index count is not acceptance if queries scan lifetime history. Scoped selected expansion counts actual facts, not compressed container count. Capturing revision R freezes its selected values and batches; R+1 reception cannot substitute into it. A routine save/eviction is placement only, while correction/forgetting/expiry invalidates affected results before publication.

### 5.1 Physical schema and selection keys

Keep `mind_temporal_pages` and its existing generic world/record identity and revision columns. Its canonical payload is mixed batch slices with their original batch/entry/member identities. Split physical blocks only at the complete logical-unit boundaries above; never renumber. Derive these columns through the one encoder:

```text
actor_id, physical_life, receipt_epoch
first_batch_order, first_entry, first_member, last_batch_order, last_entry, last_member, first_at, last_at
entry_bytes, receipt_count, encoded_bytes, charge_directory
subject_keys[], track_keys[], source_ids[], individual_ids[]
value_refs[], occurrence_keys[], lookup_buckets[]
```

`entry_bytes` is the sum of stored scalar/member-unit charges, not the actor's shared closure charge; do not sum it as the former page `logical_bytes`. `charge_directory` is the derived metadata described in §6.1. Allocate a physical ID once through the existing structured record-key helper over actor/life/epoch/first batch/first entry/first member. That creation anchor is not an evidence identity. A sparse correction keeps the existing physical ID and predecessor even if it removes the first member; update bounds/projections to the survivors, without deriving a new ID. Delete an empty block. Generic parent/position columns needed by canonical reconstruction remain. Remove `kind`, `retired_revision`, old receipt-ordinal lists, per-kind clocks and the span relation after their callers convert. Do not retain obsolete fields as compatibility aliases.

`track_keys` identify continuous observer-local contact/exposure/channel/grant and typed part across value replacements. Extend existing track/identity helpers. Subject keys never merge separate bodies merely because they share a name or hidden entity identity. Scope boundaries include their affected tracks in the projection even without value changes. First-use descriptors include tracks needed for old-state selection; this does not make their seeds searchable occurrences. Source/correction and shared-value projections include every seed dependency, including old confirmation and frame references.

Do not store a `member_keys[]`/receipt-ordinal array or member-bucket projection enumerating every check's facets. A direct raw receipt already supplies actor/life/epoch/batch/entry/member. Under world/actor scope, seek the nearest predecessor by `(first_batch_order, first_entry, first_member) <= requested`, descending with `LIMIT 1`. After that bounded seek, verify its last-address bound, life/epoch, eligibility and preparation allowance, then decode the exact surviving member/part or prove its hole/expiry. Do not put those rejection predicates inside a scan that can keep walking older blocks for an absent receipt. Deduplicate selected block IDs before body hydration/byte admission; merge captured pending changes through the existing overlay. This replaces the old neighbor-check and selected-fence member lookup without per-unit SQL metadata. Validate disjoint physical ranges/slices, unchanged logical addresses and accurate surviving bounds after correction so the nearest predecessor is the only possible container.

A held-state proof carried by a later seed is a different selection: retain its track, as-of cut, exact old support and captured seed/current-binding carrier through the existing read/fence owner. Re-resolve that bounded state selection; requiring the old raw receipt to remain eligible would incorrectly erase still-supported carried state. Neither route needs a global member index. Correction selects exact source dependencies, including seeds.

### 6.2 Separate age and pressure frontiers

Save `{ expiredThroughTime: number | null, pressureThrough: { address: ReceivedAddress, receivedAt: number, order: number } | null }` in the existing temporal actor. Pressure retains its entry's actual time/order for state-range clipping, while prefix ordering uses numeric batch/entry/member coordinates, not an opaque epoch string. Null means no removal by that criterion. The receiver/retention owner alone advances these monotonic frontiers; a later larger allowance never resurrects data that already expired but awaits collection.

```text
when age work is due or admission encounters pressure:
    ageFloor = simTime - selected maxAge when previous floor is null
               otherwise max(previous floor, simTime - selected maxAge)
    remove each age-expired unit and immediately apply its scalar/count/closure releases
    while optional byte/count totals exceed their existing allowance:
        remove the oldest eligible logical unit in deterministic order
        immediately apply its scalar/count/closure releases
        advance pressureThrough to that exact address
    update the next due time from remaining eligible metadata
    publish frontiers and metadata with the ordinary semantic transition
```

Skip rejected/revoked holes. Do not split a logical facet's co-covered parts or an indivisible occurrence solely to meet a count. Targeted correction/forgetting is sparse revocation and does not advance a prefix over unrelated evidence. Required support/active terms remain independently admitted by their owning account before raw recent units expire. There is no indefinitely protected hole pinning an entire recent block. If an existing required consumer still depends on raw history, convert it to the existing minimal-support owner before applying this rule.

Age and pressure cannot be collapsed into the first remaining sample. A retained check at 90 may carry state applicable at 85, even if age expiry removed a check at 70 and the age floor is 80. The state at 85 is eligible only with valid predecessor/admission/availability support; the 70 event is not. A raw unit is eligible only when its time is greater than the age floor, its complete address is after `pressureThrough`, and it is not revoked. An as-of state cut must be after the age floor and not earlier than the exact pressure boundary, and then satisfy the seed's actual state range. Current knowledge has its own eligibility and is not governed by this recent cutoff.

At the same received time/order as a partial pressure boundary, apply the requested member and remaining mask rather than rejecting every sibling. Member ordering is a deterministic retention tie-break, not invented elapsed physical time. A later seed cannot turn a removed member occurrence into an eligible event.

This is deterministic native work over explicit bounded metadata; no SQL, wall clock or provider is called. Process units once as they leave the window, using existing work limits/cooperative boundaries. Consult due/pressure state before walking the deque. A delayed cleanup must not disclose age-expired facts: reads apply the time floor at their captured game time even before optional storage deletion. Pause freezes game-age expiry. Keep existing headroom/refusal behavior and explicit recording gaps if work/admission is actually exhausted; normal operating acceptance must show that this is not routine.

At a retention-policy change, first settle each affected temporal owner's effective age floor using the old policy at that game time, then install the new policy and its due/pressure effects through the existing definition-change owner. Prepare any necessary cold metadata before that protected transition. Increasing an allowance cannot revive physically retained expired data or extend an old seed backward. This is policy-change work, not a new per-step scan or policy-history service.

Stop if descriptor duplication, query scans, metadata retention or deletion debt grows without convergence. No percentage speedup or hundreds-of-actors capacity is promised in advance.

## 10. Decisions and maintained records

Recommendation: chronological receiver batches, immutable mixed save blocks, useful rich-value sharing, exact actor frontiers and derived bounded retention metadata. This deliberately replaces the installed late-closed-span representation; it does not weaken exact received chronology. Keep all current sensing/attention/action/save defaults. Reduced canonical bookkeeping means the same byte allowance may retain more useful evidence; logical fact/context counts still expand coverage and age limits remain unchanged. Physical first-use seed/index bytes do not become fictional observations.

No product decision blocks this implementation. Actual operation-kind proportions, query-family dominance, descriptor/ownership byte balance, candidate-index selectivity and attainable capacity remain empirical uncertainties. The recommended implementation has explicit removal tests for these risks; operating qualification remains required. Further native-rule reduction is a separate design need, not silently included here.
