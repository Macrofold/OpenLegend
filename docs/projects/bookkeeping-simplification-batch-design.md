# Received batches and recent-history lifetime — proposed design

**Design only, November 4, 2026.** Source inspected: Macrofold/OpenLegend `codex/stealth-runtime-01-evidence`, `c25038837ba0fc7e5c69f9a9b31209b00170982f`. This extends the existing [feature specification](bookkeeping-simplification-feature-spec.md#11-received-batches-and-recent-history-lifetime) and [technical design](bookkeeping-simplification-tech-design.md#14-proposed-received-batches). BK17–BK19 are installed; the changes here are proposed, not implemented or performance-qualified. [BK20–BK23](../maintainers/production-data.md#received-batches-and-lifetime) own implementation if authorized. BK12/BK16 retain their unchanged operating requirements.

## 1. Diagnosis and evidence limits

The [final attribution](../verification/performance/2026-10/bookkeeping-simplification.md#final-bounded-attribution) measures 120.420 real seconds after 60 seconds of warmup: the standard opening has seven people, twenty animals, 74 root objects, one controlled moving player, native actions and speech, and no model calls. It advances 3,068 game seconds. Three background queue-deadline refusals and severe host contention make this an overloaded diagnostic, not a clean throughput comparison. The separate error-free five-minute run achieves 41.79% of requested normal speed. Failed earlier startup/warmup attempts contribute neither of the counts below.

**83,193 is the count of successful `appendHistoryOperation` calls**, not world events, memories, movement steps or database rows. There are five producers in `temporal-evidence.ts`: current-partition checks, closing current-partition spans, received occurrences, geometry-feature checks and closing geometry spans. The capture has no operation-kind/byte histogram. Their individual totals cannot be recovered from this counter.

An unchanged attended check currently constructs a one-stamp operation inside `captureTemporalCurrent`'s partition loop. Each append sizes the operation, resolves declarations/counts, checks admission, snapshots/appends, updates subject/source/reference lists, charges the actor and updates deadlines. Later saving encodes it and maintains database projections. Geometry has a complete unchanged-set fast path, but `recordGeometryCheck` still visits every retained feature to append separate checks. Recording-object identity also prevents otherwise equal current freshness partitions from merging (`samePartition`). These are source-established multiplication paths, not measured percentages.

**7,157 is PostgreSQL adapter calls**, including reads, direct/grouped writes and transaction control. The writer already combines 5,590 logical statements into 1,650 calls. Those 1,650 are included in 7,157; the remaining 5,507 are unclassified, not all reads. Other measured counts are 71 save spans, 91 cleanup attempts, 682 read-lane admissions, 203 writer-lane admissions, and 34 lexical batches processing 813 changed searchable accounts. An admission can execute several queries; ordinary temporal checks are not all full-text-indexed accounts. No query-family frequency, affected-row histogram or PostgreSQL backend CPU was captured.

The normal collector route uses approximately four adapter calls per successful slice: begin, candidate selection, combined collection, commit. Even 91 full slices would account for about 364 calls, subject to phase/failure boundaries. Cleanup alone cannot explain most of 7,157. Ownership projection and canonical writes are already batched; do not diagnose them as one query per contact. SQL elapsed spans overlap save, cleanup and queue spans; they cannot be summed or called database CPU.

The clean run ends with 88,166,947 bytes of retired history payload, not 88 MB of active memories or physical disk. The diagnostic ends with 158,237,469 bytes of total raw history, including 21,900,722 retired, and 1,978,607 bytes of pooled values. Different run lengths/game progress preclude a cleanup improvement comparison. The small pooled-value total argues against replacing shared rich descriptions with copies in every observer's history.

## 2. Alternatives and recommendation

| Candidate                                                           | Complete approach                                                                                                                                                                                                                                    | Assessment                                                                                                                                                                                                                                                                                         |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Minimal practical conversion                                        | One receiver batch with grouped exact checks and shared preparation; retain open intervals, kind-specific pages and span indexes.                                                                                                                    | Smaller implementation risk; removes repeated append/accounting work. Still carries late-close lookup, per-page retirement and fragmented save output. Useful intermediate stage, insufficient as the final structural target.                                                                     |
| **Recommended: chronological received batches and actor frontiers** | One authoritative receiving batch, sparse exact changes/checks, immutable mixed blocks at scheduled saves, resident recent charge headers and exact actor eligibility frontiers. Keep shared substantial values and existing lasting-support owners. | Removes per-partition mutation, late-close storage and ordinary retirement read/update cycles together. Requires a coordinated current-format conversion.                                                                                                                                          |
| Self-contained blocks with a rewritable head                        | Embed rich content, rewrite a bounded head at each save and delete whole expired blocks; no temporal shared-value ownership.                                                                                                                         | Simpler liveness but duplicates rich content across observers/blocks and rewrites previously saved bytes. A 64 KiB head permits 448 KiB/s of rewrites for seven actors or 6.25 MiB/s for 100 before other writes/WAL. Not selected without evidence that these costs beat existing sharing/append. |

Reconstructing personal experience from objective world history remains unsuitable: it cannot recover actual clipping, successful checks, attention, uncertainty or personal identity without retaining those receipts anyway. Adding a worker, slowing sight, enlarging save intervals or increasing cleanup budgets is not this design's fix. No new world rules, service, journal or model loop is introduced.

## 3. One receiving result, multiple consumers

Extend `withCurrentPerceptionBatch` / `withTemporalAcquisition`; do not create a second observation pipeline. A synchronous receiver-owned builder collects an ordered `ReceivedBatch` while the actual receiving owner mutates current knowledge. It borrows immutable values and exact owned bindings. Capture outgoing information before replacement, never by comparing end-of-tick worlds.

The canonical batch contains:

- Actor/physical-life/receipt-epoch identity, actual received boundary and local sequence. Reuse existing structured identities and causal allocation. Each subtransition retains its original order; equal game time is not equal causal order.
- A small dictionary of genuinely common receiver frames, channels and support clock tuples. Different frames/times/source revisions remain explicit exceptions. A shared observer frame is recorded once; it is never reconstructed from the observer's newer position.
- Immutable coverage bindings for the exact local subject, grant lifetime, original acquisition and typed member/part set. Reuse binding identity while membership/provenance is unchanged. Its cardinality and source projection are computed once, not by stringifying/set-building on every check.
- Ordered entries for admitted baseline, received value/measurement change, successful coverage check, admission/availability boundary and discrete occurrence. Entries reference exact bindings/masks and common clocks; changed scalar values are inline, substantial stable values keep existing shared references. Boundary entries are metadata, not invented sensory occurrences or lasting memories.

At each actual reception, append compact inputs for its already known affected members. Do not re-enumerate all selected contacts afterward merely to rediscover the change. Flush/account/append the builder once per receiving boundary, splitting only at existing work/byte admission limits. Large legal acquisitions may require multiple bounded pieces; preserve the original atomic transition and all required evidence. Do not keep an unbounded deferred builder or silently discard a suffix.

Admission still precedes retaining each contribution. In the existing deterministic transition/member order, reserve required evidence through its mandatory path, then check optional logical contributions against local remaining allowance before adding them. Preserve admitted contributions and exact rejected-coverage gaps; do not turn partial admission into all-or-nothing batching. Aggregate accepted charges into the owner once at flush. Rejected optional recording does not undo actual current perception, and final batching cannot bypass work/pending limits.

Unchanged checks carry their actual timestamps and precise masks; they do not become separate value/receipt/proof objects. Repeated identical coverage can use one immutable membership plus an ordered scalar array of exact check times/revisions. No arithmetic cadence inference, interpolation or new run-compression framework is needed. Common clock columns can be shared only when equal; successful support does not imply a fresh measurement. Missing checks remain missing. Necessary exact samples still consume data and logical count.

Separate current freshness masks from history-admission bindings **within the existing contact/geometry owners**. Equal current clocks can merge independently of different recording origins. Retain independent detail, pose, description, association and other typed parts. Recording refers to current-owned bindings; it does not duplicate their values or become a second writable map of knowledge. Remove reservations for a future full closing-span copy: admission now reserves/charges its actual baseline and subsequent exact entries before accepting them.

When geometry's current owner certifies an unchanged complete set, emit one check of that exact immutable feature-set membership. Membership changes produce a new binding or a precise subset. A feature not included in the successful check is not refreshed. This is a general set-coverage mechanism, not a special cliff/ground rule.

Attention consumes changed received inputs, not reconstructed field proofs. Keep discovery/stability/required-cause rules; resolve an unchanged selection before building candidate descriptions/groupings. Derived candidate and next-deadline state is maintained by the existing attention owner and rebuilt on restore. Goal, focus, identity, familiarity, eligibility, expiry or relevant relation changes invalidate their actual dependencies. A deadline lookup reads the next deadline; it does not build `attentionRelationAnchors`. Native reactions still consume the current permitted scene before physical advancement completes. Player/current/model projections borrow the same immutable received facts through existing scoped readers; later asynchronous use captures only its permitted selection and rechecks privacy.

## 4. Chronology and lifecycle

History records facts when received/admitted, not when a potentially long interval eventually closes. Native/read consumers may derive an interval from ordered samples and boundaries, but it is not another saved authority.

| Transition                    | Target behavior                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Broad acquisition             | Update current state and local correspondence. No detailed route for every visible subject. Compatible neutral value preparation can be shared across observers; grants, local identity and dates cannot.                                                                                                                                                                       |
| Attention entry               | Record a baseline of admitted current members with original measurement/support times and a distinct admission time. No earlier movement is acquired. Entry alone creates no lasting account or fresh measurement.                                                                                                                                                              |
| Unchanged successful check    | Add exact common clocks plus the checked binding/mask to the receiving batch; no copied value, closed span, independent operation envelope or stable-value ownership update.                                                                                                                                                                                                    |
| Received change               | Preserve each intermediate value in order, including p0→p1→p2 at one game time. Record only changed parts, while retaining a supported snapshot seed for selected reads. Same-original equal-value remeasurement updates only that member's explicitly supplied measurement/acquisition and support tuples; support-only confirmation leaves measurement/acquisition unchanged. |
| Independent equal acquisition | Preserve B's independent original even if its neutral value equals A. Withdrawing A cannot remove B.                                                                                                                                                                                                                                                                            |
| Unchecked/loss                | Update availability and append an admitted coverage boundary. Keep the last actual position/date; do not invent the moment/location of disappearance or treat loss as a new observation.                                                                                                                                                                                        |
| Attention exit                | End admission at its exact order. Current sight and learned knowledge continue independently. A later entry starts at then-current received state, without filling the gap.                                                                                                                                                                                                     |
| Required occurrence           | Retain exact speech/action/outcome through its existing source owner and one ordered batch reference. Required minimum support is secured independently before optional recent evidence can expire. No second copy in a universal event store.                                                                                                                                  |
| Meaningful retention          | Existing knowledge/account owner retains only necessary exact support or a warranted, explicitly less precise account. Names/places/promises do not pin route blocks. Trivial sequences may disappear without summarization or an AI call.                                                                                                                                      |
| Correction/forgetting         | Exact semantic sources and dependent claims revoke through existing owners. Invalidate pending output immediately; rewrite/remove only affected bounded blocks when physical erasure is required. Other witnesses, independent acquisitions and unrelated members survive. Ordinary contrary testimony remains new evidence for its actual recipients.                          |
| Reopen/restore                | Restore exact current state, batches, clocks, eligibility and owned support, with no new observation. Ordinary reopen keeps its epoch; explicit checkpoint restore preserves old chronology and starts the existing new operational epoch. Current grants/privacy/spending retain their existing external fences.                                                               |

Logical references identify actor/life/epoch, received batch and member/entry, never SQL row offsets. Preserve original family/revision types and exact observation uncertainty. Epoch order uses the existing saved timeline ordering; do not compare opaque epoch strings or reset ordinals as if globally ordered. The save acknowledgement continues using committed causal cuts, so an old prefix cannot reappear as a new append. Format conversion updates every caller; no compatibility reader remains.

## 5. Save layout and cold reads

Reuse `mind_temporal_pages`, `WorldRecords`, `PendingWorldSave`, `LiveReadCuts` and the existing direct writer. Replace kind-specific payloads with mixed chronological blocks. At a detached save, gather the new suffix across all native containers **for each actor/life/epoch**, preserve entry order, and pack by the existing preferred 64 KiB physical target. Start a new block for owner/epoch, actual size or the scheduled save-cut boundary, not operation kind/native-container identity. Saving ends its immutable blocks; a later save does not fill their unused space. A single indivisible oversized supported occurrence retains its existing bounded exception. No whole old tail is re-encoded; a refused save retains its immutable cut and newer pending data.

Each block is independently decodable using its inline data and referenced immutable rich values, with no predecessor-page replay. Include a first-use descriptor/clock seed **only for bindings actually used in that block**, including the then-held state for a check without a value change. Preserve original dates and separate the seed from eligible received entries. Do not baseline the entire broad scene, all ten attention subjects or untouched terrain at every save. The seed is codec context, not a new sample, retained fact or eligibility extension. Saving a block can repeat compact descriptors; it must not repeat full field-proof objects or copy pooled descriptions. This bounded repetition is an explicit tradeoff for selected cold reads, and its bytes must be measured.

One metadata projection supplies actor/life/epoch, chronological order/time bounds, exact logical charge totals and used subject/member/source/value keys. Keep the primary identity, actor/order/time selection and bounded candidate buckets with exact membership checks. Remove `mind_temporal_span_ranges` and its writers/readers: no span is inserted long after its observed time. Review each of the seven page indexes against actual converted queries; drop only those with no distinct caller. No duplicate JSON lookup arrays, per-check SQL rows or newly introduced per-field table. Keep one existing shared-value use per distinct block/value, generated in the already batched ownership projection. Inline position/frame/check changes add no pooled-value rows.

Cold readers first restrict actor, life, epoch and received time/order, then subject/member candidates and exact current eligibility. For an as-of member value, seek its latest eligible received entry at/before that cut **and applicable later admission, availability and grant boundaries**. Candidate membership includes common subject/set boundaries, even when they contain no value entry; do not copy the boundary per field. A face checked at 10 and contact lost at 20 is dated past knowledge at 30, not a current visible face. Attention exit/reentry cannot bridge an unrecorded route.

If no preceding entry remains, inspect the nearest following exact member block's **old predecessor seed**, or a captured current binding. A seed includes the actual predecessor's value, independent clocks, frame, grant, admission and last state/availability boundary; it is valid only over its certified unchanged-state range through the first real entry, clipped by recording and retention eligibility. All source references come from that predecessor, never the newer check or save-time world. No separate saved interval catalogue is added. The exact member/boundary indexes support bounded predecessor/successor selection; exhausted preparation returns incomplete, not absence.

For example, an unchanged admitted value measured at 50 and checked at 70 and 90 may have the exact predecessor state for the 90 check in a later block. At cut 75, provided 75 remains inside the actor's eligible history range, use the 70 entry or its eligible carried state with measurement 50/support 70; never report a check at 75 or use support 90. If the 70 event has expired, it cannot be returned as a retained occurrence, but the seed can still describe dated held state within its retained valid range. An age cutoff of 80 makes cut 75 unavailable regardless of that seed. If the range or its support is unavailable, report unknown. At cut 95 the actual 90 check remains usable even after its predecessor block is collected. Acquisition at 80 or an intervening loss prevents a successor seed from answering an earlier cut. This preserves the installed long-unchanged-state contract without inventing continuous visibility or reacquiring expired events.

For a sequence, traverse only bounded candidate blocks, merge exact pending batches and apply pending corrections/deletions before limits. First-use seeds are selected decoding context, not independently searchable occurrences. Historical late closures no longer require separate span-range joins.

Keep existing preparation limits, exact source fences and explicit incomplete outcomes. A hash collision can cause extra candidates, never false access or silent truncation. Test sparse/absent/member selections and cold old cuts; a smaller index count is not acceptance if queries scan lifetime history. Scoped selected expansion counts actual facts, not compressed container count. Capturing revision R freezes its selected values and batches; R+1 reception cannot substitute into it. A routine save/eviction is placement only, while correction/forgetting/expiry invalidates affected results before publication.

## 6. Recent eligibility without a SQL retirement loop

Extend the existing temporal actor retention owner with an exact ordered eligibility frontier and bounded charge metadata for the retained recent window. A derived resident deque contains block/batch order, receive-time bounds and cumulative logical byte/count charges, including the exact boundary-entry charge directory needed for partial trimming. It contains no body/value copies or independent permissions. Rebuild it from current-format canonical metadata once at activation/restore; update it through append, acknowledged save, correction and expiry. It is bounded by **retained recent data**, not lifetime encounters. Include its retained bytes in server accounting; do not keep expired headers forever.

Maintain the invariant: personal bytes equal eligible scalar entries plus the distinct binding/value/support closure those entries still require, charged once per actor under the existing logical policy. The body-free directory carries exact closure-use counts and release deltas. Expiring an early baseline cannot release a value's charge while a newer check still requires it; trimming one member cannot release a shared header/closure still used by another. Final use removal releases that closure. Physical descriptor/seed duplication is server overhead only. Logical count uses the existing facet/occurrence rules, not the number of batches or typed parts. Reconstruct and compare these totals at current-format load.

Normal age/pressure decisions can then inspect this small owning metadata without a SQL snapshot/header query or an asynchronous stale plan. Apply the selected world's existing age/count/byte order, required-support exclusions and admitted indivisible occurrence semantics. Partial boundaries retain exact entry/member eligibility rather than discarding a whole multi-subject batch. Current knowledge is never expired merely to free recent history. An append and its eligibility changes publish under the same semantic owner; SQL persistence follows the existing save contract.

The saved actor frontier is the authority for ordinary recent availability. All temporal, story-perspective, native, pending, player, model, editor and cold readers apply it before returning content. Required evidence already retained by another owner remains available only under that owner's own grant; it cannot reopen the route. The frontier includes epoch/order semantics and exact partial-boundary state; late-arriving storage writes cannot move it backward. Correction and targeted forgetting remain exact source operations, not a coarse frontier advance.

Remove ordinary per-page `retired_revision` writes and receipt-perspective delete scans. The collector selects blocks wholly below the **durable** frontier and deletes them and dependent ownership/selection rows in bounded batches. A partially eligible boundary block remains physically stored, with old entries inaccessible; account for this bounded slack separately from collectible debt. Co-located eligible content is never forgotten to simplify deletion. Objective world events have their separate policy and are not deleted because personal receipts expired.

Unsaved/in-flight references remain protected until their normal commit settles. Advancing the live frontier can stop disclosure immediately, but physical deletion must respect the acknowledged cut and pending-reference protection. A late save installs both its exact history and frontier atomically; newer pending changes overlay it. Failed transactions publish no committed placement/acknowledgement replacement and release no pending ownership; already accepted live batches, frontiers and charge headers remain valid and pending. Save cuts contain no partial native reception. Pause/resume, restore, actor removal and shutdown reuse existing detached scheduling/ownership boundaries.

The small searchable-account/summary/commitment pools retain their independent world-ranked maintenance. Convert the existing selected-actor × account-table × criterion reads to a set request in one read snapshot: requested scopes supply actor, class, cutoff and limits; each table uses indexed lateral selections and returns its own next-due aggregate. Merge due/pressure duplicates before hydration and preserve policy order and exact pending overrides. SQL effort still scales with legitimate selected actors; round trips need not. Do not build another whole-account metadata mirror or reintroduce a scan of every actor on movement.

## 7. Shared write execution and scheduling

Keep one writer, atomic head/receipt/source changes, one-second target saves, five-second admission backpressure and existing pending-byte ceiling. A save prepares only actual changed table families; ordinary current checks do not invoke account, lexical, story or source-version work when those inputs did not change. Existing row batching is retained. Group mixed block rows and their unique value-use changes for all actors before bounded flushes; preserve actual parent/read dependencies, not accidental per-kind/native-container flush boundaries. Do not add a generic transaction graph, second durable queue or parallel writer.

Native physical effects, actual reception, current availability, required reactions, admission and exact ordered history intent finish synchronously before accepting that physical prefix. SQL encoding/application, cold selected reads, optional descriptions/AI, lexical preparation and physical deletion may finish afterward under existing captured-cut/failure contracts. Coalesce replaceable current metadata; retain every admitted intermediate received change and occurrence. Async work consumes the same CPU/database resources and is not credited as eliminated cost.

The target removes history work upstream; it does not remove unrelated status/animal eligibility processing. The profile attributes substantial native work there too. Extend existing active/due participant owners only after a separate concrete design identifies safe unchanged-rule skips. No measured evidence supports claiming this history conversion alone will achieve normal speed.

## 8. Expected growth and pressure tests

Let R be actual receiver acquisitions, P independently checked partitions/features, C changes/occurrences, M changed coverage bindings, A active history owners, S save cuts and B encoded-byte chunks. Current append-owner overhead can grow with R×P. The target pays batch-owner overhead for R+C's ordered pieces, coverage preparation for M, and retains the unavoidable exact scalar checks/changes. Physical rows follow actor/save/byte blocks, approximately O(A×S+B), rather than native containers×operation kinds×save cuts. The first-use descriptor cost still follows used bindings per block. Shared rich content, real receiver differences and exact samples are not constant-cost.

For illustration only, one receiving boundary checking ten subjects with four independently covered groups can currently make forty check appends. The target makes one bounded batch with the same exact coverage. Likewise one successful sixteen-feature geometry-set check needs one coverage entry, not sixteen standalone operations. These illustrate named removals; the diagnostic has no histogram proving that this is the actual average or a percentage reduction.

Dense first exposure still establishes every legitimately received current contact, local identity and grant. Only admitted history is recorded; attention does not hide the other visible people. Rich neutral preparation can be shared across compatible observers. A character's ten years of history adds no lifetime scan: recent bodies/charge headers expire by policy, while useful names, places and accounts follow their separate limits. Total learned relationships and objective archives retain their existing growth policies, not a newly invented cap.

| Case                                         | Required result / useful failure                                                                                                                                                                                                                   |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ordinary walking and stationary surroundings | Preserve all actual admitted positions; common observer frame appears once per batch. A stationary body does not receive a new copied appearance just because the observer moved. Exact checks remain; absent checks cannot support extrapolation. |
| Crowded arrival                              | Broad coverage includes more than ten bodies; only detailed admissions get sequences. Count initial current content, batch descriptors and history separately. No private recognition by shared ID.                                                |
| Attended anvil→kitchen→conversation sequence | Every received intermediate change, activity and speech retains order. No destination inference, narrative episode handler or model needed to label motion. Loss/reentry does not bridge unseen travel.                                            |
| Independently stale face/position/name       | New position/check masks cannot freshen old face or grant a name; partial check seeds preserve old dates after cold load.                                                                                                                          |
| Daughter/cliff/fifteen pursuers              | Familiarity can prioritize the daughter; broad pursuers and acquired geometry remain available outside slots. Native supported cues precede optional cognition. No daughter/cliff handler, unseen terrain or all-pairs diary.                      |
| Equal values, unknown identities             | Different originals/observers stay different; later recognition changes current supported associations, not past knowledge.                                                                                                                        |
| Correction during read/save                  | Exact revoked sources disappear before disclosure; independent B and other members survive. Old captured answers fail their fences; newer unsaved entries and a late acknowledgement cannot resurrect A.                                           |
| Expiry and restoration                       | Exact partial frontier hides expired entries before deletion. Learned support survives separately. Pending+saved reads contain each entry once; actual checkpoint restore and subsequent cold reopen preserve dates/order without observations.    |

## 9. Reviewable stages and acceptance

1. **BK20 — Receiver batches and shared reads.** Convert all five append producers, acquisition/inspection/speech/outcome callers and current/geometry recording. Separate freshness from recording membership; consume dirty reception directly in attention and maintain its next deadline. Remove per-partition append owner calls, repeated immutable membership counting, full candidate construction on reuse and full terrain-set expansion on a compatible check. Keep this reviewable as an intermediate source commit; no dual final runtime.
2. **BK21 — Chronological block conversion.** Convert current/proof/reference, temporal selection, pending overlays, saved codecs/schema/indexes, privacy/correction, account support, exports and restoration together. Remove open-closing-span reservations, delayed span append and `mind_temporal_span_ranges`; pack mixed actor suffixes across containers once per save. Preserve rich sharing. No old-format adapters, parallel history store, full scene baseline or ordinary saved-prefix rewrite. Validate first-use seeds against an independently timed, irregular, partially covered sequence and cold as-of reads.
3. **BK22 — Exact frontiers and set-based maintenance.** Convert every access consumer before removing per-page retirement flags/scans. Maintain bounded recent charge headers through one owner; ordinary age/quota selection uses zero database reads. Batch actual account candidates across scopes, and collect wholly ineligible blocks with durable-cut/pending-reference safety. Check partial boundaries, withheld save completion, correction, active obligations and restore. End-to-end removal counts must include downstream rows, indexes and ownership, not only native operation envelopes.
4. **BK23 — Full integration and operating qualification.** Review the complete affected diff and supported caller inventory, update current contracts only when installed, then run selected existing semantic/static checks and the smallest measurement below. Preserve all BK12/BK16/SR07 obligations, future physical sensing and full PP07/SAI-A scope. No unit suite is required by this design and no new maintained tests are authorized by it.

First validate exact supported behavior through ordinary walking, crowd arrival, irregular attended changes, partial freshness, loss/reentry, correction during pending work and actual cold/checkpoint restore. Structural acceptance requires one append/accounting boundary per compatible receiving batch, no lost logical facts, no per-kind page fan-out, no late-span relation, zero routine SQL recent-frontier reads/page-retirement updates, and no copied rich-value baseline per observer/save. Changed format validation, failed-save rollback and private read fencing remain mandatory.

At the end of authorized implementation, use the existing bounded diagnostic owner to count **operation kinds/logical facts**, batch/seed/proof/value bytes, tables/SQL families with calls/statements/rows/bytes, read causes, actual index work, and start/end produced/collected/debt bytes at matched boundaries. Attribute SQL source families through stable caller labels without logging private parameters. This fills the current evidence gap; it is not a reason to launch another campaign during design. Check one unchanged attended set across saves, one changing/partial set and two small crowd cardinalities before interpreting totals. Reject mere counter renaming, a lower clock/activity level, larger context/retention limits, hidden prefix replay or reduced personal evidence as a gain.

Then one clean five-minute standard gate on an adequately uncontended host must still reach ≥0.98 normal speed without concealed pause, routine gaps or growing pending debt. Record actual useful game progress, command tails and main/backend CPU separately. If it fails, take at most one bounded attribution and stop for explanation; do not enter another tweak loop or expand population. If it passes, measure multiple retention cycles for production/reclamation balance, retained headers/heap and cold read growth before wider existing scale qualification. Stop if descriptor duplication, query scans, metadata retention or deletion debt grows without convergence. No percentage speedup or hundreds-of-actors capacity is promised in advance.

## 10. Decisions and maintained records

Recommendation: chronological receiver batches, immutable mixed save blocks, useful rich-value sharing, exact actor frontiers and derived bounded retention metadata. This deliberately replaces the installed late-closed-span representation; it does not weaken exact received chronology. Keep all current sensing/attention/action/save defaults. Reduced canonical bookkeeping means the same byte allowance may retain more useful evidence; logical fact/context counts still expand coverage and age limits remain unchanged. Physical first-use seed/index bytes do not become fictional observations.

No product decision is blocking this proposed design. Actual operation-kind proportions, query-family dominance, descriptor/ownership byte balance, candidate-index selectivity and attainable capacity remain empirical uncertainties. The recommended implementation has explicit removal tests for these risks; approval to implement is still required. Further native-rule reduction is a separate design need, not silently included here.
