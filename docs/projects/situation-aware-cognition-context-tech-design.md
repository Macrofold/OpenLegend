## 1. Scope, baseline and controlling contracts

This document specifies the implementation of [situation-aware cognition context](situation-aware-cognition-context-feature-spec.md). It changes how the server prepares and presents an informed character decision, not what the character is allowed to know or do. The runtime source baseline is `Macrofold/OpenLegend`, `main`, commit `0b1262a597ca718be54c287eea0619b073952f32`; the accepted [NPC speech streaming design](npc-speech-streaming-tech-design.md) is reconciled against that repository's `main` at `a612eecf43d225b5f9087287573ec3e054641cf9`. The relevant runtime cognition implementation is unchanged between those commits. Statements headed **Current** describe that inspected implementation. **Target** describes the coordinated design. No runtime improvement, provider-token saving, delivered public speech stream or character-quality result is established by this document.

The [memory contract](../memory-architecture.md#3-one-compact-model-facing-context) owns actor perspective and required evidence; [action availability](../action-capabilities.md#action-availability-and-temporary-execution) owns executable choices; [identity](../identity-and-references.md#contract) owns exact references; [save/load](../save-and-load.md#continuation-and-identity) owns continuity; [AI providers](../ai-providers.md) owns dispatch and financial outcomes. This design supplies their coordinated context implementation. It creates neither a second memory store nor an action authorizer. The [engine/world boundary](../engine-and-world-boundaries.md#5-a-repeatable-boundary-decision) remains controlling: installed content supplies its meanings, while the server enforces permitted reads, bounded work and final admission.

The core scope covers construction and presentation of ordinary generated decisions, direct replies, ordinary native action selection, configured decision reconsideration, and currently implemented consumers of their shared preparation and response payloads. Preserve each installed caller's actual evidence, operation, inspection, provider and publication contracts. Reflection and consolidation consume corrected shared payloads/evidence only where the changed definitions already reach them; this project does not turn ordinary cognition into the reflection harness. A request begins with fresh model conversation state under the existing policy.

This project can ship independently of pending SPK, NST and CTR implementation. Their selected interfaces below are coordination requirements when separately installed, not features or whole-project acceptance gates assigned to SC. In particular, sparse `operations` can be the complete current SC delivery; NST later replaces that sole generated envelope with its sole `records` envelope at its own coordinated cutover. Existing installed privacy, speech-publication, receipt and source-eligibility contracts remain mandatory. Section 10's server-bound revisions/work-mode projection is a fully specified optional follow-up; core delivery retains current revision fields and meaningful modes. Worked gameplay cases illustrate generic information invariants and do not require adding the depicted mechanics, worlds or personal-history systems.

## 2. Non-negotiable properties

1. **Preserve complete accepted identity.** The accepted About me text, protected author-defined identity and current character voice are not truncated, replaced with keywords or rewritten by a per-request summarizer. Derived retrieval cues never replace that text in a generative character decision.
2. **Preserve the complete required actor-permitted evidence.** The initiating cause, independently required coalesced causes and personal work outcomes, relevant corrections, protected commitments, current goals/work, and dependencies necessary to interpret the selected situation remain present. This means complete permitted meaning, not omniscient knowledge or every historical record.
3. **Keep independent choices.** A short action list is assistance. Unlisted attempts, declining, quiet continuation, curiosity, play, affection, solitude, humor and other supported noninstrumental choices remain possible. Relevance cannot become a native permission check or prescribe the emotionally correct response.
4. **Keep speech and action together.** One reply may contain speech, action and other independent logical operations, including repeated kinds. NST's speech transport records normalize to one logical utterance, not extra operations. Physical completion and admission order are different: an accepted walk can continue while a later permitted speech operation is spoken.
5. **Preserve exact references.** Every model-visible object/person/action/method/knowledge handle has one matching request-owned binding. Names are labels, never an alternative resolver. Removing UI form metadata never removes the References mappings.
6. **Preserve uncertainty and limitations.** A partial inventory page, failed retrieval, inaccessible container, uncertain identity or unprepared action is not evidence of absence. A person's statement remains testimony; an inspection is not proof that the described event happened.
7. **Keep costs and outcomes honest.** Preparation does not consume native resources, random numbers or durable object IDs. No automatic paid repair, mandatory new detail round or hidden summarization call is added. Existing separately authorized routes retain their own accounting and failure rules.
8. **Use one accepted snapshot and explicit dependencies.** Retain owned immutable preparation across waits. Recheck changed authority, evidence and operational prerequisites at the responsible boundary; do not rebuild an answer from a mutable global “latest context.”
9. **Optimize work before output.** Select permitted IDs and payload sizes before hydration, formatting, exact geometry or schema expansion wherever the owning query supports it. A final 16-row list does not justify scanning every item or person first.
10. **Measure the full request and actual play.** Count instructions, selected facts, reference text, schemas, tools when present, output allowance and any separately admitted preparatory calls. Actual provider usage remains distinct from local estimates. Smaller requests alone do not prove informed or enjoyable behavior.

The hard guarantee is mechanically checkable coverage of declared required sources and dependencies. No finite selector can prove it anticipated every surprising connection an intelligent character might make. The objective is an economical, sufficient representation of the current permitted decision: remove redundancy and unsupported relevance while preserving necessary meaning and demonstrated decision quality. It is not a proof of globally minimum context, a requirement to fill an allowance, or a guarantee that a model chooses one predetermined answer. Existing discovery and supported inspection remain available; demonstrated consequential omissions are quality failures to correct at the source, requirement, selection or representation owner.

## 4. Typed preparation model

### 4.1 Scope and immutable ownership

`DecisionContextScope` contains existing world/timeline/generation, actor and physical-life identity, authorized request/audience/control state where applicable, decision/job ID, captured native sequence/simulation time, selected cognition and installed-definition pins, selection-policy version and accepted About me revision. It also retains privacy/evidence revisions and the selected source families needed by the existing publication guards. These values stay server-side except meaningful time, audience or uncertainty the character needs to understand. Capture the actual immutable selection policy with the request; configuration changes during a wait cannot reorder or reinterpret its prepared evidence.

`PreparedDecisionContext` owns:

- The frozen scope and an immutable selected-source manifest.
- The composed decision requirements, discovery cues and their exact support keys.
- Read-only context units and their dependency graph.
- The required/optional disposition of each selected unit and a reason for that disposition.
- Final rendered instructions/context, sparse schema, reference bindings and action bindings.
- Request-budget accounting and coverage summaries.
- Dependency revalidation and admission callbacks using existing semantic owners.

Capture immutable IDs/scalars or owned copies. Do not retain Immer draft proxies, a mutable `WorldState`, a borrowed reusable cache slot or arbitrary raw source objects as the prepared result. Existing pure native preparation can be retained only under its documented lifetime/dependencies. An unrelated request replacing a shared cache does not erase the retained preparation. A relevant authority or source change can still invalidate it.

The final render, schema, reference map and binding digest must all describe the same finalized manifest. Late additions from appraisals, actor invention or selected activities are admitted into that manifest before the request is frozen; they cannot append unaccounted text or new schema references afterward.

### 4.2 Context units and source identities

A `ContextUnit` is one source-owned, actor-permitted meaning that can be included or omitted as a whole. It is not an additional stored memory. Its native `family` discriminators are `identity`, `body`, `work`, `obligation`, `evidence`, `feeling`, `contact`, `possession`, `method`, `capability`, `instruction`, `reference`, `coverage`. These identify actual data meanings and their typed owners, not scenario classes, relevance priorities, quotas or an admission order. Another installed capability or event using those existing native types does not require changing the compiler. A genuinely new native source type requires its own typed owner/adapter, with the same eligibility/dependency/coverage obligations; it does not justify a scenario switch or extensibility platform. Dependencies such as a reference or coverage statement normally travel with their supported root rather than competing as independent optional facts. Each unit carries:

| Field              | Meaning                                                                                                                                                                                                                                                                                                  |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `key`              | An unambiguous structured key with world/timeline, actor, source family, stable source identity, revision and selected view where required. Use the existing key/digest owner; never concatenate arbitrary IDs with delimiters.                                                                          |
| `source`           | Exact retained evidence, installed definition or native projection owner and its version/dependency stamp. Several source families may legitimately share an ID.                                                                                                                                         |
| `disclosure`       | Already-validated actor scope and supported perspective; no raw hidden state is available to the selector.                                                                                                                                                                                               |
| `meaning`          | Typed permitted values/roles/qualifiers, or exact attributed authored prose.                                                                                                                                                                                                                             |
| `dependencies`     | Exact unit/reference/definition keys needed to interpret this unit safely and meaningfully.                                                                                                                                                                                                              |
| `requiredReasons`  | A set of explicit reasons, such as initiating cause, current obligation, selected threat strategy, bound work, contradiction/correction, or dependency of another required unit. Empty means optional; no semantic model may clear a nonempty set.                                                       |
| `selectionSignals` | Existing typed topic/subject/purpose/constraint associations and supported relevance evidence. These are data contributed by semantic owners, not a fixed situation enum; an inferred association is never promoted to a fact.                                                                           |
| `representations`  | Available deterministic complete wording, existing valid source-linked compact wording where allowed, and an optional discovery description. Each states what meaning it preserves; a discovery description is not a substitute for required detailed evidence.                                          |
| `size`             | Known encoded lengths and proven lower/upper bounds for each admissible complete representation, derived from source metadata before full hydration. Identify exact counts separately from estimates; an oversized upper estimate alone does not prove overflow. Final rendered bytes are checked again. |

Deduplicate only the same source/meaning and compatible view, retaining the union of roles and dependencies. The same utterance as trigger and recent memory is one source with both reasons. Two similar utterances by different people are two occurrences. A quote and a claim that it describes a true event are different meanings. A corrected account and its correcting evidence remain distinguishable. Two purposes using the same physical first action remain separate choices.

### 4.3 Coverage has explicit outcomes

Use a discriminated result at each source-family query and dependency expansion:

| Result         | Permitted interpretation                                                                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `complete`     | The scoped query established all results under its stated predicate and snapshot. Only this can support a negative statement for that predicate.                                |
| `partial`      | A valid page/subset is supplied; retain its cursor or continuation capability and what remains unsearched. Do not calculate an exact omitted count by scanning the rest.        |
| `notRequested` | The family/detail was unnecessary for this request or remained optional. It is not evidence that nothing exists.                                                                |
| `unavailable`  | A required read/optional service failed, was exhausted or could not be prepared. Preserve whether a usable subset exists; never substitute an empty complete result.            |
| `stale`        | A relevant scope/source/permission changed. The old content cannot be newly disclosed or accepted as current.                                                                   |
| `forbidden`    | The current actor lacks permission to obtain the requested meaning. The model-facing result must not reveal the hidden resource or reason beyond the owner's permitted refusal. |

Render coverage only when it could change the character's decision: for example a partial possession page, uncertain attribution, unavailable recollection or an uninspected container. Keep diagnostic counts and internal codes out of ordinary character instructions. Preserve distinctions between current observation, last seen, heard report, inference, imagination, correction and known absence.

When NST is separately installed, its [terminal semantic readiness](npc-speech-streaming-tech-design.md#terminal-semantic-readiness) is an additional source-owner eligibility rule, applied before these results: open accepted speech is available to its permitted human presentation route but ineligible for model/word-derived consumers. Its shared eligible-source selector and derived readiness metadata must precede ranking, source limits, exact required-ID reads, hydration, maxima and derivatives; no `requiredReasons` flag or opportunistic context read bypasses it. This does not discard an eligible required utterance. Closure makes the complete/interrupted permitted account newly eligible once, using its retained readiness order while preserving occurrence chronology. Carry the interrupted marker and never infer the missing ending. An older occurrence becoming ready must invalidate affected compacted source membership through the existing owner. SC preserves this interface when present; implementing NST readiness is not a prerequisite for the current context compiler. Context selection introduces no per-part retrieval, embedding, summary, reaction or paid call.

## 5. Situation detection without an exclusive classifier

“Situation” means the current combination of permitted facts, constraints and the admitted caller's decision question. It is not an engine enum, a scene classifier or a catalogue of prompt templates. Existing semantic owners determine which of their meanings and dependencies apply; the compiler combines those contributions without selecting a winning situation label. Do not hardcode tests for names, species, items, locations or example scenarios, or purchase another model call to choose a context template.

### 5.1 Generic decision requirements and source contributions

Compose one request-local `DecisionRequirements` value from the current caller, its captured world/cognition definitions and existing actor/source owners. This is an internal typed boundary at the existing preparation module, not another stored policy or extensibility registry.

| Member             | Required meaning and producer                                                                                                                                                                                                                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `question`         | The actual admitted caller question/purpose and its existing route/strategy identity. Preserve an explicit player's or native caller's question; do not replace it with an inferred narrower task or the answer the benchmark expects. An ordinary autonomous decision uses its current authored decision purpose.        |
| `requiredRoots`    | Exact source/unit keys with nonempty required reasons contributed by the caller, current identity/body/work/goal/outcome owners, installed rules and route requirements. Contribution is additive; neither another contributor nor optional relevance may clear a source-declared requirement.                            |
| `queryCues`        | Supported typed source/subject/definition/purpose/constraint associations from permitted facts and current definitions, with the support keys that justify them. Use these through existing scoped queries and attention. Cues are not evidence that an inferred event occurred and are not a fixed list of scene labels. |
| `enabledSemantics` | The current route's actual operation/capability meanings, bindings and required shared instructions, contributed by native definitions. This preserves genuinely available broad capabilities and open attempts; predicted likelihood never revokes a legal operation.                                                    |
| `selectionPolicy`  | The immutable current world/cognition relevance and representation policy, including its version, existing thresholds, source-ranking semantics and any established cross-source comparison. No per-family quota, scenario-specific template, new relevance model or new tuning language is introduced.                   |

Each existing source adapter receives the captured scope, the relevant typed cues/exact required keys and the remaining existing work allowance. It returns eligible `ContextUnit` metadata, exact dependency keys, actual query coverage and any existing relevance evidence/order. Its dependency expansion is a bounded read by those keys, not a callback with arbitrary world access. The source owner interprets its data: an event owns participant roles and attribution; an installed activity owns parameter meanings and consequences; current work owns continuation and committed-resource facts. The compiler cannot infer hidden dependencies from free text, invent a game consequence or decide that two vaguely similar records are the same event.

Composition is mechanical: union required keys/reasons and cue support; deduplicate only identical source/meaning/views; retain conflicting accounts as distinct evidence; take the union of enabled meanings under the caller's actual authority; close all declared required dependencies. If contributions disagree on a source revision or permitted view, obtain a coherent owner result or return stale/unavailable. Do not resolve the conflict by choosing whichever text is shorter. Known required evidence remains protected even when no optional policy recognizes a cue.

Optional admission requires a supported positive relevance reason for this question or the actor's currently applicable broader concerns under the captured policy. Source existence, available bytes, a family name or a repertoire rank is not such a reason. A contrary account, alternative use or personal association may provide that reason through its existing source/policy; the compiler does not reserve a compulsory “fun,” danger or social slot. Stop when no qualifying candidate remains, even if the request has ample unused space.

The policy maps existing relevance evidence into a deterministic candidate order as follows. It declares one comparison basis for the whole participating candidate set: either an already defined shared rank/ordinal, or only source-local ordering. A shared rank is usable only when its meaning and direction are defined for every participating source; sort by that common rank and then the neutral deterministic tie key below. Do not compare unrelated raw vector scores, recency numbers or model scales as though they shared units, or mix ranked and unranked pairwise comparisons. With only source-local ordering, preserve each source query's established relevance/recency order, treat its current qualifying heads as tied, select the smallest tie key, advance only the chosen source and repeat. This fallback supplies reproducibility for otherwise incomparable candidates; it makes no semantic cross-source priority claim and imposes no round robin, raw-score sum or required contribution from any family. Capture the selected basis with the request; source completion order cannot affect selection. The first implementation uses the current policy's actual shared scale when available, otherwise the specified source-local merge; it does not need a new calibration system. Adding a cross-source calibration later requires the existing qualification owner and does not alter required-evidence rules.

For both equal shared ranks and source-local head ties, compute the tie key with the existing digest owner over the canonical complete structured source identity from section 4.2. Compare digest bytes lexicographically; compare the canonical identity bytes only if the digests collide. Identical source/meaning/views are deduplicated under the existing rule. Do not sort directly by family-prefixed identities: that would give a lexically early family an unintended admission advantage. The digest removes that prefix-order rule without introducing a scorer, new hash implementation, randomness, quota or claim of optimal relevance. Retain each computed tie key within this request and meter its encoding, hashing, storage and comparisons under section 13.1. Required facts and their dependencies remain protected regardless of this optional ordering.

For example, a newly installed capability using the existing activity definition and known-method types supplies its own purpose, parameters, supported constraints and output/reference dependencies. The existing capability/method owner exposes those units when its native availability and the current question/cues support them. The same closure, ordering and rendering handle them without `if greeting`, `if crafting` or a new engine signal. Adding a genuinely new native data meaning may require a typed adapter at its source owner; it does not require defining every possible situation in which that meaning could matter.

The feature document's scenarios illustrate combinations of these contributions. They are not an exhaustive input taxonomy, ranking policy or feature backlog. Absence of a matching cue does not prove a capability impossible; incomplete discovery retains its honest scope and existing open-attempt/inspection paths.

## 6. Selection, dependency closure and budget admission

### 6.1 Preparation sequence

Run the following sequence once for an admitted decision opportunity, reusing existing actor/source preparation. The sequence is not another periodic scheduler.

1. **Capture scope and flush this actor's pending sources.** Resolve current authority, body eligibility, accepted identity and relevant installed definitions. Obtain one coherent native/read snapshot and the matching evidence-generation boundary. Reuse the existing memory read cache and source preparation; do not flush or hydrate unrelated characters. When NST is installed, use its default-safe terminal-eligible source APIs and readiness-order maxima before subsequent selection; human-readable open speech is not a model source.
2. **Read required metadata by exact identity.** Start with the singular trigger, independent coalesced causes, required outcome source IDs, active obligations/corrections, current goals/frontier/attempts, current body and accepted About me. Read source kind, revision, eligibility and known payload length before optional bodies. A source ID's presence in another family does not satisfy the required record.
3. **Compose decision requirements.** Combine section 5.1's caller question, additive owner-declared required roots, supported query cues and enabled semantics from those facts and cheap permitted current observations. Preserve any installed strategy's complete required choice set. Do not run optional relevance filtering over a source or strategy whose current contract requires completeness; no scene label determines the request shape.
4. **Build the required dependency closure.** Starting from every required unit, repeatedly include its exact dependencies until no new keys remain. Shared dependencies are included once; cycles terminate through the visited-key set. Required speech brings its actual speaker/received-role/gap information, work brings its purpose/transition/held-resource meaning, and any executable choice brings its exact references, units, required parameters and known consequences. A dependency is not an excuse to read hidden world truth.
5. **Prove early feasibility of the request.** Use exact metadata counts or valid lower/upper encoded bounds for the required complete representations, references, semantic instructions, schema and applicable appraisal/invention/strategy additions. A proven lower bound above an existing allowance can refuse before optional work. An upper bound at or below it establishes provisional fit. When the allowance lies between them, perform the bounded exact required-set accounting/rendering needed to decide, through the same source/preparation limits, before optional hydration, compaction, attention or dispatch. An overly conservative upper estimate alone must not reject a request that exact permitted preparation can show fits. A storage envelope's size is not a lower bound on a shorter faithful model representation. Never omit a known required field to obtain admission or hydrate beyond a source owner's hard limit to settle uncertainty.
6. **Discover optional candidates from bounded indexed subsets.** Preserve existing direct-query and semantic-retrieval owners. Exact subjects, current purposes, obligations, recent changes and contradiction links are queried before optional semantic search. Preserve the current hard-query baseline as candidate discovery and failure fallback coverage, not a demand to repeat full catalogs in every prompt. Record which families were actually searched. Candidate selection does not grant perception, inspection, learning or execution.
7. **Apply existing optional attention.** Supply semantic relevance only the permitted context and candidate meanings needed for that question. Do not include the generative response schema/manual or UI form definitions in a Jev attention request. Retain current relevance thresholds/uncertainty semantics and the selected world's behavioral guidance. No model result may demote required units.
8. **Choose useful complete optional units within remaining space.** Filter and order positively justified candidates by section 5.1's captured comparison basis. Equal shared ranks, or the source heads in source-local mode, tie by the existing digest of complete canonical structured source identity; canonical identity bytes break only digest collisions. This is reproducibility for an otherwise unresolved order, not a semantic comparison or family priority. Never use locale collation, query completion order or world RNG. For each next candidate, admit its complete root and full dependency closure only if its supported meaning adds decision value and fits. An already represented identical meaning needs no second root. When a closure does not fit, mark that candidate considered once and continue with the next ordered candidate, advancing its source in source-local mode; do not stop all discovery at one oversized source. Dependencies join the selected root immediately and are not separately ranked. Remove optional roots in reverse actual admission order when later exact accounting requires fitting; required roots remain protected. Stop when no qualifying candidate remains, not when the allowance is full. No fixed source-family turn, positive/negative memory quota or mandatory opportunity slot is selected.
9. **Hydrate only selected bodies and required dependencies.** Charge all visited rows, source bytes, native checks and dependent queries to the same preparation. If a selected body is unavailable or larger than its bound, apply the dependency-failure rule below and record actual coverage; never leave a selected root without its supporting meaning. Required-body failure follows section 6.3 and is never downgraded to a generic summary. A bounded extra metadata record may establish continuation without computing the full omitted population.
10. **Refresh changed current facts after asynchronous preparation.** Preserve source-time history. Refresh only the exact affected current observations/body/work/definition facts through their owners, retaining the original actor/audience/source scope. Recompute any newly required closure. A failed request-wide authority/scope or required observation/recognition/source guard invalidates that preparation. A source change confined to optional support follows the same dependency-failure rule; do not keep stale semantic content or an invalid fallback. New facts must not inherit old source timestamps.
11. **Create references and schema from the finalized manifest.** Build all visible labels/handles, action bindings and knowledge references together. Include current relevant appraisal/invention context through this same step. Account for encoded unit fragments, reference entries, schema fragments and structural delimiters before assembling complete strings. If the total exceeds an allowance, remove optional roots in reverse selection priority, update their supported closure and affected reference/schema fragments, and then render the complete final request. Measure its actual UTF-8 bytes; a remaining required overflow refuses dispatch.
12. **Freeze and admit the exact request.** Retain the prepared bytes/schema/manifest and their digest for dispatch, local validation, diagnostics and source checks. Run normal spending/execution admission once. No adapter may silently append a manual, full activity catalog, old conversation or raw world object.

A deterministic correction of local encoding after removing an optional unit is unpaid preparation, not a provider retry. The preparation loop is bounded by the admitted finite candidate set: each iteration either considers one previously unvisited candidate, removes an optional root, finishes, or returns a coded failure. Do not repeatedly materialize the entire prompt/schema after every removal or grow speculative variants before size admission.

Maintain the selected dependency graph and its accounting incrementally. At graph construction, collapse dependency cycles into components; the resulting component graph is acyclic. Each selected component holds protected-root support, optional-root support and support from selected incoming components. Activating a previously inactive component activates its dependencies; removing a root propagates deactivation only when no root or selected incoming component still supports it. A component containing required support cannot be removed. This handles a shared tool/reference or a cycle without deleting another retained choice's meaning or retaining an unreachable optional cycle forever. Cache each admitted fragment's encoded length, including escaping; update counts and affected bound reference/enum fragments without copying unchanged bodies. Candidate-closure traversal and retained graph bytes use the explicit request-local compiler meter in section 13.1; current source-row guards alone do not enforce that work bound. Consider a rejected candidate once and do not repeatedly scan unselected source bodies. Sorting, cycle detection and accounting remain pure functions in the focused selection module, not a new graph service.

**Dependency failure:** use the retained graph's reverse edges, charged to the same meter, to find every selected root whose closure includes an unavailable or invalid source. If any required root is affected, follow section 6.3. Otherwise remove all affected optional roots, then deactivate only unsupported components through the existing support accounting. Preserve unrelated roots and shared valid dependencies. If bounded removal cannot finish, use only an already finalized still-current required fallback or defer; never dispatch a partly repaired manifest.

“Fits” must have an accounting basis. A proven lower bound over remaining space can reject an optional candidate for size; an upper bound within remaining space can admit it provisionally. Otherwise use an exact bounded measure when available. If the remaining optional preparation allowance cannot settle that candidate, record it as unprepared/partial and continue; do not claim its actual complete size was too large or its capability absent. Final required meaning and actual serialized limits still control admission. This preserves cheap metadata selection without mistaking an estimate for evidence.

### 6.2 Dependency rules that prevent misleading brevity

| Included meaning                                  | Required supporting meaning                                                                                                                                                                                                             |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A recent answer such as “yes” or “leave it there” | The actual relevant preceding utterance/reference needed to interpret it, if retained and permitted; otherwise preserve ambiguity. Never guess a missing referent.                                                                      |
| An offered action                                 | Its exact target/tool/material bindings, known current requirements, quantity/unit, selected purpose, work transition and consequential known cost/cancellation facts. A description of a first step cannot promise the whole activity. |
| A continuing plan                                 | Remaining native steps/blocked state, current purpose and relevant bound outputs/held resources; completed effects appear through their source-linked memories, not duplicate plan prose.                                               |
| A promise or accepted cooperation                 | Its exact permitted parties, terms, current status, deadlines and how an independent action or interruption affects it.                                                                                                                 |
| A fear/anger/other selected feeling               | Actual available value and installed scale/meaning, subject/source and relevant lifetime, not an invented zero or a label stripped of intensity. Required threat feelings use exact lookups/continued pages at the appraisal owner.     |
| A known method                                    | What is actually learned, relevant executable steps/requirements/output contract and currently unsupported or unknown prerequisites. Installation alone is not learning.                                                                |
| An inventory conclusion                           | The relevant item identity/quantity and the query's actual coverage. “I have no food” requires a complete scoped predicate, not the absence of food from one page.                                                                      |
| A last-seen destination                           | The retained observation's time/location/identity support and current uncertainty; do not replace it with the target's hidden current position.                                                                                         |
| A claimed or corrected event                      | Its acquisition, speaker/observer roles, uncertainty and eligible contradictory/correcting support. Similar text does not establish corroboration.                                                                                      |
| A numerical comparison                            | Values, units, direction of the scale, current-versus-historical time and any known threshold that changes the decision.                                                                                                                |

Some necessary context is a **negative constraint**: no clear view, no understood words, a tool already committed to work, a refusal, a corrected belief or a capability currently unavailable. Do not delete these merely because their fields are empty/false. Conversely, omitted optional mechanics require no invented negative claim.

### 6.3 Overflow and unavailable information

Use the existing `ContextBudgetError`/coded preparation outcomes and extend their internal detail to identify the responsible owner and required unit class. `required-context-overflow` is an internal preparation reason under the existing job/trace disposition `context-exceeded`, not a new replacement public disposition. `required-context-unavailable` similarly distinguishes missing required preparation within the existing failure/defer owner's result; it does not redefine provider refusal, empty output or financial uncertainty. Do not place private IDs/text in public errors. The operative order is: remove duplicate representation; use a shorter deterministic representation that preserves complete required meaning; remove optional units and their unique dependencies; then refuse/narrow the operation whose required evidence cannot be obtained. Never truncate a required quotation, About me, promised terms, exact quantity or reference map.

| Condition                                                                    | Behavior before generation                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Optional recall, attention or history compaction fails                       | Use required evidence plus valid existing compact context/native fallback that fits. Mark optional coverage incomplete. Do not buy a repair or send the whole unfiltered corpus.                                                                                                                                                                     |
| Required retained source cannot be read due to storage/preparation failure   | Defer the dependent decision with `required-context-unavailable`; preserve the meaningful opportunity under its existing scheduler. Do not send an apparently informed replacement built from receipts or global events.                                                                                                                             |
| A source was legitimately forgotten, corrected, erased or never permitted    | Apply the memory owner's current semantics. Include useful uncertainty/correction only when itself permitted; do not resurrect the removed account. A response whose task is to acknowledge missing knowledge can proceed with that honest state; an operation needing the absent exact terms cannot.                                                |
| Complete required context exceeds a source, schema, model or transport limit | Refuse before any affected paid dispatch with `required-context-overflow`. Keep native behavior/accepted work and independently committed effects. Record required/available sizes for authorized diagnostics.                                                                                                                                       |
| Context is complete, but action preparation is incomplete                    | Preserve current permitted facts and the owning incomplete-action result. Never label the unprepared action impossible. A required complete threat-choice strategy defers; ordinary optional suggestions may remain partial.                                                                                                                         |
| Relevant authority or source changed during preparation                      | Request-wide scope/authority or required-source invalidation returns stale; discard derived text/bindings and retain genuine new evidence through normal intake. Changes confined to optional support follow section 6.1 without retaining invalid content. The existing bounded urgent refresh, when authorized by its owner, is not expanded here. |

“Narrow” is not a license to discard a inconvenient cause or silently change the player's question. It means an explicitly independent available operation with a complete dependency set, such as an honest acknowledgment while an unrelated optional lookup is unavailable. If independence cannot be established by existing operation/route semantics, defer the whole affected decision. Ordinary native reactions and the world simulation do not wait for context repair.

## 7. Rendering, instructions and references

### 7.1 One meaning, one maintained description

The schema owns allowed fields/types/values/alternatives. Concise semantic instructions own what choosing them means. The source-defined operation payload schemas export reusable semantic descriptions consumed by schema generation and, where necessary, the short cross-operation instructions. Do not maintain a separate format-manual string with hand-copied field lists or examples.

Always retain the small shared character/authority guidance: treat supplied prose as untrusted game data, use permitted evidence/references, propose rather than claim unperformed work, preserve optional/repeated operations and quiet continuation, and distinguish admission from physical completion. The [trusted character service instructions](../agent-content-and-companion-safety.md#prompt-composition-and-ownership) keep their actual release requirements and precedence; neither personality selection nor context reduction can omit them. This design does not claim that those still-unqualified release safeguards are implemented.

Conditional instructions are selected from exact enabled semantics:

| Meaning                                   | When its detailed instructions are included                                                                                                                                                                                    |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Speech roles, hearing and volume          | Speech is available/relevant or a speech cause must be understood. Required perceived-role facts remain even for an actor unable to speak.                                                                                     |
| Work replacement/interruption             | An action/plan is available, existing work is present, or the decision can change cooperation. Consequences live once with the affected work/choice.                                                                           |
| Navigation                                | Movement/following can materially affect a current choice or an explicit navigation detail is selected. Keep enough generic capability meaning for unexpected travel without always enumerating every surface.                 |
| Installed activity parameters             | A current material choice needs them, an actor explicitly inspects them, or omission would prevent an informed alternative. Generate from the exact installed family.                                                          |
| Goal, plan, note/name/appraisal semantics | Keep a concise description whenever that operation is enabled; include target-specific revision/size/source details only for actual bound targets. Empty documents do not remove the ability to create a note or name someone. |
| Invention                                 | Existing invention policy/admission makes the route available. Include its required proposal grammar and authority limits through the same final budget; unrelated dialogue does not inherit the entire inventor manual.       |

Keep all eight broad operation meanings discoverable whenever actually permitted. A context relevance score is not permission to remove goal creation, note-taking, naming or appraisal from ordinary thought. Genuine body/world/route limitations may remove unsupported schema branches, as the existing capability owner does. A fallback route that forbids proposals retains that actual route restriction; optional selection cannot invent a new one.

The minimum instructions should state explicitly that **speech can accompany ongoing physical work** and that **several different operations can appear in one reply**. No instruction asks for a thought, action, feeling, goal or explanation merely to complete a template. Examples used for documentation or checks are not pasted into every model request.

### 7.2 UI metadata versus necessary labels

Create an AI projection of installed request definitions at their current semantic owner. Keep the family ID, useful purpose, exact field meanings/types, real choices, units, deadlines, mode consequences and supported output/continuation facts. Exclude `presentation`, `submitLabel`, form widgets and duplicate field captions that add no semantic information. A label that explains a meaningful value stays in concise wording even if the UI also uses it.

The model receives one activity description, not a raw UI form. The human menu can continue using its richer presentation from the same installed definition. This does not authorize copying world laws into server constants or forcing another world to use bundled survival actions.

### 7.3 Exact name-to-ID mappings remain

The finalized manifest provides one authoritative request-owned mapping for every selected entity, possession, container item, remembered subject, action, known method and editable knowledge target. Required mappings are reserved before optional text. A schema enum of opaque tokens does not tell the model which token means Orin, the knife or the cache; useful labels remain mandatory.

Initially retain the existing **References** section and consolidate duplicated descriptions elsewhere. Later render an entity's handle alongside its primary description and omit its second reference row only after a mechanical coverage check proves the exact mapping and its necessary roles are still present. Inventory-only IDs and inspected container-item IDs must survive either layout. A raw entity's global name/position is never recovered merely to enrich that row.

Reference construction uses the exact selected permitted ID closure. Move the derivation into the existing entity-reference owner with structured identity inputs and collision resolution over that selected set; do not hash all world entities before selecting a few references. Retain existing observer/recognition/exposure semantics, including SPK's accepted stable-recognition target when implemented. Recognition does not grant a name, current location or unseen history. Handle text may vary when a legitimate request's selected set changes; the immutable server binding is the authority. Never accept a handle from a previous request just because its short text happens to match.

For collisions, compute each selected subject's complete digest from the unambiguous owning identity tuple, use the existing short-prefix policy, and lengthen colliding groups deterministically until distinct. Build the final table before schema compilation. If later selected dependencies add IDs, rebuild the table, rendered annotations and schema together; do not silently change already-dispatched handles. Whole-world collision enumeration and a new persisted alias registry are unnecessary.

Keep namespace distinctions explicit. Entity handles cannot be used as method/definition/source/goal identities merely because both are strings. Surface and authored-definition IDs retain their current dedicated binding until a selected alias is introduced through the same owner. A method output refers to its earlier submitted step's actual receipt, never an invented future entity token.

### 7.4 Numerical and spatial presentation

Preserve all actor-permitted current body measurements required by the existing body projection, with installed meanings, units and scale. Keep exact quantities and boundaries required to choose or execute an action. Deterministic human-oriented formatting may remove irrelevant floating-point representation noise only under the attribute/geometry owner's explicit display precision; canonical stored values and executable bindings remain exact. Do not independently round health, food, time or a near-threshold distance in the context formatter.

Do not enumerate every public support surface simply because it is public. Select the current support, supports of actually described/selected destinations, relevant transitions and the permitted discovery path. A direct coordinate choice still uses the spatial owner's canonical support/placement validation; a reference is not proof of reachability. The [spatial contract](../spatial-world.md#movement) owns frame, height, support and route meaning. If exact safe movement needs a support whose identity cannot be supplied or inspected, retain that detail now or preserve the owner's unavailable result. Do not infer hidden geometry or pretend an unexplored route is clear.

### 7.5 Model-readable decision projection

The [existing decision benchmark](../verification/decision-api-benchmark.md) and its [corpus audit](../verification/decision-benchmark-audit.md) offer useful examples of supplied-context construction. Their recorded successes support examining that representation; they do not prove that a particular format caused success or that real-world retrieval already supplies equivalent evidence. The source details and qualified named examples remain in the [evidence record](situation-aware-cognition-context-evidence-and-decisions.md). Apply the following contract at the existing `response-context.ts` and native projection owners:

| Projection concern                       | Required behavior when relevant                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Question, evidence and output contract   | Present the actual caller question/purpose separately from attributed evidence and the authoritative response schema. Do not bury the task in an archive or duplicate the schema as a prose field manual. No expected answer, grader rationale, difficulty tag or author-only evaluation metadata enters the model request.                                                                                     |
| Current native state                     | Supply currently authoritative permitted counts, available/reserved resources, work status and applicable conditions directly from the native owner. | Meaningful values                        | Keep units, scale direction/range where necessary, time/frame, applicability and current-versus-historical status beside the values they qualify. | Attributed relational facts              | Keep subjects, objects, participant roles, purpose/action scope, source and uncertainty linked to the proposition. A change supersedes only the facts its owner says it changes; later testimony does not automatically erase an earlier experience or become objective truth.                                                                                                                                  |
| Capabilities and consequences            | Describe a selected capability's useful purpose with its actual prerequisites, relevant current costs/limits and supported output/consequence contract. | Exact references and independent choices | Place useful meanings next to their unambiguous request bindings, retaining the References coverage rule. Opaque IDs, answer position or a familiar benchmark name are never semantic evidence.                                                                                                                                                  |

These are projections of existing typed facts and definitions, not a new fact database, ontology, permission solver, predictive simulator or model pass. Do not copy a synthetic scene's one-goal/four-plan shape, generic consent flag, fixed meters, arbitrary memory bundles or guaranteed plan outcomes into production. Array sizes and fields follow actual source cardinality and necessary meaning. Preserve incomplete perception and uncertain predictions as such; the benchmark's answer key is never a missing source to manufacture. The compiler may reorganize or deduplicate faithful facts to make them usable, but cannot strengthen their authority or add unsupported certainty.

## 8. Detail access without a mandatory second generation

### 8.1 Selected first delivery

Use existing explicit native inspection and the ordinary unlisted-attempt path. Do not add a ninth response operation, a generic tool-calling loop or an automatic “retrieve then ask GPT again” sequence. Immediate generative levels retain their current zero tool-round allowance. The character may select a supported inspection as an actual action; its resulting permitted evidence can support a later ordinary decision under existing intake/admission. This is voluntary gameplay, not a hidden per-request tax.

An omitted optional detail must satisfy all of these conditions:

1. Its absence does not remove required meaning or a material urgent alternative.
2. The initial context retains the capability's useful meaning, so the character can recognize that the option exists.
3. Where decision-relevant information is omitted, a current exact permitted inspection/detail handle can actually obtain it. The open-proposal route may instead avoid loading optional invocation syntax only when the initial facts already support an informed exact intention and its existing grounding preserves every specified reference, amount and qualifier. Merely allowing a proposal that returns information-needed is not a way to retrieve missing knowledge.
4. The result's true scope, current availability, meaningful time/action consequence and coverage are understandable.
5. If no supported route can obtain the information when needed, the initial request includes the detail instead. A conceptual future inspection feature cannot justify deletion today.

Keep required information about an urgent alternative in the initial threat context. Requiring a character to inspect a weapon's known capabilities while being attacked is not an acceptable reduction. Likewise, known terms of an active agreement, currently held resources and an already inspected selected item do not become optional background just because they have dedicated readers.

Do not implement an unused tool registry now. This explicit gate does not postpone the required current-context fixes in SC01–SC11.

## 9. Compact response contract

### 9.1 Root and operation envelope

Retain eight logical operation kinds under the existing `RESPONSE_LIMITS`. When NST is not installed, SC ships the strict sparse `operations` root described here as its complete current contract; finishing SC does not require a subsequent NST release. If NST is already installed or separately cuts over later, its sole `records` root composes the same sparse payloads as specified in section 9.6. Each enabled route has one current generated format, not two accepted versions or a lasting compatibility reader. A request-enabled invention envelope remains a separate existing root property only on routes that actually support it; do not add an empty invention property to every reply. An empty logical response remains valid under either installed contract.

Each logical operation is a strict object containing exactly `localId`, `requiresAccepted`, and **one** of `talk`, `act`, `think`, `goal`, `plan`, `note`, `name`, `appraise`. The selected payload is nonnull. No inactive payload keys are declared or returned. All properties declared in that branch are required. Use `z.union`/nested JSON Schema `anyOf`, not a root union or a nullable object containing unrelated union alternatives. `additionalProperties: false` applies to every object. Native envelope validation must enforce the same actual structure, not require the old minimum key count or old null fields.

Common fields retain their existing meanings: `localId` is a unique request-local identifier matching the current supported grammar/length; `requiresAccepted` contains distinct earlier local IDs only. An empty dependency list permits independent admission. An earlier accepted operation is not proof that its physical work has finished. Later dependent operations are skipped with the existing dependency-refused outcome if the required earlier admission failed. Cycles, forward references, duplicate IDs and invented aliases are invalid. The native receipt keeps each component's actual disposition.

Use shared exported payload schemas for immediate operations, reflection and native preparation instead of introspecting `operationSchema.shape.note.unwrap()` after the envelope becomes a union. One payload owner may legitimately have a model-facing projection and a native command with server-bound metadata; neither is an old-wire-format reader. Update current producers/consumers in one coherent contract change, increment the existing cognition instruction/contract version, and retain no legacy adapter, version-suffixed alternate type or dual parser.

## 10. Later refinement: server-bound revisions and one work mode

**Deferred optional follow-up, fully designed; not a core SC release dependency.** SC01–SC11 retain the current revision fields and meaningful modes. SC12 may later remove derivable echoes after a separate decision to implement that optimization and qualification of the current sparse contract. The server already knows which exact revision it showed the character; asking the model to copy that number adds tokens and can create avoidable validation failures. Moving the value into native binding nevertheless changes trust/concurrency handling, so the following complete specification is retained rather than silently bundled into context selection. Every imperative in sections 10.1–10.3 applies only if that follow-up is selected; native mutation must still receive and check the exact expected revision.

### 10.1 Binding and model shape

Extend the existing prepared response binding with a read-only `revisionBindings` map keyed by the complete world/timeline/actor/record-kind/target identity. Each entry retains the expected revision, whether the target existed, required source/content coverage, and the owner's read dependencies. Use exact keys/typed records; an entity reference and a knowledge-document reference are different namespaces.

Remove `expectedRevision` from model-facing goal updates, plans, note edits and name edits. Remove model-only `noteRevision`, `nameRevision` and comparable fields from References when no remaining decision consumer needs them. Do not remove a meaningful current plan status, actual amount, time remaining or correction because it also has a revision. The server supplies native expected revisions from the retained binding immediately before each operation's existing mutation owner runs.

A full replacement of a nonempty knowledge note requires the exact current note text in that operation's prepared read set; a note's label/revision alone is insufficient to preserve information. A newly created/empty note instead requires a captured authoritative absence/empty state. The initial selector includes material relevant note text and keeps the note capability discoverable. An omitted nonempty document is not a prepared replacement target. Obtain its detail through a current supported route or a later properly prepared decision; do not invent an inspection API or silently replace unseen text. Independently permitted operations continue under their usual rules. The same principle applies to revising an unseen goal objective or naming an unresolved subject.

For absent targets, distinguish a captured known absence from a missing binding. Revision zero may represent the owner's current absent-record convention; it never means “ignore revision checks.” Creating a goal uses the native allocator and returns its actual ID in that component receipt; a model-provided `$localId` is only an accepted same-reply alias.

### 10.2 Same-reply write semantics

Maintain a small response-local table of the last **accepted** writer and resulting revision for each target. It is derived while the existing serialized response commit runs, not a persisted second state store. Apply these rules in operation order:

1. With no earlier accepted write to the target, compare its current owner revision with the captured binding. A mismatch refuses that component as stale; never reread the newest record and silently adopt it.
2. If an earlier accepted operation in this reply wrote that target, a later write may use the resulting revision only when `requiresAccepted` explicitly includes that last accepted writer's local ID. Otherwise the later write still expects the captured revision and is refused after the conflicting change.
3. A dependency on an older writer is insufficient if a later accepted write to the same target intervened. Require the current last writer, avoiding accidental overwrite of a sibling operation's accepted edit.
4. A failed/skipped writer changes neither the target nor the table. A dependent operation receives the existing dependency-rejected outcome; independent operations remain eligible.
5. Target creation through a valid earlier local alias uses the created ID/revision only with the required accepted dependency. No alias can refer to a future operation, another request, or a nonmatching receipt kind.
6. Read dependencies remain protected too. For example, a child goal depending on the displayed parent purpose must not silently bind a changed unrelated parent objective. Exact owner guards determine whether a changed record matters.

The native owner returns the affected target/revision information needed for this table as internal typed commit metadata. Do not infer mutation from text, increment revisions manually in a transport adapter, or assume every accepted operation writes the same record. Existing command/result facts, accounting and component receipts remain authoritative. A dependent write is based on an explicit prior proposed effect and its accepted receipt; no new model call is required.

Perform the model-to-native binding once at the existing admission boundary using the retained request. The native `ActorResponse`/command representation can include revision metadata the model never sees. This is a current trust-boundary projection with distinct responsibilities, not compatibility with the retired padded JSON shape. Update every current producer/parser/caller and the diagnostic schema label in that stage; no old schema remains accepted.

### 10.3 Transition mode appears once

For an installed request whose declared mode field is the same work transition as `act.mode`, derive that field from the single selected `act.mode` at native binding. Its installed definition explicitly identifies the shared role. Keep independent mode-like fields if their meanings differ. A known prepared choice's allowed transition remains part of the exact binding and must match the selected mode; no default overrides it.

This removes repeated form metadata without changing enqueue/replace/interrupt semantics. Qualification must show an exact replacement with lost work/resources, a legitimate temporary interruption with supported resumption, an independent social withdrawal that starts no physical work, and a mismatched unsupported transition refused before costs.

Use the configured/pinned adapter capability, not assumptions about a newer model sharing a product name. Exact local provider tokenization may be unavailable; retain the conservative byte gates, disclose estimate limits and compare with actual provider receipts rather than purchasing a counting request automatically. `maxOutputTokens` controls potential output; lowering it does not remove input context and can create truncated replies.

The token estimate is a diagnostic, not a proven token lower/upper bound or a new refusal policy. Do not reject otherwise admitted context solely because a byte-to-token heuristic exceeds an assumed window. Where an existing qualified exact counter applies to the configured representation, use its result under that owner's actual limit; otherwise preserve the established byte/provider gates and report the unknown tokenization component honestly. A partial estimate whose schema component is unavailable must not be labeled a complete total.

Count all separately admitted work for the decision: semantic retrieval/query embeddings, attention, any existing optional summary, threat relevance/appraisal and choice, generation, interpretation, configured reconsideration and NST's separately admitted passage screening when enabled. A smaller final GPT request can still be a more expensive pipeline if extra calls were added. A no-dispatch preparation refusal reports no generation spend but retains any already incurred preparation costs. Missing usage is not zero spending.

When the separately selected NST route is installed, measure the actual records schema and complete output document, including record wrappers, escaping and any escalation/invention envelope. Independently enforce its normalized logical-response limit; smaller payloads do not create extra utterance, record, output, tool-round or provider budgets. [NST-L02/L09](../limits/npc-speech-streaming.md) retain their exact units and accounting. Listener fan-out creates zero generating executions, but real screening is not assumed free. Its immutable request uses relevant already prepared permitted context, bounded candidate text and trusted policy inputs through NST06/PD07; it does not hydrate a second world/recall dump. Count every billed screening request/input/output and known/uncertain receipt under the original root allowance. Context reduction adds no screening supplier or extra call. The already selected screening owner may hold for new meaningful input under its existing bounds, never retry unchanged input or purchase a substitute answer. Retain its qualified progressive/completed-output-only/unavailable choice; completed-output-only uses the same generation and still requires screening.

### 11.2 Stable prefix without stale meaning

Place the trusted shared instructions and genuinely stable selected-world semantics before actor-specific and current-event material where the configured adapter permits that arrangement. Keep schema names stable for a contract shape rather than embedding a job ID. Canonicalize only fields whose ordering is semantically irrelevant; preserve chronological evidence, operation order, action-choice insertion/tie semantics and selected priorities.

Measure whether prefix reuse outweighs schema variation on the actual selected model/route; never retain stale facts, drop needed alternatives or expose another character's context to obtain a larger cache hit.

### 12.2 Current preview, selected public speech and independent operations

For the retained private-preview contract before NST's public cutover, `previewSpeechOperation` must positively parse the exact talk branch, not merely check that a remembered list of other fields is null. In particular, the current helper's manually enumerated exclusion list omits `appraise`; the sparse closed talk branch must reject any second payload, including a feeling proposal. Validate `requiresAccepted` is empty and perform current listener-specific disclosure checks before exposing words. Keep that current backend preview private, provisional and absent from memories/world events/other listeners. Do not restore the retired world-first preview row. Failure, cancellation or stale scope withdraws provisional text; final admission emits at most one actual utterance through the ordinary speech owner. Native event/request/component identity reconciles it, not matching text. A preview never starts a walk, writes a note, accepts a goal or changes a feeling. NST10 owns removal of the obsolete public-NPC attachment at the coordinated cutover; no parallel public preview remains.

NST's selected public contract is different: an exact closed speech record can supply an approved passage that becomes real speech only after its durable native commit, before the whole generated JSON is complete. Never apply a blanket “partial JSON has no effects” rule to that already admitted prefix, and never treat a partial string or unsaved candidate as speech. Later malformed syntax, incompatible envelope, policy/source failure or cancellation closes accepted words interrupted and rejects the unaccepted remainder. The normalizer reuses exact speech progress receipts and must not emit those words twice. Full typed response validation still precedes every generated non-speech response operation and successful complete closure; a later native action refusal preserves admitted speech and suppresses only its dependent effects under the ordered owner.

NST's [validity and terminal coordination](npc-speech-streaming-tech-design.md#validity-pause-and-terminal-coordination) owns the retained publication proof. Word-derived/model consumers wait for terminal readiness, including the speaker's self account. No private preview or screened passage grants action authority. ### 12.3 Save/load and reproducibility

Context units, selection graphs, rendered prompts, prepared reference maps and local cache entries are derived operational state. Do not serialize them into the authoritative world as a second mind. Persist only the existing accepted character/world/source state, durable request/accounting/receipt data and the minimum diagnostic manifest under their current owners. Follow the current data-format policy; no old-save reader or compatibility fixture is authorized.

Same-version save/load must retain accepted identity, goals/obligations, actual source-linked outcomes, method/output bindings, exact work progress and native random sequence. Rebuild derived selection/indexes against the restored world/source cut, without creation hooks, new rewards, new random draws or replayed paid calls. A restore changes timeline/authority generation, so an old in-flight result cannot publish even if its entity/source IDs recur. Current account grants and privacy overlays remain outside rewindable game state.

With NST installed, its current-format save/recovery owner also retains accepted speech and the frozen permitted accounts, closes a captured open prefix interrupted through its exact close-only proof, and establishes terminal readiness once. These are NST's existing selected recovery consequences, not work for the context selector or permission to replay speech. Rebuild context eligibility and any affected compacted source coverage from that recovered terminal state. Never persist unscreened candidates as character evidence, revive the original generator, remask stored hearing or let late provider settlement publish into the restored timeline.

The selector uses no world RNG. With identical permitted source snapshot, installed policy, source-specific relevance results and configuration, its selected units/order/aliases/schema are deterministic. Future live model replies are not promised to reproduce; use recorded accepted decisions for native replay. A cached derived summary retains exact source coverage and becomes unavailable after a relevant correction/forgetting/restore, rather than silently feeding abandoned-future experience into the restored character.

If some operations already committed before failure or a separately admitted later stage failed, preserve those real effects and their costs. Do not replay speech, consume an item twice, recreate a method output or roll back a private feeling merely because later action generation did not finish. Unknown external completion retains the existing financial/execution uncertainty; context optimization adds no retry authority.

## 13. Performance and preparation work

The four design answers are:

| Question                             | Answer                                                                                                                                                                                                                                                                                                         |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| What grows?                          | Admitted decisions per actor, nearby density, possessions, known methods/definitions, retained personal evidence, simultaneously required commitments/threat choices, and dependency fan-out. Multiplying actors × every world entity or definitions × every item × every target is the principal risk.        |
| What preparation is shared?          | Immutable installed definition meanings, actor-independent schema fragments, one actor/snapshot observation/access preparation, one memory read cache, exact source metadata, native tool prerequisites and physical checks shared by different purposes.                                                      |
| What invalidates reuse?              | Actual definition/source/privacy/recognition/body/work/geometry/custody/authority dependencies, meaningful clock boundaries and timeline restore. A generic global world revision is insufficiently selective, while an unchanged outer object is insufficient proof of nested immutability.                   |
| How is the whole operation measured? | Through actual decision/inspection/generation-preparation/publication callers, with metadata rows, bodies/bytes, candidate/reference/definition/physical-check counts, cold/warm timing, retained memory, request usage and later admitted behavior. A formatter microbenchmark does not qualify the pipeline. |

The pure closure visits each admitted unit/edge at most once per closure pass; optional ordering operates on the already bounded candidate set. For `V` admitted units, `E` dependency edges and `C` optional roots, graph construction/cycle condensation is `O(V + E)` and ordinary sorting is at most `O(V log V)`. Section 5.1's source-local fallback can scan `S` current source heads for each candidate, costing `O(C × S)` comparisons; those comparisons are charged rather than called free. Monotone component activation and removal update only affected support. Exact marginal-closure fit checks can nevertheless revisit a shared inactive subgraph for different rejected roots: their worst case without work admission is `O(C × (V + E))`, not a whole-pipeline linear guarantee. The new compiler meter below stops that repeated work before its admitted counter allowance is exceeded. Request-scoped metadata reuse may reduce repeated checks, but do not precompute an unbounded all-roots transitive-closure matrix. Source-size lower bounds can reject provably oversized construction before copies/string assembly; uncertain upper estimates follow section 6's bounded exact-measure rule. Do not use an input character ceiling as permission to build an arbitrarily large object first.

### 13.1 Explicit compiler work admission

**Current gap:** `recall.ts::candidateSet` checks `RETRIEVAL_ROWS` and note `RETRIEVAL_BYTES`; `memory-repository.ts` checks required/correction rows and serialized bodies before hydration. These are source-admission guards, not a graph-edge, repeated-fit or CPU meter. The final context/schema/transport gates also occur too late to contain arbitrary graph construction. Current native work accounting does not automatically cover this new server compiler.

**Selected mechanism:** `decision-context-selection.ts` owns a request-local `CompilerWorkMeter`, using the existing pure `workVector`, `addWork` and `requireWork` arithmetic and `WORK_LIMITS.group` ceilings exported by `packages/domain/src/work-budget.ts`. The selected limits and rationale remain in [SCX03](../limits/cognition.md#scx03--bound-discovery-and-hydration-before-final-rendering) and the existing work owner; do not duplicate or invent numerical constants here. This is a newly selected application of those existing ceilings. It creates no durable `admitWork` invocation, action/resource charge, saved work root or whole-world pause. Required compiler exhaustion affects the current decision preparation only.

The meter retains `used`, `heldFinish` and current admitted retained representation, under the same immutable preparation scope. Cumulative counters never reset for a new root, source page, fit attempt, asynchronous wait, optional fallback or same-preparation refresh. A separately admitted later preparation may have its own meter; starting another preparation is not an automatic retry or a way to continue the exhausted pass. Report the aggregate work through the existing decision diagnostics as well.

| Existing work unit        | Exact compiler charge and enforcing point                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `candidates`              | Charge before examining each source metadata row or optional-root candidate. Reexamining a row in another pass is another visit. Existing source-family row limits still apply independently.                                                                                                                                                                                                                                                                                                                                                                                   |
| `tests`                   | Charge before each graph-node processing step, adjacency entry visited, dependency membership/support test, fit check, digest invocation and comparison primitive. Digest comparison charges each compared byte pair; a digest collision additionally charges each inspected canonical UTF-8 identity byte pair, including long equal prefixes. Character inspection during encoding is also charged. Repeated visits in cycle detection, fitting, activation or removal are not free because the record was previously admitted.                                               |
| `inputBytes`              | Charge the actual normalized source/metadata/key bytes processed or copied by compiler stages. Charge repeated processing passes again. Check a page/body's declared bound before fetching or allocating its representation, then reconcile exact consumed bytes under the same meter. A source-size upper bound is not falsely reported as an exact input count.                                                                                                                                                                                                               |
| `outputBytes`             | Charge encoded fragment/request bytes before allocating or appending them. Discarding a speculative rendering does not refund the cumulative encoding work. The smaller context/schema/provider-body limits independently control what may be sent.                                                                                                                                                                                                                                                                                                                             |
| `retainedBytes`           | Admit the increment before retaining a node, adjacency list, interned key, scratch array, encoded fragment, fallback projection or final buffer. Use an incremental declared representation estimate under the existing native retained-work estimation convention; do not stringify the entire graph to estimate its next edge. Shared owned payloads count once; simultaneously retained base/working/scratch representations count at their actual overlap. Release occupancy when the owner drops the representation, without refunding cumulative visits or encoding work. |
| `depth` and durable units | Use iterative graph algorithms. Semantic dependency-chain length does not consume the native call-nesting `depth` allowance and does not acquire a new 32-edge limit. Any actual implementation nesting follows its existing implementation bound. The compiler allocates no `effects`, `claims`, `subscriptions`, `live` or `queued` native work.                                                                                                                                                                                                                              |

All increments and reservation arithmetic are finite safe integers; overflow is refusal, never counter wraparound. The implementation may use a checked hot-path increment to avoid allocating eleven-field vectors for every edge, but it must be equivalent to the pure owner arithmetic and its exact ceiling. Charge before the corresponding primitive/allocation, rather than recording an overrun afterward. Tests are deterministic operational units, not measured CPU nanoseconds.

Acquire dependencies lazily from exact permitted source metadata or a bounded source-owned iterator. Admit each page/node/edge increment before materialization. If an owner cannot return a bounded page or declare its dependency representation's size, improve that owner's narrow read contract; do not obtain an unbounded array first and apply the meter afterward. Existing SQL/source/native-query limits remain with their owners. This compiler meter does not pretend to count a database engine's internal scans or establish a CPU ceiling for an opaque library call; real query plans, encoding/schema compilation and complete-caller timing remain mandatory SC08 qualification.

Use a specified traversal order so exhaustion is reproducible. Optional admission follows section 5.1: a common supported rank with digest-based ties, or a stable merge of actual source-local orders when no common comparison exists. For that merge, scan the current qualifying source heads, choose the smallest existing-owner digest of complete canonical source identity, then advance only that source; canonical identity bytes break only digest collisions. Charge every head/digest/identity comparison and remove exhausted sources. This tie rule supplies reproducibility, not semantic cross-source relevance or a compulsory family turn. Use stable bottom-up mergesort with run widths 1, 2, 4 and so on wherever the compiler sorts a finite set; the left run wins an exact tie. Do not rely on an engine-dependent `Array.sort` comparison schedule. Required graph roots and dependency adjacency lists may use canonical-key order for bookkeeping, independent of optional relevance; charge their actual byte comparisons, and skip an interned common scope prefix only when equality is already established. Optional roots retain their actual admission order for support/removal accounting. Use iterative depth-first traversal with a retained next-edge index and iterative Tarjan component detection; process component activation/deactivation queues in deterministic admission order with sorted adjacency. Source-owned chronology, plan-step order and narrative roles remain unchanged in rendering.

Construct each optional tie key through the existing canonical-identity encoder and digest owner once per retained identity. Admit the canonical encoding and hash before their buffers or work are requested: charge encoded/hash input bytes under `inputBytes`, the digest invocation under `tests`, emitted canonical/digest bytes under `outputBytes`, and retained buffers under `retainedBytes`. Repeated encoding or hashing is charged again if not reused. Digest and collision comparisons charge each inspected byte pair as above. These deterministic operational counters do not claim to instrument a hash library's internal CPU instructions; complete-caller timing retains that responsibility. No new digest implementation, registry, scoring system or persisted tie-key store is introduced.

**Reserve completion before optional work.** Once the complete required graph fits, fully finalize and locally validate a current-format required-only fallback through the same reference/schema/encoding owners. Retain its ready-to-dispatch messages, tools/schema, reference/binding manifest and encoded provider body, with actual byte counts. It is the same current contract and source cut, not a second old-format reader or another memory store. Count its construction and simultaneous retained representation normally. This concrete retained request avoids a general symbolic resource-analysis or emission-planning framework.

The fallback's coverage is written for its explicit use condition: an optional extension could not be prepared or retained within the preparation allowance. It says that optional expansion is unavailable for this reply and that omission does not establish absence; required source queries keep their established complete/partial coverage and any usable continuation. Use this fallback only when that condition is true. The ordinary successfully finalized request retains its actual source-query outcomes instead. Record actual optional query attempts/results separately in bounded preparation diagnostics; never dispatch a prewritten `notRequested` claim about a query that was attempted. A new material finding must still be promoted to required evidence before either request can be used.

Before any optional expansion, reserve the fallback's finite remaining seal, represented as an ordered list of exact scope/permission/source-version/binding checks already identified during its preparation. Charge its explicit check-loop primitives and known key-byte comparisons under the counter table, including every possible comparison in that list; it requires no body hydration, schema compilation or request re-encoding. Existing native guard owners retain their own admitted work and may return stale/unavailable. An unbounded new guard is not covered by calling it one test: give that owner a bounded narrow check before enabling this path. A seal mismatch invalidates the fallback rather than entering another read/encoding pass. Failure to finalize the fallback or reserve its seal refuses before optional work or paid dispatch. There is no need to pay for attention first to learn that required finalization cannot run.

An optional increment must satisfy `used + heldFinish + nextDemand` against each cumulative ceiling, and the equivalent occupancy check for retained representation. It cannot spend the required hold. Build the extended selection with only unheld capacity, update encoded sizes/support incrementally, and attempt its finalization under that capacity. If optional acquisition, repeated fitting or finalization exhausts it, discard the incomplete optional extension and seal the still-current already finalized fallback using the hold. No additional context/schema rendering is needed. Report actual optional coverage; do not label exhaustion absence or claim that all investigated detail was included. Holding the base avoids consuming the last work credit and then discovering there is no capacity to render any informed answer.

If new information changes the required set, or a relevant source/authority guard invalidates the base, that base is no longer an acceptable fallback. Rebuild/replace the required projection and its hold only through the existing permitted refresh rule and remaining meter. Releasing an unused hold does not refund work already performed. If the new complete requirement cannot be prepared, defer the affected generation with `required-context-unavailable` and a compiler-work reason; preserve accepted native work and real receipts. A source change confined to optional support uses section 6.1's dependency-failure rule; no retained root may depend on invalid meaning. Before dispatch, exactly one finalized manifest, reference map, schema and byte sequence becomes the owned provider request.

**Qualification:** prove deterministic selected/fallback results and counter exhaustion on repeated shared-subgraph fits, long common key prefixes, dense/cyclic dependencies, a permitted dependency chain longer than 32 edges, and a late required-source change. Verify admission fails before the rejected allocation or edge visit; optional exhaustion can still finish valid required context; a stale fallback never dispatches; and no native work state or world-pause flag changes. Measure heap/RSS, latency, query work and the complete caller separately. Encoded/estimated retained-byte admission is not a measured heap ceiling, and finite counters or cooperative yielding do not promise a wall-clock latency bound.

Address these concrete current growth points in their existing owners:

- Select permitted reference IDs before hashing/formatting them; no whole-world entity map for one small request.
- Select required possessions and a permitted inventory page before expanding the whole inventory. Keep equipped items and exact tools/ammunition already bound to current/paused work.
- Reuse target-independent native capability/equipment/recovery checks before evaluating remaining tool/target combinations. Distinct purposes can reuse one physical check but retain distinct semantic identities.
- Select complete source keys/sizes before cold SQL hydration; batch related permitted reads in one compatible snapshot and verify the actual database plan. A `LIMIT` on returned rows is not proof that the database did bounded work.
- Compile immutable installed request descriptions/schema fragments once per exact definition pin, then bind only the actor-specific references/choices needed now. Do not recompile a full family for each item or actor if its immutable meaning is identical.
- Keep public supports and learned methods paged/selected through existing query owners; a broad catalog's public status is not a reason to serialize it for every greeting.
- Diagnostics use counters/reason enums and bounded selected manifests first. Full private text is loaded only for an authorized explicit inspection; context logging does not create a second full transcript store per poll.

Use request-scoped reuse by default. A longer-lived cache needs an existing owner, explicit dependencies, bounded retention and disposal on source correction, grant/control changes and restore. Do not store another actor's private prepared text under a shared world-only key. Dynamic schema compilation caches, if justified, key the exact immutable schema digest and dialect, not merely its schema name. Missing invalidation coverage requires rebuilding, not a speculative cache.

Qualification compares the small quiet scene, ordinary busy conversation, mixed speech/threat, many simultaneous local actors, large possession/method sets, cold retained memory and a large irrelevant world separately. Increase unrelated distant entities while holding the selected local scene fixed; the selected request/reference work should remain independent of that irrelevant population. Increase genuinely relevant local density separately to expose necessary growth. Include uneven cooperation graphs, changed containers/definitions, clock-only meaningful changes and restore, rather than reporting only a warm idle snapshot.

No arbitrary new per-character fact count, personality excerpt length, fixed context profile count, tool quota or generic target-token number is introduced. Existing workload ceilings remain in the limits inventory. Savings are measured against matched requests; absolute latency/population targets retain their existing project owners and unqualified status. A timeout/exhausted query remains incomplete evidence.

### 15.3 Fun, informed choice and complete cost

Compare matched currently supported decisions, keeping required identity, permitted source conditions, available operations and provider settings fixed. Existing benchmark examples known to yield correct constrained answers can inform representation and regression comparisons, with their published evidence scope retained. They are not the real-source selector's answer key, and their synthetic facts, archive sizes or hypothetical mechanics are not required production features. For an objective task, use its independently justified constraints; for an open character decision, several supported responses may be valid. The compiler cannot choose a preferred answer first and then retain only evidence favoring it.

Core qualification separately assesses required-source/dependency coverage; quantities, referents, timing, conditions and uncertainty; retention of the currently supported choice space and identity; rendering clarity; and complete preparation/provider/inspection cost. Record matched request sizes and actual latency/refusal/extra-call consequences where measured. A structural pass alone does not establish informed behavior, and a shorter initial request that creates avoidable repeated inspection or failures can regress the intended experience.

Fun matters here as a constraint against unnecessarily narrowing the existing character's choices, personality and useful possibilities. The repertoire scenes are optional ways to notice such a loss, not a required checklist of jokes, keepsakes, discoveries, detours or new emotional/relationship features. Reuse supported ordinary play evidence when it helps assess the changed decision. Broader whole-episode, later-return and human enjoyment qualification remains with the existing [compelling-character evaluation](compelling-characters-feature-spec.md#production-route-and-creative-comparisons) and its CE/CR/AG owners; completing all of it is not an SC delivery prerequisite. CTR's specifically named Ada counterattack acceptance remains with CTR and is not imported into this context-construction task.

A quality miss records the permitted source/meaning, its omission or misleading projection, the actual decision problem and whether correcting initial requirements, selection or wording resolves it. Prefer fixing the existing owner over expanding every prompt or adding another model. Preserve contrary examples, invalid output and unfinished/uncertain calls. Paid qualification requires existing account authorization and the task cap; no paid comparison is performed by this design-only work.
