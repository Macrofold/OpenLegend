## 1. Outcome

The next proposed follow-through is [Section 17](#17-proposed-receiving-preparation-and-command-admission): remove unnecessary receiving and retention work and the command dependencies it obstructs. [Section 16](#16-save-intent-and-shared-confirmation) retains installed repairs and completed experiment dispositions; neither establishes wider operating acceptance.

People should move, cooperate, pursue animals, build things and talk without the server repeatedly reorganizing their memories merely to save their next action. A witness can remember a meaningful sequence and later disagree with another witness because they received different evidence. An ordinary walk need not become a permanent diary. A remembered person, useful place or promise must survive without preserving every coordinate that preceded it.

The server runs the authoritative world in memory, sends permitted live updates to clients, and batches changed records directly into ordinary PostgreSQL transactions. Selected recent experience is append-oriented. Stable, sufficiently rich received values remain shared. Physical deletion happens in bounded background batches; access, expiry and correction take effect through their semantic owners immediately.

This replaces the custom durable change journal and its later application stage, hidden physical-page decisions on live objects, and separate accepted/applied/pending ownership catalogues. It does **not** remove PostgreSQL’s own transaction recovery, command receipts, protected accounting or coherent save/load.

The [contact/group redesign](attention-and-scenes-runtime-design.md#13-proposed-structural-replacement-contacts-and-grouped-receipts) supplies the native current-perception foundation. It removes redundant per-field records and persisted derived attention candidates. This project integrates that work and replaces its retained journal/shared-slot storage machinery; it does not create another perception model or task queue for those native changes.

## 2. Behavior to preserve

- **One server-owned reality.** Clients send intentions and render permitted state. Saving less frequently never transfers authority to the browser. Network updates do not wait for routine database flushes.
- **Actual reception.** Stored world position, personally observed position and remembered position remain different facts. Personal evidence never follows an unseen object by dereferencing its current entity.
- **Independent detail.** A fresh position does not refresh an older face, name, weapon or activity. Observation time, support, source revision, uncertainty and the receiver’s actual frame remain available where they change meaning.
- **Broad awareness and finite detail.** Detailed attention does not cap visibility. It automatically retains supported temporal changes while selected; it requires no watch/follow command. Required speech, own effects, knowledge and obligations keep their independent admission.
- **Useful memory.** Recent detail is reliable at the actual admitted sampling resolution while retained. A useful account may survive; trivial sequences may disappear. Expiry neither guarantees a summary nor purchases an AI call.
- **Current defaults.** Keep selected-world acquisition periods, Focus/attention allocation, familiarity/recognition, current-detail semantics, recent/lasting/speech allowances and ordinary action timings. The [base-world profile](../worlds/base/attention.md) remains their sole author. This project changes storage granularity and execution, not sensing fidelity to improve a benchmark.
- **Coherent effects and explicit durability.** Ordinary gameplay is accepted atomically in server memory and saved in ordered batches. A crash may lose its unsaved suffix for all participants together. Spending, access-control changes and explicit durable operations retain their protected boundaries; restoring a world never repeats paid work.
- **Private personal history.** Another observer’s reference to a shared payload does not make it remembered, understood or visible to this observer. Correction, forgetting and current privacy restrictions apply to cold data and restored checkpoints too.

The [attention feature](attention-and-scenes-feature-spec.md#94-receiving-attending-and-remembering-are-separate-decisions) owns the full gameplay contract; this project changes its physical storage and lifetime implementation only. Full vision/acoustics, attention/combat integration, PP07/SAI-A, aggregate crowds and new semantic cognition remain their existing unfinished scopes.

## 3. What saving promises

“A command” means an admitted request such as move to a point, pick up an item, speak or edit a record. A confirmation reports the result of that request; it is not the same event as every later movement update. A “save package” is a coherent captured set of state and dependencies, not an extra game mechanic. The custom journal’s package of changes is removed; manual checkpoint files remain useful.

Ordinary gameplay is accepted in memory and enters the ordered save stream. Protected operational effects retain durability; the complete admission, read and restart mechanics are in [live acceptance and ordered saving](bookkeeping-simplification-runtime-design.md#6-live-acceptance-and-ordered-saving).

| Activity                                                                  | Live behavior                                                                                     | Durability and failure                                                                                    |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Ordinary commands, accepted NPC gameplay results and native progress      | Validate and accept one complete authoritative transition, then publish without awaiting its save | Save effects, evidence and outcomes together in ordered batches; a crash can roll back the unsaved suffix |
| Real spending, external irreversible effects and access/control mutations | Use the existing protected owner                                                                  | Durability remains required before the protected effect or success acknowledgment                         |
| Thinking, optional search preparation and storage maintenance             | Bounded background work, with no native mutation turn held during I/O                             | Late output rechecks actual sources and permissions; it cannot recreate forgotten evidence                |
| Checkpoint, restore, authoring/installation and explicit durable export   | Establish the requested complete cut                                                              | Report success only after its required persistence; preserve previous usable state on failure             |

Target one-second save opportunities. Stop admitting further ordinary progress at five seconds since the oldest unsaved acceptance, or the pending byte ceiling, until storage catches up. Reserve 64 KiB inside the 64 MiB combined pending/in-flight ceiling for prompt emergency Pause. This bounds admission, not database outage duration or an indivisible operation's execution time. A failed write preserves the live pending suffix and stops new admission; restart restores the last complete saved cut. Clients never supply authoritative recovery or blindly replay old commands. Real-time storage pressure and ordinary memory consolidation remain distinct.

An ordinary action is authorized when it takes effect in the live world. Expiring the player's login afterward cannot undo that accepted action merely because it has not reached disk. Permission changes block subsequent affected actions and disclosures, and settle durably in order with already accepted effects.

A personal historical query applies its captured pending changes to the durable snapshot outside mutation. Thinking that needs saved evidence joins the next scheduled batch for a fixed captured cut; it does not force a separate early save. The wait consumes the existing urgent inference budget and may defer a request without extending its deadline or buying another call. Optional indexing may lag, while required facts remain available through exact readers. Player-only narration never becomes another actor's knowledge. [Persistence limits](../limits/persistence.md#bks-l08--ordinary-live-acceptance-target) own the operational envelope.

## 4. What is stored, and why

| Meaning                             | Stored form and lifetime                                                                                                                                           |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Current world truth                 | Latest ordinary entity/component state, with existing native continuation and saved randomness                                                                     |
| Current personal view               | Bounded current contacts/features, sparse per-field freshness/support and the existing limited motion baseline; no lifetime sightings list                         |
| Recent attended/required changes    | Sparse received baselines, changed samples, scoped coverage boundaries and occurrences; bounded immutable blocks append to SQL                                     |
| Shared received detail              | One immutable, viewer-compatible value for stable body detail, richer descriptions or geometry where sharing is useful; references identify values, not permission |
| Lasting knowledge or memory         | A selected account and its minimal exact support or explicitly less precise provenance; no automatic ownership of the entire source chunk                          |
| Search, display and scheduling aids | Derived from those owners, rebuilt or invalidated as needed; not another writable account of what happened                                                         |

Saved actor totals/deadlines choose maintenance; compact actor-scoped SQL reads supply retained headers outside simulation steps. No additional resident header catalogue is maintained. This reduces bookkeeping while leaving complete-game query cost as required qualification.

Small changing measurements, including position/heading, stay inline in their personal frame/current record. Stable or richer detail remains shared across compatible recipients and samples. This deliberately trades a little duplicated scalar data for fewer payload rows, references and deletion decisions. The native value owner applies one representation rule: non-body fragments up to 192 encoded bytes stay inline; stable bodies and larger fragments use shared IDs. It reuses encoding already needed for exact equality and charging, without a global deduplication scan or per-producer configuration.

The illustrative body samples discussed in this design were about 298–323 bytes of compact JSON; pose was about 75–78 bytes and stable detail about 221–249 bytes. They included rendering identity, dimensions, outward state and optional visible properties, not just coordinates. These are small source-inspection examples, not a capacity measurement. Richer mechanics can grow details, reinforcing the reason to keep stable-value sharing. Evaluate total benefit using value size, actual compatible recipients, update frequency and retention, including row/index/reference costs.

Perspective differences already matter: received clipping, clarity, precision and permitted fields select compatible values. Future detailed front/back body-part visibility belongs to the vision owner. Sharing never authorizes storing the hidden “complete body” in everyone’s personal context.

The AI receives selected permitted current information and recent changes, not raw database rows. Existing model projections omit artwork identifiers, icons and storage bookkeeping, and select usable labels, spatial/body detail and relevant descriptions. Storage compaction must not become prompt truncation or additional sensory acquisition.

## 5. Complete journeys

### BK-J01 — An ordinary shared walk

A player’s movement command is accepted once in memory and joins the next save batch. The server subsequently advances movement and observation in memory, publishes permitted changes to another connected player, and saves progress in ordered background batches. Updating current position coalesces between saves; admitted attended samples and discrete occurrences retain their order. The second player sees motion before the next routine database flush. A crash restores the last complete saved cut, including its associated personal evidence, without inventing the unsaved route.

### BK-J02 — A deer disappears

An observer receives a deer, later gives it detailed attention and receives several movements. History starts from the actual available baseline; earlier unrecorded travel cannot be retrieved from another witness or global truth. Current contact closes through one supported availability transition. Last received position and retained chronology remain dated. The loss does not create an autobiographical memory by itself. An unchecked held value is distinct from an ended live contact: ending removes the current targeting grant, while admitted history or independent knowledge preserves the dated last-seen value. A later deer is not identified from hidden entity identity. When detail expires, a separately retained useful impression or knowledge may remain; otherwise it is gone.

### BK-J03 — Daughter, pursuers and a cliff

Broad current evidence can include more people than the detailed slots. Familiarity can prioritize a legitimately recognized daughter without asserting affection or hostility. Independently received physical features keep the cliff available outside those slots. Existing bounded relational queries combine received movement and geometry; no all-pairs relationship log or hardcoded “daughter danger” story is stored. Native supported reactions continue before optional model interpretation. Personal frames preserve attended changes; the AI sees the selected current scene and recent change, not every coordinate in storage. Saving/cleanup does not add sensing or model work.

### BK-J04 — A route, work and a later recollection

An attended unknown person passes an anvil, enters a visible furnished room, works, eats and returns to speak. Exact received changes and occurrences retain their order without guessed episode boundaries or an inferred anvil destination. A kitchen category can be inferred from acquired furnishings/activity; a proper name remains separate knowledge. A selected useful recollection may survive as an impression. Necessary learned identity, name, place or promise copies only its exact support. Deleting the old recent chunk cannot delete that independent support; neither support nor the impression resurrects the entire route.

### BK-J05 — Shared detail, different witnesses

Several observers receive the same deer appearance. One shared immutable value can serve them. Their positions, times, received frames and permitted detail remain personal. Another observer with poorer or different reception gets a different variant or less information. Forgetting one person’s account removes only their eligibility and dependent personal material; a different witness may still own the shared value. Once no real owner needs it, ordinary background deletion removes the whole value.

### BK-J06 — Correction, cold history and restoration

A selected source is corrected or explicitly forgotten while recall is running. The semantic change invalidates its exact dependents before later publication. Cold SQL and temporary model copies cannot bypass it. Logical withdrawal does not wait for physical cleanup; a bounded maintenance pass later removes unnecessary rows/index entries. Same-format restore preserves the coherent fictional cut but applies current external privacy, access and spending protections. Refusing an incomplete checkpoint inspection changes no live object, physical layout, pending write or subsequent save.

## 6. Why this improves the game

The distinctive payoff is remembered consequence without omniscient recording: a companion recalls helping make a useful object, a rival recognizes a return without becoming friendly, and witnesses give honestly different accounts. Quiet discovery still allows a portrait or beautiful place to matter without a reward system. Fast ordinary movement gives those encounters room to happen; cleanup and save machinery should be invisible during healthy play.

These use existing actions, cognition and knowledge rather than new quest, relationship or scene frameworks. Qualify a small encounter and useful return before making a crowd-capacity claim. Native acceptance proves that permitted facts reach current/history/recall consumers and remain usable after saving or expiry. Existing scoped character-quality/player acceptance evaluates whether someone voluntarily makes a useful choice or finds the return worthwhile; a forced utterance or data fixture does not prove gratitude, interpretation or fun. Broader combat, ecology, society, magic and alternate-world repertoire entries retain their own owners; this foundation grants none of their unimplemented behavior.

## 7. Scope, alternatives and acceptance

Deliver one direct transactional persistence path, explicit append batches, useful shared values with simple ownership, independent minimal retained support, bounded asynchronous cleanup, pure capture/validation and all current producers/consumers. Remove superseded mechanisms in the same current-format conversion. No released-save migration, dual writer, fallback journal, region service, generic garbage collector, event-sourced engine or additional paid maintenance loop is included.

Copying every received body would simplify deletion but multiply richer stable values. Sharing every tiny scalar would save some payload bytes while multiplying rows and bookkeeping. The selected hybrid keeps each benefit where its lifetime justifies it. A custom journal might reduce a narrow acknowledgement cost, but this project prioritizes one durable truth and lower complete-path work. Faster hardware, more workers and reduced sensory cadence are not substitutes for completing these removals.

**Required pass:** BK-J01–BK-J06 through actual supported acquisition, public/NPC consumers and PostgreSQL continuation; coherent save failure/retry, exact correction/forgetting, no cleanup on an ordinary command path, and the existing standard/substantial normal-clock operating gates. **Required measurement:** full storage/index/heap cost, sustained cleanup, dense populations, mature-history distributions, faster clocks, ordinary acceptance latency and protected durable-operation latency under the [technical acceptance plan](bookkeeping-simplification-tech-design.md#10-acceptance-and-measurement) and the companion's selected durability contract. A failed required pass leaves implementation unready; a capacity exploration does not become an unsupported population promise.

## 9. Independent retention and database-work reduction target

Recent observation detail, lasting personal knowledge, required commitments, exact speech and world-event archives have separate purposes. Preserve the selected world's ordinary retention targets and exact age eligibility. Minimum evidence needed by a learned name, place, method or commitment is retained by that owner before the original recent chunk expires. Routine movement-history expiry must not search all personal accounts or erase an independently supported fact. Unknown individuals, later recognition, testimony and fallible impressions keep their distinct meanings.

Lack of references is not a gameplay reason to delete a historical event. Personal forgetting changes personal access; this project adds no automatic world-archive deletion or indefinite record-everything promise. Optional pools have bounded maintenance headroom; required support remains reserved and protected. Physical deletion, search preparation and optional quota enforcement are bounded background jobs. A saturated optional buffer may expose missing coverage but may not freeze physical time or fabricate detail; normal operating acceptance must demonstrate that this fallback is not routine.

The [runtime companion](bookkeeping-simplification-runtime-design.md) owns exact data/change contracts, every measured SQL category, caller conversion, gameplay cases and stage-by-stage removal checks. It extends the existing writer, reception, knowledge and memory owners. No separate store, journal or model-based expiry is added. [BK08–BK16](../maintainers/production-data.md#database-work-reduction) tracks delivery. Design completion does not close BK07/SR11/RU11 or full PP07/SAI-A.

## 12. Playable personal knowledge and sparse recent history

**Implementation reconciled November 5, 2026, 09:04 UTC; operating qualification remains open after the failed sustained run.** The [matched AWS investigation](../verification/performance/bookkeeping/2026/2026-11-05-runtime-ablation.md) separates historical regression from subsystem costs. [Technical alternatives](bookkeeping-simplification-tech-design.md#15-compact-native-evidence-and-change-history) compare preserving every historical check with recording useful changes. This section supersedes the earlier exact-check representation; the coordinated current-format conversion includes readers, independent support, correction and restoration.

The essential experience is that people notice their surroundings, recognize familiar people, react to danger, remember an attended sequence and retain useful names, places, promises and impressions. Their knowledge is personal and fallible. A detailed audit of every successful sensory check is not itself a player benefit. Current broad surroundings remain available outside the finite detail slots; fifteen pursuers cannot make an acquired cliff disappear from the daughter's situation.

The runtime retains current received values with independent freshness and records actual changes, occurrences, attention-entry baselines and gaps. A face can remain stale while a position becomes fresh. An attended person walking, working, eating and speaking supplies an ordered sequence without an invented destination or episode label. A lost deer remains last seen at its actual position/time, with a gap thereafter. Attention entry does not acquire the earlier route. Unknown people remain unknown; a room can be interpreted from acquired contents without requiring a sign or granting unseen knowledge.

Attention selection belongs to each observer separately. The observer receives a cheap broad view, chooses which subjects merit detail using permitted cues and held knowledge, then inspects that final selection once. If a newcomer replaces one of ten selected people, the departing subject keeps its earlier observations but receives no extra detailed inspection just because it was selected before the change. Newly acquired detail can influence the next selection opportunity. Other observers can choose differently, and bodies/terrain outside the ten detail places remain represented by the broad view. Native selection uses the existing world heuristics, without a model call to rank every candidate.

Removing unchanged-check history deliberately gives up a complete historical checklist and arbitrary reconstruction of exactly what was still confirmed at every past instant. Sparse history describes received samples and changes, never an inferred uninterrupted view. Ordinary expiry may discard whole old optional blocks, including some younger neighboring records. Useful learned support survives in its existing independent owner; it cannot be pinned to the expiring route.

A finite thought already supplied with permitted evidence may finish after ordinary recent-history expiry, within its existing request deadline. Explicit forgetting, correction, privacy revocation or timeline replacement still invalidate affected output. The character's proposed physical action always needs current authority and prerequisites. This changes the prior rule that ordinary optional expiry alone invalidates the captured thought; it adds neither a history-retention lease nor another model call.

The installed base-world tuning under qualification uses broad sight each second of normal play and detailed sight each half-second, while retaining the existing one-third-second contextual-geometry/relation period, world clock and ten default detail slots. This is a threefold increase over the preceding 20/10-game-second sight intervals and can delay noticing an approach, departure or developing danger. Ordinary detail is acquired for one final selection per opportunity; newly discovered detail can change selection at the next opportunity rather than trigger another inspection immediately. Dated held detail stays stale until actually checked. Direct events and physical effects retain their own handling. Sight-only slowing nearly matches slowing sight, geometry and relations together, so the latter additional delay has no demonstrated benefit. Earlier pre-conversion cadence trials remained below normal speed; the completed structural source now passes scheduled-boundary correctness, while matched AWS operating qualification remains required. Shared 120/60 remains diagnostic evidence, not the chosen timing. Clean scopes are not polled merely because an interval elapses; unfinished geometry or one recognition check must not silently trigger full sight.

Animals remain physically active: feeding, fleeing, wandering, flying and responding under their authored rules. The main reduction is in the observer work their movement causes. One changed animal does not justify remeasuring all unrelated attended subjects. Narrowing sensory work and controller eligibility are separate correctness/performance experiments; observers still receive required loss, final stopped positions and actual events. No offscreen sleeping, reduced population or new animal-mind framework is selected. The optional E2 eligibility witness was measured and removed; the original controller queue remains.

Snapshots preserve the same eligible personal knowledge and recent history as the captured live world. Wholly collectible history awaiting disk cleanup is omitted together with only its obsolete perspectives and unowned shared values; partly live records, useful support, events and other private accounts remain. Manual, automatic, recovery and operational saves share this rule. Failure identifies the specific record/package/count allowance, preserves the prior usable save and is never reported as success. Capture filters and ownership validation share one selection; deleting garbage is not a prerequisite to saving. Limits are not increased to hide redundant data.

World policy continues to choose sensing, attention, salience, fictional retention and meaningful learning. The engine supplies efficient reception, ownership, ordered changes, bounded execution and private consumption. No hardcoded daughter/cliff, anvil/kitchen or approach-episode handler is introduced. Connected native/PostgreSQL checks cover these semantics; AWS operating checks remain required before speed or capacity claims; [BK24](../maintainers/production-data.md#bk24--reception-cost-removal) and [BKS-L11](../limits/persistence.md#bks-l11--sparse-history-and-bounded-capture-proposal) retain scope and tradeoffs.

Ordinary command preparation may wait for remembered information or a previous command receipt while the world continues. The server checks current permission and current game conditions when the command actually takes effect. Revoked control cannot execute a prepared command, and a repeated request cannot execute twice. The [service admission contract](bookkeeping-simplification-runtime-design.md#53-sessions-controls-and-story-display) owns that correction. BK24 is the implementation task for this coordinated reception, recording, shared-reading and ordinary-admission replacement; connected command checks establish its admission behavior, while normal-speed acceptance remains separate.

The earlier connected checks pass within their recorded scope; BK25's atomic withdrawal and old-life retirement repair now also passes connected native and PostgreSQL cold checks. [The staged experiment and adoption gates](bookkeeping-simplification-tech-design.md#isolated-experiments-and-adoption-gates) explicitly separate proven work-removal targets from full-path benefit. World timing remains subject to its isolated adoption gate. No scale or enjoyment qualification is implied by source integration.

## 13. Proposed native execution and current-read reduction

**Selected source implementation complete; operating acceptance remains unmet. November 5, 2026, 21:15 UTC.** The [pre-BK25 AWS investigation](../verification/performance/bookkeeping/2026/2026-11-05-deep-runtime-ablation.md) measured **99.9624% normal clock on `bd7da905`, with no subsystem removals**. That baseline includes the installed BK24 fixes and predates this implementation. Its six-minute baseline still nearly consumes one CPU core, has 996.5 ms accepted-command p95 and skipped inputs, and fails subsequent full cold validation. This is neither responsive/restorable acceptance nor a demonstrated gain from the removal experiments.

The goal is prompt play with active wildlife and independent witnesses. Reviewing whether an animal should keep feeding should not rebuild unrelated characters' physical calculations.
