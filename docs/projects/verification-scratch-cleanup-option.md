# Deferred option for local verification cleanup

If [ordinary producer cleanup](verification-workers-tech-design.md#local-scratch-cleanup) proves insufficient, this design covers a possible `pnpm verify:scratch RUN_ID` for one local or managed run. Only the local producer can opt in a disposable output, at exclusive creation under the verified private scratch root. A name collision leaves the existing file untouched. A downloaded manifest can identify bytes but cannot grant deletion authority on the receiving machine. At close, record the exact relative path and finished identity and version in private run state outside scratch. Keep results and shared inputs separate. Prefer bulky outputs with existing build or transfer records. Never enroll files by scanning, matching names or importing old folders. Unregistered files stay for owner review.

Preview needs read authority. Privately show escaped relative paths, file sizes, estimated reclaimable space where known and skip reasons. Derive its ID from the eligible selection, sealed inventory, run ID and revisions of that run’s local ownership and retention decisions. Preview leaves no files or holds. For a new `--apply PREVIEW_ID`, recompute under the exclusive claim and verify deletion authority. A mismatch requires a fresh preview. Require a closed run, recorded result, finished readers and writers, no hold and any required collection receipt. Planned consumers must have finished or have independently verified retained inputs.

Work from the original root and directories. Refuse ambiguous paths, links, mount crossings and paths outside the root. Unlink only the registered regular file with matching identity and contents. An advisory lock alone cannot exclude an unrelated writer. Where the platform and producer cannot prevent a file or path changing between check and removal, offer preview only. Use empty-directory removal for registered directories. An interrupted run first goes through recovery.

Atomically persist the pending selection in local run state before deletion. An unreadable record stops recovery. Retry only its remaining eligible entries under the original authority. A handoff or changed retention decision requires a fresh preview for the remainder. Verify the original run root outside scratch. An unavailable or replaced root leaves cleanup unresolved. An already absent entry on verified storage earns no reclaimed-byte claim. Report unfinished writes, leftovers and partial failures privately. Once complete keep the outcome and preview ID. Reapplying it does nothing. A local cleanup retry neither reruns a case nor changes collection, worker-release or spending receipts.

The collector uses the same operations without another download. Before enabling automatic apply, compare it with the producer’s existing or manual cleanup on equivalent disposable runs. Exercise unauthorized inspection, foreign or handed-off runs, delayed reports and changing holds. On each intended filesystem, check unexpected or replaced files, redirected parents, independent writers and interruption between deletion and receipt. Verify removals, retained results, shared controls and untouched active runs. Include registration and verification overhead, closeout time, and peak and settled disk on an otherwise idle volume. Shared storage can free fewer bytes than file sizes suggest. Keep diagnostics outside gameplay timing and avoid archive-wide scans. Enable automatic apply only where it passes these checks and reduces leftover disk use or operator work enough to justify its cost.
