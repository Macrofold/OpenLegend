## 2. What the measurements establish

Canonical evidence: [current 20-added-animal diagnosis](../../verification/performance/2026-10/animal-reductions.md#current-20-added-animal-diagnosis--october-23-1914-edt). Twenty added frightened deer join an opening containing twenty animals: **40 total**, not twenty. Normal Main speed requests 60 game seconds per real second; that is a clock conversion, not a requirement for 60 simulation updates. Thus 23.77 game seconds would take about 0.396 real seconds if the server kept up.

The unsampled 30.0414-second run advanced 866.3708 game seconds, **48.1% of requested normal speed**. CPU sampling changed the workload overhead: its 30.0446-second run advanced 750 game seconds, 41.6%. A counters-only repeat advanced 900 game seconds in 30.0311 seconds, 49.9%. Do not combine these as one sample or use the sampled run as the uninstrumented baseline. All added animals survived and completed their escape behavior in these runs; slowness is not evidence that route selection never finished.

## 3. A representative update, before and after

The current server collects owed game time, obtains the one world writer and starts an editable result. The native loop resolves due work, prepares bodily rates and movement limits, chooses a safe elapsed interval, advances positions and meters, commits action/projectile/environmental effects, updates observations and ongoing relationships, then finishes an immutable result. The server shares compatible internal intervals within its approximately 32 ms coherent-return intent, returning sooner for waiting operations. Commands waiting for the writer and cooperative I/O opportunities are separate from that target.

For each deer today, relevant work can include checking current movement/perception restrictions, active body effects, current action, route/review deadlines, personally perceived danger, foraging and wandering. Movement uses support/obstacle checks and, for callers that require it, occupied-body sweeps. Noticing obtains nearby candidates through existing spatial indexes, rejects impossible range/cone cases, performs uncertain geometry queries and records only what that deer can perceive. Native animals do not acquire every human memory subsystem merely because they share the world. Sleeping or stationary animals still have needs, damage and wake conditions.

The current complete update is:

1. **Acquire the existing writer.** Apply queued commands only at a complete boundary. Rebuild disposable prepared data on a cold world; warm updates consume exact changes since the retained revision.
2. **Resolve due start-state work.** Select due or invalidated participants from existing relation/actor indexes. Finish expired effects, navigation acceptance and current action stages in the existing deterministic ordering. A new action earns no elapsed time from before it started.
3. **Refresh only affected facts.** For those participants, update current capabilities, relevant bodily predicates/rates, movement preparation and absolute next deadlines. A geometry edit invalidates affected spatial proofs, not every character's food-rate calculation. Unsupported coupling still uses the existing conservative calculation.
4. **Choose the next interval.** Take the minimum of already prepared numerical deadlines, requested time, motion/sampling bounds and global physical events. Initially scan a compact deadline table; a heap is not required. A sampling boundary says when to inspect movement/awareness, not that every bodily rule changed.
5. **Advance actual participants.** Move only actors with movement that can currently progress. Use prepared scalars and local route cursors, then commit the resulting pose/path/accounting through the existing mutation owners. Integrate each supported meter to this time using its retained rate; process shared supplies and discrete damage under their exact existing owners.
6. **Apply endpoint consequences.** Resolve arrivals, releases, hits, depletion, status transitions, rain/material changes and completed work in the current phase order. Refresh newly invalidated eligibility before another movement/action phase. Released arrows keep flying after their shooter stops cooperating or dies where the existing contract permits.
7. **Update observations that are due or event-required.** Physical attack/sound/action-time evidence uses current checks. Routine sight follows the selected cadence policy. Apply each observer's evidence in canonical order, then wake relevant native choices and voluntary character reconsideration. A worker's ray answer supplies geometry, never identity or permission.
8. **Choose bounded native continuation.** An animal with a new danger or due review uses its own current evidence, reusing the same assessment if nothing relevant changed. A pending entity-local route request stops that animal while unrelated world time continues. Process random choices in the same canonical order, never worker-completion order.
9. **Continue the owned edit if useful.** Yield to I/O using the existing host budget. If no command/read requires a boundary and the batch budget remains, handle the next compatible internal interval without freezing/reopening the world. Otherwise publish a complete immutable result and exact changed-record information.
10. **Project and save through existing owners.** Reuse unchanged permitted view sections; coalesce replaceable motion at the existing delivery boundary. Save stable captured data through the existing background/command policies. Acknowledged commands retain their required durability.

This removes repeated preparation; it does not eliminate useful known-time arithmetic. Predicting the exact future appearance of ordinary sight remains removed. Computing an arrival from distance/speed or a hunger threshold from current value/rate is a different, cheap scheduling operation.

### 4.1 Retained preparation and invalidation

Retain one disposable preparation per exact world continuation. It has participant records keyed by exact entity ID and physical life where applicable, current definition references, local revisions, prepared capability restrictions, rule groups/rates and owned absolute deadlines. Cold membership comes from the existing active/root, status-bearing and environmental rosters, including non-actor entities with bodily effects; do not hydrate or enumerate retired historical entities. Global records cover geometry/weather/shared-supply/definition work. Use nested maps or existing typed identities, never ambiguous delimiter strings. Indexes are derived, not saved authority.

A deadline records its kind, owner, absolute game time and the dependency generation that made it valid. Selected kinds are the actual existing families: action/work stage, path/support arrival, animal review, bodily threshold, periodic effect, contribution expiry, global environment and routine sampling. The kernel dispatches to existing owners; no arbitrary callback queue. Derive owner-local dependencies from compiled rules and existing semantic changes. Maintain reverse references only for actually admitted cross-entity dependencies.

At time 100, A's arrival can be 112, B's 118 and B's hunger threshold 180. At 112, apply A's arrival, refresh its consequences and any actual affected neighbors, then retain B's unchanged 118/180 deadlines. Never subtract the elapsed slice from every stored time. A deadline that was predicted from a changed rate is replaced from the **current** meter, not rescaled from a stale remaining duration.

On equal timestamps, preserve the existing phase order and canonical entity/insertion ordering within a phase. Collect the due set before processing; consequences can invalidate/re-enqueue work for the same timestamp under the existing bounded zero-time handling. Do not create an unbounded fixed-point solver. No RNG for selection, ordering or cache rebuilding.

| Changed input                                   | Work invalidated                                                                                                 | Work retained                                          |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| Pose/support/heading                            | That body's movement facts, relevant spatial memberships, incident sensory pairs and relevant danger assessments | Unrelated bodily rules and unrelated relations         |
| Attribute write/threshold/rate                  | Referencing predicates/rates, capability transitions caused by those effects, dependent deadline                 | Other subjects unless declared linked                  |
| Action start/end/phase                          | Subject action predicates, movement selection, work deadlines, incident cooperation                              | Unrelated offers/status groups                         |
| Effect/contribution creation, expiry or removal | Affected subject/target capability and condition groups, current rate anchor                                     | Unrelated capabilities and subjects                    |
| Geometry/support/gate change                    | Intersecting movement/sight preparation, affected route admissions                                               | Unrelated food/energy rates                            |
| Personally perceived attack/sound               | Listener/target danger or recognition/decision work                                                              | Other observers' private evidence                      |
| Definitions/global laws                         | Actual dependent groups; broad rebuild for unclassified/shared dependencies                                      | Only groups whose independence is proved               |
| Load, restore, new world, unknown lineage       | Cold rebuild of derived preparation                                                                              | Saved authoritative values, deadlines and consequences |

Use a broad fallback when dependency coverage is unknown. Record the fallback reason so an unclassified common rule does not silently turn every update back into a global scan. Fallback scope must be the affected coupled component when known; global only when required. Subject-local signature checks consume the existing per-owner semantic-change cursor: a different body moving or time passing before the owned deadline does not reconstruct unchanged rule inputs. Subject writes invalidate that subject; unknown/global writes retain the full audit. Add no validation on every trusted scalar read merely to prove the same input again. Retained bodily deadlines compare their local rates with the complete current forecast for that subject. An incoming effect or native drain/replenishment that changes those rates uses the existing full condition-boundary calculation; checking only which body a predicate reads cannot prove its future rate is independent.

### 4.2 Current read views and cheaper physical writes

Pure loops receive a compact current physical frame: identity/life, position/support/heading, body profile reference, speed, capability bits, action/path identity and required sense facts. It extends current spatial/exposure preparation. Refresh changed entries; do not rebuild an array of all entities each interval. Prefer ordinary stable records initially. If profiling demonstrates iteration cost after proxy removal, parallel arrays may replace that representation behind the same reader. Stable ID-to-slot and slot generation prevent stale worker answers; free slots reuse no gameplay identity and iteration retains canonical order.

`readOnlyDraftView` is a shallow current view, not a guarantee that all nested values are plain. Extract needed nested scalars once. Do not use `original()` to read a value changed earlier in this edit, deep-clone a world, or let a mutable proxy escape into a worker/cache. Deferred meters use `currentAttributeState`, never raw stored anchors.

The selected A04 scope is **component-level owned writes**, not a new world/ECS:

1. At the existing movement owner, capture the current supported pose, path cursor and relevant pursuit/forage accounting into local plain values. Pure segment checks advance these local values. Keep intermediate observed motion segments when an existing consumer requires them.
2. Stop at every consequential support/contact/action boundary already required by the integrator. Do not collapse a meaningful intermediate crossing or retargeting opportunity just because the final position is the same.
3. Commit the completed movement step through a shared spatial writer. Create fresh changed `placement`/spatial fields and changed path/accounting branches once, rather than writing through nested proxies for each waypoint. Reuse immutable body definitions, route tails and unchanged branches. Do not copy the complete actor or its memories.
4. Record old/new pose, support/heading, exact changed component and current action/life dependency through existing mutation notifications. Preserve placement revision semantics and source-motion evidence. Consumers must reread changed branches after the commit; no retained mutable action/path reference may stand in for the new branch.
5. The outer domain draft still owns the transition, event records, complex actions, permissions and ordinary edits. Assignment of complete changed branches establishes the existing entity change lineage; explicit semantic notifications carry subsequent in-batch invalidation. Newly constructed mutable branches belong exclusively to that draft until publication. They cannot alias a published world or a read snapshot. No ordinary caller may mutate them outside their semantic owner.
6. At finish, seal/freeze changed branches using the existing publication owner and retain unchanged immutable references. Audit save/projection/exposure consumers against explicit change data before removing any patch-derived audit. Keep patch tracking for still-general edits; do not delete it globally because movement uses fewer leaf patches.

The shared writer replaces the final placement and updates heading through the existing attached physical component. Flight and fall controllers can hold mutable child progress, so replacing that parent would strand a live controller. This reduces proxy reads, leaf assignments, transient path edits and patch volume without inventing a second authoritative pose store. It deliberately does not promise to remove all Immer use. If the retained profile still attributes a dominant cost to top-level entity proxy writes, the next extension is the **same component owner** with explicit publication tracking, not an unrelated mutable world; that escalation requires a measured finding and a complete consumer audit before implementation.

### 4.3 Capabilities and bodily dependencies

Compile the existing condition tree into dependency facts alongside its existing evaluator: subject attributes, action facts, time windows, effect/contribution state, source/target bindings and definition references. Unknown operators mark the group conservative. There is no second condition interpreter. Cache rule applicability only while those dependencies and its next relevant time boundary match.

Current capability answers include timed contribution expiry, participation/life and foreign contribution sources. Share the existing immutable capability-mask/display preparation; read cheap current body/action facts directly in movement and observation consumers. Do not maintain duplicate moving/locomotion/perception sets: following can change from holding to walking inside an advance without an unrelated meter write. Bodily integration retains its existing status-participant roster, and action admission/progress retain their capability guards and participant owners. Incapacitation prevents voluntary movement, but routine observation still follows the installed perception restriction, matching current sight and deadline scheduling. A locomotion restriction is not proof that needs, damage or senses can be skipped. Definition changes and contribution-source deletion invalidate their actual dependents before another action step.

Linear meters use one anchor `{value, at, rate, min, max, nextBoundary}` through `native-values.ts`, selected only when supported operations form an independent continuous law. Before rate changes or explicit writes, settle to the exact current game time. New rates start there. Cross-person transfers, drain/replenishment competition, periodic/discrete damage, unsupported ordered clamps and shared work retain existing eager/conservative execution. The generic engine does not classify by names such as food or sleep.

For eligible linear rates, equality means the same meaningful values, threshold times and effects within existing numerical/spatial tolerances, not identical counts of tiny floating-point additions. Event/identity/RNG ordering, conservation and discrete outcomes remain strict. A meter's revision becomes a meaningful invalidation generation, not one increment per former arithmetic subdivision; audit readers that currently compare revisions and include current time/anchor identity in current-value cache keys. Stable saved anchors and their validated rules reproduce the same current value after loading. Do not add a global arbitrary epsilon or loosen combat/permission comparisons.

### 4.4 Publication, workers and persistence

The world writer remains exclusive. Server wall-clock yielding stays outside deterministic domain code. Remove the unconditional one-interval service cap in favor of repeated coherent intervals within the existing roughly 32 ms batch target, with existing roughly 8 ms I/O yields and earlier return for waiting commands/reads. A long individual operation is still a measurable latency risk; the target is not a hard deadline.

On yielding a **preparation** opportunity, do not expose a partially mutated world. On yielding a **complete** boundary, the service may finish/freeze the current result and service queued operations. Async saving holds only an immutable captured result; later edits must not mutate anything reachable from it. Coalesce replaceable positions at the existing ~50 ms public boundary, but never collapse speech, attack outcomes, permission revocations, receipts or distinct personal evidence.

Workers receive compact physical query inputs and geometry identity only. Main-thread preparation includes world/timeline, geometry and query generation, entity life/pose/body/action dependencies where relevant. Domain admission rechecks those dependencies, applies answers in canonical request order and uses exact local calculation for stale/failed/small work. Do not send private histories, expose hidden locations to an animal, or let arrival order choose saved RNG draws.

Background saving remains about once per real second under its existing backpressure/crash-loss policy; synchronous commands retain existing atomic/durable acknowledgement. Use exact changed-record identity to reuse encoding, not JSON string equality or a whole-world rescan. A skipped optional projection cannot skip an authority/privacy change. Reuse the existing private-read guard immediately before disclosure after every asynchronous wait: invalidating a cache cannot stop an already running read from returning revoked text. Public projection keeps its required current visibility checks; delayed routine awareness never grants live hidden coordinates. No database migration is implied by disposable preparation; any saved anchor/cadence representation changes require current validators and schema callers together, without old-format readers.

### Concrete data contracts for implementation

The following shapes describe the selected responsibilities; use existing branded IDs and definition references rather than inventing aliases. These outlines describe the logical contracts. Exported current representations include `NativeStatusPreparation`, `NativeValueWindow`/`NativeValueBinding`, `SensoryProgress` and `GeometryBatch`; no parallel saved representation is installed:

```ts
type NativeDeadline = {
  at: number; // absolute game seconds
  owner:
    | { kind: 'participant'; entityId: string; life?: number }
    | { kind: 'system'; family: ExistingNativeSystemFamily };
  cause:
    | 'action'
    | 'arrival'
    | 'review'
    | 'attribute'
    | 'effect'
    | 'contribution'
    | 'environment'
    | 'sample';
  generation: number;
};
type PreparedParticipant = {
  entityId: string;
  life?: number;
  physical: PreparedPhysicalFacts; // plain current scalars, not a draft Entity
  capabilities: PreparedCapabilities;
  rules: PreparedRuleGroups; // existing compiled evaluator and dependencies
  deadlines: readonly NativeDeadline[];
};
```

Keep these types private to native preparation, not in the public wire protocol or saved schema. `family` resolves only an existing trusted system owner, not arbitrary generated callbacks. Store only finite valid deadlines; absence means no known due event, rather than a serialized infinity. One participant may have several deadlines; do not retain only the earliest and lose a later unchanged threshold. A generation belongs to the exact affected preparation, not a world-wide counter that invalidates everyone after any write. Dirty IDs are deduplicated; a semantic change can invalidate several named groups without replacing the whole participant.

At the start of a native interval, materialize any **required** previously earned dependent value, resolve due start transitions, refresh changed groups, then select the minimum valid future time. At the endpoint, integrate using the rates captured at the start, apply consequences, and then reconsider conditions. Never use an endpoint's newly activated rate for the interval that just elapsed. Discard only the fired/invalidated deadlines and regenerate them from current authority. Equal-time events are dispatched by the kernel's existing phase order, not by arbitrary deadline insertion order.

For A15, extend the current per-attribute native arithmetic representation with a discriminant for `linear` versus the existing `ordered` execution family. The existing stored `AttributeState.value` remains the **one anchor value**. The linear binding holds its start time, net rate, limits and exact contributing rule/episode references; it must not store a separately writable copy of that value. There is one linear binding per entity/attribute even when several supported effects contribute to the rate. Episode elapsed/work accounting stays at the existing shared episode owner and is charged once, not once per attribute. Settling a contributor before removal/rate change preserves its earned portion and then recomputes the group's net rate. Explicit writes settle and update the canonical anchor through the same current-value API. Remove migrated ordered segments from that attribute, not from unsupported siblings. Current-format validators reject missing/ambiguous modes; no reader interprets an old development representation as current data.

For A16, extend the vision branch of `SenseDefinition` in `perception.ts` with required `routineTiming: 'boundary' | 'cadence'`. `world-modules.ts` validates it; cadence mode requires a positive `sampleSeconds`. Update current authored definitions, installation/projection consumers and fixtures together, with no legacy fallback. Boundary mode is the existing supported boundary-triggered comparison; Main's cadence candidate reads its period from `worlds/base/senses.ts`. If several installed vision senses contribute, preserve `resolveSenses`'s existing combined query and resolved cadence semantics; a definition dependency covers the complete participating set, not just the first sense.

Add optional **per-entity saved sensory progress**, conceptually `sensoryProgress.routineSight = { nextAt, senseDefinitions }`, to the current entity schema and save/restore validators. Bind the complete exact installed sense-definition references. Do **not** store the cadence only in `world.nativeInterval`: that record is invalidated by ordinary semantic mutations and would restart the observation clock. Progress is authoritative timing, not cached visibility or private knowledge. It is created for supported sampled vision, removed when the observer/sense is removed, and refreshed on actual sense-definition/policy change. On enabling sight after a restriction or acquiring a new sense, perform the ordinary current initial check and schedule from that instant. Other entities' changes cannot reset it. At a due sample, advance to the next cadence point without replaying nonexistent intermediate observations. A paused world earns no game time; loading retains the saved due time. Once established, each sampled channel keeps its due boundary even while bodies are stationary; an overdue clock triggers the next current check instead of skipping another period. Scheduling and recording share the same relevant-observer predicate. Quiet native animals retire any previous clock when their observation consumer ends; an unconsumed deadline must not force repeated tiny steps.

A18 extends the contact definition with `awarenessTiming: 'crossing' | 'sampled'` and a positive `sampleSeconds` for sampled mode. It uses `sensoryProgress.incidentalContact` under the **same** timing owner, independently of vision: a blind observer must still notice supported touch. Reuse a shared authored period in Main's candidate, not an engine constant. When vision/contact deadlines coincide, prepare one physical frame and apply both due channels; a vision restriction must not delete contact progress unless the installed restriction also blocks contact. Exact physical contact and explicit watch/reach work never use this optional routine clock. Main installs no contact sense, so no ordinary-Main speed gain is available from this switch. The supported contact-only sampling path shares the timing owner and remains a small current feature; it is not a compatibility option. Apply the packet's measured complexity/removal rule to additional trial machinery.

`types.ts`, the entity validator and existing record encoding/load owners must change together for these two saved representations. Derived participant frames, deadline indexes, capability preparation and worker query results remain unsaved. Slot numbers never enter saved references. No new protocol/version compatibility layer is needed.

## 6. Conversation decisions retained

- **Escape remains deliberately simple.** Use personally known threats, choose away from their combined directions; opposing threats should favor a perpendicular opening rather than a numerically unstable tiny sum. Choose a deterministic saved-random tie direction only when no useful preferred direction remains. Use the installed 10–15 m desired distance and existing finite angle sequence. Accept a feasible route reaching at least 75%; below that try at least three angles, accepting the best at least 50%; otherwise try up to ten and take the best physically feasible result. No indefinite random-coordinate search or exhaustive optimum. Navigation can detour around an obstacle; supported prefixes and alternative angles handle a blocked direction. This design preserves the already delivered controller and its authored tuning, rather than reimplementing it.
- **No invisible-danger oracle.** Remembered danger may retain an old personally observed point with the installed uncertainty. A creature can move behind a wall and discover another threat later. Geometry/route clearance is shared engine work; hidden people are not injected as avoidance goals.
- **Navigation waiting is per request.** Animal escape requests stop the animal while the world continues. Existing callers retain their world-blocking behavior where requested. A route proves physical feasibility, not current permission/capability to move; execute through ordinary admission.
- **Preparation alone does not frighten prey.** Bow drawing/attack preparation is not an animal danger signal. Personally perceived executed attacks, projectiles and physical impacts can establish danger through the current evidence owners. Bow range and observed-motion leading were separately authorized; retain the current authored envelope and fixed released trajectory. Do not tune speeds/range/alarm rules to pass performance tests.
- **Routine sight and prediction differ.** Current sight decides what a character can notice now. Future sight prediction searched for an exact later visibility transition; that ordinary prediction is gone. Optional prediction for an AI's deliberate tactical choice is a separate future capability, not continuous perception work.
- **Nearby filtering already exists.** Query spatial cells/regions, then range/cone and obstruction checks. Distant-entry bounds use conservative possible relative motion and invalidate on speed, pose, transport, geometry or sense changes. They do not calculate every pair in the world continuously. Co-located open pairs can reuse geometry proofs too, but a doorway, turn or changed wall can invalidate visibility. Close distance alone is not proof of perpetual sight.
- **People currently do not form ordinary opaque crowd walls.** Sight uses installed opaque geometry. Body overlap/occupied movement checks serve a different purpose. Do not add crowd occlusion as an optimization; it would change what people can see and add work.
- **Scaling is not guaranteed linear.** Sparse spatial grids reduce candidates toward local population. When everybody fits within everybody's range, genuine directed observer–target work approaches O(N²). Exact future crossing searches added work per pair; simpler current checks reduce that multiplier, not the dense pair count. Maintain changed pairs, not merely a dirty observer followed by a rescan of its entire surroundings. Action-time-only sight cannot replace awareness needed for autonomous danger responses and personally witnessed speech/events.
- **Engine comparisons provide techniques, not parity claims.** Budgeted senses, compact batches, active-only work and variable-frequency simulation are useful. Thousands of visually animated agents with simplified targeting are not equivalent to OpenLegend's private evidence, bodily rules, committed actions and durable history. Preserve only the strict mechanics that support play; do not simulate needless numerical subdivisions.
- **Measurements stay understandable.** Report normal-speed game time versus real time, added and total animals, command delays and animals completing escape. Do not mix 8×/1× periods as comparable phases or present internal alarm clearing as the player's task. Twenty added animals keeping up is the immediate goal; 500 is exploratory, not a mandatory target. No unchanged Ada/temperament trials or endless benchmark tuning.

## 8. Delivery, verification and residual uncertainty

The detailed sequence, acceptance scenarios and measurement boundary are in [implementation packets](animal-execution-tasks.md#delivery-order-and-verification). Estimate **3,000–6,000 changed runtime logic lines** across all selected core and conditional experiments, excluding tests and deletions; the documentation task changes zero runtime lines. This is a high-risk cross-layer change because stale dependencies, mutable snapshots and delayed evidence can alter gameplay. It is not a promise that 21 independent optimizations yield additive speedups.

The largest uncertainties are measurable: how much broad preparation remains after local due handling; whether component writes remove enough proxy work; how much anchored meters help after read reuse; whether larger batches improve total command latency; and whether any movement geometry batch is large enough to benefit from workers. Each packet gives a concrete implementation and failure response. Do not reopen the entire design after a local finding. Fix the violated owner/consumer, use the defined conservative path where necessary, and keep the specific gap open until resolved.

Design completion means all 21 items have an explicit disposition, owner, algorithm, dependency and verification. Runtime completion requires the implemented caller and retained evidence, not this chapter or a checked design box. Final performance acceptance requires actual complete-server measurements; the existing broader smooth-3×, long-play and human gates are not waived or declared passed by this work.
