## Ownership and the unit of delivery

Work from one real entry point to a visible or durable outcome. Examples include selecting a tool from the browser, an NPC choosing the same action, the simulation waking a sleeping resident and a creator applying an edit. Start with the [current source inventory](../maintainers/native-simulation-core-coverage.md#full-server-conversion-inventory). Its existing field, command, finalization and SQL sections remain part of this design.

| Owner                                        | Inputs, outputs and lifetime                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Installed world                              | One authored definition or trusted world-specific implementation per law, including action families, cognition settings, animal behavior and display wording. Build a single reviewed artifact where multiple consumers need the same data. The host resolves its exact installation. A world may omit language, sleep or a recipe entirely.                                                                                  |
| Simulation in `native/simulation`            | Accept typed commands, due simulation work and validated proposals. Check physical life, choice bindings, costs, installed rules and eligibility. Stage ordered effects, saved randomness, IDs, event/observer evidence and dirty rows in the existing reversible candidate. Publish once. Return purpose-specific read products and change notices. Only this owner mutates the live world.                                  |
| Compute and admission in `native/world-host` | Admit world operations before dispatch using the existing bounded workers. Keep one writer, rollback, poison handling and reader custody. A pending database, socket or provider wait holds its own resources outside compute workers and the world lock.                                                                                                                                                                     |
| Application in `native/game-server`          | Authenticate, resolve scope, schedule due work, assemble permitted outputs, reserve spending, drive providers and PostgreSQL, authorize final disclosure and deliver. Keep unrelated jobs independent, order conflicting work for one character, and serialize accepted world effects.                                                                                                                                        |
| External formats                             | Browser HTTP/SSE, MCP, model HTTPS, installed artifacts, database values, checkpoints and canonical bytes required by signatures/digests have actual format contracts. Encode at their owner. Pass typed values inside Rust. Serialize at the actual wire, storage or canonical hash boundary. A build-time TypeScript authoring or rendering tool is a separate consumer and must work without starting a Node world writer. |

For each family, start with a real instance in current-format storage. Follow it through discovery, a command or timed transition, observer and NPC evidence, accepted changes and derived records, then save and restart. Follow the [full conversion cases](native-simulation-core-tech-design.md#94-full-adoption-inventory-and-removal-targets) for preview rollback, shared materials, partial response effects, missed observations, cancellation and restore. Advance the family's inventory row only after its actual consumers pass. An inaccessible route or an empty list on a positive case leaves the row open.

## Typed handoffs inside Rust

**A villager answers a question.** Today the [simulation read](../../native/simulation/src/simulation/read.rs) already holds encoded first-person facts. The [NPC packet builder](../../native/simulation/src/runtime/npc.rs) joins these with appraisals, perception and candidates. The [reply formatter](../../native/game-server/src/npc/decide/prepare.rs) sizes and parses that bundle, projects a prompt, serializes a binding and sends it back to the simulation. [Recall](../../native/game-server/src/npc/decide/prepare/recall.rs) has separate source and current reads. Removing only the final join would still pay for encoding at acquisition.

1. Freeze witnesses for a manual reply and an automatic decision. Capture permitted prompt fields, reference/offer meanings, candidate order, original and current dependencies, first transport start, accepted operations, terminal receipt and cold result. Use controlled responses through HTTPS. Keep private evidence out of diagnostic logs.
2. At acquisition, build typed, purpose-specific facts from the existing authoritative field selectors. For decision preparation include the selected self facts, received bodies/current facets, appraisals and executable offers. For recall include the scoped selected personal sources, chronological positions and the small set of body identities/leases its formatter needs. Preserve exact personal text, event-time identity and optionality. Expose a borrowed view of an **owned, immutable, funded read**, or move an already-prepared field into its sole consumer. Never expose a borrowed live world to the async host. Reuse the existing response ticket for evidence and offered references. Retain the job’s original deadline and any player grant with the caller that enforces them.
3. Change both ends in the same slice, including the internal original-attention reader in [origin.rs](../../native/simulation/src/runtime/npc/origin.rs), candidate formatting, intake and the return binding wherever they consume the same field. The host must not call a capture that still eagerly produces an unused string. Where the old addon still has an actual comparison caller, serialization belongs in its adapter on demand. Remove that adapter at cutover. Avoid a public mirror of the entire actor schema and a generic JSON value tree as a substitute for the old string.
4. Borrow while rendering synchronously. Across a wait retain only the accepted read, funded output, binding or required shared subtree with its actual backing. Reserve before allocating. A small reference into a large parent can pin the whole parent. Measure lifetime/bytes and use a narrow owned copy when that costs less. Release temporary fields after their last consumer. Independently held recall, transport and publication retain their own custody. The simulation owns the actual executable choice. A caption or a freshly visible target grants no action or permission.
5. Use typed bind/validate on the same original and fresh reads, preserving the existing fresh-preparation opportunity before dispatch, the authorized first poll of transport, cancellation, original deadline, spend reservation, idempotent application and durable receipt. Test unrelated movement, relevant withdrawal before dispatch and during reply, disconnect, held readers and a genuine allocation refusal followed by explicit retry. Preserve exact UTF-16 code units for stored text, including an unpaired surrogate. Apply the existing permitted display conversion only at the output that needs it. Keep saved sequence limits, absent versus null, stable ordering and genuine signature/hash bytes. Reuse the [pending-intention and allocation checks](../benchmarks/native-runtime-foundations/2026/2026-11-20-rust-npc-background-work.md#pending-intentions-and-packet-admission), including rejection of inconsistent stored text without a database write. When the packet join disappears, exercise admission at the actual remaining allocations.
6. Run an isolated old/new comparison. The [smaller packet trial](../benchmarks/native-runtime-foundations/2026/2026-11-20-rust-npc-background-work.md#full-versus-smaller-reply-packet) measured about 134 KB down to 63 KB in two same-state checks. Median peak transient reservations fell from 185.2 to 150.9 MiB. Sampled server plus database memory was 532 and 537 MiB. Paired combined CPU per game-second changed by −8.0%, −3.7% and +3.5% with differing background NPC work. The direct Rust handoff still needs its own measurement. Verify zero internal encode/decode passes on the converted edge separately from timing. A refused allocation still records the actual stage before transport. Replay of the same request ID returns its recorded outcome. A permitted [explicit retry](../../native/game-server/src/npc/retry.rs) uses a new ID against the original accepted speech. It can save one reply without speaking the player’s words again. Verify both outcomes after cold reopen.

**Receiving the model’s answer.** [Generation and effects](../../native/game-server/src/npc/decide.rs) decode the external answer, transform movement from the character’s received frame and encode an internal operations envelope. [Application](../../native/game-server/src/npc/apply.rs) reads that envelope back. Convert this return path separately from the outgoing facts. Pass the validated, funded operations and the existing ticket to [native response admission](../../native/simulation/src/runtime/npc/bindings.rs). Reuse the [response envelope](../../native/simulation/src/response/envelope.rs) and its grammar checks. It preserves field presence, exact text and ordering used by the stored replay digest. Compare that digest and duplicate-ID outcomes before removing the intermediate string. Reconstructing the envelope from default-filled structs can change the digest. Resolve a relative move against the original position, heading and support. Preserve independent speech when a later action fails, the order of dependent operations, authorized previews and the terminal receipt. Exercise the same answer while the character turns or loses a target, then replay its ID after restart. A preview alone proves no accepted speech.

**Next edges.** Convert by producer and real caller, reusing the same approach only where data actually crosses the old boundary.

| Edge to trace                                | Implementation decision and check                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

Decode once at HTTP, resolve the scoped references, and pass a typed command plus its genuine signature/receipt identity. Keep canonical hashing if the receipt depends on it. | Finite local questions and answers           | Follow [answer_operation](../../native/game-server/src/boot.rs), `operation_format`, `control_format`, `activity_format` and `decision_render/choices`. | Saving, search and operational reads         | [The writer](../../native/game-server/src/store/write.rs) already binds SQL parameters from typed changed rows. Preserve this and ordinary changed-row reuse. Convert only internal re-encoding of prepared rows/evidence. A read gets an exact accepted cut and pending prefix before its first wait. Save acknowledgement cannot invalidate independently held reads. Preflight that admits an untrusted/large transfer in a fixed snapshot has a purpose. Remove a repeated query only when an equally bounded alternative passes the same reader, memory and atomicity checks.                                                         |
| Node-specific lifetimes and data conventions | Trace `runtime/consumer`, `runtime/handoff`, `runtime/retained_values`, wrapper finalizers, export IDs, declarations and reservation formulas to their actual users. Retire V8 heap estimates and JS object-liveness exports with the last Node caller. Rust still needs allocation admission, existing reader leases, privacy revocation and ownership until bytes drain. ICU collation, numeric order, UTF-16, digests, SQL null and client protocol rules can have independent consumers. Remove a representation only after tracing those consumers. Pinned Detour geometry and language data require no Node process.                 |

Follow the receiver's type when names match on multiple owners. For example, `boot::complete_route` already passes a typed geometry answer and its allocation into the hosted world. Counting another `resolve_navigation` overload in the addon as a Rust-server conversion would misidentify the work. For the opposite case, [stopped checkpoint recovery](../../native/game-server/src/store/checkpoint/recover.rs) feeds `restore_input.bytes()` to `begin_restore`. Keep validation at checkpoint/SQL ingress, then use a typed admitted restore request when the input was produced inside Rust. Qualify the damaged-world, atomic-failure and retry paths separately from ordinary play. Changes here convey no ordinary-play speed claim.

Select fields before allocating, preserve exact evidence bindings privately, and fund the final product once. When a digest exists solely to check that a JS wrapper returned the question it received, trace every reader. A native ticket carrying the issuing session, candidate and exact question can enforce that binding directly. Retire the digest only once no receipt, stored value, external signer or independent reader requires those bytes. Swapped, replayed and expired answers must still fail. Compare separate revisions without building both representations on every call. Moving work to a worker, adding shared caches, changing database pooling or duplicating a large capture to shorten a borrow are **separate experiments** if profiling identifies a material problem.

## Long-lived character memories

The TypeScript [scheduling and publication path](../../apps/server/src/cognition-maintenance.ts) implements more than a periodic timer. The [native maintenance runtime](../../native/simulation/src/runtime/maintenance.rs) and [consolidation driver](../../native/simulation/src/simulation/driver/consolidation.rs) already own semantic checks. The Rust [startup loop](../../native/game-server/src/launch.rs) starts lexical index maintenance, which builds search data. It does not schedule summaries. Rust can read existing summaries. Build the missing host path without introducing a second memory owner.

1. **Select due work.** Wire one cancellable maintenance task into startup, restore and shutdown under the existing director/resource owners. Reuse dirty-actor notifications, due game-time deadlines and per-character admission. Inspect only due actors under the existing [maintenance scheduling limits](../limits/cognition.md#maintenance-read-backoff). Rebuild due state at startup from the current world and durable schedule. Do not poll every actor's full history every tick. Compare the Source gates for living body, safe opportunity, pending learning, elapsed time in the current continuous sleep episode, configured reflection, ordinary raw work, interactive priority, pause and real-time backoff. Use installed policies. A linguistically incapable animal never becomes eligible just because time passed.
2. **Select one actor and one exact batch.** Use the [memory contract](../memory-architecture.md#6-hourly-consolidation-and-six-hour-raw-recall) and Source `memory-consolidation.ts`, `memory-repository.ts` and `native-consolidation.ts`. Select independently retained personal memories and awareness, with complete actor, source kind, ID and version. Routine hourly eligibility starts **older than** six game hours. A clock crossing never extends raw retention. Protect exact speech, outstanding obligations, important exceptions, personal perspective and chronology. Enforce current row and byte budgets in the selected database snapshot before hydration and overlay the pinned pending writes. Material arriving later belongs to a later batch. A protected-only hourly batch preserves exact text without requiring the idle thinking opportunity that routine summarization needs. Keep the actor’s other admission checks. It requires no inference. An empty selection buys no call.
3. **Admit and settle each paid request once.** Preserve hourly source digests, daily selection/cursor and sleep episode, and their timeline and live-generation guards. Record the attempt guard before dispatch. Use the configured `memory_consolidation` request per admitted partition. Reserve the background allowance once, leaving the configured interactive allowance available. At first send, check evidence, grant, body/opportunity, cancellation and the applicable deadline. Start transport under the synchronous disclosure check. Release the turn before waiting for the response. Settle the original provider receipt even if a later cancellation or withdrawal prevents a gameplay effect. At publication recheck current authority, relevant sources, cancellation, deadline and eligibility. Never require a second spending reservation to apply a funded answer. [Dispatch](../../native/game-server/src/decision_dispatch.rs) and [application](../../native/game-server/src/npc/apply.rs) own the corresponding checks for ordinary replies.
4. **Validate and publish.** Each routine source handle must occur exactly once in contiguous chronological groups. Protected originals keep their language and separate intervening groups. A daily interpretation reviews a completed game day during the same qualifying sleep episode and remains imagined. Waking or starting a different episode invalidates the old opportunity. Reject unknown, missing, duplicated or reordered sources, invalid file/identity edits and non-feasible output. Collect all partitions of the selected batch before one protected candidate. Stage summary/source changes, coverage and derived invalidations in the protected write. Advance the daily cursor only for a committed batch. If the cursor is written separately, a crash between writes must leave the existing pre-dispatch attempt guard intact. Recover by exact committed evidence or record unresolved progress. A stale cursor cannot authorize paying for the batch again. [OrdinaryProjection](../../native/game-server/src/store/history.rs) explicitly refuses summary and several edited-memory row families. Implement the required protected projection and exact reconciliation before enabling scheduling. Deleting that refusal alone would leave stale readers. A later failed daily batch preserves earlier committed batches.
5. **Recover and continue.** Cancellation on restore/shutdown invalidates old captures, joins outstanding work and drains the writer. A failed scheduling read has an advisory backoff. A failed critical write, an unknown transaction result and an uncertain paid attempt each follow their existing recovery policy. Never reinterpret one as authorization for another submission. A restart with committed daily progress resumes after that cursor. An ambiguous paid attempt requires recovery of the original job or an explicit uncertain outcome. Independent new observations, other actors' ownership, access and billing survive. [Maintenance failure policy](../memory-architecture.md#maintenance-storage-failures)
6. **Join the siblings.** Use the same scheduled intake and publication rules for real activity learning and optional intentional reflection, with their distinct Source priorities, eligibility, outputs, quotas, fairness and attempt records. Preserve the currently configured paid executor/tool permissions, workspace and protected identity. Check B can converse while A waits for review. Index refresh, embedding publication, ordinary decisions and consolidation have different triggers and durable outcomes. Trace each independently through its existing caller rather than starting one periodic scan per feature.

**Required fixture.** Create eligible and protected memories through actions/speech. Cross the six-hour boundary under the real clock or ordinary controlled game-time advancement, then reach a completed-day sleep review. Observe the actual HTTPS request, complete coverage, stored summary and next permitted recall after cold restart. Exercise busy-body protected-only cleanup, a balance exhausted by an already funded successful call, two observers sharing an event, concurrent new experience, correction/forget before sending and before publication, budget refusal, mid-partition failure, restart after dispatch and a new dream episode. Compare exact source coverage/order, identity, retention, attempt count and saved outcomes with Source. The three-hour heavy opening remains useful for ordinary CPU but cannot close this gate.

**Search by meaning.** Source [MemoryIndex](../../apps/server/src/memory-index.ts) schedules paid vector generation only when configured. The Rust lexical worker indexes words. Preserve both uses without adding a paid call to a movement update. Follow Source's `recall.ts`, `embedding-batches.ts` and `vector-store.ts`. Select missing eligible actor/source revisions, deduplicate and bound the batch, reserve spend, publish under exact generation/source/model/dimension, and invalidate on edit or withdrawal. A cached vector grants no permission to read its source. Compare configured, unavailable, incomplete and uncertain-provider cases. Through actual NPC recall, show a relevant permitted source found by meaning, a still-working lexical read without embeddings and no result from a withdrawn source. Apply the existing fallback/coverage policy when only part of the index is ready.

**An NPC asks what it saw.** The Rust [response schema](../../native/game-server/src/npc/decide/prepare.rs) offers questions about the received scene, but [the host](../../native/game-server/src/npc/decide.rs) refuses a populated query list. Restore the existing [query and final-answer path](../../apps/server/src/decision-situation-query.ts) under R4. Follow [cycle 5, step 5O.7](../technical/cognition-walkthrough.md#cycle-5-decide-what-to-do-and-make-model-calls) for allowed queries and shared work bounds.

1. Classify a validated first answer as final operations or one batch of read-only questions. Refuse a batch mixed with operations or invention before any effects. A direct answer takes the ordinary path with zero query reads and zero extra generations.
2. Answer only from this character’s original received scene/history and its scoped references. Use the core’s one-use [open_npc_response](../../native/simulation/src/runtime/npc.rs) to move the original reads out of their ticket. Follow the [existing native query caller](../../apps/server/src/native-decision-query.ts) to bind the expanded ticket. Keep missing or partial coverage explicit and bind newly disclosed references to their source and lease. Recheck after asynchronous reads and at first send. Fresh sight of something else cannot fill an old gap.
3. If the final request is funded and current, send it once under its own attempt ID in the same job, with queries disabled. Settle each provider receipt independently. End the first preview before opening another. A funding refusal, cancellation or withdrawn source leaves accepted player speech intact and never resubmits the first call.
4. Reuse the [mixed-host comparison fixture](../maintainers/native-simulation-core.md#provisional-128-mib-continuation--november-11-2026) through the Rust browser conversation. Check an ordinary answer and a question about an observed subject. Verify exact calls, a single saved reply per completed conversation and cold replay. Hold the expansion, withdraw its source, and require zero second dispatches and no new reply. Also exercise a foreign reference, partial history and exhausted second-call funding. A query with no usable answer must preserve the actual incomplete coverage and grant no new target.

**Complete the offers as well as the effects.** The same Rust schema caller currently supplies empty knowledge, identity and retention reference lists and no appraisal schema. Populate each from its own permitted source when the installed policy offers it. Use one scoped binding for the provider schema, provisional display where allowed, and simulation admission. Check a resident who has a real reference and another who lacks it. Exercise a remembered interpretation or appraisal through generation, application, recall and restart. Reusing a presentation label as a target would bypass this boundary.

**Making and using an item.** Begin with a known installed recipe and two players near the same limited stock. Record what each can inspect, which material belongs to whom, and the quantity and identity the recipe requires. Use the actual menu and an NPC request to prepare the offered action. The preview may compute reach and requirements but must revert IDs, RNG, reservations and save dirtiness. Let one participant take the last required material before the other's confirmation. The stale confirmation must neither spend stock nor manufacture output. Re-offer the method when the materials are legitimately available, complete it once, put the result to its intended use, and confirm the receipt, item lineage, memory and inventory after a restart. This exercises an action branch, a protection boundary and a reward the player can use. Apply the analogous concrete journey for each family in [the full adoption inventory](native-simulation-core-tech-design.md#94-full-adoption-inventory-and-removal-targets).

**Release inputs need an owner after deletion.** [The storage exporter](../../scripts/rust-game-server-storage.ts) currently instantiates the TypeScript repository against a disposable PostgreSQL database to capture schema SQL and imports record/reader/statement definitions from the former host. Before retiring that host, move canonical current-format DDL, row descriptions and bound queries to their actual storage owner (shared static SQL/data where useful). Generate and validate the release from that single source. Verify an empty database with the required extension, a populated database, asset authorizations and damaged-state recovery. Likewise trace the cognition, scene, navigation and view exporters to every imported world or presentation rule. Preserve verified definitions and digests. Eliminate imports that require building another playable server. Compare artifact meaning and native startup on a clean build machine.

**Configuration and lifecycle.** Compare `apps/server/src/config.ts`, startup and each feature's actual call sites with `boot.rs`, `launch.rs` and `npc/settings.rs`. For each retained operating mode map the setting, unit, default, validation, owner and positive/disabled behavior. Include local/OIDC access, awaiting-creation hosts, provider routing/model settings, budgets, privileged tools, player capacity, asset mounts and save/maintenance controls. Keep credentials server-side. Check startup under each materially distinct mode, controlled loss of its dependency, drain and restart with active work. Ignore obsolete flags only when the capability has a verified replacement or the flag solely selected a retired host.

Reuse the existing real journeys for [camp life](../verification/camp-life.md), [expedition rewards](../verification/rewarding-expeditions.md), [action reconciliation](../verification/action-reconciliation.md), [personal memory](../verification/attention-and-memory-core.md), [world creation](../verification/playable-world-creation.md) and [asset access](../verification/game-asset-storage.md). The [runtime-unification design](runtime-unification-tech-design.md#retire-the-alternate-pipeline-only-after-capability-reconciliation) identifies useful belief and relationship edits hidden in an older reflection path. Preserve these supported capabilities once, using the current mind publication and its field-level permissions. Carry a superseded or still-unimplemented requirement under its existing disposition. Do not resurrect an alternate pipeline because a fixture still calls it.

## Verification and cutover

1. Pin the current sources, authored opening hashes, database structure/seed, release, language/navigation assets, driver and inputs. Start from the retained narrow reply path. Record which checks are source inspection, same-cut component comparisons, real caller checks and measured gameplay. Keep frozen campaigns in their original revisions.
2. For one change at a time, record its baseline oracles **before removing its last caller**. On independent databases drive Source and Rust through the same real inputs and compare admitted operations, observer-specific output, recall witnesses, randomness/IDs, durable changes, refusal and cold continuation. Compare request-local aliases by binding and scope where their values are intentionally unpredictable. Existing compatibility-free save policy applies. A disabled family, only testing empty arrays, or a different amount of accepted work cannot establish parity.
3. For uncertain performance or behavior-preserving redesigns run the existing three interleaved repetitions per arm, clean release builds on the standard managed 16 GiB worker and independent databases. Use one simulation worker in both Rust arms, the current 2 GiB transient allowance, the normal clock and browser stream, ordinary reclamation and one-second saves. Use the established 180-second, 26-actor workload with both replies applied and saved, plus a separate due-maintenance or family-positive window for the work it never exercises. Long-lived evidence can be generated by real play and reopened at an equivalent saved cut for each arm. Keep timing free of diagnostic counters. Requalify held-reply/cancel/view-loss/repeated cycles when lifetimes change.
4. Lead with server and exclusive PostgreSQL CPU (% of one core), achieved game speed, and command/first visible movement/durable-save latency (median, average, p95 and sample counts). Include offered/completed time/debt, client/worker accounting, combined CPU per completed game-second, SQL calls/rows/prepared bytes, WAL/growth, actual RAM/settling and separate resident/transient/pending reservations. Mark unavailable metrics and account for varying automatic NPC work. Use the [measurement policy](../performance/measurement.md#planning-comparisons). Revise or reject an unhelpful implementation. Repair failed required journeys before comparing cost. Architecture cleanup alone establishes no speed claim.

Avoid keeping a live fallback, cross-writing two databases or deleting shared world definitions. Build/typecheck remaining tools and browser, deny unexpected runtime dependencies and recheck the real startup and recovery paths.

**Experiment decisions.** For each uncertain representation, scheduling or SQL change, freeze the primary measure, expected work and failure cases before timing. Use adjacent Rust builds differing only in that change, with common fixes in both. For example, measure outgoing reply facts and incoming operations separately. Run the same source-withdrawal, held-reader and exact-retry cases on both builds. Use [NSC-L10](../limits/native-simulation-core.md#nsc-l10--stand-alone-rust-server-comparison) and the affected feature’s limits. A repeatable material regression rejects the alternative. Variation or unequal completed work leaves its performance inconclusive. A failed required journey keeps the task open. A simpler typed representation can earn its place on correctness and ownership without a claimed CPU win.

Measure the idle cost separately on Rust before and after enabling it, on an opening where nothing is due. For the optional scene question, compare direct answers separately from answers that actually needed the extra call. For memory review, compare equal completed sources/partitions and also the first interactive reply during a held review. These are different workloads. No gameplay reduction or new numerical target is selected.
