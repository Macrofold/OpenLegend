### Execution sequence and completion criteria

1. **Audit and baseline (SC01, PO01, DI01, ACT07.1, MP01.1).** Trace current writers,
   readers, record codecs, save capture, privacy and direct position/custody assumptions.
   Record deterministic wilderness/charge traces and matched native stress measurements.
   Inspect branch deltas at the affected seams through DF02, not blind branch merges.
2. **Shared state (SC02–SC08).** Extract typed native/sparse state operations without
   changing sequential physiology or RNG. Add atomic claims, explicit partial transfers,
   duplicate-safe holds and independently removable active contributions using the current
   status owner. Integrate actual charge and finite-resource consumers, canonical records,
   restoration, retirement, permitted projections and authoring capability descriptions.
3. **Authority (MP01.1–MP01.6, MP04.1–MP04.4).** Implement verified authentication,
   durable current account/grant/control ownership, immutable request scopes, scoped
   receipts and all HTTP/tool/async publication checks. Make projections and streams
   audience-specific. Implement bounded exit/inactivity/validated return, then demonstrate
   two genuine authenticated sessions, takeover, contention, revocation and recovery.
4. **Objects (PO02–PO09).** Replace separate writable lots and duplicate locations with
   entity components and one tagged placement. Convert supported saved state atomically;
   preserve identity and quantities. Implement exact split/merge/retirement, individual
   equipment, finite nested bags, separate declared ownership, bounded contents UI and
   safe work/removal/save/inactive-root integration.
5. **Dependencies and budgets (DI02–DI08).** Introduce dependency metadata with the
   first new owners; retain conservative invalidation until coverage is proven. Extend
   existing ActorWork with captured-generation acknowledgment, membership-aware spatial
   and nonspatial consumers, aggregate root/descendant/recurrence admission, current
   installation limits and explicit required-work failure. Keep the current scheduler,
   cadence, evidence and spend owners.
6. **Continuity (ACT07.2–ACT07.7, ACT08.1–ACT08.4).** Extend the current appraisal owner
   with stable identity, admitted policies, multiple source kinds and persistent/native
   lifetimes. Preserve existing fear/discomfort during migration; demonstrate persistent
   grief and an opt-in internal source. Extend the existing coupled reflection boundary,
   source correction/forgetting and permitted panels/context. Present directional social
   notes from the current knowledge document without a second writable representation.
7. **Combined qualification and reconciliation.** Exercise complete real consumer loops
   and failures across both SQL adapters, native simulation, ordinary browser/network
   surfaces, restart and restore. Inspect the complete affected diff and fix in-scope
   issues. Update canonical current behavior, focused child/parent trackers, decision
   history and actual verification evidence. Completion requires every agreed slice and
   its required evidence; a compile, isolated module or partial milestone is insufficient.

Each durable slice integrates SL00 at introduction. Domain owns deterministic transitions;
WorldService and the existing repository own serialization/publication; protocol owns
public intentions; client owns presentation. Current authority/privacy/accounting do not
rewind. No duplicate inventory, scheduler, emotion store, world writer or provider harness.

Implementation review decisions: account rebinding uses a separate audited access mutation,
settles both bodies through the participation owner, and retains historical human privacy
ownership outside rewind. An access administrator cannot transfer another human's private
character content by rebinding or restoring an older save. Rebinding to an unowned NPC or
another character already owned by that account requires fresh explicit control acquisition.
Player-to-player speech uses the existing native command/receipt/evidence path and ordinary
composer without provider setup. Appraisal reframing retains the original occurrence and
adds separate interpretation provenance; it cannot restart a fixed native decay curve.
Authored NPC grief has a separate opt-in policy and durable scoped receipt; prior experience
policies keep their exact pins. Cold object history binds occurrence-time custody, keeping
older records private when that evidence is unavailable. Creator capability discovery now
describes the supported native owners and limits to the current world assistant without
expanding the finite generated recipe schema or granting mutation tools.

The SC06/DI06 lifecycle audit also requires reservation occupancy to join the existing
work accounts (approximately 200–250 logic lines plus caller verification). The reservation
owner will derive live/retained totals by claimant, definition and invocation from its
canonical records; no second writable allocation ledger is introduced. New holds must
bind an actual action or admitted native process and its actor. Already saved holds retain
their identities and quantities; legacy records without claimant evidence remain charged
to world/host capacity, without inventing historical ownership. Admission combines these
totals with native work, terminal release drops live occupancy while retained receipts
remain accounted, and completion/cancellation/save-reload checks must prove conservation.
Required verification includes aggregate refusal before publication, exact duplicate
handling, real action termination and both SQL adapters. Terminal receipt retention is
bounded by resident capacity; a future cold-only reservation reader must preserve exact
idempotency before those receipts can be evicted.
Measured admission of 2,024 small holds initially took 8.88 seconds because each admission
rebuilt all prior receipt metadata. Admission now extends draft-owned derived indexes and
transfers them at publication; consumption/release preserve conservative rebuilds and exact
native summation order. Warm/cold and fork comparisons are required before qualification.
The PO06 reference audit adds a rebuildable reverse index for independent contribution
sources (approximately 100–150 logic lines). Item merge/split equivalence must reject live
incoming source references, not just state stored on the item itself. Maintain this index
from the same exact changed-entity publication set and current draft bindings. Source loss
must cease effective capability blocking immediately; the existing native lifecycle still
owns final state/events. Verify source-bound merge rejection, unrelated-source preservation,
same-phase attachment/end, cold rebuild and fork isolation without scanning a wide bag on
each item operation.

The final lifecycle audit adds approximately 200–300 logic lines for terminal independent
contribution residency. Preserve terminal records in `sim_status_effects`, evict them only
after canonical commit, and restore complete records for save capture and explicit policy
maintenance. Native singleton cooldown state remains hot. Rebuildable completeness metadata
must survive domain transitions and prevent deletion of cold SQL rows. Native episode IDs
remain monotonic; direct caller-supplied contribution IDs require complete history before
fresh admission, while exact retained command receipts still replay. Definition replacement
must refuse incomplete reference coverage until maintenance materializes it, then enforce
the existing exact pin rule. Verify both SQL adapters, restart, capture/restore, forked
indexes, duplicate replay, policy pin rejection and a mature repeated-lifecycle workload.
Also correct split lineage so moving units into a new identity records only a split;
consumption history must represent an actual loss of units.

## Thorough implementation review

The developer requested a full review and in-scope improvements after delivery. Refreshed
`origin/main` remains `ce7ef555f50c979ac3d2179cf5876ea4a55e1318`; the branch is already
at that base and the complete uncommitted implementation is preserved. Review scope is the
entire foundation diff, including new files and existing callers. Initial repair estimate:

Confirmed first repairs (approximately 80–140 logic lines): protect held reservoir stock
at the sole sparse-value writer, settle admitted hold consumption before its coupled value
publication, and retain explicit native failure without advancing time. Typed owner edits
must reject unchanged. Fixed contribution attach/refresh retries must consult exact committed
receipts before applying current-time admission checks. Verify fresh expired requests and
changed-body retries still reject, plus native rate/held consumption and both-adapter reload.

Further confirmed repair (under 30 logic lines): physical command/quantity eligibility catches
must propagate `WorkBudgetError`. A nested transfer currently returns an ordinary item failure
after exhausting its enclosing candidates envelope, and quantity validation similarly hides
the contract breach. Preserve ordinary eligibility outcomes while aborting required enclosing
work; verify nested native commands, quantity planning and an actual pickup completion.

Control projection repair (under 20 logic lines): the general action catalogue currently
enables native commands for a noncontrolling tab although execution correctly refuses them.
Apply the existing control grant to catalogue availability with a clear reason, avoiding
unnecessary native previews. Verify the real HTTP catalogue and browser menu before/after
explicit control acquisition; retain read-only composition and inspection affordances.

Final owner-boundary repair (under 15 logic lines): item quantity/retirement ports currently
rely on callers to protect holds. Enforce remaining backing at publication inside the item
owner, after an admitted phase settles consumed holds, so new native callers cannot bypass
this invariant. Verify direct refusal, exact held boundary, own-hold consumption and final
retirement with preserved availability revisions and native reservation validation.

Consumption stress also exposed repeated reservation-index rebuilding at publication. The
repair adds about 80 logic lines to update the existing draft-owned index for settled holds,
sharing admission copy-on-write helpers. Integer totals remain exact; changed continuous
totals retain canonical summation order. Warm/cold accounts, retained receipt bytes, deadlines,
invocation membership and forks agree. Three matched runs reduced median held-item consumption
wall time by about 48%, with identical complete world digests.

Review sequence: inspect typed state/claims and object/index invariants; trace authentication,
control and async publication; audit appraisal/source/cold-history ownership and save/restore;
check dependency/work accounting and measured hot paths; inspect protocol/client/rendering
consumers and complete documentation. Prefer repairs through existing semantic owners and
remove duplicated work only where equivalent behavior can be demonstrated. Do not change
accepted product contracts or integrate the other branches under this review.

Verify each substantive correction through an actual downstream native/HTTP/browser journey,
including a meaningful failure case; use both SQL adapters for persistence changes and matched
stress for hot-path changes. Keep the no-suite/no-paid-call policy and required CI. Completion
requires a reread of the resulting full diff, focused tracker/evidence reconciliation, passing
relevant static checks and no remaining actionable in-scope finding.

## Cross-project implementation order

1. **Refresh the actual implementation base and reconcile overlapping code through DF02.** Preserve current main record/query/privacy/Worker work, relevant invention/hearing/action/cadence changes and exact admission/receipt behavior. This design branch does not authorize blindly merging those branches. Resolve genuine semantic conflicts before coding the affected slice.
2. **Establish the smallest contribution and authority contracts first.** SC01–SC04 make ownership/claims usable through current native consumers. MP01 can prove two humans against those or current finite resources; it does not wait for a complete nested-object system. Carry explicit scope and semantic change keys from each introducing slice.
3. **Build object identity and containment through the real tool/bag consumer.** PO uses the stable P1 claim boundary and P2 authority. Its canonical migration replaces current item/placement ownership in place; it does not redefine resource arithmetic or create a second inventory service.
4. **Introduce dependency metadata early; qualify it with concrete consumers.** DI01–DI03 may proceed alongside earlier projects. Conservative current invalidation remains until precise membership coverage is proved. DI04–DI07 integrate actual P1/P3/SW/EPR owners; EPR05 remains the scheduler implementation. Avoid circularly requiring the full P4 framework before those first consumers exist.
5. **Deliver appraisal and social continuity over current native/CR owners.** Basic ACT07 persistence and ACT08 subject-note views can proceed with existing change hooks. Advanced context/reflection uses the current publication boundary and later precise invalidation; neither live inference nor a universal emotion taxonomy is a prerequisite for native continuity.
6. **Join SL00 in every durable-state slice, then qualify combined behavior.** Register capture, current-record completeness, references, rebuilds, stale callbacks, privacy and non-rewindable authority/accounting as state is introduced. Individual fixture success does not replace the combined native/database/client failure scenarios or PF/D5 workload evidence.
