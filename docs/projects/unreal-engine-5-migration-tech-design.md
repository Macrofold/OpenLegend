### Components and inputs

Keep one UE runtime module initially. Give the game instance the session and request lifetime, a per-connection model the currently permitted view, the level the render components and resource handles, and the local player the input contexts and widgets. Inbound transport queues complete messages in order. Only the game thread changes the displayed model or touches UE objects. On a fresh scope, increment a generation before releasing the old model and detach all old listeners. Level changes can rebuild visuals from the current permitted model. Share only genuinely public immutable render resources across scopes. Studio automation lives in the editor/build workspace. Browser creator tools keep their existing application and grants.

Keep the public boundary small. The packaged client reads the existing public wire format via independently cleared bindings, with positive and refused message examples captured from the real Rust routes using disposable accounts. Decode fields required by each consumer, keep unknown authored vocabulary as data, and select actions/labels from the installed world. A missing required decoding shape ends the affected operation with an actionable update or reconnect. It must never become a default action or a valid empty state. Use captured fixtures for field and Unicode fidelity, then exercise the live server and two independently permitted views. Code sharing, including running a schema generator against AGPL inputs, still needs UE01 clearance.

**UE5 implementation and future ports.** Use Actors, C++ components and Blueprints for the local camera, characters, animation, effects, highlights and building previews. Choose the tool that best serves the UE5 implementation. A C++ subclass of `AActor` still depends on the Actor framework. These objects consume the permitted model and submit intentions through the session owner. A smith’s animation can show a hammer strike. The installed Rust activity completes the work and produces the item. Keep Actor handles, Blueprint class paths and World Partition cell IDs inside the client. Budget to port object lifetimes, input and widget bindings, animation graphs and plugin integration. Preserve the public field meanings, coordinate mapping and logical art bindings across clients.

## UE02 — Entry, identity and the first frame

Use one game-instance-owned C++ session object for the selected HTTPS host, the private session cookie jar, a random connection ID unique to this running instance, one ordered game event stream and outstanding requests. UI and level loads subscribe to that object. Releasing a level never logs out, takes control or starts a second stream. Keep the host and asset origins in trusted environment configuration. Invitation links may select an allowed environment and start the existing enrollment flow. A link supplies no account, grant or controller authority. The current Rust access router implements hosted OpenID Connect and a separate explicit loopback development login. Its callback sets an HttpOnly game session in **the browser**. Desktop credential transfer is a new host feature. Open the configured hosted sign-in page in the system browser with an S256 challenge and a callback restricted to a literal loopback address, ephemeral port and fixed path. Under the Rust access owner add a desktop authorization start, browser confirmation and HTTPS code exchange. Bind the challenge, callback, state and short expiry to one pending attempt within the existing login resource budget. Reuse ordinary login, invite validation and the signed-in account. Display the account and require the user's confirmation before completing the desktop handoff. Return only state and a random one-use code to loopback. The app verifies its pending state before exchanging the code. Require the initiating verifier and matching callback at exchange. Under the existing authority owner, atomically consume the code, confirm the browser session is still authorized and issue a distinct revocable session for its verified account. Reuse session issuance, expiry and grant lookup. Leave the issuer’s previous-session argument empty so the browser stays signed in. Deliver the desktop cookie in the HTTPS response. Keep the host’s identity-provider state and verifier separate from the desktop exchange. Race redemption with logout, revocation and a second redemption. Each one-use code can create at most one authorized desktop session. Session writes keep their access checks and commit handling together after admission, even if the app or browser disconnects. ## UE03 — Scene, physical agreement and what each observer learns

One adapter converts authority coordinates at the scene edge. In server coordinates, up is +Y, heading zero faces +Z, and the right hand then points toward −X. For world origin offset `O` in metres and world point `p`, set `q=p−O`; the UE position in centimetres is `100·(q.z,−q.x,q.y)`. Invert for submitted points and retain the **selected support's public surfaceId**. Use the same axis transform for velocity with length conversion, and only its axis part for unit directions and normals. Convert rotation through the basis (`B R B⁻¹`) before extracting a rotation in UE units. For a heading h in radians the UE forward vector is `(cos h,−sin h,0)`. Account for the reflection once at import when winding geometry and building tangent frames. Keep canonical positions in double precision metres, shift local display anchors together on rebase and invalidate cached screen-space picks. Test 0/quarter turn, both hands, normals, pitched ramp, overhang, two stacked floors and a distant pick/return, including inverse round trips. [World heading](../../packages/spatial/src/approach.ts) · [World point and support](../../packages/spatial/src/types.ts) · [UE coordinate conventions](https://dev.epicgames.com/documentation/en-us/unreal-engine/coordinate-system-and-spaces-in-unreal-engine)

Keep a scene binding keyed by each authorized public reference for its current view, separate from public terrain release/cell identity. Bind position, appearance, verbs and permitted cues. Rust decides crossing a threshold, contact, reach, support, hearing and elapsed time. UE predicts the controlling player’s grounded steering from the first keypress. The body and following camera use one displayed position. Hold other characters at their latest permitted measurements. Two sightings alone disclose no intervening path. Hold progress on pause, lost freshness or discontinuity. Snap/reset on replacement, teleport or stale support, then resume from the new authoritative pose. A visual roof cutaway can expose only already-permitted entities. Use one active camera and the one permitted scene for [all three views](../features/unreal-player/play-and-perception.md#looking-moving-and-choosing-an-action). Behind the character, the player’s mouse sets the horizontal steering angle while moving. Follow the displayed body without feeding its predicted or corrected heading back as new mouse input. Elevated framing follows position without automatically rotating. Its orbit and the shoulder view’s aiming reticle leave held steering in its existing world direction. Pull the camera inward against permitted scenery in tight quarters. Read the character’s confirmed sight guide for its range, angle and optional heading. Respect a disabled or zero-range sense and all-around sight. Reuse the existing guide’s clipping against permitted geometry. A predicted turn does not rotate the physical sight guide. [Rust guide](../../native/game-server/src/player_scene/self_view.rs) · [Range guide contract](../spatial-world.md#perception-range-guides)

Camera switches and reticle motion use the current view locally. They open no stream and request no state, action menu or NPC availability. Read those on real entry, interaction or relevant invalidation under their existing owners. Picking and aim assistance use only permitted subjects and geometry at the displayed pose. Rust validates the submitted target or point. [Physical and camera contracts](../spatial-world.md) · [Time](../simulation-time.md) · [Browser scene interface](../../apps/client/src/world-renderer.ts)

Consume distinctions between currently seen, heard and remembered **before** spawning or loading assets. Use the delivered evaluation cut and sight-confirmation time where specified. Silence or omitted detail implies no new information. An unidentified voice behind a wall can produce the permitted words, apparent direction or area and matching caption, with a generic cue at the allowed precision. It must produce no exact speaker transform, recognizable voice, portrait fetch, shadow, reflection, minimap dot or body to pick. New sight can reveal a body under a fresh public reference. Remove source-bound cues and late callbacks on correction, forgetting or withdrawal. Other worlds may admit a different sense or no identifying speech. Rust supplies the permitted evidence. The graphics setting, camera and GPU never calculate what an NPC knows. Check scene, map, downloads, captions/audio, menus, accessibility tree and logs for two differently situated embodied accounts. Check actual display on each, then revoke one while another keeps walking and speaking.

On selection, send the contact’s public `targetId` to the action menu and submit only the chosen offer through its real handler. A remembered communication reference identifies a possible recipient. ## UE04 — Acting, hearing a reply and returning

- Put the three angles in the existing Camera and graphics selector. Provide a remappable scene shortcut to cycle them while walking (initial binding X). Follow and shoulder start in mouse-look. Elevated play starts with a free pointer and drag-to-orbit. In mouse-look, Escape first dismisses the active popup or cancels its owning gesture. Otherwise it frees the pointer for selection and click-to-walk. Moving the free pointer over a merchant does not steer a held walk. An explicit aiming gesture still picks at release. Provide a focusable HUD control to resume mouse-look and consume the activation. Ignore angle changes while a pointer gesture owns a shot or placement drag. A player can release or cancel first. Preserve a target already frozen for review and keep the camera switch independent of weapon preparation, release and spending.
- Route input through one active context (scene, placement, menu, modal or text). Reserve a gesture for its initial owner until release or cancel. Resolve a named action on press and recheck on release. Where the action explicitly aims, pick the current eligible body or support on release. A drag ending over an actor does not issue a click. Use engine input mapping and widget focus for keyboard and pointer. Drive menus from authorized `/api/actions` offers. Send steering changes, renewals and release through the [movement contract](unreal-engine-5-migration-movement.md#open-legends-movement-contract). Release on focus loss or modal takeover while possible. Stop renewing on suspension, disconnection or control loss. [Input leases](../../native/game-server/src/world_input.rs) · [Action selection](../../native/game-server/src/player_http/actions.rs)
- A click submits the host-supported command or typed action with its offered public target/support, current request context and one original identity. Before sending retain the receipt lookup fields specified for that operation, including exact original payload where the route requires it, encrypted under the private owner for restart recovery.
