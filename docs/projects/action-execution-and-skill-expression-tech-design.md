## Behavior-to-implementation contract

Deliver the [ND38 player feature](action-execution-and-skill-expression-feature-spec.md) through **ordinary admitted actions**, not a second minigame result engine. A human chooses a permitted action; its physical preparation remains native; an optional input exercise yields bounded **action-specific execution evidence**; one trusted family derives any permissible effect; the actual world owner commits the effect, receipt and disclosure. A resident chooses through its ordinary controller and executes through the same physical owner using character competence, not simulated cursor input.

The first complete connected demonstration is (a) quick versus optional timed ranged/melee attacks while walking, observing and tracking real animals/opponents, and (b) optional **point-placement fit** during real woven-container manufacture, yielding an item-specific effective carrying capacity and optional derived grade. Include no general scripting interpreter, second combat solver, second item-quality store, nominal 'equipment quality' modifier ignored by use, universal stats, or per-frame model call.

[Existing engine/world boundary](../engine-and-world-boundaries.md#5-a-repeatable-boundary-decision) remains controlling: stable identities, authorization, resource accounting, ordered native effects, safe observation, restoration and data-driven admitted definitions are reusable; the selected game's weapons, skills, injury/evasion law, ring tuning, material fit, item facet, names, and quality grades are **replaceable world policy**. Other coherent worlds can omit any mechanism. A supported family may be compiled native code without becoming universally installed.

### Engine-owned versus world-owned computations

**Engine/reusable finite services:** pointer-gesture lifecycle, device-neutral normalized input coordinates/phase, frame-independent ring renderer, score calculation under an admitted fixed numeric curve, bound/finite action preparation, exact invocation identity, authoritative transition/receipt, immutable/pinned action evidence, object-property accessor, and observer-scoped projection.

**World-owned authored decisions:** which installed action permits timed release or precision placement; visible ring bands, tempo/skill influences; which body condition affects timing; which combat outcomes a release changes; actual weapon recovery, projectile/strike laws, evasive response; which recipe admits finishing, which supported item facet it affects, percent bounds, grade text and criteria. An invented item, label or arbitrary world data cannot register a new property-mutating callback, executable formula or security grant.

## 1. Player input and shared attempt lifecycle

### 1.1 Finite named states

The client gesture owns only `idle → candidate-tap → manual-hold → submitted/cancelled`. A tap released before the **hold threshold** submits one **normal native action**; crossing the threshold opens the active optional gesture without submitting a first hit. An already selected native aim that is winding up can be held and released **once**, subject to readiness and normal work time. Unavailable/blocked/recovery is explicit and consumes no extra action. An active long hold never repeats a shot. Avoid mode/click ambiguity by capturing tool, chosen action, permitted target identity/life or point-only intent, world/timeline/control epoch and selected world profile at pointer-down.

A held button's ring phase is computed on the client from a **monotonic real elapsed timer**, independent of game simulation speed, local render-frame count, server state-delivery frequency and wall-clock/date changes. Input can be sampled at display refresh for presentation; **send no recurring network or paid model updates**. A release sends one finite commit request with the final pointer-derived aim point and timing sample; all native world consequences happen only after admission. A tab blur, connection loss, life/control change, cursor-over-own-body cancellation, Escape, modal entry, player switching mode or rejected capability clears the gesture and never 'releases on cleanup'.

One gesture may prepare a native action on server; the server's exact action/target/pins and resource claims are authoritative. Client gesture cancellation must cancel only the matching unfinished owned aim/finish, not an unrelated plan or a flight already released. A late acknowledgement/replay cannot start or fire an old gesture after mode/cancel. Use existing command request/receipt identity and load epoch fencing. Only explicit correct release commits a native projectile or strike. No new general-purpose persisted gesture database.

#### Exact attack-gesture transaction order

**Chosen first implementation:** in attack mode, a valid primary **pointer-down** captures the action/tool/intention and dispatches **one ordinary native beginning of preparation immediately**, rather than waiting for the hold threshold. This makes normal tap and deliberate hold pay the same weapon windup; if blocked, do not show a usable green release. Crossing the 150 ms local threshold changes only the optional client presentation to a moving ring. The **native source** owns ammunition reservation, body handling, preparation progress and interruption. The client never announces that an attack actually started before its authoritative admission receipt.

Pointer-up is **one release intention** (ordinary if under the threshold; optional scored if held). If the native begin acknowledgement or actual windup is still pending, store that **single immutable intended release** for the same pending action and perform it at the earliest native ready boundary, rechecking actual actor/tool/method/point/permission and cooldown. Do not turn premature release into a second attack, roll another release timing, spend ammunition early, or automatically update the final aim point from a later moving deer. If begin is refused, fail the release without any physical effects. If the player cancels before that boundary, cancel only that exact unfinished native preparation; a late begin reply must lead to cancellation, **never** replay the old release. If released flight/strike was already committed, cancellation cannot undo it.

**Wire operations are typed variants of the existing single native command/receipt path**, not a second attack service: (1) begin the exact chosen physical action with stable request ID; (2) commit one point/score-bearing release against its returned action ID; (3) cancel that exact unfinished action. Same-device consecutive requests stay ordered by the command owner, not arrival time. The client may retain release intent until the begin receipt confirms identity; if the tab disconnects, the native ongoing action is inspectable on reconnect with explicit Release/Cancel, and there is no automatic fire. Current authenticated control/life/epoch, definition pins, observed intended subject, selected weapon/ammunition, current work and source law are bound at admission and revalidated where they can have changed. The UI ring can continue animating while awaiting the begin reply, but its local optimistic state grants no authority.


### 1.2 Movement alongside preparation

WASD supplies a normalized intended **actor-relative/camera-relative ground-plane direction** to the existing movement/navigation owner, with proper support/elevation and body collision; movement must be authoritative server input, not repeated public `move to point` commands every graphics frame. Introduce a narrowly admitted transient **locomotion intent** with bounded renewal/dead-man release and an actor/controller identity so delayed packets cannot keep someone walking. Integrate native elapsed time and existing spatial movement; do not add another position writer, route bypass, client-supplied position or second physical plan. The client may interpolate presentation within observed public state but never changes world collision/target coordinates.

The selected default-world attack-aim compatibility can combine **one accepted primary combat handling action** with **one locomotion intent**, while remaining incompatible with chosen guard, crafting, another weapon preparation or independent unrelated manual work. This is a **resource-claim distinction**, not unrestricted multi-lane actions for every actor or species. The affected body/weapon action owner must explicitly admit this combination; unsupported bodies return a truthful refusal. Reaching a different floor/ledge, changing tool, death, body/control loss or incompatible interruption ends or invalidates the exact owned actions normally.

For melee, the WASD participant must close distance deliberately; timed green outside real reach does not auto-approach or land a hit. Native NPC navigation/approach still works for NPC commands and ordinary menus. For ranged, approach is never predicted from an unseen fleeing target. Facing/orientation must be derived from the admitted aiming action at the release boundary under supported body rules, not from camera orbit; this first slice need not invent a global turn-speed skill.

### 1.3 Attack-mode ownership

The mode is a **local player-control UI state**, not `actor.hostile=true` or a hidden native combat phase. Store it only through existing supported player settings/current session when needed, never as permission, damage, actor knowledge or a second engagement list. Enter manually through the remappable toggle (candidate Shift+T), on an actually **admitted** own offensive request, or on **personally delivered current directed assault/injury evidence**. The existing combat pair table still decides preferred `Speak`/Attack for Command-click; mode merely interprets eligible ordinary primary clicks. Do not infer attack mode from being close to a person or querying a target's private intention.

Manual Off suppresses re-entry from the **same** observed hostility revision; an actually fresh qualifying assault can turn it on again. Do not repeatedly re-enable from a retained grace timer, reconnect re-render or stale stream. A new controlled character/tab starts visibly in a safe neutral mode until manual entry or fresh evidence; the exact transport/control epoch fences late responses. Primary click in attack mode must capture both the selected tool and target/aim intent, not silently fall back to Speak/Move when temporarily unavailable. Secondary menus and accessible targeted action route remain working alternatives.

### 1.4 Pointer aiming and cancellation

The PlayCanvas camera projects screen pointer location onto a **permitted physical world ray/point** using current visible support/body/surface geometry. The aim point can be on a moving target's observed visible body or an ordinary visible surface, not automatically the subject's center. Freeze the **final pointer aim point at release**, with exact support/elevation where applicable; the shot direction is the vector from the weapon/body's native launch anchor to that point, then normalized. It is not a continuously homing ray or a resurrected remembered coordinate. If no finite nonzero supported ray exists, refuse without ammunition/impact. Camera changes and stacked levels must not silently choose a hidden floor.

**The first selected base-world ranged family supports a point-directed attack**: pointer-down may select an eligible visible 3D point on ground, scenery or a currently observed body. If a recognized person/animal is under the pointer, preserve its exact identity and physical life as the **intended subject for admission, warning and historical attribution**, separate from the release point. A ranged player's eventual chosen release point remains the only directional target; the point may move away from the subject while tracking or leading. No entity is homed onto after release. In a selected world that permits point fire, an animal's loss of sight during preparation need not cancel an otherwise valid **point-directed** shot, because the actor is using their own available observed point/direction, not the animal's hidden current position. Do not silently convert a different target-bound method into point fire.

If the mouse starts over empty perceived ground, a compatible ready launcher can shoot toward that point normally; a melee weapon does **not** acquire a fictitious point-damage attack. The server reprojects/verifies the selected aim's finite range, actual launch geometry and permitted 3D support or visible direction. A point on an ambiguous unseen floor, an invalid zero-length ray or prohibited surface is refused before debiting ammunition. The real physical flight can nevertheless strike a previously unseen body on the way, without telling the shooter who that body was. A target identity is never inferred from an unseen global object lookup.

**Lethal review cannot be evaded by changing command shape.** If the down-gesture was actually aimed at a currently recognized human, the same exact source/subject lethal/PvP review applies even when the client sends an aim point. A no-subject point shot in the bundled world requires an explicitly disclosed general chance of hurting any physical interceptor; the preview may not scan/reveal hidden bystanders. CTR01's released-world contact permission remains binding on the actual collider, and no newly lethal interception cancels a committed flight after release. Point-only shots are unavailable in another world that does not install their permitted family.

Deliberate mouse movement entering the controlled character's visible cancellation area while holding cancels before release; character movement or camera follow alone never triggers cancellation under a stationary pointer. Escape and a reachable Cancel button are identical action cancellation. Do not treat every incidental pointer crossing as a new selected target. The highlight can be local presentation and does not require the server to know each hover sample.

## 2. Typed execution interaction and score

### 2.1 One installed binding, with input separate from physical intent

Extend the existing installed action/capability descriptor and its exact `DefinitionPin` from `world-modules.ts`. Do not build another action registry. Each optional execution descriptor identifies one supported input kind, an immutable world-authored profile and the finite consequence channels its trusted family can consume. The first channels are ranged contact, melee contact, pre-defense injury and woven-container fit. Neither a browser nor an invented definition may supply an arbitrary stat path, callback, code string, raw damage or item capacity.

These are **required planned fields**, attached to the existing owners; names may follow neighboring TypeScript conventions without changing their semantics:

| Owner | Retained meaning | Admission and consumers |
| --- | --- | --- |
| Installed execution descriptor | Exact profile pin; `timed-release` or `point-placement`; finite shape/score parameters; supported consequence channel/rates; permitted ordinary/manual/assisted routes | Definition admission validates each required field and supported family; catalogue and UI use its safe projection; no profile means ordinary action only |
| Native `Action` optional execution binding | Existing action ID and actor physical life; ordinary/manual/assisted mode; exact action/tool/recipe and execution pins; at most one accepted input choice | Begin, continuation, cancel and effect completion share this binding; never add a second pending-action dictionary to gameplay state |
| Timed input choice | Tagged normalized `phase` in `[0,1)` or explicit ordinary choice | No browser score, accuracy, source role or clock authority; aim coordinates belong to the physical release command in §1, outside the scoring input |
| Placement input choice | Tagged normalized workpiece coordinates `(u,v)` in `[0,1]²` or explicit neutral finish | Valid only against the exact native craft's guide and one unanswered choice; actual material evidence belongs to §4 |
| Evaluated input | Mode, finite score in `[-1,1]`, admitted profile pin and exact accepted command/receipt identity | Computed by the trusted evaluator once; action history may retain permitted evidence; this is neither hit verdict nor final item quality |
| Released attack / produced item | Only the pinned native contribution and source facts needed by its later physical owner | Flight survives source loss without rescoring; item use reads its own stamped facet without hydrating the maker's private history |

Authenticated account, current world/timeline/control generation and source route are server-bound at every request. They are not saved permission grants and cannot be selected by client enum fields. The saved action's identity/life and exact meaning can survive a legitimate reconnect; the new command must use current authority. Existing request receipts settle exact retries before new-action feasibility under the continuation contract. A different payload for an existing request or a second different choice for one action refuses without mutation.

A missing optional descriptor is supported absence. An invalid **present** definition, mismatched input kind, missing required field, nonfinite/out-of-range sample, stale physical life/action/pin or unrecognized claimed effect refuses at the owning boundary; do not silently downgrade corrupt state to ordinary or excellent. Read-only previews consume neither materials nor world randomness.

### 2.2 Deterministic evaluation and presentation

The timed-release evaluator accepts a phase and the admitted profile; it does not read rendering frames, a hidden opponent or current wall-clock time. The client advances phase from monotonic real elapsed time after the hold threshold. One full period traverses outward and back. For the selected triangle waveform, normalized white-ring radius is `r = 1 - abs(2 * phase - 1)`. For authored target center `c`, green half-width `g`, ordinary half-width `y` and maximum radial distance `D = max(c, 1-c)`, let `d = abs(r-c)`:

```text
if d <= g: score = 1 - d/g
else if d <= y: score = 0
else: score = -min(1, (d-y)/(D-y))
```

The installed profile must satisfy finite `0 < g < y`, `0 < c < 1`, `y <= min(c,1-c)` and `y < D`, with a positive finite period. This prevents empty bands and zero divisors, rather than validating incidental conventions. Use the same pure evaluator for permitted UI prediction and authoritative interpretation. A shared boundary scores exactly zero: project it as ordinary; positive is strong, zero ordinary and negative weak. Do not color a zero result as a promised improvement. The [base-world timing profile](../worlds/base/skilled-action-execution.md#concentric-release-interaction) owns exact initial values; the [limits](../limits/action-execution-and-skill-expression.md#ase-l02--ring-pace-and-visible-timing-bands) own their restrictiveness and tuning status.

An ordinary tap, explicit skip and NPC action without human input contribute exactly zero. An accessible skilled alternative may reach the same positive maximum through the same admitted family. It is an input route, not an automatic hidden reward or a lower item class. The precise controls are in §6; competitive acceptance is separately restricted in §5.

World-installed character/condition/weapon-familiarity contributions may alter the admitted bands or period. None is a mandatory engine Dexterity/Focus field. The initial base-world slice installs no new focus, intoxication or clothworking statistic. If a future installed contribution changes the active challenge's meaning, invalidate that sample and offer a fresh permitted preparation; do not keep displaying an old curve while secretly scoring a new one. Unrelated simulation ticks do not invalidate a profile. Physical handling/condition is evaluated by its normal native owner at the relevant preparation, release or contact boundary; changing the ring never changes native windup or recovery.

Browser phase, monotonic timestamps and coordinates remain **untrusted input claims**. Deterministic recalculation prevents fabricated score/stat fields; it does not prove human timing, actual pointer motion or freedom from automation. No server challenge database or trusted competitive clock is selected here.

For point placement, evaluate distance in the admitted workpiece's local frame, never pixels or device resolution. The same signed pattern uses the family's positive radius, ordinary radius and finite penalty-tail width. Exact guide construction and first-slice numbers have one owner in [fitted woven containers](../worlds/base/skilled-action-execution.md#the-chosen-noncombat-proof-fitted-woven-container). The workpiece does not share the combat ring's animation, target position or timing law merely because both produce a bounded scalar.

### 2.3 Family-owned contributions

Let `b` be the native baseline **after** the existing tool, character competence and applicable condition calculation; `s` the evaluated input; and `p,q` the exact family's excellent-improvement and poor-reduction coefficients. The common relative arithmetic is:

```text
factor(s) = 1 + p * max(s, 0) + q * min(s, 0)
result    = nativeChannelClamp(b * factor(s))
```

Definition admission requires finite nonnegative coefficients and a nonnegative resulting factor over the supported score range. The [base-world weapon table](../worlds/base/skilled-action-execution.md#weapon-specific-consequences-selected-initial-testing-profiles) selects its actual coefficients; these are initial balancing inputs, not measured fun or a universal 25% multiplier. A hypothetical 75% baseline with a 25% relative excellent coefficient becomes 93.75%, not 100% and not 100 percentage points. Apply existing sling competence once before this contribution, never once at aim and again at contact.

Contact quality affects only a legitimate physical opportunity under §3. It cannot create collision, make a body intangible, steer the ray, bypass shielding or add a second random miss after injury. A body with no feasible evasive clearance remains collidable even when source handling is poor. Injury scaling occurs before the existing defense/susceptibility/health-clamp owner, with actual inflicted quantity recorded after clamping. Do not round a probability as though it were whole-point health.

Only an actually supported native critical mechanic could consume a future critical channel; this slice creates none. A future charge or spell gesture needs a useful supported family, not speculative channels now. Manufacturing uses its own material-derived baseline and integer packing rule in §4; no generic engine item-quality scalar is introduced.

## 3. World physical contact and the evasion reconciliation

### 3.1 Replace trajectory deviation rather than layering new odds on it

Currently `releaseShot` uses `baseShotDirection(world, delta, targetRadius, steadiness)`, spending randomness at release to deviate a ray. **Selected change:** compute exactly one **aimed straight direction** from current authoritative launch anchor to the **captured release aim point**; never introduce a random angular deviation when that installed shot has manual cursor aiming. Ordinary taps in combat mode use the pointer's captured click point through that same ray law, not auto-lock to the target's center. NPCs use their **own actor-permitted selected aim point**/target evidence and competence-driven contact chance; never use fake timing score or privileged future target position. An off-ray target isn't contacted regardless of high accuracy. A visibly off-target player shot can strike an intervening object/participant according to the existing physical law.

**Important:** this is a deliberate replacement of the bundled release-error law, not a claim all other installed worlds must use it. Preserve any coherent alternate installed law through an explicit selected shot profile only if actually supported, without parallel copies or legacy adapters.

### 3.2 Resolve a body's opportunity to evade only at genuine geometric contact

A projectile's actual swept segment queries relevant **solid and body contact candidates**, in established stable earliest-contact order, using the existing spatial owner (including elevation, thickness/radius and moving intervals). **Only at a body's genuine contact candidate** may the selected world resolve ordinary competence/pose/local evasion, shield coverage and injury:
1. A solid cover contact has the world's real material/obstruction effect, not a character's evasion roll. Preserve first actual solid result.
2. A relevant bodily intercept first resolves the qualified world-authoritative local avoid/defense opportunity from its **actual native defender state** and the projectile's committed effective contact chance (including any trusted allowed manual modifier). Any evasion randomness comes from the saved world random sequence at this canonical contact, **not** a client roll, per-render-frame draw or after-the-fact UI message.
3. If the body evades, emit a real bounded **projectile-avoided-by-body** occurrence (time, position, exact physical life, attributed source and permitted observation). It represents a small lean/twist/duck with **no required navigation step**. The projectile continues its *same physical ray*, with the evading physical life excluded from recollision for that flight. It can still hit another body or actual wall behind. Do not label the traversed body 'physically hit then unharmed', mutate an actual position to fake a step, make it globally intangible or grant blanket invulnerability frames.
4. If evasion fails, offer actual shield/contact-defense to the existing impact owner, then armor/susceptibility and actual injury; no second random 'miss' after a committed injury. Absorbed injury is distinct from evasion. The first real physical contact that stops the projectile terminates its flight. For selected capable world rules, a shield may block the shot and prevent all injury without automatically counting as a dodge.
5. A moving animal that doesn't geometrically intersect receives **no evasion roll**; its movement caused a physical miss. A target outside vision/at an old location isn't supplied live coordinates; a lawful **point shot** can still follow an actually chosen aim point without refreshing the unseen subject. Actual unintended body candidates can be harmed only through normal selected world participation/collateral contact law (CTR01) and observer-sensitive evidence.
6. Capture each evasion/contact result **once per exact flight/body life**, including across coherent time slices, resends and save/reopen. Maintain canonical tie ordering for simultaneously intersecting candidates. At a dense line of people, cost grows only with real local candidates and is bounded by the existing native work budget; don't roll infinitely against the same avoided capsule. No spatial candidate is excluded before the exact query solely because the source didn't intend to hit it.

**One native contact probability, not two hit tests:** at the *release* boundary snapshot source/tool/ammunition/body/competence and a permitted finite human score, and capture the authored effects that cannot legitimately change in flight. At a genuine moving-body contact candidate, the actual body's native world contact policy contributes its current posture, awareness/ability (if disclosed to that calculation), bodily susceptibility and selected evasion rule. The selected first family computes `p = clamp01(sourceHandlingChance × releasedQualityFactor × currentContactContextFactor × (1 − currentBodyAvoidanceFraction))`. Here `sourceHandlingChance` is the currently applicable handling/competence value **calculated once at release**; `releasedQualityFactor` is one pinned native-derived optional input multiplier, neutral for actual human-controlled bodies under the first trust policy; `currentContactContextFactor` and `currentBodyAvoidanceFraction` are **world-owned** native terms, both neutral 1/0 when not installed. Use one saved native random draw only for that actual body's qualified opportunity and record the evaluated inputs, chosen result and exact contact occurrence in native history. Do not draw a second 'miss' after shield/body impact, alter flight direction or rerun source skills if the shooter later dies. The original bundled `rangedAccuracy` condition factor must migrate to the **actual relevant native contact**, not stay tied to a possibly unhit intended deer; qualify its existing meaning and other selected worlds before changing implementation.

For a physically stationary or unaware actor, `currentBodyAvoidanceFraction` need not imply a deliberate reflex; a failed contact can represent the coarse occupied capsule's available near-miss clearance under the world's law. A deliberately dodging animal/person needs actual qualifying awareness/capability and an event attribution that does not fabricate intent. A wholly restrained/unresponsive body may have a different selected avoidance policy, but never infer a volunteered dodge from a mere miss. As a projectile advances, process solid/body candidates in canonical earliest order: avoid a body → append that exact life to the flight's excluded set → resume searching the **unchanged ray** for the next eligible earliest candidate; actual shield/body/solid stop ends this finite first-contact projectile. Preserve world time fractions, stable tie-breaking, bounded candidate work and same-version saved avoided lives.

The result for the visual 'Miss' indicator is derived from this actual event and only emitted to characters who could see/experience it. A renderer can animate a slight local lean without asserting an unobserved position or changing the authoritative character anchor. A terminal flight can be an observed hit, shield stop, physical miss, evasion/multiple evasion, solid impact, range expiry or **unobserved/unknown**. Do not grant shooter omniscience from a high-quality timing score.

This design depends on selected **CTR01 actual-body collateral** and **CF02 shield** behavior; integrate those contracts first or as one coordinated owner change. Never add a target-only impact exception to make the new score easier to implement.

### 3.3 Melee contact and honest reach

A strike remains one targeted native attempt with pinned tool/profile and exact physical target life; the manual release controls native strike quality but does not force impact before actual work/windup, range, reach, current participation or accepted lethal review. The native strike/contact owner resolves any supported local evasion/guard and post-defense injury once; no new `damageOnPointerUp` path. For the first version, allow straightforward released strike toward the chosen observed target only if native reach/facing/collision rules admit it. A cursor indicator is not geometry authority.

Preserve the prior native `windupSeconds` and `recoverySeconds` within the same action. Hold progress while moving must be reconciled explicitly with the body's handling/movement claims. Human input release when no native ready strike exists **cannot skip windup**: a short tap means request an ordinary native one-shot strike; holding starts/maintains an ordinary windup; an early release means one visible committed **release request** within that same action which executes at earliest native readiness with the captured point, provided all live constraints still hold. No automatic extra shot or use of a newer target. Test how this feels rather than claiming 'instant' when world law requires preparation. A sufficiently long hold can release immediately when ready. A different installed world may choose shorter windup, not silently bypass authority.

If target becomes unavailable, incomplete preparation/cancellation uses existing no-material-cost rules; a committed contact/injury and recovery are irreversible. Player defence/guard actions have separate future gesture design; while attacking, present unavailable defence honestly.

## 4. Noncombat proof: quality-sensitive woven container

### 4.1 Actual existing owner and selected family

Use the admitted `base:woven-container` manufacture family and its existing individual output. The [camp-container family](../worlds/base/camp-containers.md) owns compatible materials, quantity bounds, binding, ordinary capacity, empty packing load and elapsed work. The [selected base-world fitting rules](../worlds/base/skilled-action-execution.md#the-chosen-noncombat-proof-fitted-woven-container) own the exact guide, scoring curve, factor bounds, integer rounding and initial tuning. Those constants are not generic engine defaults.

Only a method whose exact installed family/output definition advertises the supported `pouch-fit` finish may offer it. Include that support and its exact meaning in the existing mechanical definition/recipe pins. Names, free-text quality requests, a generic container field and the separately authored `woven_bag` definition do not grant support. Existing items cannot be upgraded by submitting a finishing input. The first family requires no tool, station or physical workbench; the on-screen workpiece is a view of the current craft.

Material investment continues to determine the ordinary usable pouch. Fitting changes the actual load that fits inside that individual movable kit. Actors currently have no finite total carrying-load limit, so this does not increase character carrying strength. Acceptance must compare a useful packed kit, an ordinary pouch, a fitted pouch and direct carrying without adding an encumbrance system to create demand.

### 4.2 Distinct manual interaction and numerical meaning

The player selects ordinary **Craft** or **Finish carefully** before starting the same native manufacturing attempt. Ordinary manufacture needs no input and completes at its existing work boundary. Careful manufacture accepts one committed placement on a visible seam/fastening fixture. It uses the shared local marker-position input owner and its pointer, touch and keyboard routes, without a combat timing ring, a reflex deadline or numeric coordinate entry. Both guide marks and the alignment instruction are visible. The interface does not paint the perfect answer or reveal a continuously updating score while the player positions the marker.

#### Selected initial placement profile

The [base-world fitting section](../worlds/base/skilled-action-execution.md#the-chosen-noncombat-proof-fitted-woven-container) defines the complete initial fixture and scoring law. Preparation derives that fixture from the exact admitted role quantities and pinned family meaning. Material names, identifiers, an arbitrary hash and undeclared textile properties cannot change it. Any future material-specific geometry needs a real admitted material property and an exact dependency pin.

The generic finishing boundary accepts a tagged manual/assisted local placement or explicit **Finish normally**. Validate finite coordinates within the profile's admitted local domain, then compute a finite score under the pinned profile. A neutral choice carries no coordinates. The client supplies neither a score, a fit factor nor a capacity. The two skilled input routes share the same scoring and attainable useful outcome; the ordinary choice remains a complete usable path. There is one accepted choice for the action, including across new request identifiers, rather than repeated opportunities to improve an item.

Let `B` be the exact output definition's ordinary capacity and `f` its admitted, creation-time fitting factor. An ordinary container without a fitted facet reads its pinned `B`; for an admitted fitted item the common reader derives `effectiveCapacity = round_profile(B × f)` using the output profile's selected positive-integer rule. It validates a finite supported factor and a positive safe-integer capacity. The fitting law is continuous; the native packing capacity remains an integer. A small positive score need not change that integer. The initial world therefore selects no categorical grade. Future worlds may derive a meaningful grade from supported properties or install a distinct discrete property, with its own native consumer; no universal quality tier is introduced.

### 4.3 One canonical per-item property, no silent stacking

`ItemLot` remains the physical item's canonical owner. Extend its existing individual record with one optional fitted-container facet: an exact supported output-profile pin and the final finite factor. A valid ordinary item may omit the facet; a malformed present facet must never become an ordinary item by fallback. The output definition explicitly admits the facet and pins its meaning. Its factor is frozen when that item is created and is not recomputed from a later maker's skill, owner, recipient or mode of play.

The actual manufacture/action record retains accepted input, evaluated score, mode, exact consumed-input evidence and the produced-item link. Do not require old private action history to calculate an item's current capacity, or duplicate its factor in a second quality authority. Keep ordinary recipe facts separate from actual instance facts. The definition continues to describe the ordinary recipe output; inspecting either of two same-definition pouches must show that particular pouch's capacity.

All capacity consumers use one exact-item accessor, including the following existing owners:

| Existing owner | Required use |
| --- | --- |
| `packages/domain/src/objects.ts` | Movement/ancestor deltas, quantity plans, joint reciprocal moves and current-format containment validation use each actual container's effective capacity. |
| `packages/domain/src/inventory-inspection.ts` | Authorized inspection and resident facts use the inspected item's effective capacity. |
| `apps/server/src/inventory-view.ts` | Item detail, comparison, contents pages, storage candidates and transfer destinations use the same value within their existing disclosure scopes. |
| `packages/domain/src/item-characteristics.ts` | Add exact-instance facts without allowing the invented-item `recipe.facts` shortcut to replace effective capacity with the recipe baseline. |
| `packages/domain/src/handover.ts` and `apps/server/src/handover-actions.ts` | Disclosed terms snapshot that offered item's public capacity; actual transfer still validates current identity, revisions, access and feasibility. |

Do not mutate `ItemDefinition.container.capacity` globally, generate a definition/recipe for each achieved factor or recompile the recipe for every listed item. Reuse validated immutable definition meaning. Live definition changes cannot remove or reinterpret fitting support while dependent objects exist; existing exact current-world admission owns that refusal. Same-version saves retain the facet and validate its dependency pins before checking contents. Invalid support, non-finite/out-of-range values and contents exceeding effective capacity reject explicitly, without legacy coercion.

Containers remain individual, quantity-one objects. Split, merge, source-credit and inventory-grouping paths must preserve that invariant, including for malformed loaded data. The existing `lotCarriesState` guard must recognize an admitted retained facet rather than silently treating it as stateless. Extending quality to homogeneous materials is outside this slice and would require a separately admitted equality/lineage rule; a better unit cannot confer its quality on a merged ordinary stack.

Fitting changes no empty packing load, quantity, nesting-depth rule or contained item's identity. A moved subtree still contributes its own packing load plus the actual load of all contents to each enclosing container. Unknown load remains unknown. A roomy inner pouch cannot conceal its contents' load from an outer pouch. Joint moves compute shared ancestors' final net deltas once; a refusal is atomic and leaves both objects and their contents intact. Moving a whole container never rewrites its children's identities or local placements. The selected world's worked nested-pouch example is an acceptance fixture, not a second packing law.

### 4.4 Work timing and outputs

Reuse one admitted recipe, one current physical action and the existing manufacture completion writer. Input preparation and acceptance do not produce an item or bypass work. Capture exact input evidence from the successful resource operation **before the existing material debit at work start**: declared role, actual contributing item identity, exact definition/unit pins, pre-debit revision and actual consumed quantity. These are historical facts, not new reservations or a requirement to find those lots again at completion. Bound the snapshot by the recipe's required input-unit total, with entries only for positively consumed lots. If one definition fills both roles, retain the existing single aggregate debit and assign its selected units to declared role order deterministically; never debit it twice.

Retain only the family-specific finishing binding needed on that action: selected mode, existing action/actor-life and exact recipe/profile identities, consumed-input evidence, and at most one accepted tagged choice with its evaluated result and receipt identity. The fixture is derived from those pinned inputs. If its finite marks are retained for continuation, validate their equality with that derivation. There is no detached, transferable unfinished object or second attempt registry. Current authenticated control/session generation is checked on each command; a saved action does not grant a new session the old session's authority.

| Native work and input | Required behavior |
| --- | --- |
| Work remains; no choice accepted | Continue native work and permit one skilled input or neutral choice. |
| Work remains; one choice accepted | Continue work; an exact retry returns its acknowledgement and a different choice cannot replace it. |
| Work reaches zero; no choice accepted | Keep this one action at **Ready to finish**, with the actor's existing physical-work claim, no output and no repeated work/timer polling. |
| Work reaches zero with a choice, or a choice is accepted while ready | Atomically validate continuation, compute final fit, create/stamp one individual output, record actual output/evidence, end the action and release its claim. |
| Cancel, accepted replacement or another genuine native interruption before output | End with the actual cause and ordinary costs: already consumed materials remain spent and no pouch is produced. Later input cannot revive it. |

Terminal resolution belongs to existing receipts/history; do not retain a live `resolved` action. If implementation adds explicit phase tags, current-format validation must enforce their consistency with remaining work and accepted input. The waiting branch must not remain a recurring zero-deadline completion candidate or enter coarse-work/AI polling. The finishing command wakes its legal completion directly. Existing kernel progress/completion, temporal-boundary and action-scheduling owners must all recognize the same waiting condition.

Before starting, display the actual ingredient debit and explain that stopping after work begins leaves those materials spent. Final validation checks current actor/life/control, the continuing action, exact supported recipe/output/profile meaning and existing native permissions. It does **not** recheck availability of inputs already consumed or charge a second set. A dependency change before start refuses without debit; an invalidated craft after debit ends with its truthful already-spent-material outcome. The initial family adds no tool/station claims. Injury, life loss, movement or another replacement interrupts only when the existing native work policy says it does. Under existing pause rules, new finishing/material completion is unavailable while paused and the actor's own Cancel remains available.

Same-version save/reopen preserves the exact working or Ready to finish action, including an accepted choice, **when native work has not actually been interrupted**. Restored pending-presence protection remains the save/participation owner's existing rule. A normal transport reconnection reads the current action and offers only its legal next choice. Genuine departure or another native interruption ends the action; later reconnection cannot restore spent inputs or manufacture the missing pouch. Lost acknowledgements recover the original receipt before treating the request as new work, under current disclosure authority. Finishing, cancellation and replacement races serialize at the same native authority so they cannot duplicate output or apply quality twice.

### 4.5 Inspection, trade and authentic native competence

Authorized inspection may expose the supported public effective capacity without revealing contained load, remaining space or nested items. Those require their existing deliberate container access/inspection route. Offer parties receive a bounded historical snapshot of public capacity when terms are disclosed, allowing both people and residents to assess the item. Remembered trade facts do not query unseen live stock. Acceptance still rechecks the exact item, definition, item/placement/contents revisions, source, access and final transfer feasibility. Quality disclosure does not grant a recipe, private maker identity/competence or the unobserved placement and score. Existing provenance is disclosed only where its current owner permits it.

Custody, drop, death-drop, containment and trade preserve the same item and factor. The selected noncompetitive safeguard permits fitted goods to retain their useful quality in ordinary shared play. Server recomputation and finite bounds prevent a caller from declaring arbitrary capacity; they do not certify a human pointer trace or prevent a modified client from selecting an ideal coordinate. This is a selected first-slice trust policy, not a completed competitive fairness solution. A ranked production mode enabled without a separately qualified policy uses neutral creation; it does not downgrade an existing item on transfer.

The starting bundled world has no installed clothworking competence modifier, so residents make useful ordinary pouches with neutral fit through normal manufacture. Do not synthesize pointer events, unconditional perfect results or a second NPC craft executor. A later genuinely installed native craftsmanship rule may affect a resident's and a human actor's ordinary result through this same creation-time item owner. Normal craft, careful craft and that future native contribution remain one conserved recipe/output family.

## 5. Authority, privacy, multiplayer and lifecycle

**Two trusts must remain distinct.** The source of the *attempt's performance claim* can be the local client; the source of physical permission, target, action, resources, damage/quality law and world state is the server/domain. Exact input cannot request its own effect modifiers, temporary immunity, hit verdict, raw world entity position, tool profile or inventory result. Read-only previews spend nothing and cannot establish a later admission promise.

Until separately approved competitive PvP input verification exists, treat **manual execution bonus as neutral when the actual contacted body is human-controlled** (including an unintended player hit by a shot nominally aimed at wildlife). Carry a bounded release score for permitted NPC/animal resolution but **select the actual defender at contact**, preventing a user from laundering a bonus through a different displayed target. Source/flight identity, contact time, effects, damage and privacy remain server authoritative. Ordinary lawful PvP attacks still run under current world policy.

For the selected **noncompetitive craft**, admit user placement coordinates as an intention only; the server binds the exact workpiece guide and recomputes fit, never accepts an item stat/score from the client. **Allow the produced quality-bearing item to be traded or given to another person without degrading it**: its real material cost, lawful method, single output and finite fit bounds are enforced by native work, not by trust in perfect input. This route is not cheating-proof against a client that submits an ideal position, but it creates no free material and is a deliberate low-stakes shared-world choice. A separately designated high-stakes ranked competitive production mode must either use normal neutral output at creation or obtain its own approved fairness contract; no later owner transfer may retroactively change quality.

For future PvP, unresolved: whether a server-chosen timing seed and absolute server receipts, a latency-compensated challenge, server-owned sampled input, alternate command validation, or an explicit competitive disabled mode can provide satisfactory fairness. The technical solution must account for jitter, browser process suspension, replay, time skew, latency classes, accessibility parity and modified clients. **This project records the decision as deferred rather than assuming that clamping a browser number solves it.** A future owner must approve a specific trust model before lifting this safe gate.

Source/client/actor identity, physical life, authored profile pin, action ID and attempt revision survive server waiting, save/load and receipt recovery through existing owners. The client may lose its animation state on tab close; a prepared native shot/unfinished craft still has exact state and a reachable native Cancel/Resume/Finish option after reconnection, without duplicating a release. Do not persist browser animation frames or trust restored local elapsed phase as an authoritative retroactive score. Restore unfinished work's exact skill profile/captured committed performance when it is already accepted, using current-format validation. Effects already released continue according to their physical owner after injury, departure or death; the source never acquires fresh knowledge from historical attribution.

## 6. Device/UI and accessibility integration

`scene.ts` owns world input precedence; reuse `world-interaction.md` and the actual design-system. Required scopes: active modal/child popup, text editing and IME, camera drag/pan, placement/building mode, tool/target picker, combat mode, selected gesture and ordinary world actions. Consuming Escape cancels exactly one topmost scope. Track pointer identity, down/up/cancel and tab/connection epoch; dragging to aim must not be mistaken for camera drag, and existing construction/selection must not fire on a canceled gesture. Control-click on macOS remains secondary. World clicks outside attack mode retain selecting/walking, and secondary menus always remain intentionally accessible.

The overlay tracks the release pointer independent of layout scale, camera pan/orbit, changes in rendered entity position and browser pixel ratio, with color-independent band boundaries, readable relative-size adjustments and minimal feedback. The player's body cancel target is a deliberately visible **screen-space projection** of actual own public body, not the hidden entity's entire hitbox; keyboard Escape and the Cancel control remain usable at every viewport/zoom. No effect/grade text is composed in a renderer; take selected labels from the world/action's permitted descriptions.

WASD ignores focused editor/text inputs, modal scopes and default browser shortcuts. Key repeat does not create movement impulses or mode toggles; held directional intent is monotonic and stops on keyup, blur, loss of control or cancellation. Support keyboard-select/release aiming alternative and an accessible skip/assist route; accessible assistance keeps the same native baseline and does not reveal unseen targets. One input mode at a time, without separate tool-specific gesture listeners scattered through components.

Actual user scenarios must include low/high FPS, monitor scaling, zoom/floor selection, sprite near an upper level, fast cursor tracking, pointer leave, permission refusal, world pause, simultaneous WASD+release, network delay, stale response, NPC attacks while a modal is open and switch between player and other controlling tab.

## 7. Performance, cadence, and bounded work

**Growth:** local frame drawing is O(1) per active gesture, never O(number of entities); native body-contact candidate work grows with local collider density and released flights (existing spatial index/work budget); available-action preparation grows with applicable tools/methods and targets only at an actual request; item quality resolution is O(1) per owned exact item; no world-wide scan per tick. **Sharing:** immutable installed profiles/geometry descriptors reused within their stable definition pins; current permitted target/tool preparations reused only in the owning current unchanged read. **Invalidation:** actor life/control, body/condition/competence, equipment and profile pins, current visibility/geometry, actionable work, time deadline and held gesture/receipt epoch. **Measurement:** sample browser input-to-cue and release-to-request latency, end-to-end release-to-observed flight, physics during pending model jobs, projectile first-contact candidate count, ordinary versus skilled manufacturing and projected item capacity under the same device/world/clock, including sparse and concentrated cases.

Do not send 60 network writes/second for pointer tracking or WASD if an interval- or change-based intent channel with a bounded renewal can carry the same actual movement. Retain the current single-writer authoritative transition and existing 50-ms publication only where it is actually appropriate; client graphics smoothness is separate. A client drag sampling interval does not spend simulation time. Bound native continuation by actual meaningful contact/work deadlines and the existing work budget; if full collision preparation cannot complete, preserve a truthful unfinished/technical state rather than simulating no contact.

**Required critical cases:** release exactly once across duplicate HTTP/receipt replay; evade/body/solid ties with canonical ordering; multiple bodies along one ray; moving bodies across sparse interval boundaries; shooter gone after release; 500 simultaneous active but unrelated characters without global per-frame rescoring; many registered irrelevant tools with one selected action; current-format restore of held aim and selected craft; reduced-motion/manual/assisted parity; fast time acceleration does not create 8× browser callbacks.

## Open decisions, dependencies and current-format constraints

The chosen first slice intentionally makes **no promise of competitive browser timing trust**, general hitbox animation, genuine fluid/wind ballistics, universal crafted durability or already installed Dexterity/Focus.
