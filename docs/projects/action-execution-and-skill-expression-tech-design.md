## Behavior-to-implementation contract

Deliver the [ND38 player feature](action-execution-and-skill-expression-feature-spec.md) through **ordinary admitted actions**, not a second minigame result engine. A human chooses a permitted action; its physical preparation remains native; an optional input exercise yields bounded **action-specific execution evidence**; one trusted family derives any permissible effect; the actual world owner commits the effect, receipt and disclosure. A resident chooses through its ordinary controller and executes through the same physical owner using character competence, not simulated cursor input.

The first complete connected demonstration is (a) quick versus optional timed ranged/melee attacks while walking, observing and tracking real animals/opponents, and (b) optional **point-placement fit** during real woven-container manufacture, yielding an item-specific effective storage capacity. The first pouch has no categorical grade; optional meaningful grades remain supported for later families. Include no general scripting interpreter, second combat solver, second item-quality store, nominal 'equipment quality' modifier ignored by use, universal stats, or per-frame model call.

[Existing engine/world boundary](../engine-and-world-boundaries.md#5-a-repeatable-boundary-decision) remains controlling: stable identities, authorization, resource accounting, ordered native effects, safe observation, restoration and data-driven admitted definitions are reusable; the selected game's weapons, skills, injury/evasion law, ring tuning, material fit, item facet, names, and quality grades are **replaceable world policy**. Other coherent worlds can omit any mechanism. A supported family may be compiled native code without becoming universally installed.

### Engine-owned versus world-owned computations

**Engine/reusable finite services:** pointer-gesture lifecycle, device-neutral normalized input coordinates/phase, frame-independent ring renderer, score calculation under an admitted fixed numeric curve, bound/finite action preparation, exact invocation identity, authoritative transition/receipt, immutable/pinned action evidence, object-property accessor, and observer-scoped projection.

**World-owned authored decisions:** which installed action permits timed release or precision placement; visible ring bands, tempo/skill influences; which body condition affects timing; which combat outcomes a release changes; actual weapon recovery, projectile/strike laws, evasive response; which recipe admits finishing, which supported item facet it affects, percent bounds, grade text and criteria. An invented item, label or arbitrary world data cannot register a new property-mutating callback, executable formula or security grant.

## 1. Player input and shared attempt lifecycle

### 1.1 One native preparation, one release, exact recovery

**Selected implementation target; not current runtime behavior.** The client owns only `idle → candidate-tap → manual-hold → submitted/cancelled` presentation. `ActorComponent.action` remains the sole primary physical work owner. A pointer gesture, movement lease or local ring is not another Action, physical plan, resource reservation or position writer.

In attack mode, valid primary pointer-down immediately requests **one beginning of the exact chosen native attack**, capturing the displayed action/definition, tool, ammunition choice, initial permitted intended subject or point, and current input scope. Native preparation, reservation, windup, interruption and later recovery remain with the existing ranged/strike owner. A hold changes how that same preparation will be released; it never starts a second attack. Unavailable sources remain visibly unavailable, with no silent substitution of another weapon, ammunition lot, Speak, Move or target-bound method. A melee hold introduces a release-ready state in the existing strike progression: reaching the windup deadline while still holding does not automatically impact. Ordinary explicit menu/NPC strike routes retain their own native approach and one-shot progression.

A valid absent optional descriptor retains the ordinary route. For the first bundled **knife and Punch**, which have no held-execution profile, pointer-down captures only the exact ordinary choice; pointer-up invokes that one ordinary native action after any required review. Holding does not start a timed/held-ready strike, and cleanup never invokes it. These actions keep their existing native work and menu/NPC behavior; a long hold neither repeats nor grants a bonus. The explicit ordinary Attack button remains available. An invalid present descriptor is a refusal, not this absence path.

**A Begin that requires lethal review admits no preparation before confirmation.** The existing review owner first prepares the exact proposed attack read-only; it creates no action, ammunition reservation, equipment change, cost, recovery or random outcome. Receiving that review finishes the old pointer gesture and discards any queued pointer-up release, held keys and ring phase. Present the world-authored confirmation as **Prepare attack**. Explicit confirmation admits only the reviewed native preparation under current authority and returns its action ID/profile; it never interprets the old button-up as Release. The admitted confirmation starts a fresh local hold-toggle session when its profile is displayed, with a new phase origin and the selected presentation, rather than inheriting old pointer elapsed time. Continue through the visible Release/Attack normally/Cancel controls or a fresh eligible deliberate input. Confirmation cannot resume held WASD, start an animation from an abandoned clock or fire automatically because windup is already ready.

Classify a pointer-up by monotonic elapsed time from its down event. A release below the [world-owned hold threshold](../worlds/base/skilled-action-execution.md#concentric-release-interaction) is ordinary score zero. Crossing that threshold allows the optional ring only after the exact admitted input profile has actually arrived. Start its phase origin once at the later of those two boundaries. Before admission, show local pending feedback without a usable green promise. A release before the admitted profile was displayed is ordinary, even when network delay exceeded the threshold; it is never scored against an unseen phase. After display, use one fixed admitted profile for the attempt. Rendering stalls cannot turn a long hold into a tap merely because a timeout callback ran late.

The ring uses monotonic **real elapsed time**, independent of date changes, graphics frames, world simulation speed, server publication and provider jobs. Phase is computed from the admitted period; frame updates draw locally. Send no recurring pointer/phase samples or paid-model work. The real-time input lease below renews control availability, not a score. Native movement, windup, recovery, resources and impacts use the selected world's simulation clock. Neither stepping the ring nor waiting for a release pauses the world.

Pointer-up captures **one immutable release intention**: final physical point where applicable, ordinary/timed input, displayed phase and manual/assisted provenance. If begin has not returned an action ID, retain that intention locally only while the same live gesture remains authorized. If native preparation is not ready, the admitted action retains one pending release record; its receipt says **release requested**, not **released**. The native ready boundary can consume it once while its current foreground input authorization remains valid. Do not recalculate timing, update the point from a later target, spend ammunition at request acceptance, queue another attack or fire repeatedly during a long hold.

At actual release, validate current actor/tool/method, relevant installed pins, readiness, body recovery, actual geometry, retained intended subject and release-review dependencies. Use the then-current native launch anchor and the frozen endpoint. A genuine accepted melee reach miss consumes native recovery under the strike owner; a refusal before an attempt commits does not. Ranged post-release handling uses the selected new native body recovery deadline described in §3; ring period never substitutes for weapon recovery.

Cancellation names only this gesture and its unfinished admitted action. Mode Off, deliberate self-region entry, Escape/Cancel, pointer cancellation, lost capture, tab blur, unrelated modal entry, pause, connection/control/life loss or rejected capability clear local held input and disarm future automatic release; cleanup never sends Release. Cancel before begin acknowledgement establishes a terminal marker for that exact begin, so a late begin cannot prepare an unwanted action. **The sole modal exception is this attempt's own exact lethal-review dialog:** it preserves only the existing review's frozen uncommitted choice and, for release review, its already admitted native preparation. It suspends movement and automatic release, not the world, and grants no continuing pointer/keyboard authority. User Decline, Escape or close drops that review and cancels only its matching unfinished preparation; closing never submits the choice. An already released projectile/committed strike remains real. If release won at the server before cancellation arrived, report the actual released result rather than claiming cancellation.

Native preparation can remain inspectable only where ordinary participation/interruption permits it. Reconnect, reload or Resume restores explicit native **Release/Cancel**, never held keys, a local phase or an armed automatic release. A saved pending-release record retains its exact evidence as needed for the receipt/history owner but restores **unarmed**. Deliberate recovered Release uses the current visible point and a fresh neutral release request against the exact surviving action, after resolving any uncertain original release receipt. Craft's retained ready-to-finish work follows its own §4 lifecycle; transient mouse cancellation does not invent an automatic ordinary/excellent completion.

### 1.2 Finite request, receipt and input-order contract

Keep the existing authenticated `/api/command` envelope, `commandId`, `commandEpoch`, `X-OL-Client`/`X-OL-Scope`, `WorldService.command`, command binding, native transition and durable `commandReceipt` recovery. Extend the current protocol declarations, `commandInputSchema`, `bindCommand`, catalogue descriptors, `command-request.ts` and `ui/aim-controls.tsx` together. Do not introduce a second attack executor or persisted gesture database. `ApiResult.actionId` is already the native action identity; it is distinct from the request's command ID and catalogue option ID.

The following are **selected fields for this narrow integration**, not descriptions of existing wire support. Use existing validated reference/pin types when implementing them; never expose raw actor life or accept an actor ID as authority.

```ts
type AttackGestureIdentity = {
  inputEpoch: string;
  gestureSequence: number; // positive safe integer, increasing per current controller
  beginCommandId: string; // original /api/command identity, never regenerated on retry
};
type AttackReleaseInput =
  | { kind: 'ordinary' }
  | { kind: 'timed-release'; phase: number; mode: 'manual' | 'assisted' };
type AttackExecutionControl =
  | {
      operation: 'begin';
      inputEpoch: string;
      gestureSequence: number;
      presentation: 'animated' | 'step';
    }
  | ({ operation: 'release'; actionId: string; input: AttackReleaseInput } & AttackGestureIdentity)
  | { operation: 'confirm-review'; inputEpoch: string; gestureSequence: number }
  | ({ operation: 'cancel'; expectedActionId?: string } & AttackGestureIdentity);
```

The existing top-level `lethalReviewId` identifies the one actor-scoped review. The command repeats its required native attack fields unchanged; `confirm-review` supplies fresh operational authority and no new release sample. The server obtains the frozen input/profile and original execution stage from this exact review record, requires every repeated point/source/action field to match, and reconstructs the reviewed semantic choice for validation. Unknown or conflicting gameplay fields refuse; omission of a new sample cannot choose ordinary or rescore the old one. The existing review binds whether it is **begin preparation** or **release existing preparation**, its original begin command identity, and any exact native action reference. A confirmation cannot choose its own stage or another action. A fresh strictly greater gesture sequence identifies this deliberate continuation; the server binds the original begin identity and returned/current native action to that sequence. Its outer command ID is a new explicit confirmation request, retained unchanged for retries. A confirmed initial Begin creates one preparation only. A confirmed release can commit once if ready or arm one pending release under the new current lease. Ordinary release/cancel identity checks are not weakened for commands without this exact current review.

`execution` is accepted only on the supported native attack begin/release/scoped-cancel command forms. It cannot register a new action or arbitrary effect. The current `aim` and `strike` bindings gain deliberate held preparation when `execution.operation` is `begin`; absent that payload, their existing ordinary routes keep their meaning. `release-shot` continues to name its native aim through `aimId`. Add the finite native `release-strike` variant with `expectedActionId` for the held-melee ready state; it uses the existing strike impact owner, not the ranged executor. Update native types/binders/support classification alongside that state. Require `execution.actionId` to match `aimId` or `expectedActionId`, respectively; the duplicate spelling cannot select two different actions.

At most **one bounded current attack-gesture slot** belongs to a live controller. It stores the highest accepted gesture sequence, original begin command identity, bound action ID and phase: `open`, `release-requested`, `cancelled`, `released` or `ended`. It coordinates input only; action state, ammunition and effects stay native. A matching cancellation is terminal even if it arrives before begin or confirmation. Lower sequences cannot revive work; a higher deliberate begin cannot silently replace an unresolved gesture or unrelated work. A reviewed continuation can attach a fresh sequence to the same exact native preparation only through its existing review record. Native release marks the slot `released`; refusal, cancellation or other terminal work marks it `ended`/`cancelled` with the actual cause. Retain the sequence watermark while permitting the next deliberate gesture; a finished action cannot leave an unresolved slot blocking subsequent input. Duplicate command lookup precedes fresh eligibility checks; conflicting content under one command ID refuses. Late HTTP results update neither abandoned gestures nor another actor's UI.

The existing `commandEpoch` is a retained retry epoch, not a transient restart fence. Publish an opaque `inputEpoch` from the existing server `generation` plus current world/timeline/control/life authority. Reissue it whenever pause/suspension, load/restart, handoff, detected loss or expired active-input authorization would otherwise allow pre-boundary movement or pending release to resume. Durable command receipts keep their own recovery scope. A current epoch does not attest human timing or mouse input.

### 1.3 Movement alongside preparation and the live input lease

WASD supplies a normalized **camera-relative ground-plane direction**, transformed to finite world `(x,z)` intent. It carries no client position, speed, distance travelled or elapsed simulation time. The existing body/support movement owner consumes finite steering segments while idle or while the selected ranged/melee preparation or committed weapon recovery explicitly permits steering. Movement remains available after release; a recovering strike still owns its same Action/deadline while the shared movement owner consumes steering. Recovery blocks incompatible new combat work, not ordinary legal retreat. It uses the existing `moveAlongPath`/`setSpatialPosition` and support-walk transition owners; collision, floors and elevation remain native. `ActorComponent.action` is still the sole physical work slot. Guard, craft, another weapon preparation and unrelated manual work remain incompatible. An ordinary move/evade/menu action uses ordinary replacement admission. Unsupported bodies/tools expose refusal, not generic parallel work.

Use a narrow authenticated input-control update within the existing WorldService control/presence owner, not a durable gameplay Action or receipt for each heartbeat. Direction changes/stop and renewal are separate finite messages; all are scoped by current `inputEpoch` and controller authority:

```ts
type WorldInputUpdate =
  | {
      kind: 'steer';
      inputEpoch: string;
      movementSequence: number;
      direction: { x: number; z: number };
    }
  | {
      kind: 'renew';
      inputEpoch: string;
      renewalSequence: number;
      movementSequence?: number;
      pendingRelease?: { gestureSequence: number; beginCommandId: string; actionId: string };
    };
```

Movement and renewal sequences are positive safe integers with independent server high-water marks in the current input epoch. Direction is a finite normalized vector or exact zero for Stop. **Only a strictly higher movement sequence can change steering, and only a strictly higher renewal sequence can extend expiry.** Older/equal packets are ignored/refused without extending either lease, including otherwise identical replays. A renewal must also name the currently accepted nonzero movement sequence and/or exact still-armed pending release; it cannot recreate stopped movement or expired/cancelled work. Reset these operational counters only with a newly issued input epoch, whose old packets are refused. Attack sequencing is independent: a newer WASD packet cannot drop a release, and a release cannot revive stale movement. Acknowledgements report the current epoch and accepted sequence, not a fabricated gameplay receipt.

The [world input table](../worlds/base/skilled-action-execution.md#concentric-release-interaction) owns initial renewal/expiry values. Renew only while movement is held or a still-authorized early release is pending, with **100 real milliseconds** as the initial renewal target and **250 real milliseconds** as the server expiry. These are unqualified test defaults, not measured latency claims. The existing five-second general presence heartbeat remains a separate service; it cannot serve this deadline. An unchanged valid renewal extends only the operational lease and avoids full world preparation. No aim positions, ring samples or native resources are rewritten on renewal.

On a direction-change or expiry boundary, finish the already admitted simulation segment under the previous direction, then apply the new direction or stop. Coalesce unsimulated redundant updates to the latest valid intent without dropping already committed movement. Camera-relative direction changes caused by orbit are sent at the bounded input cadence, with immediate Stop; orbit frames do not each create a gameplay command. Integrate boundaries once through the shared native interval owner, never by advancing the entire world per input packet. Capture actual piecewise body tracks for `projectileBoundary`/`advanceProjectiles` candidate bounds and swept contact, including compatible steering; the current approach-only prediction cannot silently treat a steering body as stationary. There is no queue of repeated move-to destinations and no client collision bypass.

Server monotonic expiry is operational state outside saved domain time. Pausing or invalidating input first disarms leases/automatic release before further world continuation. Under the existing manual-pause exception, exact cancellation remains possible; new movement/begin/release is unavailable until Play and fresh input. The browser clears held keys on blur, blocked UI/modifiers, pause and control loss and does not reconstruct them on reconnect or modifier release. A network partition has no instantaneous remote cancellation guarantee: the finite lease bounds unobserved input, and any already committed effect is reported honestly.

For melee, the human must move into actual reach; green never auto-approaches or grants a point-only hit. Existing NPC and explicit-menu navigation remain intact. For ranged, valid steering changes the eventual launch anchor without moving the frozen endpoint. Derive actual facing from the admitted action under supported body rules, not camera orbit; ND38 does not need a universal turn-speed mechanic.

### 1.4 Attack mode and qualified personal notices

Attack mode is visible local player-control state, not native hostility, permission, knowledge or a second engagement list. Selected defaults are unmodified WASD, exact **Shift+T** toggle, plain **T** equipped target, **Shift+W** world-agent panel, and retained **Shift+A/Shift+S** Act/Speak. Exact modifier dispatch resolves the current W and Shift+T collisions. Narrow remapping belongs to the current settings/input owner; completing all ND13 remapping is not a prerequisite. A new controlled character/tab starts neutral. The combat pair table still chooses Command-click's preferred Speak/Attack; explicit secondary/contextual actions keep their semantics.

Auto-entry consumes a typed controlled-player notice produced by existing native offense/personal-observation evidence, not a client guess from event text. Add a compact `GameView.player.attackModeNotice` containing `noticeSequence`, `occurrenceId`, `occurredAt` (simulation time), and `kind: 'own-offensive-action-admitted' | 'personally-experienced-assault'`; optional source reference/label must already be permitted by that evidence. Bind it to current input scope and carry it through the public patch producer and `applyGamePatch`. Generic conflict categories, HP changes, testimony, environmental harm, proximity and hidden intentions are insufficient. No world-wide hidden attacker search is needed.

The initial view consumes the current sequence without entering; fresh later qualifying evidence enters once. Manual Off consumes the latest notice and cancels the matching gesture. Repeated publication, reconnect, old events and retained threat grace do not re-enter. A fresh assault can update mode while a modal is open, but cannot close it, steal focus, start an attack or turn a dismissal into a shot. An unidentified personally experienced assault can qualify without revealing its source. Store no private threat fact merely to explain the toggle.

### 1.5 Physical pointer aim, consequence review and cancellation

Extend the plain-data `WorldRenderer` boundary with a separate aim picker. Current entity/card selection and support-only `groundPoint` are not physical aim-point selection. The camera intersects permitted displayed body/scenery/surface geometry and returns a finite XYZ point plus its basis: supported surface with exact support/shape reference, or observed body/point with any already permitted opaque `bodyReference`. Preserve actual elevation and the point under the pointer, not a selected entity center. A body-height aim is not a navigation `SurfacePoint`. Sky/background or ambiguous unseen floor gives no point and an unavailable marker; never use y=0 or stale hidden coordinates.

The server checks finite bounds, installed range/source law, actual launch geometry and claimed permitted references/support meaning. It cannot prove a physical mouse was there, and ND38 does not introduce viewport certification. Do not require unobstructed weapon-to-target line of sight merely because the visible/read-through aim is behind cover: a valid shot can hit intervening cover. Current rendering selection privileges never remove solid collision. Freeze the final world point at release request and use the actual current native anchor when release commits. Never update that point from a moving or newly unseen subject.

The selected base-world ranged family permits point fire even without a creature selected. Retain a recognized pointer-down subject as original intention and historical attribution, separate from the final directional point. A point-directed animal shot may remain valid after the animal disappears if the point/direction itself remains admissible; do not convert other target-bound methods into point fire. Melee always requires its eligible observed subject.

**Review both the original intended human and a newly recognized human indicated by the final release ray.** The current owner is `WorldService.evaluateCommand`, which stores one pending lethal review per controlled actor and binds its exact input digest, scope, expiry, native command and permission. Extend that owner and `lethalAttackOffer`; do not introduce a parallel approval store. Register the ND38 `aim`/`strike` held-Begin forms that require review, and the new native `release-strike`, alongside existing review-eligible release/attack paths. Native read-only admission and actual execution must agree on those forms.

Query only observer-permitted recognized local bodies against the finite submitted native ray. Omitted browser target IDs and ground-down/person-up input cannot bypass review. Preserve the initial intended person separately; the frozen point controls direction, not homing. Check current meaningful source/subject/permission dependencies both when preparing review and when confirming/actually releasing. A new indicated person, changed point/source/tool, replaced action/life or changed relevant pin requires a new exact review; it never inherits permission from a similar label. Use the actual launch anchor at commitment, including movement before the review stopped steering. If native readiness later changes the indicated recognized person or another reviewed dependency, disarm the pending release and require fresh exact review before any effect. Preview never discovers hidden collateral. The world-authored point-fire warning and CTR's released-contact law govern later physical interceptors without retracting an already committed flight.

**Separate reviewed meaning from current operational authority.** Today's `evaluateCommand` digest includes all input except `lethalReviewId`; ND38 must define a closed semantic projection for these exact attack forms rather than hash the reissued input epoch as part of the attack. Its digest retains native operation/stage, exact source and action references, original intended subject/recognized release subject, frozen endpoint, admitted profile and release sample/provenance, and every consequential gameplay field. Only transport/request identity and the input epoch/gesture-order envelope are outside that semantic digest. Their own command-receipt fingerprint still includes the complete submitted request, so changing those values cannot mutate an existing receipt. Reconstruct the exact choice from the review plus the validated unchanged native request fields, then recompute and compare its semantic digest on confirmation; never drop unknown gameplay fields or use an arbitrary client-supplied digest.

The review's separate authority binding retains principal/controller, world/timeline, actor/life, server generation, native action/pins and its current expiry. **Rotating only the narrow input epoch for this review's own modal does not renew or replace that binding.** Pause, blur, another modal taking ownership, disconnection, actor/control/life/world change, load/restart, relevant native interruption, expiry or explicit cancellation invalidates the review and its frozen choice. It is not saved, cannot survive another control session and cannot grant permission to a recovered action. A duplicate receipt may describe an earlier review; it cannot resurrect the expired record.

Establish the review and disarm movement/automatic release in the same accepted server boundary before publishing its modal. For a **release review**, pointer-up's endpoint and sample become one uncommitted frozen choice in that existing review. The already admitted preparation may progress to its native ready state while the dialog is open, but no automatic release is armed. Its reservation/cost remains whatever the native preparation already owned; opening review adds none. Keep that choice only while its own review modal and original review authority remain valid. Display the world-authored action as **Release attack**. Explicit Confirm submits precisely that frozen choice under fresh current input authority using `confirm-review`; it does not recompute the old timing, take the cursor's new point or restart preparation. The server validates the exact choice and current native feasibility again. If ready it can release once; if early it accepts one immutable pending release and starts the fresh live lease. The result distinguishes requested from actually released.

User Decline/Escape/close is a **scoped cancellation**, not just a local dismissal. Use the existing native `cancel` command with the exact `lethalReviewId` and, when one exists, matching `expectedActionId`; distinguish this cancellation branch from confirmation before the ordinary review-confirmation check. Resolve only the current actor's exact review and cancel only its associated unfinished action. A Begin review has no action to cancel and must never fall through to unscoped Stop. Cancel-before-review-response still uses the original begin/gesture marker, preventing a late response from opening or acting on it. Remove the review as part of the same accepted cancellation boundary, so a late Confirm cannot recreate it.

While Confirm is pending, retain its exact command ID and fresh gesture sequence. A deliberate Cancel remains possible and names that continuation as well as the review/original begin; the same gesture cancellation marker wins if it reaches the server first, or cancels its matching unfinished preparation/pending release if admitted first. If Confirm already consumed the review but its release is still pending, resolve Cancel through that exact fresh gesture/original begin/action binding; absence of the consumed review does not discard scoped cancellation. Do not allocate another Confirm ID to retry an uncertain result. A successful Confirm may close its dialog programmatically without being interpreted as a second user Decline. If the shot already committed before cancellation, its real result wins. Failure or uncertain confirmation exposes Check result and cannot replay the old pointer release. No dialog close, focus return, publication replay or epoch refresh itself performs an attack.

Deliberate pointer movement entering the visible screen projection of the player's own body cancels the unreleased gesture. ### 2.2 Deterministic evaluation and presentation

```text

else if d <= y: score = 0
else: score = -min(1, (d-y)/(D-y))
```

## Open decisions, dependencies and current-format constraints

The chosen first slice intentionally makes **no promise of competitive browser timing trust**, general hitbox animation, genuine fluid/wind ballistics, universal crafted durability or already installed Dexterity/Focus. Those need separate demonstrated benefits and authorizations. Keep the candidate tuning of hold threshold, rings, poor/green factors, pouch fit and accessibility controls in the [base-world profile](../worlds/base/skilled-action-execution.md) and inventory them in [ASE limits](../limits/action-execution-and-skill-expression.md), not anonymous literals.

Consequential unsettled choices requiring Mike before building any _dependent expansion_: actual competitive PvP claim policy; competitive timing/aim authenticity protocol; additional real quality facets beyond pouch fit; future specialized charge/defense. The numeric profiles above are **selected initial implementation values for verification**, with later balancing informed by actual playtests; they are not unanswered pre-implementation questions. Implement the independently settled narrow noncompetitive feature through the stated baseline without introducing guess-dependent extensions.

No older-save migration or API compatibility wrapper is permitted under [AGENTS.md](../../AGENTS.md#development-save-policy). Same-version saved aim/work, item quality, authoring pins, exact current validator and release continuation must be verified. Do not discard current saves unless they are truly incompatible development data under the explicit root policy; preserve useful starting-world content when replacing the default starting world. Invalid profiles/records refuse at their boundary rather than silently treating broken state as a legendary or ordinary result.
