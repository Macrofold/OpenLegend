# Parallel batch 01 — PW09 — Correct word recall and avoid unrelated memory recounts

**Proposed implementation brief.** Engineer 5: **30 hours**, following 34 hours of World Agent streaming work. The engineer's separate 16-hour integration allowance covers both packages; it is not another memory implementation budget. The [feature specification](../parallel-batch-01-playable-week-feature-spec.md) and [technical design](../parallel-batch-01-playable-week-tech-design.md) own the expanded week; [PW09](../../maintainers/parallel-batch-01-playable-week.md#pw09--correct-and-efficient-memory-retrieval) owns completion. Creating this document does not authorize runtime implementation.

## Outcome and current gaps

A character looking for words in retained evidence should find the same normalized words regardless of the database machine's locale. Another character acquiring evidence or finishing vector indexing should not force the first character to rerank an unchanged word query or recount unchanged indexed memories. A character's correction, forgetting or restored timeline must still invalidate that character's results before they are used.

Current source at local main `6664144a` provides two concrete implementation targets and one measurement decision:

## Implementation sequence and contracts

### 1. Reproduce current caller cost — 4 hours

Record the implementation revision, PostgreSQL/pgvector version and collation/locale. Use explicit zero-provider fixtures and inspect the selected script's side effects before execution. Baseline a character's lexical `selectContext` and full `candidateSet` path, including coverage and body preparation. Compare first query, repeated unchanged query, another actor's write and the target actor's write. Record which SQL statements repeat, not just elapsed time.

### 2. Share Unicode words and build a locale-independent index — 8 hours

Keep `search_text` as the exact displayed source wording: history search reads it, and it must not be replaced with a normalized surrogate. The derived index uses the shared normalization in this order: NFKC; Unicode lowercase; current `i` plus combining-dot folding; then contiguous Unicode letter/mark/number words. Preserve repeated source words and their positions for ranking; deduplicate only query terms as today. Do not strip accents or apply a language stemmer.

Keep `search_vector` and its GIN index as the repository's derived lexical projection, but construct its lexemes from those normalized words rather than feeding the original text through `to_tsvector`. Build a parameterized PostgreSQL `tsvector` value with explicitly quoted lexemes and positions; construct the OR-of-prefix `tsquery` from the same words and cast that bound parameter directly to `tsquery`. Use one small escaping/serialization helper for PostgreSQL full-text values. Never concatenate user text into SQL, rely on session locale to split/lowercase words, or use an ASCII encoding that introduces a smaller effective word limit. Preserve the current full-text representation's supported lengths/positions; verify its existing edge behavior rather than silently introducing a new application limit or changing a supported source into an unsearchable one.

Projection of memory, awareness and summary rows stays inside the existing transaction in `project`. Source corrections, replacement wording and deletion update the derived vector through the same owner. Canonical record payloads, hashes and memory wording remain unchanged. The index is disposable derived data, not a second memory authority. Creation of a fresh current-format database builds it from current records; current-format save/load and a projection rebuild must yield the same indexed words.

Changing the generated-column definition is a current-format schema change. Follow the repository's current storage-version validation and [save/load contract](../../save-and-load.md). Do not add an old-save reader, backfill migration for incompatible development databases, automatic deletion or replacement. If an existing database is incompatible, fail explicitly. A same-format derived-index rebuild reads canonical source rows and publishes a complete consistent projection before readers use it.

Retain existing query behavior: null query selects recent evidence; non-null query matches **any** normalized word prefix, then uses current rank/importance/recency/ID ordering and protected-required precedence with fallback. This differs deliberately from owner-history search, which requires **every** query word. Share normalization, not those policies or history's eight-word/64-character request rules. Unicode normalization and punctuation boundary corrections can change which records match and therefore their ranking; document the intended examples. For unchanged ordinary ASCII token sequences, results and scores must remain equivalent. Hyphenated and other parser-special text belongs in the explicit changed-word-boundary cases rather than an unsupported assertion that every old parser rank remains identical.

### 3. Scope cache invalidation to the evidence that changed — 8 hours

Retain the global publication counter for existing consumers that need it. Add no new persistent revision authority. Repository-local epochs describe reuse of disposable caches; committed SQL rows, current generation and source revisions still decide eligibility.

| Reusable value                   | Required dependency stamp                                                                                                                       | Mutation and read rule                                                                                                                                                                                                                                                                                                                                   |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Lexical selected metadata        | Scope including world/actor/generation, normalized query words, requested limit; repository reset epoch and actor source revision.              | Any relevant evidence/eligibility change for this actor invalidates it, including a newly added better match. Another actor's commit does not. Keep `current(scope, selected IDs/revisions)` inside the database read snapshot and compare the stamp before and after asynchronous work. Selected-row validation alone cannot detect a new better match. |
| Eligible/indexed coverage counts | Scope, model, dimensions; reset epoch, actor source revision, actor-wide vector-reuse epoch and actor/model/dimension vector-publication epoch. | A source/eligibility change invalidates that actor for all models. A model-specific vector publication invalidates that actor/model/dimension only. Reusing vectors for known changed sources invalidates the known actors across models unless the actual affected models are already available.                                                        |
| Request body/preparation cache   | Existing world/actor/source kind/ID/revision and admitted byte accounting.                                                                      | Preserve existing request ownership, exact body identity, byte admission and SQL freshness. Do not promote it to a cross-request mutable cache.                                                                                                                                                                                                          |
| Reset or unknown mutation scope  | Repository reset epoch plus current generation.                                                                                                 | Full restore, global `experience_state` eligibility change, projection rebuild or unknown affected actor scope clears cache values and associated scoped stamps. This deliberate broad fallback is preferable to stale evidence.                                                                                                                         |

Extend the existing actor-revision bookkeeping with **bounded cache-owned** vector epochs: maintain stamps only for actors/models represented by live cache entries or active readers. Eviction clears unused stamp entries; a newly created entry gets a fresh monotonically increasing token, never a reused zero that can validate an old read. Active reads hold their token until completion. A simple reference-counted scope record is sufficient; do not create permanent per-source or per-ever-seen-model maps. Existing 64-entry lexical and 512-entry coverage cache bounds remain. Verify storage after eviction and many temporary actors/models; map sizes must follow live cache/read scopes, not lifetime writes.

For writes inside a transaction, bump the affected vector stamp before tentative publication and again in `afterCommit`, matching the current protection against a cache populated during the transaction. A rollback may cause a conservative miss but must never expose tentative counts. Explicit transactions continue to bypass committed coverage caches and read their own database snapshot. Determine whether a caller already has a transaction before opening the repository's read snapshot; such lexical reads also bypass shared-cache lookup and population, so tentative or older transaction results cannot populate a committed cache. Ordinary lexical reads retain the current snapshot binding and source validation. Where a committed publication callback supplies actor identity, use it; do not infer affected actors from a client or a stale result.

`publishVectors(scope, model, values)` has exact world/actor/model/dimensions and uses the narrow stamp. `reuseVectors(worldId, changed)` already receives actor/source sets on incremental publication; invalidate those actor scopes across models without a global reset. Its full-restore/unspecified form uses the reset epoch. Global generation changes invalidate all old scope keys, and reset clears maps so old generations do not accumulate. Warm A must survive B's vector write, while A's own source correction must invalidate even if no previously selected row changed.

### 4. Exercise privacy, transactions and restart — 5 hours

Use applicable existing checks in [`store.test.ts`](../../../apps/server/src/store.test.ts) and [`context.test.ts`](../../../apps/server/src/context.test.ts) after inspecting their fixtures; supplement only missing cases with a small disposable operational scenario. Existing store-close/reopen and scoped-candidate checks are supporting coverage, not proof of the new cache races. Hold reads across correction, forgetting, source replacement, restore and vector transaction commit/rollback. Retrieve through the real memory caller and verify that no record from another actor, unauthorized source or stale timeline appears. Include a newly relevant row not present in the cached result. Reopen a current-format store and rebuild derived caches/indexes from authoritative records; the selected evidence must match before close.

No model run is needed. Fixture recall validates selection and authority, not quality of a model's interpretation. Preserve existing paid vector reuse/accounting: cache invalidation must never dispatch replacement embeddings or erase accounting on restore.

### 5. Measure growth and record the vector-index decision — 5 hours

Complete the matrix below with exact search as the production baseline. Record whether exact vector ranking, broad lexical matches, cold coverage, body hydration or caller preparation dominates after the two implementations. For HNSW, record the actual scoped query plan and installed extension capability, and make a concrete go/no-go recommendation for a separately scoped approximate-index experiment. There is no HNSW installation or production query switch in PW09.

An affirmative next-step recommendation needs measured residual vector cost and a plausible way for the installed pgvector version to apply world/actor/generation/model/dimension eligibility without returning too few authorized candidates. A later disposable HNSW comparison must measure exact top-300 overlap/recall, protected evidence, filtered small actors amid larger ones, complete caller latency, index size/build/rebuild time, update cost and stale-source behavior. Synthetic vectors can measure those mechanics but cannot establish semantic quality. Do not promise a universal source-count threshold or claim that an HNSW index automatically fixes a materialized, scoped cosine query.

## Completion, effort and risk

PW09 completes only when both implementations reach the actual memory callers, locale/ranking/privacy/lifecycle rows pass, and matched evidence demonstrates the removed invalidation work. Exact-vector measurements and the HNSW recommendation are required supporting evidence, not a substitute for those changes. Unavailable PostgreSQL/locale support or unresolved race cases keep the corresponding acceptance open.

The allocation is **4 + 8 + 8 + 5 + 5 = 30 hours**. Expected changes are approximately **250–450 logic lines**, excluding tests/documentation, with medium risk concentrated in full-text serialization and transaction-safe cache stamps. Reassess if a repository dependency makes either design materially larger. The scoped invalidation implementation must not grow into a general cache framework; the two current repository caches are its consumers. Use the separate integration allowance for combined streaming/memory review and checks. Report incomplete work rather than dropping required privacy or recovery checks to fit the estimate.

Cannot be promised now: a fixed latency at 100,000 or one million sources; cheaper cold exact cosine ranking; bounded work for every broad lexical prefix; natural-history retention qualification; reduced pre-admission observation construction; production ANN quality; or closure of PF08/C17. Actor history remains untruncated. No runtime, database or provider measurement was run while writing this plan.
