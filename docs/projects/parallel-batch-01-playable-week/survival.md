## Outcome and complete scope

The bundled people still get hungry, sleep, collapse, recover at camp and respond to food as before. Those choices and their language come from the installed world. A clockwork character can instead have integrity and charge, with no food or energy definition, hunger rule, sleep rule, food suggestion or fabricated missing value. The owner editor shows that character's actual meters and ranges. Health remains bodily integrity: changing its representation must not bypass death, collapse, action cancellation, remains, private condition notices or saved history.

Complete means stage 1, stage 2a and stage 2b of the approved plan, including runtime consumers, authoring descriptions, current-format persistence and outcome comparison. A constants file beside an engine that still requires `actor.fullness`, `actor.energy` or `physiology: 'wilderness-v1'` is incomplete. This does not finish external world packaging, arbitrary anatomy, all action-family extraction, live replacement of every world rule, invented potions or poison permissions, or the separate proportional-step project.

## One meter owner and explicit units

Add the trusted passive `number-v1` attribute host alongside the existing reservoir and category hosts. It uses the existing `actor.attributes[id]` / entity attribute storage, definition pins, per-value revisions, `readState`/`writeState`, condition reconciliation and semantic invalidation. Reuse the existing numeric schema `{kind, min, max, initial, unit}` and its finite-value validation; do not create another quantity component.

The base food and energy definitions change to this host. Their authored IDs may stay stable in current source, but changed implementation/metadata produces changed pins and an incompatible development format. Remove the native-fullness/native-energy hosts, dedicated actor values/revisions and `capabilities.needs`; after initialization there is one value per meter. People receive both meters; native animals receive only the currently used energy meter. Animals' unused stored fullness is not a real need and is not initialized in the new model. Constructors in `worlds/base/world.ts`, `bodies.ts` and creator spawn paths use authored binding lists and values. An installed definition alone does not attach a value to every actor.

Health keeps the body-backed host and `actor.health` as authoritative raw points. Require a valid body with a finite positive maximum; absence of a body is inapplicable, never an invented maximum of 100. Reading its configured numeric attribute maps bodily health proportionally into the definition's range; writing performs the inverse conversion through the body owner. For the base range 0–100, the displayed unit remains percentage points. Thus a 36-point body shown at 50% has 18 raw health points. No sparse copy of health is stored.

`changeRate.amount` is always **attribute units per game second**, including a body-backed attribute. Convert only at its owner boundary. The base damage numbers preserve existing people with maximum 100; an unlike body's new authored rate uses its declared units. A health floor in a recovery rule is likewise expressed in that attribute's range, not raw hit points. Validate operation targets and units before use, not by matching a label such as “Health.” Unit strings describe quantities; equal strings never grant a resource-transfer interface.

Missing values remain meaningful. `readState` retains unsupported, uninitialized/not-applicable, unknown and known outcomes. A missing optional meter neither reads as zero nor falls back to the base world. Creator editing of a value does not attach a missing meter; the existing separately admitted binding path retains that authority. Current-format validation checks every saved attachment against an installed definition and its exact pin. Initial values are used only at authorized creation/attachment, never on ordinary read, save load or a failed query.

### Concern and presentation metadata

Moving a native meter to sparse storage must not accidentally give it reservoir behavior. Today `setAttribute` latches concerns and emits `attribute-concern` events, while the director treats sparse concern rows as reconsideration inputs. Applying that unchanged to energy would add events, shift reconsideration to 25, and preserve an unwanted second exhaustion sentence.

Extend attribute metadata with explicit concern behavior: `concern.mode: 'instant' | 'latched'`, `concern.notify: boolean`, `concern.reconsider: boolean`, and `recoveryMargin` for a latched concern. When concern exists, mode/flags are required; no concern means no concern text, notice or concern-driven reconsideration. An instant concern uses the existing strict `value < below` comparison, stores no latch and has no margin. A latched concern initializes from that comparison and clears at `min(max, below + recoveryMargin)`; the margin is finite, nonnegative and expressed in attribute units. The existing reservoir dead band is authored as the same 5% of that definition's range; base health and energy use immediate descriptions with no added concern-transition notice or concern-driven reconsideration. Food continues to use the existing condition-episode owner. These controls affect supported notifications/projection only; they never select an action. Keep the separately configured 15/10 reconsideration predicates below.

Add `critical` and `editorCritical` presentation predicates. Each is either `{compare: {operator: 'lessThan' | 'lessThanOrEqual', value, rounding: 'none' | 'nearest-integer'}}`, `{concernActive: true}`, or absent. Comparison values must be finite and within the numeric range; concern-active requires an authored concern. Absence means no critical decoration for that surface. This represents the current differing displays without placing the numbers in React. Replace the survival-role presentation enum with bounded symbolic `{icon, color}` references. Base definitions select the existing meter assets and theme tokens; the client resolves only its trusted asset/token catalogue, never CSS, SVG or HTML supplied by a definition. Unknown symbols use the existing neutral/text fallback. A symbolic asset named `meter.food` is an asset reference, not engine logic saying that every world has food.
