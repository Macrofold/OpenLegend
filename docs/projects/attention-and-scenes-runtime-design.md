## 1. Outcome, evidence and scope

Walking, looking and speaking should remain responsive while characters notice and remember the same permitted facts. An AI may take time to understand those facts. Its eventual action starts from the world that actually exists then; it cannot stop the clock or revise an earlier physical outcome. Preserve useful recent sequences and exact required evidence without copying a character's whole appearance and original observation into each movement endpoint.

The current diagnosis finds amplification before any model call. The standard opening has 163 entities, including seven people and 20 animals. At one ordinary sight boundary, six changed sources produce 28 observer/source updates, 56 full endpoint captures and roughly 153 KB of new pooled values. About 96% of that increase is motion payload. One approximately 5.3 KB motion value embeds two approximately 2.6 KB endpoints, each repeating an approximately 1.9 KB original observation. These are serialized sizes, not measured heap allocations; there is no recursive exponential nesting. The separately measured complete-server workload contains 21 people, 21 animals and 100 root objects. Its native batches, saving and public-view preparation are all expensive with zero provider calls. Neither workload establishes population capacity.

| Measured or code-confirmed cause                                                          | Root correction                                                                | Work that must remain                                        |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------ |
| Full observations embedded in current movement values; later converted to compact history | One compact received-sample representation from the first write                | Exact endpoint values, times, source support and continuity  |
| Changed pose carries unchanged descriptive body data                                      | Separate typed pose and outward-body values under the existing body facet      | Same body information when a consumer requests it            |
| Observer movement invalidates every subject's attention description                       | Independent source, observer-frame, freshness and description dependencies     | New spatial relations and genuine sight confirmations        |
| Repeated recursive copying, freezing and reference-union scans                            | Seal changed leaves once; update derived ownership from exact changed roots    | Immutable publication and complete reference validation      |
| Append rewrites a growing logical receipt/value collection                                | Immutable storage suffix segments using existing ordered writes                | Same logical chronology, identities, deletion and cold reads |
| Save admission and pending application retain or reprocess excessive data                 | Compact prepared writes, bounded ownership proofs and existing durable journal | Atomic acknowledged commands, authority and crash recovery   |
| Movement refresh prepares unrelated menus, inventories, trade and event history           | Dependency-specific public sections; details on opening their reader           | Current permissions, honest loading and action revalidation  |
| Optional delivery failures can enter the global storage-failure path                      | Distinguish optional reader failures from authoritative failures               | Stop on genuinely unsafe authoritative state or storage      |

This design changes representation, invalidation and scheduling. It does **not** reduce sight frequency, attention capacity, evidence fidelity, recent-memory duration, recognition rules, supported physical consequences or current clock defaults. The selected world still owns all fictional policy and tuning. Full physical vision/acoustics, ATI investigation, attention/combat integration, complete PP07/SAI-A and broader scenes retain their existing unfinished owners.

## 2. Non-negotiable boundaries

1. **One native transition remains ordered.** Complete physical outcomes, due sensing, exact received evidence and required knowledge/retention effects before publishing that transition. Yield only at an existing coherent boundary. Readers see the last complete world while the next boundary is being calculated.
2. **One semantic owner writes each fact.** Extend perception, received values, temporal evidence, actor work, saving and public projection. Do not add a second event archive, attention queue, memory store, command replay system or general change-tracking framework.
3. **Sharing never shares a mind.** Neutral values may be shared. Receipt identity, observer/body life, original facet, scope, recognition, uncertainty and private retention remain personal. Unknown people remain local individuals until actual recognition supports more.
4. **Actual observation is irreplaceable.** A later database query or current-world lookup cannot reconstruct what someone previously saw. Movement samples are received positions, not inferred destinations or narrative episodes. The same mechanism handles other temporal facet changes.
5. **Logical policy and physical storage are distinct.** Preserve the existing logical evidence charging rules and limits. A shared reference does not make an arbitrarily large permitted account free. Separately meter physical payload, indexes, prepared buffers and pending application. Do not discount logical charges to pass performance checks.
6. **No new AI entitlement.** Movement, changed frames and database completion do not create model calls. Keep existing cause admission, discovery allowance, concurrency, spending, original deadlines and no-automatic-paid-retry behavior. Async execution does not mean a call every few seconds.
7. **No compatibility layer.** Change the one current representation, codecs, validators and every caller together. Incompatible development saves may be replaced only under the existing development-save policy; preserve authored starting content and real financial records.

## 3. Compact evidence from the first write

### 3.1 Representation and ownership

Use `perception-evidence.ts`, `perception-values.ts`, `received-values.ts` and `temporal-evidence.ts` as the owners. Promote the existing compact temporal motion semantics into the shared current/history type; remove the full-original current motion form and its later conversion. Reuse existing identities rather than inventing replacement IDs. The following are required meanings, not additional parallel interfaces:

| Record                 | Required contents                                                                                                                                                                   | Must not contain                                                                                 |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Neutral received value | Typed immutable value, such as exact position, geometry, outward appearance or effect detail                                                                                        | Observer identity, canonical identity inferred from private data, full original observation      |
| Personal facet support | Observer/life, original ID/revision and facet ordinal, actual scope/channel, value reference(s), acquisition/measurement/confirmation times, uncertainty and existing validity data | A nested full observation or mutable current-world pointer                                       |
| Motion                 | Two exact received endpoint supports and existing continuity/gap semantics                                                                                                          | Copied body/carried/attribute facets from either endpoint; guessed destination or activity label |
| Confirmation           | Existing facet support plus the actual confirming source/time/frame                                                                                                                 | A copied `CapturedCurrentFacet` containing another complete original                             |
| Body facet             | Flat references to outward-body detail and pose, with the same personal facet support                                                                                               | Appearance/description duplicated inside every pose change                                       |
| Captured cut           | Selected personal records plus their complete deduplicated immutable source/value/frame closure                                                                                     | Late lookups into current world state to fill missing historical facts                           |

An endpoint's neutral coordinates may live in the shared value pool; its observer-specific proof stays in the personal descriptor. Preserve the flat-pool rule: pooled atomic values contain no references to other pooled values; the personal descriptor carries all value/frame references. A provenance key identifies a dependency, not a grant to retrieve discarded original content. The existing compact immutable `ReceivedObservation` may still be shared by its facets; the prohibited embedding is a fully materialized original inside another facet.

For the existing `ObservedBody`, pose contains `position`, `heading` and `supportSurfaceId`; outward-body detail contains every remaining field, including dimensions, appearance, description, label, effects, quantity and kind-specific outward details. Audit the union exhaustively. Materializing a body must reproduce its permitted shape exactly, including optional fields. Geometry consumers read pose and dimensions without reconstructing descriptions. Do not merge uncertain observed location with body placement: their precision and permissions remain distinct. This is a typed split for two existing semantic components, not generic JSON patching or a recursive content-addressed object graph.

For implementation, the compact sample descriptor must retain these existing meanings independently: original fact key; confirmation source; `measuredFrom`/`measuredThrough`; `acquiredAt`; `confirmedFrom`/`confirmedThrough`; exact location and frame references. Motion contains earlier/later sample descriptors, actual exposure and supported correspondence. Reuse the current `TemporalMotionSample` fields where equivalent rather than adding aliases. A full read materializes these selected fields, not unrelated facets of either original.

The existing facet union owns splitting, materialization, exact logical charge and dependency enumeration. Extend those operations exhaustively for the supported families. Current views, temporal recording, correction, capture, serialization and cold reads must use these same operations. Never maintain separate lists of reference-bearing fields in storage and privacy code. Both motion endpoints, confirmation sources, aliases and source revisions participate in dependency closure.

Convert the actual caller chain together: `experience.ts`/`experience-manifest.ts` and remembered impressions; received scene/geometry/history readers; server `experience-context`, `perceived-context`, `recent-history`, `situation-context` and public views; current/temporal validators; history residency, memory repository and correction indexes. Replace recursive original-source discovery in `nativeObservationDependencies`, `ownedObservationSources` and `observationLearningSources` with the shared typed dependency visitor. Preserve their existing occurrence aliases and recognition dependencies. A compiler-clean new type is insufficient if a consumer still eagerly materializes a whole original to read one field.

Create compact endpoints directly from the received lease/sample before replacement. Do not call the full-original capture helper and then discard most of its result. Store required immutable endpoint data at that moment; a reference to a replaceable current lease is insufficient. Same-time source order, genuinely different observation times, loss/reentry and body replacement remain explicit. Two endpoints alone do not prove uninterrupted visibility.

### 3.2 Exact headers, frames and freshness

Store repeated observer/phase metadata once in the existing receipt/chunk context. Use an exact shared default only where the represented field is equal; preserve every unequal override. This includes the distinction between acquisition, last actual measurement, confirmation and current support. Reading held information never fabricates a new measurement.

A completed sensing phase may genuinely reconfirm unchanged detail. Preserve `effectiveCurrentFacetSupport`'s existing phase overlay, which publishes current freshness without rewriting every held lease. For retained attended evidence, reference that actual phase/frame and the exact held subject/value supports. Represent observer movement once in the phase context with scoped subject bindings, instead of generating a fresh full stationary-body observation for every subject. Membership changes, changed values and losses remain explicit ordered entries. Reuse the existing temporal context/receipt owner; add no independent frame-history store. Retain explicit per-subject receipt references unless a lossless run encoding preserves the exact sample order and time mapping; a shared frame is not permission to omit required confirmations.

The historical reader combines the retained frame context and exact bound value to recover the same permitted relative position. It must not consult a subject's later position, later membership or current source policy. Context sharing is allowed only while the corresponding received support remains valid under the producer's existing contract. Context and support closure count toward retention and correction. If no context is retained, do not promise reconstruction of that frame.

### 3.3 Acquisition to consumption, literally

1. Prepare a changed source's neutral permitted values once for that source revision and sensory variant. Shared preparation must not bypass an observer-specific visibility or recognition decision.
2. Apply each actual observer receipt: keep its exact personal support, replace changed current references, and update independently measured freshness/loss.
3. Derive native attention inputs from the changed meanings described in §4. Broad current motion remains available even when the subject is outside detailed attention.
4. Before overwriting evidence needed by an attended/required recording, append compact supports to the existing temporal owner for subjects attended before **or** after that acquisition, including entry baseline and actual loss. Preserve all admitted source order and gaps; detailed attention starts recording at actual admission, without retrospective routes. A slot release, source loss, correspondence break and technical coverage loss remain distinct.
5. Publish the sealed native result. Public readers materialize only their permitted selected fields. NPC context reads the bounded current scene and admitted recent sequence through existing source fences.
6. Explicit source inspection obtains the complete authorized original closure from its existing retained owner. A captured cut packages that closure once and remains self-contained after later pool reclamation. No loss of inspectable source detail is authorized by compact motion.

Unknown identity, stale appearance with fresh location, correction of one endpoint, loss of sight and restoration must produce the same permitted outputs as before. Exact source inspection may be more expensive than an ordinary movement update; that is intentional and bounded by the requested cut.

### 3.4 One compact native current-evidence representation

Use the existing exact `perception-records.ts` defaults as the domain's sole canonical current-evidence representation, rather than keeping expanded native envelopes and compacting/expanding them for storage. Promote its source catalogue, receiver header and sparse facet metadata to the current-evidence owner. A full `LiveFacetSupport` remains an ephemeral read/capture value, never a second writable store. Keep existing identities, insertion order, unequal timestamps, original ordinals, source-life/continuity and receiver frames exactly. Defaults remain relative to the exact original facet, never the current clock. The visual-confirmation phase remains a read overlay.

The owner admits originals once; current facets and this-sequence received IDs reference that catalogue. Replace/update/delete through the same mutation owner. Only membership-changing batches nominate retired originals; pose updates do not rebuild the catalogue. Remove a catalogue entry only when neither current facets nor current-sequence reception retain it. Raw builders and current-format restoration retain complete validation. Original lookup is not permission: callers still establish actor/life/current membership and resolve actual pool addresses before consuming values.

Convert source comparison, eligibility, geometry, attention, ownership accounting and correction to compact reads. Materialize the complete logical envelope only for a consumer that actually needs it, such as an exact captured cut, loss finalization or retained receipt. Reuse the existing metadata rules in those reads; do not make every facet read expand an entire owner. Remove the superseded server encoder/decoder and convert all current callers/fixtures together. The physical current-perception records stay with their existing catalogue owner. Exact logical captures, original inspection and cold restoration must remain equal. This removes repeated construction/conversion; its measured 38% reduction in lease property count is not a whole-game speed promise.

## 4. Change only the work whose input changed

Extend the existing native write/change journal and immutable lineage metadata. Each semantic writer records changed owner/key, changed semantic fields, append ranges and retired ranges while it already knows them. This metadata is process-local, revision-bound and derived; it is not a saved second authority. Every consumer receives the same finalized change description. A raw builder or restored world without lineage uses a full boundary rebuild once, not a guessed empty change set.

The acquisition result needs four separate signals: a subject-keyed map of changed/entered/lost facets; an optional completed visual phase with revision, exact frame reference and through time; whether that frame changed; and the actual confirmation support supplied by that phase. Build these while applying receipts, not by serializing the before/after world. Retain the previous attention membership until recording has selected the union of before/after attended subjects. Retain old endpoint/loss supports before replacing their live ownership, add new current/history ownership, then release old references and nominate zero-owner candidates. Finalization emits the combined exact delta once; a consumer may not infer 'nothing changed' from unchanged outer map identity.

| Actual change                                      | Necessary work                                                                                               | Work that should reuse its previous result                        |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| Source pose                                        | Current pose/motion, relevant received geometry and native relations, admitted chronology, pose view section | Outward description, names, unchanged familiarity and trade menus |
| Observer frame                                     | Received spatial context, spatially dependent salience/relations and selected frame history                  | Source description, identity novelty, nonspatial attention scores |
| Actual unchanged-detail confirmation               | Freshness and admitted confirmation/context support                                                          | Value encoding, appearance description and novelty                |
| Appearance, carried exposure or public attribute   | That facet, its description-dependent attention inputs, admitted chronology and affected view section        | Unchanged unrelated facets                                        |
| Familiarity/name/recognition                       | Affected individual's eligible scores and permitted identity presentation                                    | All unrelated individuals and source geometry                     |
| Goal, explicit focus or installed attention policy | The actor's affected priorities/selection                                                                    | Other actors and source preparation                               |
| Loss, correction, forgetting or privacy revocation | Exact affected current/history supports, dependency closure and authorized consumers                         | Unrelated sources; no late rehydration of revoked information     |
| Inventory/offer/control change                     | Relevant available actions and open inventory/trade readers                                                  | Closed detailed panes and unaffected viewers                      |

Split attention's description/change watermark from spatial-frame and freshness dependencies. Removing the frame from a broad revision key alone is insufficient: recompute the spatial score components that genuinely changed and preserve the attended frame history. Reuse cached components only under their exact inputs. Rebuild one actor's final ordering only when a changed component can alter it; preserve deterministic tie-breaking, stable/lent slots and fair discovery.

Ground observations use an adaptive subdivision anchored to the physical surface, not to the observer's moving view bounds. A changed eye recertifies previously received patches against the actual current range, cone, surface support and complete ray hull. Certified patches keep their original facts and acquisition frame; failed or unvisited patches lose current permission and close at their last supported time. No pending original can revive forgotten or corrected evidence. New discovery/subdivision still waits for the selected discovery interval. When discovery and recertification coincide, nearest-first preparation shares the existing patch budget, including retained candidates, so neither gets an extra allowance. Boundaries survive only with both currently certified support patches. Changed life, map revision, actual detector definition or geometry policy requires new acquisition. Incomplete preparation remains unknown. This corrects ground disappearing merely because its observer walks; it does not establish unseen terrain or change the configured limits.

Correctness still costs work proportional to actual observer/source relationships and real received changes. A dense room can require many per-observer receipts; this design does not promise constant time for real information. It removes repeated payload construction, unrelated downstream work and repeated whole-resident scans. Existing spatial candidate selection remains conservative; no all-pairs semantic relation graph is added.

## 5. Seal once and account for ownership incrementally

### 5.1 Immutable publication

At the semantic writer, create and validate new leaves and establish their immutable ownership once. Reuse already-proven immutable children; finalize the changed container once at the native boundary. Remove the second recursive copy/freeze of unchanged perception, temporal and value-pool subtrees. No Immer draft, foreign mutable object or caller assertion of trust may cross publication.

Use the existing owned-builder/lineage mechanism for proof. A shallow `Object.freeze`, an arbitrary `trusted: true` argument or merely matching a revision does not establish immutable children. Raw construction, restoration and provider/storage boundaries retain complete applicable validation. Mutation after proof invalidates that proof. A nested `draftWorld` preview must detach its changed rows while restoring its parent's writable append buffers afterward; never freeze a parent buffer and continue writing through it. Preserve the current persistent-state mechanism; do not introduce a general persistent-map library just to avoid a bounded shallow map copy. Measure remaining shallow-copy cost separately.

At final publication, the current writer's newly owned map may seal in place only after every actual row proves immutable; foreign mutable rows keep detached snapshots. Private previews never seal their parent's working map.

Evidence/accounting maintenance preserves pending native arithmetic instead of materializing every character's unchanged physical values. Ordinary commands settle their actual participants through the existing native-value owner; target mutation owners settle their affected episodes. Generic editable drafts retain the full barrier. The [simulation-time contract](../simulation-time.md) owns those exact arithmetic and eligibility guarantees. Reuse sensory preparation across a storage-only replacement only when all of its actual physical, definition, visibility and time inputs are unchanged.

### 5.2 One derived resident reference index

Build a reference index from canonical resident owners once on load. Update it from exact changed roots, leases and appended/retired ranges. The index records references by true retaining owner and value/source key. Keep actual retention ownership distinct from temporary residency/capture pins; a capture watermark alone cannot extend optional memory.

Retention preparation, residency compaction and eviction validation reuse one complete ownership result for the same world/index revision. Do not independently traverse and union the same received graph. Only released block/ordinal candidates require indexed cold-reference checks. If lineage is unavailable or inconsistent, rebuild the affected owner/index and validate; never treat an unknown reference count as zero.

Correction and forgetting become logically effective at the accepted boundary. Physical pruning stays in the existing canonical/source application transaction. `MemoryRepository.prepareRetention` / `prepareTemporalRetention` produce exact replacements/deletes, `WorldRecords.stageRetirements` folds them into prepared changes, and `applyRecordSources` applies them atomically. The existing accepted journal preserves those exact changes until application commits; there is no durable background-GC queue to rely on and this design does not add one.

Before preparing deletion, check world generation, accepted/applied revision, reference-index revision and pending accepted journal dependencies. A newly retained reference cancels stale deletion. New unrelated revisions require refreshing only affected candidate roots and pending suffixes, not restarting all cleanup or demanding an unchanged global revision. References may be acquired only from currently permitted supported facts; knowing an old pool address cannot resurrect forgotten material. A crash between accepted logical retirement and application resumes from the durable journal without sweeping historical payload. Do not defer physical deletion beyond application/journal-prefix pruning under this design.

Sharing must not pin expired siblings. Release individual unowned values/ordinals even while another value in their physical segment survives; preserve stable ordinals and never reuse a retired ordinal. Count pending cleanup bytes until actual deletion, and honor the existing cleanup backlog/admission limits. No durable reference-count table becomes a competing authority.

## 6. Append storage and a short durable command barrier

### 6.1 Segmented physical layout

Keep logical temporal chunks, received-value blocks, personal receipt identities and ordinals. Fill a logical temporal chunk up to its existing complete byte allowance across simulation timestamps; every receipt retains its exact time and order. A timestamp change does not require a new chunk. Expiry and count/byte pressure remove the exact old prefix, including inside a partly retained chunk, without pinning expired siblings. Change their existing `world-record-schema.ts`/`temporal-storage.ts` codec to store immutable suffix segments. Use one narrow helper for the two actual append collections: temporal receipts and received values. Do not add one SQL row per coordinate or rewrite the entire growing chunk.

Each physical segment has its existing parent identity, first ordinal, exclusive end ordinal, exact encoded size and reference metadata. Its primary identity is parent plus first ordinal under the existing identity contract. Seal a suffix at a durable preparation boundary, splitting at existing byte/count bounds. Do not keep reopening the last stored segment to add one item. Small parent headers retain counts and index ranges. Existing capture-watermark identities become child records, so changing one watermark does not rewrite an actor's whole map.

Preparation compares an exact accepted baseline with a frozen next snapshot. Proven append lineage reuses all stored segment descriptors and emits only the new suffix. The prepared-commit token owns newly assigned physical layout until acceptance. Attach reusable layout metadata to immutable collections through the existing record/history codec mechanism. A failed/uncertain retry must recover that exact prepared outcome before assigning another layout; it cannot generate duplicate suffixes. Queued preparation must carry the accepted predecessor's layout even while normalized tables lag.

Replacement, correction and partial deletion use the same codec's affected-segment replacement path; they are not append operations. Stable ordinal coverage includes explicit retired slots where the logical model permits them. Current-format decoding checks disjoint contiguous coverage of the declared range, permitted holes, header totals, payload shape, ownership and complete references before reconstructing the same logical collection. Restoring never re-executes commands to rebuild evidence. Cold queries filter actor/life/subject/time metadata before hydrating only the requested closure.

The growing alias/subject/individual/value-reference unions and receipt index belong on the existing immutable receipt-segment rows, prepared once per changed page through the existing semantic dependency visitors. Keep only bounded actor/life/epoch/time/order/range/count/byte and physical-page totals in the mutable parent storage header. This does not change the logical `TemporalChunk` or its full retention charge. The selected full-chunk reader reconstructs its logical unions; ordinary selectors use indexed `EXISTS` against pages before hydration, never aggregate all parent payload merely to filter. Preserve the existing actor/source/life/time fences and metadata/preparation limits. Correction and pruning replace only affected pages and their indexes atomically with the journal; no duplicate source store or migration reader is added. Extend the existing codec's preparation boundary to receive exact source support rather than inventing aliases from partial receipt metadata.

Keep exact page aliases, subjects, individuals and value references, but index their namespaced lookup keys through one deterministic 16,384-bucket `SMALLINT[]` filter. PostgreSQL GIN retains dictionary keys after their last posting disappears; indexing ever-new receipt aliases directly therefore retains historical key space after expiry. The fixed bucket vocabulary bounds that dictionary. Every bucket match must also satisfy the original exact array predicate and existing actor/life/time scope; collisions add candidates, never evidence or authority. One shared helper prepares page and query buckets. Include this derived field in encoded-byte admission and current-format validation; replace affected pages and their filter atomically. Retention still deletes postings through ordinary PostgreSQL maintenance, with no per-step reindexing or new alias store. Qualification must measure refill/prune index reuse and collision-heavy exact reads, not infer physical boundedness from logical deletion.

### 6.2 Acceptance and background application

Reuse the existing [durable journal](performance-overhaul/journal-contract.md), world mutation lane, application worker and read fences:

1. Enter the mutation lane and validate the command and authority against the current world.
2. Complete its required native transition, including exact evidence and earlier unsaved native progress covered by this save. Seal only changed leaves and capture the expected durable predecessor.
3. Prepare compact changed records, receipt/source plans and new suffix segments. Reuse validated column extraction and encoded values; do not immediately decode the encoder's own output and repeat its complete validation.
4. In one short database transaction, check mutable authority, world/generation/predecessor, command receipt and applicable real constraints; durably append the complete exact change description and receipt and advance the committed revision.
5. Only after successful COMMIT, install the accepted candidate and acknowledge it. Release mutation ownership so the world and subsequent commands can continue.
6. The existing worker applies accepted changes in order to ordinary tables and optional indexes. Completion advances applied coverage. **It never reinstalls the older captured world.**
7. Table-backed readers fence to their captured committed revision, then verify generation and applied coverage in their read snapshot. Wait outside the world mutation lane; recheck any authority/action prerequisites before using a delayed read to mutate the world.

Native progress already continues during a background progress save. Preserve that owner and its honest durable coverage. Do not release the current command save's lock around its existing await: that code subsequently installs an old captured candidate and could overwrite newer simulation. The selected fix is a shorter durable barrier, not published speculative command effects or rollback descendants.

### 6.3 Bounded proof-based admission

Keep the existing 512 indexed constraint-probe ceiling, 32 unapplied revisions, 32 MiB encoded debt, one worker and at most eight accepted revisions per online application batch. The selected change is to stop treating every safely owned append row as an independent unknown SQL constraint, not to raise the limits.

For owner-produced suffixes, prove the parent/generation, exact accepted predecessor, deterministic identity construction and non-overlapping successor range once per changed parent. Within that proof, validate ordinal coverage and schema locally; no separate SQL membership probe is needed for each contained receipt/value. Externally supplied identities, unsupported unique constraints, referenced physical parents and mutable authority still receive their real bounded indexed checks. Unknown/destructive families keep the existing synchronous atomic writer until their semantics are explicitly covered. SQL constraints still apply during ordered application; admission must have proved they cannot fail from an already accepted predecessor.

The record schema may explicitly identify a collection whose entire canonical membership stays resident across saving, compaction and loading. For such immutable collections, the codec can prove new identities absent from the exact accepted predecessor and derive unique final positions without SQL re-probes. Apply this to current perception collections and capture watermarks; never infer completeness for cold history or shared-value pools. Keep contradictory pending identities, positions and ancestor deletions checked even when SQL is unnecessary. Foreign baselines, mutable collections and unsupported constraints retain full admission.

Separate **physical reclamation of unowned payload** from semantic correction/forgetting in the prepared change classification. The current `canDeferWorldTables` rejection of any `changes.expired` also rejects ordinary unowned received-value release. Replace that blanket check only for exact segment/block replacements or deletes whose complete current, retained, indexed-cold and accepted-pending ownership proof has no surviving reference. Include those changes in the same durable entry and atomic source application. Actual privacy/semantic deletion and other unsupported destructive families retain their synchronous treatment. Correct the classification at its owner; do not special-case movement in the journal caller.

Only the semantic owner's prepared object can carry reusable validation proof; no public boolean bypass. Persisted journal recovery and foreign/current-format input receive full validation. Keep statement/byte bounds and truthful busy/admission behavior. If one transition or outstanding debt exceeds a bound, drain or use the existing synchronous path before acceptance; never partially accept required evidence.

### 6.4 Bound pending memory and recover exactly

After preparing complete application inputs, pending entries retain changed records, exact personal source plans and small revision metadata. Remove `TableWrite`'s retained full `before`, `state` and `historyAfter` roots from each online journal entry. Reuse the existing compact `JournalTables` worker interface. Keep the current world, required durable baseline and at most one active preparation; do not keep 32 full world generations merely because encoded journal debt is under 32 MiB.

Account separately for encoded debt, decoded/prepared application inputs and one worker batch, including duplicated buffers during handoff. Existing count/byte bounds remain provisional, not a heap-capacity claim. Use measured memory to select an additional preparation-byte bound only if the compact inputs still exceed the existing operating envelope; record that operational decision in the persistence limits owner before relying on it.

Append failure leaves the preceding accepted command state. An ambiguous COMMIT is resolved through the exact receipt/head recovery owner without rerunning the command. Worker failure preserves accepted journal data and stops new save admission under the existing sticky-failure contract. Lost completion requires fencing the previous writer and proving durable generation/applied coverage before publishing completion once. Restore, checkpoint and shutdown use existing drain barriers; old-generation completions cannot mutate the restored world. Rebuild derived indexes after restore.

## 7. World advancement and asynchronous cognition

### 7.1 What finishes when

| Before the next coherent native boundary is published                                         | May finish after the world advances                                                                |
| --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Due movement/collision, harm, status changes and action completions                           | Model context formatting/hydration after capacity admission, model inference                       |
| Independently due sensing, exact received facts, loss and freshness                           | Optional interpretation, useful-account consolidation, embeddings and narration                    |
| Attention membership needed to determine admitted recording; required temporal/source support | Expensive optional source/history readers and selected menu/trade details                          |
| Installed native protection, relation/latch changes and required knowledge/correction         | Formatting/coalesced delivery of public views; ordinary-table application after durable acceptance |
| Command's short durable acceptance barrier before its acknowledgement                         | Bounded physical reclamation after logical expiry/revocation                                       |

The AI director already runs calls asynchronously. This is not a new model execution system. Audit all actual callers to prevent optional SQL, public presentation or provider work from becoming an indirect world-mutation wait. Making a synchronous copy/serialization function `async` does not move its CPU cost off the event loop. Reduce that work first; reuse the existing bounded worker only for its actual storage responsibilities.

### 7.2 Exact request/answer sequence

1. An existing justified cause offers an actor work item. Coalesce through `ActorWork`/thought intake; do not create a ticket for each motion sample.
2. Admit existing actor/world/provider/spending capacity before expensive optional hydration. Keep the actual cause and its source watermark. A busy actor's genuinely newer causes remain pending for the next justified opportunity; use the existing generation/acknowledgement rules so completion cannot clear a newer cause.
3. Capture bounded actor-permitted current/recent evidence and exact source dependencies. Keep finite request-owned copies, not a whole-world snapshot. Apply existing private retrieval fences. An in-flight copy does not extend optional source retention or defeat later correction.
4. Release the world lane before model execution. Native movement, other actors, sensing and saving continue. A character's already admitted native activity continues under its existing interruption rules.
5. When a result returns, use existing decision validity/publication owners to check actor/life/control/timeline, original deadline, exact retained sources, current grants and current effect-specific prerequisites. An unrelated world revision does not by itself invalidate the result.
6. Admit supported physical proposals against the **current** world. A still-valid remembered interpretation and a now-impossible physical action can have different validity under existing answer-group rules. Do not discard valid history solely because somebody walked elsewhere; do not execute a stale action because its prose is sensible.
7. Commit permitted effects once through ordinary semantic owners and saving. Rejected/expired work does not automatically start another paid call. Cancellation that has not actually settled still owns capacity and real cost.

Preserve existing cause-specific immediate/useful-lifetime limits and generator timeouts; an original deadline includes follow-up work. Do not universalize a particular current 31-second usefulness limit or 35-second generator timeout. There is no promise that every unfamiliar danger is understood before harm occurs. The selected few-second aspiration begins at justified admission and remains subject to actual capacity and human-like misses.

**Example, preserving existing supported mechanics:** a parent receives their daughter's motion, the broad presence of 15 pursuers and a supported drop edge. Detailed attention determines retained fine history, not who physically exists. The native scene/relation owners prepare the existing received spatial evidence; no new daughter/cliff-specific rule is introduced here. Native installed reactions and physical movement continue before an AI returns. A late warning or rescue proposal is admitted only if its present preconditions hold. If harm has already happened, the answer cannot retroactively prevent it. Full new combat/protection mechanics remain separately scoped.

### 7.3 Failures must stop the right work

Classify errors at the owning boundary. A proven optional reader/view-formatting failure invalidates that reader or closes its affected stream with a truthful recoverable error; it does not become a global storage error that pauses every character. Log the exact failing stage and permit a fresh bounded read when appropriate. A failed authoritative save, corrupted authoritative input or unsafe native invariant retains its existing stop/recovery behavior. Do not blanket-catch and ignore unknown errors or continue a partially executed transition.

## 8. Public views and optional readers

Extend existing `ViewCache`, public projection and scoped readers, not a new cache service. Split dependencies for received pose, descriptive details, identity/art, controls, event windows and compact trade availability. Keys include actual owner/source revisions plus viewer/life/control/grant scope and relevant installed definitions. Never use outer world-object identity as the only invalidation signal, and never reuse another observer's private result.

Movement updates pose/current evidence sections. Reuse unchanged descriptive and inventory sections. Corrections, forgotten information, control changes and privacy revocation invalidate affected cached sections before delivery. Cache equality cannot be inferred only from a neutral value pointer when personal freshness or permission changed.

Keep a cheap trade availability/title/offer summary in the ordinary view. Prepare full handover options, inventory lots and trade details only for an opened reader. Reuse existing actions, inventory and trade-disclosure endpoints; add only a missing narrow read of the existing trade-view owner if necessary. Update the client trade pane, action picker, inventory and offer presentation together. Opening shows a real loading state, then current costs/blockers; it does not grant undiscovered container contents. Active panes refresh on their relevant inventory/offer/control changes and target loss. Discard delayed results for a superseded selection or grant. Action execution always revalidates current conditions.

Always-visible HUD, quick-slot and current-work item bindings retain their required compact projections regardless of whether Inventory is open; use the existing inventory-binding reader for exact selected IDs. Defer only optional detailed pages and menus. Audit all `view.player.inventory` consumers before narrowing its payload; a closed Inventory pane does not imply no visible inventory consumer.

Keep existing 50 ms publication coalescing, bounded yielding between viewers and latest-queued-revision work lanes. Under slow delivery, skip superseded optional view construction, never native evidence or a required command result. An unchanged section should not be re-encoded. Do not enqueue one full public snapshot per native sample.

The current event collector stops only after both the 60 journal and 30 conversation targets are filled; a speech-free interval can therefore accumulate excessive automatic history. Select each existing window independently, then union/deduplicate in original order. Preserve separate active-caption/required-event lifetimes and paginated older history. Verify actual visible windows before changing the collector; if a consumer depends on the excess, move it to its explicit required/history reader rather than silently delete its input.

Use stable keyed event additions, changes, removals and order updates in the current protocol where the existing patch owner supports them; extend that owner if its only operation replaces the whole array. A reset still reconstructs the complete bounded current view. Correction/history-epoch changes clear obsolete replay. Update server and client together without an old-wire adapter. Before reporting transfer savings, correct the measurement's `snapshot` versus actual `reset` event classification and measure bytes by section; the earlier total stream measurements do not establish exact patch amplification.

- Correct either motion endpoint or its confirmation; forget one source while retaining another in the same segment; lose/reacquire an individual; restore with active work. Verify current, captured, retained summary, public and NPC consumers all honor their applicable source/privacy boundaries.
- Hold a provider call open, including ignored cancellation. Player movement, another NPC's native work, sensing and saves continue; capacity remains owned until settlement and no automatic redispatch occurs. A new cause arriving during completion remains pending.
- Return a valid old interpretation after unrelated motion; accept once where still supported. Separately consume a resource, lose the target, replace the body, change control, expire/correct a source or restore the world; reject only effects whose current validity failed, without stale physical action or information leakage.

### 10.2 Measurements and pass conditions

Use the same world, deterministic inputs, hardware and enabled diagnostics for comparisons. Report the 163-entity standard opening, the distinct 21-person/21-animal/100-object complete-server fixture and the 1,007-entity dense diagnostic separately. Separate initial exposure/cold start from warm ongoing movement. Prior complete-server runs were configured at 3× and achieved about 0.19–0.21 of normal; they were not configured-1× qualification.

Run **actual configured 1×** first, then requested 3×, using real command arrival timing and existing normal-clock acceptance thresholds. At normal 60:1 time, a three-game-second interval represents 50 real milliseconds; that budget must cover sustainable native work and the other admitted server work, not merely a single helper. Report real/game elapsed time, backlog, command latency distributions and worst stalls. Do not accept a finite catch-up burst as sustained speed. Dense initial exposure remains a separate cost and must not freeze ordinary connected play outside the admitted envelope.

For each completed native step/command, report source candidates and changed sources, actual observer/source updates, created values and bytes by facet, full-original materializations, attention description versus spatial recomputations, appended receipts, changed ownership roots versus scanned references, sealing/copying allocations, encoded segment bytes/rows, SQL statements/awaits, pending buffers, public section bytes and optional detail calls. Use CPU samples and explicit phase timings together; distinguish overlapping inclusive time from exclusive time and distinguish encoded size from heap.
