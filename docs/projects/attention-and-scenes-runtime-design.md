## 1. Outcome, evidence and scope

Characters should notice useful surroundings, remember a recently attended sequence, and act while other minds are thinking. Walking must not manufacture several copies of every observed movement. A long-lived character retains useful knowledge and selected memories, not a permanent map of everything that ever moved.

The [recorded baseline](../verification/attention-and-memory-core.md#final-runtime-comparison--october-29-2026) fails normal-speed acceptance. Its standard opening has seven people, twenty animals, 74 root objects and 163 total entities; the complete server achieved 0.771 normal speed over 30 real seconds with no model calls. Animals also move autonomously; “only the player moves” is not a valid description of that workload. More recent high-host-load diagnostic timings identify work, not a comparable throughput result.

A separate 60-game-second native recording census, without player commands, produced 977 personal recent receipts: 538 movement receipts, 361 terrain receipts, 60 facet-loss receipts and 18 other receipts. Movement repeated location, body pose and two-endpoint motion. The terrain total included 144 newly acquired patches and 217 repetitions linking old terrain to changed attention. Ten actual sight-loss transitions became sixty facet records. Receipt JSON occupied about 2.25 MB, versus about 168 KB of newly shared values. The receipt figure includes geometry/frames, not just metadata. These are recent records, not permanent memories. The census and complete-server profiles have different workloads and must not be added together.

The redesign removes those amplification mechanisms, rather than only packing them more tightly:

| Current cost                                                 | Selected replacement                                                                                             |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| Uniform three-game-second broad sight                        | Change-fed broad and detailed sampling with different world-owned rates                                          |
| Full current/detail work for every changed body              | Cheap broad membership/placement; field-specific updates; materialize rich detail only for its consumer          |
| Position + posed body + two-endpoint motion history          | One admitted sample; derive body placement and motion from personal samples                                      |
| Full confirmation/loss envelopes per facet                   | One receiver frame, sparse field changes and grouped availability transitions                                    |
| Ground subdivision and attention-dependent terrain baselines | Shared physical features, bounded personal contextual acquisition, independent feature timeline                  |
| Repeat world/entity scans and list creation for counts       | Maintained membership/count queries and changed/due participant cohorts                                          |
| Repeated freezing/copying of the same evidence               | One private batch writer, immutable chunks and one publication of changed owners                                 |
| Cold ownership discovery before ordinary commands            | Immediate logical retirement; indexed, bounded physical reclamation on the existing maintenance/application path |
| AI requests retaining old worlds                             | Finite actor-permitted request data and independent late-effect admission                                        |

Keep the working clock, physical action/collision rules, language semantics, local identity, knowledge support and selected recent-memory horizon. Change the visual sampling policy explicitly; it is no longer a promise to preserve every old three-game-second sample. Preserve exact values and order **at the newly specified received resolution**. Broader physical vision/acoustics, investigation/combat integration, PP07/SAI-A and social scenes retain their own delivery and acceptance.

### 1.1 Alternatives and selection

| Candidate                                                   | Advantage                                                                      | Rejection or selected use                                                                                                                                                                     |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pack today's receipts more tightly, keep uniform polling    | Smallest conversion; almost identical sampling                                 | Leaves unnecessary sight, loss, terrain and duplicate motion production in place. Insufficient root correction.                                                                               |
| Record all physical motion globally and query it later      | Simple shared route lookup                                                     | Wrong knowledge boundary, unlimited unrelated world history, complex retrospective visibility. Rejected.                                                                                      |
| Shared physical sample streams with personal ordinal ranges | Excellent compression when observers receive identical consecutive samples     | A range can accidentally grant intervening unseen samples; cadence/precision/gaps need a second selection language. Do not require it.                                                        |
| Observer delta frames referencing shared exact values       | Explicit personal acquisition; common headers once; generic field changes      | **Selected.** Add exact adjacent-run encoding only for measured repetition within this representation.                                                                                        |
| Predict every future sight crossing                         | Can avoid periodic candidate work                                              | Requires fragile predictions about motion, occluders, sense changes and world rules. Rejected.                                                                                                |
| Change-fed, periodically serviced sight                     | Actual writes provide invalidation; sampling bounds latency without prediction | **Selected.** A quiet unchanged region does no raycasts or record production. Required occurrences keep their actual event boundary.                                                          |
| Put all sensing/storage on workers                          | Moves foreground delay                                                         | Does not remove work; adds transfers, stale results and queues. Keep minimal acquisition native; defer optional work and physical cleanup. Add CPU offload only after a demonstrated benefit. |

The [research comparison](attention-and-scenes-research.md) remains supporting context. Neither research analogies nor these paper estimates establish game capacity.

## 2. Non-negotiable boundaries

These are the selected design's integrity requirements, not inherited prohibitions on changing its implementation.

1. One semantic owner admits received information. The same transaction updates current support, attention, admitted recent changes and required effects. No caller can create lasting memory by calling a “final confirmation” shortcut.
2. Share neutral data, never permission. A shared source/sample address grants no access. Resolve the actor/life-owned current or historical selection first; use its precision, modality, local correspondence and source revision.
3. A sample is not a continuous route. Preserve every admitted intermediate sample while retained, but never infer what happened between samples or across an unchecked interval. Do not infer an anvil destination from proximity.
4. Preserve independent freshness. Seeing a position again does not refresh a hidden face, item, name or activity. Validity/support and actual measurement time are distinct.
5. Required physical effects, actual speech reception and admitted obligations cannot disappear because optional attention, a query budget or a model is busy. Their existing finite admission owns overflow.
6. Optional thought does not hold the world. No model call per movement, sensing phase, forgotten detail or elapsed few seconds; keep existing justified causes, spending, capacity and no automatic paid retries.
7. One current format and one writable authority. Convert producers, readers, validators and saves together; no compatibility branch, old-store fallback or second scene/memory archive.
8. Exact personal logical retention, physical bytes and temporary buffers are separate charges. Sharing is not unlimited memory. Required exact support and optional fading keep their existing meaning.

## 3. Compact evidence from the first write

### 3.1 Representation and ownership

Extend the existing `perception-evidence`, `received-values`, `temporal-evidence` and current-format codec owners. The following are storage meanings inside those owners, not new services or parallel APIs.

| Owner                  | Stored data                                                                                                                                                       | Lifetime                                                                                               |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Shared received values | Immutable typed neutral values, including received precision/clipping variants; no observer identity or nested observations                                       | While a permitted current, recent or required owner needs the value; bounded reclamation lag afterward |
| Current personal track | Local track/body-life binding, current field references, per-field original support and measurement times, availability masks, latest two compatible pose samples | Current encounter plus independently retained minimum knowledge; no list of all prior poses            |
| Personal frame         | One acquisition time/order and observer-frame reference; small dictionaries of track/source/field references; ordered changes and availability transitions        | Admitted recent/required coverage                                                                      |
| Temporal chunk         | Actor/life/epoch header, ordered frames, dictionary and index metadata, exact byte/change totals and coverage bounds                                              | Preferred recent horizon subject to explicit optional limits                                           |
| Feature view           | Actual received feature variant, original support, supported validity intervals and later changes                                                                 | Independent of attention membership; retained only while current/recent/required ownership needs it    |
| Captured cut           | Finite selected personal records and deduplicated immutable values/frames/support                                                                                 | Request/capture owner and its explicit validity; never a pointer to an old whole world                 |

Use bounded per-chunk dictionaries to avoid repeating actor IDs, source IDs, field names and observer frames in every change. A frame entry is conceptually `(track, changedFieldMask, valueRefs, unequalSupportOverrides)`; an availability entry is `(track, affectedFieldMask, lastSupported, checkedAt, reason)`. Source identities include revision, body life and original field/occurrence ordinal where relevant. Dictionary compression must be exact and self-contained across cold reads. Numeric values remain exact; do not assume floating-point subtraction is lossless.

Acquisition time and default measurement/confirmation time may be carried once by the frame **only when equal**. Speech occurrence time, delayed receipt, an older inspection, a held appearance and a newly measured position can differ in the same frame. Encode those differences explicitly. Frames have deterministic order within equal game times. A current facet owns compact personal acquisition/support metadata directly, without requiring temporal admission. If history is admitted, its fact handle also addresses the exact frame/operation/field. Broad-only reception creates no recent frame solely to make provenance addressable. A still-current or required fact keeps its small original support/locator after a historical page expires, not the unrelated page or all sibling facts. Full original observations are selected read products.

Only an actual receiver result enters this owner. Preparing a physical value or finding a spatial candidate does not create history. Canonical world IDs stay inside bindings; public/model references remain observer-local. Sharing is keyed by the actual emitted typed value and source meaning, including uncertainty and variant—not merely by entity ID. Producer parameters and field codecs remain exhaustive typed families; do not introduce arbitrary JSON patches.

### 3.2 Exact headers, frames and freshness

A source-only move changes its pose fields. The observer's own move changes one receiver frame and affected spatial relations, not every stationary subject's outward appearance. Appearance, carried exposure, public attributes and identity each retain separate dependencies. Source confirmation updates a small current support watermark or exact confirmation run; it does not append a copy of the unchanged value.

An exact run can contain `first, step, count` only after each represented check actually completed under the same support and timing rule. A different timestamp, precision, dependency, missing check or availability change ends the run. There is no inference that all globally stored source samples between two received samples were seen. Repeated reads of held state produce no acquisition or confirmation. Unchanged physical dependencies can support reuse through the producer's certificate; that reuse keeps the original measurement time and exposes current validity separately.

Capture and correction use one typed dependency visitor shared by current evidence, temporal chunks, knowledge capsules and storage indexes. Preserve original and later confirming support, source aliases, modality, frames and independently timed fields. Ordinary motion consumers do not expand complete original observations. Exact inspection materializes only the selected permitted closure.

### 3.3 Acquisition to consumption, literally

At an acquisition boundary:

1. Read the existing native change feed and due observer work. Select candidates before source preparation.
2. Prepare each needed neutral source field once per actual revision/received variant. Determine individual reception using the installed sense and Perception rule.
3. Update changed current fields and support; emit small entered/changed/unavailable/confirmed results. Preserve needed old samples until recording admission completes.
4. Update attention from affected native scores. Record changes for subjects attended before **or** after the boundary, including a newly admitted baseline. Required occurrences use their independent source/consumer admission.
5. Append **one personal frame containing all admitted changes at this acquisition**, rather than one full receipt per subject/facet. A changed receiver frame is itself an admitted context change while relevant detailed/required history is active, even if stationary subjects changed no fields; record that frame once. Reuse neutral values. Apply lasting-memory admission independently; a frame is not a permanent memory.
6. Update exact ownership/count/index deltas, release replaced references and publish once at the coherent native boundary. Optional consumers select a finite permitted cut; no later world lookup repairs missing old evidence.

For example, an unknown person's three received placements reference P1, P2 and P3 in three frames. Their unchanged appearance is one A1 reference in the entry baseline. “Approaching” uses compatible P1/P3 plus the receiver's actual frames; the route reader can still return P2. Tool contact or speech enters its actual ordered event slot. There is no “approach episode,” no nearest-landmark label and no second motion payload. An independently received uncertain location remains a separate field if it differs from body placement; share only identical values.

Attention means the native detail allocation, whether chosen automatically or through an admitted focus request. It needs no watch action. Entry keeps the latest received baseline and future admitted changes. It does not read a pre-entry route from shared storage. A legitimately already-received two-point current motion baseline may remain, without granting earlier points.

### 3.4 One compact native current-evidence representation

Keep small current rows and append-only recent chunks under the same received-value owner. Current rows do not retain the entire recent window, and recent rows do not duplicate the whole current map. Materialized `ObservedBody`, full observations and motion are read products, not duplicate writable stores.

Split outward body data from placement. The received pose sample supplies only position, heading and support actually emitted by the sense, preserving unknown/coarse fields; outward data supplies dimensions, appearance, description, effects, quantities and the other existing fields. Audit all variants and readers. Derive motion from compatible adjacent personally received samples, with their original times/precision and continuity, for current views, native cues, player history and NPC context alike. This replaces stored `observed-motion` endpoint envelopes, not the ability to request motion. Ordinary elapsed time or a source moving between samples does not itself break body correspondence: compatible samples support net displacement and separation change, without proving a continuous path. Actual occlusion/correspondence uncertainty is separately marked and forbids unsupported cross-gap joins.

On sight failure, keep the last known values and update one availability transition for affected fields. If six fields lose visual support together, one mask closes them; hearing or a retained name may remain valid. An occluder/pose change can make support **unchecked** before the next measurement; it is not proof the target disappeared. Record the uncertainty boundary when needed for attended history. Later successful checks must not silently fill it. Distinguish actual failed sight, attention release, correspondence/body replacement, technical missing coverage and source correction.

Current last-known information and detailed history have different lifetimes. The attended deer’s last placement and gap remain queryable within retained coverage. An unattended deer's earlier route remains absent. Closed unattended current tracks release their fields after the existing bounded correspondence grace unless a real current/required owner remains. Attended last-known data is read from retained frames; deliberately learned knowledge has its own bounded owner. Do not retain a permanent last-known map of every tree or stranger. The identity owner decides whether reentry supports the same local individual; the history codec never joins tracks merely because raw source IDs match.

## 4. Change only the work whose input changed

### 4.1 Sight scheduling without predicting the future

Use the existing native semantic change feed, sensory index and due-work owner. A physical writer reports the changed entity/feature, affected fields and old/new bounds once. Do not add a second global event bus or saved visibility schedule.

- Source movement, spawning, removal, appearance and emitted light invalidate relevant source/observer relationships.
- Observer movement, gaze, life, detector/attribute or sense-policy changes invalidate that observer's affected view.
- Door, solid, terrain or other occluder changes invalidate observers whose bounded sensing region can intersect the changed occluding volume, including stationary observer/target pairs.
- Nonlocal authored dependencies declare their actual wider scope; conservative region/observer invalidation is preferable to false reuse.
- Actual speech/contact/effect occurrences dispatch through their present source owners at occurrence time. Visual sampling is not a hearing or collision timer.

Store a deduplicated dirty-observer set with dirty source/cell/field flags. Keep the earliest unproved-support invalidation time and conservative union of old/new/swept affected bounds until serviced, even if a door returns to its original pose. One bounded pending scope marker suffices; this is not a history of every physical mutation. Large dirty sets collapse to one “rescan this observer region” flag; they do not accumulate every intermediate world mutation. Keep occurrence order and already-admitted samples separately, so dirty coalescing cannot erase required events/history. Intersect conservative spatial bounds before exact visibility. Reuse static preparation; reject wholly outside/blocked hierarchy nodes only with valid conservative proof. Ambiguous candidates get the installed narrow sense calculation.

The [world profile](../worlds/base/attention.md#selected-acquisition-cadence) selects broad and detailed sampling periods. Due broad work discovers new bodies and updates coarse current coverage; due detailed work visits the small selected track set. Exclude already-detailed tracks from duplicate broad pose sampling; entry/removal and changed membership still update the common current view. One track has one latest personal sample, with its true time, regardless of which acquisition path supplied it. A required event or immediate action can perform its own current check without running a whole observer scene. Native animals use the same permitted sensed primitives through their existing controllers without acquiring a compulsory human recent-history/semantic-memory store. Broad acquisition includes the installed minimum detection/classification/placement and actually available recognition cues; recognition is not restricted to subjects already winning detail. Reuse unchanged acquired exemplars/description variants, and rerun recognition only when relevant evidence quality, correspondence or personal support changes. Fair discovery may request one eligible source's supported description even without a prior semantic interest match. Source fields not requested by a changed consumer are not hydrated merely to build a full observation. A consumer requesting an unacquired rich field must use the current sense acquisition/admission owner; coarse presence grants no direct read of hidden appearance, inventory or attributes. Reconstructing an already received field is a read; acquiring an additional field is a new personal receipt with its real time.

When nothing relevant changed, advance the owner's next due check without raycasts, descriptions or new records. Keep actual due expiries, finite unfinished discovery, priority/clear deadlines and required effects. A discovery continuation rotates fairly and stops when its current candidate pass is complete; missing unknown space is not endless work. No deadline is predicted from a future path or expected occlusion crossing.

Start with one aligned world phase per rate so observers can share the same source sample. Service its due observers in deterministic order through the existing bounded native continuation, and publish only a coherent completed boundary. Do not assign an arbitrary unique sampling instant to every observer: that defeats moving-value sharing. Add a fixed small number of phase buckets only if complete measurements justify reduced burst latency against additional distinct samples. Restore keeps actual phase/due state, not a new immediate synchronized burst. Acceleration advances these same game-time periods faster; pause stops them. Host milliseconds control execution yielding, not fictional evidence. Do not impose a hard wall-time cap that secretly skips required samples at faster clocks.

This deliberately permits a brief appearance wholly between broad samples to be missed. The detailed stream is reliable **at its sampled resolution**, not a perfect physical trajectory. Changed geometry invalidates a continuous-visibility claim even if a door changes twice before the next check. Collision, actual impacts and utterance reception remain exact under their own owners. Validate stealth/doorway play at the selected resolution; sampling frequency is not a substitute for those semantics.

### 4.2 Contextual terrain instead of a ground diary

Keep physical geometry in its existing map/support/solid owners and compiled spatial indexes. Replace observer-centred ground subdivision/recertification with selected **physical features**: visible support surfaces, solid outlines, boundaries, volumes and authored landmarks. Merge compatible planar geometry through existing preparation; never merge differing properties, holes or levels. Features need stable source/revision bindings, not new world entities.

Acquire a bounded personal feature view for self/current task, changed attended anchors, world-authored salient landmarks and explicit inspection. This native cheap context feeds existing relation cues **before** optional cognition. The selected world admits cue anchors from detail, self and actual work/required-cause targets under its shared relation budget; broad regions supply context without automatically creating a cue for every body. Detailed body slots cannot consume the whole static-context allowance. Do not traverse every ground patch, and do not re-record features when attention membership changes. Ordinary uniform support needs only the current received support/elevation answer; it creates no terrain history unless a retained observation, contextual query, place or required consumer actually needs that geometric fact. Prefer stable feature-local received extents already covering the requested neighborhood. Moving a query box must not automatically create a new polygon/fact: reuse a still-certified extent, derive distance from the new body sample, and acquire a different extent only when the consumer needs newly covered geometry. This prevents query-local clipping from becoming the old patch factory under a new name.

The sense producer still clips visible extents and supplies uncertainty. A full shared polygon may be used only if its emitted extent was actually received. A range/occlusion boundary is a coverage limit, not a cliff. A drop measurement needs received near/far support; unseen terrain is unknown. Native route/physics queries may have their own permitted physical inputs, but cannot expose their hidden map to a personal context reader.

Context selects bounded nearest/support/boundary reads around anchors using existing indexes, early feature-family filters and conservative distance bounds. Include the existing supported native-cue anchors and coarse broad-region context, not only individually detailed bodies; a relevant received ground boundary must not depend on winning a body slot. Union/deduplicate candidate features and requested local extents across anchors before expensive sensing. A certified extent can serve several anchors without repeated clipping or another personal record. For each candidate, intersect the query-local region of interest with its physical feature, receptor view and range. Reuse the physical owner's finite convex decomposition; certify each emitted interior against all relevant intervening occluders, not just polygon corners. Split only query-local ambiguous pieces within the installed geometry work/error bounds. Uncertified fringe or exhausted work stays unknown. Bound candidate/index/occluder visits, clipping operations and output bytes; do not preserve an unfinished whole-field-of-view rectangle grid. A very large floor with one blocker must neither reveal its hidden extent nor disappear wholesale when a visible local piece can be certified. World policy owns useful terrain/material/landmark distinctions and which native activities request them: concealment, cover, elevation, food or route context are examples, not engine scenario rules. Existing thought can choose an explicit supported focus/query; do not parse an arbitrary personality into an object catalogue each sensing step.

Store a feature's neutral geometry once per exact received variant and its personal acquisition/validity interval once. Historical context joins personally retained sample times with those intervals. It never attaches all terrain to each person or fills old gaps from today's map. Required place knowledge or a chosen lasting recollection retains only its minimum support. An inferred kitchen classification is a supported personal belief, not automatic knowledge of the author's room name.

### 4.3 Lists, cohorts and downstream reuse

Extend existing indexes rather than cache arbitrary arrays keyed by whole-world identity.

| Consumer                   | Required query/invalidation                                                                                                                   |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Root/entity capacity       | O(1) maintained root/entity counts; indexed ID iterator only when actual entities are needed                                                  |
| Sensory participants       | Installed eligible observer membership; change on life/sense/role, not every clock tick                                                       |
| Moving/action participants | Existing active action/motion membership and due boundaries; reuse within the native batch                                                    |
| Status/rates               | Existing participant and definition preparation; touch affected/due actors and actual changed values                                          |
| Animal decisions           | Existing eligible/controller/due-work index; changed food/threat/body inputs invalidate relevant choices                                      |
| Attention                  | Cache description, familiarity, spatial score and priority expiry separately; recompute changed components and final selection only as needed |
| Public/UI views            | Changed personal pose/support/identity/control sections; optional inventory/trade detail only for its actual open reader                      |

Counts update atomically with insertion/removal/root membership, including custody changes, death/body-role changes where applicable, raw construction and restoration. A derived index has one rebuild at a real load/foreign-input boundary and exact owner deltas afterward. Its absence is not an empty world. Preserve existing deterministic order where iteration matters; do not create a fresh list merely to get its length.

A sensory deadline must not trigger unrelated status/action/controller preparation for all 163 records. Reuse installed definition preparation and the already existing elapsed-value machinery; do not introduce a universal future-event predictor or a second rate engine. Animal/status scans were secondary in the measured tiny world; their redesign is precise reuse, not a claim they caused most of the slowdown.

## 5. Seal once and account for ownership incrementally

### 5.1 Immutable publication

Retain one private working world per native batch and the last completed world for readers. There is already no world copy per actor. The host's 50 ms wake, native game-time sensing deadlines, coherent publication, durable progress-save cadence and optional network delivery are different clocks. The 905 current-map copies and 3,644 sealed evidence-owner structures in the diagnostic run were in-memory containers; they were not that many database saves.

Apply all actor/source changes to the same writer. Publish only on a coherent boundary, coalescing within the existing yield/return policy. Seal new leaves once, freeze the changed container once and reuse proven immutable children. No full history traversal for a pose update. A nested preview captures only the finite data its reader needs; it must not freeze a parent's working buffers or force an entire interim world publication.

Use the existing owned-builder/lineage mechanism. Do not replace the whole engine with an ECS or add a persistent-map library before the compact row/chunk conversion is measured. Large append history belongs in immutable bounded segments with a small current tail; a pending model/save/view job never retains a chain of old worlds. Foreign/raw/restored values retain full current-format validation. A shallow freeze or a boolean “trusted” flag is not proof of safe children.

### 5.2 One derived resident reference index

Logical permission ends at the accepted expiry/correction/forgetting boundary. Remove affected personal rows/index membership, advance privacy/source generations and reject stale current/cold/request access immediately. **Physical deletion is separate maintenance, never a cold-history scan required merely to accept ordinary movement.** This supersedes the earlier rule requiring every unowned value to be reclaimed in that same command's application.

The existing received-value/reference owner updates exact resident reference deltas from changed roots and appended/retired chunk ranges. Persist canonical receipt/segment membership and retirement candidates through the existing journal/application owner. Candidate identity is an existing source block/segment plus generation/range, not one independent job per coordinate. Persist pending cleanup state and its cursor in the existing retention/application records before deleting the final owner row; keep it until physical completion. Journal-prefix pruning cannot erase its only copy. If that owner cannot yet persist independent completion, finish deletion inside its bounded application transaction before retiring the batch. A prose promise to reconstruct already-deleted metadata is insufficient. Coalesce candidates, retain a restartable bounded cursor, and reconstruct work from retired/expired segment metadata after restart. No separate message broker, lifetime tombstone ledger or second writable reference-count authority.

Maintenance runs after required application work, in bounded transactions. It filters exact candidate blocks/ordinals **before** expansion, checks current/cold retained ownership plus not-yet-applied accepted references, and releases only unowned payload. A single value kept by another witness must not pin expired siblings. Stable ordinals are never reused. A reference's last release schedules reconsideration even if an earlier pass found it still retained.

Serialize deletion admission through the existing world/save authority: select candidates outside the gameplay lane; briefly capture/validate affected-owner generations and pending accepted suffixes; apply the bounded deletion with the writer/worker's normal fences. Never decide from an unchecked SQL snapshot while newer references exist only in the journal or resident world. Conflicts retry that bounded maintenance batch; they do not restart all-world cleanup or hold unrelated commands. New references require a current personal grant; an old address cannot resurrect retired data.

Keep physical unreclaimed bytes, maintenance scratch and backlog charged until actual reclamation. At pressure, stop new optional history admission/shorten explicitly reported optional coverage and drain bounded cleanup. Preserve required headroom; if required durable work cannot fit, use existing truthful pre-installation admission failure. A permanently stalled collector fails qualification even if commands initially feel fast. Current-format restore, checkpoint and privacy erasure include logical generations and pending retirement state. Ordinary expiry may lag physically; explicit privacy erasure acknowledges completion only after its existing storage/snapshot obligations finish.

## 6. Append storage and a short durable command barrier

### 6.1 Segmented physical layout

Reuse the existing temporal-chunk, shared-value block and segmented-storage owners; redefine the current logical temporal chunk as personal frames/checkpoints with stable fact addresses. Preserve actual occurrence/source ordering and supported alias lookup, not the old receipt DTOs, serialized IDs or format for compatibility. Fill a logical temporal chunk up to its existing complete byte allowance across simulation timestamps; every frame operation retains its exact time and order. A timestamp change does not require a new chunk. Expiry and count/byte pressure remove the exact old prefix, including inside a partly retained chunk, without pinning expired siblings. Change their existing `world-record-schema.ts`/`temporal-storage.ts` codec to store immutable suffix segments. Use one narrow helper for the two actual append collections: temporal receipts and received values. Do not add one SQL row per coordinate or rewrite the entire growing chunk.

Each physical segment has its existing parent identity, first ordinal, exclusive end ordinal, exact encoded size and reference metadata. Its primary identity is parent plus first ordinal under the existing identity contract. Seal a suffix at a durable preparation boundary, splitting at existing byte/count bounds. Do not keep reopening the last stored segment to add one item. Small parent headers retain counts and index ranges. Existing capture-watermark identities become child records, so changing one watermark does not rewrite an actor's whole map.

Preparation compares an exact accepted baseline with a frozen next snapshot. Proven append lineage reuses all stored segment descriptors and emits only the new suffix. The prepared-commit token owns newly assigned physical layout until acceptance. Attach reusable layout metadata to immutable collections through the existing record/history codec mechanism. A failed/uncertain retry must recover that exact prepared outcome before assigning another layout; it cannot generate duplicate suffixes. Queued preparation must carry the accepted predecessor's layout even while normalized tables lag.

Replacement, correction and partial deletion use the same codec's affected-segment replacement path; they are not append operations. Stable ordinal coverage includes explicit retired slots where the logical model permits them. Current-format decoding checks disjoint contiguous coverage of the declared range, permitted holes, header totals, payload shape, ownership and complete references before reconstructing the same logical collection. Restoring never re-executes commands to rebuild evidence. Cold queries filter actor/life/subject/time metadata before hydrating only the requested closure.

The growing alias/subject/individual/value-reference unions and receipt index belong on the existing immutable receipt-segment rows, prepared once per changed page through the existing semantic dependency visitors. Keep only bounded actor/life/epoch/time/order/range/count/byte and physical-page totals in the mutable parent storage header. The new frame/checkpoint logical chunk retains complete logical charging; its replacement schema updates all native/current-format readers together. The selected full-chunk reader reconstructs its logical unions; ordinary selectors use indexed `EXISTS` against pages before hydration, never aggregate all parent payload merely to filter. Preserve the existing actor/source/life/time fences and metadata/preparation limits. Correction and pruning replace only affected pages and their indexes atomically with the journal; no duplicate source store or migration reader is added. Extend the existing codec's preparation boundary to receive exact source support rather than inventing aliases from partial receipt metadata.

Keep exact page aliases, subjects, individuals and value references, but index their namespaced lookup keys through one deterministic 16,384-bucket `SMALLINT[]` filter. PostgreSQL GIN retains dictionary keys after their last posting disappears; indexing ever-new receipt aliases directly therefore retains historical key space after expiry. The fixed bucket vocabulary bounds that dictionary. Every bucket match must also satisfy the original exact array predicate and existing actor/life/time scope; collisions add candidates, never evidence or authority. One shared helper prepares page and query buckets. Include this derived field in encoded-byte admission and current-format validation; replace affected pages and their filter atomically. Retention still deletes postings through ordinary PostgreSQL maintenance, with no per-step reindexing or new alias store. Qualification must measure refill/prune index reuse and collision-heavy exact reads, not infer physical boundedness from logical deletion.

### 6.1.1 Page checkpoints and exact selection

Each temporal page carries a compact checkpoint for only the tracks/features referenced in that page: existing value references, original personal fact handles, original unequal measurement times and availability at the page start. It carries no payload copies, whole broad scene or chain of older page dependencies. Checkpoint size counts toward the page allowance and real ownership. A single indivisible required event keeps its existing complete admission; an optional page that cannot fit its checkpoint must split or narrow recording with explicit coverage, never omit necessary support silently.

Cold selection filters actor/life/epoch, local subject, time and retention class before decoding selected pages. Replay starts at that page's checkpoint and is bounded by admitted page/byte limits. A checkpoint is historical reconstruction state, not a new measurement or renewed memory. Partial prefix expiry keeps only the minimal baseline needed to interpret the retained suffix, with original times; baseline-only references are not independently searchable earlier history or motion endpoints outside admitted coverage, and support must cover the requested retained time; it cannot reveal earlier removed samples or keep all prior pages alive. Exact event and personal fact addresses remain stable through page pruning. Correcting an original fact reaches carried checkpoints and dependent capsules through the shared dependency visitor.

Use one codec/materializer for current capture, recent/history queries, required support, save/load and source correction. Remove old per-receipt envelope indexes where frame/operation addressing replaces them, but retain indexed original-revision/alias lookup required by real existing consumers. Count examination of individual operations/fields and checkpoint entries, not just enclosing frames, against the history preparation allowance. A 128-item query may not hide thousands of changes inside 128 frames. The retained change quota counts field assignments, availability transitions, required occurrences and other logical operations; headers/checkpoints and all references also count toward complete byte accounting. The first implementation needs explicit frame entries and dictionaries; optional lossless run encoding decodes the same personal sequence and is not a new permission mechanism.

### 6.2 Acceptance and background application

Reuse the existing [durable journal](performance-overhaul/journal-contract.md), world mutation lane, application worker and read fences:

1. Enter the mutation lane and validate the command and authority against the current world.
2. Complete its required native transition, including exact admitted personal frames and earlier unsaved native progress covered by this save. Seal only changed leaves and capture the expected durable predecessor.
3. Prepare compact changed records, receipt/source plans and new suffix segments. Reuse validated column extraction and encoded values; do not immediately decode the encoder's own output and repeat its complete validation.
4. In one short database transaction, check mutable authority, world/generation/predecessor, command receipt and applicable real constraints; durably append the complete exact change description and receipt and advance the committed revision.
5. Only after successful COMMIT, install the accepted candidate and acknowledge it. Release mutation ownership so the world and subsequent commands can continue.
6. The existing worker applies accepted changes in order to ordinary tables and optional indexes. Completion advances applied coverage. **It never reinstalls the older captured world.**
7. Table-backed readers fence to their captured committed revision, then verify generation and applied coverage in their read snapshot. Wait outside the world mutation lane; recheck any authority/action prerequisites before using a delayed read to mutate the world.

Native progress already continues during a background progress save. Preserve that owner and its honest durable coverage. Do not release the current command save's lock around its existing await: that code subsequently installs an old captured candidate and could overwrite newer simulation. The selected fix is a shorter durable barrier, not published speculative command effects or rollback descendants.

### 6.3 Bounded proof-based admission

Keep the existing 512 indexed constraint-probe ceiling, 32 unapplied revisions, 32 MiB encoded debt, one worker and at most eight accepted revisions per online application batch. The selected change is to stop treating every safely owned append row as an independent unknown SQL constraint, not to raise the limits.

For owner-produced suffixes, prove the parent/generation, exact accepted predecessor, deterministic identity construction and non-overlapping successor range once per changed parent. Within that proof, validate ordinal coverage and schema locally; no separate SQL membership probe is needed for each contained receipt/value. Externally supplied identities, unsupported unique constraints, referenced physical parents and mutable authority still receive their real bounded indexed checks. Unknown/destructive families keep the existing synchronous atomic writer until their semantics are explicitly covered. SQL constraints still apply during ordered application; admission must have proved they cannot fail from an already accepted predecessor.

The record schema may explicitly identify a collection whose entire canonical membership stays resident across saving, compaction and loading. For such immutable collections, the codec can prove new identities absent from the exact accepted predecessor and derive unique final positions without SQL re-probes. Apply this to current perception collections and capture watermarks; never infer completeness for cold history or shared-value pools. Keep contradictory pending identities, positions and ancestor deletions checked even when SQL is unnecessary. Foreign baselines, mutable collections and unsupported constraints retain full admission.

Separate **physical reclamation of unowned payload** from semantic correction/forgetting. Ordinary command preparation nominates candidates and applies logical owner changes; it does not perform cold ownership proof. Section 5.2 moves that exact proof and physical pruning to bounded existing maintenance/application work. Semantic source withdrawal and privacy obligations retain their own atomic admission/fencing. Preserve delivered append-admission proofs; do not special-case movement or treat an unverified candidate as a proven delete.

Only the semantic owner's prepared object can carry reusable validation proof; no public boolean bypass. Persisted journal recovery and foreign/current-format input receive full validation. Keep statement/byte bounds and truthful busy/admission behavior. If one transition or outstanding debt exceeds a bound, drain or use the existing synchronous path before acceptance; never partially accept required evidence.

### 6.4 Bound pending memory and recover exactly

After preparing complete application inputs, pending entries retain changed records, exact personal source plans and small revision metadata. Preserve the delivered compact pending-write path (`CompactJournalWrite` / `JournalTables`): do not reintroduce full `before`, `state` or `historyAfter` roots into online journal entries. Keep the current world, required durable baseline and at most one active preparation; do not keep 32 full world generations merely because encoded journal debt is under 32 MiB.

Account separately for encoded debt, decoded/prepared application inputs and one worker batch, including duplicated buffers during handoff. Existing count/byte bounds remain provisional, not a heap-capacity claim. Use measured memory to select an additional preparation-byte bound only if the compact inputs still exceed the existing operating envelope; record that operational decision in the persistence limits owner before relying on it.

Append failure leaves the preceding accepted command state. An ambiguous COMMIT is resolved through the exact receipt/head recovery owner without rerunning the command. Worker failure preserves accepted journal data and stops new save admission under the existing sticky-failure contract. Lost completion requires fencing the previous writer and proving durable generation/applied coverage before publishing completion once. Restore, checkpoint and shutdown use existing drain barriers; old-generation completions cannot mutate the restored world. Rebuild derived indexes after restore.

## 7. World advancement and asynchronous cognition

### 7.1 What finishes when

| Before the next coherent native boundary is published                                         | May finish after the world advances                                                                |
| --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Due movement/collision, harm, status changes and action completions                           | Model context formatting/hydration after capacity admission, model inference                       |
| Due minimal sensing, compact personal deltas and current support/availability                 | Optional interpretation, useful-account consolidation, embeddings and narration                    |
| Attention membership needed to determine admitted recording; required temporal/source support | Expensive optional source/history readers and selected menu/trade details                          |
| Installed native protection, relation/latch changes and required knowledge/correction         | Formatting/coalesced delivery of public views; ordinary-table application after durable acceptance |
| Command's short durable acceptance barrier before its acknowledgement                         | Bounded physical reclamation after logical expiry/revocation                                       |

The AI director already runs calls asynchronously. This is not a new model execution system. Bounded native feature context feeds existing cues before admission; richer optional feature queries and formatting run after publication through existing task lanes. They capture finite relevant geometry and permitted anchors, never a world. No dedicated CPU worker is required initially; only introduce offload if measured saved foreground CPU exceeds capture/transfer/queue cost under the same exact-input contract. Audit all actual callers to prevent optional SQL, public presentation or provider work from becoming an indirect world-mutation wait. Optional geometry work distinguishes materializing already received facts from acquiring new detail. A new result computed from a finite earlier sensing input retains that measurement time and a separate actual personal-availability time when admitted. It cannot enter an earlier cut, claim the actor reacted before it arrived or become current after its physical/sense dependencies changed. Preserve it as historical received support only when the captured acquisition and current source/privacy/lifetime checks authorize that meaning; otherwise discard it. Coalesce unstarted replaceable optional requests by actor/scope through existing task bounds; never coalesce already-admitted history or required occurrences. Making a synchronous copy/serialization function `async` does not move its CPU cost off the event loop. Reduce that work first; reuse the existing bounded worker only for its actual storage responsibilities.

### 7.2 Exact request/answer sequence

1. An existing justified cause offers an actor work item. Coalesce through `ActorWork`/thought intake; do not create a ticket for each motion sample.
2. Admit existing actor/world/provider/spending capacity before expensive optional hydration. Keep the actual cause and its source watermark. A busy actor's genuinely newer causes remain pending for the next justified opportunity; use the existing generation/acknowledgement rules so completion cannot clear a newer cause.
3. Capture bounded actor-permitted current/recent evidence and exact source dependencies. Keep finite request-owned copies, not a whole-world snapshot. Apply existing private retrieval fences. An in-flight copy does not extend optional source retention or defeat later correction.
4. Release the world lane before model execution. Native movement, other actors, sensing and saving continue. A character's already admitted native activity continues under its existing interruption rules.
5. When a result returns, use existing decision validity/publication owners to check actor/life/control/timeline, original deadline, exact retained sources, current grants and current effect-specific prerequisites. An unrelated world revision does not by itself invalidate the result.
6. Admit supported physical proposals against the **current** world. A still-valid remembered interpretation and a now-impossible physical action can have different validity under existing answer-group rules. Do not discard valid history solely because somebody walked elsewhere; do not execute a stale action because its prose is sensible.
7. Commit permitted effects once through ordinary semantic owners and saving. Rejected/expired work does not automatically start another paid call. Cancellation that has not actually settled still owns capacity and real cost.

**Outstanding request-memory conversion (SR05, continuing R5):** Optional waits release native advancement, but prepared requests still retain an entire old immutable world through the situation object and callbacks. This pins unrelated data; it is not a deep copy and is never the model's input. R5 remains incomplete until these existing owners use finite captured data:

- Replace the situation object's world and world-reading callbacks with its existing current/acquired cut, received scene/geometry, bounded history/prefix, frame dictionary, attention state and exact handle-to-body-lease/individual/episode bindings. Index current facts by subject during cut capture; reuse materialized values for body facts, expansion and history binding.
- Give evidence formatting a narrow captured reference/label scope containing world ID, acquired labels/handles, frames and source tokens. Expanded body grants use the captured binding table, never an old or later physical world. Do not cast a partial object as a world.
- Replace the history-reader callback's captured world with a typed actor-scoped resident-history/value closure plus existing SQL scope/prefix. Preserve accepted/applied revision, generation, exact source, logical-expiry and privacy fences; do not omit resident evidence.
- Audit returned decision/conversation callbacks and appraisal frame formatting, which also capture the world. Build callbacks in separate factories accepting only finite data/proofs and the live service authority; deleting one property or using weak references does not remove the other strong references.

Held direct, higher and reflection requests must retain equal current/history/boundary/query output and attribution; correction, expiry and restoration must still withdraw grants while native progress continues. A reachability/retained-heap specimen must show that unrelated old world data can be collected, with request data bounded by the existing preparation allowances.

Preserve existing cause-specific immediate/useful-lifetime limits and generator timeouts; an original deadline includes follow-up work. Do not universalize a particular current 31-second usefulness limit or 35-second generator timeout. There is no promise that every unfamiliar danger is understood before harm occurs. The selected few-second aspiration begins at justified admission and remains subject to actual capacity and human-like misses.

**Example, preserving existing supported mechanics:** a parent receives their daughter's motion, the broad presence of 15 pursuers and a supported drop edge. Detailed attention determines retained fine history, not who physically exists. The native scene/relation owners prepare the existing received spatial evidence; no new daughter/cliff-specific rule is introduced here. Native installed reactions and physical movement continue before an AI returns. A late warning or rescue proposal is admitted only if its present preconditions hold. If harm has already happened, the answer cannot retroactively prevent it. Full new combat/protection mechanics remain separately scoped.

### 7.3 Failures must stop the right work

Classify errors at the owning boundary. A proven optional reader/view-formatting failure invalidates that reader or closes its affected stream with a truthful recoverable error; it does not become a global storage error that pauses every character. Log the exact failing stage and permit a fresh bounded read when appropriate. A failed authoritative save, corrupted authoritative input or unsafe native invariant retains its existing stop/recovery behavior. Do not blanket-catch and ignore unknown errors or continue a partially executed transition.

## 8. Public views and optional readers

Extend existing `ViewCache`, public projection and scoped readers, not a new cache service. Split dependencies for received pose, descriptive details, identity/art, controls, event windows and compact trade availability. Keys include actual owner/source revisions plus viewer/life/control/grant scope and relevant installed definitions. Never use outer world-object identity as the only invalidation signal, and never reuse another observer's private result.

Movement updates pose/current evidence sections. Reuse unchanged descriptive and inventory sections. Corrections, forgotten information, control changes and privacy revocation invalidate affected cached sections before delivery. Cache equality cannot be inferred only from a neutral value pointer when personal freshness or permission changed.

Keep a cheap trade availability/title/offer summary in the ordinary view. Prepare full handover options, inventory lots and trade details only for an opened reader. Reuse existing actions, inventory and trade-disclosure endpoints; add only a missing narrow read of the existing trade-view owner if necessary. Under slow delivery, skip superseded optional view construction, never native evidence or a required command result. An unchanged section should not be re-encoded. Do not enqueue one full public snapshot per native sample.

Preserve delivered R6 event collection: each existing journal/conversation window admits its own bounded members before their ordered union. Use stable keyed event additions, changes, removals and order updates in the current protocol where the existing patch owner supports them; extend that owner if its only operation replaces the whole array. A reset still reconstructs the complete bounded current view. Correction/history-epoch changes clear obsolete replay. Update server and client together without an old-wire adapter. Before reporting transfer savings, correct the measurement's `snapshot` versus actual `reset` event classification and measure bytes by section; the earlier total stream measurements do not establish exact patch amplification.

### 10.2 Measurements and pass conditions

**Work model.** With N observers, S nearby sources, K detailed subjects and rates B/D, candidate work is approximately changed broad pairs × B plus changed detailed pairs × D, reduced by spatial rejection and dependency reuse. It is not O(K) for the whole game. At 300 observers and 300 mutually relevant sources, four broad opportunities per normal second can still expose 360,000 coarse pairs/second; 10 detailed subjects at ten opportunities add up to 30,000 personal associations/second. Shared values remove duplicate payload, not those genuine permissions. The detailed estimate is a conservative upper bound; detailed tracks bypass duplicate broad pose refresh.

Frame headers occur once per receiver opportunity with admitted changes; unchanged values do not produce field entries. As an **illustrative codec budget**, 12–24 bytes per compact pose association would mean 360–720 KB/second for those 30,000 associations, before frame headers, actual shared poses, indexes, JSON/SQL and allocation overhead. This is a design estimate, not an achieved binary codec or a claim about actual JSON sizes. Measure the real encoding; do not raise quotas to hide expansion. A six-minute normal-play recent window can therefore still occupy substantial aggregate cold storage. Keep bounded resident tails and indexed reads; do not keep everyone's full window in each world snapshot.

A quiet unchanged region should create no visual values/history and do no narrow sight tests. Work proportional to actual required occurrences remains. No-loop goals are concrete: no motion-pair payload, no unchanged description regeneration from observer movement, no attention-triggered terrain baselines, no per-field loss envelopes, no list allocation for a count, no ordinary command's cold ownership query, no retained whole world in an optional request.

**Qualification order and workload:**

1. **Required pass — normal opening:** exact standard combined authored opening, actual configured 1×, cold start separately then at least five real minutes warm with walking, ordinary animal work, speech and current player views. Use scripted real-time command arrivals, including a burst; disable/hold providers for the native/storage attribution run, then exercise ordinary funded cognition separately. Existing required normal-clock/latency gates remain; additionally achieve at least 0.98 of requested sustained progress without growing debt. Report pauses, technical holds and admission failures rather than removing them from elapsed time.
2. **Required pass — substantial active scene:** 100 people, 100 animals and 200 root objects in the bounded scene, with 100 eligible human observers and realistic moving/occluding/working cohorts. Qualify both one controlled player with autonomous residents and 25 controlled people with 75 residents. Use real connected authorized projection streams for the latter, one movement intention/second per controlled actor, and continuing native routes between intentions. Idle scenery or headless unused people cannot stand in for this workload. Run at least five real minutes at 1×; meet the same progress and existing command-delivery gates. This is the selected first operating envelope, not a universal population cap.
3. **Required measurements — headroom, larger scene and faster clock:** repeat the standard/substantial workloads at 1.25× and 3×; measure a 300-active-actor scene split between 100 controlled people, 100 autonomous people and 100 animals, with 100 authorized streams and real command traffic. Record the achieved envelope, p50/p95/p99/worst command latency, admission and backlog. These do not silently become a claim of 300-player or 3× support. Failure identifies the next concrete bottleneck; it cannot excuse a failed required workload.
4. **Required pass — retention lifecycle; required measurement — age:** refill/expire the selected recent horizon repeatedly with multiple actors, shared/variant values, sparse required survivors, cold concurrent queries and interrupted cleanup. Active row/reference counts, resident memory and pending debt reach a bounded steady range. PostgreSQL payload/index bloat must be reclaimable/reused under ordinary maintenance. Separately construct ten-game-year retained-owner distributions through valid setup and report all optional/required/audit/save families; no synthetic age test proves ten years of enjoyable live play.
5. **Required checks:** current-format initialization/combined starting content, actual browser producer-to-consumer journey, affected live-model semantics under the real shared budget, full required regression/type/build checks, source review and documentation reconciliation. Renderer measurements are separate from server/native capacity. No provider-fixture output establishes actual model quality or human enjoyment.

Declare hardware, source commit, actor mix, motion/work/command rates, observer overlap, diagnostics, DB/cache state and concurrent host load. Repeat matched runs for variance; do not select only a favorable result. Compare both total work and player-visible cost. The new sampling policy intentionally differs from baseline, so report its input counts and brief-visibility/route-resolution tradeoff alongside throughput; do not attribute every gain to encoding.

Instrument: shared source preparation; coarse/narrow sight candidates; changed current fields; admitted frame operations by family; geometry queries/variants; attention component updates; map/container copies and seals; SQL/admission/cleanup batches; logical/physical/index and pending bytes; public section bytes; optional context/model preparation/wait/publication; true game progress. Distinguish inclusive overlapping timing from exclusive CPU and encoded bytes from heap. Finish required failure fixes before claiming merge readiness; do not convert unmet passes into measurements after seeing the result.

## 11. Decisions and remaining work

**Selected design decisions:** replace uniform broad sampling with change-fed broad/detail rates; replace nested receipts with personal delta frames referencing shared exact values; derive motion; group availability changes; acquire relevant physical features rather than routine ground patches; retain page-local historical checkpoints; keep one writer and existing persistence/AI scheduling; move bounded physical reclamation off ordinary command preparation; finish finite optional request capture. Preserve the present physical clock/actions, detail capacity, preferred recent horizon and lasting-retention policy. Exact numerical targets and their tradeoffs belong to the world/limits owners.

**Review record, 2026-10-29:** independent construction compared sensing, history/storage and contextual/AI alternatives. Integrated-contract review checks the complete acquisition-to-save-to-consumer path; final review checks cross-document consistency, adversarial gameplay, lifecycle and total work. These are design reviews, not runtime evidence; unresolved findings must be fixed before the design handoff.

No product choice needs Mike to unblock this proposal. The selected rates and operating envelope are explicit, reversible engineering choices that require the stated implementation qualification.
