## Boundary and implementation order

Keep one world writer. Link the existing [simulation crate](../../native/simulation/src/lib.rs) into a new server crate in the [same Cargo workspace](../../native/Cargo.toml). Keep I/O, real time, credentials and provider clients out of the deterministic simulation. The server owns authentication, request and clock scheduling, permitted presentation, provider execution, SQL and sockets. These responsibilities do not require a second language or a second process. World vocabulary, definitions, reasons for decisions, activity rules and animal policy still come from the [installed world](../../packages/domain/src/worlds/base/native/). Build and ship its reviewed definitions once. A Rust module may implement a world rule without making it an engine default.

The TypeScript reference is called **Source** in existing evidence. Today [main.ts](../../apps/server/src/main.ts) selects TypeScript or the Node-hosted Rust proof. The latter already has a [Rust session and save handle](../../native/simulation/src/runtime.rs), [candidate and disclosure fence](../../native/simulation/src/host.rs), and a [bounded compute pool](../../native/node-bridge/src/pool.rs). Move the Node-independent pool/dispatcher ownership out of the addon when the executable needs it. Keep Node conversion at the addon's edge. Use ordinary modules for HTTP/access, provider, spatial and store operations within the server. One async I/O runtime and the existing bounded compute pool suffice. Never start a pool per world, socket, reader or model request. Link the server directly to the simulation. Keep the executable entry point thin. Share code below the addon only when both real hosts use it. The Rust server library must not depend on N-API.

Keep TypeScript and the existing mixed server available for the final comparison. Build the stand-alone server directly against the Rust simulation. Avoid temporary Node adapters, runtime switches or deliberately inefficient implementations solely to time a port. Encode at an actual network, storage or hashing boundary. Avoid per-field calls and internal JSON round trips. Before each port, record its callers, selected fields, failures and indirect consumers in the parent coverage inventory. One owner submits each effect, command receipt, provider request or transaction. Refuse unsupported operations explicitly.

For example, the HTTP handler verifies who controls a body. The simulation accepts the walk, identifies its changed rows and wakes the view publisher. The publisher checks what each observer may see. The save and the browser update can finish in either order. A route finder supplies a path without choosing who may walk it, and a provider supplies a proposal without authorizing its effects. Keeping these responsibilities separate inside Rust avoids another service hop. It also makes their resource isolation important. A slow socket or a large save must leave room for the next command.

Keep one authored source for each rule or template and use build-time exports or generated types when two hosts consume it. Exercise the same browser and actual provider contract against both. Frozen controls support comparison. Retire superseded owners under the parent adoption gates. The [development data policy](../../AGENTS.md#development-save-policy) permits fresh development databases and excludes legacy readers, permanent dual writes and compatibility-only adapters.

A **cut** identifies one accepted point in a particular world and generation. A **prefix** is the consecutive group of accepted changes covered by one save. A **receipt** is the stored result bound to a request ID. Reading an old cut, holding a result in memory, having permission to deliver it now and having committed it to disk are four different facts.

## 2. Start the process and run a world (RGS02)

First drive the extracted host from both the existing addon and a release executable against the same accepted world. Reuse candidate begin, prepare, ready, accept/reject and rollback. Stage all fallible work and output custody before changing accepted state. Admit one mutating turn per world before dispatch to compute workers. Immutable view, save or model work can proceed independently once it owns its input. A database read or external answer may suspend an operation. Release its worker and borrowed world data. A pending candidate retains its exclusive right to accept or roll back, so another mutation cannot pass it. Serve an independent read of the last accepted state only when its owner can prove that isolation. A long-running NPC request holds evidence and a job, never an open world mutation. On return, bind to the same world, writer generation, candidate and source. Keep original RNG order and identifiers, elapsed-time offers, accepted prefix, debt, ordinary pause/absence, cancellation, poison and shutdown behavior. Use monotonic time in the host and installed rules for game time.

Start at `prepared_products` in the [current Rust session](../../native/simulation/src/runtime.rs). Its Rust wrapper already encodes operation results, history, notices and changed records into one JSON product before handing them to the addon. Split there. Let the Rust application borrow the prepared fields until settlement and take funded ownership of only the parts it must keep afterward. Retain the encoded handoff for the Node caller. Both paths must acquire their actual output storage before Ready and settle through the same candidate key. Refuse at that boundary and prove exact rollback and retry through both hosts. Use a focused caller trace to confirm the stand-alone path never constructs the addon packet.

The present proof calls [geometry and navigation](../../apps/server/src/native-geometry.ts) and [route continuation](../../apps/server/src/native-navigation.ts) in Node. Inventory actual selected requests, including presentation geometry. Supply the same installed map, query batches, units, collision shapes, ordering, versioned navigation inputs and source/pose certificates to a Rust host implementation. Reuse the pinned Rapier and Recast/Detour behavior or their already-built artifacts via a verified Node-free binding. Distinguish physics/navigation computations from the world's decision to flee, move or perceive. Tie results to their original inputs. Port only reachable queries, with no straight-line, always-visible or empty answer fallback. Compare actual hits, ordering, routes, animal reactions, resulting records and reject/replay after stale or refused answers. Use the equivalent supported backend directly. If the available binding requires materially different geometry, ordering or copying, qualify that difference against the existing spatial caller in isolation before adopting it. Include answer parity, CPU, transfer and RAM. [Spatial owners](../architecture.md)

The launch contract takes a validated build, installed definition/asset release, trusted host settings and a current database. Freeze and validate the supported authored opening as a build/fixture artifact using the existing initializer. A fresh database uses an explicit, authorized initial activation once. Existing data cold-opens through current-format selection, validation and writer adoption. Never reseed on an open failure. Build-time shaping of an opening is permitted for all arms. Runtime selection and installation must still validate the current database header, definition pins, exact asset release and table coverage. The RGS02 correctness caller may supply the existing validated input. In RGS03 the store supplies it. RGS07 proves stand-alone launch without a JS world builder or Node geometry helper. Preserve build/source/toolchain/definition identities and use the existing locked, offline release/workspace checks for each changed target.

## 3. Read and write PostgreSQL directly (RGS03)

Use [store.commitCaptured](../../apps/server/src/store.ts), [pending save ownership](../../apps/server/src/native-pending-save.ts), [current working-set reads](../../apps/server/src/native-current-sources.ts) and the [PostgreSQL adapter](../../apps/server/src/postgres.ts) as executable contracts. Start with their current schema, statement families, batched writer and transaction order. One process owns the database writer for this world. Acquire the same database writer lock before adopting the world. A direct Rust writer and the mixed writer cannot concurrently publish to it. Use the existing database revision/generation checks even with a single host. Follow the store's initialization order on empty and populated databases. Share the current schema and index definitions as build inputs where feasible. Refuse an incompatible layout before changing it, and verify all reachable tables, extensions and derived readers on a fresh launch.

- **Acceptance to save.** Keep one accumulating tail and at most one detached prefix. Freeze the exact generation, base durable revision, through-sequence, privacy changes, derived-index inputs, ordered records and receipts. Pass the funded immutable records straight to typed SQL parameters. Expose a read-only borrowed row/batch accessor on the existing Rust save handle, retaining its owned prefix through I/O. Keep required canonical JSON columns in their actual format. Remove the current [Rust save-to-JSON](../../native/node-bridge/src/world.rs) → [JS decode under the world lane](../../apps/server/src/native-world-service.ts) → SQL parameter construction where the same data is already usable. Detach under the world turn, then release it before serialization or I/O. Newer changes accumulate independently.
- **Commit.** Check the same durable predecessor, update records, source uses, history, indexes, privacy and operational receipts in one transaction. Publish durable invalidations and acknowledge only its prefix after confirmed commit. Preserve immediate accepted-memory invalidation, ordinary one-second scheduling, backpressure and the protected transactions for spending, access, correction and recovery. Pass a transaction handle to all affected repository operations. Splitting an atomic change across connections, callbacks or languages is a failed port. A confirmed rollback retains the prefix for exact retry. A lost COMMIT reply closes affected admission until reconciliation with durable revision/generation and any bound receipt establishes its outcome. If the outcome cannot be proved, remain fenced for recovery. A committed write whose local acknowledgement failed is acknowledged once without reissuing effects. [Save contract](../save-and-load.md#background-and-synchronous-world-saves)
- **Read.** Capture the accepted revision and relevant immutable unsaved changes before an await. Open one fixed database snapshot, match its durable revision to that capture, and apply replacements, deletions and ordering before limits. If the database has passed the captured cut and that cut cannot be served, release the read and return the existing stale outcome. Only the enclosing operation may start a permitted fresh attempt. Pin required pending data past save acknowledgement until that reader ends. Skip snapshot preparation for callers that do not read gameplay storage. Keep independent operational reads independent.
- **Receipt lookup.** [Command receipts](../../apps/server/src/command-receipts.ts) protect retries. Source can batch misses. The mixed caller reserves memory for an independent result, which requires a size check before transferring a variable body. When that check proves zero rows for the same deterministic selection and parameters in the same fixed snapshot, complete admission and return empty immediately. On a hit, transfer and validate the bounded body. Check a miss, a hit, concurrent duplicate IDs, refusal and cold replay through the command endpoint. Add no query solely for this shortcut. The earlier [empty-place fix](../benchmarks/native-runtime-foundations/2026/2026-11-17-native-active-area-comparisons.md#empty-place-read-on-the-first-walk--november-17-2026) stays in the baseline. Batching across independent readers would change ownership and needs evidence of significant overlap.
- **Recovery.** Restore the latest durable world, then test a validated administrative checkpoint over damaged gameplay rows, atomically rebuilding needed derived records. Protect accounts, grants, current privacy and external spend. Inject pre-commit refusal, uncertain commit, post-commit callback failure, process death, and an edit/delete/recreation with an old reader held through acknowledgement. Compare live, durable, reloaded and continued records and receipts to the TypeScript reference at the same accepted or durable point. [Restore contract](../save-and-load.md#loading-as-an-authority-transition)

Choose current-format bindings that support the existing types, transactions, prepared parameters and bounded result transfer. A row stream alone does not bound one large field already buffered by a driver. Admit a proven maximum before retrieval or retain the exact size/preflight mechanism. Count parser and wire buffers in the transfer bound. The integrated run captures database CPU, queries and rows. The Rust PostgreSQL client offers explicit commit/rollback and prepared queries. Verify driver buffering, TLS, cancellation and ambiguous COMMIT using the selected locked build. [Driver transaction interface](https://docs.rs/tokio-postgres/latest/tokio_postgres/struct.Transaction.html)

## 8. Compare and decide (RGS08)
