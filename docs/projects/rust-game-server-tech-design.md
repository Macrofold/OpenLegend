## Boundary and implementation order

Keep one world writer. Link the existing [simulation crate](../../native/simulation/src/lib.rs) into a new server crate in the [same Cargo workspace](../../native/Cargo.toml). Keep I/O, real time, credentials and provider clients out of the deterministic simulation. The server owns authentication, request and clock scheduling, permitted presentation, provider execution, SQL and sockets. These responsibilities do not require a second language or a second process. World vocabulary, definitions, reasons for decisions, activity rules and animal policy still come from the [installed world](../../packages/domain/src/worlds/base/native/). Build and ship its reviewed definitions once. A Rust module may implement a world rule without making it an engine default.

Today [main.ts](../../apps/server/src/main.ts) selects TypeScript or the Node-hosted Rust proof. The latter already has a [Rust session and save handle](../../native/simulation/src/runtime.rs), [candidate and disclosure fence](../../native/simulation/src/host.rs), and a [bounded compute pool](../../native/node-bridge/src/pool.rs). Move the Node-independent pool/dispatcher ownership out of the addon when the executable needs it. Keep Node conversion at the addon's edge. Use ordinary modules for HTTP/access, provider, spatial and store operations within the server. One async I/O runtime and the existing bounded compute pool suffice. Never start a pool per world, socket, reader or model request. Link the server directly to the simulation. If the addon also needs the new application owners for an isolated comparison, expose them from the server crate’s library target, with the executable as a thin entry point. The server library must not import N-API.

Build from RGS01 through RGS07. Keep the current TypeScript and mixed runtimes executable as controls, each on its **own** database. During extraction, exercise a Rust owner through the existing addon's coarse application call where that permits an isolated switch. Pass owned results or a handle to the native operation. Avoid a new interservice protocol and calls per field. The final HTTP host calls those same Rust owners directly. A run has one owner for each effect, including a paid submission, command receipt and database transaction. Refuse an unsupported operation explicitly. Before replacing each owner, list its upstream callers, selected input/output fields and downstream readers, including the less frequent failure and recovery paths. Reuse the parent coverage inventory. A Rust-to-Rust call that still serializes through a JSON buffer has not removed that conversion. Keep ordinary Rust inputs and bounded typed outputs inside the process. Encode when a network protocol, stored format or content hash requires bytes. Implementation tasks and dependencies live in [RGS](../maintainers/rust-game-server.md).

An application boundary within one process still matters. A world step can ask for a route using installed map data, but it cannot open a socket or choose a payer. A socket can submit a player's intention, but it cannot change position or authorize its own view. A second service would add transfer and failure handling to those operations. Keeping two full production backends would require every game rule to be maintained twice. Keep comparison builds reproducible and retire superseded owners only under the parent adoption gates.

For example, a walk arrives with a session and a request ID. The application checks who controls the body, submits one intention, and returns the accepted result. That acceptance supplies the changed rows for the next save and wakes the view publisher. Each viewer's permission determines which changes can appear. The publisher prepares the view from accepted data while the writer can take the next command. The database and browser may finish in either order. The game neither waits for a browser to display a step before saving it nor claims it saved a step before the database confirms it.

A **cut** identifies one accepted point in a particular world and generation. A **prefix** is the consecutive group of accepted changes covered by one save. A **receipt** is the stored result bound to a request ID. Reading an old cut, holding a result in memory, having permission to deliver it now and having committed it to disk are four different facts.

## 1. Freeze a playable workload (RGS01)

1. Start with the [base opening builders](../../packages/domain/src/worlds/base/native-proof.ts), [actual deer and hare creation](../../packages/domain/src/worlds/base/world.ts) and [animal profiles](../../packages/domain/src/worlds/base/animal-response-profile.ts). Use the [authored animal and human activity rules](../worlds/base/first-playable-roaming.md) for the opening's purposes, resource placement and starting needs. Add a distinct base-world comparison preset. Use fresh identities and the ordinary supported creation, participation, intentions, social and animal owners. Make **26 distinct living actors** including the player. Place them on verified walkable surfaces along a route with both visibility and occlusion. Record seed, placements, goals, terrain/assets, scenery, definition hashes and initial record counts. Do not change Main or an old frozen campaign.
2. Establish an actual Source journey before freezing it. Arrange ten humans with reachable authored activities and animals with room and real occasions to move or react. Use ordinary NPC scheduling with controlled HTTPS responses when invoked. A prefilled memory, injected perception, driver-written position or forced reaction cannot demonstrate activity. Require actual movement from each of the ten humans, ten deer and five hares during the window, plus evidence of what each was doing. Resting, eating or talking for part of the route is ordinary behavior. Use server-side records for actors outside the player's sight. Record distance, activity, witnessed reactions, local perception and history without disclosing hidden actors to the browser. If the rehearsal does not exercise an actor, correct the opening before freezing either arm.
3. Use one authenticated foreground player, presence renewal and the normal browser stream. Freeze a timed route with approach, movement past each group, redirect/stop and two conversations with distinct human NPCs. Submit by the actual command, steering and interaction endpoints using only displayed public references. Record the route, input offsets, command IDs, expected outcomes, reply scripts keyed to the intended NPC/request phase, and automatic NPC activity obligations in all arms. As a starting schedule, use six 30-second route segments, a waypoint command at the start of each, ordinary steering/stop in two segments, and a directed conversation after reaching an eligible speaker in segments two and five. Rehearse and freeze reachable coordinates, exact offsets and input modes before any clean run. Bind replies to request identity rather than global arrival order. A slow arm cannot quietly skip offers or reschedule them to fit. No periodic full-state polls, clock pause, forced save or garbage collection during the window.
4. Prepare independent current-format databases from the same authored initial state. Use the same ten-second warmup after the initial permitted view, then offer inputs for **180 wall seconds** at the installed 60:1 rate (10,800 intended game seconds). Both scheduled conversations must apply in the primary interval. Check ordinary persistence through the normal save covering its last accepted input, reporting drain separately. Compare offered/completed time and outstanding debt at the same boundary. Save fixed-cut canonical records, meaningful travel/actions, ordered reactions and permitted player/NPC witnesses. Use deterministic fixed-offer replay for exact semantics where real-time admissions diverge. Report the actual differences and exclude unequal useful work from speed claims.
5. Reconcile the [caller and field inventory](../maintainers/native-simulation-core-coverage.md) against this specific opening. Pin which actions, statuses, wildlife controllers, active human intentions, spatial queries, provider routes and storage rows actually run. Implement missing selected families once in the shared Rust simulation, recording them under NSC04. Verify the mixed server against TypeScript before either becomes a timing control. A real deer uses its own profile. Unrelated full-game conversion is a distinct task. Keep the immutable benchmark inputs and existing failed runs.

Use the existing real-caller scenario and managed runner. Package the fixture and available release builds through the existing worker preparation. Verify actual runner support and launch identity before admission. Record common CPU/worker settings, seed, current database format, client cadence, actor activity mix and artifact hashes together. Setup or warmup must not consume the only eligible interactions.

## 2. Start the process and run a world (RGS02)

First drive the extracted host from both the existing addon and a release executable against the same accepted world. Reuse candidate begin, prepare, ready, accept/reject and rollback. Stage all fallible work and output custody before changing accepted state. Grant one runnable operation per world before dispatch to compute workers. A database read or external answer may suspend an operation. Release its worker and borrowed world data. A pending candidate retains its exclusive right to accept or roll back, so another mutation cannot pass it. Serve an independent read of the last accepted state only when its owner can prove that isolation. A long-running NPC request holds evidence and a job, never an open world mutation. On return, bind to the same world, writer generation, candidate and source. Keep original RNG order and identifiers, elapsed-time offers, accepted prefix, debt, ordinary pause/absence, cancellation, poison and shutdown behavior. Use monotonic time in the host and installed rules for game time.

Start at `prepared_products` in the [current Rust session](../../native/simulation/src/runtime.rs). Its Rust wrapper already encodes operation results, history, notices and changed records into one JSON product before handing them to the addon. Split there. Let the Rust application borrow the prepared fields until settlement and take funded ownership of only the parts it must keep afterward. Retain the encoded handoff for the Node caller. Both paths must acquire their actual output storage before Ready and settle through the same candidate key. Refuse at that boundary and prove exact rollback and retry through both hosts. Count bytes encoded and copied in a diagnostic so a function call that still constructs the old packet cannot masquerade as a removed crossing.

The present proof calls [geometry and navigation](../../apps/server/src/native-geometry.ts) and [route continuation](../../apps/server/src/native-navigation.ts) in Node. Inventory actual selected requests, including presentation geometry. Supply the same installed map, query batches, units, collision shapes, ordering, versioned navigation inputs and source/pose certificates to a Rust host implementation. Reuse the pinned Rapier and Recast/Detour behavior or their already-built artifacts via a verified Node-free binding. Distinguish physics/navigation computations from the world's decision to flee, move or perceive. Tie results to their original inputs. Port only reachable queries, with no straight-line, always-visible or empty answer fallback. Compare actual hits, ordering, routes, animal reactions, resulting records and reject/replay after stale or refused answers. Backend/binding differences are isolated experiments, including CPU, cross-thread transfer and RAM. [Spatial owners](../architecture.md)

The launch contract takes a validated build, installed definition/asset release, trusted host settings and a current database. Freeze and validate the supported authored opening as a build/fixture artifact using the existing initializer. A fresh database uses an explicit, authorized initial activation once. Existing data cold-opens through current-format selection, validation and writer adoption. Never reseed on an open failure. Build-time shaping of an opening is permitted for all arms. Runtime selection and installation must still validate the current database header, definition pins, exact asset release and table coverage. The RGS02 correctness caller may supply the existing validated input. In RGS03 the store supplies it. RGS07 proves stand-alone launch without a JS world builder or Node geometry helper. Preserve build/source/toolchain/definition identities and use the existing locked, offline release/workspace checks for each changed target.

## 3. Read and write PostgreSQL directly (RGS03)

Use [store.commitCaptured](../../apps/server/src/store.ts), [pending save ownership](../../apps/server/src/native-pending-save.ts), [current working-set reads](../../apps/server/src/native-current-sources.ts) and the [PostgreSQL adapter](../../apps/server/src/postgres.ts) as executable contracts. Start with their current schema, statement families, batched writer and transaction order. One process owns the database writer for this world. A direct Rust writer and the mixed writer cannot concurrently publish to it. Use the existing database revision/generation checks even with a single host. Follow the store's initialization order on empty and populated databases. Share the current schema and index definitions as build inputs where feasible. Refuse an incompatible layout before changing it, and verify all reachable tables, extensions and derived readers on a fresh launch.

- **Acceptance to save.** Keep one accumulating tail and at most one detached prefix. Freeze the exact generation, base durable revision, through-sequence, privacy changes, derived-index inputs, ordered records and receipts. Pass the funded immutable records straight to typed SQL parameters. Expose a read-only borrowed row/batch accessor on the existing Rust save handle, retaining its owned prefix through I/O. Keep required canonical JSON columns in their actual format. Remove the current [Rust save-to-JSON](../../native/node-bridge/src/world.rs) → [JS decode under the world lane](../../apps/server/src/native-world-service.ts) → SQL parameter construction where the same data is already usable. Detach under the world turn, then release it before serialization or I/O. Newer changes accumulate independently.
- **Commit.** Check the same durable predecessor, update records, source uses, history, indexes, privacy and operational receipts in one transaction. Publish durable invalidations and acknowledge only its prefix after confirmed commit. Preserve immediate accepted-memory invalidation, ordinary one-second scheduling, backpressure and the protected transactions for spending, access, correction and recovery. Pass a transaction handle to all affected repository operations. Splitting an atomic change across connections, callbacks or languages is a failed port. A confirmed rollback retains the prefix for exact retry. A lost COMMIT reply closes affected admission until reconciliation with durable revision/generation and any bound receipt establishes its outcome. If the outcome cannot be proved, remain fenced for recovery. A committed write whose local acknowledgement failed is acknowledged once without reissuing effects. [Save contract](../save-and-load.md#background-and-synchronous-world-saves)
- **Read.** Capture the accepted revision and relevant immutable unsaved changes before an await. Open one fixed database snapshot, match its durable revision to that capture, and apply replacements, deletions and ordering before limits. Never silently move an older reader to a newer world. Pin required pending data past save acknowledgement until that reader ends. Skip snapshot preparation for callers that do not read gameplay storage. Keep independent operational reads independent.
- **Small query experiment.** [Command receipts](../../apps/server/src/command-receipts.ts) protect retries. The earlier [empty-place fix](../benchmarks/native-runtime-foundations/2026/2026-11-17-native-active-area-comparisons.md#empty-place-read-on-the-first-walk--november-17-2026) stays in the baseline. The admitted Native receipt reader sizes the selection before transferring a variable body. For the deterministic receipt lookup only, test using its zero-row proof in the same snapshot to return empty after admission. On a hit, retain a bounded validated body before releasing the reader. Exercise both, concurrent same-ID requests, refusal and cold recovery. Measure separately from replacing the writer. Share a batch only if actual overlapping callers can keep their independent results and deadlines. Never generalize an empty lookup to arbitrary SQL or skip transfer bounds.
- **Recovery.** Restore the latest durable world, then test a validated administrative checkpoint over damaged gameplay rows, atomically rebuilding needed derived records. Protect accounts, grants, current privacy and external spend. Inject pre-commit refusal, uncertain commit, post-commit callback failure, process death, and an edit/delete/recreation with an old reader held through acknowledgement. Compare live, durable, reloaded and continued records and receipts to the TypeScript reference at the same accepted or durable point. [Restore contract](../save-and-load.md#loading-as-an-authority-transition)

Choose current-format bindings that support the existing types, transactions, prepared parameters and bounded result transfer. A row stream alone does not bound one large field already buffered by a driver. Admit a proven maximum before retrieval or retain the exact size/preflight mechanism. Measure parser, wire buffers, preflight SQL, actual database CPU and retained rows. The Rust PostgreSQL client offers explicit commit/rollback and prepared queries. Verify driver buffering, TLS, cancellation and ambiguous COMMIT using the selected locked build. [Driver transaction interface](https://docs.rs/tokio-postgres/latest/tokio_postgres/struct.Transaction.html)

## 4. Authenticate and accept player input (RGS04)

Port the behavior of [authentication](../../apps/server/src/authentication.ts), [authority and request scopes](../../apps/server/src/authority.ts) and the [real HTTP routes](../../apps/server/src/native-http.ts). Follow the browser from login and session selection through embodiment, presence, control acquisition/renewal/release, command, steering, receipt lookup, logout and reconnect. Preserve local-development mode and configured OIDC separately. Use a maintained OIDC client for discovery, PKCE, state, nonce, callback binding and issuer/token checks. Exercise a controlled issuer through the actual redirect/callback, including rejected state/nonce, expired login and logout during a held request. Never authorize a user from an email address or a supplied actor ID. Keep configured origins, cookie flags, timeouts, cancellation and trusted proxy/host handling. Database-backed grants and revocations, body life, control generation, world/timeline and payer are authoritative. Client fields are intentions and references. [Multiplayer authority contract](completed/multiplayer-authority-tech-design.md) · [Rust OIDC client](https://docs.rs/openidconnect/latest/openidconnect/)

Start with equivalent command recovery, epoch rotation and final admission. Resolve a prior receipt before looking up a target that might have been forgotten. On acceptance recheck current scope, generation/epoch, request ID and fingerprint against live and durable outcomes. Publish one result plus its save receipt. Preserve the current [serialized-input digest](../../apps/server/src/content-digest.ts) for command, choice and source identities. Compare actual bytes for field order, optional fields, Unicode and numeric encoding wherever a consumer hashes or persists them. Do not substitute Rust map iteration order. Concurrent duplicate IDs replay, conflicting inputs refuse. Preserve narrow untargeted movement and steering, targeted command resolution, release while steering is unavailable, pauses and elapsed debt. **Single-turn experiment.** For a fresh, unexpired epoch, can a command read its receipt outside the writer and take one final turn? Record the original scope/generation before the await and recheck _everything it may invalidate_ inside admission. An expired epoch uses protected rotation. Compare lane occupancy, CPU and real HTTP/first-position tails. Keep the existing two-turn implementation if the trial fails.

Exercise ordinary walk, steering renewal and release, valid/forged target, unavailable actor, simultaneous identical/conflicting command IDs, expired epoch, a control transfer or restore between read and acceptance, and duplicate recovery after restart. Check the protocol result, resulting position/action, save receipt and exactly-once application. Authorization for a new effect and authorization to disclose a recovered result both need current checks.

## 5. Publish only what each player may see (RGS05)

Port the [projection](../../apps/server/src/native-player-view.ts), [state and stream callers](../../apps/server/src/native-player-http.ts) and existing [public wire shapes](../../packages/protocol/src/index.ts). First reproduce the full permitted view and ordinary diff in Rust, including controls, clock, identity/alias, ordering, conversation, memory, practice, profile, job status and save status. Feed the unmodified browser. A stream starts from a reset and applies ordered patches against its own previous handed-off revision. HTTP reports and outgoing frames each own their storage. Keep the existing cadence and serial preparation control. A view may become stale during preparation. Follow the existing bounded fresh attempt after relevant invalidation. If a fresh permitted result cannot be established, refuse or resynchronize through the existing caller.

**Selective preparation experiment.** Use already accepted changes and observer evidence to select which sections need preparation. Begin with motion, changed visibility, reactions and their resulting history. A dirty world object alone cannot authorize a visible change. Track per-section dependencies for previous and new observer membership, actor life, installed definitions, clock/expiry, corrections, grants and independently changing server sections. When a deer walks behind a rock, the player may lose sight of it and still remember it. A detail can expire while the deer stands still. Use existing observer/time/revision owners so neither case is missed. If unchanged cannot be proved, use the full authorized comparison for that section or a fresh reset. Preserve absence versus explicit removal, display order, speech and other discrete consequences. Measure work inspecting recipients/subjects/sections as well as the final patch bytes. An index that scans or allocates more per acceptance than it saves at publication loses its comparison.

Capture only independently funded immutable inputs at one accepted point. Prepare outside the world turn. At transport handoff hold a disclosure lease which serializes relevant revocation/invalidation against release of private data. Recheck session/control, life, timeline, evidence and the stream's last revision. Within that authorized turn, select the patch or reset, encode it exactly once and hand it directly to transport. An unchanged publication encodes nothing. No deferred private encoder. Reserve capacity and confirm initial authority before sending success headers. Queuing a private frame for a later unchecked send does not satisfy disclosure. When the transport can first take a frame, perform the check there, or implement an equivalent single synchronous checked write. Backpressure retains only admitted in-flight transport and required stream state. On drain prepare again with current permission. On disconnect cancel pending work and release the stream's owners. [HTTP frame interface](https://docs.rs/http-body/latest/http_body/trait.Body.html)

Compare decoded state and every patch applied to the browser's actual previous view against a fresh permitted full projection at the same cut. Exercise initial/no-op/patch/reset, observer losing sight, forgetting, timeline replacement, reconnect, blocked drain, concurrent revocation and independent held readers. Count actual encodings and missing updates. Reuse NRF14's healthy/held observer correctness evidence where unchanged. Verify the changed Rust handoff through two real streams, including two successive updates reaching the healthy observer while the other socket cannot accept data. The earlier width-two and same-character capture sharing experiments stay withdrawn. [Existing observer results](../maintainers/native-runtime-foundations.md#multiplayer-update-delivery)

## 6. Execute NPC decisions without Node (RGS06)

An animal response remains local simulation. For human decisions trace the existing [director](../../apps/server/src/native-npc-director.ts), [shared execution admission](../../apps/server/src/cognition-execution.ts), [paid dispatch](../../apps/server/src/decision-dispatch.ts), [AI transport/decoders](../../packages/ai/src/) and native source/effect tickets. Port this selected path to the Rust application around the existing simulation operations. Include automatic work, interactive availability after the allowance await, directed Send, cancellation and receipt recovery. Preserve world-authored triggers, prompt vocabulary, provider routes, offered choices and typed schemas. The provider sees the NPC's acquired knowledge and permitted actions. Executable bindings stay in Rust.

1. Pin the permitted evidence, recipient/life and selected decision inputs. Admit the actual payer/allowance and per-character ordering. Unrelated NPCs may execute concurrently within real provider, money and memory admission. Carry the same deadline through preparation, dispatch and response. Before dispatch, use the existing exact source revalidation/fresh preparation when allowed. Record the failed comparison at its owner on refusal.
2. Commit spending reservation and dispatch intent under the existing protected barrier. Submit once through bounded HTTPS, release world and compute ownership while waiting, and retain independently funded request, validator and response-stream buffers. Recalculate real parser and transport allocation on the locked Rust stack. Node/V8 workspace estimates only cover their qualified decoder. Enforce the selected schema/size/streaming contract before any effects. Preserve judgment/generation stages, permitted previews and configured escalation only under their original conditions.
3. On completion, recheck original source, life, chronology, command binding and current permission. Apply once through the existing Rust response owner, and persist the response receipt, accepted effects and required accounting in their owning transactions. Distinguish late/stale effects, deliberate cancellation, provider refusal, known charge and unknown provider completion. Replay of an existing response/request receipt recovers its original result. Ambiguous paid completion follows the existing reconciliation path. A disconnect ends the consumer it owns. It cannot erase a committed effect, release uncertain spend or start another paid request. [Provider accounting](../ai-providers.md#receipts-outcomes-and-accounting)

Compare actual outbound contract, ordered semantic inputs, allowed options, partial and final decoded results, ledger/receipts and saved continuation with controlled HTTPS endpoints. Hold one reply while the player walks and another NPC decides. Repeat completion, cancellation, view loss, relevant forgetting, unrelated evidence change, invalid response, timeout after dispatch and replay of the same ID. Report terminal reason and effects separately from provider settlement. Keep privacy-safe witnesses. External model quality and live pricing are outside this comparison.

## 7. Serve the real browser, then remove the runtime dependency (RGS07)

Use one Rust binary for ordinary ingress, the world host, saves and selected external calls. An async HTTP stack such as [Axum with Tokio](https://docs.rs/axum/latest/axum/) supports the required routing. Before pinning dependencies check the repository toolchain, licenses, locked/offline build and release targets. Keep socket/SQL/provider waits off compute threads. Map existing body, queue, network, credential and shutdown limits into these real callers, including compressed/streamed input where applicable. Route each external HTTP call (authentication, provider, assets) through one application-owned cancellation/deadline and byte-admission contract, porting the [network behavior](completed/bounded-network-requests-tech-design.md). Configure trusted destinations and credentials from existing operator settings. Check cancellation before dispatch, preserve TLS verification and redirect policy, cap data before decode and retain ownership through actual completion. Extend the existing network-boundary check to the new Rust call sites. The server owns real time and resource admission. Worker callbacks cannot bypass the world writer.

Use the real browser network trace to finish the route inventory. Cover HTML/build files and exact permitted asset release, login/session, embodiment/control/presence, state/events, command/input/receipt, interaction availability/chat/cancel and the selected inspection/history reads. Include indirect requests on fresh entry, leaving, returning, and after a refusal. Serve static files with their existing access rules and content types. Protected assets require current authorization and exact release pins. External asset/identity/model services retain their contracts. Do not start a TypeScript server for an overlooked route. Report other unsupported routes and world families in the NSC04 inventory before any broader adoption.

Start the production release from a disposable current-format install with no Node executable, addon, JS-side geometry or application service available to the server. Use a separate client/fixture environment, record process ancestry and allowed service destinations, and run the full journey with normal saves. Kill/restart the server, verify the published durability promise and retry identities, exercise administrative recovery separately, then shut down with a held reader and pending provider work. Drain or persist outstanding obligations before dropping the store/host. Verify clean process exit, resource release and fresh continuation. Browser JS and tools used to build artifacts or drive tests are outside the server process tree. A proxy to a Node game service fails this exit.

## 8. Compare and decide (RGS08)

| Change to isolate                                | Keep fixed and measure                                                                                                                                                                                                                          |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native spatial provider or dispatcher extraction | Same routes, answers and one-worker settings. Price complete movement, provider wait and all threads. Change the backend separately from scheduling.                                                                                            |
| Direct Rust store                                | Keep the same accepted rows, reads, SQL semantics and save cadence. Compare capture-to-ACK, SQL work, CPU and memory with the mixed writer. Independently switch the zero-row shortcut for a receipt hit/miss workload.                         |
| Rust input handler, then single-turn admission   | First match the existing two-turn handler. Then change only entry scheduling. Measure command response, writer hold/wait, clock progress and durable outcomes.                                                                                  |
| Rust permitted view, then selective preparation  | First measure Rust full projection against equivalent mixed projection through the same transport. Then compare full versus selective Rust preparation. Count selected sections, materializations, encodings, update size and movement receipt. |
| Rust NPC execution                               | Use the same evidence, provider, paid-admission policy and controlled HTTPS fixtures. Compare actual request/response preparation, wait, CPU, held memory and durable effects.                                                                  |
| Rust HTTP transport                              | Same Rust handlers, store and world. Compare through the unmodified client, including login, initial reset and blocked delivery. Test a single ready consumer before changing width.                                                            |

Use the [existing measurement process](../performance/measurement.md#planning-comparisons), [worker procedure](../../.agents/rules/verification-workers.md) and [parent thresholds](../maintainers/native-simulation-core.md#first-proof-qualification-criteria). The [limits owner](../limits/native-simulation-core.md#nsc-l10--stand-alone-rust-server-comparison) defines this track's comparisons. Freeze each stage and run its correctness and isolated comparison as soon as a matched real caller exists. RGS08 owns the final three-arm run and any explicitly deferred comparison. Record build, configuration, opening, installed pins, input, fixture and database identities. Use independent databases and three balanced interleaved runs per arm per experiment on the standard 16 GiB worker. Keep the qualified 2 GiB transient profile, separate resident and pending-save accounting, and normal memory reclamation. Reconcile actual resources, spend and holds before paid use under the continuing budget. A design document allocates no funds.

Use adjacent immutable builds with one change to isolate each implementation decision. Keep the same host on both sides while changing a provider, writer, command admission or projection algorithm. For HTTP compare the Node and Rust transports around identical Rust application owners after both are joined. For necessary multi-part ports with no equivalent complete control until integration, first compare matched isolated **real caller** windows on either side of that owner, then run the complete ordinary workload with only that owner changed. Defer a speed claim if isolation is unavailable. An inseparable combined comparison names its parts and establishes only their joint effect. For the three-arm final use a rotation such as TypeScript/mixed/Rust, mixed/Rust/TypeScript, Rust/TypeScript/mixed on one machine. For an isolated two-arm trial alternate the arm order across pairs. Do not mix populations, different warmups, synthetic conversations or incomplete runs. Independent correctness repairs belong in both arms. Preserve failures. Remove a losing optional path. An essential port that still loses remains an explicit cost of the candidate. Fix broken required journeys before rerunning affected comparisons.

Run the existing focused build, type, format, release, protocol, network-owner and actual browser/PostgreSQL checks affected by each stage. Use disposable scenarios and keep diagnostic instrumentation separate from clean timing. Skip the unit suite. The final comparison has three arms on identical inputs. Run retained TypeScript, repaired one-worker mixed Native and stand-alone one-worker Rust. Balance order across repetitions and compare each on the identical 26-actor world. Both Rust arms share the same simulation. Their final difference includes the new host and every retained algorithm change. Use the isolated trials to attribute each effect. Where a common fix is required, rerun the affected control. Count server processes and their threads once, the client separately, and the exclusive PostgreSQL instance separately. Keep the controlled HTTPS responder identical and report its CPU separately when it has its own process. Report server/DB CPU as percentages of one logical core and achieved rate first, with median, mean and p95, named samples and spread. Include CPU per completed game-second, offers/debt, command acceptance/response, first visible movement (distinguish decoded receipt and actual display), save phases/age/ACK, SQL calls/rows/transfer and prepared bytes, WAL/growth, concurrent actual memory and reservation peaks/normal-GC or allocator settling. Do not add overlapping wall waits to CPU. Keep cold start, login/return, rewind and held-provider stress in separate windows.

Record **adopt for the measured scope**, **reject**, or **inconclusive**, along with bottlenecks and actual dispositions. Preserve the existing default until the parent full-game and operational gates are met. Hand the best correct one-worker baseline and new phase costs to the [within-world multicore continuation](../maintainers/native-simulation-core.md#within-world-multicore-continuation). This track does not qualify worker widths, cells, distribution or a population ceiling.
