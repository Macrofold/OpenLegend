## Outcome and first playable journey

A player installs Open Legend, signs into the existing world, walks from a wooded ridge to an inhabited valley, talks to someone, finds a useful place to build and returns to the consequences of their actions. The ridge still looks inviting from the ordinary gameplay camera. The person they met had their own perspective and plans before the player arrived. A second player can have a different account of the same encounter. The game remains playable when optional art or a model provider is unavailable. A creator can produce this result from a clean workstation with repeatable agent-run jobs and review it in motion without hand-assembling a level in the editor.

**Selected change.** Replace PlayCanvas as the primary playable presentation with an installed Unreal Engine 5 client. Preserve Open Legend’s independent server, installed-world rules, access controls, character cognition, persistent consequences and agent-driven production. Aim for grounded, painterly plain 3D, an active sun and legible day/night changes, deep landscape layers, dense woods, mist, inhabited places, and space to explore and build. Reference images are mood and composition inputs. The rights to distribute them or turn them into assets have not been granted.

**What this specifies.** Player/creator outcomes, work that crosses owners, retention and retirement, staged acceptance and decisions for design. The platform, renderer implementation, wire code generator, UI toolkit, placement algorithm, binary store tooling and deployment layout have not been prescribed. Windows desktop first and a pinned released UE 5.8 patch are recommended planning defaults. Commitments to hardware, other platforms, licenses, delivery of live bespoke assets or a distribution channel require the decisions below. No Unreal runtime exists as a result of this document.

**Why UE.** PlayCanvas already supports techniques such as shadowed volumetric fog. Its strengths include instant browser access and text-friendly iteration. The reason to move is the combination of dynamic lighting, large landscapes, distance management, character tooling, procedural placement and production profiling in one engine, plus a first-class native deliverable. Unreal increases the work for client integration, content conditioning and distribution. Raw polygon count is a poor predictor of the intended look or of total cost. Composition, convincing interactions, reusable asset families and smooth frame delivery consume much of the production effort in either engine. [PlayCanvas fog](https://developer.playcanvas.com/user-manual/graphics/posteffects/cameraframe/volumetric-fog/) · [Epic’s released UE 5.8 features](https://www.unrealengine.com/news/unreal-engine-5-8-is-now-available)

## Runtime ownership and failure boundaries

**One player action, end to end.** A click hits a visible door and retrieves its permitted subject/surface identity. Unreal may highlight the handle immediately. The server checks the actor, current permission, reach, obstruction, state and request identity, applies or refuses the action and publishes what each observer can learn. Unreal animates the admitted result. If someone locked the door after the click, the handle preview clears and the refusal reaches the player. On a lost acknowledgement the client recovers the original outcome. After a crash, restore the latest complete durable server state and respect its timeline. Never promise that an undurable frame survived the crash. [Action contract](../action-capabilities.md) · [Host and saving](../save-and-load.md)

| Question | Owner and required behavior |
| --- | --- |
| Where can I stand, build or reach? | Current installed server geometry, support, navigation and action rules. Translate the world’s right-handed, Y-up **metres** to Unreal’s left-handed, Z-up **centimetres** at the boundary. Specify handling of orientation, handed equipment, velocities, normals, rotations, long-distance precision and any local origin changes. Compare a ramp, stacked floors, an overhang, mirrored left/right hand, moving body and distant return. Rendering offsets, visual collision, animated limbs, ragdolls and hit particles cannot accept a move, grant damage or create support. [Spatial rules](../spatial-world.md) · [Epic coordinate conventions](https://dev.epicgames.com/documentation/en-us/unreal-engine/coordinate-system-and-spaces-in-unreal-engine) |
| What is real in an unloaded valley? | Installed world records and stable IDs persist independently from UE actors, asset paths, levels or World Partition cell identities. The server owns changed construction, removed resources, occupied sites and save/restore. An unloaded client region cannot despawn a person on the server. Establish which terrain, structures and collision are public, which discoveries are private and which distant shapes are decorative. A height map alone cannot represent two usable floors or a cave. |
| What does the character know? | The server owns senses, occlusion, hearing, attention, memory and permitted public descriptions. Geometry includes blockers that affect play. Decorative grass, visual fog, bounced light and camera cutaways affect depiction. If weather, darkness or cover changes perception, introduce or reuse the corresponding authored server fact explicitly. Two people may see the same fire and learn different things. A character who only heard a voice gets only the permitted words/location precision and any permitted identity. No character-camera rendering for NPC thought. Reflect each permitted direct, indirect or remembered fact at its admitted precision. Withheld facts cannot be distinguished as never learned, deliberately forgotten or still present elsewhere through client side channels. [Hearing](../hearing-and-speech.md) · [Memory](../memory-architecture.md) |
| Who runs time and decides when a mind works? | The existing host advances accepted intervals, runs or admits NPC decisions under its current scheduling and cost rules, and persists consequences. UE smooths between authorized samples within the current clock policy and stops or resets on pause, lost freshness or timeline change. Visual distance or reduced detail cannot make an NPC stop thinking. Server-side level-of-detail for cognition is a separate correctness/performance decision. A different authored world may use a different day length, sun arrangement, senses or object families. [Time](../simulation-time.md) · [World boundaries](../engine-and-world-boundaries.md) |
| What crosses the network? | The current host exposes HTTP requests/receipts and ordered server-sent events for scoped views, including full/reset and incremental delivery. Consume those semantics or demonstrate an equally private, ordered replacement. Provide distinct accounting for admitted, committed, ongoing, rejected, cancelled and uncertain outcomes where each applies. Keep trusted definitions, private memories, future routes, database access, provider credentials and operator capabilities outside the player. Carry server-corrected movement smoothly under delayed, duplicated, lost and out-of-order responses. [Rust request owner](../../native/game-server/src/player_http.rs) · [Stream owner](../../native/game-server/src/player_stream.rs) · [Public types](../../packages/protocol) |
| What happens when nobody is looking? | Maintain the chosen host’s presence, pause, world-time and paid-work policies. Support simulation and limited server qualification without a graphics device. A second viewer, operator dashboard or remote GPU build worker cannot become another world clock or writer. An idle game may intentionally pause under current rules; loading a different UE level must not change that policy. |
| Which Unreal systems may be used? | UE movement/physics, navigation, animation, local interaction queries and network utilities are candidates for presentation or prediction. Unreal's built-in replication expects an authoritative Unreal server. The external Rust host does not automatically gain replicated actors or multiplayer prediction. Require an explicit integration and reconciliation path. No parallel Unreal world authority, unscoped replication or assumption of a dedicated Unreal server per Rust shard. Engine choices for gameplay authority would need a separate product/architecture decision. [Epic networking](https://dev.epicgames.com/documentation/en-us/unreal-engine/networking-overview-for-unreal-engine) |

**Existing data and authored worlds.** Preserve same-format world continuity, current explicit saves, atomic restoration, stable item/person identity, pending operations and account/privacy boundaries. Server saves own gameplay. Local UE settings may store display, input and opted-in preferences. A packaged map or local save slot is never a second world save. Use the [current development save policy](../../AGENTS.md#development-save-policy) for incompatible development data. Do not create legacy readers, indefinite protocol versions or dual servers to rescue old development saves. If the branches’ Main contents are later integrated, reconcile the selected starting-world union and rights through the world-owned initializer. Do not ship the private proof save, an isolated showroom or an unrelated branch wholesale.




**Entry and confidentiality.** Resolve the current session and authorized viewing role before expensive scene work. Acting requires current control. An observer can see only the view that role already permits. Preserve existing pause/resume and takeover behavior for competing sessions. Show normal play only after the required content and first complete rendered frame are ready. A required-art failure exposes a clear retry; an optional-art failure uses only the documented truthful fallback. Treat every byte shipped in a common install, downloaded pack, authored map or shared PCG recipe as inspectable by its recipient. Public terrain and generic art can be shared. A curated map that embeds a secret camp, a generation seed that reconstructs hidden positions, a private character texture fetched in advance or a tooltip that names an unseen person can defeat server privacy even while the character is invisible. Inspect package contents and observable fetches from a clean, minimally privileged account. Permission revocation fences further delivery and clears in-game access. It cannot recover bytes already delivered.

**Two camera jobs.** The current elevated tactical view makes a crowded campsite and a precise building placement readable. The references often put the eye low enough to see distant ridges and layers. Require a reachable horizon-facing exploration framing as well as ordinary tactical control, with a simple way back to the character and a clear distinction between camera rotation and turning the character. Choose whether the default changes with Mike. A first-person controller, a permanent cinematic camera and hidden scenery scouting are outside the selected change. [Art branch camera contract](https://github.com/Macrofold/OpenLegend/blob/d8e39b132611a10641704c3fc87b0f9409901532/docs/world-presentation.md#camera-and-settings)

## Landscapes, weather and the visible world

**Art direction.** The references span paintings, illustrations and more realistic scenes. Their shared features are a strong skyline, readable foreground shapes, several layers of terrain, light that picks out a destination, and a route into the image. In the alpine scenes a river draws the eye toward a pass; in the hamlet a crossing and illuminated windows give the landscape a human scale; in the forest a few figures appear between enormous trunks. The swamp is dark but still readable. Preserve the project's grounded stylization, natural anatomy and proportions, grouped colors and materials, expressive silhouettes and quiet surfaces. Retain the textured Quaternius anchor and approved naturalistic supporting sources, light wind and diffuse leaf light. Concept paintings guide composition; the playable scene needs continuous depth when the player moves. Budget detail by apparent size, use and proximity. A distant roof and an equippable helmet warrant different treatment. [Approved art direction](https://github.com/Macrofold/OpenLegend/blob/d8e39b132611a10641704c3fc87b0f9409901532/art-direction/decisions.md) · [Creative brief](https://github.com/Macrofold/OpenLegend/blob/d8e39b132611a10641704c3fc87b0f9409901532/art-direction/final-board/creative-brief.md)

## Asset production, delivery and rights

**Preserve the source investment.** Keep selected concepts, editable Blender sources, rig/appearance recipes, names, materials, provenance and exact source releases. Add UE-focused preparation and playback verification. Existing GLB exports are inputs where suitable; browser-specific shader logic, texture interpretation, material settings, collision and prepared assets require explicit native equivalents. ## Audio, effects and feedback

A Native client replaces the browser’s sound playback, voice/caption presentation and device lifecycle. ## What changes the solo workload most

1. **Hardest shared problem — a beautiful place that players can change.** A mountain vista is inexpensive evidence compared with a town the player can walk into, alter and revisit. Shared physical shapes, far-away representations, changing sun, privacy, resource ownership and save/load must agree after the edit. The engine lowers the cost of drawing the result. Open Legend owns continuity and meaningful placement.
2. **Hardest content problem — compatible families that hold up in motion.** A scanned-looking rock is relatively cheap. A shirt for two different bodies, under armor, while bending and carrying an item has many combinations to qualify. Build repeatable family-level tooling and prioritize near-camera assets. Reserve bespoke work for distinctive people, destinations and high-value player inventions. A GPU can draw thousands of stones without giving artists thousands of independent designs to approve.
3. **Largest additional Unreal-specific burden — editor/build automation, the desktop client and release discipline.** Agents accustomed to editing text now also need native SDKs, binary asset transactions, deterministic reimports, GPU captures and cooked builds. Desktop UI, secure sign-in and updates carry work formerly provided by the browser. Agents can parallelize isolated jobs. They cannot remove the need to reconcile conflicting edits, wait for shaders or assess a moving scene against the intended art direction.
4. **Largest recurring runtime risk — worst-case combinations.** A lot of individually acceptable features can overwhelm the frame when animated people, overlapping leaves, many shadowed lights and editable buildings are visible together. Rendering detail, texture residency, animation, server simulation and network delivery have independent costs. Set a player hardware promise and maintain a representative heavy scene.
