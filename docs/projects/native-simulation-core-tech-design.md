## 1. Evidence and decision basis

Source inspected for this design: `244a487d0f8a55a631e7244f784edef310c0c744`, `Macrofold/OpenLegend`, `codex/stealth-runtime-01-evidence`. The main thread's BK work can advance independently; implementation must pin its actual integrated comparison base and reconcile that work before making changes.

The authorized NSC01–NSC03 implementation uses the selected local stealth-runtime tip `9080bffc43c7cfa17a47de01b566c776ffb9e7d3`, including its retained R1–R9 changes, captured-source correction/body-life fences and per-track viewpoint context; the refreshed remote was at `02a0588d8d3fed255957642ef9a2043c836f68ca` at freeze. The [delivery record](../maintainers/native-simulation-core.md#current-progress) distinguishes that frozen gameplay base from the later profiling-tools ref advancement. Its [source coverage inventory](../maintainers/native-simulation-core-coverage.md) distinguishes inspected fields/callers, changed-source reconciliation and pending native conversion/acceptance. The [prior measured disposition](../maintainers/native-simulation-core.md#nsc03-measured-disposition--november-11-2026) rejects the 64 MiB profile. The [current reassessment](../maintainers/native-simulation-core.md#nsc03-reassessment--november-12-2026) rejects the provisional 128 MiB profile after failed clean ordinary-play capacity, retaining separate resident and pending-save accounting. Complete held consumers and one-worker correctness precede bounded ranges/E2; broader migration remains outside this task. The old combined journey remains valid aggregate evidence, not a sustained-play result.

The [BK28 report](../verification/performance/bookkeeping/2026/2026-11-07-bk28-implementation.md#exact-adopted-source-qualification) measures **`d435c054...`, not the inspected head**. Its clean six-minute standard opening advances 99.348% of offered normal time with 96.85% main-thread CPU and 111.96% whole Node process CPU, in units of one logical execution thread. Command p95/p99 are 208.8/312.2 ms; maximum 689.6 ms. The separate instrumented run is slower and differs in actual outcomes. Its 32.18% exclusive draft/immutable/record utility samples and 4.18% GC identify representation work; they are not additive savings against overlapping encounter/attention/command timings. Account-aging reader occupation is a separate latency source. Models are disabled; this CPU is not LLM inference. Earlier one-second latency reports and newer parent-thread results retain their own source/workload, rather than being combined into one baseline.

Concrete architecture observations:

- `WorldService.mutate/runMutation` serializes accepted world changes. `advanceWorldSlices` runs the domain synchronously in bounded prefixes; yielding the Node event loop does not put that work on another core.
- Navigation, geometry and checkpoints already have workers. Geometry uses up to two bounded workers; navigation owns its queue and generation fences. This project does not claim to invent worker execution.
- `entity-collection.ts` uses indexed records; `draft.ts` owns working drafts, publication, copies and lineage. Unchanged structure is already shared. The target removes recurring graph/proxy machinery, not an imaginary full-world copy every tick.
- `received-batches.ts`, `perception-current.ts`, `temporal-evidence.ts` and the BK codecs already distinguish current values, independent clocks, change history and retained support. Preserve their semantics; do not restart a per-field evidence diary.
- `packages/spatial` already uses Rust Rapier through WebAssembly; Recast navigation is already a compiled implementation behind workers. Rewriting geometry alone is not the selected explanation for the remaining cost.
- The reconciled source removes generic animal announcements and eligible routine walking notices at their semantic owners. Preserve those removals in both arms; fewer occurrences from that work are not a Rust gain. Account retirement, retention policy and SQL application remain separate owners.

**Language choice.** Rust and C++ both offer native execution, memory-layout control and no mandatory garbage collector. Rust is preferred for the trial because compiler-enforced ownership and safe concurrent access fit a growing authoritative simulation, and its needed libraries exist. This is not a claim that Rust is inherently faster than C++. C++ retains a larger established AAA/editor/middleware ecosystem; OpenLegend is keeping its browser renderer and application services. Rust builds and ownership-aware implementation can cost more developer time; replacing shared graphs with indiscriminate `Arc<Mutex<_>>` or clones would defeat the purpose. A compact TypeScript design may also improve materially; the proof measures a narrow control separately without attributing every integrated gain to language.

**Unmeasured planning estimate.** The integrated single-worker migration has a rough engineering estimate of **1.5–3× CPU efficiency**, with **2× a working hypothesis**, on equal hardware/work before multicore throughput gains. This is not an adoption threshold, a lower bound or a result inferred from the profile. An idealized removal of the instrumented profile's 32.18% representation samples gives about **1.47×** for that profiled CPU work alone, not the complete pipeline. Additional gains require other work to become cheaper; replacement bookkeeping may erase gains. Compare complete CPU cost per unit of equal useful simulation, not the Node main thread after moving its work into native threads.

**Capacity arithmetic, not a forecast.** A [standard m7i.xlarge](https://docs.aws.amazon.com/ec2/latest/instancetypes/gp.html) exposes four vCPUs on two physical cores with SMT. A [Graviton vCPU is a physical core](https://aws.github.io/graviton/transition-guide.html); neither is a fixed amount of work across CPU generations. The November 7 discussion's public Ohio Linux On-Demand lookup used 730 hours/month: `m7i.xlarge` $0.2016/hour ≈ $147/month; `c7g.8xlarge` 32 cores/64 GiB at $1.1562/hour ≈ $844/month. Two such compute instances ≈ $1,688; four ≈ $3,376. These illustrative prices exclude database, AI, storage, bandwidth and spare/failure capacity; reprice before provisioning from [AWS pricing](https://aws.amazon.com/ec2/pricing/on-demand/). They neither authorize spending nor replace the standard measurement host.

At a hypothetical 50% sustained compute allocation, 64/128 physical cores supply 32/64 core-seconds per real second. Across 1,000 equivalent independent occupied scenes that is 32/64 ms per scene per real second. Treating one target core as equivalent to one measured execution thread, the measured **1.1196 whole-process CPU-seconds per real second** would require roughly **35×/17.5×** reduction; use total process work, not its smaller main-thread share. CPU equivalence, scene equivalence and the marginal per-scene share are unestablished; database and other service costs remain additional. The accepted planning scenario of 500 concurrent subscribers with twice the scene cost yields similar arithmetic, not a measured workload. Thus “960× required” incorrectly assumes one core must host everyone; the remaining engineering/economics challenge is still substantial.

MMORPG comparisons establish feasibility patterns, not interchangeable workloads. Jagex describes worlds with [tens of thousands of NPCs and a 600 ms game cycle](https://secure.runescape.com/m=news/more-worlds-more-power-the-road-to-greater-capacity?oldschool=1); NPCs can include monsters/animals, but the article does not establish that every NPC receives OpenLegend's perception/memory work or updates equally. WoW's [networking presentation](https://www.gdcvault.com/play/1018184/Network-Serialization-and-Routing-in) shows native server engineering. A marketed realm/world is not necessarily one process or CPU. Distributed populations add occupied-area work; dense populations add interactions and recipient fan-out. RAM is useful for residency, not an exponential CPU multiplier.

Each ported semantic owner performs its own validation, mutation, dependent invalidation and emitted effects. Do not add a generic write API that bypasses those owners. A host-issued capability carries current operational permission facts; native admission still checks actual game prerequisites. All externally delayed effects recheck the existing authority, life, source, definition and timeline generations.

### World and engine boundary

Install immutable definitions once from the world's existing authored source, with exact pins. Resolve runtime field/family access to validated indices/implementations during installation. Native hot loops must not call TypeScript policy callbacks for every actor or sense check. Keep ported executable law under its existing world-owned authoring root, for example `packages/domain/src/worlds/base/native/`, mounted as Rust modules by the native world-composition layer. Move rather than duplicate executable authoring authority when its conversion is adopted; the composition layer selects implementations but contains no world law. Existing authored data/text remains in its current world-owned source and can be exported as a build/install artifact. Rust bridge types own the native API shape; use NAPI-RS's built-in TypeScript declaration generation, not a new schema language or handwritten duplicate interfaces. Generated declarations are not runtime validation. Existing public protocol/provider schemas and the SQL schema remain with their own owners; a bridge DTO does not redefine them.

The proof reuses the existing pure immutable-definition and presentation validators once on finite installation records. Native admission pairs those validated canonical bodies with the actual current SQL records and checks pins, runtime links, population work and continuation itself. This avoids a second static validator without retaining a TypeScript runtime, reconstructing a `WorldState` for validation, or allowing hot policy callbacks. Finite read-only owners retain inactive authored definitions with their real presence, SQL placement and insertion high-water; retaining a definition does not enable an unconverted execution family. ICU word segmentation, Unicode case conversion and collation remain finite language preparation over selected strings; their copies, memory and CPU belong in the complete comparison alongside the existing physical providers.

A manifest lists the required trusted families and their exact versions. A proof runtime refuses an unsupported world at installation. It never substitutes a simpler action, omits a body/sense, or delegates an individual live actor back to a TypeScript world. Full adoption requires the installed standard world's entire supported family closure. No new plugin loader, scripting VM, arbitrary executable generated code or generalized ECS is needed.

## 3. Resident data and lifecycle

### 3.1 Canonical working state

Use stable external identities with process-local slot/generation handles. Resolve IDs at admission/capture boundaries; hot jobs use handles. A reused slot cannot make an old request point at a new body. Physical life, timeline, exposure identity and record revision remain separate existing meanings. Slot order, worker number and cell address are not identities and are never evidence.

Start with dense typed storage for high-frequency physical columns (position/support, motion continuation, body binding, action binding, current mechanical values) and actor-owned variable records for perception, knowledge and history. Do not densify every optional authored property into every entity. Installed schemas assign slots for actual fields; absent capabilities remain absent. Keep large immutable definitions, geometry and received value fragments shareable. Use the smallest layout that passes E1; SoA versus row/chunk layout is an experiment, not a mandate to build an ECS framework.

Every collection states its semantic order. Do not rely on hash iteration, address order or parallel completion order. Rebuildable spatial, due-work and reverse-dependency indexes are derived from canonical state and maintained by the owning mutation. Preserve existing dirty/due selection and sparse queries; porting does not authorize new whole-world scans.

Stored numeric anchors are not necessarily current values. `native-values.ts` retains earned elapsed integration, and `state-owners.ts` reads its current value without settling or emitting effects. Preserve that owner for native reads, captures, writes and restore; reading a dense column directly must not bypass an outstanding rate window. No-op reads/saves do not materialize all meters. Actual relevant mutations settle their affected bindings in the established arithmetic order.

| State                                                                         | Current owner / persistence                                                     | Copy or rebuild rule                                                                                    |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Bodies, actions, rates, elapsed anchors, pending native requests              | Native domain; saved                                                            | Update owned slots/records; retain real unfinished phases.                                              |
| Actual received values, independent clocks, local identity and names          | Native personal owner; saved under current policy                               | Share immutable values only; receiver support and permissions stay distinct.                            |
| Recent changes, required occurrences, knowledge support, correction/frontiers | Native experience owner; saved as existing bounded batches/records              | Append actual changes; edit only affected correction scope; no confirmation diary.                      |
| User grants, control, financial/provider attempts                             | Existing server authority; durable independently of rewind                      | Never copied into character memory or made native-world authority.                                      |
| Long-term personal documents and cold evidence                                | Existing canonical memory/storage owners                                        | Fetch scoped pages when consumed; no lifetime history loaded by a region transfer or every capture.     |
| Worker queues, slot indexes, spatial bins, derived preparations               | Host/native process; transient                                                  | Rebuild after restore; no arbitrary worker cache in saves.                                              |
| AI/view/save captures                                                         | Immutable bounded products with named release owner                             | Share immutable fragments; copy selected changing values once. No unbounded retained world snapshots.   |
| Cell membership and machine custody                                           | Membership derived from geometry; operational custody independent of game saves | Current deployment routing is rebuilt/fenced at restore; it cannot be rewound into duplicate ownership. |

### 3.2 Candidate acceptance and rollback

A prepared candidate is not accepted progress. The current `WorldService.tickBatch` checks finite player-input authority after computation and discards an expired private candidate, including its random draws and events. The mutable core must preserve that distinction. One world has at most one writer/candidate; no reader may borrow its tentative state. Previously captured consumer products remain usable under their existing source fences.

Prepare the next existing coherent prefix through semantic owners, with an operation-local change/undo batch. Record a changed native record/subrecord's before-value once through typed mutation access: a motion slot or contact, not an entire actor, SQL aggregate or enclosing collection. For append-only collections retain old lengths/new keys rather than cloning accumulated history. Include the simulation clock, RNG/allocator state, dependent canonical counters and actual removals. Derived indexes must either restore their affected entries or invalidate only the affected preparation. Reserve scratch/output capacity before editing; inability to reserve ends or refuses the candidate without effects. This is transient rollback support, not a durable journal or generic per-field proxy. Count its copying, rollback and discarded compute in E1/E2.

When an attention owner has prepared a complete replacement, the journal admits its observer key, undo container and retained original body before moving the original optional state into undo and installing the next state. Undo is present before fallible resident settlement, so later admission failure can restore the original allocation. The prepared next state retains its separate working admission; moving the original removes only the clone made solely for undo. In-place edits keep their existing copy-before-edit path. Nested checkpoints retain each intervening original without suppressing the inverse required by an outer rollback.

Use that same change batch for nested operation checkpoints. `commitActorResponse` currently isolates commands and preserves independent component outcomes: speech may succeed while a replacement action is refused, and a refused replacement must restore prior work. A checkpoint records undo/effect-list cursors and RNG/allocator values; first-write suppression is scoped to the checkpoint, not just the outer candidate. Keeping a child retains the undo needed by its parent; reverting it restores only that child and trims its unpublished effects. The response owner records the refusal outside that reverted child. A whole-candidate rejection still reverts every child. Preserve each owner's distinction between refusal and an admitted unsuccessful attempt; `outcome.ok === false` alone is not a rollback rule. Do not add separate transaction machinery for each command family.

Pure availability reads remain the default for previews. Where an existing preview needs hypothetical execution, run the same owner inside a checkpoint, copy only its permitted counterfactual result, and always revert before returning. Preview cannot consume live RNG/IDs/resources, dirty saving, wake cognition or create real evidence; temporary references never become live target handles. Do not rebuild a TypeScript world or fork the full native graph for previews. Include checkpoint copies, repeat writes and nested refusal in E1's cost and equivalence checks.

When computation, required acquisition and recording finish, expose a `ReadyCandidate` with base cut, input/authority bindings and complete effect/cut metadata. The host retains its existing ordered mutation lane, rechecks current permission and finite input leases, then synchronously settles that exact ready candidate through the bridge. For ordinary play, successful compare-and-set from ready to accepted is the acceptance instant; subsequent acknowledgement merely reports it. Protected durable operations retain the database acceptance boundary in section 6.2. Reject, expiry or cancellation before acceptance rolls back the complete private candidate; no event, receipt, save delta, cognition wakeup or debt subtraction may escape. Settlement is a constant-size control exchange, not a callback per actor/field. Acceptance only flips the ready-state fence; rejection schedules rollback on the native pool before the next writer. The ready candidate's large data stays resident.

Before that flip, preserve the live-allocation and accumulating-save admission owned by `HostWork.reserve` and `PendingWorldSave.admit`, converting their inputs to bounded native allocation/charge summaries. Never reconstruct a TypeScript world to call them. Preparation supplies their charge/delta; acceptance cannot be followed by a capacity refusal that loses accepted changes. Native codec sizes or conservative encoded-size bounds accompany changed records, including occurrences/receipts; do not serialize every unchanged payload to count bytes. Rejection releases provisional capacity after rollback; acceptance transfers the charge to its actual retained owner. In-flight saving and newer accumulation remain jointly bounded. Include reservation work and conservative overcharging in E1/E3.

After acceptance, publish one ordered `MutationBatch` of changed keys, exact occurrences, receipt outcomes and invalidations. A later interval's failure cannot roll back that accepted prefix. An unfinished/private interval within the candidate is not an already earned prefix; preserve the current S2 non-adoption and coherent return contract. Unexpected panic poisons the runtime and prevents further admission; recover from the last complete durable world cut under the existing unsaved-suffix crash contract, never by assuming an incomplete undo batch repaired a half-write.

Changes carry complete domain meaning, not generic property notifications. Consumers subscribe to existing semantic change classes. Unchanged access does not increment revisions, create history or dirty saved data. Genuine unchanged sensory confirmation may still update its independently needed current clock; coalesce that metadata at save time. The engine must not turn worker completion, route legs or proof bookkeeping into events.

### 3.3 Randomness and allocation

The first proof preserves the existing saved RNG algorithm/draw sequence and identity allocator. Random-dependent decisions and allocation resolution occur in the established deterministic semantic order; parallel workers may perform pure calculations without consuming either global sequence. Give temporary created references operation-local handles and resolve them at ordered commit where necessary. Never allocate IDs or draw randomness in work-stealing callbacks.

This leaves a small ordered stage, which is measured rather than assumed free. **Per-owner random streams are not selected** merely to make distribution easier: they alter seeded outcomes and require their own behavior/continuation decision. Distributed jobs return random-dependent proposals to the same ordered decision owner until a justified replacement is designed. Fewer independent random opportunities may limit scaling; report that cost rather than silently changing the model.

## 4. Native/application boundary

One long-lived native host owns the simulation instances. Node owns request scheduling, network I/O and existing repositories. NAPI-RS exports cheap enqueue/readiness methods; substantial work runs on an explicitly bounded native pool, not the Node main thread or a new unlimited libuv workload. The JS-visible object holds an opaque host handle; an asynchronous method enqueues owned inputs, never borrows a JS-owned mutable object across an await. Do not create a pool per actor, cell, request or world. The pool shares a host CPU budget with existing geometry/navigation/checkpoint workers.

Use these logical operations; exact generated names can follow local naming conventions:

| Operation             | Input                                                                                   | Output / guarantee                                                                                                                    |
| --------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Install               | Validated current-format record stream, exact world manifest, operational generation    | Runtime handle or complete refusal; no creation hooks replayed.                                                                       |
| Submit                | Request identity, typed command, current authorization scope, input lease/clock binding | Prepare one candidate or typed refusal; no effect is accepted merely by enqueueing.                                                   |
| Advance               | Admitted game-time horizon, bounded external query completions, stop request            | Ready coherent candidate, required external preparation or refusal; accepted progress/debt changes only on settlement.                |
| Settle candidate      | Exact candidate/base cut, accept or reject after host fence checks                      | Synchronous ready-state acceptance, or rollback before reuse; duplicate settlement returns its established outcome.                   |
| Capture               | Principal/actor/audience, required purpose, selected source/query and current fences    | Fixed permitted facts/cut and explicit missing/partial coverage; no raw full-world return.                                            |
| Preview               | Authorized actor/editor scope, typed supported operation and current source bindings    | Existing availability or bounded counterfactual output; hypothetical execution is reverted, and real execution needs fresh admission. |
| Apply prepared result | Original request/dependency bindings and bounded result                                 | Prepare through the same candidate/settlement owner, or return stale/refused; no direct mutation bypass.                              |
| Prepare save          | Accepted prefix or exact held protected candidate, plus writer allowance                | Immutable canonical row changes, exact append/removal/reference metadata and cut identity.                                            |
| Acknowledge save      | Exact attempt/cut and successful durable revision                                       | Release only that saved prefix; preserve newer changes and retry data on failure.                                                     |
| Stop/replace          | Current authority generation and lifecycle intent                                       | Quiesce admissions, finish or classify bounded work, release resources; old completions stay fenced.                                  |

Use owned batch buffers for high-volume outputs and generated typed objects for small commands/control. Initial conversion may copy a bounded payload once; zero-copy buffers, custom binary codecs and unsafe layouts are optional E3 experiments. No per-field FFI call, retained JS object in native worker code, repeated JSON parse/stringify of the same output, or hidden mirror `WorldState` is permitted. Node resolves a completed promise with its exact scope; native callbacks must not inherit ambient `AsyncLocalStorage` authority.

Preserve the host's ordered authorization/mutation lane across the asynchronous bridge. For ordinary live effects, the host checks current operational permission and finite input leases immediately before the cheap synchronous candidate acceptance, with no intervening await. Protected durable settlement follows section 6.2. This keeps real-time authority in the host and deterministic mechanics in the core; copying a lease at job enqueue is insufficient. Relevant grant/control changes serialize through the existing lane; delayed proposals use it too. A rejected settlement releases native capacity only after rollback finishes. A disconnected/timed-out caller does not cancel accepted play, free a still-running job or authorize retry; use the existing receipt outcome. Saving accepted play does not reauthorize against a later expired session. Routine native settlement uses the existing in-memory input/permission fences, not a SQL authorization poll per prefix. Existing protected checks retain their owner; no second grant repository is added.

An admitted command/pause waiting behind advancement can set one native host stop-at-boundary flag without waiting for the compute job to return. Check it between bounded cohorts; it requests a coherent candidate return, never exposes partial state or changes game time. A tiny synchronous bridge call must not wait for the world lock held by computation.

A client receives its existing public protocol, not the native internal representation. Server formatting can remain TypeScript only if it operates on the already selected capture. Menu, action preview, inspection, recall/context, authoring preview and diagnostics must not request the entire graph to recreate old domain helpers. Current source/version bindings stay server-side. Authoring enters through reviewed typed native install/edit operations, with ordinary exact pin and current-save validation.

Maintenance deadline extraction is an accepted-state native read, even after its actor capture exists. The application keeps capture, raw-time extraction and read release in the same existing accepted-boundary callback; it does not carry an unprotected live read across a possible private candidate. Returned deadline data owns its independent allocation. Advisory scheduling, final current-source checks and the synchronous disclosure lease retain their existing owners.

## 5. Single-machine execution and work pooling

### 5.1 Initial scheduling algorithm

1. Host admits elapsed real time once using the current clock/input owner. Native code receives game time and stop signals, never reads wall time to decide mechanics.
2. Reuse the current semantic deadline and motion-boundary owners to select a valid next interval. Do not replace the game with fixed per-second loops or new future-visibility prediction.
3. Select dirty/due subjects and relevant spatial candidates before preparing jobs. Reuse the established phase order and trusted family declarations; construct typed disjoint ranges with the actual input revision and deterministic output positions. Do not build a general dependency graph or enumerate every field read for every actor on every interval.
4. Run independent calculations against the same coherent read boundary. Split sufficiently large physical/sensory cohorts into bounded jobs; keep tiny jobs inline. Systems sharing mutable effects remain ordered.
5. Apply disjoint owner outputs in parallel only where Rust can express genuinely disjoint storage. Shared effects, random choices and conflicts use the existing deterministic phase order. Same-time competition for an item is never decided by which thread finishes first.
6. Complete required personal acquisition and recording before returning the ready candidate. Host settlement accepts or rejects the complete candidate under section 3.2; publish only accepted boundaries. Produce current-view and save work only for actual consumers/changes. Optional AI and maintenance proceed through their existing asynchronous owners.
7. Honor the existing coherent-prefix yield/stop rule. Queue waiting is not game progress. Retain unadvanced debt and pending work honestly.

The first parallel implementation uses explicit phase barriers and disjoint borrows, not a new general-purpose task-graph engine. Overlapping reads share one stable phase input; each observer job must not copy the same candidate bodies or geometry again. Families without a proved disjoint split remain serial.

A work descriptor is a compact typed family/range plus captured revision and output slot; not a closure holding the entire live world. Native tasks cannot call arbitrary Node code or wait for database/model/network I/O. External prerequisites return a typed pending request; current world-hold versus entity-local navigation policy stays unchanged in the proof. Ready candidates and blocked external work retain their logical ownership/reservations but release compute capacity; a queued capture cannot occupy a worker waiting for another operation to settle.

Use stable chunk ownership and a single explicitly sized Rayon pool for E2. Work stealing moves ready jobs, not permanent character authority. Prefer locality but allow idle threads to help. Reuse output buffers within the bounded batch; do not retain stale actor views between revisions. A local one-thread mode is the control, not a compatibility backend. Job size and maximum outstanding native bytes use [NSC-L02/L03](../limits/native-simulation-core.md#nsc-l02--compute-capacity-and-job-granularity).

Ready jobs are bounded across the host, not multiplied by worlds × cells × workers. Keep one range cursor per admitted unfinished batch, and round-robin eligible worlds/owners at coherent boundaries while preserving existing interactive priority. A canceled/stale external preparation releases its exact output; it does not retry indefinitely. Record discarded work in E2/E3. On large hosts, memory bandwidth, cache locality and NUMA placement can dominate; do not add socket-aware scheduling before that cost is demonstrated.

### 5.2 Natural independent work

Parallel candidates include geometry queries, path requests, different observers' acquisition calculations, independent status/rate calculations, selected context projection and changed-record encoding. Interacting body resolution, shared inventory transfers, outcome ordering and permission changes are not automatically independent. One subsystem must not be permanently pinned to one core. One actor must not become one OS thread.

Reusing geometry does not share private evidence: a common calculation may answer a physical predicate, while separate receiver scopes still determine what was acquired. Conversely, do not duplicate a physical simulation for each observer. Capturing every actor merely because any actor changed would reproduce the original multiplicative cost.

Scoped exposure preparation must retest changed people for their prior viewers even when both pending positions are outside the current spatial envelope. Otherwise merging unchanged roster entries can retain a departed person without current sensory support. Intersect existing selected observers’ visible rosters with pending source changes, funding the existing changed-person/detail sets before publication; missing or newly object-category sources still need removal/category reconciliation. This derived preparation grants no observation or detail by itself and drops on refusal without mutating canonical state.

Some remaining work will be serial, memory-bandwidth-bound or I/O-bound. Report task scheduling, synchronization, copying and total CPU, not just worker utilization. More busy cores are not evidence of more useful progress.

## 6. Captures, saving, correction and restoration

### 6.1 Stable consumer products without a permanent immutable world graph

Active state is mutable only through its owner. A consumer capture copies its selected changing values and shares genuinely immutable definitions/value fragments. Current facts retain the exact existing measurement/acquisition/check/source clocks; a capture time is not a new observation. Admitted asynchronous bridge work acquires the existing world mutex on a native worker; brief synchronous currentness reads must not turn that work into a fatal publication refusal. ## 7. Cells, borders and local authority

### 7.1 Cells are ownership units, not gameplay rooms

Start E4 with a regular grid in the selected geometry provider's coordinate space, keyed by spatial-space ID and integer cell coordinates. Its side length is operational tuning, not a world law or a universal sensing range. Assign a physical root by its canonical anchor; attached contents move with their existing root relationship. Query indexes still cover actual body/assembly extents. A large object crossing many cells has one authority and a conservative spatial query representation, never a cloned body in each cell.

A machine owns a set of cells, and the native pool executes their ready jobs. Many cells can share one machine; one busy cell can use multiple pure/read-disjoint jobs. Initial cells remain stable while machine assignments change. Finer cells are a later E4 tuning comparison if one indivisible cell blocks balance; do not start with arbitrary moving polygons or continuous global graph partitioning.

Spatial membership, gameplay location, update responsibility and process address are distinct. Crossing a grid line updates membership immediately, but need not move data or a job to another machine. Operational regrouping creates no in-world arrival, sight loss, attention exit, memory, action interruption or observer identity.

### 7.2 Read overlap and interaction ownership

Cells have precise owner assignments and overlapping **read coverage** for actual supported dependencies. Derive that coverage from installed sensory/effect reach, body extents, swept movement and explicit nonspatial references. Do not assume a fixed neighbor count covers every authored reality. Unknown influence scope conservatively joins the required execution scope; it is never silently ignored. Unsupported distributed families keep the world/affected work colocated until qualified.

For every interaction, the initiating semantic operation has one owner and an exact participant/dependency set. A contact pair uses canonical ordered body IDs to select one resolution owner; a directed action uses its already admitted action owner. Observers receive actual permitted outcomes independently. Read replicas carry source revision, physical life and covered time; they are disposable computation inputs, not copied minds or authority. Internal access to shared state does not permit client/model disclosure.

A cross-cell effect prepares the exact current participants and applies once at a coherent boundary. Conflicting writes serialize within that affected scope. Independent cells continue eligible work. A shared object or world-wide law is a real dependency and can legitimately enlarge the scope. A single giant battle cannot be made arbitrarily parallel by drawing more cell borders.

### 7.3 Stable ownership near borders

Use hysteresis for _machine_ migration, not delayed physical membership. The existing owner may retain an entity inside a bounded overlap belt after it crosses the nominal assignment. Transfer after sustained residence on the other side or exit from that belt. Routing resolves the actual owner, and spatial queries include remotely owned bodies at their real position. A minimum residency time discourages reversal; it must not prevent transfer when the old owner can no longer safely cover the required dependency scope or is draining.

The cell-assignment owner tracks these temporary exceptions in one bounded directory. Remove them after transfer/removal and reconstruct operational routing on restore. Do not create another permanent location property. Select a group migration over repeated individual transfers when a gathering moves together. Default experiments and overflow behavior are in NSC-L05/L06; no grace period suspends collision, hearing, damage or current evidence.

Every work offer declares a start cut, a valid through-time and its conservative read/write/influence scope. Work whose scope intersects is ordered or jointly scheduled to a common boundary. Before joining previously independent scopes, bring them to a common valid boundary using current dependencies. If influence cannot be bounded, join/co-locate the affected scopes or retain the current coherent world boundary. No speculative rollback or predictions of arbitrary future actions are selected.

Concretely, the time/admission owner pins a closed input prefix and the influence/dependency epoch for each offer. Newly arriving commands retain the current rule that their effective time follows already owed time; they cannot be inserted into an issued offer's past. Before issuing offers, the coordinator combines overlapping conservative scopes using touched spatial cells and named resource dependencies, not all actor pairs. An unproved family uses the complete affected world scope. For the coherent distributed control, the controller gathers ready candidates for the same base/candidate cut from every participating owner. Any pre-acceptance refusal rejects the entire unaccepted cut and preserves owed time. Otherwise one controller settlement accepts the participant manifest; owners resolve late/lost acknowledgements against that decision ID rather than execute again or independently abort. Views and saves cannot combine partially settled participants. A scoped read pins the necessary owners at one accepted cut only until its selected values are captured; it does not copy every region. Controller/state loss uses section 8.2's whole-world recovery. Ordinary interval settlement remains in memory; no SQL transaction or new consensus service is added per interval.

This can propagate a wait through a genuinely connected interaction chain. The target is no unconditional world-wide barrier per action; it is not a promise that all worlds can always progress independently. Preserve the current world-hold navigation policy unless its separate owner changes it. Unknown/global native families use the conservative path. E5 must measure dependency preparation and waiting; if that cost erases the benefit, do not distribute that workload. Exact cross-world clock compatibility and broader federation remain PS-D03/PS-D04 work.

### 8.2 Machine handoff protocol

One logical-world controller retains accepted time/cut ordering, RNG/ID allocation, receipts and the existing writer; compute owners hold disjoint active records. In the initial coherent-advancement control, all required owner results join the same accepted world cut, and one slow owner can delay that cut. Independent advancement is the separate E5 variant, not an assumed benefit of adding machines.

Reuse the existing request/receipt IDs and authority generations. Add operational custody only at this stage: `(world, timeline, scope, owner, ownershipEpoch, stateRevision, transferId, state)`. Store the decisive fence through the existing authority/storage owner; it is not part of a rewindable gameplay checkpoint. Directory lookups are cached by exact epoch and updated on ownership changes, not queried from SQL for every movement sample.

1. **Prepare:** reserve destination resident and transfer capacity; warm immutable definitions/geometry and existing boundary inputs while the source remains active. Record the exact candidate scope/epoch. Do not start a second simulation or copy mutable state under an unpinned cut.
2. **Quiesce:** stop new admissions for the transferring scope, settle/reject any private candidate, and reach one valid accepted boundary with required coupled scopes. Pin root membership and active record/reference closure. Queue new commands in the existing bounded controller lane. No in-world Stop is emitted; accrued real time remains owed. Unrelated calculation continues where permitted; independent time publication is not promised by the coherent-advancement control.
3. **Stage:** stream that stable active closure directly in acknowledged bounded chunks under one manifest/cut. Transfer stable identities, pending native continuation, exact operational inputs and receipt bindings; rebuild local slots at the destination. Source state stays readable and frozen for this scope, so neither a full copied snapshot nor a live-copy suffix log is needed. Destination validates pins/references and cannot execute or publish. Cold history stays in its repository. Reserve destination residency independently of the transfer-buffer allowance.
4. **Fence:** after staging completes, the controller compare-and-swaps custody from the expected source epoch to the destination epoch through the existing durable authority owner. Record the transfer ID, staged accepted cut and last complete durable world revision distinctly; a custody record does not make unsaved gameplay durable. Already accepted save work remains owned by the central writer and ordered once; it must not be resubmitted or rejected just because its source's custody changed. A rejected/uncertain fence is resolved by reading its exact outcome.
5. **Activate:** destination starts only under the committed new epoch. Route queued commands and prepared results through current owner/dependency checks; expired live input is not renewed by transfer. Deduplicate using existing receipts. Source cannot mutate under its old epoch and releases selected active data after acknowledgement. Reassignment inside the same native host/process reuses memory and needs no transfer transaction; another process, even on the same machine, uses the fenced handoff protocol.

Before fencing, resume the source only after the controller records cancellation against the exact transfer/epoch and confirms that its fence can no longer commit. A timeout with an uncertain fence leaves the scope quiesced until its outcome is resolved. Resume the frozen accepted state with current input checks. After fencing, never resume the old copy independently. A lost response alone does not prove failure. If a process failure loses required accepted state and safe continuation cannot be established, stop admission for the logical world and recover **all** its owners from the last complete durable world cut under fresh custody epochs. Never rewind one region while keeping another region's later consequences. This first distributed stage deliberately retains existing whole-world crash recovery; independent regional recovery is not selected. Failure before/after fencing, restart, correction and commands at every stage require actual qualification.

Measure the quiesce/transfer pause, backlog and coupled waits in E5. If they fail the existing responsiveness gate, reject the simple transfer for that workload. Only then consider a separately isolated E5 live-precopy variant: immutable capture of the selected initial closure, bounded ordered membership/record deltas, final quiesce and exact catch-up before fencing. Include copying, retained generations, repeated bytes and nonconverging motion in that comparison; cancel before fencing when bounded catch-up fails. Do not build precopy machinery as a prerequisite to the Rust or single-machine proof.

Read overlap retains nearby physical inputs needed for actual boundary interactions; immutable terrain/definitions can remain in bounded reusable caches. Crossing back still requires current mutable state and a new custody fence. Any conditional precopy buffer is released after its handoff. No mechanism keeps a full synchronized former-owner cache.

### 8.3 Adaptive assignment algorithm

Keep stable cells; change their grouping. Use bounded counters already available from completed jobs/messages: actual CPU service, retained active/capture bytes, queue age, cross-machine bytes and required dependency waits. Do not infer load from player count alone. Track active neighboring communication edges plus actual named remote dependencies; no observer-by-object/all-pairs graph.

At a low-frequency operating opportunity:

1. Aggregate recent cell work and active cross-machine edges. Expire idle telemetry. Maintain bounded heavy-edge candidates; losing optional telemetry means retaining the current placement, not losing gameplay messages.
2. Consider an overloaded cell group or a sustained heavy communication edge. Generate bounded neighboring-cell moves, initially one cell or its already coupled small group. Prefer transferring colder work away to make room for strongly interacting cells.
3. Refuse a candidate exceeding destination memory/CPU/service headroom or involving an active transfer/unsupported dependency. Include required read-overlap expansion in the predicted load.
4. Estimate saved recurring communication against **one-time transfer plus warmup, added overlap and placement work**. NSC-L06 supplies provisional amortization/hysteresis thresholds; estimates are only candidate selection, not performance evidence. No negative-benefit balancing merely to make CPU charts equal.
5. Migrate one bounded candidate at a time through the custody protocol. Observe actual improvement before making another move involving the same scope. Cancel or back off if traffic, pauses or total work worsen. Retain cooldown/residency to avoid chasing a moving crowd each frame.

If every useful grouping overloads a machine, preserve correct distributed interaction and report insufficient capacity. Do not force players apart, create invisible walls, lower perception or call a queued-away participant supported capacity. Product congestion/admission choices remain with D22/PS-L01; this design adds none.

The first implementation uses a local greedy placement heuristic, not optimal graph partitioning, Kubernetes rescheduling per actor, predictive AI or a bespoke distributed-actor framework. Multiple machines in one deployment Region are the qualified scope; WAN/mixed-build live migration is excluded. Same-process regrouping normally moves ownership metadata, not serialized state.

Reduced evidence/output counts require semantic explanation; dropped behavior invalidates comparison.

The proof must show a material integrated advantage under existing preselected performance criteria and preserve every declared journey. The dedicated qualification owner selects numerical gates before runs; this design does not invent a new percentage threshold or silently weaken current gates. Inconclusive or small gains do not authorize broad migration. Freeze the result and report whether representation, language, parallelism or some combination earned adoption; stop expansion if the foundation does not justify its cost.

Extend the existing [hierarchical measurement owner](../performance/hierarchical-profiling.md) with native operation/queue/capture boundaries. A V8 profile alone does not account for the native compute pool. Use a separate symbolized Linux `perf` or `samply` diagnostic covering native threads, alongside whole-process/thread CPU, allocation and existing SQL accounting; do not sum inclusive profiles. Keep clean throughput/latency runs separate from instrumented runs. Release artifacts need source-line symbols; qualify any frame-pointer/instrumentation overhead and record build flags so moving work out of JavaScript cannot masquerade as eliminating it.

### Build and deployment contract

The [Rust Performance Book's profiling guidance](https://nnethercote.github.io/perf-book/profiling.html) provides the Linux profiler and release-symbol setup; [rustc frame-pointer controls](https://doc.rust-lang.org/rustc/codegen-options/index.html#force-frame-pointers) support diagnostic stack attribution. Use `debug = "line-tables-only"` for profiled release artifacts. Begin with ordinary stable release optimization; toolchain/build tuning remains E7 rather than a prerequisite infrastructure project.

- Select and record the current stable Rust release at NSC01, pin its exact toolchain in the Rust workspace, and pin dependencies through one committed `native/Cargo.lock`. Retain the existing single `pnpm-lock.yaml` for JavaScript; no per-crate/package lockfiles or second JS package manager.
- Keep first-party Rust under the repository's AGPL-3.0-only policy. Check actual dependency licenses/maintenance and exact compatible bindings before pinning them; no broad engine upgrade merely to match a tutorial.
- Generate the bridge declarations/loader with the pinned [NAPI-RS build tooling](https://napi.rs/docs/introduction/getting-started), using its Rust exports as the source. [Declaration overrides](https://napi.rs/docs/concepts/napi-attributes) do not change runtime conversion: use actual typed conversions and owner validation, not `ts_type`/`readonly` annotations as safety checks. Integrate the minimal addon into the existing workspace/build; do not adopt a template's second package manager, broad CI/publishing workflow or automatic tests. Existing public protocol remains stable unless a separately identified required change is converted across all consumers. No duplicate command enums or world-specific vocabulary in the bridge. The build wrapper runs Cargo offline and locked, with automatic Rust installation disabled; install the exact pinned toolchain and populate its dependency cache explicitly before building. Compiler execution is local-only and grants no package-download or general shell capability.
- Build Linux x86_64 for the standard AWS proof and the developer's required local target for correctness. ARM64/Graviton is a separate correctness/performance qualification before deployment; do not claim interchangeable core speed or bitwise physics. Artifacts identify toolchain, target, features and source; a live world uses one matching build/definition set.
- Core arithmetic remains `f64` where current JavaScript uses it; retain explicit f32 provider boundaries and tolerances. No fast-math, unordered floating reductions or narrower health/time types to win a benchmark. Keep exact counts/identities within their validated ranges, using checked arithmetic where overflow would violate quantity, quota, identity or time contracts; debug-only assertions are not runtime validation. Same-build input/restore/thread-count reproducibility is required; cross-architecture bit identity is not promised without its own evidence.
- Use `cargo fmt`, focused `cargo check`/Clippy, the actual release build, generated-interface checking and existing Node build paths as appropriate. Do not make every developer edit a release-LTO rebuild. Measure build bottlenecks before adding sccache, a different linker, extensive crate splitting, PGO or custom allocators; these remain E7 candidates.
- Bound native host shutdown: stop admission, settle/classify active semantic work, finish the existing required save barrier, cancel optional queued jobs, join owned workers and release callbacks. Do not terminate another contributor's process or retry uncertain paid work. Catch unwind at native job boundaries and poison the affected runtime; no unwind may cross FFI. An abort/OOM follows host-crash recovery. Panic/worker failure is an explicit unavailable runtime, not a fallback to stale TypeScript state.

## 12. Design review and delivery boundaries

Three review lenses apply before adoption: (1) the complete player pipeline and its privacy/chronology, (2) total work including scheduling/capture/persistence/maintenance, and (3) independent ownership, coupled conflicts and recovery. Important rejected shortcuts are a faster isolated loop with omitted consumers, all-field publication on every tick, a second writable mirror, a per-person process, per-cell full snapshots, and a migration graph whose upkeep exceeds the traffic saved.

Keep the core useful even if distributed adaptation never earns adoption. A single machine with direct state and bounded jobs is a complete deployment shape, not temporary scaffolding that must pay a network abstraction tax. Conversely, full supported-game adoption is not complete while authoring, grants, cold memory or restore still depend on a hidden TypeScript authority.

The technical uncertainties are explicit experiments; no unresolved product choice blocks the scoped proof. D22/D61's exact larger distributed envelopes, capacity and federation requirements remain with their existing owners until their stage is qualified. Do not label those whole decisions complete merely because this design specifies one conservative same-world execution path.
