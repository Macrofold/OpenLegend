| Status      | Current progress                                                                                  | Last updated |

| In progress | Native NPC thought references are implemented, with sustained crowd service still open in PS04-A. | 2026-11-25   |

A player can make fifty people witness the same performance and still get fifty different accounts of it. The implementation must answer three separate questions: **what reached this witness, what requires their choice now, and what can they recall later?** The [feature](../features/noticing-and-remembering/README.md) owns those answers. The steps below extend the existing perception, decision and memory owners. A quiet witness can supply a useful lead later even if the server never asked a model about the performance.

## 2. Select personal reasons before selecting prompt detail

1. **Start at the accepted change.** Compute an act's own identity, order, outward components and authored default importance once. For each actual receiver consume the evidence reception already produced. Keep the receiver, life, time, modality, precision and source binding. Detection, seeing a face, recognizing someone, hearing words and knowing one was addressed have different prerequisites. An NPC behind a hedge can have heard evidence with no visual reference. Work on one NPC's private bodily change starts with that NPC.
2. **Match only applicable changes.** Dispatch by installed fact family, then affected actor and subject, active work or supported cue. Resolve a known subscription directly on its work owner. For an event use its occurrence identity. For a continuing condition use the existing onset, supported escalation, clearance and generation on its owner. Apply required physical results immediately. An already chosen valid step may settle a choice. Unknown coverage supplies neither a negative observation nor clearance. Evaluate independent reasons even when one is satisfied. If two prepared voluntary actions compete for the same body or item, use the accepted work’s explicit priority. With no settled precedence, leave the alternatives for one decision; the native action owner still validates the chosen step.
3. **Give the native intake reader the result.** For an occurrence, carry the receiver role and needed source bindings with its existing personal record into the intake read. For a continuing condition or blocked step, expose the matching revision from the existing latch or work owner. Do not duplicate it in a memory just to wake the scheduler. Logically a reason is `(receiver/life, reason family, exact supporting receipt or condition generation, affected choice owner if any)`. Reuse the existing source and task identities. Put labels, words and optional context behind those references. An ordinary received change can have **zero** reasons. The physical effect, evidence recording and discovery paths still run. No durable “ignored” row or reason per gait sample. Retention eligibility is independent: a reason can expire after its choice, and a witnessed fact can outlive a decision the NPC never needed.
4. **Select required evidence before optional detail at both limits.** In `unseen_intake`, select the sources for each still-open choice before ranking incidental records. Apply the same precedence to the second sort and eight-record limit in `Inspection::propose`. Carry those required references through prompt preparation even if optional recall fails. Exclude forgotten or withdrawn evidence, own speech, inferred summaries and duplicate accounts of an already handled occurrence. Preserve self outcomes, internal reviews, threat, protection and prepared-action results on their existing paths. For speech use the listener’s role (§3 and step 6). For directed actions use the received consequence. An ordinary observed event needs an independent personal reason. Importance can rank detail. A raw world event has no authority to speak for a witness.
5. **Serve a complete choice and keep the remaining work reachable.** Use the existing actor wake to request inspection. Prepare full evidence only for the chosen NPC. Coalesce compatible reasons, deduplicate their required sources and keep per-NPC ordering and fair service. Return the last fully handled prefix of the actor’s evidence sequence. Take ordinary required groups oldest first. Keep equal-sequence sources together. An urgent choice can run ahead only with durable ownership of its exact cause so later paging cannot repeat it. Stop the cursor before the first unserved group. Commit the job and prefix together through `accept_thought`. Cap the prefix by `npc_schedule_durable_identity()`, which counts sequence identities. The world save revision and the largest sequence seen during inspection cannot substitute for that result. If another page has a serviceable choice, leave the NPC pending for its next available slot without waiting for a fresh incident. If one group exceeds the full allowance, surface capacity and wait for a relevant change. Refused slots and rolled-back commits acknowledge nothing. Quiet witnesses need no SQL write per event.
6. **Recheck at actual use.** A detected player address made through interactive Send belongs to its chat job, even if the words were masked or the provider later failed. Suppress an automatic duplicate only for that same recipient and utterance. Addressed speech without a chat owner, such as an NPC speaking to another NPC, uses ordinary scheduling. A different overhearer can independently qualify. Preserve provider admission, per-NPC ordering, refresh policy, cancellation and the original evidence/time when a reply is held. At application, recheck physical feasibility separately: a cart that has rolled away cannot now be caught. Unrelated accepted activity and ordinary save acknowledgement do not invalidate a still-current request. Losing sight ends present visual support but need not revoke the historical fact that the gesture was seen. Explicit withdrawal of that fact invalidates a dependent request. Provider failure or an unserved choice conveys no consent, decision to ignore or outward action. A reconnect or repeated command can recover the original receipt without applying its effects again.

An optional discovery remains one reserved attempt per genuine free interval in the bundled world. A pre-dispatch refusal releases the reservation; a dispatched attempt spends it even if it fails. Starting or finishing a thought cannot renew the interval. Other sources can still enter the next independently warranted decision.

In the jester case, appearance, flip and gesture retain their order. There is no debounce timer. For the [specified fifty witnesses](../features/noticing-and-remembering/scenarios-and-acceptance.md#the-jester-and-fifty-witnesses), the directed recipient and the guard with an unresolved instruction have a choice. A private fear may supply a third. The other 47 can observe, continue working and later answer a question. Someone actually seeing a frightened witness stumble receives a new event. Neither the private emotion nor the first wave of model results is broadcast to the crowd.

For an explicit appeal, the installed speech act renders the words conveying the selected request and contribution. Bind each term to its occurrences in that final utterance. The [speech receiver](../../native/simulation/src/speech/receiver.rs) discloses it only if the listener received those required words. A matching word elsewhere cannot fill a masked gap. Compare the same market with inference off and on, counting correctly helped requests, unrelated offers, masked terms, provider calls and total cost.

For each enrolled character, the authorized world/character editor binds the sensitivity to a pinned rule through existing private character state. At recognition, apply the appraisal and settle the condition onset in the same native candidate before the server offers deliberation. A refused candidate leaves both feeling and onset unapplied. ### Overheard speech matcher experiment

The [bundled grammar](../worlds/base/speech.md#overheard-personal-references-experiment) classifies one listener's recorded speech and already recognized self-names. The callable Rust component uses the pinned language provider. It returns the first complete match in heard-passage and word order, otherwise a name match if one was heard, otherwise no match. A complete match borrows the whole original heard passage, which may contain surrounding words. Keep its awareness receipt as evidence. The result supplies no identity, verified assertion or new speech record.

For future live integration, complete Step 1 first and use its personal source selection and receipt lifecycle:

1. **Read the right evidence.** Use the [receiver's](../../native/simulation/src/speech/receiver.rs) `OverheardSpeech` role and actual linguistic `PerceivedSpeech`. That role includes speech addressed to someone else. The public directed flag alone cannot tell who received a direct address. Leave self, seen-only, sound-only and personally addressed speech on their existing paths. Use the listener's proper self-name from the [personal name reader](../../packages/domain/src/worlds/base/native/knowledge.rs) and any aliases already recognized through an existing owner in the same event-time scope. The speaker's labels, fallback labels such as “person” and names learned afterward supply no self-name evidence.
2. **Evaluate before limiting intake.** Prepare the match while that listener's receipt and name basis are available, through the existing typed language boundary. Pass the small derived result and exact receipt identity to [native unseen intake](../../native/simulation/src/experience/intake.rs) before its first limit, then carry any required source to [server selection](../../native/game-server/src/npc/schedule/select.rs). The later summaries lack the original heard structure. Keep matching finite per newly handled receipt and listener. Use existing speech bounds and resource admission. Leave ordinary speech, saves and captions independent of matcher readiness. Do not rescan settled speech on each wake or query aliases across the world.
3. **Offer only an unresolved choice.** Name-only may draw attention where supported. A complete match can offer a response or clarification through §2 when the listener has a live personal stake. The allegation itself can leave the listener with an open choice even when the name is ambiguous. A binding already supported by the act can supply the same personal reason without language matching. Coalesce both routes for that listener and occurrence. Another namesake can qualify independently. Full quotes reach cognition as attributed words, with the possibility of silence. Existing funding, privacy, revalidation, cancellation and exactly-once effect rules still apply.
4. **Keep refusal distinct from a result.** A completed no-match or name-only result satisfies this check. If language preparation or scratch space is unavailable, count the optional check as unserved, accept the ordinary speech and continue intake for independently warranted work. Leave the words available at later cognition. This optional check owns no separate queue or cursor. Once a match supports an admitted reason, the ordinary pending-prefix and source checks in §2 apply.

### Watches and affected rules

Use the [existing watch terms and subscriptions](attention-and-investigation-tech-design.md#41-event-and-level-subscriptions). Admit one installed event or level predicate, its operands, dependencies and funding together on the existing activity control. A refused request leaves the previous control intact. Match an event against the personally received occurrence. For a level, use the existing initial-report policy and rearm only after supported clearance. Loss of sight leaves the level unknown. Keep expiry, replacement and loss with the control. An absence test still needs coverage through its due time. A learned two-flash signal still needs two distinct witnessed flashes and a world rule that recognizes that sequence.

Defer composing independent predicates under one watch. If a repeatable gameplay need justifies it, a combined level must respond to changes on either side. For example, the gate can close while Mara remains in view. See the [scope and admission limit](../limits/attention-and-investigation.md#ati-l03--selected-input-and-composition-envelope).

Begin with the event families and active controls already owned by the current actor. For registered definitions, resolve compatible rules once on installation and group by required input family. Actor-specific entries are installed/removed with the actor's actual sensitivity, task or known name. A query follows keys for this receipt and actor. A dormant rule about an unrelated family has no per-witness evaluation cost. Genuine density can still be expensive when many rules or people really do match. Before creating a secondary runtime index, measure simple actor-local matching against it (§6). Removal, withdrawal, life replacement and restoring the world must yield the same matches as a fresh build from the canonical owners.

## 4. Keep literal memory and attach references

Extend the existing actor-owned memory and summary bodies. Keep the original text field and its exact [UTF-16 representation](../../native/simulation/src/text.rs). Use [`ObserverSubject`](../../native/simulation/src/reception.rs) for an identified individual, the reference to an already acquired [known place](../../native/simulation/src/experience/places.rs), a permitted object identity, a pinned world category, a supported game-time interval, or [`PersonalSourceRef`](../../native/simulation/src/experience.rs) scoped to the account owner. Do not copy a place capsule into each mention. The following is a logical layout for **optional** annotations on one revision of one text field. It is not a new memory class.

```text
references   local key → identified subject | known object/place | known category
                       | understood time interval and calendar | personal source revision
bindings     (start inclusive, end exclusive, local reference key)
```

Offsets count UTF-16 code units in the stored literal, after decoding JSON and before any display formatting. Each binding addresses exactly that occurrence. Several bindings can overlap, use the same range, or reuse one key. A citation about the account as a whole belongs in the existing source manifest. An unbound word stays in the literal. No mandatory speaker, claim parser or type for “thought” versus “heard.” Keep the external speech occurrence and the listener's record of it separate.

For `I heard Mara say ‘I like cats’, and I judged her for it.`, the bindings are `[8,12) → person` (Mara), `[45,48) → same person` (her), `[18,29) → listener’s utterance evidence` (I like cats) and, if established, `[25,29) → category` (cats). In a promise about collecting a violin “tomorrow,” keep that word even when its original calendar interval is known. A character may know which person spoke without knowing which violin they meant. Use the witness's stable identified subject through all retained facts about that person, including unnamed individuals. A personal ID enables historical reference; a present physical target still needs a current binding and life. Secondhand testimony cannot transfer another person's private identity access.

**Write and read in this order.**

1. For native wording, bind the participants while the personal renderer emits their text. It knows the role of a pronoun or repeated label at emission. On a free-text write use only the author’s permitted references actually supplied or evidenced for that passage. Accept plain text, including unmatched names. Never guess an ID by searching for the first matching display name. If an identified person is already bound to the fact, preserve that binding even when no name is written; keep fact-wide evidence in the manifest where no word denotes them.
2. Validate the whole revision once at its mutation owner: valid reference kind and scope, available source/identity support, existing map key, nonempty in-bounds range, and exact literal units for a claimed quote. Preserve original units, including combining characters. No binding boundary may bisect a valid surrogate pair. A separately valid isolated surrogate stays unchanged. Bind to the immutable text revision; a text edit rebuilds its bindings in the same transaction. Size the text, table, bindings and dependency edges under the existing memory/transfer bounds before mutation. For an optional unknown referent retain the unbound words. For a required established identity that cannot be admitted, refuse the replacement before mutation.
3. Save the accepted body and dependent changes with the ordinary changed rows. Follow memory writes, native [columns and retrieval preparation](../../native/simulation/src/experience/columns.rs), exact-source retention, PostgreSQL hydration, permitted player/history views, NPC context, notes and consolidation. Expose only permitted labels and request-local handles. Existing lexical and semantic recall can find a violin in plain text on a later justified read. Use the existing revision-scoped search projection of the eligible literal. Do not embed every attached key or perform searches to decide whether an NPC gets a turn.
4. When current sight is lost, stop asserting present sight. Preserve ordered changed measurements and real gaps for detailed subjects under the existing retention law. A repeated patrol requires no encounter object and no model to close a sighting. Do not materialize text bindings in each temporal sample. On admission of a lasting impression, preserve only the supported identity, time, precision and warranted wording. Consult the [recent-history contract](attention-and-scenes-tech-design.md#53-recent-chronology-without-narrative-boundaries) before changing any capture or retention rule. On fading, dropping a clause or replacing text with an empty gist also drops its ranges. A retained occurrence about an identified person still needs that subject in its surviving fact. If no fact survives, retire its optional annotations and indexes.

## 5. Consolidate, correct and reopen

Extend the existing [hourly partition and answer decoder](../../native/game-server/src/npc/maintenance/hourly/prompt.rs), the daily caller and the [native consolidation group](../../native/simulation/src/experience/consolidation.rs) together. Run under the existing maintenance eligibility, batch bounds and separate payment admission. Neither expiry nor a new movement sample schedules a summarization call.

- **Input.** For each funded partition give the model the permitted source texts with distinct local handles for their references and exact attributed passages. Keep protected sources, chronological barriers, immediate inputs and inherited coverage under the existing manifest rules. A local handle disappears with that request. Use the [captured source reading](../../native/simulation/src/runtime/maintenance/consolidation/reading.rs) and keep its literal separate from server-supplied routing metadata. A witness can literally say “(ID:seal)”. Never parse or strip those characters inside a literal. Render only real bindings as permitted request-local handles. Apply the same rule on later recall.
- **Output.** Let each group's proposed new text carry annotated passages using only offered handles. To avoid asking a model to count UTF-16 positions, use ordered literal pieces; a piece can carry zero or several handles. Give each binding occurrence a group-local key pointing to its offered reference, then list active occurrence keys on each piece. The decoder joins the literal pieces once and derives ranges from their UTF-16 lengths. For annotated output, check blankness without trimming, normalizing or rewriting the stored units. The existing decoder trims plain grouped text. Applying that step after deriving ranges would shift every binding following leading whitespace. Two different keys can denote the same person. Reject a disjoint run under one occurrence key. This represents nested and crossing ranges without counting characters in the model. An exact-quote binding names the specific permitted source passage. Literal punctuation or a string that resembles a handle stays ordinary text. Plain text and unchanged protected singletons need no annotations when none apply. Copy an unchanged singleton's established bindings from the source.
- **Acceptance.** Native code verifies complete partition coverage, owner/life/privacy, exact revisions and identified-subject support. Each binding needs support in its own group. An offered handle from a different group cannot supply an identity or quotation. Verify quoted units against the cited passage. Reordered wording needs new ranges. Keep the witness’s judgment and Mara’s words separately attributed where both sources exist. Preserve exact speech, commitments and other protected terms through the existing protected-source path. If an identified or attributed fact has no independently supported equivalent in the selected coverage and its rewrite cannot be checked, pass the original through that path as a singleton with its bindings before partitioning. This also works for free text without parsed claims and requires no search through a lifetime of memories. “Mara intends to collect it” cannot become “I saw Mara collect it” on matching IDs alone. Test more permissive paraphrasing separately. A paraphrase alone cannot prove exact wording, fulfillment or a new identification.
- **Publication.** Prepare and validate all partitions of the selected batch before replacing anything. Carry unchanged protected sources forward under existing maintenance markers. If no source can be transformed, skip the provider. An accepted singleton fallback must not re-enroll the same unchanged inputs on the next hourly sweep. The native manifest derives provenance. A reference alone neither pins an optional source body forever nor regrants access after expiry. Already-held readers retain their funded storage through release and must still pass the current disclosure check. Publish through the existing single writer with its dependency and search invalidations. Invalid output, stale support, cancellation or a failed transaction publishes no partial batch. Apply the ordinary failed-attempt policy; no automatic paid repair call. Daily consolidation of an hourly summary retains immediate and transitive dependencies. A later in-world correction is new attributed testimony. An authorized privacy withdrawal or forgetting invalidates dependent reads, summaries and indexes under the [existing privacy owner](../../native/simulation/src/experience/privacy_run.rs); an independent witness retains their own supported fact.
- **Restore.** Validate current-format text, ranges, IDs, dependencies and scope. Rebuild derived lookup state after installation/restore from canonical records. Restore latches, work terms, durable attempt/funding markers, personal sources and accepted actions from their existing owners. Restoration creates no observation, condition entry, optional free interval or reply. Exercise cold PostgreSQL return with an open watch and an accepted reply. Follow the [development save policy](../../AGENTS.md#development-save-policy) for schema changes.

### Live thought reference delivery

NPC decisions offer thought references from the bodies and private records already selected for that character. A visible object or an earlier personal inspection can supply an object identity and an evidenced item category. A remembered place comes from that character's own acquired place record. The next calendar day is anchored to the selected speech or the decision time. Reusing a saved interval preserves its original endpoints. An exact quotation must match a contiguous received passage with an unambiguous location in the selected fragment. Unrecognized words stay in the submitted thought. A well-formed optional annotation with an unavailable handle is omitted. Malformed annotations still fail response validation.

Ordinary decisions should cite each mention whose meaning is supported by the selected evidence. The generated answer copies the words of the mention and identifies which occurrence it means if those words repeat. The simulation derives the saved text positions from that exact match. An absent, ambiguous or out-of-range match leaves the wording unbound. This removes character counting from generation without guessing what a name, pronoun or relative time refers to. Verify the ordinary signed decision and save using multibyte text, repeated mentions and an ambiguous mention, then exercise cold recall and withdrawal with the same response format.

Thought references carry no physical action authority. A source-backed reference follows the cited revision for privacy withdrawal without extending the lifetime of its body. When a thought reuses a citation, it carries the original withdrawal links forward, so an intermediate account can expire without breaking them. Recalled quotations include the original speaker and hearing time when that exact hearing is already in the permitted read. On recall, separate accounts keep separate citation handles even when they describe the same place or time. Repeated mentions from a single account reuse its handle, and the same established person remains recognizable across accounts. The installed local clock supplies the time interpretation and its saved identity. Hourly and daily maintenance preserve an identified or attributed thought verbatim when a rewrite cannot establish the same fact. An unchanged singleton preserves its original bindings even if the model returns it as plain text.

Work grows with the evidence already selected for that decision and the passages within it. The existing native response ticket supplies the proofs and current disclosure checks. Preparation admits and funds each extra offer before rendering it. Each selected account shares one copy of its citation proof across the offered handles. A thought attaches that proof only on use, and omits the optional citation if its complete proof cannot fit in the response allowance. The ordinary optional memory quota still applies. A withdrawn account is discarded before decoding its original observations. Offering these references requires neither a lifetime history scan nor an additional model call. The [verification record](../verification/witness-memory-references.md) covers the signed decision, PostgreSQL continuation and scheduled summaries. The comparison and sustained crowd gates below use separate workloads.
