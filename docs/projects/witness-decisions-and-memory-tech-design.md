# Witness decisions and personal memory — technical design

| Status      | Current progress                                                                                    | Last updated |
| ----------- | --------------------------------------------------------------------------------------------------- | ------------ |
| Not started | The integration design is complete. Implementation and whole-path qualification are open in PS04-A. | 2026-11-21   |

A player can make fifty people witness the same performance and still get fifty different accounts of it. The implementation must answer three separate questions: **what reached this witness, what requires their choice now, and what can they recall later?** The [feature](../features/noticing-and-remembering/README.md) owns those answers. The steps below extend the existing perception, decision and memory owners. A quiet witness can supply a useful lead later even if the server never asked a model about the performance.

## 2. Select personal reasons before selecting prompt detail

1. **Start at the accepted change.** Compute an act's own identity, order, outward components and authored default importance once. For each actual receiver consume the evidence reception already produced. Keep the receiver, life, time, modality, precision and source binding. Detection, seeing a face, recognizing someone, hearing words and knowing one was addressed have different prerequisites. An NPC behind a hedge can have heard evidence with no visual reference. Work on one NPC's private bodily change starts with that NPC.
2. **Match only applicable changes.** Dispatch by installed fact family, then affected actor and subject, active work or supported cue. Resolve a known subscription directly on its work owner. For an event use its occurrence identity. For a continuing condition use the existing onset, supported escalation, clearance and generation on its owner. Apply required physical results immediately. An already chosen valid step may settle a choice. Unknown coverage supplies neither a negative observation nor clearance. Evaluate independent reasons even when one is satisfied. If two prepared voluntary actions compete for the same body or item, use the accepted work’s explicit priority. With no settled precedence, leave the alternatives for one decision; the native action owner still validates the chosen step.
3. **Give the native intake reader the result.** For an occurrence, carry the receiver role and needed source bindings with its existing personal record into the intake read. For a continuing condition or blocked step, expose the matching revision from the existing latch or work owner. Do not duplicate it in a memory just to wake the scheduler. Logically a reason is `(receiver/life, reason family, exact supporting receipt or condition generation, affected choice owner if any)`. Reuse the existing source and task identities. Put labels, words and optional context behind those references. An ordinary received change can have **zero** reasons. The physical effect, evidence recording and discovery paths still run. No durable “ignored” row or reason per gait sample. Retention eligibility is independent: a reason can expire after its choice, and a witnessed fact can outlive a decision the NPC never needed.
4. **Separate the required reasons from the optional context ranking.** In `unseen_intake`, select still-eligible reasons from the actor's actual records/causes before score ranking or truncating incidental descriptions. Include low-importance directed and personal cases. Keep the existing source filters for forgotten and withdrawn evidence, own speech, inferred summaries and duplicate memories of an awareness record. A new summary or recording of an already handled event cannot make it fresh. Preserve own action outcomes, internally due reviews and in-flight interruption rules on their own paths. Map the existing receiver roles exhaustively: addressed speech uses its direct path, overheard speech uses the listener rules in §3, self events and directed actions test actual personal outcomes, and ordinary observed events require an independent reason. Keep prepared-action, protection and required threat decisions on their semantic owners. In `Inspection::propose`, use the typed personal result for the ordinary witness branch. Importance can still rank details. A generic event kind or the mere presence of a significant event in the raw world log cannot establish the witness's reason.
5. **Respect the queue and evidence cursor.** Wake affected actors through the existing changed-record/due scheduling pass. A wake requests inspection only. Keep the existing queue product small. Only the full actor inspection should prepare the evidence needed for a specific choice. At admission coalesce compatible reasons for the same NPC into one opportunity and include each distinct required source once. Identify durable attempts by the existing job/opportunity IDs. Use existing fair service within priority classes; an audience is never sampled to meet a desired job count. A later gesture cannot enter a prompt as if known earlier. If more required evidence is pending than fits, take a complete serviceable choice with its dependencies and leave the remainder eligible. Return the last fully examined sequence with the admitted sources. Advance the existing cursor at job acceptance to at most that sequence and the durable cut. Examine equal-sequence sources in stable source order and keep the group together across a page boundary. Stop before a group containing an unserved reason unless an existing pending owner already holds it. If a required group alone cannot fit, report capacity, keep the cursor and serve independent actors. A refused slot or failed commit acknowledges nothing. Do not write one SQL acknowledgement for each score-only witness.
6. **Recheck at actual use.** A detected direct player address keeps its interactive job, including when every word was masked. Suppress an automatic job for that same actor and utterance under the existing speech ownership check. A different overhearer can independently qualify. Preserve provider admission, per-NPC ordering, refresh policy, cancellation and the original evidence/time when a reply is held. At application, recheck physical feasibility separately: a cart that has rolled away cannot now be caught. Unrelated accepted activity and ordinary save acknowledgement do not invalidate a still-current request. Losing sight ends present visual support but need not revoke the historical fact that the gesture was seen. Explicit withdrawal of that fact invalidates a dependent request. Provider failure or an unserved choice conveys no consent, decision to ignore or outward action. A reconnect or repeated command can recover the original receipt without applying its effects again.

An optional discovery remains one reserved attempt per genuine free interval in the bundled world. A pre-dispatch refusal releases the reservation; a dispatched attempt spends it even if it fails. Starting or finishing a thought cannot renew the interval. Other sources can still enter the next independently warranted decision.

In the jester case, appearance, flip and gesture retain their order. There is no debounce timer. For the [specified fifty witnesses](../features/noticing-and-remembering/scenarios-and-acceptance.md#the-jester-and-fifty-witnesses), the directed recipient and the guard with an unresolved instruction have a choice. A private fear may supply a third. The other 47 can observe, continue working and later answer a question. Someone actually seeing a frightened witness stumble receives a new event. Neither the private emotion nor the first wave of model results is broadcast to the crowd.

For the **language experiment**, tokenize each contiguous _heard_ passage with the world language's word boundaries. Match a learned self-name as a whole token sequence. Recognition alone can orient. For a decision, first try a bounded subject–predicate statement or question: the alias occupies the subject slot and the same received clause contains a supported predicate with its required complement. “Oren stole the toll money” qualifies; “Oren … [unheard] … money” does not. Keep the original words, including negatives and quotation marks. A recognized citation may be relevant without establishing the listener committed the act. An unmatched turn of phrase leaves the words available at later cognition. Keep these surface forms with the world's vocabulary. Do not evaluate other listeners’ aliases or goals.

For each enrolled character, the authorized world/character editor binds the sensitivity to a pinned rule through existing private character state. At recognition, apply the appraisal and settle the condition onset in the same native candidate before the server offers deliberation. A refused candidate leaves both feeling and onset unapplied. Retrying the same supported change can commit them once. After acceptance, control transfer, a repeated glimpse or loading the world cannot recreate it. Removing the enrollment ends future matches; the original feeling follows its own recovery and correction policy. Use the [authored psychological profile](../worlds/base/psychological-reactions.md) for rule selection and the [effective fear owner](emotional-physiology-tech-design.md#ep-c06--complete-effective-fear-and-parameter-resolution) for combined intensity.

### Watches and affected rules

Use the [accepted watch terms and subscription owner](attention-and-investigation-tech-design.md#41-event-and-level-subscriptions). A registered predicate may compose supported leaves. For a compound condition, retain its finite admitted expression under the existing activity's control and subscribe to its distinct leaf dependencies. On a matching change, recompute only affected clauses. Conjunction needs every term true, disjunction needs one true, and a result unsupported either way is unknown. An event-root evaluates against the specific new occurrence and personally supported levels at that cut. A level-root uses the work’s existing initial-report policy and transition latch. A sequence such as two lantern flashes needs distinct witnessed occurrences and a supported finite sequence owner. Conjunction alone does not remember an earlier flash. An absence test needs adequate coverage through its due time. Keep the control's original expiry, replacement, loss behavior and [focus, concern and work bounds](../limits/attention-and-investigation.md#ati-l03--selected-input-and-composition-envelope). Install the registered compound predicate, its dependency list and funding atomically with the control. Reject unsupported leaves or cycles before accepting a watch, keeping any previous valid control intact. The unexpressible goal remains available as prose. Bound evaluation by the existing work/byte admission including all leaves and subscriptions; do not impose a fictional limit on goals or expressions.

Begin with the event families and active controls already owned by the current actor. For registered definitions, resolve compatible rules once on installation and group by required input family. Actor-specific entries are installed/removed with the actor's actual sensitivity, task or known name. A query follows keys for this receipt and actor. A dormant rule about an unrelated family has no per-witness evaluation cost. Genuine density can still be expensive when many rules or people really do match. Before creating a secondary runtime index, measure simple actor-local matching against it (§6). Removal, withdrawal, life replacement and restoring the world must yield the same matches as a fresh build from the canonical owners.

## 4. Keep literal memory and attach references

Extend the existing actor-owned memory and summary bodies. Keep the original text field and its exact [UTF-16 representation](../../native/simulation/src/text.rs). Use [`ObserverSubject`](../../native/simulation/src/reception.rs) for an identified individual, the reference to an already acquired [known place](../../native/simulation/src/experience/places.rs), a permitted object identity, a pinned world category, a supported game-time interval, or [`PersonalSourceRef`](../../native/simulation/src/experience.rs) scoped to the account owner. Do not copy a place capsule into each mention. The following is a logical layout for **optional** annotations on one revision of one text field. It is not a new memory class.

```text
references   local key → identified subject | known object/place | known category
                       | understood time interval and calendar | personal source revision
bindings     (start inclusive, end exclusive, local reference key)
```

Offsets count UTF-16 code units in the stored literal, after decoding JSON and before any display formatting. Each binding addresses exactly that occurrence. Several bindings can overlap, use the same range, or reuse one key. A citation about the account as a whole belongs in the existing source manifest. An unbound word stays in the literal. No mandatory speaker, claim parser or type for “thought” versus “heard.” Keep the external speech occurrence and the listener's record of it separate.

For `I heard Mara say ‘I like cats’, and I judged her for it.`, the bindings are `[8,12) → person` (Mara), `[45,48) → same person` (her), `[18,29) → listener’s utterance evidence` (I like cats) and, if established, `[25,29) → category` (cats). In a promise about collecting a violin “tomorrow,” keep that word even when its original calendar interval is known. A character may know which person spoke without knowing which violin they meant. Use the witness's stable identified subject through all retained facts about that person, including unnamed individuals. A personal ID enables historical reference; a present physical target still needs a current binding and life. Secondhand testimony cannot transfer another person's private identity access.

**Write and read in this order.**

1. For native wording, bind the participants while the personal renderer emits their text. It knows the role of a pronoun or repeated label at emission. On a free-text write use only the author’s permitted references actually supplied or evidenced for that passage. Accept plain text, including unmatched names. Never guess an ID by searching for the first matching display name. If an identified person is already bound to the fact, preserve that binding even when no name is written; keep fact-wide evidence in the manifest where no word denotes them.
2. Validate the whole revision once at its mutation owner: valid reference kind and scope, available source/identity support, existing map key, nonempty in-bounds range, and exact literal units for a claimed quote. Preserve original units, including combining characters. No binding boundary may bisect a valid surrogate pair. A separately valid isolated surrogate stays unchanged. Bind to the immutable text revision; a text edit rebuilds its bindings in the same transaction. Size the text, table, bindings and dependency edges under the existing memory/transfer bounds before mutation. For an optional unknown referent retain the unbound words. For a required established identity that cannot be admitted, refuse the replacement before mutation.
3. Save the accepted body and dependent changes with the ordinary changed rows. Follow memory writes, native [columns and retrieval preparation](../../native/simulation/src/experience/columns.rs), exact-source retention, PostgreSQL hydration, permitted player/history views, NPC context, notes and consolidation. Expose only permitted labels and request-local handles. Existing lexical and semantic recall can find a violin in plain text on a later justified read. Use the existing revision-scoped search projection of the eligible literal. Do not embed every attached key or perform searches to decide whether an NPC gets a turn.
4. When current sight is lost, stop asserting present sight. Preserve ordered changed measurements and real gaps for detailed subjects under the existing retention law. A repeated patrol requires no encounter object and no model to close a sighting. Do not materialize text bindings in each temporal sample. On admission of a lasting impression, preserve only the supported identity, time, precision and warranted wording. Consult the [recent-history contract](attention-and-scenes-tech-design.md#53-recent-chronology-without-narrative-boundaries) before changing any capture or retention rule. On fading, dropping a clause or replacing text with an empty gist also drops its ranges. A retained occurrence about an identified person still needs that subject in its surviving fact. If no fact survives, retire its optional annotations and indexes.

## 5. Consolidate, correct and reopen

Extend the existing [hourly partition and answer decoder](../../native/game-server/src/npc/maintenance/hourly/prompt.rs), the daily caller and the [native consolidation group](../../native/simulation/src/experience/consolidation.rs) together. Run under the existing maintenance eligibility, batch bounds and separate payment admission. Neither expiry nor a new movement sample schedules a summarization call.

- **Input.** For each funded partition give the model the permitted source texts with distinct local handles for their references and exact attributed passages. Keep protected sources, chronological barriers, immediate inputs and inherited coverage under the existing manifest rules. A local handle disappears with that request. Do not supply world IDs or make every participant in a source a referent of every clause.
- **Output.** Let each group's proposed new text carry annotated passages using only offered handles. To avoid asking a model to count UTF-16 positions, use ordered literal pieces; a piece can carry zero or several handles. Give each binding occurrence a group-local key pointing to its offered reference, then list active occurrence keys on each piece. The decoder joins the pieces once and derives each occurrence's contiguous range from piece lengths. Two different keys can denote the same person. Reject a disjoint run under one occurrence key. This represents nested and crossing ranges without counting characters in the model. An exact-quote binding names the specific permitted source passage. Literal punctuation or a string that resembles a handle stays ordinary text. Plain text and unchanged protected singletons need no annotations when none apply. Copy an unchanged singleton's established bindings from the source.
- **Acceptance.** Native code verifies exact source partition/coverage, offered handles, attributed quote units, owner/life/privacy, revision and required identified-subject support. A person carried through a retained fact keeps the same subject. Text rewritten in a different order gets new ranges. Keep separate sources for the witness's judgment and Mara's words where each exists. Quote identity and token validity cannot prove arbitrary paraphrases true. For protected statements, commitments and exact speech, carry their admitted original terms under the existing protection. For a sole identified or attributed fact whose fidelity cannot be checked from an existing structured result, the safe baseline copies the whole original as an exact singleton with its bindings. A rewrite of “Mara told me she intends to collect it” into “I saw Mara collect it” does not qualify on the strength of matching IDs. Use this fallback even for free text without parsed claims. More permissive paraphrasing is an experiment, never sole evidence for exact words, fulfillment or a newly identified person. Do not promote generated language to proof that a reported intention was fulfilled. Assess meaning changes in the paired quality experiment below.
- **Publication.** Prepare and validate all partitions of the selected batch before replacing anything. Carry unchanged protected sources forward under existing maintenance markers. If no source can be transformed, skip the provider. An accepted singleton fallback must not re-enroll the same unchanged inputs on the next hourly sweep. The native manifest derives provenance. A reference alone neither pins an optional source body forever nor regrants access after expiry. Already-held readers retain their funded storage through release and must still pass the current disclosure check. Publish through the existing single writer with its dependency and search invalidations. Invalid output, stale support, cancellation or a failed transaction publishes no partial batch. Apply the ordinary failed-attempt policy; no automatic paid repair call. Daily consolidation of an hourly summary retains immediate and transitive dependencies. A later in-world correction is new attributed testimony. An authorized privacy withdrawal or forgetting invalidates dependent reads, summaries and indexes under the [existing privacy owner](../../native/simulation/src/experience/privacy_run.rs); an independent witness retains their own supported fact.
- **Restore.** Validate current-format text, ranges, IDs, dependencies and scope. Rebuild derived lookup state after installation/restore from canonical records. Restore latches, work terms, durable attempt/funding markers, personal sources and accepted actions from their existing owners. Restoration creates no observation, condition entry, optional free interval or reply. Exercise cold PostgreSQL return with an open watch and an accepted reply. Follow the [development save policy](../../AGENTS.md#development-save-policy) for schema changes.

Unmeasured costs, candidate matchers and alternative representations are experiments. Removing a failed optimization leaves its gameplay requirement open until a correct route passes. Keep a common correctness repair on both arms when comparing a later change.

For every uncertain change first freeze the expected outcomes, one changed variable and what would cause rejection. Keep instrumentation for counts separate from clean runs. Use existing real-caller fixtures, the profiler and [comparison policy](../performance/measurement.md#planning-comparisons). For an ordinary-play speed claim use the standard managed 16 GiB worker, three interleaved repetitions per arm, independent databases, the same authored population, normal clock, controlled replies and one-second background saves. Report server and PostgreSQL CPU separately as percentages of one core, achieved game speed, median/average/p95 visible and reply latency, actual RAM, reservations, query/row/WAL costs, provider requests by stage and complete gameplay. Record provider input/output tokens and cost, attempts per eligible person, and the number of semantic searches made solely to enter cognition (required zero). A read-only local check or lower model count cannot establish total CPU savings. Overlap, unequal outcomes or excessive variation leave the performance claim inconclusive.

No numerical cost gain or crowd service level has been established for these changes. Compare optional implementations against the simplest correct one. Retain only for a reproducible benefit in the affected measure without material loss in other agreed measures. If important, repeatable reactions are missed, narrow or repair the rule and rerun the same controls. Do not treat unmet gameplay acceptance as a completed experiment.

The functional run must also vary the **absence** of a cause: a sound-only animal can react through its installed controller with zero model requests, and an ordinary witness can lose sight and later retrieve only the portion actually retained.

The principal risks are scanning every observer's history before dropping a cue, letting incidental records hide required ones, and keeping all original texts alive through summaries. Native unseen intake currently reserves work proportional to all three retained personal collections and sorts candidates before truncation. Count headers visited, selected versus hydrated sources, time waiting for durability, original bytes retained by summaries, repeated reads after a no-choice result and clauses evaluated per receipt. Compare ordinary/held conversations and a quiet no-change interval. No single run licenses reducing individual attention, changing urgency, weakening permission checks or adding a world-wide job quota. Preserve the narrowed recall preparation and the separate decision-time action offers. The rejected speech-ownership query and cross-record lexical reuse need fresh evidence before reconsideration.
