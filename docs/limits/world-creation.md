# World creation limits

**Current scope: selected first-opening implementation, October 13, 2026; capacity qualification remains open.** The [feature specification](../projects/world-creation-feature-spec.md) owns behavior. [ND01](../maintainers/needs-design.md#nd01--assemble-a-new-world-from-a-creators-premise), INV-4.10 and EWF12 retain delivery routing. Shared authoring, questions, retention and spending stay in [invention limits](inventions.md); continuing operation stays in [scalability limits](product-scalability.md). Broader product envelopes originated on October 3 and remain proposed where labeled below.

DG12’s 5 October expansion adds the bounded library/reuse consumer below. INV-8/EWF11 retain portability, rights and data ownership; none of these proposed envelopes is measured runtime capacity.

[Batch 07](../maintainers/parallel-batch-07-playable-world-creation.md) implements the selected first-opening consumer under WC-L01–WC-L05 and WC-L13. Native/PostgreSQL and browser checks establish exercised cases, and one real language-authored inhabited opening reaches exact review and entry. Generated-tool play and complete first-play acceptance remain open; these observations establish no general capacity. It does not deliver or require the proposed library consumer in WC-L06–WC-L12.

## WC-L01 — Reference starting population and place

**Selected reference implemented; broader population targets proposed · Restrictiveness: Safe.** The first familiar reference follows the [accepted personal MVP](../../archive/05-project/first-playable-mvp.md): one wilderness locality, one live NPC and one initial human-controlled character, with the real creative gameplay loop. A ready curated opening is valid; custom creation is optional. The [bundled profile](../worlds/base/playable-openings.md) also constructs a genuinely solitary opening and supports explicit harshness without treating it as permission to omit mandatory activity inputs. This revises the earlier six-resident first reference to avoid making a larger population or authoring workflow a prerequisite for first play. Six remains an unqualified later small-community hypothesis for social variety, not a release floor, capacity result or engine-wide cap. That larger offer still requires whole-community resource, agency, interesting interaction and operating qualification; success with one resident does not qualify six. Unsupported larger requests receive an explicit supported alternative or retained draft before activation; no silent reduction to decorative residents. Broader atypical and empty fictional worlds remain product targets beyond this profile. Revisit after the feature's first-session, absence, population-change and complete-cost cases.

## WC-L02 — Initial rule-family coverage

**Bundled-family consumer implemented; expansion proposed · Restrictiveness: Safe.** The current profile uses supported native bodies, placements, finite resources, item definitions and learned methods; it adds no generated executable law. Add another composition only when its complete body, action, knowledge, resource and entry dependencies qualify. Essential unsupported behavior blocks that candidate; optional mechanics may remain explicitly deferred. The restriction keeps a useful first release concrete while allowing arbitrary premises to remain drafts. It does not make survival universal or establish general navigation, magic, construction or market support. Revisit with a real new opening that demonstrates the missing family.

## WC-L03 — Local detail and historical preparation

**Fresh native preparation implemented; broader history/rehearsal proposed · Restrictiveness: Safe.** Current creation builds only the selected people, scene, possessions, learning and bounded authored background, then checks actual standing, routes, material access and native action/knowledge prerequisites. It prepares initial cognition, perception and conditions without simulating invented earlier work or altering the eventual people's time, RNG, positions or experience during readiness checks. The broader product target may add targeted rehearsal, wider live scope or historical preparation only through separately admitted family/work and service qualification. It does not simulate centuries or populate every named distant place. Established facts constrain later detail; unsupported travel is refused before an impossible journey is accepted. This is not an unlimited lore-retention policy.

The current [world-owned candidate profile](../../packages/domain/src/worlds/base/initial-opening.ts) enforces these preparation bounds:

| Selected data                                          | Maximum                                         |
| ------------------------------------------------------ | ----------------------------------------------- |
| People                                                 | One controlled person and one optional resident |
| Scene elements / possession lots / learning selections | 24 / 32 / 6                                     |
| Traits / explicitly seeded intentions per person       | 8 / 8                                           |
| Name / each authored prose field                       | 120 Unicode characters / 4,000 characters       |
| Resource patch / possession lot                        | 10,000 finite units / 512 units                 |
| Fire fuel                                              | Seven days of finite fuel                       |

These are small-opening admission envelopes. The [recorded complete-caller checks](../verification/playable-world-creation.md#work-bounds-and-review-fixes) activate a 58-entity opening with 24 scene elements, 32 possession lots and all six supported learning selections, and separately accept exactly 24,000 UTF-8 candidate bytes while refusing 24,001. Browser editing/entry and one live language-authored creation pass; generated-tool first play remains open in Batch 07. These are sampled local workloads, not universal fictional laws, optimal allowances or measured hosted capacity. Expand the envelopes only for a demonstrated supported opening and its complete preparation cost.

## WC-L04 — Questions, revision and waiting

**Native selection/revision implemented; conversational qualification open · Restrictiveness: Medium.** The existing creator session retains the selected opening and exact application-owned identities, seed, values, draft revisions and review. Native selection, editing and checks require no generation. Prefer one consequential question at a time within the existing QST envelopes, and ask none when known choices and suitable defaults already resolve the material question. No additional universal interview-count limit is selected. Creation sections are not mandatory screens; optional rehearsal and deeper inspection do not block a qualified start. Existing episode, turn, record and spending boundaries remain controlling; no automatic paid question loop, keystroke-triggered regeneration or indefinite paid waiting. Preserve selected parts and re-evaluate affected behavior. Offer play when a faithful useful candidate is ready; further variations are deliberate choices. At exhaustion, retain available work and offer explicit narrower scope or renewed authorization. Revisit using novice/experienced creator correction, actual play and abandonment evidence.

## WC-L05 — Drafts and opening reserves

**Finite endowment/readiness implemented; reserve balance qualification open · Restrictiveness: Safe.** Retained candidate comparison uses existing draft/storage policy; no unlimited undo/archive or automatic deletion is promised. The bundled openings supply explicit finite starting possessions and reachable resources. Readiness checks native manufacturing requirements and accessible food; deliberate harshness can waive food scarcity, never missing activity inputs or required routes. Native solitary gathering, fiber preparation and pouch manufacture were exercised, but complete first-session usefulness and reserve balance remain open. Qualify reserves against the opening loop, current need rates and world clock; there is no universal reserve quantity. Revisit reserves and retention independently from actual first-session and storage evidence.

## WC-L06 — First library and publication scope

**Proposed · Restrictiveness: Very safe.** DG12 first transfers one root supported recipe and its complete eligible requirements between two prepared local worlds in the same known authority context. No public marketplace, remote account federation, arbitrary script, automatic update or general live migration is included. A later one-invention free release may go to one other already-known account within the same supported operator environment, using their authorized prepared destination and sufficient recorded grants. No new default license is selected. At unsupported origin, rights or capability boundaries, retain the original and explain the blocker. INV-8/EWF11 retain delivery; this is a consumer profile, not another installer.

## WC-L07 — Complete transfer work

**Proposed · Restrictiveness: Safe.** At most 32 distinct exact definition references and 1 MiB of decoded definition/manifest text in the first one-root transfer. Deduplicate shared references; stop with an explicitly incomplete preparation on a missing requirement, unresolved cycle or over-limit closure. Never truncate required content or activate a partial recipe. These values contain a small recipe proof and require qualification, not an assertion of optimal capacity. Existing per-argument, candidate, session, traversal and authority limits in CTX02/CTX03 still apply; the aggregate package allowance does not enlarge a 24,000-byte candidate or 28,000-byte tool argument. Future preparation must reference retained content without forcing the complete package into every request.

## WC-L08 — Library presentation and search

**Proposed · Restrictiveness: Safe.** 20 permitted entries per displayed page, with stable selection and explicit continuation. Ordinary lexical search/filtering precedes result hydration; no automatic AI search, thumbnails or generation per card. The underlying corpus and query work are separately growing dimensions and need INV-8/data qualification; a page size is not a scan bound. There is no proposed lifetime 20-entry or 64-draft-derived invention cap. At partial/unavailable search, disclose the result scope and retain the selected entry.

## WC-L09 — Pending imports and updates

**Proposed · Restrictiveness: Safe.** One active import preparation per destination, no unattended pending-import backlog, zero automatic retries and zero automatic installation updates. Another request can inspect, cancel or deliberately wait for the current work. Exact already-installed content yields “Already available here.” A larger live change remains INV-5 work and cannot be smuggled through a library refresh. Ordinary play continues during optional preparation subject to its existing authority/maintenance rules.

## WC-L10 — Retained history and copies

**Proposed target; total growth unqualified · Restrictiveness: Too liberal until the service storage profile is qualified.** Preserve the accepted eligible all-past-contribution target; no independent lifetime deletion/count cap is selected here. Account contributions, revisions, retained dependency bytes and release history can grow through invention and publication. A source reference is not an independent copy. Exact total storage/retention admission remains INV-8/D4/PD10; block a new unsupported retention/publication operation honestly rather than silently delete prior work or claim it was saved. Existing authoring-session expiry is not library deletion. This inventory does not promise unlimited free storage or legacy compatibility.

## WC-L11 — Media and generative work

**Proposed · Restrictiveness: Very safe.** Zero new model calls for exact browsing, known local compatibility, reopening or unchanged eligible reuse. Separately requested adaptation retains existing authoring/spending controls. First transfer uses qualified native appearance; arbitrary remote media, commissioned art and executable code are excluded. Required missing presentation blocks the affected promise; optional omitted illustration is labeled. Richer asset reuse stays with the existing art-pipeline inventory, not a second storage budget here.

## WC-L12 — Rights and private-origin presentation

**Proposed · Restrictiveness: Safe.** Show only permitted origin metadata, credits, inventory and dependency explanations to each audience. Original, imported, adapted and learned views remain distinct. Zero price supplies no new modification, commercial-use or redistribution grant. A partial distributable pack is labeled partial; a complete authorized inventory may contain restricted references that are not exposed publicly. Previously granted rights follow the actual version terms; exceptional privacy/security/rights removal remains separately authorized. No product-wide free-use license, self-hosted ownership adjudication or compulsory contribution policy is chosen by DG12.

## WC-L13 — Prepared empty creation targets

**Implemented boundary; complete qualification open — October 13, 2026 · Restrictiveness: Very safe.** The creator journey uses an existing authorized creator session and operator-configured local targets with independent current PostgreSQL storage, data directories and current account/operating policy. An awaiting-creation target starts no bundled world or autonomous activity before exact reviewed activation. Only the current supported creation profile is admitted; no automatic host provisioning, occupied-world replacement, library import, remote federation, arbitrary executable law or generated media is supplied. Client/model selection carries a permitted target identity, never a connection string, path, executable command or new entitlement. An unavailable, occupied, changed or unsupported target preserves the draft and refuses activation. Native/SQL cases, the admitted maximum/rejected excess, browser interaction and one real language-authored opening-to-entry have been exercised; [OC01–OC05](../maintainers/parallel-batch-07-playable-world-creation.md) still owns generated-tool play and complete creation-to-play acceptance. The one-resident reference does not establish a population capacity, and target count, retained candidates and total storage remain independently growing work under the existing authoring/hosting owners. Expansion requires a complete supported profile or hosting use case, not merely a larger numeric allowance.

Required deferred routes use the existing real navigation worker through a separate bounded preparation owner: at most 64 requests per admitted batch, one active batch, eight queued batches, a 20-second total deadline and a 128 MiB worker heap. One worker shares map/body preparation within its batch and terminates on completion or failure. Overload, timeout and unavailable preparation remain incomplete; they do not establish that no route exists. Native standing/approach and an obstructed worker detour have been exercised without changing the eventual world. These operational ceilings bound the selected request, not sustained concurrency, population capacity or navigation latency; qualification and expansion follow the actual supported consumer.
