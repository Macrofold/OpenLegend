# Network request lifetimes: limits and constraints

[Feature specification](../projects/completed/bounded-network-requests-feature-spec.md) · [Technical design](../projects/completed/bounded-network-requests-tech-design.md) · [NET delivery](../maintainers/bounded-network-requests.md) · [Tracking rules](README.md)

All NET-L entries below are **Current — implemented engineering defaults, with focused qualification recorded in the [network verification report](../verification/bounded-network-requests.md)**, reviewed October 18, 2026, unless explicitly describing an existing owner. Values are starting envelopes, not service objectives or guarantees for every network/device. Existing limits retain their stable IDs and ownership. Authority, exact identity, no duplicate spending and current-permission checks are correctness obligations, not tunable limits here.

## NET-L01 — Finite budgets and clock behavior

**Current · Restrictiveness: Safe.** Every finite operation requires a positive finite duration; an optional absolute Unix-millisecond deadline and caller cancellation may shorten it. Expiry uses the earlier remaining wall-clock and monotonic budget captured once. Maximum individual timer arm is 2,147,483,647 ms; longer valid durations rearm against the original expiry. Expiry includes connection, network-dependent preparation, body reading, required callback waits and authorized retry/backoff. No phase resets the original allowance.

At expiry the caller stops waiting; remote work may continue. Resumption checks reject late results before publication. A forward wall-clock correction can cause early expiry; this is the deliberate conservative tradeoff. Continuous subscriptions use NET-L04 instead of an infinite finite-request timeout. [Arithmetic and settlement](../projects/completed/bounded-network-requests-tech-design.md#4-deadline-arithmetic-and-settlement).

## NET-L03 — Body memory and explicit complete projections

**Current reuse of existing bounds; explicit no new full-view byte bound · Restrictiveness: Too liberal for unqualified complete-view memory.** Existing AI request/response/diagnostic/SSE limits remain with [LA053–LA055, HD01 and LA192](ai-execution.md); exact assets remain with [AST04](game-asset-storage.md#ast04--local-cache-and-download-work); private authoring frames/snapshots remain with [WS01](inventions.md#ws01--world-agent-stream-delivery). No buffer may grow past a currently applicable bound.

General browser API complete views/operations and main gameplay reset/patch frames currently lack a complete-response byte ceiling. Preserve their complete semantics through the explicit `complete-projection` policy, permitted only at reviewed browser API/game-event boundaries. This is a deliberate absence of a new cap, not unlimited time or unbounded request count. Native event-group byte limits and inbound server request limits do not establish a safe browser response allowance.

Full projection/serialization/socket memory remains excluded from the retained-diff cap in [LA165](multiplayer.md#la165). NET11 records representative large supported views and complete bytes/observed memory; existing PD05/LA165 capacity work remains open. Choose any later finite ceiling from that evidence and reconcile its producer/error/recovery behavior; never truncate a full view silently. No arbitrary global 64 MiB ceiling is selected here.

New metadata adapter bounds: OIDC discovery/token/JWKS response **1,048,576 decoded bytes per HTTP response**; SDK metadata/secret read **1,048,576 bytes** where the shared adapter consumes an encoded response. Preserve larger existing recovery metadata limits from AST08 instead of applying the small metadata profile to them. Rate these new metadata bounds **Safe**: reject oversized data with no session/signing-key publication; test the pinned SDK's largest supported fixtures. They are new operational limits, not vendor schema guarantees.

## NET-L04 — Continuous subscriptions and liveness

**Current · Restrictiveness: Safe; no total healthy-connection lifetime.** Browser subscriptions connect within **15 seconds**, receive a complete event/comment heartbeat at least every **15 seconds** from the application server, and expire after **45 seconds** without a complete valid frame. Partial trickled bytes do not renew liveness. Preserve the main **six-second** failure reconnect delay and use it for the private progress owner; one reconnect timer and one attempted connection per owner, with unresolved cleanup still counted under NET-L05.

There is no finite maximum duration for a healthy owned subscription. Disposal/access loss ends it. Visibility/resume uses the existing application policy and checks expiry before adopting queued data. Finite provider inference streams retain their original total budget and do not inherit an unsupported provider heartbeat assumption. Preserve existing private snapshot cadence/size and server **30-second** continuous blocked-write cutoff under [WS01](inventions.md#ws01--world-agent-stream-delivery) / [LA166](multiplayer.md#la166).

Private subscription size limits allow the existing 128 KiB payload plus 1,024 bytes of SSE framing and apply per frame, including an incomplete frame, not to cumulative lifetime bytes; main game frames retain their explicit complete-projection policy. No replay buffer grows with connection age. Preserve HTTP status before framing: access rejection does not cause repeated reconnect with known invalid authority, and HTTP 204 stops automatic reconnect until deliberate owner reinitialization.

Reason: three heartbeat intervals tolerate short scheduling/network delays without confusing a paused world with a failed connection. These values need browser/proxy qualification; they do not certify network availability.

## NET-L05 — Active and unresolved owner capacity

**Current · Restrictiveness: Safe.** Capacities count logical admitted operations, including any raw request/body/callback cleanup still unsettled after local timeout. Each operation is sequential; genuinely parallel child requests acquire their own slots. Existing narrower scheduler/cache/paid limits always apply. Owners are a fixed bootstrap set, not a per-request/per-user map. Refuse before dispatch when full; no extra queue or timer-based quarantine reset.

## NET-L06 — Cleanup and shutdown observation

**Current · Restrictiveness: Safe.** No ordinary HTTP result waits for unconstrained body cancellation in `finally`. Track original cleanup asynchronously under the retained lease. Owner shutdown receives the existing caller's remaining shutdown budget and reports unresolved work; no new fixed window overrides the server's existing shutdown stages.

Remote child processes receive **2,000 ms** between SIGTERM and SIGKILL after request timeout where the platform supports it. This grace does not extend the caller's network wait; the child slot persists until observed exit/close. Never signal unrelated processes. Known model cancellation retains its existing separate five-second allowance under NET-L02 and does not extend gameplay publication eligibility.

## NET-L07 — Retry and recovery boundaries

**Current shared default: zero automatic retries · Restrictiveness: Very safe.** The request primitive invokes its transport once. Existing read-only polling and proven conditional exact-asset retries remain at their semantic owners. Steps/retries inside one finite operation share its original deadline and cannot start while predecessor cleanup remains unresolved. Preserve the existing maximum three S3 conditional-transfer attempts under AST04; do not combine them with SDK automatic retries. Continuous subscriptions may reconnect under NET-L04 into a newly counted slot while an old connection's cleanup retains its slot; there is only one current connection per semantic owner and the shared NET-L05 capacity still bounds overlap. No reconnect resets or releases old cleanup.

An explicit later read of the same durable receipt may have a fresh observation window. Existing user-triggered identical-request recovery for creation, drafts and question answers also remains permitted by its existing idempotent owner: retain the original identity and exact submitted payload, and follow the route classification in the technical design. This is not a generic helper retry and does not renew paid execution eligibility. A changed operation ID, new Run, repeated one-use login code or replayed cloud mutation is not receipt observation. Current authoritative values are evidence of current state, not necessarily proof that the original uncertain request caused them. Missing response/usage/cost never proves no effect or zero charge.

## NET-L08 — Diagnostics and enforcement scope

**Current · Restrictiveness: Safe.** Use fixed role/kind/phase counters plus existing bounded sanitized logs; no new unbounded URL/request-ID labels, raw body history, token-frame capture or automatic network recorder. Existing AI diagnostic/exchange limits remain at their owners. Cleanup errors do not overwrite the original result.

All application-owned runtime/tooling network boundaries, SDK dependencies and generated cloud sources must be inventoried and checked. Browser-managed navigation/CSS/fonts/beacons, incoming server sockets and local-only computation are explicit classifications. Static analysis cannot prove arbitrary dynamic code safe; ambiguous new escape paths fail review/checking rather than receiving an automatic exception. [Boundary design](../projects/completed/bounded-network-requests-tech-design.md#10-source-boundary-enforcement).

## Reconsideration and remaining qualification

No automatic expansion task is created for every default. NET11 owns qualification of the selected mechanism and profiles. Existing complete-view memory, cache scale, hosted authentication, deployment, provider billing and workload acceptance remain with their original trackers. Raising owner capacity to hide unresolved cleanup or extending a deadline after dispatch is not an acceptable tuning change.
