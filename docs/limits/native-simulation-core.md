# Native simulation core limits and experiment boundaries

**Status: the selected 2 GiB proof has current matched ordinary, held-reader and lifecycle measurements; E1 rejects measured Native adoption.** The current assignment finishes NSC01–NSC03 and its adoption decision before another mechanic. Broader designed conversion, cells, distributed custody and adaptive stages retain their separate execution boundary. The earlier 64/128 MiB decisions remain historical evidence for those profiles. Numerical improvements guide candidate retention/repair; correctness, permission, accounting and recovery requirements remain mandatory. [Feature](../projects/native-simulation-core-feature-spec.md), [technical design](../projects/native-simulation-core-tech-design.md) and [NSC tasks](../maintainers/native-simulation-core.md) own purpose, mechanics and delivery. Existing physical, attention, memory, admission, saving and provider limits retain their owners.

## NSC-L01 — Proof and adoption scope

**Approved staged scope; Very safe.** The first proof supports a declared complete capability closure, not every game family. Unsupported worlds/commands refuse before effects; no live fallback actor or hidden TS authority. All selected movement, reaction, receiving, recording, consumer and persistence work must run. NSC04 converts the complete installed supported world after its actual engineering dependencies are ready. The November 13 authorization removes the earlier requirement for a material E1–E3 percentage gain before broader implementation; it does not qualify incomplete semantics or unsupported families. Performance comparisons remain isolated after each coherent batch.

## NSC-L02 — Compute capacity and job granularity

**Proposed experiment; Safe.** One explicitly sized compute pool per native host; one-worker execution is the initial control. Compare useful thread counts within the authorized host's CPU quota while accounting for Node, PostgreSQL and existing worker demand. Do not infer physical cores from vCPU count. Initial dispatcher permits at most two ready compute jobs per configured compute worker **across the entire host**; additional admitted ranges stay as compact cursors, not allocated job/output objects. Blocking I/O holds no compute job. Batch size is selected from E2's actual cost, with tiny cohorts inline. This bounds scheduling overhead without truncating required work; coherent remaining work/debt survives. No fixed one-core-per-cell or one-thread-per-character policy.

The host foundation enforces one process pool, positive configured worker count no greater than the operating system's available parallelism, and at most two queued/running outer jobs per worker. This is logical CPU admission, not a physical-core or capacity claim. Each compute worker has an explicit 8 MiB stack reservation so current typed saved-action decoding works in debug builds; the actual RSS/committed stack cost belongs in the complete AWS memory comparison. A default-stack cold-restore failure and the successful bounded-stack replay remain correctness evidence, not a capacity result. Actual gameplay range cursors and phase scheduling remain unqualified.

The E2 dispatch prerequisite queues waiting calls against that same host allowance and sends one runnable outer call per world to Rayon. The rejected publication variant used at most two scoped branches within an admitted ordinary advance, for at least 16 written rows, 16 KiB of existing payload and at least 4 KiB in each of two ordered ranges. Small work or unavailable parallel scratch used the inline encoder; parallel work charged overlapping key-order scratch and one complete output. The [current-policy active-area E2 comparison](../benchmarks/native-runtime-foundations/2026/2026-11-17-native-active-area-comparisons.md#current-policy-worker-width-and-active-area-scaling) qualifies all 18 equal-work runs, without a material throughput or completion-tail improvement. Inline encoding is the active mode. Rejection applies to this changed-record split, not to other independent phases.

The existing host compute admission bound is twice its configured workers, including queued work. A full pool refuses before enqueueing and exposes a distinct overload result. The target preserves elapsed debt and defers this pre-execution refusal rather than making it a fatal world failure. The checked GET/clock/SSE-release/NPC/navigation owners use their existing overload behavior. Ordinary save refusal before capture leaves the same pending prefix eligible for the next scheduled opportunity. Failure after capture, SQL or acknowledgement keeps its fatal storage owner. The [actual caller evidence and limit](../maintainers/native-simulation-core.md#remaining-proof-checklist) distinguish compute admission from transient-byte capacity and preserve poison and cancellation outcomes.

The [whole-phase one- and four-area diagnostic](../benchmarks/native-runtime-foundations/2026/2026-11-17-native-active-area-comparisons.md#whole-phase-native-profiling-and-e2) finds no eligible substantial range in its exercised gameplay. Combining four measured independent pieces gives under 1% ideal added worker capacity. Ordered movement, per-observer evidence and provider dependencies must first expose a genuinely independent batch before a wider experiment is useful. The measured ranges remain inline.

## NSC-L03 — Requests, captures and pending data

**Proposed experiment; Safe.** Reuse the existing host request admission/age limits and save-work ceiling rather than add an unbounded second bridge queue. Initially allow one private mutation candidate per world, with scoped parallel subjobs and read captures only at accepted boundaries. Enqueue is not acceptance; expired input rejects all of its tentative effects. Track native output/capture bytes as well as Node buffers. Use the selected **2 GiB (2,147,483,648 bytes) per native host** transient allowance shared by candidate scratch/undo, detached output and retained consumer/bridge capture buffers, independently of the existing pending-save allowance; shared immutable content is counted once plus actual references. A bounded record/page capture reserves capacity before materializing. Optional requests defer; required requests wait within the current deadline or return explicit busy before admission. Accepted required effects/history are never silently discarded. A legitimately larger atomic output fails the experiment unless supported through existing complete paging or a separately qualified larger allowance; this is not permission to hide evidence. E1/E3 must include retained/peak memory, slow consumers and actual release after cancel/failure; a timeout does not free still-running native capacity. No unbounded capture-generation chain.

The existing trusted host constant now selects the 2 GiB transient reservation budget; native owners must still connect every candidate/capture allocation before claiming a complete memory bound. Installed save settings now use the existing independent per-world pending-save allowance. Host telemetry separately reports transient, canonical resident and pending-save reservation bounds; these overlapping lifetime/admission measurements are not process RSS. Detached prefixes and shared captured records retain their actual owner until release, including after writer stop. Parsed native JSON obtains a separate conservative allocation escrow before decoding; actual derived view/save/context owners share that escrow through opaque native references. Capacity-only consumer admission now also supports a finite host byte reservation and exact JSON-shape preflight for actual SQL/formatter consumers, without a world read/write or source grant. Scoped SQL hydration now reserves before raw transfer and decoding; reading/index text and cache products retain actual consumer guards. Capacity refusal/retry and detached-product release pass component checks. Player comparison views retain their decoded capture/definition admission independently of output bytes. The publication callback selects state/reset/patch/no output before outgoing encoding; only the selected payload obtains encoding workspace and copied transport storage. The synchronous disclosure encoder expires on callback return; a transport close or write completion releases copied bytes without retaining the decoded view. Validator workspace and the selected context/model transformations have scoped ownership and actual-caller evidence. The aggregate retained-read/receiving overlap failed the prior 64 MiB allowance; the 128 MiB profile passes actual AWS held-consumer completion, cancellation, view loss and three repeated cycles. Recorded owner attribution is bounded and the 128 MiB longer-play runs fail capacity; settling remains unqualified, so no complete supported-runtime memory guarantee follows. Collection of the raw Buffer alone does not release it, and unused parent capture graphs are not retained. Ready also requires the real funded Buffer handoff, so an opaque handle or a failed copy cannot admit effects. The installation decoder now has a separate typed preflight: row/definition/original payload strings are funded as their actual String carriers, while indexed cells and normalized text keep their richer bounds. Dynamic map backing is charged only for the actual table, cold-directory and indexed-cell maps; fixed struct field identifiers do not allocate those maps. The regenerated 6,728,167-byte public current working-set packet installs under the unchanged 64 MiB allowance, and its public cold-history forget/SQL/ACK/restore scenario passes. A separate 6,670,740-byte offline installation peaks at 58,146,377 transient reserved bytes; transient and resident reservations do not measure RSS. Later semantic definition materialization retains its separate funding obligation, and complete NSC-L03 allocation coverage remains unqualified. Its cooperative shutdown waits up to five seconds on a separate lifecycle thread before reporting pending cleanup. That operational bound prevents an unbounded control wait; it neither kills live work nor releases its reservations. A pending host retains ownership until actual joining succeeds. World-save shutdown barriers remain the host service's separate required integration.

Cold action/agency preparation and the remaining agency continuation buffers now use their actual temporary and resident owners; recorded intention extras do not increase the transient allowance. Root publication settles changed actors before acceptance and rollback restores backing. In-flight SQL selections retain their original cut/metadata independently of request cleanup; paired-capture refusal releases both admitted halves. These owners pass their selected real-caller, refusal and rollback checks; their isolated batch measurement is recorded in the [current repair checkpoint](../maintainers/native-simulation-core.md#recorded-destinations-and-received-terms-repair--november-13-2026); they do not establish a complete allocation or RSS bound.

The explicit map-growth repair matches the existing funded target with exact reservation rather than increasing the 2 GiB allowance. It preserves genuine pre-write quota refusal, canonical rollback and separately charged retained capacity. Actual 14→15 receiving/save/reopen and correction/forget callers pass; incomplete frozen ordinary-play runs and the separate isolated repair measurement retain their own dispositions in the repair record. Owner reservation totals and unclassified shutdown residuals establish no RSS or settling result.

Released native consumer bodies and their opaque wrapper headers have different lifetimes. Explicit release returns a body's reservation after its last real reference; a still allocated wrapper keeps its own header admission until normal JavaScript collection. Do not treat released headers as live bodies, process RSS or free capacity. The recorded G ordinary owner diagnostic identifies a player-packet decode refusal with 102,406,080 bytes in decoded-product body admission and 26,530,707 in headers, mostly released. Its observer changes header layout, so that exact failure cannot be projected onto the clean build. The independent G gameplay diagnostic also exhausts 128 MiB, without the earlier writer-busy error. The [delivery evidence](../maintainers/native-simulation-core.md#remaining-proof-checklist) retains actual source, owner/clean sizes, incomplete work and shutdown limits. No forced GC is selected. The explicitly authorized 2 GiB profile requires fresh controls; the historical 128 MiB observations do not qualify it.

The 128 MiB profile's plain held-consumer runs pass their stated journeys, while its clean ordinary automatic play failed receiving, decoded-player-product or save-publication admission. Some failed applications retain accepted state/debt and unfinished Native shutdown; clean supervisor process/database containment is a separate result. The [current evidence](../maintainers/native-simulation-core.md#remaining-proof-checklist) records these failures without a Native cost-savings or supported memory-bound claim. The newly selected 2 GiB allowance supersedes that operational profile; forced gameplay GC and weaker accounting/privacy are not selected. Reaching the new bound requires live-owner attribution and repair, not automatic rejection of the entire implementation.

The [current 2 GiB held comparison](../benchmarks/native-runtime-foundations/2026/2026-11-15-held-play-2gib.md#twenty-second-settling-and-current-callers--november-17-2026) completes repeated reply, cancellation and physical view-loss work with independent older readers and equal 20-second normal-GC observations. Its maximum transient admission is 82.41 MiB, with resident and pending-save reservations separately owned. Final clean-run transient remains 32–22,142 unclassified bytes. The separate owner diagnostic identifies released headers at its own cuts. Three cycles establish measured release without qualifying a long-session plateau or a full supported-world allocation bound. Actual RAM retains its separate observed values.

The ordered installation encoder was removed after E3: actual complete-path CPU cost increased without removing a binding tested limit. Both current installers use the ordinary monolithic JSON encoder with unchanged pre-serialization builder/UTF-16/output admission. The final ordinary Source/native SQL journey passes, while the held-reply resource failure remains negative evidence for the prior 64 MiB profile.

The Native typed-request allocation envelope is qualified for Node.js 22.23.2 and locked AJV 8.20.0 with strict validation, no data mutation, `loopRequired=1`, `loopEnum=1` and `code.optimize=false`. Bounded schema admission refuses another Node version or an unsupported schema profile before compilation and provider dispatch; Source keeps its default compiler. Counts cover the admitted application JSON/CodeGen/input/output allocations and their actual reference custody, separately from a process RSS ceiling or V8 compiler/JIT internals. Complete CPU and physical memory measurements still include those costs. Independently admitted, deeply frozen schemas may share a separate capacity-only input lease through actual transport cleanup. Mutable, shallow-frozen or unrecognized inputs retain defensive copying and strict JSON/size validation. The strict validator profile is unchanged. Mike selected 2 GiB as the current transient allowance; qualification must distinguish funded allocation bounds from RSS and released wrapper headers awaiting normal garbage collection.

## NSC-L04 — Cell size and overlapping reads

**Proposed experiment; Medium.** Initial base-world E4 candidate: regular **128-metre cubes** in its existing spatial coordinates; compare smaller/larger sizes only when selected workload evidence needs them. Other providers must supply their coordinate/space mapping; metres and a universal sight range are not engine assumptions. No cell population cap is selected. A cell owns roots while actual body/assembly extents and supported influence determine query overlap. Large extents use conservative shared range queries rather than materializing every covered cell. A hot cell can run independent jobs on several cores; finer ownership cells are a measured tuning option. Excessive overlap or a genuinely inseparable hotspot limits efficiency and must be reported, not hidden by clipping interactions.

## NSC-L05 — Border hysteresis and former-owner data

**Proposed experiment; Safe.** Initial E6 settings: retain the present machine owner within a belt **10% of cell side length** beyond its assignment; transfer after **three real seconds** of stable residence outside the nominal assignment, or immediately when leaving the belt or coverage cannot be maintained. Reversal preference uses **30 real seconds** minimum residency; required drain/coverage overrides it. These real-time operational windows do not change physical position, game clocks, sensory deadlines or action law. At most one current temporary ownership exception exists per live root; remove it on final handoff/removal. Existing source/destination directory epochs remain authoritative. No full synchronized former-owner cache is selected; retain only bounded immutable resources and boundary reads required by actual interactions. Re-evaluate E6 against moving/cycling subjects and long-range/fast supported motion.

## NSC-L06 — Placement work and migration admission

**Proposed experiment; Safe.** Initial E6 candidate: inspect accumulated placement counters at most every **five real seconds**; retain per-active-cell totals and at most **2,048 heavy communication edges per host**, with deterministic tie ordering. Telemetry overflow retains current placement and reports incomplete analysis; it never drops gameplay exchange. Propose one neighboring cell/coupled-group move at a time, and allow **one in-flight outgoing migration per host**. Compare projected **30-second** traffic savings against at least **twice** the measured transfer/warmup bytes, while separately requiring destination CPU/memory headroom and no increase in observed synchronization delay. These are conservative candidate heuristics, not equivalent units or performance guarantees. The measured complete result controls adoption. Stop/reject candidates on queue pressure, transfer timeout, nonconvergence or insufficient resources; current authority remains correct. The initial transfer warms immutable data, then freezes only the exact scope while streaming its active state, using existing bounded network deadlines and native pending-byte admission. Failed responsiveness triggers an isolated E5 precopy comparison, not an unconditional live-copy suffix log. Cold history is fetched only for a real consumer.

## NSC-L07 — Distributed scope and time

**Proposed experiment with required integrity invariants; Very safe.** First distributed qualification is one operator, deployment Region, compatible build/definitions and logical world clock, with the existing centralized storage/authority owner. Coupled effects tolerate **zero semantic clock skew**: use a common valid boundary and exact once-only owner. Independent private calculation is allowed only within proved influence bounds. Unsupported/global effects retain a conservative joined/co-located scope; no false future visibility proof or speculative rollback. WAN, mixed-build live migration, cross-world travel and independent database shards are not part of this stage. Required state loss recovers the whole logical world at its last complete durable cut; no independent regional rollback is selected. No loading screen or geographic gameplay wall is required by a cell/machine boundary.

## NSC-L08 — Population and operating budget

**No new population limit; unqualified capacity.** Dozens/ideally hundreds of active characters and approximately 500 concurrent players in the stated subscription scenario are goals. More cells than machines and fewer cells per machine in dense areas are allowed. No machine is promised to fit an arbitrarily large tightly coupled encounter. Around **50% sustained CPU utilization** is illustrative planning headroom, not a universal runtime throttle or evidence that hot workers are safe. The $3,000 preferred/$5,000 stretched monthly whole-service scenario includes AI/database/bandwidth/storage; it authorizes no spending. Actual admission remains under existing multiplayer/operational owners. PF/PS/PD retain capacity and cost qualification.

## NSC-L09 — Retention, tooling and absent bounds

**Proposed preserved policy; Medium.** Current attention, independent-detail freshness, required evidence and memory expiry remain unchanged. Worker creation, cell transfer and machine reassignment grant no evidence or retention extension. Total lifetime memory is not copied into native hot state or transferred with an actor. Active rows grow with actual active entities/observers and permitted contacts; capture work grows with actual selected output; influence work grows with supported intersecting scopes. These dimensions have no new arbitrary actor/pair cap here. Existing quotas/admission and conservative dependency joining remain protections, while population/large-extent experiments must establish practical capacity. More recent bytes or network replicas are not free allowances. Keep one Rust workspace lockfile in addition to the existing JS lockfile; no backward-compatible format/dual-runtime requirement. Cross-architecture bitwise physics is unqualified; same-build ordered execution and current-format continuation are required.

## NSC-L10 — Stand-alone Rust server comparison

**Recorded result.** The stand-alone Rust host qualifies for the measured Base opening. The same-size Node-hosted reference falls behind the authored simulation rate. Use the [measured results and scope](../benchmarks/native-runtime-foundations/2026/2026-11-18-rust-game-server.md#decision-and-resource-closeout).

**Routine comparison.** Run [RGS](../maintainers/completed/2026/rust-game-server.md) on one player, ten active human NPCs, ten deer and five hares, with a foreground stream and ordinary one-second saves. Use 180 real seconds after warmup. Report activity and debt by minute, complete CPU, visible movement, durable saves, database work and memory for the window. Keep the existing host allowance, separate resident/pending-save owners and actual provider/transport limits. Across three repetitions, nearest-rank p95 of run-level CPU is the largest run. For latency, report the number of commands or replies and missing observations. With fewer than 20 samples p95 is the maximum (fewer than 100 for p99).

**Extended measurements.** Choose the smallest applicable case when a decision needs evidence the routine run cannot supply. If a movement-latency target is in doubt or has too few samples to decide adoption, use the existing [six-minute command schedule](../benchmarks/native-runtime-foundations/2026/2026-11-17-native-active-area-comparisons.md#repaired-matched-source-and-native-comparison) with one mover on the same heavy opening and ordinary streaming. If held memory appears to accumulate, use the [three-cycle, 20-second settling checks](../benchmarks/native-runtime-foundations/2026/2026-11-15-held-play-2gib.md#twenty-second-settling-and-current-callers--november-17-2026) with normal reclamation. Longer aging or crowd claims use their existing [workloads](../performance/simulation-inventory.md). These are separate from ordinary timing. Functional cancellation, privacy, recovery and retry checks still run through the affected callers. Report a sparse or unmeasured result as such.

**Decision.** Freeze the workload and acceptance rules before timing. Apply the [E1 rule](../maintainers/native-simulation-core.md#first-proof-qualification-criteria) to stand-alone Rust versus TypeScript using server plus exclusive PostgreSQL CPU per completed game-second. Require equivalent complete gameplay, correct disclosure and recovery, genuine memory admission, sustainable progress and the applicable [interaction and durability targets](../maintainers/native-simulation-core.md#applicable-multiplayer-timing-policy). The mixed arm shows the net effect on the same simulation. The whole-server comparison supports a whole-server claim. Use an isolated trial for a genuinely uncertain mechanism under [RGS08](../projects/completed/2026/rust-game-server-tech-design.md#8-compare-and-decide-rgs08). A repeatable material regression rejects scoped adoption. A difference within repeat variation or an unresolved required measurement leaves adoption inconclusive.

Work can grow with due actors, recipients, changed fields, pending rows, live readers and outbound requests. Bound acquisition and transfer before allocation, keep ordered effects under one writer, and charge retained data until its actual last user. Use [host limits](#nsc-l03--requests-captures-and-pending-data), [persistence](persistence.md), [cognition](cognition.md#la231) and [network limits](bounded-network-requests.md). No per-species, per-region or lower world-wide AI cap is selected by this workload.
