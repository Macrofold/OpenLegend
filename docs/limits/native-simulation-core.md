# Native simulation core limits and experiment boundaries

**Status: Proposed operating constraints for an accepted staged design; nothing here is installed.** [Feature](../projects/native-simulation-core-feature-spec.md), [technical design](../projects/native-simulation-core-tech-design.md) and [NSC tasks](../maintainers/native-simulation-core.md) own purpose, mechanics and delivery. Existing physical, attention, memory, admission, saving and provider limits retain their current owners.

## NSC-L01 — Proof and adoption scope

**Proposed; Very safe.** The first proof supports a declared complete capability closure, not every game family. Unsupported worlds/commands refuse before effects; no live fallback actor or hidden TS authority. All selected movement, reaction, receiving, recording, consumer and persistence work must run. Full-game conversion follows only a material integrated E1–E3 result. This deliberately limits the trial to contain rewrite risk; it is not a permanent product capability reduction. NSC04 removes the trial restriction by converting the complete installed supported world.

## NSC-L02 — Compute capacity and job granularity

**Proposed experiment; Safe.** One explicitly sized compute pool per native host; one-worker execution is the initial control. Compare useful thread counts within the authorized host's CPU quota while accounting for Node, PostgreSQL and existing worker demand. Do not infer physical cores from vCPU count. Initial dispatcher permits at most two ready compute jobs per configured compute worker **across the entire host**; additional admitted ranges stay as compact cursors, not allocated job/output objects. Blocking I/O holds no compute job. Batch size is selected from E2's actual cost, with tiny cohorts inline. This bounds scheduling overhead without truncating required work; coherent remaining work/debt survives. No fixed one-core-per-cell or one-thread-per-character policy.

## NSC-L03 — Requests, captures and pending data

**Proposed experiment; Safe.** Reuse the existing host request admission/age limits and save-work ceiling rather than add an unbounded second bridge queue. Initially allow one private mutation candidate per world, with scoped parallel subjobs and read captures only at accepted boundaries. Enqueue is not acceptance; expired input rejects all of its tentative effects. Track native output/capture bytes as well as Node buffers. Use a provisional **64 MiB per native host** allowance shared by candidate scratch/undo, detached output and retained consumer/bridge capture buffers, independently of the existing pending-save allowance; shared immutable content is counted once plus actual references. A bounded record/page capture reserves capacity before materializing. Optional requests defer; required requests wait within the current deadline or return explicit busy before admission. Accepted required effects/history are never silently discarded. A legitimately larger atomic output fails the experiment unless supported through existing complete paging or a separately qualified larger allowance; this is not permission to hide evidence. E1/E3 must include retained/peak memory, slow consumers and actual release after cancel/failure; a timeout does not free still-running native capacity. No unbounded capture-generation chain.

## NSC-L04 — Cell size and overlapping reads

**Proposed experiment; Medium.** Initial base-world E4 candidate: regular **128-metre cubes** in its existing spatial coordinates; compare smaller/larger sizes only when selected workload evidence needs them. Other providers must supply their coordinate/space mapping; metres and a universal sight range are not engine assumptions. No cell population cap is selected. A cell owns roots while actual body/assembly extents and supported influence determine query overlap. Large extents use conservative shared range queries rather than materializing every covered cell. A hot cell can run independent jobs on several cores; finer ownership cells are a measured tuning option. Excessive overlap or a genuinely inseparable hotspot limits efficiency and must be reported, not hidden by clipping interactions.

## NSC-L05 — Border hysteresis and former-owner data

**Proposed experiment; Safe.** Initial E6 settings: retain the present machine owner within a belt **10% of cell side length** beyond its assignment; transfer after **three real seconds** of stable residence outside the nominal assignment, or immediately when leaving the belt or coverage cannot be maintained. Reversal preference uses **30 real seconds** minimum residency; required drain/coverage overrides it. These real-time operational windows do not change physical position, game clocks, sensory deadlines or action law. At most one current temporary ownership exception exists per live root; remove it on final handoff/removal. Existing source/destination directory epochs remain authoritative. No full synchronized former-owner cache is selected; retain only bounded immutable resources and boundary reads required by actual interactions. Re-evaluate E6 against moving/cycling subjects and long-range/fast supported motion.

## NSC-L06 — Placement work and migration admission

**Proposed experiment; Safe.** Initial E6 candidate: inspect accumulated placement counters at most every **five real seconds**; retain per-active-cell totals and at most **2,048 heavy communication edges per host**, with deterministic tie ordering. Telemetry overflow retains current placement and reports incomplete analysis; it never drops gameplay exchange. Propose one neighboring cell/coupled-group move at a time, and allow **one in-flight outgoing migration per host**. Compare projected **30-second** traffic savings against at least **twice** the measured transfer/warmup bytes, while separately requiring destination CPU/memory headroom and no increase in observed synchronization delay. These are conservative candidate heuristics, not equivalent units or performance guarantees. The measured complete result controls adoption. Stop/reject candidates on queue pressure, transfer timeout, nonconvergence or insufficient resources; current authority remains correct. The initial transfer warms immutable data, then freezes only the exact scope while streaming its active state, using existing bounded network deadlines and native pending-byte admission. Failed responsiveness triggers an isolated E5 precopy comparison, not an unconditional live-copy suffix log. Cold history is fetched only for a real consumer.

## NSC-L07 — Distributed scope and time

**Proposed experiment with required integrity invariants; Very safe.** First distributed qualification is one operator, deployment Region, compatible build/definitions and logical world clock, with the existing centralized storage/authority owner. Coupled effects tolerate **zero semantic clock skew**: use a common valid boundary and exact once-only owner. Independent private calculation is allowed only within proved influence bounds. Unsupported/global effects retain a conservative joined/co-located scope; no false future visibility proof or speculative rollback. WAN, mixed-build live migration, cross-world travel and independent database shards are not part of this stage. Required state loss recovers the whole logical world at its last complete durable cut; no independent regional rollback is selected. No loading screen or geographic gameplay wall is required by a cell/machine boundary.

## NSC-L08 — Population and operating budget

**No new population limit; unqualified capacity.** Dozens/ideally hundreds of active characters and approximately 500 concurrent players in the stated subscription scenario are goals. More cells than machines and fewer cells per machine in dense areas are allowed. No machine is promised to fit an arbitrarily large tightly coupled encounter. Around **50% sustained CPU utilization** is illustrative planning headroom, not a universal runtime throttle or evidence that hot workers are safe. The $3,000 preferred/$5,000 stretched monthly whole-service scenario includes AI/database/bandwidth/storage; it authorizes no spending. Actual admission remains under existing multiplayer/operational owners. PF/PS/PD retain capacity and cost qualification.

## NSC-L09 — Retention, tooling and absent bounds

**Proposed preserved policy; Medium.** Current attention, independent-detail freshness, required evidence and memory expiry remain unchanged. Worker creation, cell transfer and machine reassignment grant no evidence or retention extension. Total lifetime memory is not copied into native hot state or transferred with an actor. Active rows grow with actual active entities/observers and permitted contacts; capture work grows with actual selected output; influence work grows with supported intersecting scopes. These dimensions have no new arbitrary actor/pair cap here. Existing quotas/admission and conservative dependency joining remain protections, while population/large-extent experiments must establish practical capacity. More recent bytes or network replicas are not free allowances. Keep one Rust workspace lockfile in addition to the existing JS lockfile; no backward-compatible format/dual-runtime requirement. Cross-architecture bitwise physics is unqualified; same-build ordered execution and current-format continuation are required.
