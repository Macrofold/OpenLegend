# Cognition Lab limits and constraints

The [feature specification](../projects/cognition-lab-feature-spec.md) and [technical design](../projects/cognition-lab-tech-design.md) select these constraints for implementation under [CL01–CL11](../maintainers/cognition-lab.md). Every entry below is **Proposed** at design baseline `795dae71d1cf6a2e846ebfaaeb7c70342bc01f66` on October 24, 2026; none is measured laboratory runtime capacity. Exact starting values are implementation defaults to qualify, not optimized constants. Shared cognition, interface, provider, save, reference and action limits remain with their existing owners.

## CLL01

**One active lab scenario and dedicated storage.** Status: **Proposed**. Restrictiveness: **Safe**. Run one lab runtime beside the normal game runtime, using its own PostgreSQL database and data directory. Saved scenarios and retained comparisons are unlimited by a new count quota but subject to CLL07 storage admission; execute new comparison variants serially. Loading another scenario requires settling or cancelling the active lab run, then replacing only lab state. Do not silently fall back to the gameplay database. This fits the current single-active-world repository and hardcoded schema/search-path ownership without a multitenant rewrite; it does not promise separate CPU or provider capacity. Owners: CL01/CL08/CL09 and technical design composition.

## CLL02

**Shared execution and transport ceilings.** Status: **Proposed consumer of current owner limits**. Restrictiveness: **Medium**. Use the installed provider's request/response limits, model/context allowance, schema validation, reference restrictions, action admission, account spending and service concurrency. The lab grants no larger hidden allowance and performs no automatic paid retry to improve an experiment. An oversized prepared override is rejected before dispatch with its relevant limit and retained draft; exact original capture remains readable. Only actual supported model configuration is selectable. Reuse [cognition limits](cognition.md), [AI provider behavior](../ai-providers.md) and the selected native owner rather than copying numbers that can diverge. Owners: CL04/CL05/CL07.

## CLL03

**Explicit operator holds.** Status: **Proposed**. Restrictiveness: **Medium**. A selected breakpoint holds an undispatched stage. Human inspection time is recorded separately and excluded from that stage's provider timeout and the lab run's active-wall guard; it is not erased from elapsed experiment time. Already dispatched requests retain their actual timeout, cancellation, settlement and cost behavior. Hold adjustment uses an explicit lab timing seam on the decision owner; no global clock rewrite and no suspension of a network request midflight. Long-held work has a visible state and can be discarded; scenario replacement or relevant edits invalidate prepared authority. Owners: CL06/CL07 and technical design hold/deadline contracts.

## CLL04

**Paging and detail loading.** Status: **Proposed**. Restrictiveness: **Safe**. Timeline, run, memory, history, relationship and other growing collections use indexed cursor queries, a default page of 50 rows and a maximum requested page of 100 rows. Search applies before paging through the same scoped query. Lists return summaries and identities; full request, memory, output and object details load by explicit selection. A page is not a total retained-item limit. Show the next-page/remaining-data affordance and distinguish partial capture from undisplayed records. Never hydrate or serialize the whole history to obtain a page, and do not implement giant nested detail trees. Owners: CL03/CL05/CL08/CL09; related payload/work bounds in CLL09.

## CLL05

**Desktop density, fixed controls and navigation depth.** Status: **Proposed**. Restrictiveness: **Medium**. Design and qualify first at 1920×1080 and 2560×1440 CSS-pixel viewport targets at default density. Use 8 px outer/gap spacing, a 40 px header and 32 px run strip; 28 px compact rows/targets, normally 16 px glyphs, 13 px labels and 14 px prose with about 20 px line height. These are lab defaults, not new global game tokens. Keep readable text at least 12 px and shared focus/contrast semantics; user zoom must preserve access. Reserve navigation space and keep the composer, run controls, category navigation and inspector navigation fixed. Each pane has at most one primary vertical scroller; a focused modal/editor temporarily owns its own scroller. Fixed finite icon sets do not get a scrollbar. Every growing collection exposes search from its first use in a stable fixed location, including while empty or filtered; fixed small sets use their compact controls without a search or scrolling strip.

From a visible response summary, the selected actual call's exact input, questions/options, selected memories and effect changes each require at most one direct navigation action; a selected memory's full content requires at most one further action. When a multi-call response has no unique recorded primary call, one additional explicit call choice is permitted before opening that exact payload; never invent a combined request or choose an arbitrary supporting call. Breadcrumb length never imposes equivalent click depth. Column proportions, comparison replacement behavior and reduced-viewport handling are owned by the feature specification. Rationale: fast manipulation of many explicit details on Mike's large desktop without moving controls or obscuring important content. There is no claimed uncoached usability pass. Owners: CL02/CL05/CL11.

## CLL06

**Bounded run defaults and explicit renewal.** Status: **Proposed**. Restrictiveness: **Safe**. One response stops at the focal character's immediate publication or explicit no-decision/failure disposition, or at the first exhausted run guard: **60 simulated seconds**, **20 newly dispatched model calls per execution interval across all lab actors**, or **180 active wall-clock seconds**. Operator holds are excluded from active wall time under CLL03; provider deadlines and spending admission still apply. Count dispatch before admitting another model call. Reaching a guard requests a safe hold, stops new dispatch and settles or cancels already admitted work through its owner; it does not fabricate character silence or roll back incurred work. Display **Run limit reached** and which guard fired.

**Continue** explicitly renews the displayed guard allowance on the same run; never loop or renew automatically. **Advance time** starts at 5 simulated seconds; **Run for** starts at 60 simulated seconds. The user may choose a longer finite duration or adjust guards through compact run settings, within native numeric/time validation and actual spending authorization. **Run until stopped** is an explicit mode with the same visible configurable guards, not an unlimited hidden process. No separate arbitrary global duration ceiling is selected here; every accepted run request nevertheless contains finite guards. A physical action can remain started/in progress when One response stops; **Advance to outcome** stops on that action's real terminal outcome or these guards. Rationale: quick everyday experiments, visible recovery from missing focal opportunities and no endless wait for recurring thought. Initial numbers require CL11 qualification across ordinary reaction and longer maintenance episodes. Owners: CL06/CL10/CL11.

## CLL07

**Retained evidence and storage admission.** Status: **Proposed**. Restrictiveness: **Medium**. Starting scenarios, continuation checkpoints and retained runs are different records. Keep explicitly saved work until the developer removes it; do not evict pinned work by age or a hidden item count. Use a configurable lab-data byte allowance, initially **2 GiB**, covering lab checkpoints and retained capture artifacts; count actual serialized bytes and reserved in-progress capture, with one owner. At **80%** show a compact storage indicator; at the allowance stop admitting another capture or save and preserve existing evidence. Offer export/remove/increase-allowance actions. Storage exhaustion cannot authorize gameplay-data deletion or silently relabel an incomplete capture as complete.

Current-format imports/exports only; no migration or old-schema support. Capture one coherent actual applied origin at new-run start, accounting for it within this allowance; reuse it for that episode's later intervals. Complete request/response bytes are retained once per capture, with records referring to them; do not duplicate a whole world per utterance or model call. Capture-only reruns cannot continue native effects without a real compatible checkpoint. Exact per-run capture allowance is CLL09. Rationale: durable useful investigations with explicit bounded local growth, avoiding a retention platform for a zero-user development tool. The initial size is a chosen starting allowance, not measured capacity or a repository quota. Owners: CL05/CL08/CL09/CL11.

## CLL08

**Custom model-only fields.** Status: **Proposed**. Restrictiveness: **Medium**. Support text, boolean, number and labeled meter values with an explicit subject, visibility and description. No extra count ceiling is selected beyond existing edit/transport/storage budgets. Optional meter display bounds describe that field; they do not create an engine stat, trigger, action option, perception, emotional cause, retrieval index or derived native modifier. Unsupported native fields remain unavailable rather than accepted as disguised prose. Clearly label the model-only scope wherever it is edited or captured. Reaching the installed request allowance produces explicit overflow/selection evidence and never silently converts the field into a canonical mechanic. Owners: CL03/CL05/CL07 and technical design editor contracts.

## CLL09

**Capture, work and response budgets.** Status: **Proposed**. Restrictiveness: **Safe**. Reserve up to **64 MiB of exact capture artifacts per run** by default, adjustable within CLL07's available allowance; retain a full accepted provider request/response within its native limit rather than slicing it into misleading evidence. Reserve the complete application request and the bounded normalized response allowed by the native owner before dispatch; if that required capture cannot fit, stop with capture capacity as the reason. Reserve optional provider-wire artifacts only when the adapter exposes a bounded capture. Missing or unbounded optional wire capture is marked unavailable and does not block ordinary Say or other supported execution. A finalized run records completeness and all interrupted/error dispositions. Payload requests return at most **1 MiB per content chunk** with exact offset/continuation identity and a download path for complete content; paging must not cause server reformatting of the whole artifact. Small summaries exclude raw envelopes.

Use existing native scheduler/provider concurrency and bound lab-only database queries to CLL04 pages; no new per-character background polling, whole-world hydration on keystroke or eager capture of unrelated game requests. Cancel obsolete search/detail reads and scope cache keys to lab world/timeline/revision/record identity. These values are intentionally simple implementation starting points, not throughput evidence. Qualify long histories, concurrent game/lab work and ordinary response latency under CL11; use measurements before adding workers, a generalized event bus, a new search system or a queue platform. Owners: CL05/CL08/CL11.
