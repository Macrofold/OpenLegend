# Cognition Lab limits and constraints

The [feature specification](../projects/cognition-lab-feature-spec.md) and [technical design](../projects/cognition-lab-tech-design.md) own these installed contracts. Defaults remain practical starting values rather than optimized capacity claims. Qualification is recorded in [integrated verification](../verification/cognition-lab.md), [control](../verification/cognition-lab-control.md), [storage](../verification/cognition-lab-storage.md) and [native capture/restore](../verification/cognition-lab-runtime.md). Shared cognition, interface, provider, save, reference and action limits remain with their existing owners.

## CLL01

**One active lab scenario and dedicated storage.** Status: **Implemented; qualification scope below**. Restrictiveness: **Safe**. Run one lab runtime beside the normal game runtime, using its own PostgreSQL database, data directory and persistent server-owned remote execution namespace. Imported native world/actor IDs cannot alias gameplay's mutable remote workspace or session. Saved scenarios and retained comparisons are unlimited by a new count quota but subject to CLL07 storage admission; execute new variants serially. Loading settles/cancels active lab work and replaces only lab state. Never fall back to gameplay storage. This fits current single-active-world ownership without a multitenant rewrite; CPU and provider capacity remain shared. Owners: CL01/CL08/CL09 and technical design composition.

## CLL02

**Shared execution and transport ceilings.** Status: **Implemented consumer of current owner limits**. Restrictiveness: **Medium**. Use the installed provider's request/response limits, model/context allowance, schema validation, reference restrictions, action admission, account spending and service concurrency. One host-owned execution pool serves game and lab through scoped registrations; a second runtime does not multiply process capacity. Recover/reconcile each store's uncertain attempts only against that store, preserving their occupied capacity after runtime disposal until native settlement. Explicit Lab generation settings may raise or lower the ordinary output default before capture and paid admission; reflection/full harness ceilings stay owned by their callers. There is no hidden spending multiplication or automatic paid retry to improve an experiment. An oversized prepared override is rejected before dispatch with its relevant limit and retained draft; exact original capture remains readable. Only actual supported model configuration is selectable. Reuse [cognition limits](cognition.md), [AI provider behavior](../ai-providers.md) and the selected native owner rather than copying numbers that can diverge. Owners: CL01/CL04/CL05/CL07.

## CLL03

**Explicit operator holds.** Status: **Implemented; qualification scope below**. Restrictiveness: **Medium**. A selected breakpoint holds an undispatched stage. Human inspection time is recorded separately and excluded from that stage's provider timeout and the lab run's active-wall guard; it is not erased from elapsed experiment time. Already dispatched requests retain their actual timeout, cancellation, settlement and cost behavior. Primary, higher-model and maintenance queue/dispatch owners all honor the scoped gate and adjust their own undispatched deadlines. Registered primary/higher decisions retain timing ownership through initial persistence, context preparation and handoff; nested waits count once and pending credit settles before provider entry. A held wait consumes no free execution lease and must settle on cancellation/invalidation so Stop/load can drain. Dispatched or uncertain work retains its native capacity until settlement. No global clock rewrite or midflight network suspension is permitted. Long-held work stays visible; scenario replacement or relevant edits invalidate prepared authority. Owners: CL01/CL06/CL07 and technical design hold/deadline contracts.

## CLL04

**Paging and detail loading.** Status: **Implemented; qualification scope below**. Restrictiveness: **Safe**. Timeline, run children, stage evidence collections, memory, history, relationships, field descriptors and dynamic choices use indexed cursor queries, a default page of 50 rows and a maximum requested page of 100 rows. Search applies before paging through the same scoped query. Bootstrap and run/stage headers contain fixed summaries/references rather than embedding these collections. Lists return summaries and identities; full request, memory, output and object details load by explicit selection. A page is not a total retained-item limit. Show the next-page/remaining-data affordance and distinguish partial capture from undisplayed records. Use known maintained totals or loaded/more indicators rather than a whole-history count scan on refresh. Never hydrate or serialize the whole history to obtain a page, and do not implement giant nested detail trees. Owners: CL02/CL03/CL05/CL08/CL09; related payload/work bounds in CLL09.

## CLL05

**Desktop density, fixed controls and navigation depth.** Status: **Implemented; qualification scope below**. Restrictiveness: **Medium**. Design and qualify first at 1920×1080 and 2560×1440 CSS-pixel viewport targets at default density. Use 8 px outer/gap spacing, a 40 px header and 32 px run strip; 28 px compact rows/targets, normally 16 px glyphs, 13 px labels and 14 px prose with about 20 px line height. These are lab defaults, not new global game tokens. Keep readable text at least 12 px and shared focus/contrast semantics; user zoom must preserve access. Reserve navigation space and keep the composer, run controls, category navigation and inspector navigation fixed. Each pane has at most one primary vertical scroller; a focused modal/editor temporarily owns its own scroller. Fixed finite icon sets do not get a scrollbar. Every growing collection exposes search from its first use in a stable fixed location, including while empty or filtered; fixed small sets use their compact controls without a search or scrolling strip.

From a visible response summary, the selected actual call's exact input, questions/options, selected memories and effect changes each require at most one direct navigation action; a selected memory's full content requires at most one further action. When a multi-call response has no unique recorded primary call, one additional explicit call choice is permitted before opening that exact payload; never invent a combined request or choose an arbitrary supporting call. Breadcrumb length never imposes equivalent click depth. Column proportions, comparison replacement behavior and reduced-viewport handling are owned by the feature specification. Rationale: fast manipulation of many explicit details on Mike's large desktop without moving controls or obscuring important content. There is no claimed uncoached usability pass. Owners: CL02/CL05/CL11.

## CLL06

**Bounded run defaults and explicit renewal.** Status: **Implemented; qualification scope below**. Restrictiveness: **Safe**. One response stops at the focal character's immediate publication or explicit no-decision/failure disposition, or at the first exhausted run guard: **60 simulated seconds**, **20 newly dispatched model calls per execution interval across all lab actors**, or **180 active wall-clock seconds**. Operator holds are excluded from active wall time under CLL03; provider deadlines and spending admission still apply. Count dispatch before admitting another model call. Reaching a guard requests a safe hold, stops new dispatch and settles or cancels already admitted work through its owner; it does not fabricate character silence or roll back incurred work. Display **Run limit reached** and which guard fired.

**Continue** explicitly renews the displayed guard allowance on the same run; never loop or renew automatically. **Advance time** starts at 5 simulated seconds; **Run for** starts at 60 simulated seconds. The user may choose a longer finite duration or adjust guards through compact run settings, within native numeric/time validation and actual spending authorization. **Run until stopped** is an explicit mode with the same visible configurable guards, not an unlimited hidden process. No separate arbitrary global duration ceiling is selected here; every accepted run request nevertheless contains finite guards. A physical action can remain started/in progress when One response stops; **Advance to outcome** stops on that action's real terminal outcome or these guards. Rationale: quick everyday experiments, visible recovery from missing focal opportunities and no endless wait for recurring thought. Native fixtures qualify finite guards and ordinary immediate reactions; longer independent maintenance and character-quality acceptance remain with CL11 and their existing owners. Owners: CL06/CL10/CL11.

## CLL07

**Retained evidence and storage admission.** Status: **Implemented; qualification scope below**. Restrictiveness: **Medium**. Starting scenarios, continuation checkpoints and retained runs are different records. Keep explicitly saved work until the developer removes it; do not evict pinned work by age or a hidden item count. Use a configurable lab-data byte allowance, initially **2 GiB**, covering serialized retained lab metadata, checkpoints, capture artifacts and reserved in-progress writes, with one owner. Native-only stimuli, no-call intervals, annotations and operation records participate in admission even without a model call. Reserve the finite receipt/terminal-status space needed to finish admitted work. This measures retained logical lab bytes, not PostgreSQL indexes/physical disk use or the native world's complete history; native history and authoritative spending keep their existing owners and limits. At **80%** show a compact storage indicator; at the allowance refuse further retained growth while preserving accepted outcomes. Offer export/remove/increase-allowance actions. Storage exhaustion cannot authorize gameplay-data deletion or silently relabel an incomplete capture as complete.

Current-format imports/exports only; no migration or old-schema support. Capture one coherent actual applied origin at new-run start: the native checkpoint plus its immutable lab context/settings snapshot, both charged to this allowance; reuse it for that episode's later intervals. Changed lab settings alone need only a small new descriptor when the native cut is unchanged. Complete request/response bytes are retained once per capture, with records referring to them; do not duplicate a whole world per utterance or model call. Removing one descriptor preserves bytes still referenced by another retained/current record; remove the stored-byte charge only after physical deletion succeeds. Maintain usage incrementally, rebuilding at startup/recovery only when necessary. Capture-only reruns cannot continue native effects without a real compatible checkpoint. Exact per-run capture allowance is CLL09. Rationale: durable useful investigations with explicit bounded local growth, avoiding a retention platform for a zero-user development tool. The initial size is a chosen starting allowance, not measured capacity or a repository quota. Owners: CL05/CL08/CL09/CL11.

## CLL08

**Custom model-only fields.** Status: **Implemented; qualification scope below**. Restrictiveness: **Medium**. Support text, boolean, number and labeled meter values with an explicit subject, visibility and description. No extra count ceiling is selected beyond existing edit/transport/storage budgets. Optional meter display bounds describe that field; they do not create an engine stat, trigger, action option, perception, emotional cause, retrieval index or derived native modifier. Unsupported native fields remain unavailable rather than accepted as disguised prose. Clearly label the model-only scope wherever it is edited or captured. Reaching the installed request allowance produces explicit overflow/selection evidence and never silently converts the field into a canonical mechanic. Owners: CL03/CL05/CL07 and technical design editor contracts.

## CLL09

**Capture, work and response budgets.** Status: **Implemented; qualification scope below**. Restrictiveness: **Safe**. Reserve up to **64 MiB of captured run evidence, including retained run metadata**, by default, adjustable within CLL07's available allowance. A shared full origin checkpoint is charged to CLL07 rather than duplicated into each run's evidence allowance. Retain a full accepted provider request/response within its native limit rather than slicing it into misleading evidence. Reserve the complete native-operation request, supplemental model-readable inputs and bounded normalized response allowed by the native owner before dispatch; if that required capture cannot fit, stop with capture capacity as the reason. Reserve optional provider-wire artifacts only when the adapter exposes a bounded capture. Missing or unbounded optional wire capture is marked unavailable and does not block ordinary Say or other supported execution. A finalized run records completeness and all interrupted/error dispositions. Payload requests return at most **1 MiB per content chunk** with exact offset/continuation identity and a download path for complete content; paging must not cause server reformatting of the whole artifact. Small summaries exclude raw envelopes.

Optional Library scenario/checkpoint descriptions allow **1,000 characters** of searchable summary metadata, keeping brief setup notes bounded without copying them into character input. The same limit applies to save admission and the editor; native state and custom experimental context retain their separate owners.

Use existing native scheduler/provider concurrency and bound lab-only database queries to CLL04 pages; no new per-character background polling, whole-world hydration on keystroke or eager capture of unrelated game requests. Cancel obsolete search/detail reads and scope cache keys to lab world/timeline/revision/record identity. These installed values are explicit work bounds, not throughput evidence. Qualify long histories, concurrent game/lab work and ordinary response latency under CL11; use measurements before adding workers, a generalized event bus, a new search system or a queue platform. Owners: CL05/CL08/CL11.

The browser admits **4 active lab detail/list GETs** with at most **32 waiting reads** across the mounted panes and temporary surfaces. Queued reads consume their existing observation deadline and disappear when their owning view cancels; they are never retried automatically. The one sequential changes reader remains separate. Every dispatched read still uses the existing shared browser owner with capacity **16**, including its physical-closure accounting. This caller admission prevents a restore or two-inspector/modal opening from exhausting that shared owner through transient read fanout; it does not increase network capacity or release unresolved transfers. A serial comparison admits at most **100 variants**, using the shared protocol limit so its complete known-run identities fit the reserved terminal receipt.
