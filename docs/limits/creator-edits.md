# Creator edit propagation: limits and constraints

[Tasks](../maintainers/creator-edits.md) · [Design](../projects/creator-edit-propagation-tech-design.md)

## CE01

**Accepted target, not implemented — October 3, 2026.** No automatic semantic memory cascade. Mandatory deletions require explicit dependency proof and a complete approved preview. Optional associations are selectable. This protects coherent state without pretending semantic similarity is authority. Plan size, closure work and retained approval lifetimes have no selected numeric bounds yet; the implementation must choose and measure them before claiming complete coverage. Oversize or unsupported closure must block application, never truncate required deletions. Existing [invention bounds](inventions.md) apply where those services are reused.

## CE02

**Later target, not implemented.** Search scope and result pages will reuse [memory limits](memory.md) and actual semantic lookup. No maximum batch, paid allowance or retention target is selected by this document. Large memory sets create vector-search, review and mutation costs; implementation must bound them, expose incomplete coverage and respect the account owner's explicit paid cap. AI suggestions require selected exact diffs and cannot apply automatically.
