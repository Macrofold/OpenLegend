# Extending Open Legend

Use the smallest responsible module. Favor an explicit finite contract and meaningful scenarios over a framework that anticipates every future game.

Start with [Engine and world boundaries](engine-and-world-boundaries.md#5-a-repeatable-boundary-decision). Determine whether the change is a supported configuration/composition, a new reviewed native implementation behind an existing interface, or a new host capability. World-specific names should not automatically require changes across every transport, context, UI and scheduler layer. The [world-module runtime](../archive/07-technical-architecture/world-module-runtime.md) defines the target shared boundary, and [EWF](maintainers/extensible-world-foundation.md) tracks its implementation. Until a particular interface is delivered, the native extension steps below describe the current code path; do not pretend a generic API exists.

## A new native rule or component

Start in `packages/domain/src/types.ts` with a versioned, serializable component or reference. Add the rule to a pure transition; use the saved RNG instead of `Math.random`, and supplied simulation time instead of `Date.now`. Document which inputs it consumes, which component owns each output, when it interrupts work, and the observations it emits. Emit only committed outcomes. Add a scenario for conservation, cancellation or competing access if relevant.

For a genuinely new host operation, or before its family adapter is available, the current native path requires the coordinated changes below. Once INV-3 supplies the family contract, a new supported definition should use that contract rather than repeating these edits across generic code.

If a player needs a new action, add its intention to the public protocol and bounded request validation, map it to a domain command, and register its options in `action-catalogue.ts` (plus `view.ts` for inline controls). Include discoverable unavailable entries when prerequisites are missing; enumerate all learned definition variants without an AI retrieval cap. Reuse pure command admission for availability and prove that browsing leaves the world unchanged. Add a common explanation and any target/condition-specific description in `action-descriptions.ts`, using only the permitted observation. Reuse stored recipe/item prose for inventions, then add trusted, current mechanical facts. Keep blockers in `reason`; the picker displays them beneath unavailable labels. Use `commandFacts` for actual material costs, yields and game-time durations. The client renders server-provided options and treats all descriptions as plain text. Never let a renderer-specific object or a freeform client effect enter authoritative state. Family discovery is owned by [INV-3](maintainers/inventions-and-world-evolution.md#inv-3--expand-beyond-the-three-recipes-through-registered-families); prose resolution by [AG05](maintainers/agent-agency.md).

## A new invented family

INV-3 owns the mechanical family descriptor, draft codec, action discovery and execution adapters. The common registration/manifest metadata is defined by [World-module runtime](../archive/07-technical-architecture/world-module-runtime.md#3-definition-envelope-and-composition). Reuse one mechanical family registry. A new family may need native engineering; another supported definition within that family should not need new generic protocol or cognition switches.

For future visual/audible behavior, follow the [proposed perception contract](../archive/07-technical-architecture/perception-and-attention.md): shared near/medium/far descriptions, supported state overlays, event-time sound emissions and exposure-filtered context. Keep description/semantic-index data separate from executable rule authority. Richer exposure/description records remain proposed; finite derived interest subscriptions are implemented in `interests.ts`. Incompatible development formats are rejected explicitly under the active no-legacy policy. Preserve same-version integrity and the separately defined lifecycle for live definition changes; do not add old-save compatibility machinery for this extension.

First implement the trusted mechanism in ordinary domain code. Define suitable material roles, permitted properties, units, parameter bounds and incompatibilities. Add admission counterexamples, such as a rock that is rigid but cannot be an arrow shaft. Update `DECLARATION_CONTRACT`, the strict authoring schema, Jev route candidates and the scoped prompt. Include at least two compositions exercising the same mechanism to avoid weapon-specific hardcoding.

Recipe and output-item descriptions are already required, bounded fields saved at admission. Use those for the current crafting/equipment families. When a future family needs distinct common situations (for example animal, NPC and player targets), introduce a small versioned set of validated description variants at creation, with an explicit default. The application should select variants from trusted target kinds and permitted facts; avoid one text per state permutation, model calls on hover, arbitrary template expressions or exposing private state. New variant fields need strict schemas and explicit incompatible-development-save rejection before use. Prose explains mechanics and never establishes them.

Invented definitions are data. A new property does nothing until a trusted operator consumes it. Do not implement a universal `effects` map, eval, generated scripts, or automatic physics from prose. Unsupported operations should stay unsupported until they have normal tests and review. If replacing admitted definitions later, design immutable versions, references, migration and rollback before introducing an edit API.

## Attributes, senses, and deliberate v1 limits

New attributes use [typed applicable state, concerns and presentation](../archive/07-technical-architecture/world-module-runtime.md#4-typed-state-and-attributes); senses use [reviewed detector/projection interfaces](../archive/07-technical-architecture/world-module-runtime.md#6-senses-and-observation-interfaces) feeding EPR. Follow [P01–P12 and intentional specificity](engine-and-world-boundaries.md#intentional-v1-specificity), the [roadmap](extensibility-roadmap.md) and [examples](extensible-world-examples.md). Fixed v1 implementations are allowed with an explicit owner, seam and expansion trigger; their names are not universal. Report native, adapter, data-defined, composable or scriptable support only where delivered.

### Implemented attribute extension path

The current [attribute foundation](architecture.md#extensible-attribute-foundation) supports reviewed numeric reservoir/category definitions. Add another same-family definition without adding a named protocol, React, cognition or scheduler branch. Definitions specify bounded schema, units, owner implementation, disclosure and presentation; sparse state is initialized only for explicitly selected actors. `world-presets.ts` is the native charge/disposition example. The manifest contains full definitions and pins; no external package lookup occurs on a tick.

Authorized local god tooling can POST to `/api/god/definitions/attributes` for the current manifest/generation, and `/api/god/definitions/attribute` to admit a definition, publish a presentation-only revision, or remove an unused definition. Requests bind the expected manifest revision and restore generation. `/api/god/editor/attributes` returns permitted actor values; `/api/god/editor/attributes/save` accepts atomic typed edits, with `expectedRevision: null` explicitly initializing a supported sparse attribute. Ordinary players and NPC jobs receive no authoring grant. The technical endpoint is an interim surface; INV-4/EWF12 still own conversational authoring and UI refinement.

Do not add replenishment supply by changing a definition: supply is finite native instance state, created by a reviewed world preset. A source and recipient bind the same exact resource definition; matching labels/units are insufficient. Current revisions cannot alter mechanics or replace active action bindings. Lifetime effects and multi-operation controllers remain separate owners, not nominally supported fields.

### Implemented sense adapter path

`perception.ts` supplies reviewed versioned detectors; the same world manifest records bounded definitions, default bindings and content pins. Actor bindings select installed IDs. New physics requires a reviewed host implementation. `createTouchDemo` is the coarse-proximity example; [Architecture](architecture.md#registered-senses-and-coarse-contact) states its observation/navigation limits. Keep identity-bearing provenance out of contact projections. Install or replace immutable descriptors/bindings before simulation; do not mutate them in place during a tick. Reuse `spatialCandidates`, `emit` and the existing awareness/scheduler path instead of adding a modality-specific service.

## Models and Macrofold

Implement `AiClient.judge` and `AiClient.generate` with the result/receipt contracts in `packages/ai/src/types.ts`. Preserve unavailable, invalid, refused, canceled and uncertain outcomes, usage provenance and actual model reporting. Do not retry paid calls invisibly. Tests can inject a client; the application marks injected execution as fixtures unless explicitly configured otherwise.

The server has a Macrofold backend selected when its key is configured; fully pooled multi-actor execution remains unverified. Extend it through the existing execution port. It must preserve stable request IDs, cancellation/deadlines, provider receipts, bounded resources, permission-scoped context and durable attempt semantics. Macrofold must not become the authority for world state or declaration admission. The [platform brief](../archive/07-technical-architecture/macrofold-implementation-brief.md) describes the broader proposed service behavior. Native play works without Macrofold, but the current live full-deliberation route requires its harness; direct inference cannot silently substitute for it.

The planned [agency runtime](../archive/07-technical-architecture/agent-agency-runtime.md) extends decision admission, operational goals and native continuation through existing application/domain boundaries. Follow [AG](maintainers/agent-agency.md) for that work and EPR for reaction intake; generated goal prose cannot become an alternate mutation path.

## Memory and context

Follow the single [memory architecture](memory-architecture.md) and [CR01–CR12](maintainers/cognition-redesign.md) backlog. Keep physical truth, raw/consolidated experience, accepted inner-world prose, native commitments/knowledge and god-only thought presentation separate. Summaries are recallable experience with honest attribution; search indexes remain derived and neither can replace native facts.

Build compact English context with full accepted About me text and one Jev-selected recall view. Treat authored `data.text`/awareness content as the decision-facing event representation; do not duplicate structured fields when that prose already expresses them. Keep IDs, quotas, versions, operational correlation metadata and coverage server-side except reflection quotas and necessary action handles. Speech defaults to level 2 with no mandatory mind patches; complex routes and independently scheduled file reflection have separate contracts and commit boundaries. Every cognition job gets fresh model conversation state.

Apply sentence-based stimulus projection and embedding recall to all admitted semantic decision opportunities, including hazards/notable events, encounters and changed needs/goals as well as speech. Native templates preserve perceived uncertainty; internal event fields remain authoritative server bindings. Never block native danger responses on recall or reasoning.

Event-time awareness includes the player. Retain one shared witnessed event plus permitted actor projections, not duplicate raw memories; unwitnessed actions still commit native state. The native notability policy also retains notable unseen events, without granting actor awareness or recall. Consolidate older-than-six-hour experience hourly using a small-model route, independently of reflection and sleep. Publish validated reflection files atomically as one current PostgreSQL text row, preserving concurrent observations and the old snapshot on failure.

For implemented immediate composed responses and future narration, follow the [Narrator/conversation design and NC tracker](narration-and-conversations.md). Optional accepted talk/act/think components have independent receipts and personal experience; a private thought is not a world event or god-only reflection presentation. Expressive actions initially have no new mechanical effects. Keep Narrator prose in private story storage with typed source links, never in the world-event stream or NPC recall. Conversation membership does not grant speech awareness; merge history remains attached to its original conversation. Reuse scoped context/retrieval and authoritative effect receipts; do not let prose or voice settings mutate the world. On-the-spot action/effect invention remains deferred to NC13.

Selection must use present people, recent events, goals, unresolved concerns and conflicting beliefs. Follow the canonical delivery order: structured lookups, required embedding-based arbitrary-intent retrieval, then selective-recall tools justified by demonstrated initial-context gaps. Derive cues from accepted state without another narrative authority, and verify that useful recall affects later behavior rather than merely entering context.

Retrieval can evolve behind the actor-scoped query port. Add meaningful privacy, attribution, forgetting, overflow and publication-race checks when implementing these contracts. Preserve native obligations and skills through same-version restore and admitted live definition changes. Update every related document under the [documentation rules](../AGENTS.md#documentation-is-a-maintained-source-of-truth), not just this guide.

When adding a cognition stage, add its structured child record to the [god-mode debugger](memory-architecture.md#god-mode-cognition-debugger) in the same slice. Preserve trigger correlation, no-call dispositions, actual input/output and acceptance boundaries; retrieval records include available similarity scores and Jev judgments. Keep private diagnostics authorized and bounded, separate from actor context, and never make native simulation depend on diagnostic capture.

## Time controls and presence

Keep simulation rates in the server clock configuration, never in rendering or individual need/work rules. New speed presets must update bounded HTTP/service validation, the controls and rate-equivalence tests. Preserve fractional simulation debt at 0.5×. Only transitions that actually affect pause/speed should reset clock debt.

Keep foreground attention separate from connection liveness. Window blur can mean the tab is visible but unfocused; background timers may stop while its event stream remains connected. The saved pause preference selects which signal permits advancement, and manual pause/storage errors override either. A future transport must supply equivalent connect/disconnect signals. Do not turn an opted-in background tab into permission to simulate server downtime. Update preferences with partial patches so independent controls never reset each other.

For shared worlds, aggregate presence at the authority. A world with **Continue while unattended** enabled advances without a present player; otherwise it pauses only when every admitted player is disconnected or unfocused. Never let one player's local pause/focus setting stop a world while another player remains present. Keep disconnected-character exposure/removal separate from the world-clock decision.

## Persistence and migrations

Follow the [save/load design](save-and-load.md) when adding state or changing storage: document ownership, durable dependencies and reconstruction responsibilities in the subsystem design.

Implement `GameRepository` for storage changes; PostgreSQL and SQLite adapters already exist. Keep world CAS and domain receipts atomic, and paid-attempt admission durable before dispatch. Unknown external completion must not become permission to resend. A save adapter must preserve item identity, RNG, in-progress work, knowledge and all supported component versions. Under the [2026-09-21 active development policy](save-and-load.md#active-development-policy), incompatible changes require explicit refusal, not migrations or legacy fixtures. Bump `SAVE_FORMAT` in `apps/server/src/game-saves.ts` when saved interpretation changes incompatibly; new fields inside `SavedWorld` are serialized automatically. A new authoritative store must join the capture/install boundary. Do not silently reset saves.

Current adapters use transactional `WorldChanges` batches plus periodic snapshots and atomic PostgreSQL inner-world rows. Follow the [current persistence and public-update contract](architecture.md#state-and-transitions): keep returned domain snapshots immutable, mutate only through domain drafts/transitions, and preserve unchanged branch identities. Event append shortcuts require proof recorded by `finishWorld`/`updateWorld`; manually assembled arrays safely fall back to a diff. Keep importance-only experience edits distinct from prose changes: refresh derived retrieval metadata without forgetting dependent summaries. Backup/import must include all journal revisions. Public `GamePatch` types must be projected independently; never reuse private journal operations for transport. Further normalized persistence follows the [production data model](../archive/07-technical-architecture/production-data-model.md), with independently queryable canonical records and the [stable data/MCP interface](../archive/07-technical-architecture/data-queries-and-mcp.md). Build new database consumers against that contract rather than the snapshot JSON shape. The [delivery plan](../archive/07-technical-architecture/data-delivery-and-scale.md) specifies migration and retention; partitioning, physical sharding and specialized indexes follow measured workloads. Do not assume the bounded prototype journal can reconstruct missing history.

## Governance, discovery and workshop extensions

Read the [governance](../archive/03-design-proposals/invention-governance-and-ownership.md), [controls](../archive/03-design-proposals/playability-and-controls.md) and [world workshop](../archive/03-design-proposals/world-agent-and-workshop.md) contracts before building these future features. Keep invention authorship, account grants, world installation and character knowledge distinct. Every admission path must honor the current world policy; workshop edits require immutable versions and explicit activation/migration. A player's complete action catalogue and a god's authorized journal queries are different projections from a bounded NPC prompt. Do not widen the current public DTO to implement either.

## Visuals and assets

Preserve the scene's distinction between right-click (actions on release) and right drag (camera only), including the small movement threshold, pointer capture and cancellation cleanup. Native context-menu events can arrive before or after pointer release, so a camera gesture must not also open actions. Keep keyboard/Control-click access and test both event orders when changing these handlers.

`apps/client/src/scene.ts` projects the game onto PlayCanvas. `art.ts` creates original pixel textures/sprites from code; they can be replaced with licensed art without changing game rules. The camera, resource hit testing, readable DOM controls and scoped entity projection remain separate. Check the art-direction feedback before changing style. External reference pictures are inspiration, not granted production assets.

The initial focus-blur experiment is isolated in `vision-blur.ts`; it consumes projected screen geometry from the scene and never requests extra entities. `perception.ts` owns sight/hearing range rules, and the server projects the sight radius. Replacing the circular approximation with an occlusion field should change a scoped presentation/query contract, not grant the renderer world authority. Retained unseen images are visual history only: preserve frozen state, non-interactivity, bounded retention and removal/revalidation on return.

Object action menus must scope both available and unavailable candidates to the selected world object before preview; reserve personal work for self context and panel controls; empty ground offers walking. Keep right-click selection independent of panel navigation, and preserve the saved toggle across label changes. Map hit testing and hover must share the blur cutoff and revalidate stationary pointers as the scene changes.

## React components and traits

Extend the [production design system](../apps/client/src/design-system/README.md) and connected `apps/client/src/ui` components. Do not reintroduce imperative HTML panels or a competing palette. React Aria owns reusable control behavior; plain-text generated content never enters icon SVG markup. Use current public DTOs for inspection and facts, and retain private god endpoints for diagnostics. Any future quick-action cooldown ring needs an authoritative cooldown contract, separate from work progress.

Create people through `createActor` in domain data so they receive three saved, distinct traits. Edit `packages/domain/config/traits.json` for new starting dispositions; IDs must be unique with a name and description. Existing saves retain copied descriptions. Use `initializeActorTraits` only to fill missing legacy values, not to reroll an actor. Traits currently have no numerical or automated cognition effects.

To make another existing entity family placeable in god mode, add one finite entry and transition case in `god-tools.ts`, then project its label through `GameView.godTools`. Keep the client a chooser rather than an authority: the god endpoint must use a strict schema and the domain must recheck the type, walkability, occupancy and lifecycle rules. Update the icon mapping, searchable menu fixture and server/domain cases together. Generated definitions, arbitrary quantities and effects belong to the separately confirmed conjuring design and must not enter this native spawn catalogue implicitly.

For owner editor extensions, reuse `EditorPanel` and the right-hand `Pullout` component in `apps/client/src/ui`. Use bounded summary/hash lists, fetch raw JSON on selection, and send only changed records with optimistic hashes. Keep JSON drafts separate from lists; index and validate the full save batch before applying any mutation. Deleting actor evidence must call authoritative forgetting rather than filtering arrays. Identity, ownership, evidence links and mechanical fields are immutable through generic JSON editing; add a dedicated domain transition when one of those semantics must change. See [public updates and owner editors](architecture.md#public-updates-and-owner-editors) for the current behavior.

## Shared living actors and history

Extend `living.ts` body data and the common native effect mutation, rather than adding another species-specific health/death writer. Preserve body revision checks, actual effect provenance, finite yields per death and full god revival after harvesting. Gate cognition, memory and speech by their capabilities; `actor` existence alone must never schedule paid work.

Conversation changes belong to `conversations.ts`, and history/story projections commit through `HistoryRepository` within the world transaction. Never infer legacy membership or make membership an audience grant. Keep source edits, forgetting and source-dependent private narration consistent. See [current contracts](architecture.md#current-consuming-data-contracts).

## Story selection and owner editing

`packages/domain/src/story-selection.ts` owns the pure evaluator registry, bounded numeric field contract and `editStoryMechanism` mutation. New executable predicates require reviewed host code. New numeric declarations alone have no behavior. Keep the scheduler dependent on `StorySelection`, and keep cognition scoring independent. The canonical selection contract is in [Narration](narration-and-conversations.md#replaceable-story-selection).

In god mode, open **World Events → Story mechanism**, load the configuration, edit its JSON and save. The separate entity-change JSON is a bounded array, for example `[{"entityId":"hare-1","values":{"story_importance":9}}]`. Values replace that entity's active namespace; `null` removes it and restores declared defaults. Fields live in `entity.mechanismFields[policy.id]`. Actors include animals; objects include resources, remains and campfires. Inventory items and places have no encounter entity contract yet.

The same-origin owner routes are `/api/god/editor/story` and `/api/god/editor/story/save`; saves require the loaded policy revision, full policy, and at most 100 entity changes. Removing declarations requires removing their stored values in the same save. Invalid configuration or values reject the whole transition. No story fields are added to ordinary player DTOs. A version edit does not reset semantic introduction milestones. The trusted `silent_v1` evaluator provides a replacement that always selects silence.

A supported consequential rule example is `{"type":"body-effect","role":"target","fact":"healthDelta","maximum":-20,"significance":9}`. Rules may constrain a declared entity field with `field` and `minimum`; structured facts use `fact` and `maximum`. Supported event types are `body-effect`, `death` and `god-revived`; numeric facts are `healthDelta` and `injuryDelta` on body effects only. Explicit rules may select consequential events involving ordinary entities. Default rules are empty. This deliberately does not invent sacrifice, rescue, betrayal, arbitrary expressions or generated executable behavior.

## Performance boundaries

Follow [the runtime design](performance.md) and [implemented critical path](architecture.md#performance-critical-path). New actor creation and capability admission must initialize required identity/mind/cognition state in the domain transition; ordinary saves no longer repair actors. Preserve domain append proof when composing transitions; caller hints alone never authorize skipping history cleanup. New story producers must signal the existing repository only after commit and retain startup recovery. Optional database reads must not gate position/action publication, and asynchronous projection caches must reject superseded scopes. Never expose a world-global history counter as a player invalidation signal. The current timing endpoint is local-owner diagnostics, not a multiplayer metrics permission contract.

Evict hot events only with their untrimmed source projection in the same durable commit; omission from RAM is not deletion. Cold owner edits must include cold dependency references, and restore must preserve history coverage. Keep ordinary gameplay receipts atomic with effects and reject expired epochs before evaluation; never apply their expiry policy to paid/admin identities. New cognition inputs must invalidate actor tickets or supply a simulation-time deadline. Snapshot-index caches rely on the immutable domain contract and must not be reused across draft mutation.
