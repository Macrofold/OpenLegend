# Base-world time fidelity

[Simulation time](../../simulation-time.md) owns the engine interval contract. This document owns the bundled world's current fidelity choices; the numbers are not universal laws of authored realities. [PF13](../../maintainers/simulation-time.md#pf13--elapsed-time-simulation) owns delivery and qualification, and the [boundary catalogue](../../maintainers/simulation-boundaries.md) holds future exact bounds.

## Clock and fallback horizon

The base clock converts one real second to one game minute at normal speed. Speed selection scales elapsed game time, not a required count of native updates. The current finite family accepts intervals up to 60 game seconds, shortened by known mechanical deadlines or fidelity bounds. The host usually offers less time at each wake. Partial progress toward that interval boundary survives current-format save/load under the [native interval contract](../../simulation-time.md#native-interval-contract); restoration cannot restart the remaining sampling distance. The finite horizon remains 60 game seconds; the current experimental sensing bound is four metres, as described below. There is no mandatory one-game-second loop for idle scenes, and no 20 FPS render limit.

## Selected stealth reaction durations

**Selected target, not a delivered bodily-startle mechanism.** The [shared emotion/time contract](../../projects/stealth-awareness-tech-design.md#time-and-lifecycle) keeps this world's 60:1 normal clock. A provisional startle of **three normal-speed seconds** admits 180 simulation seconds once through the installed clock/effect owner:

| Runtime speed | Elapsed real time for an uninterrupted 180-simulation-second episode |
| ------------- | -------------------------------------------------------------------: |
| 1×            |                                                            3 seconds |
| 3×            |                                                             1 second |
| 8×            |                                                        0.375 seconds |

These conversions assume the simulation makes the corresponding progress; technical delay does not spend unadvanced game time. Pause freezes the remaining episode. A speed change affects subsequent clock advance without restarting or rescaling admitted progress. Restore resumes the same cause/life-bound episode and does not create a second onset. The selected G controls expose acceleration only through current creator/debug authority; their presence in local tooling gives an ordinary player no speed or inspection permission.

D specifies supported susceptibility, composition and recovery through the existing status/appraisal owners. Current fear/anger decay remains expressed per game hour; it is not silently converted into the new short reaction unit. Effective fear is a missing accuracy/evasion integration target, with no automatic running/fleeing speed reduction. The [shared tracker](../../maintainers/stealth-awareness.md) owns design and subsequent delivery; this section changes no installed durations, fidelity limits or runtime qualification.

## Everyday work durations

Fresh bundled worlds use these gathering and preparation times:

| Work                | Game seconds |
| ------------------- | -----------: |
| Gather plant fibers |          720 |
| Gather wood         |          840 |
| Gather stone        |          480 |
| Gather berries      |          600 |
| Prepare fibers      |          960 |
| Twist cord          |         1200 |

[Resource setup](../../../packages/domain/src/worlds/base/resources.ts) supplies gathering times for ordinary and custom openings, spawned patches and outer wilderness. [Item rules](../../../packages/domain/src/worlds/base/items.ts) supply fiber preparation and the shared native/invented-cordage cost. Menus and execution use those same rules or the selected patch’s stored duration.

The current October 17 pacing experiment doubles the previous tenfold durations, making them twenty times the former original defaults. At the requested 3× clock, gathering fibers takes four real seconds, and gathering fibers, preparing fibers and cord, gathering berries and eating takes about 19.33 real seconds, before approach, interruption or technical delay. The previous trial took two and 9.67 seconds respectively. Longer work reduces repeated completions, decisions and database writes; the same uninterrupted work now takes twice as long as the preceding trial, twenty times as long as the former original defaults. Material production per game hour falls and food/energy spent per output rises; travel and interruptions make the total ratio vary. Movement, perception, needs, health, yields and ingredient costs retain their separate rules. This is an authored pacing compromise, not a change to the clock or a full-game performance pass. [BW15](../../limits/base-world.md#bw15--everyday-work-pacing) and [PF16.66](../../maintainers/performance.md) retain its rationale and evidence.

Changing the shared cordage rule changes its trusted recipe-family digest. Older base-world manifests selecting the previous 600-second cordage rule or the original 60-second rule fail the existing exact dependency checks, including worlds without an invented cord recipe, and require a fresh current development world. Old compiled recipes are not retained through an adapter or silently recompiled. No existing database or save was reset here; all verification uses owned fresh worlds. Installed resource costs are never rewritten: a world whose selected families still match keeps its patches’ stored durations. Newly started native fiber/cord preparation uses the current shared rule.

## Spatial fidelity

**Experimental policy update — October 17, 2026, 15:12 EDT.** The maximum sensing step changes from one to four metres to reduce repeated simulation/publication work. The existing smaller nearby-sense bound remains. Brief sight/contact timing, follow/approach reconsideration and blocked landing retries can change; this is a deliberate fidelity compromise. Swept static geometry, route/support transitions and actual action admission retain their existing owners. Ordinary frightened-animal steering keeps its separate one-metre review deadline, and wandering remains a 0.4-metre impulse. Finite physical checks pass; a prediction-lifetime repair preserves checked sighting identities over 32 future publications, with a tiny initial stored-countdown difference still documented. The fifth and sixth complete observations average 2.982×/2.995× and fail smooth 3×; the sixth also includes Orin's hunger death after his scripted workload stopped. The driver can strand an idle resident after a busy exception; a guarded diagnostic recovery is now implemented and checked separately, without changing hunger rules or repeating the complete-game observation. Detailed qualification is tracked in the [execution plan](../../projects/performance-overhaul/execution.md#diagnostic-motion-fidelity-compromise--selected-october-17-2026-1504-edt); selecting this policy does not claim smooth 3×.

An active route, fleeing body or falling/flying creature normally limits an interval to at most four metres of travel. An available memory actor's smaller positive non-hearing sense radius tightens a mover's bound to one quarter of that radius only when their conservative reachable envelopes overlap during the shared interval. Both participants' maximum movement and body extents contribute; a distant tiny sense does not shorten unrelated travel. Movement retains its current static-geometry sweeps, waypoint and support checks. Occupied-body admission remains action-specific; ordinary walking does not gain a universal continuous moving-body collision guarantee. This bound limits the timing error of sampled visual/contact exposure. Flight/perch/fall/flee deadlines run as private motion slices with synchronized occurrence-time positions. A mid-air corridor turn with no wait or landing is private to the flyer: it continues along its next leg inside the same slice, each leg swept separately, and the four-metre bound applies to total path length. A flyer reaches an available landing exactly on arrival. A refused landing leaves the flyer where that slice began, and it retries after the same gap. An unavailable landing less than one game second away instead retries at that same sensing cadence: clearance by a departing body has no exact deadline, and a gap left by an unrelated boundary could shrink toward zero and stop the world. Such a landing can therefore occur up to one cadence after its spot clears. Landings on a route whose whole lap takes under one game second also use that cadence, so a degenerate route cannot land again at every tiny slice. A slice that only moves bodies leaves other entities' captured rates pending; they are applied through the same operators at the next shared boundary, command, prediction or publication, and before any work that ends in that slice. Deferral is world-wide, not per entity: while any serial-clamp fallback, active body-health rate or reservoir replenishment applies, every slice integrates all rates immediately. For predictable movers (flyers on their private path, walkers carrying out a `move` command and fleeing animals, including each way a sweep, landing or flee direction can fail), the exact times a sight or body-contact predicate can change are solved against the same geometry, and a slice that would jump over a whole visibility or contact interval, or a whole gap, ends inside it so the unchanged sampler records it. Falls and every other approach (to a target, resource or item) keep the sampled bound; intervals shorter than 10⁻⁹ game seconds are treated as floating-point tangency. A future high-speed actor must not silently justify either teleporting across obstacles or a claim that all observers were continuously evaluated.

Wandering currently makes non-emitting impulses of at most 0.4 metres on its own saved timer. The finite 60-second horizon is shorter than its repeat period; due impulses retain timer remainder and use deadline/identity order for random choices. If a smaller sensory bound requires it, that timer contributes an interval boundary. Crossing a narrow visibility opportunity during the impulse remains the declared exposure approximation. New wander emitters, larger impulses or shorter repeat periods must revise this integration rule before admission.

Ordinary wandering’s running timer is now an absolute game-time deadline where floating-point clock precision permits; paused timers retain a remaining wait. At very large clocks where `abs(simTime) × Number.EPSILON > TIME_EPSILON / 4`, an explicit running remaining-wait form preserves tiny delays that an absolute timestamp would round away. This is a current representation choice, not an older-format reader or a different wandering law. A derived due queue avoids sorting every animal at each endpoint; roster synchronization still visits current animals. Existing start-phase identity/interleaving and end-phase epsilon-rounded deadline/identity ordering retain which creature receives each saved random choice. No extra overdue hops or altered impulse frequency are introduced.

The [certified reuse contract](../../simulation-time.md#native-interval-contract) retains only already-covered, certain sight/contact paths across unrelated mechanical rebuilds. It changes no base-world range, sample height, horizon, displacement bound, linger window or event timing. Hover, wait, landing and wandering deadlines still constrain certainty through their existing movement owners; unsupported or changed paths recompute.

**Selected visual sampling law; not implemented:** [Vision and gaze](../../projects/vision-and-gaze-tech-design.md#9-actual-trajectories-and-bounded-temporal-sensing) uses fixed-epoch **0.05-normal-second** cells for affected dynamic scopes, actual native discontinuities and existing supported analytic narrow-window assistance. Completed support is held between due measurements; value measurement, actual acquisition and availability remain separate. Shared daylight coefficients use one-normal-second epoch samples. This is an explicit finite model: unsupported subcell flashes/gaps can be missed or held, and no general continuous optical proof or accumulated aliasing bound is promised. [VG05–VG07](../../maintainers/vision-and-gaze.md#vg05--as-visual-producer-and-bounded-temporal-sensing) owns original trajectory/control anchors, preparation and restore. The current four-metre bound remains the implemented displacement approximation and its nonvisual owners remain in force; it cannot substitute for the selected visual cadence. Capture, camera and publication add no samples.

## Physiology and effects

Food and energy boundaries come from the installed schema bounds, condition descriptions and predicates in the authored status definitions. Their behavior/rates remain owned by [survival](survival.md), the status-effect definitions and the attribute owners. The old fixed threshold list, including unused energy level 5, is removed. An interval stops at depletion or death before charging a subsequent period of starvation or exhaustion. Work beginning on arrival receives no pre-arrival duration.

A value changed by opposing status rates, or by a status rate alongside a reservoir drain, follows one projected net flow: it moves at the sum of those constant rates and stays at a schema bound while the sum points outward. This is the limit of the former serial clamps as their step shrinks; the serial version depended on how an interval happened to be divided, and a status outrunning a drain at the maximum shrank its own boundaries toward zero until native work stopped the world. A single rate, or several of one sign without a drain, keeps its exact serial clamp. Replenishment against a reservoir drain (a conserved transfer from a supply) and other serial-clamp cases keep the bounded one-game-second fallback until their transfer and priority laws are defined.

Current fidelity limits and their expansion triggers are catalogued in [NW12](../../limits/native-work.md#nw12).

## Named clock times

A request may name **dawn (06:00)** or **dusk (18:00)** as a stopping time, for example "follow her until dusk" or "wait until dawn". These names and hours are this world's choice, authored as `namedTimes` beside `clockOffsetHours` (day 1 starts at 08:00) in `worlds/base/config/status-effects.yaml`, the current authored home of the world clock. They are saved with the world and validated at load: at most eight names, each one or two lowercase words of up to 24 characters, with an hour from 0 to just under 24. A save without `namedTimes` is refused explicitly under the [development save policy](../../../AGENTS.md#development-save-policy).

Engine code never states these names. Deadline binding, request validation, the typed-request parser, AI instructions, capability descriptions, the AI's structured-output choices and the Character panel's "Stop at" options all read the saved world's list, so a world that names only "noon", or no times at all, works without code changes. A named time already reached today, including the current instant, means the next day's occurrence, so a stopping time is always in the future and at most one game day away; a name the world does not define is refused rather than guessed. Stored requests are checked for shape only when a save loads, so removing a name later never makes a save unloadable; such a request is refused when it is used, and the Character panel marks a no-longer-named choice as unavailable.

A follow or wait that ends at a named time is an exact interval boundary: elapsed-time integration stops at that instant instead of running the 60-second fallback horizon past it. Named times are a small clock vocabulary, not a general time-expression parser; "wait N minutes" is the only relative form. A separate clock policy is warranted when another clock consumer (calendar, seasons) appears.

Clock displays (the HUD clock, event times and God-tool time labels) read the world's `clockOffsetHours` from the view. Daylight is not yet a world setting: the renderer's daylight curve (06:00–18:00, in presentation code outside this project's file ownership) and the HUD's day/night icon (06:00–19:00) keep their own hours; making them read a world daylight policy is tracked in the [base-world tracker](../../maintainers/base-world.md).

## Review trigger

Revisit these bounds when fleeting encounters matter to a mechanic, new movement/sense ranges create excessive global interval splitting, an admitted operation has unknown within-interval changes, or mixed-load evidence identifies fallback work as a bottleneck. Keep the authored policy, its adapter, the catalogue and [RP06](../../maintainers/revisitable-policies.md#rp06--elapsed-time-fidelity-and-integration-limits) aligned. Changing fidelity is a visible behavioral decision; rendering performance alone cannot authorize it.
