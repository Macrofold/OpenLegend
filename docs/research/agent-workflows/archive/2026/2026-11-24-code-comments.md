**The sample has strong local rationale around ordering, cancellation, acceptance and resource ownership. No runtime defect or measured bottleneck is established by a missing comment.

## Research and its limits

These sources inform the guide; they do not establish a universal optimal comment length or measured improvement for Open Legend.

| Source                                                                                                                                                                                             | Finding, limits and implication                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Macke and Doyle, NAACL Findings, June 2024](https://aclanthology.org/2024.findings-naacl.66/)                                                                                                     | Incorrect documentation hurt test-generation-based understanding of Python functions. Removing correct comments did not significantly change test success, but comments improved coverage. Older models and small function tasks do not establish maintenance behavior. Prioritize factual accuracy, not blanket coverage.                                                                                                         |
| [Kang, Milliken and Yoo, June 2024](https://arxiv.org/html/2406.14836v1)                                                                                                                           | A manual study of 540 generated Java comments found factual errors even in the strongest evaluated model's output. This is not an error-rate estimate for today's agents. Review behavioral claims and do not invent historical intent.                                                                                                                                                                                            |
| [Pan et al., EMNLP Findings, October 2026](https://aclanthology.org/2026.findings-emnlp.916/)                                                                                                      | Correct solution information helped code generation; comment frequency and broad intent categories did not reliably predict success. Algorithm generation is distinct from maintaining source comments. Prefer relevant information over style or density rituals.                                                                                                                                                                 |
| [Roberto Aranda/OpenStation, October 13, 2026](https://openstation.blog/2026/10/13/i-deleted-168000-lines-of-comments-my-ai-agent-didnt-notice/)                                                   | Removing about 168,000 comment lines made little quality difference on two feature tasks, three repetitions per condition. One agent/project and partly model-scored outcomes limit generalization. The result questions the marginal value of those existing comments, not all rationale documentation.                                                                                                                           |
| [Alan Ho/Bookette, November 20, 2026](https://gist.github.com/elderengineer/5305264cbe94aa31b4626d8ecb982e59)                                                                                      | A self-published 90-run study across three modules found that removing comments reduced rationale recall and detection of cleanup-like regressions. Its favored compact policy detected 6/14 trap bugs versus 10/14 with existing comments; a rewrite also introduced an inaccurate claim. Small samples, one reader model and grading choices limit confidence. Preserve constraints without adopting its rigid placement policy. |
| [Gloaguen et al., AGENTS.md study, September 2026 revision](https://arxiv.org/html/2602.11988v3)                                                                                                   | Repository context files generally did not significantly improve task success and increased average inference cost by over 20%. This tests instructions, not inline comments, mostly on Python repositories. It supports narrow routes and proportionate obligations rather than assuming more context is free.                                                                                                                    |
| [Sohil Kshirsagar/Tusk, October 3, 2025](https://www.usetusk.ai/resources/the-case-for-comment-driven-development)                                                                                 | Firsthand experience describes lost rationale during refactors and ambiguous threshold wording. Useful motivation for exact conditions and same-change upkeep; not controlled evidence for productivity claims or universal verbosity.                                                                                                                                                                                             |
| [OpenAI harness-engineering account, February 11, 2026](https://openai.com/index/harness-engineering/)                                                                                             | Firsthand agent-first engineering experience favors a short entrypoint and discoverable, maintained repository knowledge. It does not isolate comment effects. Keep one guide with selective routing and optional research.                                                                                                                                                                                                        |
| [Rust API guidelines](https://rust-lang.github.io/api-guidelines/documentation.html) and [rustdoc item links](https://doc.rust-lang.org/rustdoc/write-documentation/linking-to-items-by-name.html) | Existing tools support contracts, failure/safety obligations and symbol references. The contrasting practitioner experiments are compatible: deleting redundant explanation may do little, while deleting non-obvious rationale can destroy constraints that code alone does not communicate. Neither experiment establishes a general token-saving percentage.

## Design decisions

- **Clear prose still matters for agents.** There is no strong evidence here for cryptic shorthand or a bespoke machine-only comment language. Reduce duplicated content and retrieval, not clarity.
- **Both contracts and rationale matter.** “Explain why” must not prohibit a short summary of effects that would otherwise require tracing a large implementation.
- **Keep essential facts local and deeper explanations linked.** Exact symbols/headings support discovery; bare links or manually maintained call graphs increase retrieval and drift.
- **Scope dependency review to changed assumptions.** Update affected callers, callees and contracts together, without requiring a full transitive review for every use.
- **Comments are claims, not enforcement.** Investigate disagreement with code, tests or accepted requirements. Types/API structure and existing checks help protect behavior; this guide does not authorize new tests or runtime changes.
- **Adopt selectively.** Preserve strong existing rationale. Backfill consequential entrypoints when authorized, rather than rewriting or shortening the repository wholesale. Evaluate correctness and total task reading/retrieval/correction cost; comment counts alone measure neither.
