# World Agent investigation and custom-value edits

This is the finite operation contract for `ol_trace`, `ol_entities` and the `attribute-values` draft kind. It specializes the [shared tool service](invention-workshop-tools.md), [relationship graph](invention-graph.md) and [composition/activation](invention-composition.md) contracts without replacing their authority. [Focused delivery](maintainers/world-agent-writes.md#navigation-and-custom-value-continuation) records implemented versus pending scope; [runtime evidence](verification/workshop-navigation.md) is separate from target semantics.

The same application descriptors and service functions drive local owner inspection and MCP. World-wide investigation is not NPC knowledge or a permission to mutate. The existing native Macrofold adapter selects implemented tool names from these descriptors. A new tool requires connector approval and fresh execution/session configuration under the current frozen tool policy; do not silently broaden old run grants or reset their retained charges. A new definition-kind adapter uses the existing draft/validation/review/Apply service, not a second registry or a direct database writer.

The owner interface offers definition versus live-entity search and a bounded relationship witness list. It fetches only on explicit interaction. A graphical canvas, port editing, live harness quality, all-domain dependency extraction and complete interaction proof are not implied.

## Bounded relationship traces

`ol_trace` complements direct `ol_graph` pages with bounded breadth-first investigation over the current definition projection. Inputs are an exact root, direction (`out`, `in`, or `both`), optional relationship filters and exact target, maximum depth, and maximum visited nodes. Defaults are depth 4 and 40 nodes; hard limits are depth 12, 100 nodes and 16 adjacency-page expansions. Each expansion inherits the existing 100-edge output and 1,024-entry scan bounds. A separate one-edge root lookup resolves the displayed root. No transitive index, global path enumeration, persistent worker or paid inference is introduced.

The result retains source-backed nodes and first-discovery witness edges, not all edges among those nodes. For a target, parent links return one shortest hop path in the selected directed projection. Original edge direction is preserved even during reverse traversal. Cycles are visited once rather than interpreted as invalid mechanics. Root-to-self resolves a zero-hop path. A discovered path is not evidence that every interaction has been examined.

`coverage.status` distinguishes `target-found`, bounded work, and complete reachability in the named projection/filter. Target status is `found`, `unresolved` while work remains, or `not-found-in-projection` only after exhausting the projected frontier. None is a safety/compatibility verdict: `impact` remains `not-evaluated`. At depth limits even an unexpanded apparent leaf remains conservatively unresolved. A no-match filtered page can have a continuation and cannot prove absence.

Return the index snapshot, work counters and frontier references/depths, including a direct-neighborhood cursor when a page is interrupted. If the node bound interrupts a page, its start cursor may repeat previously seen edges; it must never skip unexamined evidence. Callers continue with `ol_graph` using the same direction/filter and exact frontier reference, or start another bounded trace. This is explicit exploratory continuation, not a durable complete-closure certificate. A changed source rejects old cursors/references under the existing graph contract. Live arrangements and evidence still use their own direct readers; a definition trace does not scan every instance or private memory.

The owner relationship list uses this same operation and labels witnesses, limits and frontier records. This provides navigable evidence now without requiring a graph canvas, layout dependency, graph database or new authoritative registry. Full impact jobs, cross-domain extraction and visual port editing remain INV-15 work.

## Live entity discovery

`ol_entities` resolves world entities by name or ID, with optional exact entity-kind/controller filters. The caller's world inspection grant controls scope; names and controller labels are not authority. Return exact current inspection references, not raw body state. Inventory items retain the separate `ol_instances` path. This closes the discovery gap between inspecting a body and knowing its identifier; `ol_context` also exposes the currently controlled actor as a selection, not a control grant.

Pages return at most 50 records (default 20), scan at most 1,024 roster entries, and retain an explicit cursor even when a filtered page is empty. The reader caches a sorted roster for a frozen entity-map identity and admits at most 50,000 entries. It runs only on demand, not per tick. New map snapshots recompute the bounded roster signature; there is no assumption that one immutable map remains unchanged forever.

A cursor binds world generation, roster membership/names/kinds/controllers, and query/filter. Movement and reservoir drain do not invalidate membership paging. Each emitted reference identifies that entity's inspection projection at that page's read time; results do **not** promise a frozen live-world snapshot across pages. Renaming, adding/removing entities, changing controller or restoring the world requires restarting the listing. Detailed inspection still rejects an exact reference if its displayed facts subsequently change. No hidden current-world data becomes NPC knowledge through this administrative query.

Larger or frequently changing rosters may warrant a mutation-owner-maintained directory revision and index. Add it only after measuring actual request pressure; a small-world reader does not justify another database, per-tick scanner or eager all-pairs search. Extraction/read bounds and lack of full live-snapshot pinning are part of the returned coverage, not implicit capacity guarantees.

## Reviewed custom attribute values

The `attribute-values` kind is a separate **world-owner instance intervention** on already attached custom reservoir/category attributes. It is not a new mechanic, an ordinary character recharge, a source-transfer operation, or an NPC power. It cannot modify native health/needs, create bindings, remove attributes, change definition parameters, or write arbitrary fields. Source-free fictional quantity adjustment must be stated explicitly in the human review; never describe it as a resource-conserving action.

The strict payload is `{entityId, changes:[{attributeId, expectedRevision, value}]}`. It selects one body and one to sixteen distinct existing custom attributes. `expectedRevision` is a safe nonnegative integer, including zero for an initialized attribute. Values are finite numbers or bounded category strings; the native definition validator decides ranges/choices. Unknown fields, duplicate attributes and missing bindings are rejected. Discover the body through `ol_entities`, inspect its actual values/revisions through `ol_activity`, and inspect definitions with `ol_inspect`/`ol_schema`; the agent must not guess revisions.

Drafts pin the target identity and manifest. Human review names each old/new value and its units, explicit quantity creation/removal, and one affected body. The impact token includes selected current value revisions and values, rather than unrelated tick time. Approval and Apply revalidate the same pins. Reservoir drain, another editor or a status effect changing a selected value makes the old plan stale—even if its value later returns to the previous number. Unrelated attributes and clock changes do not grant authority to overwrite the selected values.

After a stale value, read the new evidence, submit an explicit revised payload with current revisions, validate and prepare another human review. The previous approval does not follow that revision. Pausing before a time-sensitive edit is a human action, never an implicit side effect of inspection. A model cannot reset the expected revision to bypass native comparison. Changing the selected body is a new reviewed revision through the existing draft machinery, not a silent retarget.

Apply invokes `editActorAttributes` using its existing atomic prevalidation, typed values, concern events and revision increments. No duplicate sparse-state writer, world registry, provider call or new gameplay save format is introduced. The existing permanent Apply receipt prevents repeated quantity adjustment and remains recoverable after operational projection failure. Subsequent native drain/replenishment uses the same installed reservoir law; an editor intervention does not invent a charger or confer knowledge.

This narrow adapter is reversible at the API/design level but its live consequences are ordinary committed world history. A later correction is another reviewed intervention, not erasure of observation, prior work or real charges. Sense/controller replacement, native-body redesign and many-body/law migration remain separate explicit adapters under their owning contracts.
