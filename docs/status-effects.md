# Declarative status effects

This document owns the finite status-effect runtime. Worlds author named mechanics as data; the runtime evaluates conditions, applies registered operations, and commits observable transitions. [Sleep and waking](worlds/base/sleep.md) owns the default world's restorative-rest content, not engine behavior.

## Configuration

`world.statusEffectPolicy` contains `revision`, `clockOffsetHours`, `namedTimes` (the world's [named stopping times](worlds/base/time.md#named-clock-times)) and an ordered `definitions` array. A definition has `type: "statusEffect"`, a unique `id`, `target: "$subject"`, `label`, `enabled`, `requires`, `reactivationDelaySeconds`, `occupiesAction`, `interruptOn`, and `whileActive`. Optional fields are `activationCondition`, `automaticActivation`, `automaticDeactivation`, `actions`, `presentation`, `onActivate`, `onDeactivate`, and `lifecycleCause` (bounded cause text for a configured body-health change). The TypeScript schema is in [status-effects.ts](../packages/domain/src/status-effects.ts); authored defaults live in [status-effects.yaml](../packages/domain/src/worlds/base/config/status-effects.yaml). `pnpm config:generate` parses YAML and validates it against the default world registry before producing the checked-in `status-effects.generated.json`. Dev/start/build regenerate it; `pnpm config:check` rejects drift. The domain imports only generated data, with no YAML parser or file I/O. Edit the YAML rather than generated JSON. Existing saved policies remain authoritative and are updated through policy admission, never overwritten at startup.

Conditions compose nonempty `all`/`any` groups. A `compare` names a target, registered numeric attribute, operator (`equal`, `notEqual`, `lessThan`, `lessThanOrEqual`, `greaterThanOrEqual`) and value in that attribute's units. Optional `unit: "fractionOfRange"` instead expresses the comparison value as a fraction of that target's actual range, including its body-specific maximum Health. A `field` comparison names a target and one supported host property: controller, alive, incapacitated, grounded, activeWork, or kind. `activeWork` means an action, airborne movement or native fleeing. `dailyWindow` names `$world`, `localTime`, and start/end hours in game time, including windows across midnight. `statusActive` names another definition and an entity target. `hasAttribute: {target, attribute}` requires an installed definition and tests whether that bound entity has an applicable known value; an optional absent value is false. It never attaches a value or broadens disclosure. Binding/definition changes invalidate its result, and it contributes no time crossing. There is no expression-string evaluator, JavaScript or cron parser.

`requires` determines applicability; loss of applicability ends an active instance. `activationCondition` applies to both explicit and automatic activation. `automaticActivation` is an additional condition for simulation-driven activation; omission means explicit activation only. `automaticDeactivation` ends an instance on a matching condition. Explicit activation ignores the automatic reactivation delay.

`whileActive` supports:

- `changeRate`: explicit entity `target`, registered `attribute`, signed `amount`, and `per: "gameSecond"`. An optional `when` condition gates this operation. Values clamp to the registered numeric range, and writes use the attribute's authoritative owner.
- `changeEvery`: explicit entity `target`, registered `attribute`, signed `amount`, positive `everyGameSeconds`, and `unit: "attribute" | "fractionOfRange"`. The latter scales the amount by the target's actual numeric range. Optional `when` uses the shared interval-start condition. Each hit occurs at an elapsed-time multiple after a full first interval; ending and reactivating starts a new cadence. Pauses and same-format restoration preserve elapsed progress without replay. Whole-point health must use this operation instead of `changeRate`, avoiding changes that depend on simulation slice size.
- `restrictCapabilities`: explicit `$subject` target and any of `actions`, `locomotion`, `speech`, and `perception`. This v1 operation restricts the receiving entity; effects on another entity's capabilities require a separately admitted instance on that entity.

Awake resource expenditure can be a separate definition with conditional negative rates; it is not implicit behavior of the runtime. Dream eligibility belongs to cognition policy, which names an effect definition and an elapsed-time minimum. It is not a status-effect operation.

## Targets and attributes

An instance belongs to an **entity**, not an actor component. `$subject` is that entity; `$source` and `$actionTarget` are explicit entity IDs bound when the instance is admitted. Automatic activation binds all three to the receiving entity. Manual command admission binds the source to the acting entity and the action target to the selected subject. Trusted domain compositions may bind a different action target, allowing an effect attached to one object to change another object's value. Those bindings are saved, not dynamically selected every tick. There is no global entity query or arbitrary object-path writer.

Attribute IDs resolve through the existing world-module registry. Actors retain their existing attribute/native-value owners. Non-actors may carry sparse registered passive-number/reservoir/category state on `entity.attributes`; native body attributes cannot be installed on objects. Missing attributes or unresolved targets are inapplicable, including for inequality; missing is never zero. Numeric targets must be available at activation and while active. Current writable adapters support passive numeric meters, reservoirs and one body-backed numeric health representation. Its required `nativeHealth` metadata selects `units: "points" | "proportional"` and `precision: "whole-points" | "continuous"`. Points use zero through the actual body's maximum; proportional units map that body range into the authored schema. Whole-point writes round each nonzero delta to the nearest magnitude with minimum one, then clamp. Continuous health rates accumulate per target before body reconciliation; periodic hits remain separately recorded. Health changes follow the installed meter's disclosure and exact committed amounts, retaining death/incapacity, action cancellation, remains, condition and body-revision effects. Passive health changes create no combat injury experience or injury wakeup. Ordinary body-effect commands retain their injury semantics.

This is a finite v1 family, not an arbitrary effect language. Extend the operation owner when a concrete mechanic needs another trusted operation; do not add parallel values or interpret new fields implicitly. Broad authoring of object attributes, arbitrary target selection, persistent area effects, arbitrary stacking priorities and generalized resource conversion are not implemented.

### Independent capability contributions

A non-occupying definition containing only capability restrictions may opt into
`contribution: { disclosure, lifetime }`. Disclosure is `owner` or `public`; lifetime
is `explicit-removal`, `source-sustained`, or `fixed` with positive `seconds`.
Automatic activation is unsupported for this branch. Existing native statuses retain
their singleton and ordered-rate behavior.

Each contribution uses its episode as its saved instance key and retains its source,
target, exact definition digest, revision and lifetime. Ordinary status commands bind
the source to their admitted actor. Their deactivate action removes that source's
contribution, leaving other sources active. Explicit domain attach/refresh/end ports
retain request receipts; refresh cannot resurrect an ended episode or change its
lifetime family. Ending a contribution never restores an old body snapshot.

Capability queries read all active contributions plus the native status. Owner
projections show repeated sources as a count; public projections omit owner-only
definitions and never include source bindings. Fixed deadlines use simulation time.
Source-sustained instances stop applying immediately when their source disappears, dies,
retires or belongs to an inactive containment root; the native phase finalizes the state.
Whole-object movement preserves source identity; live incoming source references prevent
split/merge from silently changing it. Existing native
requirements and interruption rules also apply. Definition replacement/removal is
rejected while retained contributions need the old exact definition; unsupported
live migration is not silently performed.

After commit, terminal independent instances leave the hot world but remain in
`sim_status_effects`. Native singleton cooldown records remain resident. Active reload,
full save capture and explicit policy maintenance use the same canonical records, with
durable ordering across partial maps. Caller-supplied new identities require complete
history; an exact retained command receipt still replays without resurrection. Native
commands allocate fresh monotonic episode IDs. Policy maintenance materializes history
before validating exact pins, including ended contributions.

## Transitions

`activateStatusEffect`, `deactivateStatusEffect` and `interruptStatusEffects` are the shared mutation boundary. A saved instance contains an active flag, episode ID, elapsed seconds, automatic reactivation deadline and source/target IDs. An occupying actor effect interrupts previous work without refunding consumed inputs, creates one ongoing action tied to its episode, and completes or interrupts the associated plan through the existing owner. Non-occupying effects also work on objects. An occupying effect requires an actor because native plans/actions are currently actor-owned.

Elapsed-time integration reconciles start-boundary activation/deactivation in saved entity/definition order, prepares all rate predicates against that shared starting state, integrates the interval, then reconciles endpoint completion. Effects or work starting at the endpoint receive none of the preceding interval. A completed restoring effect cannot also charge an opposing expenditure effect retroactively. There is no unbounded condition fixed-point loop. Non-health active rates retain definition order and native bounds and never emit per-interval numeric-change notices; simultaneous health rates reconcile at the body-before-action phase for each target. Health causes accumulate with nonzero rates in the same invocation-local flow, then deduplicate and sort; each target no longer rescans every captured interval. All captured status accounting is charged before a rate can end its body, and ended episodes cannot recreate work allocations. Conserved transfers remain with their existing owner. [Simulation time](simulation-time.md#native-interval-contract) owns interval prediction and fidelity.

The runtime prepares deeply immutable condition trees once into the existing handwritten operator functions, weakly keyed by condition identity. This caches interpretation, **not condition results**: entity bindings, attributes, status flags, simulation time and clock offset are read on every invocation. Saved condition order and short-circuit behavior remain unchanged. Mutable or shallow-frozen authoring trees are prepared anew, so edits cannot reuse stale captured fields. No generated source, `eval`, alternate effect engine or mutable entity ownership is introduced. Performance qualification belongs to [PF03](maintainers/performance.md#pf03--native-cpu-and-incremental-admission), coordinated with [HE05](maintainers/hearing-and-speech.md#he05--runtime-and-performance-qualification).

Host interruption reasons, such as injury, recovery, voluntary cancellation or a new action, are matched against the authored `interruptOn` list. Body unavailability always clears active instances: a dead/incapacitated actor cannot retain an occupied native action. This cleanup suppresses deactivation narration because the lifecycle owner emits the truthful event. Invalidated rate targets end the instance rather than redirecting effects to another entity.

`onActivate` and `onDeactivate` optionally emit a `stateChanged` event with an explicit target and narration template. The supported bindings are `subject`, `source` and `actionTarget`, using the shared [name-template grammar](entity-names.md#authored-narration-templates): bare `.name` or an explicit `:indefinite`/`:definite` article. World-authored templates choose the wording; the engine does not infer a mechanic from a name. Committed events use the existing observation audience, experience and conversation boundaries. They are narration, never speech or accepted model responses. Temporary perception restriction does not itself declare a participant physically out of conversation range; ordinary distance/inactivity rules still apply.

## Native participation

Each native continuation prepares a conservative participant roster through `mayAdvanceStatusEffects`; this is not permission to skip a condition that might become true. Every active instance remains eligible for processing, including one whose definition was disabled and must now deactivate. A potential automatic instance requires an enabled automatic definition, an actor when it occupies actor work, and available numeric rate attributes. Its automatic bindings all refer to its subject. Current rate operations cannot create a missing actor component or attribute, which is why these absence checks are safe.

The roster is refreshed after nested command transitions that may change participants. Any future operation that creates capabilities or attributes must extend this participation contract before using the same pruning. Frozen entity/definition/manifest identities support eligibility reuse; mutable input takes the uncached path. Threshold, clock and other live activation/deactivation conditions still execute at the applicable elapsed-time boundary. Predicate preparation and roster pruning do not change saved rates, elapsed-time updates, event ordering or effect mutation ownership.

## Capabilities and presentation

Command admission checks the relevant restrictions. A subject may explicitly deactivate its own active effect or cancel even while general actions are restricted. Physical interaction with another entity must be authorized by the definition and pass the existing visibility/reach check. The shared server action builder supplies authored labels to player menus and NPC candidates; `actions` declares activation/deactivation labels, optional `activateIcon`/`deactivateIcon` symbolic client-catalogue names, plus `allowOther` and `activateOther`. Quick actions, entity actions and the full catalogue retain the exact selected operation's icon, with a generic state-change icon when none is authored; the client does not map a status ID or its English label to sleep/wake behavior. An effect can therefore permit waking another actor without permitting forcing that actor into the state.

Movement/ambient locomotion, speech admission and sensory queries consume generic capability restrictions. A pending conversational/decision run is canceled when speech becomes unavailable; final speech admission independently rechecks it. Player action jobs use the action-capability restriction instead, so speech-only loss does not cancel nonverbal movement. An already-committed response remains accepted even if its own action activates a restriction. Cancellation does not invent a narration event.

Public projections contain only permitted active labels and presentation data. Internal bindings and object attributes are stripped from general observations. `presentation.pose: "horizontal"` changes the billboard pose, not the physical body. The supported particle configuration names text, `anchor: "head"`, and `motion: "floatAway"`; reusable DOM markers animate without an accumulating particle queue. Markers disappear with the effect or observation, respect floor visibility, freeze on pause and remain static under reduced motion. The renderer knows no named mechanic.

## Admission and persistence

The creator-only `POST /api/god/status-effects` accepts `{}` to inspect the registry, or `{policy, expectedRevision}` for non-removal replacement. Omitted installed definitions return `review-required` with a route to World Agent removal review; this endpoint cannot bypass exact human review. Ordinary replacement preserves the existing paused-world refusal. Admission validates every operator, field, attribute and definition reference before committing. It rejects stale revisions and unknown fields, and removal of an effect still required by installed body or cognition policy. An explicitly null dream policy has no effect dependency. Changed/removed native singleton definitions deactivate their existing instances under the old definition before replacement; unchanged definitions retain their episodes. Retained independent contributions instead require their exact old definition and reject unsupported replacement/removal.

### Reviewed condition removal

A creator can choose **Review removal** while inspecting an installed condition or working on a status-policy candidate. The server starts from exact installed roots, follows every native `statusActive` predicate backwards to include required dependent definitions, and retains one readable witness and field path per inclusion. True and false predicates both establish structural dependencies; mutual references terminate through a visited set. A retained condition referenced by a required removal is an optional supporting condition, kept by default. Selecting it adds a root and recomputes required dependents; required inclusions cannot be unchecked. Unchecking one optional choice keeps it required when another selected condition still depends on it. The deletion-only candidate preserves all other definition content/order, named times and clock settings. Whole-policy candidates receive the same removal analysis, but expressly authored mixed edits must resolve dangling references themselves.

The exact saved review distinguishes definitions and ordinary condition records to remove, active episodes and occupied activities to end, and blockers. It includes inactive cooldown records and non-actor objects. Body conditions, the dreaming reference and exact retained independent contribution pins block removal instead of being silently edited. Complete condition history is materialized through the existing indexed storage owner before preparation, exact native-check reads and revision comparison, and again before new Apply. Comparison shares one preparation across both revisions; unrelated memories, appraisals and object history are not loaded. An omitted retired physical owner retaining a condition makes coverage incomplete and blocks the edit. Counts cover the complete retained plan, while pages show its sections under current permission. Hidden ordinary effects prevent approval; protected contribution pins return a permitted generic blocker without exposing their owners. Disclosure checks each affected subject, source and action target through its current containment/attachment ancestors, so an object inside another human’s inventory cannot bypass that human’s private boundary. Strict current inspection still refuses absent/retired subjects; retained effects may keep historical references, with resident or cold retirement custody checked without inventing a live placement. Missing referenced objects use one request-scoped, batched exact canonical custody read; only proved canonical absence permits a genuinely absent historical reference. Unavailable preparation refuses disclosure, and current scope, timeline and live ancestry are checked after the read before returning any detail.

Optional-choice revisions create a new exact candidate and invalidate earlier approval. Apply rechecks dependencies, ordinary episode/source/target/action membership, retained pins, current authority and timeline through one native policy admission. Elapsed time or an unrelated meter change alone does not invalidate unchanged effects. Real endings use old definitions, release only their actual work and preserve unrelated effects, previously changed quantities, completed actions, events and memories. The existing world commit includes the permanent operation receipt; replay returns that receipt rather than repeating removal. Current authority still permits recovery of that historical receipt after gameplay load, even when the operational completion acknowledgement was lost; recovery leaves restored definitions and instances unchanged. Gameplay load creates a new timeline and cannot reuse an earlier approval to remove restored definitions. [Batch 09](maintainers/parallel-batch-09-reviewed-content-removal.md) retains full acceptance, [CE01](limits/creator-edits.md) owns capacity restrictions, and [current evidence](verification/reviewed-content-removal.md) distinguishes implementation from completed qualification.

#### Installed world rules and removal integrity

The installed world supplies condition IDs, labels, predicates, ongoing effects, ending narration, clock offset and named stopping times. Removal uses those exact definitions and copies surviving content; it has no special protected-ID list for bundled Sleeping, Energy expenditure or Exhaustion. Body/dreaming dependencies block only when the currently installed policies reference the selected definitions. Changing those policies is a separate admitted operation, not an implicit deletion repair.

The finite native family owns typed reference validity, exact contribution pins, episode/work consistency and ending execution. The application owns creator/private-human permission, exact human approval, bounded retained detail, atomic publication and identical-result recovery. These integrity and access requirements cannot be waived by fictional world rules or by merely displaying a relationship. Scope includes ordinary conditions on supported non-actor objects; it does not grant arbitrary family retirement. Native living-body/contained-processing limitations remain with their existing EWF owners.

The [reviewed World Agent write path](world-agent-runtime.md#durable-write-sessions) already uses the supported status-policy adapter, exact draft approval and Apply receipts. A direct settings form is a separate interface extension. General non-actor attribute authoring is not supplied by the existing actor-body binding/value adapters.

Validation bounds each definition to 32 operations and each condition to 128 nodes/depth 12.
Combined installation and invocation admission use versioned work vectors and current
actor/module/world/host limits, rather than an arbitrary definition-count cap. Installed body-policy conditions and service-array lookups join those budgets; optional command services are not represented as continuous writes. Required
native query/effect work is charged without truncating audiences or silently skipping
effects. Runtime work follows physical roots and active operations; terminal independent
history is queried only through explicit maintenance/capture paths.

Policy, instances, elapsed time and bindings serialize with the world. Periodic progress must still represent a finite next deadline; validation refuses exhausted or unrepresentable saved progress. Current-state validation checks definition/instance/action integrity, exact installed attribute/body-policy dependencies, raw body health and sparse ownership. Removed native meter aliases are incompatible. New-world creation supplies its explicit authored composition; reading or reopening a save never attaches missing meters or installs missing defaults. Runtime admission refuses incompatible formats and live markers without conversion or regeneration. Agent handling of incompatible development data follows the [root policy](../AGENTS.md#development-save-policy). Same-format save/load preserves episode identities, elapsed time, revisions and work progress. Pauses and ordinary save/load do not replay wall-clock time.
