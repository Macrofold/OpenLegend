# Worlds, authoring and invention

[Glossary index](README.md) · [What a character learns from experience](actions-and-learning.md#what-experience-can-teach)

## What a world supplies

| Canonical term           | Meaning in OpenLegend                                                                                                                                                                                                                                                       | Source                                                                                                                                                      |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Engine                   | The shared machinery that runs worlds. It enforces permissions, orders changes and saves their results. Whether people get hungry, which actions feed them and what those actions are called belong to the selected world.                                                  | [Engine and world responsibilities](../engine-and-world-boundaries.md#2-four-logical-layers)                                                                |
| Authored reality (world) | The fictional world an author defines, including what can exist, the rules it follows and how play can begin. Starting that world creates a running world with its own history.                                                                                             | [What OpenLegend runs](../engine-and-world-boundaries.md#1-the-product-being-built)                                                                         |
| Running world            | One live instance of an authored world, with its own current state and history. Two instances can start with identical definitions and later contain different people and possessions.                                                                                      | [Starting a world](../projects/world-creation-feature-spec.md#45-review-the-release-and-start)                                                              |
| Base world               | The playable wilderness world bundled with OpenLegend. Its rules and vocabulary come from the base-world definitions, including when Rust runs them. **Main world** is one starting choice for this world.                                                                  | [Bundled world and its code](../worlds/base/README.md#code-boundary), [Main world](../worlds/base/playable-openings.md#main-world)                          |
| World rule (world law)   | A rule the author chooses for what can happen in the fiction, such as how starvation affects health. The host separately enforces spending limits and account permissions.                                                                                                  | [Fictional rules and protected constraints](../engine-and-world-boundaries.md#4-what-must-remain-protected)                                                 |
| World policy             | The world's selection among supported rules or parameters, such as which bodies can return after death. Name whose policy it is when host limits or access policy are also involved.                                                                                        | [Choosing the owner](../engine-and-world-boundaries.md#5-a-repeatable-boundary-decision), [Base-world death policy](../worlds/base/player-death.md)         |
| World module             | A group of definitions or policies and their declared dependencies. A **pack** is a possible unit of distribution with its own rights. External world-package loading remains a future capability.                                                                          | [World module](../engine-and-world-boundaries.md#2-four-logical-layers), [Package boundary](../worlds/base/README.md#code-boundary)                         |
| Installed definition     | An exact description or rule admitted for use in this world. An item definition can describe a sling even when nobody owns one or knows the recipe. Creating a sling, learning the recipe and installing the definition are separate changes.                               | [Current recipe-family implementation](../invention-foundation.md#current-recipe-family-slice)                                                              |
| World module manifest    | The saved record of the world’s selected module definitions, policies and exact [definition pins](identity-and-references.md#what-a-name-or-id-identifies). It identifies, for example, which body policy the world uses. A character’s current health is saved separately. | [Manifest and definition pins](../../packages/domain/src/world-modules.ts), [World rules and bindings](../world-constitution.md#1-what-the-constitution-is) |
| World constitution       | In the governance design, the resolved view of a world's governing rules, installed definitions and approval policies. Individual records and grants remain authoritative. A character can only learn the parts available to them.                                          | [World constitution](../world-constitution.md#1-what-the-constitution-is)                                                                                   |
| Supported family         | A kind of behavior for which the host already has a trusted implementation. An authored or generated definition can select its allowed inputs and effects. Naming a new effect in a description does not make that effect executable.                                       | [Adding a family](../extending.md#a-new-invented-family), [Base-world recipe families](../worlds/base/invention-families.md#supported-families)             |
| G0                       | Extension level for expression using existing capabilities. A character can say they intend to light a fire or propose a plan using the current fire rule.                                                                                                                  | [Extension levels](../engine-and-world-boundaries.md#9-a-ladder-of-power-not-a-new-taxonomy)                                                                |
| G1                       | Extension level for configuring or composing supported behavior through typed definitions. An author could add a new recipe using materials and effects the engine already supports.                                                                                        | [Extension levels](../engine-and-world-boundaries.md#9-a-ladder-of-power-not-a-new-taxonomy)                                                                |
| G2                       | Extension level for introducing a new bounded algorithm. Running such an algorithm requires an isolated execution interface that has been implemented and qualified for it.                                                                                                 | [Extension levels](../engine-and-world-boundaries.md#9-a-ladder-of-power-not-a-new-taxonomy)                                                                |
| G3                       | Extension level for a change to the host software itself, such as adding a new spatial operation, privilege or way of interpreting stored data.                                                                                                                             | [Extension levels](../engine-and-world-boundaries.md#9-a-ladder-of-power-not-a-new-taxonomy)                                                                |

## Creating or changing a world

| Canonical term           | Meaning in OpenLegend                                                                                                                                                                                                                               | Source                                                                                                                                                        |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| World creator            | The person using authorized tools to define or change a world. Creating its fiction gives no claim on another account, player's private information or real-money allowance. A host operator separately controls the service.                       | [Creator and host boundaries](../projects/world-creation-feature-spec.md#2-boundaries-inherited-from-the-project)                                             |
| World Agent              | The out-of-world assistant that inspects or prepares changes for an authorized user. Its tools act within that user's grants. An NPC making a decision in the world must use that character's permitted evidence.                                   | [World Agent and inhabitants](../world-agent-runtime.md#2-world-agent-versus-inhabitants)                                                                     |
| Premise                  | What the creator wants to be true about the world or the experience. A proposal translates it into available rules and circumstances and identifies essentials that the host cannot yet deliver.                                                    | [Describing a world](../projects/world-creation-feature-spec.md#41-describe-the-world)                                                                        |
| Opening                  | The initial situation when play starts, including the participants, locations, supplies, knowledge and opportunities supplied by the world. **Main world** and **Solo testing ground** are named starting choices for the base world.               | [Playable starting worlds](../worlds/base/playable-openings.md), [Fresh construction](../worlds/base/playable-openings.md#fresh-construction)                 |
| World creation candidate | The proposed starting world under review. Its creation profile determines which contents the host can build and how to check them. A preview shows what the candidate contains. Starting the world uses the approved candidate.                     | [Creation types](../../packages/domain/src/world-creation.ts), [Review and start](../projects/world-creation-feature-spec.md#45-review-the-release-and-start) |
| Opening readiness        | Whether a proposed opening supplies what players need for its promised first activity, such as accessible ingredients and a reachable destination. The creation profile specifies which checks establish readiness.                                 | [Opening readiness](../projects/world-creation-feature-spec.md#6-readiness-means-support-for-the-selected-experience)                                         |
| Read (authoring)         | Permission to inspect particular world or authoring facts. A World Agent can inspect only the facts its session is allowed to see.                                                                                                                  | [Authoring powers](../invention-workshop-tools.md#2-read-prepare-and-apply-are-separate-powers)                                                               |
| Prepare (authoring)      | Permission to produce a change for review, such as a draft recipe. The proposed change remains separate from the live world.                                                                                                                        | [Authoring powers](../invention-workshop-tools.md#2-read-prepare-and-apply-are-separate-powers)                                                               |
| Apply (authoring)        | Permission to make an exact reviewed change take effect under current rules. An earlier successful inspection or preparation grants no right to apply it.                                                                                           | [Authoring powers](../invention-workshop-tools.md#2-read-prepare-and-apply-are-separate-powers)                                                               |
| World-owner freeze       | In the governance design, an owner’s restriction on replacing, removing or rebinding specified installed rules. Changing the protected rules requires an explicit authorized unfreeze or change. Ordinary uses permitted by the rules can continue. | [World governance controls](../world-constitution.md#4-stability-is-several-independent-controls)                                                             |
| Author refinement lock   | In the governance design, protection against unsolicited redesign or automatic replacement of the author’s selected candidate or appearance. The candidate still needs its required checks.                                                         | [World governance controls](../world-constitution.md#4-stability-is-several-independent-controls)                                                             |
| Runtime quarantine       | In the governance design, a restriction that stops unsafe execution or publication within the affected scope. A quarantined definition can still be frozen, inspected and retained for recovery.                                                    | [World governance controls](../world-constitution.md#4-stability-is-several-independent-controls)                                                             |

## Invention, making and learning

| Canonical term      | Meaning in OpenLegend                                                                                                                                                                                                                        | Source                                                                                                                                                                                    |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Invention           | Developing a reusable definition or method through supported mechanisms. The current recipe path can produce an admitted recipe and item definition. Ordinary crafting uses an existing method to produce physical items.                    | [Current invention path](../invention-foundation.md#current-recipe-family-slice), [Using versus inventing](../repertoire-foundation.md#2-one-route-for-use-another-for-definition-change) |
| Invention project   | The durable record for a creative objective, with the work and revisions that belong to it. A chat is a way to work on the project. A funding session records separately authorized spending.                                                | [Project and revision identities](../invention-foundation.md#4-the-invention-project-and-its-identities)                                                                                  |
| Draft revision      | An editable snapshot of a proposed invention, based on a particular earlier revision. It can record intended behavior, appearance, constraints, references and unresolved choices.                                                           | [Draft and candidate records](../invention-foundation.md#4-the-invention-project-and-its-identities)                                                                                      |
| Submitted candidate | The exact, immutable version of a proposal submitted for checks or review. A later edit presents a different candidate.                                                                                                                      | [Draft and candidate records](../invention-foundation.md#4-the-invention-project-and-its-identities)                                                                                      |
| Recipe family       | A supported construction rule with roles for inputs and a trusted compiler for the result. For example, a sling family decides which materials can serve each role. A recipe is one concrete use of the family.                              | [Supported base-world families](../worlds/base/invention-families.md#supported-families), [Compiler and admission](../invention-foundation.md#current-recipe-family-slice)                |
| Recipe candidate    | A proposed recipe with ingredients, quantities, family parameters and wording. The code calls it a `RecipeCandidate`. A proposal alone gives a character neither the recipe nor an item.                                                     | [Recipe records](../../packages/domain/src/types.ts), [Admission](../invention-foundation.md#current-recipe-family-slice)                                                                 |
| Recipe definition   | The admitted description of what the recipe consumes, how much work it requires and what it can produce. The code calls it a `RecipeDefinition`.                                                                                             | [Recipe records](../../packages/domain/src/types.ts), [Admission](../invention-foundation.md#current-recipe-family-slice)                                                                 |
| Production method   | An installed method for making a particular item. A character can learn it by inspecting a suitable physical record. Knowing it lets the character attempt the work when they have the required ingredients, access and other prerequisites. | [Learning a recipe](../knowledge.md#physical-production-method-records)                                                                                                                   |
| Provenance          | The origin and supporting history of a particular result. A definition supplied by the world and the same method discovered by a character can have different origins. Neither origin gives every character knowledge of the method.         | [Authored and invented methods](../invention-foundation.md#current-recipe-family-slice)                                                                                                   |
| Repertoire          | A curated catalogue of gameplay possibilities and worked examples used to choose features worth building. A repertoire entry can remain an idea. Use **installed capability** for something a particular world actually supports.            | [Repertoire catalogues](../repertoires/README.md)                                                                                                                                         |

## Composing and validating mechanics

| Canonical term                       | Meaning in OpenLegend                                                                                                                                                                                                                                                               | Source                                                                                                                                                                   |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Mechanic                             | A rule or process that determines what the simulation does, such as a rule for how much rain passes through a roof.                                                                                                                                                                 | [Meaning of a declaration](../../archive/07-technical-architecture/declarations-and-evolution.md#what-a-declaration-means)                                               |
| Declaration                          | A versioned, structured description the simulation understands, such as a material profile or recipe. Calling a material “waterproof” in ordinary prose cannot install that behavior.                                                                                               | [Meaning of a declaration](../../archive/07-technical-architecture/declarations-and-evolution.md#what-a-declaration-means)                                               |
| Capability (composition)             | An operation the host supports and an author can use in a compatible definition, subject to permission. A method can combine several capabilities.                                                                                                                                  | [Registered capabilities](../action-capabilities.md#4-one-capability-registry-several-views), [Composition contract](../invention-composition.md#3-composition-contract) |
| Composition contract                 | The requirements and promises for combining a supported operation with other parts of a definition. These include its accepted inputs, permitted reads and effects, and possible results on success or failure.                                                                     | [Composition contract](../invention-composition.md#3-composition-contract), [Registered capabilities](../action-capabilities.md#4-one-capability-registry-several-views) |
| Port (composition)                   | A named connection that specifies what a reusable definition accepts or produces, such as a quantity of material with particular properties.                                                                                                                                        | [Ports and binding phases](../invention-composition.md#3-composition-contract)                                                                                           |
| Port binding                         | An assignment that supplies what a named connection requires. Its contract states when the assignment is allowed, such as when the definition is installed or when an action starts. A saved template can have empty ports. Execution requires all mandatory bindings.              | [Ports and binding phases](../invention-composition.md#3-composition-contract)                                                                                           |
| Dependency                           | Something the meaning or validity of a definition relies on, such as the exact family used to compile a recipe. A change to that dependency can require a new check. Past authorship, a similar name and an optional design idea are different relationships.                       | [Dependency and impact](../invention-validation.md#4-dependency-graph-and-impact-analysis)                                                                               |
| Relationship graph (invention graph) | An inspectable view of how definitions, instances and evidence relate. For example, it can tell a creator which recipes depend on a material. A recipe describes how to make something. Editing a picture of the graph cannot install a recipe or transfer an object.               | [Graph authority](../invention-graph.md#1-purpose-and-authority), [Kinds of relationships](../invention-graph.md#3-relationship-vocabulary)                              |
| Validation finding                   | A result about a specific candidate, requirement and body of evidence. For example, a recipe may have compatible inputs but lack a required appearance. An unfinished check remains unknown. A validation result does not give a character a memory of carrying out the experiment. | [Dimensions of acceptance](../invention-validation.md#2-separate-dimensions-of-acceptance), [Current checks](../invention-validation.md#finite-authoring-preparation)    |
| Required check (invention)           | A check the applicable validation policy requires before the candidate can proceed, such as verifying permission to use a dependency or confirming that the host implements an operation the proposal needs.                                                                        | [Validation policy](../invention-validation.md#31-policy-hierarchy)                                                                                                      |
| Invention review                     | Assessment of a particular proposal, including whether it does what its creator intended. A reviewer cannot waive a mandatory integrity check. A reviewed proposal still needs any required approval and activation.                                                                | [Validation policy](../invention-validation.md#31-policy-hierarchy), [Review and live use](../invention-foundation.md#6-readiness-review-and-live-use)                   |
