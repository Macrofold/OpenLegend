# Accounts, access and participation

[Glossary index](README.md) · For the person at the keyboard and the character they play, see [characters](characters-and-cognition.md).

## Who can do what

| Canonical term                     | Meaning in Open Legend                                                                                                                                                                                                                                                                      | Source                                                                                                                                                                      |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account                            | The identity under which someone signs in to the application. The same account may play a character in one world and have only spectator access in another.                                                                                                                                 | [Identity records](../projects/completed/multiplayer-authority-tech-design.md#2-identity-and-records)                                                                       |
| Verified sign-in identity          | The pair of verified values, issuer and subject, that the hosted server uses together to find a game account. Several characters in different worlds can belong to that account.                                                                                                            | [Verified token fields](../../apps/server/src/authentication.ts), [account lookup](../../apps/server/src/authority.ts)                                                      |
| Issuer (sign-in)                   | The identifier of the sign-in service that issued the identity token. The server verifies its value in the token’s `iss` field.                                                                                                                                                             | [Token verification](../../apps/server/src/authentication.ts), [issuer configuration](../projects/auth0-sign-in.md#scope-idp01)                                             |
| Subject (sign-in)                  | The identifier a sign-in service assigns to the user who signed in. It appears in the token’s `sub` field. Two different services can use the same subject string for different users.                                                                                                      | [Verified identity](../../apps/server/src/authentication.ts), [account lookup by issuer and subject](../../apps/server/src/authority.ts)                                    |
| Authentication session             | The server’s record of a signed-in account, including expiry and revocation. A browser connection uses the session. Several tabs can share it.                                                                                                                                              | [Authentication](../projects/completed/multiplayer-authority-tech-design.md#3-authentication-adapter-and-local-development)                                                 |
| Tab ID (character control)         | The identifier a browser tab sends with its control requests. Multiple HTTP requests from the same tab can carry the same ID. The server checks whether that tab currently controls the character.                                                                                          | [Tab ID](../../apps/client/src/tab-session.ts), [request scope and control](../projects/completed/multiplayer-authority-tech-design.md#5-control-replacement)               |
| World grant                        | The server record listing an account’s permissions in one world. For example, it can grant the account permission to play a particular character or to view the world as a spectator.                                                                                                       | [Server types](../../apps/server/src/authority.ts)                                                                                                                          |
| Access capability                  | One permission the server checks for an account in a world, such as `play`, `inspect` or `manage-access`. A character’s physical ability to perform an action has its own rules.                                                                                                            | [Permissions](../projects/completed/multiplayer-authority-feature-spec.md#3-permissions-and-information-surfaces)                                                           |
| Actor binding                      | The assignment of a particular character in a world to an account that may request control of it. The assignment can persist while the player is offline. A separate control lease identifies which tab may issue commands now.                                                             | [Identity records](../projects/completed/multiplayer-authority-tech-design.md#2-identity-and-records)                                                                       |
| Recorded account owner (character) | The account recorded as owning a particular character. It stays associated with that character even if the player changes characters or loses world access. Reading the character’s private history requires current permission. The server stores this association in `auth_actor_owners`. | [Account ownership rule](../limits/multiplayer.md#mp06), [account authority](../../apps/server/src/authority.ts)                                                            |
| Control lease                      | The world server’s record of which account, session and browser tab may currently issue player commands for a character. Another permitted tab can view that character without holding the lease.                                                                                           | [Control replacement](../projects/completed/multiplayer-authority-tech-design.md#5-control-replacement)                                                                     |
| Control generation                 | The counter used to identify the current assignment of control. When control transfers, the generation changes so the server can refuse commands from the old tab.                                                                                                                          | [Control replacement](../projects/completed/multiplayer-authority-tech-design.md#5-control-replacement)                                                                     |
| Request scope                      | The server’s record of who made one request, for which world and timeline, and with which grant and control generation. It distinguishes a character’s permitted viewpoint from an account’s separately authorized inspection.                                                              | [RequestScope](../../apps/server/src/authority.ts)                                                                                                                          |
| Spectator                          | A person signed in to view a world’s public overview through the `spectate` permission. A spectator invitation grants no character to play.                                                                                                                                                 | [Invitations](../../apps/server/src/invites.ts)                                                                                                                             |
| Operator                           | A person whose account has permission for particular administrative tasks, such as issuing world invitations. Name the permission when describing an operation. Running the service, creating world content, paying for it and owning rights to it are separate roles.                      | [World operations](../projects/completed/multiplayer-entry-maintenance.md#decisions)                                                                                        |
| World access invitation            | An offer to give the account that redeems it a specified role in a world, such as playing a character or viewing the public overview. Redemption requires the server’s access checks. Characters can also invite one another on outings inside the game.                                    | [Invitation records](../../apps/server/src/invites.ts)                                                                                                                      |
| God mode                           | The game mode that makes creator tools available, such as adding a character or inspecting an NPC. Each server operation still requires the appropriate permission. The mode grants no general right to read another player’s private notes.                                                | [Information surfaces](../projects/completed/multiplayer-authority-feature-spec.md#3-permissions-and-information-surfaces), [game controls](../../apps/client/src/main.tsx) |

## The character in the world

| Canonical term                       | Meaning in Open Legend                                                                                                                                                                                                                                                          | Source                                                                                                                                                                        |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Participation state                  | Whether the character’s body is active in the world, leaving it or inactive. The saved values are `active`, `exiting` and `inactive`. Closing a browser tab and completing the character’s departure are separate events.                                                       | [ParticipationState](../../packages/domain/src/participation-state.ts)                                                                                                        |
| Exit attempt                         | One attempt to remove a player character from physical participation after their last controlling connection leaves. The world records which attempt is pending so a return can interrupt the correct departure.                                                                | [Presence, exit and return](../projects/completed/multiplayer-authority-tech-design.md#7-presence-exit-and-return)                                                            |
| Return anchor                        | The saved position and supporting surface that the world checks when placing a returning character. A change to the surface can make the saved position unusable.                                                                                                               | [ParticipationState](../../packages/domain/src/participation-state.ts), [return rules](../projects/completed/multiplayer-authority-tech-design.md#7-presence-exit-and-return) |
| Resident                             | Someone who lives in a particular place or community. A gatekeeper can be both an **NPC** and a **resident** of the town. A visiting NPC still counts as an NPC.                                                                                                                | [Participation and belonging](../projects/participants-and-world-travel-feature-spec.md#2-what-participation-means)                                                           |
| Default actor for local interactions | The actor that local conversation or goal requests can use when the caller leaves the target unspecified. At world creation, `defaultResidentEntityId` identifies the first actor with the `npc` controller, if there is one. Residence and account control are separate facts. | [Opening identity](../../packages/domain/src/identity.ts), [optional local binding](../identity-and-references.md#control-and-projection)                                     |
| Visitor                              | A character temporarily visiting another place or community. Specify **same-world visit** for ordinary travel within the world and **cross-world visit** for the proposed transfer of the same character between compatible worlds.                                             | [Travel design](../projects/participants-and-world-travel-feature-spec.md#3-the-first-useful-visit)                                                                           |
| World membership                     | An account’s access to a particular world, as recorded in its world grant. For a paid subscription use **premium-world membership** or **platform membership**, according to which service the offer covers.                                                                    | [World permissions](../projects/participants-and-world-travel-feature-spec.md#2-what-participation-means), [offers](publishing-and-shared-worlds.md)                          |
