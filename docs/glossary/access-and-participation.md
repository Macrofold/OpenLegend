# Accounts, access and participation

[Glossary index](README.md) · For the person at the keyboard and the character they play, see [characters](characters-and-cognition.md).

## Who can do what

| Canonical term           | Meaning in OpenLegend                                                                                                                                                                                                                                                                                                      | Source                                                                                                                                                                      |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account                  | The application identity of the person signing in. An account can have different permissions and character bindings in different worlds.                                                                                                                                                                                   | [Identity records](../projects/completed/multiplayer-authority-tech-design.md#2-identity-and-records)                                                                       |
| Verified identity        | The sign-in service’s verified pair of issuer and subject. The issuer identifies the sign-in service. The subject identifies the user within that service. OpenLegend maps this pair to an account.                                                                                                                        | [Sign-in](../projects/auth0-sign-in.md#scope-idp01)                                                                                                                         |
| Authentication session   | The server’s record of a signed-in account, including expiry and revocation. A browser connection uses the session. Several tabs can share it.                                                                                                                                                                             | [Authentication](../projects/completed/multiplayer-authority-tech-design.md#3-authentication-adapter-and-local-development)                                                 |
| Tab connection (control) | The browser tab identified on a control request. One tab can make many HTTP requests. Opening a second tab with the same signed-in account does not give it control. Use **network connection** for the transport.                                                                                                         | [Browser tab ID](../../apps/client/src/tab-session.ts), [control replacement](../projects/completed/multiplayer-authority-tech-design.md#5-control-replacement)             |
| World grant              | An account’s current permissions in one world. A grant can include a character binding. In access-control prose use **world grant** for the record and **access capability** for an individual permission.                                                                                                                 | [Server types](../../apps/server/src/authority.ts)                                                                                                                          |
| Access capability        | One permission checked by the server. Examples include `play`, `inspect` and `manage-access`. An action a character’s body can perform is a different kind of capability.                                                                                                                                                  | [Permissions](../projects/completed/multiplayer-authority-feature-spec.md#3-permissions-and-information-surfaces)                                                           |
| Actor binding            | The association between an account and the particular character it can request to control in a world. The account can have this binding while offline.                                                                                                                                                                     | [Identity records](../projects/completed/multiplayer-authority-tech-design.md#2-identity-and-records)                                                                       |
| Historical actor owner   | The account recorded as owning a character for privacy purposes. That association protects the character’s history after control or membership changes. Code uses `auth_actor_owners`.                                                                                                                                     | [Account authority](../../apps/server/src/authority.ts)                                                                                                                     |
| Control lease            | The server’s record of which account, session and tab currently control one character. **Control generation** is the counter that changes on transfer so the old tab’s commands can be refused.                                                                                                                            | [Control replacement](../projects/completed/multiplayer-authority-tech-design.md#5-control-replacement)                                                                     |
| Request scope            | The identity, world, permissions and control context the server established for a particular request. Code records the audience as embodied play or authorized inspection.                                                                                                                                                 | [RequestScope](../../apps/server/src/authority.ts)                                                                                                                          |
| Spectator                | An account viewing the information its spectator grant permits. Spectator access by itself provides no character to control.                                                                                                                                                                                               | [Invitations](../../apps/server/src/invites.ts)                                                                                                                             |
| Operator                 | A person authorized to carry out specific service or world administration tasks. Name the permission, such as managing invitations or restoring a checkpoint. An operator may also be a [world creator](worlds-and-creation.md#creating-or-changing-a-world), payer or rights holder. Each role has different permissions. | [World operations](../projects/completed/multiplayer-entry-maintenance.md#decisions)                                                                                        |
| Invitation               | An offer issued under existing world permissions. Redemption establishes the specified access for the accepting account after server checks. An invitation to enter a world and an in-world invitation to visit a character are different actions.                                                                         | [Invitation records](../../apps/server/src/invites.ts)                                                                                                                      |
| God mode                 | The privileged game mode exposing authorized world inspection and creator tools. Private player records and server access checks still apply. Use the actual capability name when discussing an API permission.                                                                                                            | [Information surfaces](../projects/completed/multiplayer-authority-feature-spec.md#3-permissions-and-information-surfaces), [game controls](../../apps/client/src/main.tsx) |

## The character in the world

| Canonical term                     | Meaning in OpenLegend                                                                                                                                                                                                                                                          | Source                                                                                                                                                                        |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Participation state                | Whether a character is physically active, in the process of leaving, or inactive. A player closing a tab and their character finishing departure are separate events.                                                                                                          | [ParticipationState](../../packages/domain/src/participation-state.ts)                                                                                                        |
| Exit attempt                       | The pending departure started when the last participating controlling connection goes away. Reconnecting before completion can reconcile that same attempt.                                                                                                                    | [Presence, exit and return](../projects/completed/multiplayer-authority-tech-design.md#7-presence-exit-and-return)                                                            |
| Return anchor                      | A saved position and supporting surface used to place a returning character. The world checks whether return there is still possible.                                                                                                                                          | [ParticipationState](../../packages/domain/src/participation-state.ts), [return rules](../projects/completed/multiplayer-authority-tech-design.md#7-presence-exit-and-return) |
| Resident                           | A character who lives in a particular place or community. Either a player character or an NPC can be a resident. Use **NPC** when describing who controls the character.                                                                                                       | [Participation and belonging](../projects/participants-and-world-travel-feature-spec.md#2-what-participation-means)                                                           |
| Default NPC for local interactions | The local opening’s optional fallback when a caller needs a character, for example for a conversation. Initialization records the first actor with the `npc` controller as `defaultResidentEntityId`. A solitary opening can have none. Residence is not an eligibility check. | [Opening identity](../../packages/domain/src/identity.ts), [optional local binding](../identity-and-references.md#control-and-projection)                                     |
| Visitor                            | A character temporarily visiting another place or community. Specify **same-world visit** for ordinary travel within the world and **cross-world visit** for the proposed transfer of the same character between compatible worlds.                                            | [Travel design](../projects/participants-and-world-travel-feature-spec.md#3-the-first-useful-visit)                                                                           |
| World membership                   | The relationship granting an account access to a world. Where the commercial proposal means a paid subscription, use **premium-world membership** or **platform membership**.                                                                                                  | [World permissions](../projects/participants-and-world-travel-feature-spec.md#2-what-participation-means), [offers](publishing-and-shared-worlds.md)                          |
