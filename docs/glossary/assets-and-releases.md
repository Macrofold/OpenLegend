## Files and identities

| Canonical term            | Meaning in OpenLegend                                                                                                                                                                                                                        | Source                                                                                                                       |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Asset                     | A cataloged piece of content such as a character model or a sound. Its stable **asset ID** identifies it across revisions within its owner’s catalog.                                                                                        | [Identity contract](../projects/game-asset-storage-tech-design.md#3-identity-and-reference-contract)                         |
| Asset revision            | An immutable version of the asset’s description and representations. An exact reference includes the owner, asset ID, revision ID and manifest checksum.                                                                                     | [AssetRevisionReference](../../packages/assets/src/index.ts)                                                                 |
| Blob                      | The exact bytes of one stored file. Two asset revisions can refer to the same bytes. A **blob checksum** identifies the bytes for integrity checking.                                                                                        | [Identity contract](../projects/game-asset-storage-tech-design.md#3-identity-and-reference-contract)                         |
| Artifact reference        | A reference to file bytes giving the storage boundary, access domain, checksum, byte length and media type. Current access must also be checked.                                                                                             | [ArtifactReference](../../packages/assets/src/index.ts)                                                                      |
| Asset manifest            | An immutable description of one asset, source bundle, study or release. It maps relative paths to exact files and names dependencies and rights evidence. The **manifest checksum** covers the serialized manifest itself.                   | [AssetManifest](../../packages/assets/src/index.ts)                                                                          |
| Asset release             | The exact selection of asset revisions and dependencies prepared for use together. A **pack release** identifies content offered under specified reuse terms and may include these assets. A **server release** identifies a software build. | [Release identity](../projects/game-asset-storage-tech-design.md#3-identity-and-reference-contract)                          |
| Asset index               | The selected release reference together with the mapping of expected paths to exact artifact references. The development and study tools can select different indexes.                                                                       | [AssetIndex](../../packages/assets/src/index.ts), [selecting a release](../asset-workflow.md#start-and-select-a-small-scope) |
| Access domain             | The scope within which the asset service checks permission to use file bytes. Possession of a checksum or knowledge of an asset ID does not confer permission.                                                                               | [Storage identity](../projects/game-asset-storage-tech-design.md#3-identity-and-reference-contract)                          |
| Rights evidence           | A record supporting a particular asset use, such as the applicable license or permission. A file being publicly downloadable says who can fetch it. Its rights determine what a recipient may do with it.                                    | [Asset workflow](../asset-workflow.md#where-files-belong), [rights records](../../packages/assets/src/index.ts)              |
| Art library               | Storage for editable originals and preservation copies. **Runtime storage** serves selected game files. **Study storage** serves review material and explicitly published source downloads.                                                  | [Storage boundaries](../asset-workflow.md#where-files-belong)                                                                |
| Intake                    | The storage boundary for incoming material awaiting acceptance. A file can exist there before it has been reviewed or published.                                                                                                             | [Intake and recovery](../projects/game-asset-storage-tech-design.md#44-intake-and-recovery)                                  |
| Asset recovery checkpoint | A recovery record for the asset registry and referenced files. Use **gameplay checkpoint** for an earlier saved state of the game.                                                                                                           | [Asset recovery](../asset-workflow.md#create-and-verify-recovery-checkpoints)                                                |

## Making and displaying art

| Canonical term        | Meaning in OpenLegend                                                                                                                                                                                                                              | Source                                                                                                                |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Art study             | Reviewable alternatives or a visual experiment. A **production kit** contains usable deliverables for the agreed scope. **Runtime integration** makes the selected result work in the actual game.                                                 | [Art deliverables](../production-workflows/art-flows/README.md#request-and-stopping-point)                            |
| Editable source       | Material a contributor can reopen and revise, such as a Blender scene. A **runtime export** is the derived file prepared for use by the game.                                                                                                      | [Edit or generate art](../asset-workflow.md#edit-or-generate-art)                                                     |
| Appearance            | What a subject is meant to look like. A **visual representation** is a particular way to display it, such as a sprite or skinned model. The progressive-art design names its proposed records `AppearanceDefinition` and `RepresentationManifest`. | [Art design](../projects/3d-pixel-art-tech-design.md#3-proposed-data-contracts)                                       |
| Visual binding        | In the progressive-art design, the assignment of an approved appearance and permitted representation to an entity as seen by a particular audience.                                                                                                | [VisualBinding design](../projects/3d-pixel-art-tech-design.md#visualbinding)                                         |
| Sprite                | An image depicting a subject in the rendered scene. **Billboard** describes how a surface carrying that image turns towards the camera. The character’s physical heading is a separate simulation value.                                           | [World presentation](../world-presentation.md#motion-and-depth), [billboard code](../../apps/client/src/billboard.ts) |
| Level of detail (LOD) | A representation with a different rendering cost, selected for the viewing conditions. In art prose, **rendering detail** describes the image. **Detailed attention** describes what a character observes.                                         | [Representation design](../projects/3d-pixel-art-tech-design.md#representationmanifest)                               |
| Local read-through    | A rendering effect that shows the player character or a currently visible subject through scenery blocking the camera. A remembered subject that the character can no longer see is ineligible.                                                    | [Local read-through](../world-presentation.md#local-read-through)                                                     |
