# Art, assets and releases

[Glossary index](README.md) · [Player interface](interface-and-presentation.md) · For a package of reusable game content, see [publishing](publishing-and-shared-worlds.md).

## Files and identities

| Canonical term            | Meaning in OpenLegend                                                                                                                                                                                                                       | Source                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Asset                     | A cataloged piece of content, such as a character model or a sound. One asset can have several revisions.                                                                                                                                   | [Identity contract](../projects/game-asset-storage-tech-design.md#3-identity-and-reference-contract)                         |
| Asset owner               | The engine package, world package, collection, creator or world instance whose catalog identifies an asset. The owner reference specifies its kind and ID.                                                                                  | [Asset identity contract](../projects/game-asset-storage-tech-design.md#3-identity-and-reference-contract)                   |
| Asset ID                  | The stable identifier of an asset within its owner’s catalog. Its display name can change while its ID stays the same.                                                                                                                      | [Asset identity contract](../projects/game-asset-storage-tech-design.md#3-identity-and-reference-contract)                   |
| Asset revision            | One immutable version of an asset’s description and representations.                                                                                                                                                                        | [AssetRevisionReference](../../packages/assets/src/index.ts)                                                                 |
| Asset revision ID         | The identifier allocated to one revision within the owner and asset ID. It is allocated before the manifest is serialized.                                                                                                                  | [Asset identity contract](../projects/game-asset-storage-tech-design.md#3-identity-and-reference-contract)                   |
| Asset revision reference  | The owner, asset ID, revision ID and checksum of the exact serialized manifest. All four identify the revision and the manifest bytes to verify.                                                                                            | [Asset identity types](../../packages/assets/src/index.ts)                                                                   |
| Blob                      | The exact bytes of one stored file. Two asset revisions can refer to the same blob.                                                                                                                                                         | [Identity contract](../projects/game-asset-storage-tech-design.md#3-identity-and-reference-contract)                         |
| Blob checksum             | The SHA-256 hash of a file’s exact bytes. The asset service uses the storage boundary and access domain to locate the copy and checks the caller’s current access separately.                                                               | [Asset identity contract](../projects/game-asset-storage-tech-design.md#3-identity-and-reference-contract)                   |
| Artifact reference        | A file reference with its storage boundary, access domain, SHA-256 checksum, byte length and media type. The service checks current access before use.                                                                                      | [Asset identity types](../../packages/assets/src/index.ts)                                                                   |
| Storage boundary (assets) | The logical storage destination for a file, such as the private art library or runtime storage. Trusted configuration maps it to physical storage.                                                                                          | [Asset identity contract](../projects/game-asset-storage-tech-design.md#3-identity-and-reference-contract)                   |
| Asset manifest            | An immutable description of an asset revision, source bundle, study or release. It maps relative paths to exact files and lists dependency revisions and references to rights evidence.                                                     | [AssetManifest](../../packages/assets/src/index.ts)                                                                          |
| Manifest checksum         | The SHA-256 hash of the exact serialized manifest bytes. A file named inside the manifest has its own blob checksum.                                                                                                                        | [Asset identity contract](../projects/game-asset-storage-tech-design.md#3-identity-and-reference-contract)                   |
| Asset release             | An exact selection of compatible asset revisions and their dependencies for use together. For reusable game content and its reuse terms, see [pack release](publishing-and-shared-worlds.md#publishing-and-commercial-design).              | [Release identity](../projects/game-asset-storage-tech-design.md#3-identity-and-reference-contract)                          |
| Asset index               | The selected release reference together with the mapping of expected paths to exact artifact references. The development and study tools can select different indexes.                                                                      | [AssetIndex](../../packages/assets/src/index.ts), [selecting a release](../asset-workflow.md#start-and-select-a-small-scope) |
| Access domain             | The scope within which the asset service checks permission to use file bytes. Possession of a checksum or knowledge of an asset ID does not confer permission.                                                                              | [Storage identity](../projects/game-asset-storage-tech-design.md#3-identity-and-reference-contract)                          |
| Rights evidence           | A record supporting a specified use of an asset, such as a license or a creator’s permission. The service checks current rights separately when publishing or using the asset, even if the file is publicly downloadable.                   | [Asset workflow](../asset-workflow.md#where-files-belong), [rights records](../../packages/assets/src/index.ts)              |
| Art library               | Private storage for editable originals and preservation copies.                                                                                                                                                                             | [Storage boundaries](../asset-workflow.md#where-files-belong)                                                                |
| Runtime storage (assets)  | Storage that serves the asset files selected for use by the game.                                                                                                                                                                           | [Storage boundaries](../asset-workflow.md#where-files-belong)                                                                |
| Study storage (assets)    | Storage that serves review material and explicitly published source downloads.                                                                                                                                                              | [Storage boundaries](../asset-workflow.md#where-files-belong)                                                                |
| Intake                    | The storage boundary for incoming material awaiting acceptance. A file can exist there before it has been reviewed or published.                                                                                                            | [Intake and recovery](../projects/game-asset-storage-tech-design.md#44-intake-and-recovery)                                  |
| Asset recovery checkpoint | A restorable copy of coherent asset publication records and their referenced files. Restoration checks current permissions separately. World progress has its own [gameplay checkpoint](runtime-and-storage.md#saving-and-continuing-play). | [Asset recovery](../asset-workflow.md#create-and-verify-recovery-checkpoints)                                                |

## Making and displaying art

| Canonical term            | Meaning in OpenLegend                                                                                                                                                                                                                                                                                                             | Source                                                                                                                                   |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Art study                 | Reviewable alternatives or a visual experiment used to choose an art direction.                                                                                                                                                                                                                                                   | [Art deliverables](../production-workflows/art-flows/README.md#request-and-stopping-point)                                               |
| Production kit            | The usable, checked art exports requested for a task, such as the selected character art at the agreed sizes. Installing them in the game is a separate delivery step.                                                                                                                                                            | [Art deliverables](../production-workflows/art-flows/README.md#request-and-stopping-point)                                               |
| Runtime integration (art) | Making the selected art work in the actual game.                                                                                                                                                                                                                                                                                  | [Art deliverables](../production-workflows/art-flows/README.md#request-and-stopping-point)                                               |
| Editable source           | Material a contributor can reopen and revise, such as a Blender scene.                                                                                                                                                                                                                                                            | [Edit or generate art](../asset-workflow.md#edit-or-generate-art)                                                                        |
| Runtime export            | The file derived from editable art and prepared for use by the game.                                                                                                                                                                                                                                                              | [Edit or generate art](../asset-workflow.md#edit-or-generate-art)                                                                        |
| Appearance                | What a subject is meant to look like. The progressive-art design describes it in an `AppearanceDefinition`.                                                                                                                                                                                                                       | [Art design](../projects/3d-pixel-art-tech-design.md#3-proposed-data-contracts)                                                          |
| Visual representation     | A particular way to display an appearance, such as a sprite or a skinned model. The proposed `RepresentationManifest` describes the representation.                                                                                                                                                                               | [Art design](../projects/3d-pixel-art-tech-design.md#3-proposed-data-contracts)                                                          |
| Visual binding            | In the progressive-art design, the part of an entity’s view that specifies its approved appearance revision, representation choices and visible state or attachments for that audience.                                                                                                                                           | [VisualBinding design](../projects/3d-pixel-art-tech-design.md#visualbinding)                                                            |
| Sprite                    | An image depicting a subject in the rendered scene.                                                                                                                                                                                                                                                                               | [World presentation](../world-presentation.md#motion-and-depth)                                                                          |
| Billboard                 | A surface in the rendered scene that turns toward the camera. A sprite can be displayed on it while the character’s body keeps its own heading.                                                                                                                                                                                   | [Billboard code](../../apps/client/src/billboard.ts)                                                                                     |
| Level of detail (LOD)     | A representation with a different rendering cost, selected for the viewing conditions. In art prose, **rendering detail** describes the image. **Detailed attention** describes what a character observes.                                                                                                                        | [Representation design](../projects/3d-pixel-art-tech-design.md#representationmanifest)                                                  |
| Local read-through        | The camera effect controlled by **See-through reveal**. It draws the player character or another currently visible subject over scenery that obscures them from the camera. **Nearby visible objects** limits which subjects qualify by distance. Holding Option (Alt) while the game has input temporarily overrides that limit. | [Local read-through](../world-presentation.md#local-read-through) · [Camera setting](../../apps/client/src/ui/world-visual-settings.tsx) |
