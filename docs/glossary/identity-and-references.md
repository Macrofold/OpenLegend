## What a name or ID identifies

| Canonical term                  | Meaning in OpenLegend                                                                                                                                                                                                                                           | Source                                                                                                                |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Stable ID                       | The stored key that continues to identify the same entity or record within its scope after a rename. Say what it identifies, such as an **entity ID** in a world or an **event ID** in a history. Two people with the same display name can have different IDs. | [Identity contract](../identity-and-references.md#contract)                                                           |
| Composite key                   | Two or more fields that together identify one record. For example, two observers can have separate records of the same event. A lookup for one observer’s record must include that observer and any other fields that identify the record, such as its kind.    | [Identity contract](../identity-and-references.md#contract)                                                           |
| Definition ID                   | The key for an authored definition, such as a kind of tool. An **item instance ID** identifies a particular item in the world. Two knives made using the same definition can have different owners and locations.                                               | [Definitions and physical entities](../identity-and-references.md#contract)                                           |
| Definition pin                  | The definition ID, version and content digest that together identify the exact definition in use. A digest is computed from the definition’s content. Two versions can have the same definition ID and different content.                                       | [Definition pin validation and comparison](../../packages/domain/src/definition-pins.ts)                              |
| Canonical name (entity or item) | The name stored for an entity or item before display grammar is applied. A common noun is stored as “hare” and can be shown as “a hare.” An article that belongs to a proper name stays, as in “The Nameless.”                                                  | [Entity names and articles](../entity-names.md#one-grammar-owner)                                                     |
| Permitted label                 | The name or description this observer is allowed to see for a particular subject. One observer might see “a person” while someone who has learned the name sees “Ada.” Learning a name changes what the observer may be shown.                                  | [Display grammar](../entity-names.md#one-grammar-owner), [actor context](../identity-and-references.md#actor-context) |
| Name form                       | The grammatical category of a permitted name, such as proper name, singular count noun, plural or mass noun. The interface uses it to display “a hare” but “Ada” when it introduces the subject.                                                                | [Entity names and articles](../entity-names.md#one-grammar-owner)                                                     |

## What a reference lets its recipient do

| Canonical term                  | Meaning in OpenLegend                                                                                                                                                                                                                                                                                                   | Source                                                                                                       |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Observer-local contact          | One observer’s reference to a source they detected, such as a sound behind a door. The observer can refer to the sound while its cause is still unknown.                                                                                                                                                                | [Observer-specific references](../identity-and-references.md#selected-observer-specific-evidence-target)     |
| Remembered-individual reference | A reference that lets an observer recall or discuss someone using evidence they have retained. A guard can talk about a familiar visitor after the visitor leaves. To act on someone now, the guard needs evidence linking the present body to the action.                                                              | [Observer-specific references](../identity-and-references.md#selected-observer-specific-evidence-target)     |
| Current-body reference          | A reference to one particular life of a body for a present interaction. The player interface supplies an opaque identifier for a currently visible character. It changes when that character gets a replacement body or the server restarts. A normal injury leaves it stable. The server checks the action separately. | [Control and projection](../identity-and-references.md#control-and-projection)                               |
| Known-place reference           | A token for a remembered destination that a character is allowed to select. For example, a character can offer to guide someone to a remembered place without seeing it now.                                                                                                                                            | [Destination references](../identity-and-references.md#contract)                                             |
| Decision-scoped handle          | An identifier the server gives a model for a permitted subject in one prepared decision. The server resolves it using the map for that decision. The model cannot grant itself a new target by naming one.                                                                                                              | [Actor context](../identity-and-references.md#actor-context)                                                 |
| Response-local alias            | A name that one generated response uses to refer to another operation or proposed output in that response. The application assigns any durable identity when it admits the result.                                                                                                                                      | [Identity contract](../identity-and-references.md#contract)                                                  |
| Evidence reference              | The identity and exact revision of the record supporting a particular claim. For example, a reference to a private memory identifies the content used for a decision. If the memory is corrected, its new content cannot silently stand in for the old evidence.                                                        | [EvidenceRef and source revisions](../identity-and-references.md#selected-observer-specific-evidence-target) |
| Source fragment                 | An immutable piece of source material, such as part of an utterance. Several observers’ records can refer to that same fragment. Each observer’s own record establishes which parts they perceived.                                                                                                                     | [Shared temporal references](../identity-and-references.md#selected-shared-temporal-references)              |
| Observer receipt (perception)   | The record of which observations one particular observer actually acquired, and in what order. Two characters can hear different words from the same utterance while their records refer to some of the same underlying data.                                                                                           | [Shared temporal references](../identity-and-references.md#selected-shared-temporal-references)              |
