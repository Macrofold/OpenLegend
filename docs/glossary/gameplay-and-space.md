# Gameplay, bodies and space

[Glossary index](README.md)

## Time and actions

| Canonical term              | Meaning in OpenLegend                                                                                                                                                                                                                                               | Source                                                                                                                                                    |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Simulation time (game time) | Time that has passed inside the running world. A game second and a real second are separate units. A player can turn the camera while the simulation is paused.                                                                                                     | [Independent clocks](../simulation-time.md#independent-clocks)                                                                                            |
| Simulation interval         | An amount of game time over which already-active work advances. Movement, collision or an action completing may require the engine to split an interval. A browser frame, server wake-up or state update each has its own timing.                                   | [Interval and event ordering](../simulation-time.md#native-interval-contract)                                                                             |
| Elapsed-time debt           | Game time the clock owes that the simulation has yet to complete. If the server falls behind, report the time actually completed. Skipped opportunities for optional thoughts do not add simulation debt.                                                           | [Clock, progress and debt](../simulation-time.md#independent-clocks), [Optional work](../simulation-time.md#product-scalability-time-and-detail-targets)  |
| Calendar time               | Dates meaningful in the fiction. Advancing the calendar separately from bodily activity or movement is a design target. The existing speed control changes how much simulation time is owed.                                                                        | [Separate calendar proposal](../simulation-time.md#product-scalability-time-and-detail-targets)                                                           |
| Command                     | A request to the simulation for a specific change. For example, the command to shoot names a target. The server checks whether the actor can start the shot.                                                                                                        | [Grounding an intention](../action-capabilities.md#5-intent-envelope-and-semantic-fidelity)                                                               |
| Action                      | Something an actor does or attempts in the world. A shot takes time, can be interrupted before release and can miss. The actor’s [action intention](actions-and-learning.md#what-a-character-wants-and-can-try) records what they meant to attempt.                 | [Recorded results](../action-experience.md#what-is-recorded), [Grounding an intention](../action-capabilities.md#5-intent-envelope-and-semantic-fidelity) |
| Action capability           | An operation the installed world supports under stated prerequisites, such as shooting a bow.                                                                                                                                                                       | [Capability registry](../action-capabilities.md#4-one-capability-registry-several-views)                                                                  |
| Action choice               | A specific action offered to a particular actor, with inputs such as which bow to use and whom to aim at. Its availability is checked again when the actor tries it.                                                                                                | [Availability and execution](../action-capabilities.md#action-availability-and-temporary-execution)                                                       |
| Activity                    | Work an actor can undertake, such as moving stock from a bag to a cache. An activity can contain several actions. Its plan records what is still to be done. Another character must decide whether to cooperate.                                                    | [Executing activities](../action-experience.md#selected-execution-and-inspection)                                                                         |
| Action occurrence           | The record of one actual attempt, including stages, interruption or completion, outputs and effects. An attempt to deal eight damage against two remaining health records the two health actually lost. A learned method describes steps the actor could try again. | [What an action records](../action-experience.md#what-is-recorded)                                                                                        |

## Bodies, abilities and survival

| Canonical term   | Meaning in OpenLegend                                                                                                                                                                                                                                                          | Source                                                                                                                                                               |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Body             | The part of an entity that occupies physical space in the simulation. A moving body can collide with an obstacle or be hit by a projectile.                                                                                                                                    | [Authored terrain and bodies](../spatial-world.md#authored-terrain-and-bodies)                                                                                       |
| Body profile     | The dimensions and physical reference points used to simulate a body, including its radius, height and eye position. A mesh or sprite depicts the body.                                                                                                                        | [Authored terrain and bodies](../spatial-world.md#authored-terrain-and-bodies)                                                                                       |
| Replacement life | Under the bundled rule, a player can choose to continue after death. Their character keeps their identity, memories and relationships and begins a new physical life. Commands targeting the old body cannot silently attach to the new one.                                   | [Player death and continuation](../worlds/base/player-death.md#death-and-possessions), [Binding a body target](../identity-and-references.md#control-and-projection) |
| Life stage       | A proposed phase of biological or social development, such as childhood or adulthood, with capabilities defined by that world. This is distinct from a character's physical life ending, and age by itself grants nobody control of the character.                             | [Proposed stages of childhood](../projects/generations-and-family-life/childhood-and-population.md#stages-change-possibilities-not-ownership)                        |
| Attribute        | A value the world defines for an entity, with declared meaning, visibility and supported changes. For example, the base world's health and fullness are different attributes. Use the particular attribute's name when “stat” could mean either a game value or a measurement. | [Attribute meanings](../engine-and-world-boundaries.md#semantics-before-meters), [Attribute definition](../../packages/domain/src/world-modules.ts)                  |
| Need             | Something a character may act to satisfy, such as hunger. Feeling hungry leaves the character a choice about whether and how to seek food.                                                                                                                                     | [Bundled survival rules](../worlds/base/survival.md#bodily-conditions-and-chosen-responses)                                                                          |
| Reservoir        | A quantity with defined bounds and rules for changing it. In Base, fullness is a reservoir. Falling fullness can make the character hungry.                                                                                                                                    | [Bundled survival rules](../worlds/base/survival.md#bodily-conditions-and-chosen-responses)                                                                          |
| Bodily condition | A state of a character’s body described by the world’s rules, such as “starving” at a specified fullness.                                                                                                                                                                      | [Condition descriptions](../worlds/base/survival.md#bodily-conditions-and-chosen-responses)                                                                          |
| Condition (rule) | A test in a rule that determines when an effect applies or an operation can run. For example, a status effect can apply damage only when a quantity has reached its threshold.                                                                                                 | [Conditions in status-effect definitions](../status-effects.md#configuration), [Transitions](../status-effects.md#transitions)                                       |
| Status effect    | An installed rule that can change the affected entity over time or when it enters or leaves a particular state. For example, starvation can reduce health while fullness stays at zero.                                                                                        | [Status effects](../status-effects.md#transitions), [Condition descriptions](../worlds/base/survival.md#bodily-conditions-and-chosen-responses)                      |
| Trait            | A characteristic or disposition attributed to a character. A description such as “patient” alone grants no mechanical benefit.                                                                                                                                                 | [Semantics before meters](../engine-and-world-boundaries.md#semantics-before-meters)                                                                                 |
| Skill            | Proficiency at performing a particular activity. For example, Base sling handling affects how the character uses a sling. Knowing a sling recipe tells them how to make one.                                                                                                   | [Sling handling](../worlds/base/practical-competence.md#one-narrow-competence), [Semantics before meters](../engine-and-world-boundaries.md#semantics-before-meters) |
| Native response  | A supported reaction computed by ordinary simulation rules, such as an alarmed hare starting to flee. A reaction can occur without a model deciding what to do, and does not give every witness knowledge of its cause.                                                        | [Animal alarm and escape](../worlds/base/animal-responses.md#what-starts-and-renews-an-alarm)                                                                        |
| Incapacity       | A condition that prevents a living character from performing some or all actions. Which actions remain possible depends on the world’s body rules.                                                                                                                             | [Body and survival](../worlds/base/survival.md#bodily-conditions-and-chosen-responses)                                                                               |
| Death            | The end of a character’s current physical life under the world’s rules. In Base, a dead player character can begin another physical life by choosing **Continue**.                                                                                                             | [Body and survival](../worlds/base/survival.md#bodily-conditions-and-chosen-responses), [Continue](../worlds/base/player-death.md#continue-near-a-rest-spot)         |
| Player absence   | The player is away from the game. The world’s departure rules determine what happens to their character. Returning to the session does not revive a dead character.                                                                                                            | [Logout and return](../worlds/base/lifecycle-and-protection.md#human-logout-and-return), [Continue](../worlds/base/player-death.md#continue-near-a-rest-spot)        |

For what counts as an injury and what treatment does in the proposed care system, see [danger, care and death](social-life-and-stories.md#danger-care-and-death).

## Objects, custody and work

| Canonical term    | Meaning in OpenLegend                                                                                                                                                                                                                                        | Source                                                                                                                                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Item definition   | The world’s description of a kind of item, such as a stone. A definition can exist before any physical item of that kind is made or found.                                                                                                                   | [Item types](../../packages/domain/src/types.ts)                                                                                                                                                        |
| Item lot          | An identified quantity of a particular item kind. Ten interchangeable stones can form one lot. An individual keepsake retains its own identity.                                                                                                              | [Item lot](../../packages/domain/src/objects.ts), [Inventory and piles](../worlds/base/items.md#ground-piles)                                                                                           |
| Material property | A supported characteristic of a material, such as flexibility. Changing its display name does not give it new properties.                                                                                                                                    | [Material and work rules](../worlds/base/invention-families.md#material-and-work-rules)                                                                                                                 |
| Ingredient role   | The purpose an ingredient serves in a recipe, such as the shaft of an arrow. The recipe sets the requirements for a material that fills that role.                                                                                                           | [Material and work rules](../worlds/base/invention-families.md#material-and-work-rules)                                                                                                                 |
| Placement         | An entity's authoritative physical relationship to the world. It can sit at a world position, be contained by another entity, or be attached at a supported point. Contained and equipped objects move with their parent.                                    | [Placement in code](../../packages/domain/src/spatial-state.ts)                                                                                                                                         |
| Assembly          | A physical arrangement of parts in the world, such as posts supporting a roof.                                                                                                                                                                               | [Canopy arrangements](../worlds/base/editable-shelters.md#flat-and-sloping-arrangements-using-the-same-rules)                                                                                           |
| Shelter           | Cover that an arrangement actually provides under the world’s rules. A roof can keep rain off an item beneath it while an item beside it gets wet. Naming the place or obtaining permission to build there provides no cover.                                | [Rain exposure](../worlds/base/editable-shelters.md#rain-and-drying-for-the-first-scene), [Canopy arrangements](../worlds/base/editable-shelters.md#flat-and-sloping-arrangements-using-the-same-rules) |
| Item custody      | Who physically holds an item or which container holds it. Someone carrying a borrowed tool has custody of it.                                                                                                                                                | [Possessions and transfers](../worlds/base/social.md#offering-and-accepting-possessions), [Shared containers](../worlds/base/items.md#shared-containers-and-active-work)                                |
| Item ownership    | Whose property an item is under the world’s rules. A lender can keep ownership while a borrower carries the item.                                                                                                                                            | [Possessions and transfers](../worlds/base/social.md#offering-and-accepting-possessions)                                                                                                                |
| Item access       | Whether a particular actor is permitted and physically able to use or move an item. Seeing a bag does not grant access to its contents.                                                                                                                      | [Shared containers](../worlds/base/items.md#shared-containers-and-active-work)                                                                                                                          |
| Inventory         | The items in a character’s possession. Inventory can include a weapon stowed in a bag.                                                                                                                                                                       | [Held equipment](../worlds/base/items.md#compatible-held-equipment)                                                                                                                                     |
| Equipment         | Items fitted to compatible attachment points on a character’s body, such as a bow held in both hands. Equipping an item can make particular actions available.                                                                                               | [Held equipment](../worlds/base/items.md#compatible-held-equipment), [Equipped strikes](../targeted-actions.md#equipped-contact-strikes)                                                                |
| Resource source   | A world object that can supply material under an installed gathering rule, such as a patch of reeds. A finite source can run out.                                                                                                                            | [Authored sources](../worlds/base/first-playable-survival.md#authored-sources)                                                                                                                          |
| Stock             | A quantity of items already available to use or transfer, such as gathered reeds in a bag.                                                                                                                                                                   | [Stock transfer](../action-experience.md#fresh-stock-binding-in-finite-methods)                                                                                                                         |
| Finite attempt    | One bounded action to obtain something from a source, such as one cast at a fishing spot. Reserving work time or knowing the method does not guarantee a catch.                                                                                              | [Finite source attempts](../food-preparation.md#finite-source-attempts), [One fishing cast](../worlds/base/river-fishing.md#one-chosen-cast)                                                            |
| Yield             | The quantity an attempt actually produces. A completed fishing cast can yield zero fish.                                                                                                                                                                     | [One fishing cast](../worlds/base/river-fishing.md#one-chosen-cast)                                                                                                                                     |
| Crafting          | Using a supported method, materials, tools and work time to make something. The result belongs to that attempt. [Invention](worlds-and-creation.md#invention-making-and-learning) can add a new method to the world.                                         | [Known manufacturing](../worlds/base/first-playable-survival.md#known-manufacturing-catalogue)                                                                                                          |
| Food preparation  | Using a selected food-preparation definition to turn specified ingredients into its outputs. The definition supplies the work time and any heat requirement. The character needs the actual ingredients.                                                     | [Food preparation](../food-preparation.md#preparation-definitions-and-exact-choices)                                                                                                                    |
| Output port       | A named result of a particular step which another step can use. A method names the result it expects. A later step can use only what the earlier step actually produced and what remains available. A step that produced nothing cannot supply a later step. | [Outputs and later steps](../action-experience.md#selected-execution-and-inspection)                                                                                                                    |

## Space, movement and combat

| Canonical term     | Meaning in OpenLegend                                                                                                                                                                                                                       | Source                                                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| World position     | A point in three-dimensional space, measured in world metres with height on the Y axis. Two characters at the same horizontal coordinates can be at different heights.                                                                      | [What a location means](../spatial-world.md#what-a-location-means)                                                                 |
| Support surface    | The physical surface a body stands or rests on. One character can stand on a bridge while another stands on the ground directly underneath.                                                                                                 | [What a location means](../spatial-world.md#what-a-location-means)                                                                 |
| World place        | An authored location, such as the camp hearth. A static named place has a physical point, a landmark and an arrival radius.                                                                                                                 | [Static and known places](../spatial-world.md#static-named-places-and-known-places), [Base-world places](../worlds/base/places.md) |
| Known place        | A place a particular character has learned about. Their record can retain its last observed location and description. Remembering the hearth does not reveal who is there now or whether it is lit.                                         | [Static and known places](../spatial-world.md#static-named-places-and-known-places)                                                |
| Terrain            | The map’s physical ground and land features. Its installed definitions determine properties such as walkable support, sight obstruction and sound transmission.                                                                             | [Terrain and physical bodies](../spatial-world.md#authored-terrain-and-bodies)                                                     |
| Blocker            | Physical geometry that obstructs a specified operation, such as walking or seeing along a particular path. Name the operation when the distinction matters.                                                                                 | [Terrain and physical bodies](../spatial-world.md#authored-terrain-and-bodies)                                                     |
| Static scenery     | Art placed at a location in the scene, such as a drawn tree. Any collision, cover or obstruction there needs separately defined physical geometry.                                                                                          | [Static scenery](../spatial-world.md#static-scenery)                                                                               |
| Facing             | The direction an actor’s body points in the world.                                                                                                                                                                                          | [Body orientation](../spatial-world.md#what-a-location-means)                                                                      |
| Camera             | The viewpoint used to draw the scene for the player. Turning it changes the picture. The actor’s facing, what they can see, and the path of an already released projectile are determined by the simulation.                                | [Camera perspective](../spatial-world.md#tactical-camera-and-perspective)                                                          |
| Route              | A planned path a body can take over its available surfaces. Conditions can change before the body travels that path.                                                                                                                        | [Movement](../spatial-world.md#movement)                                                                                           |
| Movement           | The actual change in a body’s position as the simulation advances and checks current physical conditions.                                                                                                                                   | [Movement](../spatial-world.md#movement)                                                                                           |
| Follow             | An action that directs the actor to keep a chosen separation from a target. It uses the actor’s current evidence about the target to update the route.                                                                                      | [Base-world follow](../worlds/base/navigation.md#native-follow)                                                                    |
| Clearance          | Whether a body of a particular shape and size fits along a movement path.                                                                                                                                                                   | [Physical interaction](../spatial-world.md#physical-interaction-design-checks)                                                     |
| Reach              | Whether an actor can physically reach a particular target for an interaction from its current position.                                                                                                                                     | [Physical interaction](../spatial-world.md#physical-interaction-design-checks)                                                     |
| Physical contact   | A physical relationship in which body surfaces touch or their occupied volumes overlap. A target can be in sight or within reach before any contact occurs.                                                                                 | [Physical contact](../spatial-world.md#physical-contact)                                                                           |
| Threat response    | A character’s chosen response to evidence of danger. It can include speaking, leaving, continuing current work or choosing a specific defensive action. A purpose such as protecting someone does not itself authorize a pursuit or strike. | [Meaning of a threat response](../worlds/base/threat-response-options.md#1-what-a-response-means)                                  |
| Aim                | Selecting the point or subject the actor intends to hit with a projectile. An intended target can move before the projectile reaches it.                                                                                                    | [Aim and flight](../targeted-actions.md#chosen-aim-committed-flight-and-evasion)                                                   |
| Projectile release | The point at which the projectile starts its flight in the world. From this point its flight and any hits follow the world’s physical rules.                                                                                                | [Aim and flight](../targeted-actions.md#chosen-aim-committed-flight-and-evasion)                                                   |
| Projectile impact  | The projectile’s actual encounter with a body or obstruction during flight. An obstacle between the shooter and the intended target can take the hit.                                                                                       | [Aim and flight](../targeted-actions.md#chosen-aim-committed-flight-and-evasion)                                                   |
| Contact defense    | An action such as guarding against an incoming strike using a compatible shield. The guard has to meet the actual contact and timing conditions.                                                                                            | [Contact defense](../targeted-actions.md#finite-chosen-contact-defense)                                                            |
| Evasion            | An action in which the defender moves their body to avoid danger. Choosing to evade still leaves the outcome to the physical interaction.                                                                                                   | [Physical evasion](../worlds/base/skilled-action-execution.md#physical-arrow-and-local-evasion)                                    |

## Social actions

| Canonical term       | Meaning in OpenLegend                                                                                                                                                                                          | Source                                                                                                                                                               |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Item offer           | A proposal to give or exchange specified items under stated terms. Making the offer leaves the items where they are until the recipient accepts and the transfer is allowed.                                   | [Offering possessions](../worlds/base/social.md#offering-and-accepting-possessions)                                                                                  |
| Offer acceptance     | The named recipient’s decision to take the stated terms. For an item transfer, the game checks the participants, access and exact items before transferring all agreed items together.                         | [Offering possessions](../worlds/base/social.md#offering-and-accepting-possessions)                                                                                  |
| Spoken promise       | A supported commitment made through speech. It can matter later even if unfulfilled. A promise to give someone an item leaves the item where it is until a real transfer occurs.                               | [Spoken promises](../worlds/base/social.md#spoken-promises)                                                                                                          |
| Voluntary outing     | A proposal and, if accepted, a shared purpose for travelling together. Each character keeps their own movement, choices and right to leave. A companion's consent to travel does not transfer control of them. | [Voluntary outings](../worlds/base/social.md#voluntary-outings), [Consenting travel companions](../action-experience.md#consenting-travel-companions)                |
| Biological kinship   | A family relationship established through parentage in the world. A recorded parent has no automatic right to control a child’s decisions or possessions.                                                      | [Objective family facts](../worlds/base/social.md#objective-family-facts), [Family life proposal](../worlds/base/generations-and-family-life.md#what-family-changes) |
| Knowledge of kinship | What a particular character has learned about a family relationship. Their evidence or belief can differ from the parentage recorded in the world.                                                             | [Objective family facts](../worlds/base/social.md#objective-family-facts), [Family life proposal](../worlds/base/generations-and-family-life.md#what-family-changes) |
| Barter               | An exchange of agreed items in both directions. The recipient can inspect the terms before accepting.                                                                                                          | [Gifts, barter and counteroffers](../worlds/base/social.md#offering-and-accepting-possessions)                                                                       |
| Gift                 | A transfer offered without asking for something in return. An offered gift changes hands only after the recipient accepts and the transfer succeeds.                                                           | [Gifts, barter and counteroffers](../worlds/base/social.md#offering-and-accepting-possessions)                                                                       |
| Durable agreement    | In the proposed commission system, parties accept terms for a later exchange. A commission for a pouch creates a commitment. The maker still needs materials and must produce and deliver the pouch.           | [Proposed commission rules](../worlds/base/durable-agreements.md#first-agreement-rules)                                                                              |
| Institution          | In the proposed equipment-sharing design, an association with recorded membership and agreed roles for coordinating use of goods. The goods can remain individually owned.                                     | [Proposed institution and its keeper](../worlds/base/shared-equipment-and-institutions.md#what-the-institution-means)                                                |
| Mandate              | In the proposed equipment-sharing design, the specific authority someone accepts for a role, such as lending a named bow on agreed terms. Membership alone grants no authority to lend the bow.                | [Proposed institution and its keeper](../worlds/base/shared-equipment-and-institutions.md#what-the-institution-means)                                                |
