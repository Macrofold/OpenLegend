# OpenLegend glossary

Use **NPC** for a non-player human character. Say **an NPC who lives in town** when residence matters. For an attention limit, count **the subjects a guard can track in detail at once**.

## Words that need context

| Wording you may encounter         | Choose the term that answers the question                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Human, agent, autonomous resident | A **player** is the person playing. Their **player character** acts in the world. The game controls an **NPC** such as the gatekeeper. A **resident** lives in a place. The **World Agent** helps someone author the world. [Characters](characters-and-cognition.md) · [Residence](access-and-participation.md#the-character-in-the-world)                                                                                     |
| Attention place, slot, focus      | Count the **subjects** the observer can track in detail at once. A **place** is a location. **Focus** is a Base world attribute. **Deliberate attention** is a character’s choice to concentrate on a subject. **Keyboard focus** tells the interface where to send keystrokes. [Attention](perception-and-memory.md#what-receives-closer-attention) · [Interface](interface-and-presentation.md#controls-selection-and-camera) |
| Native, Source                    | A comparison can involve the **TypeScript server**, the **Node-hosted Rust simulation** or the **stand-alone Rust server**. Name the ones it used. Use **rule-controlled** when describing how an animal chooses a response under an installed rule. [Runtime](runtime-and-storage.md#which-program-runs-the-game) · [Actor controllers](characters-and-cognition.md)                                                           |
| Act, action, command              | **Act** is the player control for describing a gesture or attempt. A **command** asks the simulation to do something. An **action** is what a character does or attempts. [Player controls](interface-and-presentation.md#what-the-player-opens) · [Gameplay](gameplay-and-space.md#time-and-actions)                                                                                                                           |
| Account, owner, control           | A person signs in with an **account**. A character’s **personal account** describes an experience. A **recorded account owner** is associated with a particular character. A **control lease** identifies the browser tab currently allowed to issue commands for that character. [Access](access-and-participation.md) · [Experience](perception-and-memory.md)                                                                |
| Subject                           | In **sign-in**, the subject identifies a user to the service that signed them in. In **perception**, the subject is what a character senses, such as a passing hare or an unidentified sound. [Sign-in](access-and-participation.md#who-can-do-what) · [Perception](perception-and-memory.md#what-happened-and-what-reached-the-observer)                                                                                       |
| Seen, identified, target          | Say which fact the evidence supports. A guard can **detect** a voice, **recognize** the speaker, or **learn a name** from what was said. A **current-body reference** lets the guard refer to a particular body for a physical action. Each fact needs its own evidence. [Perception](perception-and-memory.md) · [References](identity-and-references.md)                                                                      |
| Memory, capacity                  | Use **character memory** for what someone remembers in the game and **process memory** for the RAM a running program uses. A **configured allowance** sets a limit, an **external quota** is a limit set by a service provider, and **measured capacity** reports how much work completed under stated conditions. [Perception](perception-and-memory.md) · [Measurement](measurement-and-delivery.md)                          |
| Save, load, return                | A player **reconnects** to the running world. A **background save** writes accepted play to storage. After a server restart, it can **reopen** the latest durable world. An authorized operator can **restore** an earlier checkpoint. [Saving and continuing play](runtime-and-storage.md#saving-and-continuing-play)                                                                                                          |
| Observer receipt                  | A character’s **observer receipt** records what that character perceived. **Player-view delivery** means the update reached the measured client. To report what appeared on screen, measure **display** separately. [Personal evidence](identity-and-references.md#what-a-reference-lets-its-recipient-do) · [Measurements](measurement-and-delivery.md#what-was-measured)                                                      |
| Worker, campaign                  | A **compute worker** in the simulation performs game calculations. A **managed verification worker** runs development checks. A **shared campaign** is an in-world undertaking. [Runtime](runtime-and-storage.md) · [Measurement](measurement-and-delivery.md) · [Shared worlds](publishing-and-shared-worlds.md)                                                                                                               |
| Invent, install, learn, craft     | Someone **invents** a new method. The world can **install** an approved recipe. A character **learns** the method and can use it to **craft** an item when the required materials and tools are available. ## Using the convention

Use the label the player actually sees when giving interface directions. Quote the exact identifier when describing code. For example, the player opens **Journal → Commitments**. The code uses the key `promises`.

Give each distinct meaning its own row. Use a qualifier when the same word names different things, as in **gameplay receipt** and **provider receipt**. An acronym can share a row with its expansion, as in **heads-up display (HUD)**. Give related concepts separate definitions, even when the same individual fits both. The gatekeeper is an **actor** because the simulation tracks their actions and an **NPC** because the game controls that human character.
