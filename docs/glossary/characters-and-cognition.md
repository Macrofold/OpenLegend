# Characters, decisions and AI services

[Glossary index](README.md) · For the out-of-world assistant, see [World Agent](worlds-and-creation.md#creating-or-changing-a-world). For residence and participation, see [the character in the world](access-and-participation.md#the-character-in-the-world).

## Who is acting?

| Canonical term                   | Meaning in OpenLegend                                                                                                                                                                                                                                                                                                  | Source                                                                                                     |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Player, player character         | The player is the real person using the game. The player character is the character they play in the world. A player can be signed out while their account remains bound to their character.                                                                                                                           | [Account and character binding](access-and-participation.md#who-can-do-what)                               |
| Entity, actor, character         | An entity is an individually identified thing in a world. An actor is an entity with state for performing actions, such as a gatekeeper or hare. It remains an actor while unconscious. Use **character** for an individual in the story. A gate can be an entity without being an actor.                              | [Identity and references](../identity-and-references.md#contract)                                          |
| Controller                       | The role that determines how an actor receives decisions. The saved `actor.controller` values are `player`, `npc` and `native`. Inviting a player can change this field while the entity keeps its original `kind`. Species, capabilities and the account's permission to take control are checked separately.         | [Control and projection](../identity-and-references.md#control-and-projection)                             |
| NPC (non-player character)       | In OpenLegend prose, use **NPC** for a human character played by the game, such as a gatekeeper. An eligible NPC can become a player character when someone accepts an invitation and binds their account. The same person remains in the story.                                                                       | [Invitation and enrollment](../projects/completed/multiplayer-entry-maintenance.md#decisions)              |
| Rule-controlled animal           | An animal whose choices come from the installed world's rules. Base hares, for example, can flee through the `native` controller without asking a model. In this usage, **native** names how behavior is chosen. It applies in both the TypeScript and Rust implementations.                                           | [Base animal responses](../worlds/base/animal-responses.md#playable-purpose)                               |
| Animal with cognition and speech | A creator can grant those capabilities to a compatible animal. In the TypeScript implementation this can change its controller from `native` to `npc` while preserving the animal’s species and physical identity. When describing a code check, say **actor with the `npc` controller** if it includes these animals. | [God-mode capability grant](../../packages/domain/src/god-tools.ts)                                        |
| Narrator                         | Renders permitted events or experiences as prose for a player. A description of an injury cannot cause the injury or give another character knowledge of it.                                                                                                                                                           | [World events, private experience and narration](../narration-and-conversations.md#2-three-kinds-of-truth) |

## How characters decide and respond

| Canonical term                   | Meaning in OpenLegend                                                                                                                                                                                                                                                                            | Source                                                                                                                                                     |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Agency, cognition                | Agency is the character's ability to choose goals and actions. Cognition is the work of considering a situation, which can lead to speech, thought, an attempted action, a change of plan or no new action. A previously chosen plan can continue without a new model call.                      | [Character decisions](../agent-agency.md#2-a-decision-may-produce-nothing-one-thing-or-several-things)                                                     |
| Autonomous decision              | A character considers what to do on the game's initiative, for example after hearing someone nearby. A direct player conversation begins with the player's request. Either can lead to a model request. A hare fleeing under its world rules uses a different decision mechanism.                | [Reaction intake](../events-perception-and-reactions.md#one-intake-several-executors)                                                                      |
| Reaction opportunity             | A reason for this actor to reconsider, such as hearing a warning or finding a chosen path blocked. The game can continue existing work, use a world rule or admit a model request, depending on the opportunity.                                                                                 | [Events, stimuli and reactions](../events-perception-and-reactions.md#2-the-six-distinct-concepts)                                                         |
| Decision context                 | What the server can supply for this actor's particular decision, including permitted evidence, relevant prior experience and offered choices. A returned reference must still resolve to an allowed target.                                                                                      | [Actor context](../identity-and-references.md#actor-context)                                                                                               |
| Mind document                    | A character’s private record of how they understand themselves or their world, including beliefs, values and relationships. “They stole my berries” can be a mistaken belief even when “I saw them take berries” accurately records the event.                                                   | [What belongs in a character’s mind](../memory-architecture.md#what-belongs-in-a-characters-mind)                                                          |
| Private thought, reflection      | A thought records an in-character idea that can be mistaken. Reflection is a separate opportunity to reconsider experience and edit the character's private account of their life. Neither operation makes the contents audible or publishes the model's internal reasoning.                     | [Mental operations](../agent-agency.md#mental-and-external-operations) and [reflection](../memory-architecture.md#8-reflection-workspaces-and-publication) |
| Utterance, expression            | An utterance supplies words that may reach a listener. An expression is an observable gesture or descriptive attempt. The player’s **Speak** and **Act** controls create these different outcomes. Describing a blow in Act cannot damage the target.                                            | [Speech and descriptive actions](../narration-and-conversations.md#player-speak-and-descriptive-act)                                                       |
| Addressee, listener, witness     | The addressee is whom the speaker meant to address. Listeners are those who actually heard something. A witness may only have seen a person speaking. A directed utterance can reach a bystander more clearly than its intended recipient.                                                       | [Speech intent and audience](../narration-and-conversations.md#speech-intent-and-audience)                                                                 |
| Provider stream, accepted speech | A provider stream carries pieces of a model's response to the server. Words become an in-world utterance through the speech operation. Progressively committing approved passages before the whole reply finishes is a separately accepted design with implementation and qualification pending. | [Public NPC speech streaming](../ai-providers.md#accepted-public-npc-speech-streaming)                                                                     |

## What an AI request does

| Canonical term                          | Meaning in OpenLegend                                                                                                                                                                                                                                                                                                       | Source                                                                                                                            |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| AI, large language model (LLM)          | In provider and billing discussions, **AI** refers to model services the game can call. A large language model (LLM) can generate an NPC's proposed words from the supplied context. Use the specific operation when describing costs or behavior, because many NPC actions need no model at all.                           | [AI provider operations](../ai-providers.md)                                                                                      |
| Judgment, generation                    | A judgment answers supplied questions or rates offered choices. Generation produces new material, such as dialogue or a proposed action. Both use the character's permitted inputs. Only the game's normal validation and execution can change the world.                                                                   | [AI provider operations](../ai-providers.md)                                                                                      |
| Jev, TypeSafe, Noul                     | Jev is TypeSafe's judgment model. It can choose an offered option, assign a score or answer a **Noul** question with a value from zero to one estimating whether a condition holds. The `judge` operation is a kind of request and can also use other supported judgment models.                                            | [Provider behavior](../ai-providers.md#provider-behavior-and-limits)                                                              |
| Macrofold, model, provider              | Macrofold is a service through which the server can send a request to a configured model or run a hosted agent. The model produces an answer. A provider or intermediary can report its own request ID, timing and charge. A Macrofold **Worker** hosts agent execution and is separate from simulation threads.            | [Macrofold routes](../ai-providers.md#current-macrofold-routes) and [Workers](../ai-providers.md#shared-worker-setup-and-cutover) |
| Job, provider request, provider receipt | A job is an application task, such as preparing and applying an NPC decision. It can end before any provider request starts or require several requests. A provider receipt records what happened to one request, including known or uncertain usage. Whether proposed gameplay effects were accepted is a separate result. | [Admission](../ai-providers.md#admission-and-cancellation) and [receipts](../ai-providers.md#receipts-outcomes-and-accounting)    |
| Spending reservation, settled usage     | A reservation holds part of the available allowance before dispatch. Settlement records attributable use, or retains a hold while the charge is unresolved. Cancelling a job can prevent future work while still leaving a charge for work already dispatched.                                                              | [Provider accounting](../ai-providers.md#receipts-outcomes-and-accounting)                                                        |
