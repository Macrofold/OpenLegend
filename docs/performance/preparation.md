# Preparation, reuse and retained data

Part of the [performance contract](../performance.md). Read for the matching mechanism; historical results qualify only their recorded workload and revision. [Verification](../../.agents/rules/verification.md) selects checks.

Separate finishing the available candidate pass from proving complete source coverage. An unchanged incomplete source waits for relevant evidence or an existing required deadline; it must not repeatedly rescan the same known rows merely because unknown information remains unknown.

## Growing command-result collections

Recording or checking one prior command must not copy every previous result merely to obtain a writable snapshot. The current exact-key command collection shares unchanged balanced-tree branches; its lookup, update, deletion, enumeration and current-format validation have one owner. Saved logical record IDs/bodies remain independent of this runtime layout, and the existing canonical record codec still owns database/checkpoint reconstruction. Receipt insertion order is irrelevant, so only this collection uses neutral storage positions. Entity and history order are unchanged, and no retained command is pruned.

The measured benefit is age-dependent: fresh fixed-work CPU is neutral; the compared older-world fixed workload uses4.93%less total CPU. Real older service phases also improve but complete different work. Neither result establishes smooth3×or fixes database waits. ## Design recurring work before implementation

For a new passive process, repeated query or publication loop, identify what grows independently: eligible objects, nearby overlapping structures, observers, simulated intervals and retained receipts/history. Estimate work across those dimensions, including cold membership/index rebuilds and projection/commit costs. A bounded graph inside one object does not bound world-wide scanning each interval. Use existing membership and bounds indexes to reject irrelevant candidates before exact work, and admit the complete required transition; exhaustion cannot silently skip a material, support failure or observer. A small representative workload cannot establish settlement capacity or retained-memory bounds.

Separate active lookup from retained accounting. Completing work that needs a few held materials should query those live holds through the existing reservation owner, rather than rescan every finished receipt for each selected item. Retained receipts still count toward admission and cold reconstruction; do not delete them or raise an allowance to make a benchmark pass. Measure the complete caller with both current work and growing retained history. The [shelter review](../verification/editable-shelters.md#post-delivery-review-october-7) demonstrates this distinction with five live holds and separately bounded history fixtures.

For repeated totals, counts or pending-work checks over an append-only journal, reconstruct derived values once and update them from each newly committed event using the same rules as replay. Keep the journal authoritative and update derived financial values only after the required durable write succeeds. Compare live updates with reconstruction for interleaved, unfinished and uncertain attempts. The [benchmark tooling audit](../verification/decision-benchmark-audit.md#reproduction-and-tooling-limits) identifies the current accounting and export owners.

Separate structural inputs, collection membership and changing values when choosing cache dependencies. A moisture or clock update need not rebuild unchanged roof geometry or material choices; custody, definition, attachment or geometry changes must invalidate the data they affect. Reuse the owning immutable inputs or revision contracts, not the outer world object's identity or a fingerprint recomputed for every candidate. Mutable draft identity does not prove unchanged contents: candidate queries must read current candidate geometry, and reuse of an unchanged committed input needs the owner's evidence that it is unchanged. Keep caches derived; reconstruct transient caches from restored authority and validate any reusable derived artifacts through their owning dependency contract. No cache becomes another saved authority.

Material exposure reads the latest entity, item and definition records through the existing read-only draft view, including child records already drafted in the current transition. This avoids creating writable child drafts while merely checking cloth/fiber membership, placement and moisture. Preparation is synchronous and never retained across an interval; actual indexes and writes keep the original world owner, and captured rain/family references keep their existing paths. Cache eligibility, material order and wetting/drying rules are unchanged. [PF16.135 evidence](../verification/performance/19-material-preparation.md) separates the matched older-world CPU saving from unresolved command latency and sustained qualification.

A cached subshape needs its own immutable inputs or exact dependencies: incrementing a containing map revision does not invalidate a cache keyed by a mutable panel object. Freeze owned derived shapes and recompute mutable provider shapes. Before constructing motion crossings, skip a footprint whose position and height did not change. The [shelter follow-on measurements](../verification/editable-shelters.md#corrected-contact-and-single-bay-lean-to-october-7) preserve exact results and separately report bounded warm/cold costs; neither technique establishes larger-world capacity. Existing design/performance/review routes load this guidance before recurring or physical work.

When a compound operation validates in an isolated candidate, apply its actual writes through the receiving mutable transition and transfer the affected owners' derived indexes. Adopting whole frozen branches can break a later write in that same interval; copying the whole world to avoid it adds history-dependent cost. Exercise a zero-duration custody change followed by ordinary state/work updates, and compare derived accounting with reconstruction from current authority. Temporary draft inputs must not evict shared immutable geometry. The [state transition contract](../architecture.md#state-and-transitions) and shelter evidence record this boundary.

Skip a steady-value process only when its law cannot change the result over that interval and the next relevant weather, motion, attachment or permission boundary is still handled. Batching and shared reads must retain exact scope, ordering and required effects. Choose a bounded read cadence, preserve cancellation and share identical in-flight reads when their scope/snapshot permits; clock updates must not create overlapping refreshes without an admitted purpose. The [performance workflow](../../.agents/skills/openlegend-performance/SKILL.md) owns matched measurements and the decision to add further indexing, workers or regional execution after unnecessary work is removed. These are design requirements, not a claim that all current consumers are incremental or qualified at scale.

Before predicting the next meter/status boundary, prepare the installed numeric definitions, relevant condition/drain thresholds, first-ID lookup and health classification once for that synchronous forecast. Reuse that preparation across its existing boundary readers, and skip unchanged-rate values before reading them. Dynamic actor values, body-dependent ranges and condition matches remain live. Preparation ends with the call: it is not a long-lived world cache. Preserve the existing authoring distinction between original installed clock definitions and current metadata/health definitions; changing that visibility policy is a separate behavior change. [Exact comparisons and measured CPU benefit](../verification/performance/02-native-render-and-route-trials.md#sharing-installed-attribute-rules-within-a-forecast) retain mutable-authoring, full-transition and service limits.

## Inactive history residency

Canonical SQL rows retain all permitted memory, awareness and summary sources. Residency is not recall eligibility or forgetting. Ordinary service recovery filters source rows before decoding their bodies; ordinary commits release inactive sources only after durable publication. The accepted record baseline tracks that release separately from semantic deletion, and durable ordinals preserve append order across eviction and restart.

The working set keeps six game hours of personal memory records and unresolved commitments. Awareness is a durable SQL stream with an ordinary resident tail of at most 256 records per actor and a 1 MiB preparation allowance; the latest 24 records remain resident even if they exceed that byte allowance, preserving native observation continuity. The latest eligible ongoing personally received agreement also remains resident outside that tail/byte target, including assent whose unseen withdrawal is unknown. Current-source metadata is maintained only for changed agreements, source edits/deletion, forgetting and correction. Recovery selects the indexed current sources alongside the indexed tail before loading bodies; it does not scan retained history for each relationship. Completed/expired terms return to ordinary history residency. Eviction changes placement only: SQL retrieval, pending evidence and maintenance still see all eligible sources. Summaries stay in SQL. Global hot events retain their recent tail plus dependencies of resident evidence and knowledge. Cold evidence does not pin its entire global event history in RAM. Recovery enumerates actor-owner rows and seeks each actor’s indexed awareness tail and list maximum. Recent personal memories and unresolved commitments use separate indexed selections; no retained-history DISTINCT or grouped maximum is required. The [current database format](../save-and-load.md#playable-week-format-gate) rejects incompatible layouts before initialization, under the development-save policy.

Recall, paged editors, the god mind inspector, the player's optional memory panel, invention context and world-assistant context use scoped database selection. Optional text is hydrated only after selection; exact vector search remains the existing recall owner. Lexical context searches use the existing stored tsvector/GIN projection; broad matches still have corpus-dependent ranking cost. Read results require current source/generation checks. Optional history reads use the independent read lane rather than holding the simulation mutation queue.

Maintenance uses indexed SQL outside the mutation queue to select a chronological prefix of at most 128 sources. Its 512 KiB allowance applies before payload hydration and again to the prepared evidence. Publication materializes only the selected identities and bounded event aliases through the existing mutation owner, then rechecks source revisions and generation. Daily progress records a fixed upper revision and cursor so accepted summaries cannot re-enter the same review. Creator event edits, character-memory edits, correction and forgetting prepare the indexed transitive dependency set on the read lane, then reject any intervening world publication before atomic mutation. Unrelated cold source bodies are not loaded. All appraisals belonging to affected actors are loaded because privacy invalidation must also scrub terminal records. Preparation has no new source cap or automatic retry; large affected sets can still exhaust the existing read deadline or memory. Checkpoints stream stable database pages in one owned worker after a short revision barrier; [save limits](../save-and-load.md#current-history-capture-boundary) and [measurements](../verification/checkpoints-and-recovery.md#bounded-history-checkpoints-and-recovery) distinguish capture from paused reconstruction/install costs. Personal memory records can still grow inside the six-hour window; awareness no longer grows with the complete window. A single admitted transition can temporarily hold its complete output until commit. The SQL commit precedes resident-tail eviction. All current physical entities still reside in one simulation process; regional residency remains a separate target.

Dense acquisition preserves every distinct event, recipient, RNG draw and native transition. The implementation builds recent encounter membership once per observer, reuses actor-name patterns and personal perspective text, and seals newly detached event/experience values at the end of the mutation so draft finalization does not repeatedly traverse them. Registered changed history arrays are snapshotted and sealed before generic finalization, with exact immutable-prefix checks preserving append proofs and conservative handling of edits/deletes/forks. Private motion slices retain only encounter dependencies between phases. These reduce traversal/copy overhead; they do not eliminate immutable array copies or actual observer-by-subject work. [PF08/PF09](../maintainers/performance.md) and [measured evidence](../verification/data-runtime-hardening.md#data-runtime-hardening) retain the remaining capacity gates.

## Simulation CPU and growing history

Position baselines and event-observer candidate indexes copy only the scalar fields they retain. They do not snapshot complete actors, plans or bodies just to capture a position and sight range. Exact sight checks still use current world geometry; the later encounter phase retains its full phase snapshot where required.

Read immutable installed attribute/sense/status definitions outside draft proxies only where admission replaces them wholesale. Mutable actor state instead uses the existing current read-only draft view: pure meter, condition, effect-rate, participation and capability reads see every preceding write without creating drafts for unchanged children. Native contribution review inspects ordinary status membership read-only and reacquires writable records only for its existing lifecycle operations. Derived membership indexes keep their actual owning container keys; body-profile results retain detached snapshots for modified body drafts. Re-read status membership after each ordered rule so an earlier activation/deactivation affects the next rule. Body-health mappings, earned practice, missing values and individual rule-test charges retain their owning operations; the view is neither cached truth nor writable authority. Bounded visibility caches must degrade to uncached exact queries at capacity rather than evicting the whole working set on each sequential scan. Cache limits restrict retained optimization state, not the number of sources perceived.

The encounter-preparation owner combines its existing audited sensory-field changes with the draft owner's exact inserted/replaced/deleted entity IDs. Its bounded per-draft union retains an ID after an insertion is later deleted, and incomplete or overflowing coverage remains conservative for the rest of that draft. Raw newly installed descendants are inspected through the same sensory dependencies. Physical membership changes refresh authoritative root order and body-size maxima; publication drops draft-only coverage, and forks without the current exclusive cache ownership rebuild. Unsupported writes still rebuild from current authority. This avoids re-reading every physical entity after known custody or resource changes without weakening visibility, contact, observer order or evidence.

Exact ray-family projection reuses the spatial owner's prepared map shapes and query-local hull. Its separating-axis and plane checks traverse the same ordered dense geometry with scalar loops, and edge cross products pass scalar components rather than allocating temporary vectors. This reduces temporary allocation without changing numeric operations, tolerances, candidates, sight/contact classifiers or native charges. It adds no global scratch or second geometry cache; [measured allocation and neutral CPU results](../verification/performance/03-saving-and-render-preparation.md#scalar-ray-projection) qualify this narrower improvement.

The proposed [spatial validity contract](../events-perception-and-reactions.md#6-spatial-work-and-invalidation) covers event-time geometry and receiver/source invalidation; performance budgets and escalation gates remain here.

Preserve the accepted [elapsed-time contract](../simulation-time.md), ordered consequential outcomes and saved randomness while reducing repeated work. One-game-second integration was an implementation choice, not a clock requirement. The finite native loop compiles sorted actor/animal/heat IDs once per call and reuses them across accepted intervals; status eligibility also includes applicable non-actor entities. Nested plan-command transitions refresh the roster. Future native spawning or component changes must refresh it at their mutation boundary. IDs, not draft entities, survive draft replacement. Without eligible observers, sensing produces no evidence; lifecycle cleanup and feature baselines remain authoritative. Finite elapsed integration is implemented under [PF13](../maintainers/simulation-time.md); unsupported coupled laws retain the documented fallback. This does not authorize merging independent commands or skipping unmodeled physical/sensory effects.

Actor observation assembly omits private routes/state before one final deep copy. Returned records remain isolated; do not substitute an aliased public view or a persistent copy of private plans. Candidate selection and required evidence remain the existing owners' responsibility.

The remaining CPU candidates are:

- Reuse the delivered actor-initialization boundary for traits, minds and installed policy when loading/creating actors or changing capabilities, rather than reintroducing full-actor initialization during every save. - Preserve the implemented draft-local source-ID index for append admission. It scans retained IDs once per mutation-owner draft array, then maintains membership on accepted additions; it does not duplicate writable experience. Non-add changes invalidate it, array replacement obtains a new identity, and raw mutable builders use live lookup. Duplicate, owner, forgotten-source and obligation checks remain required. Benchmark targeted freezing or narrower drafts before changing the immutability strategy; do not replace Immer wholesale without evidence.
- Maintain reusable indexes for outstanding commitments, recently changed actors and event IDs. In larger worlds add spatial candidate sets and dirty-region invalidation; distance is a candidate filter, not an authorization rule.

Actual game-time throughput must cover the selected clock rate with headroom for commands, persistence and publication. Use the installed [world clock policy](../simulation-time.md#independent-clocks), not an engine-wide seconds-per-second constant; elapsed time owed is not a transition count. The number of integration intervals depends on mechanical deadlines and fidelity limits. A fast timer cannot compensate for excessive total work or an oversized atomic interval. Establish an immutable snapshot boundary that lets finalization skip unchanged retained branches; preserve mutable world construction and current-format initialization, append lineage and privacy invalidation. Measure both initial freezing and steady-state growth, rather than counting only a short pre-frozen run.

Distinguish overload from actual process suspension. Accept a bounded prefix and release mutation ownership before yielding between batches; continue catch-up without waiting for another routine timer interval. Bound catch-up work without discarding admitted simulation debt or allowing causal reordering. A long batch must not be interpreted as offline absence merely because the next timer interval exceeds two seconds. Keep genuine suspension and player-presence semantics explicit.

Optional diagnostics, narration/provider work and optional view reads can run independently; authoritative transitions and command receipts still require ordered acceptance. Checkpoint encoding can use a captured immutable revision outside the mutation lane only with revision-safe installation. Moving CPU-heavy finalization to a Promise does not remove blocking; moving it to a worker does not increase that world's single-worker throughput. Reduce the measured traversal before adding workers or database lanes.

Keep authoritative hot state bounded by active entities and required working memory. Long-lived events, completed jobs, epoch-bound gameplay receipts and UI scrollback already use durable repositories; [inactive history residency](#inactive-history-residency) describes current loaded-state selection. Further reductions must preserve cold lookup for referenced IDs and complete current-format restore, not revive an old-layout migration or remove required resident evidence. A cache eviction is not permission to delete historical truth. Current controller and timeline permissions are separately revalidated; they are not substitutes for that retry epoch. Retained source memory and optional consolidation pressure do not gate native simulation or authorize evidence deletion.

Finite linear needs/work integration is now implemented. Regional idle scheduling and general analytical/coupled systems remain candidates: preserve threshold crossings, event-time awareness, path conflicts, action completion, stable ordering and random choices, or explicitly record an accepted gameplay change. Do not lower fidelity silently to advertise a higher population.

Perception should read position and capability scalars once after movement, query local candidates, compare prior membership with sets and preserve unchanged visibility-array identities. ### Preparing complete results

Where an existing size allowance applies, before copying growing explanation paths or constructing a complete retained result, check whether a provable size lower bound already exceeds that allowance. Count the representation that will actually be retained, including serialization escaping and encoding differences. Refuse early only when that proof cannot reject a result that fits; preserve admitted content and the final exact size check. Avoid repeatedly serializing the growing result just to measure it. This can bound otherwise quadratic explanation copying; it does not bound relationship extraction, validation or historical loading, which need their own complete-path measurements. [Batch 09 review evidence](../verification/reviewed-content-removal.md#explanation-construction-and-exactness) demonstrates the oversized-path case under an unchanged detail allowance.

For exports/reports that legitimately include a growing complete collection, bound the construction working set as well as the write queue. Where the format permits, serialize and release bounded rows/chunks with backpressure; an asynchronous write after constructing a whole object and JSON string still pays for synchronous serialization and both allocations. Preserve required output bytes, ordering, atomicity and durability. Measure peak memory separately from retained data: bounded output does not make eager preparation of every unselected view cheap. The [benchmark tooling audit](../verification/decision-benchmark-audit.md#reproduction-and-tooling-limits) records the retained eager-construction limit.

## Design and review guidance

Remove unnecessary work first: meaningful change triggers, conservative rejection before exact queries, bounded candidates, existing indexes, shared immutable definitions and dependency-correct caches. Include observer scope, geometry/state revisions and lifecycle in invalidation; prefer relevant participant/item/region and component changes over global revisions when they completely cover the result. Budget exhaustion is not evidence of absence or unreachability. Hearing filtering must preserve actually audible recipients and privacy/intelligibility semantics.

Before expanding actor/tool choices across targets, separate actor/tool prerequisites from target-dependent checks. Reject proved unusable equipment or actor recovery once through their existing owners, then prepare only remaining combinations. Reuse remains request/snapshot-scoped and never grants later execution; every offered exact command still needs current admission. Count avoided and remaining combinations as well as elapsed time. [AV02's complete-caller review](../verification/shield-defense.md#second-implementation-review--october-7-2026) reduced repeated checks without hiding valid choices; its large-inventory measurements still exposed preparation before final selection.

Match the query to the caller's required answer. Validate a known exact identity directly instead of enumerating a collection to find it; stop existence/first-match searches once answered, and build a full result list only when needed. Use the relevant indexed subset for discovery. Direct and collection queries must share the owning access, compatibility and current-definition checks; a cheaper read cannot bypass them. [AV02's equipment review](../verification/shield-defense.md#follow-up-review) demonstrates the repeated-list cost and bounded improvement, not a universal timing target.

Separate cheap status/eligibility from historical text hydration. Reuse compact status once per caller batch, and select permitted evidence IDs before indexed, bounded detail reads; do not render history for every menu entry or visible person. For participant-local work, follow the participant's owned relation rather than scanning every active relation per update or per ending. A necessary publication-wide reconciliation runs once at its semantic boundary. Emit a newly satisfied condition once; suppress redundant announcements, never distinct actual outcomes.

Derived selectors should hold immutable IDs/scalars or owned copies, never draft proxies or a second writable gameplay claim. Prefer the existing exact-write publication lifecycle and ordered/spatial helpers. Verify cold construction, warm reuse, insert/remove/move, cancellation, death/retirement, fork and restore cases relevant to the selector; unknown mutation coverage rebuilds. Increasing unrelated inert objects separately from living density/history exposes different costs. Do not generalize one warm snapshot measurement into full-server or population acceptance. [Sling review evidence](../verification/practical-competence.md#requested-review--october-6-2026) records the concrete repeated-scan and body-filter failures.

Explicitly look for duplicate or overlapping queries across callers and consider reusing already-fetched data, fetching only missing data, or sharing identical in-flight reads. Reuse must match the required fields, permissions/observer scope and state or transaction snapshot. Prefer request-scoped reuse; longer-lived caches need clear ownership, bounded storage and complete invalidation, including edits, deletions and restores. Keep shared results read-only and indexes derived from their existing authoritative owner. Measure the complete path to confirm a real reduction in work without stale or unauthorized data.

Retain an operation's exact owned immutable preparation through later storage or disclosure waits instead of retrieving it again from a shared recent cache. Another request replacing that cache does not invalidate the retained facts; actual dependencies and current authority still need checking at final use. Trace every inspection, preview, comparison, check and admission caller of shared native validation against its promised answer: a caller offering a completed check must await its required deferred preparation; a status-only read may explicitly report incomplete work. Unavailable/exhausted preparation remains incomplete rather than absence. A successful sibling caller does not qualify it. [Batch 07 review](../verification/playable-world-creation.md#october-13-requested-complete-change-review) demonstrates both failures through actual awaited callers.

Key derived work to its actual dependencies, not the whole world's revision. For example, unchanged cover geometry can survive a moisture update, while eligible-object membership changes with custody/definitions and current position/moisture must still be read live. Reuse an existing owner's immutable identity or revision only when its update contract proves those dependencies; mutable builders/drafts need a live read unless the owner proves safe reuse. A cache accelerates a query, never authorizes an effect. Validate or rebuild reuse after restoration and bound retention through the owner's lifecycle. [The shelter review](../verification/editable-shelters.md#delivery-review) records actual reuse and invalidation checks.

Writing already-earned numeric values into otherwise unchanged records can also invalidate unrelated spatial or sensory preparation by changing record identities. Before normalizing a whole set for prediction or reading, distinguish consumers that require owned writes from those that can use the current-value owner. Audit raw readers before removing a write barrier, and compare complete current values and continuation rather than requiring identical stored anchors; include extra replay and downstream preparation in the measured cost. [The forecast comparison](../verification/performance/save-and-publication-followthrough.md#forecast-result-fewer-character-rewrites-lower-finite-simulation-cost) demonstrates this consequence without changing the arithmetic law.

### Repeated readers and fresh projections

Before building a repeated reader, count the scans, compilation and allocations per row and across its callers. A bounded page can still rescan all carried stock or revalidate the same definition for every row. Put shared preparation at the existing quantity/query/validation owner, using indexed membership and one compatible read scope; do not make each display invent its own totals. Hoist or memoize shared parent/container/owner calculations (access checks, ancestor chains, observer names, placement) and stateless helpers (such as `TextEncoder`) outside per-row loops so paging evaluates each `ownerId` once ([missing-belonging review](../verification/parallel-batch-08-the-missing-belonging.md#4-performance-query-plans-and-product-assessment-my05)). Separate the cold preparation cost from warm reuse and instrument work counts as well as elapsed time. [Expedition evidence](../verification/rewarding-expeditions.md#requested-review--october-6-2026) shows why 16 records caused 32 compilations and repeated stock scans despite bounded paging; it does not establish a universal timing budget.

Separate exact definition validity from current permission, deliberate inspection, learned knowledge and executable stock. Reuse successful exact validation only where the owner guarantees immutable data and a complete dependency key; drafts/builders, changed snapshots and restore must see fresh values. A frozen outer object alone does not prove its contents immutable. Cached facts grant no disclosure or execution; preserve the owner's current authority checks. Retaining failed/partial checks also needs an explicit dependency contract. Weak ownership can release old snapshots; it does not establish correctness by itself.

For calculations depending only on an immutable definition, key reuse by that original definition before allocating stripped copies or wrappers: a fresh object per row defeats identity-based memoization. Stable definition identity alone cannot justify retaining world-dependent validation across changed worlds; first establish the compiler/query's complete dependencies. [Second expedition review](../verification/rewarding-expeditions.md#second-requested-review--october-7-2026) distinguishes reusable recipe identity from fresh published-world validation.

Derive projection/memo dependencies from every displayed fact, not only the list's membership revision. Inspection/selection and learned knowledge can change while item identities and quantities stay identical. Verify the actual downstream display immediately after the relevant change, without an unrelated simulation tick masking a missing dependency; also check access revocation, changed definitions/materials and independent observers where relevant. Exercise changes initiated outside the selected component as well as its own successful mutations, including removal of facts and actions that are no longer permitted. Shared calculations must preserve current refusal, privacy and mutation checks. For client refresh/late-read behavior, frontend work also follows [React mutation guidance](../ui-ux/react.md#effects-asynchronous-work-and-mutations).

Simulation time is also a dependency: countdowns and timed availability can change while every entity object and revision stays identical. Reuse timed facts only until their next meaningful display or eligibility boundary, using the displayed time bucket or deadline as appropriate; do not invalidate unrelated untimed facts on every clock tick. Exercise a clock-only advance with unchanged entity identity through the actual downstream description or offer. [The rivals review](../verification/rivals-and-contested-ground.md#requested-full-branch-review--october-9-2026) found a stationary character's recovery stuck at 120 seconds when it should have displayed 115.

Share target-independent scans, sorting, exact assignments and definition-signature calculations once within the unchanged permitted read; copy mutable command bindings for individual choices. Trace the existing mutation owner's revision/invalidation before adding a cache dependency: an existing ancestor revision may already cover nested contents or holds, while a global dependency needlessly refreshes unrelated choices. Verify through the actual mutation owner. A cache or prepared read never authorizes later execution.

Verify reuse through the runtime's snapshots or wrappers, not just plain fixture objects: unchanged eligible definitions should reuse work, while direct and nested edits must recompute their meaning. [The second river review](../verification/river-meal.md#second-requested-review--october-7-2026) demonstrates both cases.

For exact assignment/search, reject provable shortages before branching, solve independent requirements separately and skip equivalent candidates only when every relevant constraint agrees. Keep specifically selected identities distinct; future quality, provenance or other requirements must enter the equivalence relation. A work ceiling protects failure, but can still permit a visible stall: exercise an impossible ambiguous case as well as a valid case. Exhaustion remains incomplete computation, not absence. [The river review](../verification/river-meal.md#requested-implementation-review) demonstrates these issues without establishing a universal timing target.
