## Growing command-result collections

Recording or checking one prior command must not copy every previous result merely to obtain a writable snapshot. The current exact-key command collection shares unchanged balanced-tree branches; its lookup, update, deletion, enumeration and current-format validation have one owner. Saved logical record IDs/bodies remain independent of this runtime layout, and the existing canonical record codec still owns database/checkpoint reconstruction. Receipt insertion order is irrelevant, so only this collection uses neutral storage positions. Entity and history order are unchanged, and no retained command is pruned.

The measured benefit is age-dependent: fresh fixed-work CPU is neutral; the compared older-world fixed workload uses4.93%less total CPU. Real older service phases also improve but complete different work. Neither result establishes smooth3×or fixes database waits. [Complete experiment and limits](verification/performance/18-command-record-layout.md).

## Design recurring work before implementation

For a new passive process, repeated query or publication loop, identify what grows independently: eligible objects, nearby overlapping structures, observers, simulated intervals and retained receipts/history. Estimate work across those dimensions, including cold membership/index rebuilds and projection/commit costs. A bounded graph inside one object does not bound world-wide scanning each interval. Use existing membership and bounds indexes to reject irrelevant candidates before exact work, and admit the complete required transition; exhaustion cannot silently skip a material, support failure or observer. A small representative workload cannot establish settlement capacity or retained-memory bounds.

Separate active lookup from retained accounting. Completing work that needs a few held materials should query those live holds through the existing reservation owner, rather than rescan every finished receipt for each selected item. Retained receipts still count toward admission and cold reconstruction; do not delete them or raise an allowance to make a benchmark pass. Measure the complete caller with both current work and growing retained history. The [shelter review](verification/editable-shelters.md#post-delivery-review-october-7) demonstrates this distinction with five live holds and separately bounded history fixtures.

For repeated totals, counts or pending-work checks over an append-only journal, reconstruct derived values once and update them from each newly committed event using the same rules as replay. Keep the journal authoritative and update derived financial values only after the required durable write succeeds. Compare live updates with reconstruction for interleaved, unfinished and uncertain attempts. The [benchmark tooling audit](verification/decision-benchmark-audit.md#reproduction-and-tooling-limits) identifies the current accounting and export owners.

Separate structural inputs, collection membership and changing values when choosing cache dependencies. A moisture or clock update need not rebuild unchanged roof geometry or material choices; custody, definition, attachment or geometry changes must invalidate the data they affect. Reuse the owning immutable inputs or revision contracts, not the outer world object's identity or a fingerprint recomputed for every candidate. Mutable draft identity does not prove unchanged contents: candidate queries must read current candidate geometry, and reuse of an unchanged committed input needs the owner's evidence that it is unchanged. Keep caches derived; reconstruct transient caches from restored authority and validate any reusable derived artifacts through their owning dependency contract. No cache becomes another saved authority.

Material exposure reads the latest entity, item and definition records through the existing read-only draft view, including child records already drafted in the current transition. This avoids creating writable child drafts while merely checking cloth/fiber membership, placement and moisture. Preparation is synchronous and never retained across an interval; actual indexes and writes keep the original world owner, and captured rain/family references keep their existing paths. Cache eligibility, material order and wetting/drying rules are unchanged. [PF16.135 evidence](verification/performance/19-material-preparation.md) separates the matched older-world CPU saving from unresolved command latency and sustained qualification.

A cached subshape needs its own immutable inputs or exact dependencies: incrementing a containing map revision does not invalidate a cache keyed by a mutable panel object. Freeze owned derived shapes and recompute mutable provider shapes. Before constructing motion crossings, skip a footprint whose position and height did not change. The [shelter follow-on measurements](verification/editable-shelters.md#corrected-contact-and-single-bay-lean-to-october-7) preserve exact results and separately report bounded warm/cold costs; neither technique establishes larger-world capacity. Existing design/performance/review routes load this guidance before recurring or physical work.

When a compound operation validates in an isolated candidate, apply its actual writes through the receiving mutable transition and transfer the affected owners' derived indexes. Adopting whole frozen branches can break a later write in that same interval; copying the whole world to avoid it adds history-dependent cost. Exercise a zero-duration custody change followed by ordinary state/work updates, and compare derived accounting with reconstruction from current authority. Temporary draft inputs must not evict shared immutable geometry. The [state transition contract](architecture.md#state-and-transitions) and shelter evidence record this boundary.

Skip a steady-value process only when its law cannot change the result over that interval and the next relevant weather, motion, attachment or permission boundary is still handled. Batching and shared reads must retain exact scope, ordering and required effects. Choose a bounded read cadence, preserve cancellation and share identical in-flight reads when their scope/snapshot permits; clock updates must not create overlapping refreshes without an admitted purpose. The [performance workflow](../.agents/skills/openlegend-performance/SKILL.md) owns matched measurements and the decision to add further indexing, workers or regional execution after unnecessary work is removed. These are design requirements, not a claim that all current consumers are incremental or qualified at scale.

Before predicting the next meter/status boundary, prepare the installed numeric definitions, relevant condition/drain thresholds, first-ID lookup and health classification once for that synchronous forecast. Reuse that preparation across its existing boundary readers, and skip unchanged-rate values before reading them. Dynamic actor values, body-dependent ranges and condition matches remain live. Preparation ends with the call: it is not a long-lived world cache. Preserve the existing authoring distinction between original installed clock definitions and current metadata/health definitions; changing that visibility policy is a separate behavior change. [Exact comparisons and measured CPU benefit](verification/performance/02-native-render-and-route-trials.md#sharing-installed-attribute-rules-within-a-forecast) retain mutable-authoring, full-transition and service limits.

## Inactive history residency

Canonical SQL rows retain all permitted memory, awareness and summary sources. Residency is not recall eligibility or forgetting. Ordinary service recovery filters source rows before decoding their bodies; ordinary commits release inactive sources only after durable publication. The accepted record baseline tracks that release separately from semantic deletion, and durable ordinals preserve append order across eviction and restart.

The working set keeps six game hours of personal memory records and unresolved commitments. Awareness is a durable SQL stream with a resident tail of at most 256 records per actor and a 1 MiB preparation allowance; the latest 24 records remain resident even if they exceed that byte allowance, preserving native observation continuity. Recovery selects that tail before loading awareness bodies. Eviction changes placement only: SQL retrieval, pending evidence and maintenance still see all eligible sources. Summaries stay in SQL. Global hot events retain their recent tail plus dependencies of resident evidence and knowledge. Cold evidence does not pin its entire global event history in RAM. Recovery enumerates actor-owner rows and seeks each actor’s indexed awareness tail and list maximum. Recent personal memories and unresolved commitments use separate indexed selections; no retained-history DISTINCT or grouped maximum is required. The [current database format](save-and-load.md#playable-week-format-gate) rejects incompatible layouts before initialization, under the development-save policy.

Recall, paged editors, the god mind inspector, the player's optional memory panel, invention context and world-assistant context use scoped database selection. Optional text is hydrated only after selection; exact vector search remains the existing recall owner. Lexical context searches use the existing stored tsvector/GIN projection; broad matches still have corpus-dependent ranking cost. Read results require current source/generation checks. Optional history reads use the independent read lane rather than holding the simulation mutation queue.

Maintenance uses indexed SQL outside the mutation queue to select a chronological prefix of at most 128 sources. Its 512 KiB allowance applies before payload hydration and again to the prepared evidence. Publication materializes only the selected identities and bounded event aliases through the existing mutation owner, then rechecks source revisions and generation. Daily progress records a fixed upper revision and cursor so accepted summaries cannot re-enter the same review. Creator event edits, character-memory edits, correction and forgetting prepare the indexed transitive dependency set on the read lane, then reject any intervening world publication before atomic mutation. Unrelated cold source bodies are not loaded. All appraisals belonging to affected actors are loaded because privacy invalidation must also scrub terminal records. Preparation has no new source cap or automatic retry; large affected sets can still exhaust the existing read deadline or memory. Checkpoints stream stable database pages in one owned worker after a short revision barrier; [save limits](save-and-load.md#current-history-capture-boundary) and [measurements](verification/checkpoints-and-recovery.md#bounded-history-checkpoints-and-recovery) distinguish capture from paused reconstruction/install costs. Personal memory records can still grow inside the six-hour window; awareness no longer grows with the complete window. A single admitted transition can temporarily hold its complete output until commit. The SQL commit precedes resident-tail eviction. All current physical entities still reside in one simulation process; regional residency remains a separate target.

Dense acquisition preserves every distinct event, recipient, RNG draw and native transition. The implementation builds recent encounter membership once per observer, reuses actor-name patterns and personal perspective text, and seals newly detached event/experience values at the end of the mutation so draft finalization does not repeatedly traverse them. Registered changed history arrays are snapshotted and sealed before generic finalization, with exact immutable-prefix checks preserving append proofs and conservative handling of edits/deletes/forks. Private motion slices retain only encounter dependencies between phases. These reduce traversal/copy overhead; they do not eliminate immutable array copies or actual observer-by-subject work. [PF08/PF09](maintainers/performance.md) and [measured evidence](verification/data-runtime-hardening.md#data-runtime-hardening) retain the remaining capacity gates.

## Spatial cost and scheduling

[SW17–SW19](maintainers/spatial-world.md) own current spatial/presentation delivery and performance gates. The chosen backend is Recast/Detour, prepared and queried in a bounded reused worker rather than synchronously baking geometry during a command. Direct native moves remain cheap. A shared capsule/cylinder contract and exact support projection validate routes; full route cost includes that validation, not just Detour's inner search. Selective Rapier shape queries reuse static broad-phase geometry rather than synchronizing a second mutable physics world. Cold meshes, repeated profile/world replacement and resource disposal remain measured costs.

Existing idle map preparation may prepare one current grounded body through the saved controlled-character binding, with the first eligible existing root as fallback. Choose and copy the numeric body only when the existing map/timeline key changes; do not add per-tick actor scans, assume a human shape or create another authority/cache. Real requests already selected for dispatch keep their own body, but an in-flight speculative build is not preempted. This moves construction into loading rather than removing CPU work: unused body preparation, changed bodies and still-cold other profiles are explicit costs. The six-profile cache and every current body/map/action/timeline result fence remain unchanged. [Measured first-use behavior](verification/performance/02-native-render-and-route-trials.md#preparing-a-current-walking-body-before-its-first-route).

Required-data wait is technical preparation rather than an authored actor-action duration, but eligible real elapsed time is retained as ordinary simulation debt before a pending-route check returns. The native barrier still prevents integration until the current route clears; later bounded catch-up can charge hunger/deadlines and compress delayed travel. This supersedes the earlier technical-wait exclusion, which could discard an entire preceding busy host interval when a route became pending near its end. Preserve Pause/suspension/load debt clearing and current command/result fences. Deferred navigation elapsed is a subset of admitted active time, not an additional disjoint clock category. Do not block the writer or create one worker per actor. Track queue, build/query, native admission/finalization, durable commit/projection, transport and GPU separately. Additional workers, incremental tiles and state partitioning follow measured saturation, not an assumed universal library speedup. No profile/geometry limits were raised based on benchmark medians.

Renderer load is separate: many lit sprites, proxy shadows, shadowed point lights, overlapping read-through fragments, camera updates and alpha picking can dominate. Reuse materials/masks/meshes, keep lights bounded and avoid target-by-occluder CPU raycasts. Do not cull genuine authorized details or sensory evidence to manufacture a performance result. Eligibility/readability and dynamic lighting semantics belong to [World presentation](world-presentation.md).

A further 90% whole-game reduction requires end-to-end attribution (PF00), not repeated optimization of an already sub-millisecond inner query. Existing native participant, independent-copy and experience-membership improvements remain; genuine first-acquisition work, external-event fan-out, snapshots and synchronous finalization remain distinct costs. Detailed deferred cases live in SW19/PF and maintainer TODO, not a competing performance list here.

## Navigation failure and shutdown

Navigation workers are derived computation, not persistence authority. Normal exit while active, asynchronous worker errors and synchronous launch/message-clone failures use the same bounded failure path. Mutation-lane overload retains the single computed reply and retries publication after one real second, without rerunning navigation. Actual persistence failure pauses on the existing storage-error boundary rather than repeatedly recomputing an uncommittable result. No new work starts while storage is faulted. Shutdown drains in-flight result publication and already-started termination before closing the store; replaced worlds fence results by existing map/timeline/action identity. Worker failure and stale retirement remain distinct metrics. A queue waiting on required data never becomes a false no-route answer. Optional speculative body-build failure is counted separately and leaves a valid prepared map usable; a later actual request still performs its normal build/query and reports any real failure. Failed speculative preparation does not create an idle retry loop. If a successfully generated mesh cannot acquire its query wrapper before entering the cache, release that unowned mesh and rethrow; the generator already frees its ordinary unsuccessful result.

## Selected approach

The owner delegates overall architecture and performance decisions, including substantial redesign, and has withdrawn the arbitrary 20 ms retrieval target. Optimize complete interactions and sustained work under the [first-release and growth workloads](../archive/07-technical-architecture/data-delivery-and-scale.md#1-what-scaling-means-for-this-product); do not freeze the present pipeline or optimize only one query. Prefer less work, bounded active state, indexed scoped access, reusable validated results and batched changes. Measure tail latency, throughput, simulation progress, relevance, memory, storage and cost together. Existing small-world budgets are early regression guides, not final capacity proof. Record material tradeoffs and history-loss choices; privacy, action correctness and meaningful source fidelity remain requirements.

Make the cost of an interaction follow the entities and records it changes, rather than total world age, history, observers elsewhere or background activity. Keep one authoritative writer per world initially. Retain PostgreSQL durability, canonical record transactions and the existing durable story jobs, and optimize those owners before adding infrastructure.

Start by eliminating unnecessary queries and scans, batching necessary SQL, replacing idle polling with commit-triggered work, and separating gameplay publication from optional database reads. Reuse existing asynchronous I/O. Add a separate database lane, microbatch coordinator or worker only at its measured gate. More promises or threads do not reduce the amount of work, and an asynchronous query can still occupy the only connection ahead of a player command.

The requested 10,000× improvement is a direction for eliminating scaling multipliers, not a credible guaranteed speedup for one click. The deliverable is a responsive small world with explicit cost budgets, regression tests and a measured path to larger populations. Each optimization must improve its target metric without moving unbounded work elsewhere.

## Walking after the immediate fixes

1. The browser displays the destination marker immediately and sends the intention. It does not need to fetch the action catalogue first.
2. The authority validates the intention against loaded state and computes the movement transition. Native actor, ambient and exposure work yields private progress, with the server returning to the event loop after roughly 8 ms of work between yield points. The mutation owner and accumulated work meter remain held until the complete elapsed-time transition publishes. Between accepted intervals the server releases mutation ownership while retaining unadvanced game time as debt. Finalization and individual operations remain indivisible; this is not a maximum step-latency promise.
3. Prepare changed records, event-time audiences and permitted history capsules in memory. Persist them with the action receipt in one compact transaction. Ordinary event appends do not run edit/deletion cleanup.
4. Once commit succeeds, publish the action result and the player's affected view promptly. Conversation, usage and latest-narration database reads cannot gate the position/action update.
5. Notify eligible background consumers after commit. A plain movement start does not itself become a paid narration opportunity. Walking may produce a separate qualifying encounter or other meaningful event.

The database commit remains on the confirmed-action path. Keep the existing bounded routine-progress save policy; this design does not silently expand its crash-loss window to explicit commands. Client movement prediction is a later responsiveness improvement governed by the real-time specification, not proof that a command committed.

## Compact transactional persistence

Each event/observer perspective retains history access, ordering and an exact family/body-hash reference to that observer’s permitted account; there is no duplicate audience table. Current awareness bodies live in their canonical records, replaced/removed versions in the existing source-version archive. Independently rephrased history accounts use that archive explicitly. Shared account resolution reconstructs complete permitted evidence without copying each full body into the history row or substituting mutable global event text. Indexed columns support character-reply identity, permitted dialogue participants, speech type and conversation-related actions. Participant pages merge limited indexed streams. Event string references have a GIN projection for creator deletion safeguards. These projections cost disk and write work; they avoid repeatedly parsing unrelated event JSON. Record indexes have stable descriptive names, with short hashes for PostgreSQL's identifier limit, and source families only keep relevant indexes. Deleting an actor's source collection uses its exact indexed parent ID.

Normal startup reads a transactionally maintained retained-event count. Checkpoint capture and full recovery still compare that count to physical rows; the integrity tradeoff is owned by [save/load](save-and-load.md#current-history-capture-boundary).

Current canonical storage writes use typed compact row batches through the existing grouped writer, preserving complete byte/row admission, explicit columns, order, duplicate-create checks and dependency barriers. History and canonical record owners may share that bounded batch when no intervening consumer requires the writes; editing, forgetting, old-source reads, deletes and subsequent source joins keep their actual flush barriers. Recent character-result rows retain stable storage positions across ordinary rollover; true reordering and unsafe position exhaustion use complete renumbering. Exact changed entity/perception-binding lineage avoids rediscovering unchanged keys, with complete fallback for replaced, forked or unknown inputs.

The derived full-text vector/index is prepared after source commit using durable exact-revision keys. Exact account bodies, source eligibility, displayed-text history search and latest-place reads remain synchronous. Indexed context search waits for revision coverage and checks it again in its actual read snapshot. [Memory architecture](memory-architecture.md#implemented-retrieval-and-storage) and [MH15](limits/memory.md#mh15--delayed-lexical-preparation) own correctness and operational bounds. This removes a dependency from ordinary source saving, not the total index work; sustained backlog and command tails must qualify together.

### Fast append and deliberate edits

Use the application's unchanged/append/diff intent together with the domain draft’s append proof; caller hints alone cannot certify an unchanged prefix. For an admitted append, collect only appended events, calculate the shared event encoding once and bulk insert event rows and actor-scoped access/evidence perspectives. Resolve current-format history readiness once at startup and cache it only after a successful transaction; this does not authorize converting an incompatible development layout. Duplicate IDs and receipt conflicts must still fail or reconcile explicitly; an append hint is not permission to overwrite retained history.

Existing event edits, source corrections, forgetting and deletions use a separate branch of the same repository entrypoint. Their dependent story revocation, audience changes, vector invalidation and forgetting ledger remain atomic. Do not obtain speed by leaving stale private prose or evidence readable after revocation. Batch the affected IDs and load dependencies together instead of traversing SQL relationships once per record.

Prepare immutable lookup/delta inputs before opening the transaction when committed readiness is known. For dense history bursts, do not retain a second full set of prepared payloads: encode each source once into a bounded row buffer, flushing sources before their dependent rows within the same transaction. This deliberately keeps bounded encoding in the transaction rather than trading shorter lock time for unbounded temporary memory. Buffer limits count UTF-8 SQL parameter bytes and portable parameter counts; a single oversized record retains the existing one-record behavior. Preparation never authorizes a different or mutable snapshot. Prepare other bounded payloads before opening the transaction. Bound bulk writes by rows, bytes and database parameter limits. Persist changed canonical records, the head/CAS check, required history, job outcome and accepted mind changes under the same atomic boundary. Combine compatible metadata writes rather than adding per-feature round trips. Keep any complex PostgreSQL-specific statement inside a typed repository operation. Query count should grow with bounded batch chunks, not one query per witness or event.

Current checkpoints stream complete canonical records through one owned read-only worker. A short revision barrier releases gameplay mutation ownership after the snapshot is established; the repeatable-read transaction remains open while records are read and checkpoint output is written. The [capture deadline and worker watchdog](save-and-load.md#current-history-capture-boundary) bound that exposure and preserve the previous usable save on failure. File publication is atomic through the save owner, not a SQL transaction or a journal-prefix truncation. Required event perspectives and source revocations still commit with their authoritative changes. Moving any required projection to later work would need complete durable input, explicit lag/repair and privacy semantics under the existing data owners; the superseded journal-first layout is not a current implementation requirement.

### Preserve order without one global database bottleneck

Record writes group new rows separately from updated rows within each table, retaining bounded batches and insert-only duplicate detection. Tables with secondary unique indexes keep their original row order. This avoids alternating new/updated visibility records producing separate statements for every observer. Parent tables still precede children; dependent history, source eligibility and the world head remain in one atomic transaction. Job identity and completed-status protection are checked by the same upsert that writes the job.

The observer/subject sight-episode map explicitly has no insertion-order meaning: consumers resolve identities by key. Its codec therefore writes neutral ordinals and only changed bindings; a bird leaving view does not renumber every still-visible object. Reload may enumerate those map keys differently, but preserves every episode identity and disappearance/reappearance boundary. Entity order, visible-subject lists and history order retain their existing semantics. New collections must opt in only when all consumers are order-independent.

Gameplay writes retain one ordered writer connection and the advisory ownership lock. The independent bounded PostgreSQL read lane is already implemented for optional inspection and other scoped reads; reuse it rather than proposing that separation again. Bookkeeping writes still use their existing transaction owners. Remove idle queries and redundant writes before adding another connection for a measured bottleneck. No auxiliary connection may acquire a second world-writer lock or mutate world state through a side door.

A second connection removes application head-of-line waiting, not database contention. Keep its transactions short, queries indexed and deadlines bounded; long scans, shared-row locks and large writes can still hurt gameplay. Required reservations and uncertain paid receipts remain durable before dispatch/settlement under their existing accounting contract. Provider calls run outside SQL transactions and outside the mutation queue.

Cross-connection reads use captured scope/revision tokens and reject stale results on return. Revocation and publication compare authoritative source versions; optional caches or indexes never expand permission. No read replica, generic task broker or large connection pool is needed for this stage.

The shared work queue captures each submitting operation's asynchronous context. Waiting work must not inherit request, diagnostic or transaction context from the preceding operation. Transaction owners still establish their own active lifetime and publication hooks; queue ordering alone does not provide context isolation.

### Committed cognition metadata

The store shares concurrent and repeated reads of committed interest, reflection-queue and semantic-schedule records. Only encoded immutable values are retained; each consumer receives a separately parsed value. Explicit transactions bypass this cache so they see their own writes or their original read snapshot. Writes invalidate before execution and again after commit/rollback; restoring a game clears the whole cache before installation and after settlement. Cache eviction returns to SQL without dropping records. [Inventory and bounds](limits/cognition.md#cg03).

Conversation compaction uses separate SQL compare-and-swap writers and remains outside this cache. Accounting, authority and arbitrary integration keys also use their existing durable read paths. Adapters lacking transaction-state and publication hooks cannot enable shared metadata reads.

Unchanged committed memory/vector coverage counts return without opening a read transaction; transaction callers always query their own snapshot. Ordinary current-visibility/encounter-identity changes no longer invalidate retained-memory revisions or wake memory indexing. Actual awareness, memory, correction, forgetting, accepted-mind and restore changes retain their invalidation paths. These optimizations do not change what characters perceive or remember.

## Triggered background work

### Narrator

The durable story-job row is the queue. When a world commit or explicit regeneration actually creates eligible queued work, return a small after-commit signal with the world/owner and next eligibility time. Arm one timer for the earliest due job, using the configured causal batching window. Avoid resetting the timer on unrelated movement or postponing an existing batch indefinitely.

The runner claims a due job durably, releases the transaction, invokes the provider only after required spending admission, and publishes under the existing source-currentness checks. It then drains or schedules the next eligible job with bounded concurrency. Source privacy and job identity come from stored records, not the in-memory notification.

On startup, perform existing uncertain-work recovery and one bounded scan for queued/due work. On resume, drain pending wakeups and recompute the next due time. On shutdown, prevent new dispatch and reconcile in-flight claims according to the existing no-paid-retry contract. A wakeup received while the runner is active must survive its final cleanup: keep a dirty generation/next-due marker and recheck it before going idle. A crash between commit and notification is recovered by the startup scan. Because all current job creation is local and authoritative, no periodic empty database poll is necessary. External producers would require an explicit notification/reconciliation mechanism later.

This removes idle work, not durable job admission. Do not dispatch from an uncommitted transition, create a second queue table, or regenerate narration merely because a UI reloads.

### Cognition, maintenance and deadlines

The [internal-event integration](events-perception-and-reactions.md#7-internal-triggers-and-native-survival) (accepted for implementation within a named scope on 2026-09-28), [ongoing stimuli](events-perception-and-reactions.md#8-ongoing-salience-relevance-and-reminders), [actor intake](events-perception-and-reactions.md#9-reaction-intake-and-scheduling) and [consumer boundary](events-perception-and-reactions.md#10-transactions-subscriptions-and-secondary-consumers) define the inputs to this scheduling policy.

Only actors affected by newly perceived evidence, need crossings, action outcomes, relevant inventory/goal changes or elapsed deadlines become scheduling candidates. Retain recurring critical-need reminders, consolidation eligibility and sleep/day boundaries; event-driven does not mean ignoring the passage of time.

Start with small dirty-actor sets, cached scheduling state and one earliest-deadline timer. Rebuild scheduling indexes from saved state on startup; invalidate them after commit or restore. Distinguish real-time cooldown/batching deadlines from simulation-time hunger, commitments and sleep. Pausing or changing speed must not turn a game-time deadline into a stale wall-clock timeout.

The simulation timer must not await a full cognition-maintenance scheduling scan. It reports relevant changes and returns. Scheduling and model execution use bounded asynchronous capacity, with interactive work taking precedence over not-yet-started optional work. Do not cancel/retry paid work just to reclaim a slot. Per-agent spending limits do not imply unlimited host concurrency; use explicit host-wide concurrency and pending-work limits without changing billing policy.

### Browser and provider polling

Cache display-only usage totals by accounting changes and UTC month, sharing concurrent reads. Reservation, settlement (including late billing) and recovery invalidate the display snapshot only after their writes succeed. Budget admission must continue to query current durable spending; a display cache never authorizes a call.

Use scoped conversation/narration revisions on the existing SSE stream to invalidate visible history pages. Load once on opening, once on reconnect/reset and when that scope changes; fetch older pages only on demand. Keep a slow, backoff-based fallback only if the notification contract is unavailable. Hidden panels perform no history polling.

Keep presence heartbeats because they establish liveness, and retain diagnostics' existing visible-panel cadence while making reads coalesced, bounded and independent of gameplay. Provider operation polling may remain necessary where no reliable callback/stream exists; back off while idle, respect provider limits, and preserve receipt reconciliation. Do not treat all timers as defects.

## Simulation CPU and growing history

Position baselines and event-observer candidate indexes copy only the scalar fields they retain. They do not snapshot complete actors, plans or bodies just to capture a position and sight range. Exact sight checks still use current world geometry; the later encounter phase retains its full phase snapshot where required.

Mutable actor state instead uses the existing current read-only draft view: pure meter, condition, effect-rate, participation and capability reads see every preceding write without creating drafts for unchanged children. Native contribution review inspects ordinary status membership read-only and reacquires writable records only for its existing lifecycle operations. Re-read status membership after each ordered rule so an earlier activation/deactivation affects the next rule. Body-health mappings, earned practice, missing values and individual rule-test charges retain their owning operations; the view is neither cached truth nor writable authority. Bounded visibility caches must degrade to uncached exact queries at capacity rather than evicting the whole working set on each sequential scan. Cache limits restrict retained optimization state, not the number of sources perceived.

The encounter-preparation owner combines its existing audited sensory-field changes with the draft owner's exact inserted/replaced/deleted entity IDs. Its bounded per-draft union retains an ID after an insertion is later deleted, and incomplete or overflowing coverage remains conservative for the rest of that draft. Raw newly installed descendants are inspected through the same sensory dependencies. Physical membership changes refresh authoritative root order and body-size maxima; publication drops draft-only coverage, and forks without the current exclusive cache ownership rebuild. Unsupported writes still rebuild from current authority. This avoids re-reading every physical entity after known custody or resource changes without weakening visibility, contact, observer order or evidence.

Exact ray-family projection reuses the spatial owner's prepared map shapes and query-local hull. Its separating-axis and plane checks traverse the same ordered dense geometry with scalar loops, and edge cross products pass scalar components rather than allocating temporary vectors. This reduces temporary allocation without changing numeric operations, tolerances, candidates, sight/contact classifiers or native charges. It adds no global scratch or second geometry cache; [measured allocation and neutral CPU results](verification/performance/03-saving-and-render-preparation.md#scalar-ray-projection) qualify this narrower improvement.

The proposed [spatial validity contract](events-perception-and-reactions.md#6-spatial-work-and-invalidation) covers event-time geometry and receiver/source invalidation; performance budgets and escalation gates remain here.

Preserve the accepted [elapsed-time contract](simulation-time.md), ordered consequential outcomes and saved randomness while reducing repeated work. One-game-second integration was an implementation choice, not a clock requirement. ## Bounded batching, backpressure and publication

A single command on an idle healthy server should not wait for an artificial batch timer. When commands are already queued, a later microbatch can evaluate a bounded group in order against one candidate state and persist all receipts/effects together. Resolve each promise only from the committed batch. Keep one commit in flight; commands arriving during it wait in a bounded intention queue. Rejected, duplicate and conflicting IDs retain their own outcomes. Do not coalesce already-admitted discrete actions or suppress intermediate meaningful events.

Repeated unsent movement destinations may use the existing real-time design's explicit supersession contract when implemented. General action coalescing is unsafe: two eats, a pickup followed by craft, or stop followed by a new task are not interchangeable writes. Preserve fairness between players when adding multiplayer; priority must not silently reorder already-admitted causal work.

Buffers have byte/count/age limits and a defined overflow policy. Optional pending trace snapshots can be replaced by newer versions and report capture gaps. Visual updates can be recomputed from a compatible baseline. Accepted world events, source revocations, command receipts and spending records cannot be dropped. On actual storage failure, stop authoritative admission and expose degraded/paused state. Optional memory consolidation pressure is not that failure and must not stop walking. Queues smooth bursts, not sustained overload.

Scope cooldowns and stops to the resource whose limit was observed, sharing them across dependent workers. Skip that resource's unattempted entries without retiring workers needed for independent work; an aggregate spending ceiling still governs all its consumers. Check stops before expensive preparation and exercise mixed blocked and eligible work through the actual dispatcher, including resume when the stop is durable.

Player action responses follow durable commit immediately. Their affected public state coalesces at most once per 50 ms publication-start window, publishing immediately after idle instead of adding another 50 ms after work finishes, with bounded output and cooperative work between viewers; this measured shared-load tradeoff avoids redundant projection of intermediate revisions. Routine motion retains an independent cadence. Keep cached usage/narrator/history sections separate so a slow optional query cannot delay basic gameplay. New fields never reveal private events or world-global activity through unscoped revision counters.

Action acceptance and first visible movement are different milestones. The current 50 ms host wake improves on the former 250 ms opportunity, but does not require a fixed amount of native work or a frame per game second. Retain independent one-second background saves of simulation progress and coalesced optional publications. Measure movement latency against timer/projection overhead; client prediction remains the separate network-latency option. State delivery is not a rendering-frame limit.

## Scale path

World size, active population, observation density, retained history and concurrent players are independent dimensions. A thousand scattered actors and a thousand people observing the same event are different workloads. A thousand events per game minute also differs from a thousand per real minute at accelerated speed.

| Stage                                  | Intended architecture                                                                                                             | Gate before moving further                                                                                               |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Tiny world, including long sessions    | Existing process, compact atomic writes, triggered jobs, bounded hot-state CPU, cached scoped publication                         | Small-world budgets pass with optional AI/inspection load and retained history                                           |
| Roughly 100× entities/activity         | Spatial candidate indexes, dirty actors/components, batched durable writes, deadline scheduling, scoped pages and replication     | Representative distribution and crowded hotspot both measured; explicit queue and spending capacity                      |
| Roughly 1,000× world footprint/history | Hot/cold data separation, sleeping regions where semantics permit, one worker/owner per independent world or region when measured | Worker message volume, migration/recovery and boundary semantics proven; size is not assumed to mean all entities active |
| Thousands of concurrent actors/players | Fenced ownership and region/interest-based replication following the existing scale design                                        | Real load envelope, transfers, fairness, privacy, recovery and concentrated-crowd limits established                     |

The accepted product priority is a shared world divided into regions, with independent worlds also supported. Follow the [shared-world rollout](../archive/07-technical-architecture/data-delivery-and-scale.md#3-growth-stages-and-triggers): independently queryable records and bounded regional working sets first, then measured region CPU/storage distribution. Do not add Redis/Kafka, a generalized actor framework or one worker per creature without a consuming bottleneck. Multiple logical regions may share one writer/database until ownership and boundary interactions are qualified. Independent-world placement remains useful but does not qualify one crowded shared world. Actual audience delivery may legitimately cost proportional to the audience; no index can make thousands of real recipients free.

Keep CPU-bound work in a worker only when it removes a measured event-loop bottleneck after work reduction. A worker holding an entire world's active state should receive intentions and send permitted deltas, not exchange whole-world snapshots with the main thread every frame. Async PostgreSQL/provider I/O does not need a worker. Optional path/serialization jobs use versioned compact inputs and have their results revalidated by the owner.

## Bounded admission

World mutation lanes admit at most 256 pending operations; each PostgreSQL read/write lane admits 512. Pending work expires after five seconds, including an age check when a blocked event loop resumes. Already executing operations and transactions finish normally. HTTP limits simultaneous API handlers to four times configured player capacity and retained request bodies to 16 MiB, in addition to existing per-request body limits. Projection queue depth follows API capacity. Publication coalesces revisions within a 50 ms window measured from the preceding publication start and yields between viewers after roughly 8 ms, so a microtask chain cannot starve socket/command I/O. Disconnect cleanup retries after one second if queue admission expires; retries are bounded by admitted transports and never replay gameplay. Rejection is explicit `busy`/HTTP 503 with Retry-After; callers must check action status before retrying an uncertain mutation. Optional/background overload does not mark storage broken or pause the world. One writer, nested transaction ownership and durable receipts remain unchanged.

`OPEN_LEGEND_PLAYER_CAPACITY` defaults to 100 (configurable 1–10,000). Streams, service connections and projection caches allow three times this value, presence tracking six times, sessions max(4,096, sixteen times). These are coordinated admission settings, not measured population promises. [Verification](verification/immediate-gameplay-limits.md#immediate-gameplay-limits) distinguishes 100 actual connected synthetic accounts from live OIDC, hosted and simulation-speed qualification.

Perception retains derived exposure inputs and prior outputs across immutable transitions. An unchanged observer/nearby-source set reuses exposure membership; changes to geometry, senses, positions, life/memory capabilities or output identity force reevaluation. Moving contacts still receive their next stationary transition. Recovery rebuilds the cache. Work metering counts actual UTF-8 event bytes; the group output allowance is 64 MB because the release-size first crowd exposure legitimately emits over 16 MB. No audience or required outcome is trimmed. The profiler refuses rejected or nonadvancing steps instead of counting them as simulation throughput.

### Preparing complete results

Where an existing size allowance applies, before copying growing explanation paths or constructing a complete retained result, check whether a provable size lower bound already exceeds that allowance. Count the representation that will actually be retained, including serialization escaping and encoding differences. Refuse early only when that proof cannot reject a result that fits; preserve admitted content and the final exact size check. Avoid repeatedly serializing the growing result just to measure it. This can bound otherwise quadratic explanation copying; it does not bound relationship extraction, validation or historical loading, which need their own complete-path measurements. [Batch 09 review evidence](verification/reviewed-content-removal.md#explanation-construction-and-exactness) demonstrates the oversized-path case under an unchanged detail allowance.

For exports/reports that legitimately include a growing complete collection, bound the construction working set as well as the write queue. Where the format permits, serialize and release bounded rows/chunks with backpressure; an asynchronous write after constructing a whole object and JSON string still pays for synchronous serialization and both allocations. Preserve required output bytes, ordering, atomicity and durability. Measure peak memory separately from retained data: bounded output does not make eager preparation of every unselected view cheap. The [benchmark tooling audit](verification/decision-benchmark-audit.md#reproduction-and-tooling-limits) records the retained eager-construction limit.

## Eight-times spatial and sensory budget

This is the accepted optimization direction, not a declaration that every dense 8x workload has passed. PF12 sequences the broader PF/SW/EPR work; [PF13](maintainers/simulation-time.md) owns the finite elapsed-time delivery. [Earlier rebase evidence](verification/spatial-rebase-eightx.md) records the former per-second baseline; [current cadence evidence](verification/simulation-cadence.md) records actual elapsed progress and its limits.

### Define the rate before optimizing

The bundled world’s current clock policy has a base ratio of 60 game seconds per real second: 8x requests **480 game seconds per real second**, not eight. This is an elapsed-time target, not 480 required ticks. The former 2.08 ms-per-tick arithmetic does not impose an integration cadence. Measure total CPU per game-time span, actual interval counts and command tails, leaving headroom for durable boundaries, publication and GC. Yield private native work to I/O after roughly 8 ms between checkpoints; uncontended work targets 32 ms before returning a coherent world update, with an earlier coherent return when ordinary commands or reads are waiting. [NW12](limits/native-work.md#nw12) owns these separate targets and exceptions. Indivisible work and finalization can overrun either target; short samples do not prove a tail-latency guarantee.

Measure actual world-time progress against monotonic elapsed wall time, separately recording explicit pauses/suspension, admitted active time, the subset deferred behind required navigation, admitted debt, not-yet-admitted busy callback time, and queue age. Do not add deferred time to active time or normalize it away from wall-progress acceptance. A blocked native call is not completed simulation. Report cold preparation separately but also include its visible delay in command-to-movement latency. Retaining elapsed cannot make cold navigation instant or create CPU capacity for an overloaded world.

Use the starter scene, the 318-entity sensing workload and the earlier combined 329-entity/23-surface workload as reproducible cases, not population limits or a promise that every spatial distribution passes. Independently vary history, observer count, moving targets, sounds, profile count, stacked floors, render coverage and geometry edits. Short current-server results do not qualify every integrated sound/sight workload, long session or dense distribution; [joint evidence](verification/hearing-main-integration.md) retains its specific scope.

### Strict behavior and elastic presentation

| Preserve exactly                                                                                      | May reduce or defer within this contract                                                                    |
| ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Body clearance, intended support/floor, action timing, conservation and ordered consequential effects | Visual particles, decorative grass density, shadow detail/resolution and non-authoritative post-processing  |
| Character-specific sight/hearing and observer-private evidence; immediate revocation                  | Fewer redundant geometry queries when a conservative proof remains valid; never fewer legitimate recipients |
| Simulation time, retained admitted debt and ordered native effects                                    | Fewer replacement-only pose publications per real second, with smooth authorized presentation               |
| Existing command durability and forgetting/accounting boundaries                                      | Batched encodings/writes within existing transactions; no enlarged crash-loss window by stealth             |
| Read-through eligibility, meaningful interactions and native survival independent of camera position  | Camera-frustum render culling and distance/detail levels that do not affect simulation or knowledge         |

Do not cap heard speech, drop visibility entries, sleep offscreen actors or shorten sensory range to meet a benchmark. Elapsed integration must honor the accepted mechanical boundaries and explicit sampled-perception policy rather than blindly jumping through intermediate events. The current straight-line acoustic family is intentionally simpler than diffraction/reverberation; a new room-acoustic model is not a prerequisite to optimization.

### 1. Separate unchanged static work from changed agents

Cache **dependency-valid results**, not just individual ray intersections. A stationary observer looking at unchanged objects and geometry should not reconstruct the same static visible list every interval. Keep static object membership/poses separate from moving actor targets. Geometry, source identity/pose/body, observer pose/anchors/range/capability and detector policy are explicit invalidators; metadata/recognition remains freshly observer-scoped rather than cached with geometric visibility.

Use dirty entity/region work from the existing mutation owner and a phase-local scalar view, not a full-world deep copy into each worker. Snapshot/fork/load boundaries must not share mutable or revoked draft references. Unchanged exposure reuse and incremental source-bin membership are delivered by PW08/NP02, including old/new-neighborhood observer selection; [current query ownership](#shared-entity-queries-and-cognition-work) names the remaining roster, affected-observer and publication scans. Finer changed-target work remains gated by its measured cost. Preserve deterministic candidate/event order; unchanged arrays can be retained, while changed membership retains its acquisition/loss semantics.

More aggressive kinetic certificates are conditional: an outside-range pair may remain rejected until a conservative distance-to-boundary divided by relative maximum speed deadline, with immediate invalidation on teleport, sense or geometry changes. Range certificates do not prove unchanged line of sight. A skipped LOS query needs a valid swept-corridor/unchanged-geometry proof; otherwise perform the exact query. Do not implement arbitrary time throttles disguised as these proofs.

### 2. Invert hearing queries around receiver volumes

For sparse sounds, index eligible listeners' 3D sensory bounds and point-query the emission origin, rather than scan every world entity. Receiver ranges may differ, so do not assume one universal speaker radius. Use a bounds tree/hierarchical structure for very large extents rather than replicating them into unbounded hash cells. Resolve event-time availability, exact anchors, distance and transmission only for conservative candidates, then deliver to every qualified recipient in the established order.

The current thresholded transmission query is implemented: an admitted attenuation factor below the requested minimum proves rejection immediately, without constructing/sorting remaining crossings. Successful numeric answers and full-transmission callers retain canonical multiplication order. This relies on the finite family's factors being in [0,1]; amplifying authored media require new valid bounds. Do not prune a marginal multi-barrier product by a differently ordered floating-point approximation. The integrated [graded hearing implementation](hearing-and-speech.md) retains its validated candidate/transfer rules rather than copying this older binary threshold policy.

Reuse geometry-only acoustic transfer for identical emission/listener anchors and relevant geometry versions, separately applying event semantics and listener thresholds. Retain historical emission origins. Batch sounds sharing the same stable sensing boundary, not merely sounds arriving in the same wall-time interval. Full/muffled detection, localization and word/identity disclosure remain distinct EPR responsibilities. Playback mixing can be budgeted independently; the awareness ledger cannot lose events because the audio mixer is full.

### 3. Keep continuous travel cheap after a route is known

Retain Recast and the exact direct-path shortcut. Prewarm common profiles and reuse compatible prepared data; no per-actor WASM instance. Coalesce identical derived requests only when geometry, body envelope, support endpoints, traversal policy and knowledge scope all match. Keep the bounded worker/queue, deterministic admission and stale-result fences.

For static geometry, consider a revision/body-bound certificate for an accepted segment: following a subset of a validated swept capsule corridor should not redo every identical static query. Dynamic occupancy, current capabilities, support transitions, destination validity and state-dependent effects still need their checks. Far-away geometry changes could invalidate relevant tiles/segments rather than the entire world only after provenance and dirty-region coverage are complete. [PF12.6](maintainers/performance.md#pf12--eight-times-spatial-and-sensory-execution) evaluated these options: cheap warm queries, rare exact segment repeats and no production geometry-edit caller did not justify implementing them. Reopen only for a changed workload, not as unfinished accepted navigation delivery.

Whole-revision construction and first-use profile stalls remain measured limits. Bring forward affected-tile preparation when edits/content cause them; extra workers can improve responsiveness/parallel throughput but cannot repair excessive total work. The retained clock policy now deliberately charges eligible technical waiting time through ordinary catch-up, including needs/deadlines and delayed travel. Keep that fairness change explicit; it preserves elapsed time rather than removing preparation work or hiding its visible pause. Crowds/landing fairness and special traversal remain separately scoped features.

### 4. Stop paying for old state and irrelevant status rules

The host already has bounded routine persistence, frozen snapshots, append-aware history, bounded yielding and trigger-based background work. Reuse them rather than adding a second journal or universal queue. Conservative status participation and finite elapsed rates are implemented; richer applicability/deadline indexes remain candidates. Indefinite sleep/needs/wake effects still advance semantically.

Move genuinely cold historical data off repeated finalization/serialization paths under PF08 while retaining evidence, stable IDs, pending commitments, current knowledge and explicit durable reads. The [boundary catalogue](maintainers/simulation-boundaries.md) distinguishes integrated finite laws from general net-flow coupling, local schedules and analytical dormant worlds. An interval cannot skip an unmodeled interaction merely because a formula produces a plausible final number.

### 5. Separate simulation, replication and rendering rates

Simulation speed is not display refresh rate. Current public-state publication uses the leading 50 ms window described above. Further pose-only coalescing remains [PF12.7](maintainers/performance.md#pf12--eight-times-spatial-and-sensory-execution), distinct from that delivered shared-publication mechanism. Camera/animation render at device cadence, normally targeting 60 FPS or display refresh. Action acknowledgement, removals, authorization revocation and ordered story/speech/effect records must not wait for a pose throttle. Slow clients resume from authoritative scoped state plus reliable history, not a backlog of every obsolete pose. Never send an NPC's future path to make interpolation easy.

Measure browser/SSE/React work separately from the server native budget. If optimized aggregate work still monopolizes the host, evaluate one long-lived simulation owner worker receiving commands and sending permitted deltas, not full-world copies every tick. This is PF10's gated ownership change, not an additional competing world writer. Async syntax does not offload CPU.

### 6. Batch render cost without altering the world

Shared sprite-shadow submissions and grass instancing are delivered under [SW18.13/SW18.15](maintainers/spatial-world.md); their named M1 Pro workload does not close all frame tails or lower-end-device qualification. Reuse those implementations and select further model/reveal batching or resource atlases from residual profiles, rather than rebuilding shadow and foliage batching. Group by compatible material and spatial chunk, preserving per-instance alpha, virtual depth, orientation and reveal data. Whole-scene instancing can defeat culling; chunk by camera and light influence and retain offscreen casters whose shadows reach visible receivers.

Avoid regenerating unchanged static shadow contributions; invalidate on light, relevant geometry/caster and shadow-volume changes. Camera-dependent cascades may still require updates. Keep the principal sun and a bounded local-shadow budget. Expose reduced-quality presentation rather than silently changing bodily sight/hearing or removing meaningful nearby items. Actual hardware-GPU measurements determine shadow/material/overdraw budgets; software-rendered frame rates do not establish desktop capacity.

Further sealed-room/portal rejection, hierarchical route planners, simulation workers and regional partitioning follow evidence. A coarse region graph may conservatively reject impossible work; it cannot invent visibility, erase overlapping floors or grant hidden topology. The near-term strategy is less repeated work at one authoritative boundary, not a replacement engine. [PF13](maintainers/simulation-time.md) owns the current finite elapsed-time slice and its specific remaining work.

## Native burst execution boundary

A native candidate may expose cooperative checkpoints, but not a partial world. The application keeps the writer lease while servicing I/O against the preceding snapshot; commands run after a coherent prefix is accepted. Main's boundary-limited elapsed integration and private motion slices remain the simulation contract. Host yielding does not defer required evidence to a later game tick. Finalization and other indivisible operations remain separately measured gates for further work. ## Optional measurement

A disabled recorder must skip its preparation: optional clock reads, argument scans, peak statistics, arrays, timers and listeners. Keep the actual byte limits, deadlines and other facts needed for gameplay or safe resource use. Optional observation must preserve the operation’s execution and result; decoding a request for a report must not prevent the original request from reaching its authoritative validator.

Keep resource ownership, saved progress and failure handling independent of whether statistics exist. Bind asynchronous measurements to their exact recording session; Stop releases pending measurement resources and prevents late work from entering a later recording. ## Storage execution

Reusable SQL statements classify their table dependencies only when first needed outside an existing transaction, then retain that result. Each execution still checks current transaction and journal alignment; inactive or already-protected execution skips the parsing. A proven idle journal skips only the waiting timer; the actual database view still proves its saved revision. World rows and their history audit share one snapshot. Validation then checks those independently captured values after releasing the reader, and only a successful load can replace the accepted baseline. A load failure cannot restore a previously lost baseline. Memory search checks readiness once inside its actual read view and waits outside that view when preparation is incomplete.

Delayed-save constraint preparation belongs to one exact save attempt. Unsupported/oversize preparation chooses ordinary saving before encoding or append; live parent membership, pending changes, permissions, expected revision and receipt admission remain under the writer. A live suitability refusal is an ordinary fallback outcome; corruption, authority and storage errors still fail without an automatic retry. [PSF01–PSF06](maintainers/performance-safeguards.md) links focused evidence and measured limitations.

Before adding, widening or removing an index, identify both the reads it serves and how often its table changes. Each maintained index can add CPU, dirty pages and recovery-log writes even when a query returns few records. Measure representative inserts/updates and dependent reads, including absent-key and growing-history cases; report statement work separately from complete transaction and gameplay latency. Overlapping keys are a reason to investigate, not proof an index is redundant. Preserving every index is also not proof of preserving search cost: inspect the rows actually visited. An enforced single-value field may be omitted from a non-unique physical lookup key only while its owning constraints prove that premise; preserve complete identity and permission predicates and name the contract change that would invalidate it. [The fixed memory-write comparison](verification/performance/59-fixed-memory-index-burst.md) demonstrates substantially less recovery-log work without a dependable complete-operation gain.

Describe the actual cache preparation behind storage measurements. Reading or hashing a complete table before a search warms that data; repeating a search before explaining it is also warmed evidence. A fresh database, connection or process alone does not establish cold database or operating-system caches. Preserve warmed correctness/search results and explicitly leave first-use behavior unqualified when it was not measured; do not flush shared caches or change global settings to manufacture a cold case.

Independent world-record table writes and history source/perspective inserts now share bounded parameterized write statements through the existing PostgreSQL transaction. The writer explicitly supplies independent writes; there is no universal deferred-write queue. A repeated table, 64 writes, 10,000 parameters or approximately 256 KiB starts another group. Original oversized single statements remain admitted alone. Re-parenting writes complete before record deletes, and memory-index reads/upkeep remain separate after preceding writes. Revision/authority checks and final commit retain their ordinary awaited boundaries. Transaction start and its local timeout travel together. The default is enabled; `OPEN_LEGEND_SQL_WRITE_GROUPS=off` restores separate waits for matched diagnosis. [PF16.7/PF15](maintainers/performance.md#october-14-expanded-3-investigation) retains full-path performance/failure qualification; grouping implementation is not smooth-scene acceptance.

The final history group also updates the retained-event total from the complete explicit inserted/deleted count. This independent update does not read newly inserted event rows. The group checks exactly one returned total row before returning; a missing total refuses and rolls back the transaction. Intermediate bounded history flushes accumulate inserted counts, and only the single final flush applies their total. Initial total creation completes first. This changes request grouping, not retained history, count integrity or acknowledgement durability.

Key-only observer and correction dictionaries share publication-certified changed keys through canonical saving. Outer observer ownership and exact source-to-correcting-evidence maps carry no insertion-order chronology; ordered evidence and other ordered collections retain their existing order. Replaced maps, forks, mutable construction and missing/long weak lineage use complete comparison. The [October17 codec comparison](verification/performance/overhaul-storage-implementation.md#reopened-changed-key-coverage--october-17-2026) removes full dictionary enumeration for a single edit in 10,000 corrections, without claiming a whole-game speedup.

New recall metadata is inserted with current eligibility rather than immediately updating that indexed value from zero. The memory owner shares its existing eligibility expression and bounded row batching; its [transaction ordering](memory-architecture.md#implemented-retrieval-and-storage) preserves archival provenance and dependent-source/privacy reconciliation. The data-stress metric includes both archive preparation and the subsequent source insertion, excluding the intervening canonical record write as before. Matched four-case viewer measurements show a small, variable progress improvement, not complete 3× capacity; [the evidence](verification/performance/01-interaction-and-early-server.md#initial-recall-eligibility-within-the-world-commit) separates SQL callback waits from database execution.

When a world commit finishes a durable character decision, the store merges its completion fields into that job in one parameterized update. Other diagnostic/request/invention fields remain intact, missing jobs stay absent, and a completed job still resists a later failed result. The returned stored and payload fingerprints retain the original integrity refusal within the same world transaction. Later meaningful AI diagnostic publication remains separate; this removes a read round trip without delaying or weakening the committed outcome. The first successful completion time survives later diagnostic updates. The exact immediate operational jobs upsert uses the owning raw adapter while retaining any enclosing transaction: the generic table classifier otherwise mistakes its `DO UPDATE SET` clause for a table and drains unrelated pending world changes. This narrow route grants no gameplay or spending authority and does not loosen canonical readers' consistency checks. [Scoped verification](verification/performance/04-earlier-long-runs-and-cognition.md#durable-decision-job-completion).

Ordinary HTTP admission reads the current login session, world grant and control in one indexed SQL snapshot. Account/session-only routes keep their narrower read. There is no cross-request authority reuse: expiry, later disclosure and transactional commit fences remain. A read started before a committed authority change cannot repopulate the old session cache. [October17 evidence](verification/performance/overhaul-storage-implementation.md#reopened-request-admission--october-17-2026) records two reads versus one, positive query-plan coverage and held-logout checks; no whole-game latency gain is claimed.

PostgreSQL is the sole backend. Independent bounded reader/writer lanes preserve transaction ownership and admission deadlines; an owned read-only checkpoint worker streams fixed-revision records. SQL batching, callback construction, JSON encoding and dense native work still require complete-path measurement. Main-isolate heap is not total process memory; process RSS includes worker memory and phase-end samples are not peaks. The previous SQLite writer/read-worker implementation was removed because there is no embedded/offline product requirement; historical measurements retain their original scope.

The [current PostgreSQL adapter](../apps/server/src/postgres.ts) routes a prepared read outside an active transaction to its reader only when the SQL begins with a non-locking `SELECT`. Leading `WITH` or a SQL comment does not select that path; the same logically read-only query can otherwise occupy the ordered writer. Keep read-only CTEs inside an outer `SELECT`, or use the existing explicit read transaction when a consistent multi-query snapshot is required. Locking reads and writes retain their owning transaction. When adding or changing SQL selection/recovery work, verify the actual connection and transaction path as well as its query plan; `async` and a bounded result alone do not keep it off gameplay commits. [Creation receipt recovery](../apps/server/src/world-agent-store.ts) uses the outer-select form while selecting records before hydrating retained candidate bodies.

## Hearing review and lower routine-history cost

The September 27 continuation changes the base world's [sighting policy](memory-architecture.md#encounters-sensory-detail-and-reminder-continuity): ordinary animal/scenery visibility does not create stored onset records; person sightings remain evidence without automatic reasoning. Earlier statements about preserving every encounter describe the earlier behavior-preserving optimizations. Existing stored history, exact current visibility, event-time hearing fragments and meaningful action/detail events remain intact.

Computed navigation results use the existing routine-progress buffer after the action/request has committed. They no longer require a second save before walking can begin. A crash before the next ordinary save can lose that computed route; restart prepares it again from the saved request. Late results cannot publish after a storage failure or across map/timeline changes. Explicit action acknowledgments, accounting and source revocation retain their existing durability. Results of background jobs (AI and other asynchronous work) that return the identical world and have no receipt, response job or invalidation skip an empty synchronous save.

Diagnostics now coalesce for 100 ms and drain at most 64 call snapshots through bounded multi-row writes, retaining the existing backlog/retention limits and shutdown drain. Their optional delay does not apply to accounting. The September 27 text-encoded multi-statement experiment was discarded because its benefit did not justify the extra SQL encoding path. October 14 implements the separate parameterized approach described in [Storage execution](#storage-execution); the larger [PF15](maintainers/performance.md#pf15--save-round-trip-batching) proposal and four-round-trip target remain open. Required save work remains atomic. Since the ordered-save change, simulation progress uses [background saves](save-and-load.md#background-and-synchronous-world-saves) that no longer block the next mutation while awaiting storage; commands, AI results and other effects still use synchronous saves that hold the queue until written, and smoothness under storage/host stalls is **not yet qualified** ([evidence](verification/ordered-async-saves.md)). [Current measurements and limitations](verification/performance/05-september-history.md#hearing-review-continuation-september-27) retain cold/warm latency, offered speech, host load and remaining acceptance.
