# Simulation time and update cadence

This is the canonical clock/integration contract. [Performance](performance.md) owns measurement and optimization; [PF13](maintainers/simulation-time.md#pf13--elapsed-time-simulation) owns delivery. The [boundary catalogue](maintainers/simulation-boundaries.md) is a running inventory of exact deadlines, conservative limits and still-unknown bounds, not a promise that every scenario is event-driven already.

**Selected perception-runtime replacement, not implemented:** [the design](projects/attention-and-scenes-runtime-design.md#41-sight-scheduling-without-predicting-the-future) keeps physical/native ordering and this clock, but replaces uniform broad sight with aligned change-fed broad/detail acquisition at the [world-owned rates](worlds/base/attention.md#selected-acquisition-cadence). Required occurrences retain their actual boundaries; optional cognition and physical reclamation do not hold ordinary advancement. This is actual-change invalidation, not prediction of future visibility crossings.

## Player time controls

P toggles manual pause/resume. Shift + ] selects the next faster speed and Shift + [ the next slower speed from the current 0.5×, 1×, 3× and 8× control choices, stopping at either end. These shortcuts use the same server requests as the visible controls; speed changes do not resume a paused world. Typing, composition, active popups, held-key repeats and disconnected states do not trigger time changes. Pause/resume remains unavailable during maintenance; changing speed does not release that pause. Projection switching remains available on the camera toolbar; P no longer changes projection.

## Product-scalability time and detail targets

**Accepted direction, not implemented by the current speed control.** [Participation and clocks](product-scalability/participation-and-protection.md) specifies a future option to advance an authored calendar independently of mechanical activity. A date can advance rapidly without making movement, fire-starting, or cognition proportionally faster. Aging, needs, seasons, work, appointments, memory maintenance, and campaign commitments must each declare their clock before this option is enabled. Current elapsed game-time behavior below remains unchanged until explicit integration; [PS05](maintainers/product-scalability.md) owns that cross-feature gate and [PS-L11](limits/product-scalability.md#ps-l11--clocks) records the pending policy.

[Background progression](product-scalability/background-progression.md) separately permits declared coarse activity and fewer optional cognitive initiatives. This is not permission to drop owed mechanical time or reclassify accepted obligations as optional. Missed optional thoughts do not become future debt. A faster calendar does not automatically enqueue one inference or one callback for every crossed day; actual required coupled transitions still need supported bounded handling.

An activity's estimated completion remains conditional on unchanged inputs. A relevant alarm, encounter, resource mutation, or command brings affected work through the actual occurrence time before interruption or continuation. The engine cannot commit a roof's future completion ahead of an earlier interaction that is still unresolved. Observer evidence is determined at the occurrence; knowing about an invader in server state is not character awareness.

Future coarse outcomes need not equal a detailed counterfactual, but must respect committed history, world law, resources, permissions, and scoped evidence. Promotion materializes a valid present and unresolved work, not a replay or invented history. Existing conflicts, random outcomes, and protection at detailed entry must survive mode changes and restoration. This changes supported world semantics only when the relevant family and policy are explicitly implemented; it is not a silent relaxation of the current integration and sensing guarantees.

## Independent clocks

The bundled world's default rate is 60 game seconds per real second at 1x. This converts elapsed time; it does **not** prescribe 60 simulation transitions per real second. The simulation accepts elapsed game time and divides it only where a relevant mechanical boundary or explicit fidelity bound requires it. Faster clock settings increase the time owed, not a mandatory number of whole-world ticks. At 8x the clock owes 480 game seconds per real second; the number of integration intervals depends on activity, not that number.

Rendering runs independently at the browser/device frame cadence (normally aiming at 60 FPS or the display refresh rate). State delivery can be less frequent. The current [50 ms public-state publication window](performance/scheduling.md#bounded-batching-backpressure-and-publication) is not a 20 FPS rendering limit; finer pose-only delivery remains separate work. Camera/input remain responsive between state arrivals; visual interpolation never authorizes movement or reveals an NPC's future plan. Thin walls still require swept collision, not endpoint-only checks. Unknown intermediate support/topology must not be filled in with invented motion through floors.

The [base-world time policy](worlds/base/time.md) owns the current horizon, displacement bounds and coupled-rate fallbacks. Those are revisitable fidelity choices, not requirements for every authored world. A sparse-update implementation must report its actual interval count, elapsed progress and largest blocking slice; changing the clock label or hiding accumulated debt is not a performance improvement.

## Native interval contract

A native interval has a start time, a finite elapsed duration and an end time. Resolve currently due native decisions, status transitions and zero-duration action stage changes at the start. Integrate the already-active rates/work over the interval. Commit completions, expiry, body changes and permitted observations at the end, then reconsider before consuming more time. An action created at the end cannot receive the preceding interval's work. A condition that changes at the end cannot retroactively govern that interval.

Predictions used by sensing, aiming, collision and boundary selection follow the same admitted movement and execution order as the actual transition. Independent per-body predictions are insufficient when earlier movers change later clearance. A shorter ordered forecast need not be a prefix of the longer one; recompute affected motion and bounds when shortening changes that dependency. Share an unchanged ordered read; reuse a shorter interval only when its owner proves that it preserves the same executed prefix.

Periodic status changes contribute their next elapsed-time multiple as an exact boundary. Their saved effect episode already owns elapsed progress; there is no second pulse counter or browser timer. Due changes commit in the body-before-action phase and remain distinct even when two effects hit the same body together. The scheduler cannot advance across an uncommitted periodic hit. Whole-point health rejects continuous status rates because rounding on arbitrary slice boundaries would change outcomes.

When a native caller consumes several completed intervals before publication, teaching requests and observation still reconcile before the next interval starts. A learner leaving the coach's sight at such a boundary ends that episode even if they return before publication. Existing feedback completion alone grants earned credit. A requested publication during unfinished motion retains the ordinary final reconciliation; this is not a guarantee to observe every brief loss entirely between checked boundaries. The game service can share compatible intervals within its existing I/O/coherent-return budgets; every multi-interval caller shares this correctness rule.

Choose the next interval using the earliest relevant known boundary and a finite fallback horizon. Examples include action completion, support/route waypoints, depletion/capacity, effect conditions, daily-window edges, wandering/perch timers, landing, death and obligation/conversation deadlines. Conditional rates are selected from the interval's starting state. Reevaluate after a command, geometry edit, capability change or load. Rates, participant lists and sight/contact predictions remain derived. The remaining time until the current mechanical sampling boundary, and an exact ending deadline when present, are saved in the existing world settings record: restarting that progress changed contact evidence times and saved revisions. Load rebuilds current bounds and uses the earlier of their duration and the retained remainder. It never extends a freshly established deadline. A changed publication discards inherited progress; native advance supplies a newly owned remainder, while no-op validation and pause/resume preserve it. Reject nonfinite, exhausted, over-horizon or inconsistent saved progress. This preserves the current sampling rule across restoration, without saving derived rates or geometry.

Motion deadlines use private slices inside a shared mechanical interval. Known rates and non-urgent decisions can be reused until their deadline or a relevant mutation; silent status changes invalidate through the semantic owner, not an optional event log. Other moving bodies advance before simultaneous landing reservations, which retain identity order; flight evidence then uses the synchronized receivers and captured source origin. Existing movement-before-endpoint-rate/effect ordering remains. A slice that only moves bodies leaves other entities' captured rates pending; they are applied through the same operators before any occurrence, work completion, command, re-prediction or reader that needs them, and coherent checkpoints preserve the validated exact calculations needed to recover current values. Work that starts without an event, such as on arrival, discards the kept prediction so its completion is bounded. Encounter baselines retain only their perception dependencies. A caller may request publication at a coherent slice boundary; no partial draft or per-actor private clock escapes. Mechanical rates/deadlines, including a pending local re-prediction, survive publication under the exact frozen native successor identity, so carrying them across a call end does not change later outcomes; commands, edits and recovery rebuild those mechanical forecasts. Derived sight/contact calculations belong to one native call. They may survive its shared mechanical rebuilds under the complete revalidation below, but every later call, including a loaded world, starts from current poses. Reusing calculations with an older time origin across publication changed exact observation times and identities after loading; these disposable predictions no longer carry that scheduling choice between calls. The finite slice limits are owned by [NW12](limits/native-work.md#nw12).

Eligible uncoupled sparse numeric status rates also retain their exact ordered arithmetic across coherent publications. One world-owned bounded operation window supplies pure current values/revisions, effect elapsed time and charged work; reading never changes the world. One episode can retain several independent ordinary meters and ordered same-sign additions, with elapsed time/accounting charged once. A clamped or zero rate preserves time/accounting without a fictitious meter revision. Actual foreign target/source dependencies remain eager; roles bound to the same subject do not create a foreign dependency. Threshold crossings, competing writers, periodic/health/reservoir work and unproved dependencies remain eager. Commands settle their actor’s retained values before mutation; navigation completion settles its answered actors. Exact target attribute/effect/work owners settle their affected episodes. Unrelated actors retain their continuations; generic editable drafts keep the complete materialization barrier. Rebuilding a forecast by itself retains supported earned operations: forecast consumers use current-value readers, while actual setters, episode changes, changed calculation groups and bounded compaction settle their values. This avoids copying every character solely to predict the next interval. Synchronous and background saves now persist that same bounded window with its stored starting values, instead of settling it on every save. Checkpoints capture the same canonical continuation. Current-format loading validates the stored starting values, exact links and ordered operations, then a separately materialized current view. It rebuilds derived forecasts and never replays effects. Pure history residency can preserve the process-local forecast only after the domain proves that unresolved promises, running action records and all mechanical roots remain unchanged. Ordinary edits retain conservative invalidation. This extends internal representation, not game time or the installed numerical law. [NW17](limits/native-work.md#nw17--anchored-continuous-native-values) owns the bound and [current evidence](verification/performance/overhaul-simulation-implementation.md) separates correctness from capacity.

Eligible fixed-route walking can reuse a shared body forecast even when the action belongs to a plan, provided no active chosen continuous control or shared status/territorial dependency requires a common stop. Movement still samples conservatively and reconciles the plan each slice; arrival ends the shared forecast before admitting another step. The action saves its remaining permitted travel between samples, so unrelated private steps cannot restart that allowance. Animals keep their existing invocation phases. An expired bird wait prepares takeoff at that endpoint without displacement. Different arithmetic subdivisions can change last-bit numbers and operation revision counts; [the October17 comparison](verification/performance/overhaul-simulation-implementation.md#reopened-planned-walking--october-17-2026) records that tradeoff and exact same-version continuation separately from whole-game capacity.

Silent action completion and every native decision outcome reconcile changed
behavior before forecast reuse. In particular, stopping an old escape while
waiting for another route changes movement and rate inputs immediately; waiting
does not preserve the old walking action. Unrelated participants can retain their
forecasts through the existing local-change checks.

Separate exact arithmetic from sensing fidelity. Straight movement is continuous and swept. Installed vision definitions may select a positive game-time sampling cadence; routine sight then uses current geometry at bounded intervals without predicting future visibility crossings. Installed vision explicitly selects boundary-triggered routine noticing or cadence-only routine noticing. The latter stores each observer's original sampling epoch, next sample, installed-definition fingerprint and physical life; initial observation/waking happens now and schedules the next sample from that instant. Recurring deadlines use the original epoch plus an integer number of periods, rather than repeated addition: mathematically coincident native deadlines must not drift into separate whole-world phases. Due comparisons remain exact; an attention deadline never buys an early physical sample. Save/load retains the partial period, and unrelated work does not restart it. Established sight/contact clocks still bound an update after observing bodies stop moving; overdue clocks request a current check without replaying missed observations. Scheduling and recording select the same observers; quiet native bodies retire clocks they no longer consume. Main selects cadence-only noticing at its installed three-game-second period. Unsampled vision, precise body contact, deliberately chosen watching and finite approach controls retain their crossing calculations. Installed contact definitions may instead sample incidental awareness through their own saved clock, including without vision; this never samples physical collision, projectile contact, support or required reach. Their predictable paths end a slice inside an interval or gap that endpoint sampling would skip. The selected world owns its cadence and displacement bounds; a brief visual opportunity between ordinary checks can be missed. New emitters still produce evidence at the actual occurrence state, not the next arbitrary host callback.

The host may compute a private batch of sight geometry on bounded workers while
retaining the mutation turn. I/O can run, but no partially updated world or
observer evidence is published. Synchronous callers use the same exact local
calculation. This is distinct from an animal's entity-local navigation wait,
during which other entities and game time continue.

Sight/contact calculations for certain paths may survive a shared mechanical rebuild only after pending captured rates are integrated, current physical inputs are read through their owners and their remaining absolute paths, participation, capabilities, senses, body geometry and immutable map/world-definition identities are revalidated. Reuse never extends the original covered interval. Uncertain movement calculations are cleared at a shared rebuild; changed or unproved dependencies recompute. A body-to-pair reverse lookup removes only incident calculations, while a separate reconciliation prunes expired or ineligible pairs. Every native invocation, including an immutable fork or restored world, owns fresh lookup maps and sets; no command or publication inherits them. The [October 17 correction](verification/performance/overhaul-simulation-implementation.md#crossing-predictions-now-belong-to-one-native-call--october-17-2026) records the identified observation-time defect, the corrected lifetime and the remaining saved-interval precision qualification. [PW08](projects/parallel-batch-01-playable-week/simulation-performance.md) retains its historical implementation and acceptance evidence; reuse within a call remains bounded by its original covered interval.

Within each linear path piece, conservative bounds on relative body coordinates reject only pieces that cannot enter the actual sight-radius or upright-cylinder contact predicate. Strict separation includes extra numerical slack; uncertain bounds retain the full geometry path. Rejected pieces still retain their original range/height cuts, individual work charges, exact classifiers and false-run merging. Possible pieces use one spatial sweep to prepare obstacle candidates and crossing fractions together, sharing its hull and axes. Neither preparation reduction changes the observation cadence or allows a fleeting sight/contact interval to disappear. [The active-scene evidence](verification/three-times-scene-performance.md) distinguishes exact run comparisons and native CPU savings from still-open whole-game 3× acceptance.

No unbounded fixed-point loop is allowed. Bound zero-time transitions, computation and queued work, retain unadvanced time as debt, and expose technical blocking honestly. A CPU pause is not in-world hunger. Shared input ordering, conserved resources, collision, observer scope, action completion and durable command boundaries remain authoritative. Superseded one-second traces are not a new-world compatibility requirement; accepted semantic changes and numerical limits must be recorded.

## Host and persistence

AI interpretation already runs independently of native advancement. The selected [runtime correction design](projects/attention-and-scenes-runtime-design.md#7-world-advancement-and-asynchronous-cognition) makes the required-versus-optional boundary explicit: ordered physical outcomes, actual sensing and required recording complete before a native boundary publishes; optional interpretation/readers and post-acceptance database application may finish later. Late proposals revalidate current effects and cannot backdate physical outcomes. Implementation must preserve this section's clock/debt rules and command durability; the corrective optimization is not yet delivered.

The existing host timer is a wake opportunity, not a biological clock. Convert monotonic elapsed real time to owed game time, ask the domain for a bounded prefix, and subtract **actual** advanced time. Publish/yield between bounded prefixes so commands, pause, worker replies and reads can interleave. The server yields I/O after eight milliseconds and requests a coherent publication after 32 milliseconds or when another operation is waiting; one expensive slice or finalization may still exceed those targets. The domain receives a stop request and never reads a wall clock. Do not hide overload by dropping debt, counting attempted calls as progress or weakening command durability. Existing suspension, required-navigation and presence policies remain explicit and separate from computational load.

Each HTTP wake returns after that coherent processing batch, retaining unadvanced time. One owned immediate continuation wakes again while that time is runnable; otherwise the ordinary 50-millisecond timer remains the idle wake. Newly elapsed time is then admitted regularly and background thought admission receives its ordinary opportunity; the host does not stay inside an old catch-up call until its debt reaches zero. Direct service callers can still drain an explicitly offered interval. This changes host scheduling, not the clock ratio or domain's mechanical boundaries. Time still spent waiting in the current host operation must not be mistaken for an empty backlog.

The HTTP host explicitly selects monotonic admission before its first wake. Live input and timestamped ticks share one accounted-through cursor: steering or renewal admits only genuinely elapsed time, and the next timer cannot count that interval again. A speed change first admits the preceding elapsed interval at the old conversion rate. Resume starts after the paused command commits, so paused database time is excluded. Direct duration-only service calls remain deterministic; they revoke operational input and transient reviews before admitting that explicit duration instead of borrowing ambient wall time.

Fresh live input starts after all time already owed. Its finite game-time window is clipped to its real-time expiry, and every private candidate using it must still have current authority immediately before acceptance. An expired candidate contributes no effects or random continuation; its unadvanced time remains ordinary debt. The [input-lifetime contract](projects/action-execution-and-skill-expression-tech-design.md#13-movement-alongside-preparation-and-the-live-input-lease) owns the two independent lanes and their current 100 ms renewal / 250 ms expiry policy.

Memory-consolidation pressure is nonblocking. Retain source memories and bounded optional maintenance/spending; lack of a model key, consolidation delay or a large retained history must not stop walking, consume/reset debt or masquerade as a save failure. Actual storage errors retain their existing admission/pause boundary. This follows the memory owner, not an additional cadence-owned queue.

No new database, per-feature save version or second scheduler/store is introduced. Existing action remainder, flight progress, status episodes and game-time deadlines remain canonical. Any new mechanics needing a durable next-event identity must use their own existing state owner. Recovery rebuilds derived scheduling data and must not redraw random choices merely because a process restarted.

## Extensible boundary ownership

A trusted mechanical family owns its rates, due conditions and valid integration bound. The engine must not hardcode every future world's behavior into one omniscient scheduler. Start with the existing finite families and keep a documented conservative fallback for unsupported coupled behavior. Native implementation is not proof that arbitrary new authored operations can skip time safely.

Connect a due condition to both interval selection and the caller's unchanged-state skip rules. Advancing the clock alone must progress admitted work and expire its support even when no entity moves. Derive wake times from the existing owner, exclude finished or unprocessable work, and verify ordinary world advancement and restored continuation; calling an initializer repeatedly cannot establish scheduling correctness.

The catalogue records for each candidate: what stays unchanged, how a deadline/bound is calculated, what invalidates it, what must happen at the boundary, evidence status and the existing implementation owner. Prioritize removing measured repeated work; a heap, worker pool, kinetic certificate or analytic closed form is justified by an actual consumer and measurement, not as a prerequisite to this change.

## Sound/speech integration

**Accepted shared NPC text target; runtime pending:** [NST](projects/npc-speech-streaming-tech-design.md) permits the committed text body of one instantaneous utterance to grow while generation completes. Hearing/identity remain fixed at its first publication and semantic consumers wait for one terminal readiness. The 250 ms continuation coalescing value is a server write-scheduling choice, not game-time speech, a natural speaking rate or per-word physical work. No new clock, door/movement interruption or speed-ratio change is selected; [NST01–NST10](maintainers/npc-speech-streaming.md) owns implementation.

See [the integrated sound/elapsed-time record](maintainers/speech-time-integration.md); neither former branch is a pending merge prerequisite. Speech emission is a committed occurrence and listener-specific acquisition, not a once-per-tick poll. Stored heard fragments never reroll during interpolation or history reads. Caption reading duration belongs to the real-time presentation clock, with its explicit pause/hidden policy, not accelerated game time. Physical speech duration, if later implemented, needs its own start/end boundaries and movement/occlusion semantics.

[Current evidence](verification/simulation-cadence.md) distinguishes executable elapsed integration, sampled native boundaries and actual 8x server observations from still-open regional, graphical and coupled-law qualification; [regional-time evidence](verification/regional-time-and-navigation.md) covers deferred rates, net flow and fleeting crossings.
