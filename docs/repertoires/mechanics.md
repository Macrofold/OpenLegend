# Mechanics repertoire

**Status: expandable idea catalogue, not a delivery checklist or a list of installed capabilities.** This companion to the [action repertoire](actions.md) preserves mechanics worth building on. Current support and exposure belong to [gameplay availability](../../archive/05-project/implementation-status.md#gameplay-availability); implementation tasks, limits and evidence stay with their existing owners.

## Reading and extending

`M:` keys share the action repertoire's concept namespace. They are design cross-references, not runtime family IDs or automatic permission to execute. This initial collection covers the foundations and adjacent gameplay discussed during consolidation; it is not exhaustive coverage of the action catalogue. Unlisted keys remain valid placeholders. Entry defaults are idea, no implementation evidence asserted here, and priority unassigned.

The mechanism column identifies reusable responsibility; the world-choice column identifies laws/content that another coherent world could replace. A native implementation does not make the latter an engine law. Adding an example never enrolls NPCs, installs a definition, grants access, starts paid work or schedules implementation.

## Promotion and extension template

For a new entry record: stable key and aliases; a concrete action/observation; roles and permitted knowledge; reusable owner; authored-world choices; dependencies and unsupported combinations; lifecycle/failure implications; links to current contract, limits, focused work and actual evidence. Use [P01–P12](../engine-and-world-boundaries.md#design-principles-for-every-feature) before proposing an engine change.

Promotion into delivery requires a separately scoped playable journey and its focused tracker, with design decisions resolved before runtime changes. Do not copy status checkboxes or numerical limits here. The next proposed social journeys are [BW16/BW17](../maintainers/base-world.md#social-playable-slices) and [ACT09](../maintainers/actor-model.md#act09--internal-feeling-process-authoring); this catalogue does not authorize them. Add separate object/trait/media repertoires only when concrete content warrants another maintained owner.
