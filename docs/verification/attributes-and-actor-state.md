### Browser walkthrough

A disposable SQLite server on port 3218 used `reservoir-demo`, god inspection enabled, and `AI_BUDGET_USD=0`. Through the actual browser UI: the condition panel showed Health, Charge on its real 0–240 range and Disposition, with no Food/Energy meters. Opening **In view → Charged capacitor → Recharge** started timed native work; charge rose while source supply fell. Pausing, saving **Reservoir runtime check**, resuming until charge changed, then **Game → Load → Confirm load** restored the saved charge, simulation time and pause state. The final build was checked again on port 3219 with a fresh directory: **Final manifest runtime** restored charge 234.3, Day 1 08:39 and the paused state after charge fell to 222.1. This establishes native UI behavior, not live-model authoring quality.

To reproduce on a fresh directory without reading `.env`:

```sh
OPEN_LEGEND_DATA_DIR=/tmp/openlegend-reservoir-demo OPEN_LEGEND_WORLD_PRESET=reservoir-demo OPEN_LEGEND_GOD_MODE=true AI_BUDGET_USD=0 PORT=3218 node --import tsx apps/server/src/main.ts
```

Open `http://127.0.0.1:3218`, resume play, follow the browser steps above and compare the restored quantities. Use a new directory if it contains an incompatible development world. For the native touch scenario change the preset to `touch-demo` and select another fresh directory; the player stays sighted, so do not mistake the player's view or god inspection for the resident's knowledge. Sense definitions, contact episodes and pending replenishment are part of the current saved manifest/state; older development schemas are rejected without migration.

## Generic status effects

Manual domain runs exercised the authored default: NPC energy 19 stayed awake during daytime, energy zero activated the effect, nighttime energy 69 activated it, and player-controlled actors remained exempt in both zero-energy and nighttime cases. Explicit player activation succeeded. Physical deactivation emitted `Ada woke up.` with the conversation association and witnessed audience; automatic full-energy completion ended at exactly 100, without expenditure in the same interval. Current-state JSON roundtrip validation passed. Old sleep-policy evidence below describes the superseded implementation.

A separate manual object scenario admitted a definition on an object without an actor component, bound `$actionTarget` to another object, increased that object's registered charge from 20 to 24 over two steps, and ended on its target-value condition. The subject stayed at 10. Stale registry revisions and an unknown target reference were rejected. This demonstrates explicit entity/attribute bindings; it does not certify arbitrary operations or world-agent authoring.

An isolated SQLite server-service run held an explicitly labeled fixture judgment in flight, activated the restricting state, and observed cancellation with zero generator calls and no accepted response receipt. Durable history and public conversation projection contained the player's greeting followed by `Ada fell asleep.` narration. Fixture spent/reserved cost remained zero. No real model requests were made.

A production build ran in a fresh isolated local server with no credentials and a zero AI budget. Browser inspection showed Ada horizontal with floating `zzz`; the target menu offered the authored `Wake up · Ada` action. Clicking it returned successful deactivation, restored her upright pose and removed the particle. The temporary browser/server were closed afterward. This is limited manual visual evidence, not full reduced-motion/floor/multiple-effect coverage.

Sequential Node 24.13.0 stress profiles used frozen snapshots, 180 steps, zero warmup and requested 3× speed. The initial generic implementation measured 3,148ms for 514 entities (gems) and 2,334ms for 344 entities (mixed). Profiles identified repeated condition/rule traversal through draft proxies. Reading immutable admitted definitions directly and avoiding redundant self-binding lookups reduced totals to 1,412ms and 1,290ms respectively. Gems: p50 6.88ms, p95 9.09ms, max 130.04ms, 3× headroom 0.708. Mixed: p50 5.63ms, p95 7.60ms, max 232.87ms, headroom 0.775. These remain below full cold-workload 3× capacity; concurrent unrelated work and changed sensory behavior prevent attribution against historical snapshots. Profiles and JSON are `/tmp/openlegend-status-optimized-{gems,mixed}.*`.

A separate frozen-snapshot synthetic scene contained 106 actors with 100 active restorative effects, ten warmup steps and 180 measured steps: 1,132ms total, p50 5.95ms, p95 7.61ms, max 32.31ms, 3× headroom 0.883. All 100 remained active and saved state validated. Production TypeScript/Vite build passed. Automated tests were neither written nor run; regression cases are in [TODO](../maintainers/TODO.md#status-effects--deferred-automated-validation). Paid spend was $0. Dense-scene capacity and broader authoring remain follow-ups, not completed acceptance.
