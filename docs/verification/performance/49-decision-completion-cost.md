## Source assessment

The existing store records an accepted native response's completion fields within the same transaction as the world. The scripted resident helper then writes the request again with its specific routine component and a later completion timestamp. The real decision coordinator similarly writes after native admission, but adds information that is not identical to the native outcome: response components, semantic trigger, decision disposition and optional level-one choice, fulfillment and elapsed-time details. Maintenance requests may have no matching response receipt and still need their terminal update. Therefore a broad removal is **rejected before code**; it would lose useful diagnostic/recovery facts.

The exceptional 938 ms database request checks whether remembered information is ready for background maintenance. Its entire family takes only 2.956 seconds across 348 calls in this run. It can delay a request sharing that read connection, but optimizing that one query is not a demonstrated solution to the whole-game slowdown. Existing native/projection spans and save waits overlap; do not add them or call either query duration pure CPU.
