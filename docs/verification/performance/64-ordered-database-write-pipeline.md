# Send ordered save instructions without waiting between every reply

Selected October 16, 2026, 19:16 EDT, before prototype code. **Investigation selected; no implementation or benefit yet.** Smooth 3× remains unmet.

The current save often sends roughly nineteen to twenty-one requests to PostgreSQL. The compact-record comparison reduces saving time, while measured waits around database replies remain substantial. Some requests genuinely need a result before the next can be built. Many record writes already have all their inputs and merely wait for completion. Sending those instructions together, in their original order, could remove repeated reply waits without combining their database snapshots or dropping information. This is a hypothesis, not a promised saving.

## Boundary and intended design

Keep the existing transaction, authorization/head checks, original parameterized SQL, statement order, parent/child constraints, deletes, error behavior and durable acknowledgment. Only explicitly owned sequences of already prepared writes may use the transport. Reads and checked results that determine later work remain barriers. No global deferred `run` result, invented successful acknowledgment, SQL string interpolation, extra writer connection, data migration, event omission or gameplay change. An error still rolls back the complete transaction; no automatic retry.

The current [node-postgres custom-query API](https://node-postgres.com/apis/client) permits a submitted query object to own dispatch. The installed `pg` 8.16.3 query implementation already prepares bound values and parses multiple command results. Reuse those mechanisms rather than writing another parameter encoder. PostgreSQL's [extended-query message flow](https://www.postgresql.org/docs/18/protocol-flow.html) allows ordered commands before a synchronization boundary; after an error it skips later commands until that boundary. This differs from sibling data-changing SQL expressions, which can share a snapshot in unspecified order. Keep that distinction explicit.
