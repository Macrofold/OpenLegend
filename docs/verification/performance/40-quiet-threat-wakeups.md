An idle territorial animal currently requests a review every fifteen game seconds. Those reviews can end the shared interval used to calculate many people's needs, work and movement, even when nobody is close to its territory. The latest fixed-work comparison saves 19.39% of CPU by reviewing every sixty seconds instead. That proves this timing matters, but the slower version can miss a brief visitor.

This assessment asks whether the game can avoid an unnecessary review only when it can prove that no eligible intruder can reach the territory before the next shared interval ends. A nearby person, an attack, an active pursuit or an uncertain movement case must retain the ordinary behavior. This is a possible alternative to delaying all idle reviews; it is not an implemented capability or a promised speedup.

Before selecting code, trace the existing owners of review deadlines, conservative movement bounds, native interval reuse, external movement/placement changes, health changes, entry into a territory, cancellation and restoration. Identify whether the existing dependencies actually cover every wake-up. Do not create an independent writable cache or an invisible saved-behavior decision in a process-local cache. Preserve the original negative batching and navigation experiments rather than assuming fewer calculations are necessarily cheaper.

The source assessment may select a small private implementation only if those dependencies admit a complete, reviewable rule. Otherwise record the precise missing dependency and leave the ordinary behavior intact. Any selected trial requires its own preregistered affected owners, functional cases, fixed-work comparison and conditional actual-game measurement before execution. No native saving may be called a smoothness pass.

## Relevant engine research

Unreal's behavior trees avoid repeatedly evaluating unchanged decisions by reacting to relevant events. Rapier similarly stops simulating sleeping bodies, with explicit wake-up handling for user changes. These are useful design principles, not evidence that either library already manages OpenLegend's animal decisions. An OpenLegend change still needs its own complete wake-up conditions. [Epic's explanation](https://dev.epicgames.com/documentation/en-us/unreal-engine/behavior-tree-in-unreal-engine---overview), [Rapier's sleeping-body contract](https://rapier.rs/docs/user_guides/javascript/rigid_body_sleeping/).

## What the source actually supports

The ordinary review currently writes a new deadline and marks the animal's behavior as changed even when it sees nobody and chooses no action. The native simulation then discards its shared prediction. The deadline also ends that prediction every fifteen game seconds. Both causes need one shared exclusion rule; merely removing the deadline leaves repeated behavior writes, and merely skipping the writes leaves the deadline.

The existing movement owner already calculates conservative travel bounds for one shared interval. The native simulation retains predictions only across its exact immutable successor; commands, edits and restoration rebuild them. Native commands and meaningful body/behavior changes also discard the prediction. A quiet-review exclusion can therefore be recomputed from the current complete participant roster without a second saved flag or a behavior decision hidden in a process-local cache.

There are important limits. The bundled stag currently targets **player-controlled bipeds only**. Broadening the shortcut immediately to NPC plans, follow actions, flight, falling or arbitrary future movers would require additional wake-up dependencies. A player can begin a new walk through an external command; an NPC can begin its next queued action inside a shared interval. Those are different dependencies. The first trial will retain ordinary reviews whenever it encounters those unsupported cases.

## Selected private trial and tradeoff

The next trial will retain fifteen-second idle and active policies on both sides. Eligible players must have ordinary supported biped movement, no plan, follow, evasion, flight or fall; the policy must target only that supported player/body family. Other policies and uncertain cases keep the original behavior.

For every potentially eligible player, use the existing movement bound over the full existing sixty-game-second maximum interval. A player inside, or able to reach, the entry radius prevents the exclusion. Near visitors still use actual visibility and the existing target-selection/attack owner; the exclusion grants no knowledge or damage. It cannot be inferred from distance alone without the travel bound.

This deliberately changes the phase of idle reviews: a skipped empty review does not advance its saved deadline. Once a review becomes relevant, it can run immediately at the next native start and then resume the ordinary fifteen-second cadence. The trial must demonstrate entry, brief visits, new walks, placement changes, restore/fork and actual active attacks. It is not declared identical to the former polling phase, and no speedup is assumed. If the extra checking costs more than it saves, reject it. No private implementation or actual-game run has started at this assessment checkpoint.
