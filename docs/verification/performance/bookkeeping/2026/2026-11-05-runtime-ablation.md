## Source-established hypotheses

- Historical native history uses compact dictionaries/tuples. Current `ReceivedBinding.parts` contains expanded original/source/support/detail proof graphs; `flushReceivedBatch` snapshots them and `receivedBatchStorageBytes` recursively measures them before physical save encoding. The final compact save codec does not remove that upstream work.
- Unchanged successful checks already existed at the historical source. Their mere existence cannot explain the regression; removing them tests the value and cost of retaining that fidelity.
- `073e367da` adds `perceptionReferences → orderedRecordChangedKeys` and replaces the separate journal/application worker with direct saving. Reference-diff work and moving work between threads must be investigated separately from representation size.
- The earlier unmatched profiles show fewer sensory tests per advanced game second but more native publications, sealed owners and ordered-record branch visits. These counts identify paths to test, not causal percentages; hardware, trajectories and diagnostic overhead differ.

## What an ordinary movement causes

1. Native movement changes actual positions and dirty sensory scopes; action/collision, animal and status owners still run their real gameplay rules. The clock advances elapsed intervals, not sixty mandatory ticks per real second merely because its rate is 60:1.
2. Due ordinary sight reconciles affected observer/subject pairs in `updateEncounters → reconcileVisualEvidence`, updating personally received contact values, independent times and coverage. Visibility, unknown identity and last actual measurement are useful work; a newly successful check does not necessarily contain a new value.
3. The sight pass details old attention members (`perception-evidence.ts`, `processSubject` first pass), ranks through `updateAttention`, and details entrants. `reconcileAttendedTemporalEvidence` can rank again and request further detail. Candidate preparation resolves received descriptions/positions/identity and groups them; it is not a history scan. New measurement source/ordinal/time tuples also replace attention entries/context change revisions even when values are equal. Discovery novelty itself uses description revisions and does not reset stability just for a timestamp.
4. `captureTemporalCurrent` separately prepares history: targets, bindings, typed part/proof references, viewing frames, coverage and previous-check carriers. Its exact-check contract retains repeated confirmations. The changed-value cut skips 76,157 of 78,554 examined groups before most of this preparation; required occurrence and geometry paths are separate.
5. `flushReceivedBatch` filters/sorts, selects parts, snapshots the native graph, estimates its bytes through `receivedBatchStorageBytes`, prepares metadata/charge directories and updates recent individual locators. The identity owner replaces a learned row when only its latest history address changes. These actions allocate/copy/traverse data and dirty saved structures; they are not all new memories or physical observations.
6. The ordered writer later packs and encodes the native data into compact physical records, applies current/history/ownership/index changes and collects eligible storage. This final codec cannot recover CPU already spent constructing/snapshotting/sizing expanded native graphs. Player/native/context consumers separately read permitted received state; those reads must preserve admission boundaries, but need not rebuild acquisition proofs repeatedly on trusted owned data.

The graph-format difference from the historical source and these callers establish mechanisms. Subsystem cuts below establish cost contributions of broader paths, including their downstream effects; they do not assign exact nonoverlapping CPU percentages to every step.

The attention sequence above is **within one observer**, repeated independently for other observers. Ranking means comparing that observer's eligible received subjects using physical cues, unfamiliar descriptions, focus/action, familiarity, stability and discovery policy. The source comment on `reconcileAttendedTemporalEvidence` explicitly preserves both outgoing and incoming detail so selection cannot erase its triggering observation. Updating previous selections before ranking and immediately inspecting entrants serve that stronger contract, but create extra passes. Candidate B deliberately changes the contract to one final selection/detail opportunity; it does not simply remove a redundant loop while claiming identical timing.

The code already has common field/body helpers. Repeated calls still scan contact groups, prepare eligibility or construct wrappers; shared function definitions do not imply shared computed results. Earlier changes grouped and compressed stored evidence while preserving exact historical checks. Candidate B removes those checks and rich native proof structures before recording, and gives compatible callers one scoped preparation. This is proposed behavior/representation change, not a claim that the earlier implementation already eliminated the demonstrated costs.

## Conclusion and implementation priority

The regression is real on matched hardware. The system pays to construct, traverse, validate, size and save a detailed proof/check diary whose repeated values add little gameplay information. Compact SQL encoding happens after much of that CPU cost. Attention changes multiply detail acquisition and history preparation; received-state readers repeatedly rediscover fields and eligibility. Ordinary command authorization additionally holds the world mutation lane across database reads. The available CPU and wait evidence establishes multiple interacting costs, not a single slow query or an explanation based only on AWS instance size.

1. **Replace the native representation and optional history together.** Highest demonstrated removal potential: most examined current groups contain unchanged values, and removing optional recording plus attention work reaches normal speed in a short diagnostic. Keep compact current freshness and sparse attended changes, independent meaningful support and explicit gaps; remove rich proof graphs, check diaries and exact per-member accounting before save encoding. The proposed implementation has not been measured.
2. **Prepare current reads and attention once per relevant change/opportunity.** Direct typed field addressing, a coherent eligibility cut and one optional selection/detail pass remove repeated wrapper/search/admission work. Residual CPU and held-selection trials support this direction; the trials' unfilled slots prevent a numerical prediction for correct dynamic attention.
3. **Remove ordinary authorization I/O from held world mutation ownership without weakening revocation.** The final capture proves the boundary matters. Preserve current authority and protected transaction fences; distinguish a safe ownership change from merely moving an unsafe cached check earlier. No gain estimate is available.
4. **Use the world-owned 60/30 sensing policy and dependency-driven native preparation.** The isolated cadence trial improves progress materially while changing visual response fidelity; current-read/status/capability preparation also remains significant. Keep actual physical/event reactions independent and verify the new visual policy. Tuning alone still fails normal speed.

Do not implement the experimental constant byte estimate, frozen/unfilled attention, stale player projection, disabled status/sight or skipped support chain. Do not restore full reference reconstruction: its comparison shows no benefit. More threads or faster SQL cannot remove the measured native graph work.
