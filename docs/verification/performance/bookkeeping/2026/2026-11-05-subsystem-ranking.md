# Standard-opening subsystem removal ranking

**Question:** identify substantial server costs beyond observation history and attention, using comparable whole-subsystem removals rather than assuming previous prominent costs are exhaustive. This follows the [matched source investigation](2026-11-05-runtime-ablation.md); that report retains its original 25 cases and accounting. **Status:** 29 AWS experiments and review complete, including three explicitly excluded failure cases; no runtime replacement installed.

## Workload and interpretation

Repository `https://github.com/Macrofold/OpenLegend.git`, runtime source `259bb1ecdd6f9c04022d0a7b6f41b004250f0e2d`, local branch `codex/stealth-runtime-01-evidence`; the initial documentation revision was `0f38fb6855d279d1cad33761bafbd6c5400c5b36`. Subsequent design clarification `1513e9bf0` and worker policy `1111bd7ed` contain no runtime changes; every experiment uses the exact runtime source above. No branch/worktree switch or local speed workload. The [standard worker](../../../../../.agents/rules/verification-workers.md#standard-speed-test-worker) is the managed m7i.xlarge, four vCPU / 16 GiB, project `027677879749`, `us-east-2`. The measured environment uses Node v24.13.0, Intel Xeon Platinum 8488C and PostgreSQL 16.15 on loopback. Claims, actual host/session and effective settings accompany each report; matching the instance ID across stop/start does not establish the same physical host.

Primary comparisons use the authored opening, actual seed 1086, seven people, twenty animals, 74 root objects, one controlled walker, 60:1 game clock, 60-second warmup and 120-second measured phase. The HTTP client offers commands at a 500 ms base interval with the existing every-thirtieth-index burst, reads state at 4 Hz, keeps SSE open and renews presence every three seconds. Each cut activates in a disposable source copy after normal initialization/reopen unless its manifest explicitly selects startup policy. App/CPU collectors are off. The same reviewed publication-pause and fixed wait/debt observers apply to controls and cuts. Those observers add bounded measurement work; no older uninstrumented result substitutes for a matched control.

Rank removal benefit for this opening, including downstream effects. Report speed, main CPU per advanced game second, actual movement/population, failed/skipped commands, pause/debt and history together. Different achieved game time changes trajectories and retained state; these are not isolated instruction-cost percentages. Parent removals overlap their children, so do not add their gains. Full-speed saturation can hide further throughput headroom; CPU per game second remains useful but does not qualify missing gameplay. Bracket batches with controls and repeat material uncertain contrasts. A failed or paused workload is not a clean speed result.

## Coverage

The matrix covers optional recent recording, attention, sight cadence, terrain context, visibility/occlusion, animal activity, capability restrictions, physiological rate updates, player projection, ordinary authorization, account retention, physical history/value cleanup and database durability waits, plus sensory crossing refinement and native publication frequency. Shared cadence changes are separated from sight-only and geometry-only changes. Source review determines whether a broader save-removal cut can run without an artificial backpressure stall; an unsafe or invalid cut is reported as unmeasured rather than fabricated.

The five-minute automatic-checkpoint owner needs a separate 60-second warmup / 300-second measurement pair; the short primary matrix cannot establish its active cost. The older long reports lack checkpoint counters, so duration alone does not prove a checkpoint ran.

The standard workload does not buy model decisions or render a browser. `AiDirector.considerThought` rejects zero-budget/missing-provider admission before person scanning and optional AI/search maintenance; those disabled paths have no representative active cost here. It does not actively exercise every crafting, combat, trade or authoring flow. Their unmeasured incremental costs cannot be ranked as zero; the result ranks the active standard-opening server systems. Disabled functions, output effects, actual skip counters and remaining dependencies are recorded in each exact cut manifest.

## Ranking and implementation priority

1. **Observation/reception and its history representation: strongest evidence.** Freezing attention reaches 0.748 normal and suppressing optional recording reaches 0.671 against the first 0.331 control. Their effects overlap heavily. Current reads, recording/ownership and later encoding are all substantial in the CPU capture. The result supports the existing compact-current/change-history conversion, not deleting attention or meaningful memory.
2. **Ordinary sight frequency: strongest independently isolated policy lever.** Sight-only 60/30 reaches 0.597; shared 60/30 reaches 0.601, and shared 120/60 reaches 0.862. Geometry-only cadence gives no comparably large gain. This is another way to reduce work in the same reception pipeline, not an additive independent saving. Keep world-owned timing and explicit reaction/fidelity acceptance; no slower policy is installed or qualified here.
3. **Animal activity and its downstream consequences: repeatable medium effect.** Removing it improves progress 19–22% in two matched pairs, reaching about 0.43, but worsens input latency and save-admission pressure. Preserve wildlife behavior; reduce the work triggered by its motion rather than treating stopped animals as an optimization.
4. **Other tested mechanisms: no demonstrated large individual benefit in this opening.** Obstruction, terrain context, capability checks, status rates/rules, player-view preparation, young physical cleanup, synchronous commit acknowledgements, the ordinary authority query and 100 ms native publication target do not deliver a comparable win. Exact sensory refinement is unexercised. Shared native/status preparation, complete ordinary save preparation/application and command/event consequences remain coupled active work; their complete costs were not independently removed. The CPU map retains those residuals rather than assigning them zero cost.

Successful-checkpoint cost remains unmeasured because both attempts fail; checkpoint suppression does not cure the steady slowdown. Larger and older worlds, mature reclamation, paid AI/search, rendering and richer combat/crafting/trade remain unqualified. Single-run small differences are not a precise order or a statistical confidence interval. The measured controls/negative contrast and animal repeat establish the limits of this ranking.

Prioritize removal of unchanged-history/proof construction, repeated current read preparation and duplicate attention/detail work through [BK24's existing stages](../../../../projects/bookkeeping-simplification-tech-design.md#15-compact-native-evidence-and-change-history). Treat ordinary admission ownership as a fairness/correctness conversion with measured command responsiveness, not an assumed throughput win from moving an await. Resolve checkpoint export size/integrity in [SL08](../../../../maintainers/save-and-load.md#sl08--rolling-autosaves-and-retention); [PF00](../../../../maintainers/performance.md#pf00--baseline-and-attribution) owns the profiler's missing checkpoint outcomes/diagnosis. The selected design and operating gates remain unimplemented/unmet where already tracked. No new worker, cache system, storage format or game-policy change is installed by this investigation.
