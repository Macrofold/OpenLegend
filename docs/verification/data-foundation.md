## Data foundation runtime

2026-09-25, native/no-provider verification of D1/D2. Host: Apple M1 Pro, 32 GiB RAM, macOS arm64, Node 22.23.2; local PostgreSQL 14.17 with pgvector and Node SQLite. All runs used disposable worlds and `AI_BUDGET_USD=0`. No unit, integration or browser suites were authored or run. This is operational/component evidence, not multiplayer or model-quality acceptance.

The repository benchmarks are `scripts/stress-data.ts` and `scripts/stress-world-data.ts`. Both refuse an existing PostgreSQL world unless the source benchmark explicitly resumes its exact synthetic fixture; reports use exclusive new output paths. Source benchmarks use synthetic 512-dimensional vectors, not real embeddings. Thirty sequential observations supply each query percentile below; p99 equals the observed maximum at this sample size. Values include repository selection, hydration and source hash verification. The broader local retrieval also includes physical observation, conversation/watermark lookup, coverage counts, required-source lookup and candidate formatting. It excludes embedding APIs, Jev, generation, browser/network delivery and other gameplay preparation.

The final PostgreSQL large-corpus run resumed a warmed synthetic corpus at 100,060 records and appended thirty. A preceding fresh 100,000-source run measured 30.5 seconds for extraction/initial commit, 502 ms recovery and 91.3 seconds to produce/publish all synthetic vectors. The final fresh 5,000-source run measured 861 ms initial commit, 75 ms recovery and 4.23 seconds synthetic indexing. SQLite's final fresh 100,000-source run measured 4.56 seconds initial commit and 372 ms recovery. These are single cold/setup observations, with other local work possible; they are not p95 guarantees. Checkpoint-capture timings exclude final JSON encoding/file publication; the large source fixture encoded about 19.2 MB. The application currently requests 300 optional finalists; the 100-result benchmark does not establish identical application latency.

Iteration found and fixed repeated missing-index scans, join-before-limit queue plans, whole-actor eligibility updates for a single append, redundant memory preparation inside physical observation and required-source scans. SQLite full local preparation fell from 142 ms to 28 ms median on matching 100,000-source fixtures; PostgreSQL fell from 342 ms to 180 ms on successive warmed versions of the same corpus. Tail variation and slight corpus growth prevent treating these as controlled capacity ratios. Exact vector cost still grows with corpus size. One batching attempt regressed because SQLite reordered a small changed-ID join into a whole-source scan; it was stopped, its query plan inspected and the join corrected before the reported results. A cold PostgreSQL write hit the former five-second statement limit and rolled back; atomic writes now have a separate thirty-second statement limit while interactive reads retain five seconds.

These runs **do not pass the first-release capacity gate**. Initial perception acquisition creates large evidence fan-out, and active history/Immer copying remain expensive. No meaningful events were dropped to improve the benchmark. Regional residency, browser/network fan-out, real simultaneous accounts and live AI remain unqualified. Native fixture heap usage reached roughly 0.58–1.84 GB; that is not a per-player production memory estimate. The existing 64 MiB manual-save guard and main-process serialization also remain SL/PF work.

- Duplicate speech produced no second event. A forced failure while writing a native move process left both head revision and gameplay records unchanged. An enclosing transaction rollback also left notification revisions unchanged; a subsequent commit succeeded.

### Data foundation review

2026-09-25 follow-up review of the complete foundation change and its callers. Native drills used disposable worlds, Node 24.13.0, local PostgreSQL 14.17 and SQLite with `AI_BUDGET_USD=0`. Three confirmed defects were repaired:

- **Restored transcript permissions:** create a backup, forget a speech event, then restore that backup into the existing world. Before the fix, the forgetting ledger still contained the event but its transcript audience and perspective rows returned (one row each). The shared restore commit now reapplies all current forgetting restrictions after installing history; SQLite and PostgreSQL reruns returned zero audience and perspective rows. Gameplay save/load uses the same enforcement, replacing its former caller-only workaround.
- **Legacy profile import:** import a populated SQLite profile table without the later `pause_when_hidden` column. The original importer rolled back despite correctly copied values because it compared source rows against additional destination columns. It now compares every original column and row count while allowing destination defaults. The rerun retained profile revision 7 and `show_unavailable_actions=0`, supplied `pause_when_hidden=1`, and left the source database's SHA-256 unchanged. The failed original run left no world head in its destination.
- **Grouped recall edits:** retrieve repeated experiences as one grouped context candidate, edit a secondary member through the actual Person editor, then validate the pending selection. The original check accepted the changed group; the repaired check rejected it. A 300-source group repeated over thirty unchanged validations measured 0.83 ms p50, 1.92 ms p95 and 2.14 ms maximum in SQLite. The original incomplete one-source check measured 0.06 ms p50; that timing did not represent equivalent work. No live attention/provider call was made.

The native game-service save/load, duplicate-command, failed-record-write rollback and legacy snapshot/journal migration drill also passed after these fixes. Pinned formatting and `git diff --check` passed. `pnpm build` passed with the existing bundle-size warning. `pnpm typecheck` returned the same 168 normalized diagnostics as the established foundation baseline, with none added or removed. No automated unit/integration/browser suites were authored or run. Broader recovery regression coverage remains in [D1/D2](../maintainers/production-data.md#remaining-d1d2-implementation-and-evidence), grouped-attention coverage in [CR](../maintainers/cognition-redesign.md#cognition-persistence-and-consolidation-follow-up), and the previously measured population/large-save limits remain open.
