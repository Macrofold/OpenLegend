## AI director pause/resume usage race

`ai-director.test.ts`, “holds a late explicit result while paused and admits it only after resume”, sometimes counted two model calls. The second call was not a duplicate invention dispatch or double accounting. The test harness injects a fixture client for Jev and generation, but the director's memory-recall service builds its own embedding client from configuration. The harness set `OPENAI_API_KEY` and a $1 budget, so background memory indexing sent a **live** `text-embedding-3-small` request with the fake key. OpenAI rejected it with HTTP 401, and it was recorded as a dispatched model attempt (`memory-index:*`, actor `entity-0002`). Whether it settled before the assertion depended on network latency and machine load.

Reproduction: waiting 2.5 seconds before the usage assertion failed deterministically with `llmCalls` 2. The recorded attempts were the invention's Jev route, its generation and the rejected embedding request. After setting `OPENAI_EMBEDDING_API_KEY` to empty in that harness, the same delayed run recorded only the route and generation, and passed. The assertion was not weakened and no timeout was raised. The earlier report's cleanup-hook timeout ([embodied survival](embodied-survival.md#minimal-context-and-equipment-derived-hunting)) was not reproduced. The live request may have contributed, but that is not established.
