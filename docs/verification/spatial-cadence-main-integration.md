## Matched native comparison

The same seed-73 scenario added 60 people, 100 animals and 500 rigid objects (806 total entities, including inventory). Both revisions warmed to game time 60 and then advanced exactly 300 more game seconds. Baseline main used its one-second integration; the rebased branch offered 30 seconds with one accepted interval per call. Three runs per revision used frozen snapshots. The scenario uses the existing `parseScenario`/`populateScenario` helpers with seed 73, scattered placement, 60 people, 100 animals and 500 rigid “Profile gem” objects. Each domain advance uses `maxIntervals: 1`, freezes the returned world and must make positive actual progress. Wall/CPU timing excludes warm-up; p95 uses the nearest-rank percentile of the outer advance batches. Setup/first exposure, SQL, networking, rendering and providers are excluded from the measured phase.

| Measure                                                        | Main `56b8c383` | Rebased integration |
| -------------------------------------------------------------- | --------------- | ------------------- |
| Wall time for 300 game seconds                                 | 21.59–23.95 s   | 1.896–1.968 s       |
| CPU time                                                       | 21.67–22.36 s   | 2.104–2.259 s       |
| Accepted intervals                                             | 300             | 27                  |
| Observed p95 advance batch                                     | 118.8–145.0 ms  | 340.4–375.5 ms      |
| Native headroom at requested 8× (480 game seconds/wall second) | 0.026–0.029     | 0.318–0.330         |

**Accepted intervals** count successful domain advances of simulation time, shortened at relevant deadlines; they are not renderer frames or a fixed tick rate. The 27 integrated intervals span the same 300 game seconds as main’s 300 one-second intervals. **Advance batch p95** times completion of an offered one-game-second span on main versus a 30-game-second span on the branch; a branch batch can contain multiple accepted intervals. There are only ten timed branch batches, so its nearest-rank p95 is their maximum, not a well-sampled latency tail. The integrated median wall time is about 12 times lower for this workload, but these unequal batch durations do not compare command latency or equal-sized calls. **8× headroom** is measured game-seconds per wall-second divided by 480. The denominator is the authored clock scale (60 game seconds per real second at 1×, multiplied by eight), not 60 simulation ticks per second. A value below one misses that requested rate. Both revisions emitted 31,385 events; equal counts do not establish whole-world behavior equivalence. The first baseline run overlapped an early integration experiment; later baseline and all final integrated runs were serial. Desktop activity remains a source of noise.

These final measurements supersede the earlier 0.901–1.008-second, 16-interval integration result and its roughly 24× improvement. The retained flight check exposed a stalled takeoff that skipped flight work. Fixing departure-support handling restored progress, eleven accepted intervals and fifty events in this workload. The corrected result includes that work; the earlier result overstated the improvement and is not evidence of final throughput.

**Neither revision meets sustained 8× in this native workload.** It also omits the historical failing staggered-flight case, growing history and the full server/browser cost. PF12/PF13/SW19 remain open.
