# Standalone perspective texel-splatting experiment

## E07 — October 15, 2026

**Decision: defer application integration.** The static technique ran on physical hardware with the existing starting scene's geometry. It can keep coarse samples attached to captured surfaces, but newly revealed surfaces and capture replacement still change the sampling. Thin deck details and grazing surfaces remain poor fits for the present character-first art revision. No OpenLegend graphics backend, world initializer, gameplay state or active playtesting world was changed.

This completes the standalone investigation in [V3D01.9](../maintainers/3d-pixel-art.md#v3d019--standalone-perspective-texel-splatting-investigation), including a rejection/defer decision; it does not qualify animated characters or adopt texel splatting for production. The [research owner](../../art-direction/research/3d-pixel-worlds/texel-splatting.md) explains the method and integration boundary.

### Complete operation and memory measurements

These are **diagnostic measurements under concurrent starting-scene browser QA on the same machine**, not isolated device/frame-budget qualification. They must not be used as a supported population, 8× simulation, lower-end device or full-game FPS claim. The scene is only 602 merged static triangles; it omits the current world's many scenery cards, people and gameplay work.

The tool records CPU preparation/encoding, the complete encode→submit→GPU-completion wait, each GPU stage's timestamp interval, and the first-to-last GPU timestamp span. Display-frame waits, screenshots and timestamp readback are excluded from the reported complete wait. GPU timestamps were quantized in observed 0.065536 ms increments. On Metal, individual render-pass intervals overlapped; summing those durations produced impossible-looking totals larger than elapsed frame time. The report therefore uses complete first-to-last spans and grouped stage spans. Stage spans can also overlap and **must not be added** as independent costs.

### Resulting decision

Retain the repeatable tool and **defer production integration** for this scene revision. The static experiment demonstrates an interesting stability mechanism, but its capture transitions, newly revealed sample changes and grazing/thin-detail tradeoffs remain visible. The public implementation uses WebGPU while the application still uses its qualified WebGL path. Porting/migrating that path would also need to preserve permitted visibility, depth, selection, read-through and resource cleanup. None of those costs is justified by a static neutral-material result alone.

Animated heads, faces, skinning, cloth deformation/body coverage, transparent effects and view-dependent specular behavior remain unqualified. This experiment cannot solve or close the mercenary's face/clothing acceptance. If the technique is reconsidered, the existing V3D01.9 owner requires a scoped integration decision and those relevant failures to be addressed; the current ordinary-renderer art work continues independently.

The tool's entire affected source was reviewed. Node syntax checks, targeted Prettier and 12 local documentation references passed. An empty static export was rejected with the declared vertex-range error before browser/GPU startup. Final hardware runs verified the tool end to end. Broader application TypeScript/build/interaction checks belong to the integrated starting-scene implementation and are not claimed by this standalone report.

## Static stability revisit — October 15, 2026

Mike explicitly reopened technique selection after rejecting the first scene's ordinary-3D environment and identifying shimmer/artifacts as critical failures. This follow-up changes the experiment, preserves the original modes, and tests two concrete alternatives. **Fixed cubemap capture is rejected for uncovered surfaces. Full-resolution surface-grid rasterization is a promising static-material candidate, requiring application and moving-boundary qualification.** No OpenLegend backend change or static-to-animated inference follows.

### Changed controls and workload

The [same tool](../../scripts/art/texel-splatting/README.md#static-stability-revisit) now offers the `stable` profile at 192² capture density. It compares original raster, original moving eye/grid/previous splats, fixed-origin splats, and a separately named surface-grid raster alternative. The same public 46-mesh, 1,224-vertex, 602-triangle export and input hash above remain unchanged. This is an existing-scene **static subset**, not the complete current artwork or another playable world. The adapter runs independently of the application's current renderer.

- **Fixed capture:** one explicit origin at each path's start, all six faces, no eye/previous samples, no cell replacement, no camera-dependent quad-edge expansion and no eye-image background fill. Geometry capture happens once per path; illumination still changes when requested. Capture origin is never reset during that path. The temporary second source copy retains the original splatter's 18-layer storage despite using one six-face capture; the original splatter remains available unchanged except density.
- **Surface grid:** ordinary full-resolution triangle rasterization, with material and light evaluated at 0.12-metre grid centers projected onto each original face plane. Exact triangles provide coverage/depth at 1280×720 with 4×MSAA. A one-time 50,568-byte vertex buffer repeats flat geometric plane coefficients per triangle; it does not move or add triangles. This is **not cubemap splatting**, an application shader, authored game art or a model composed of permanent colored cubes.

Both new controls use black background to expose missing coverage. The original controls retain their sky. Comparisons concern geometry, not those backgrounds. Light, pose and geometry are frozen on camera paths; only the dedicated light path varies sun elevation. The eight paths are within-cell translation, boundary-crossing translation, 40° orbit, 70°→35° perspective zoom (matched orthographic coverage change), changed sun, thin deck detail, lateral deck disocclusion and a genuinely still view. Both perspective and orthographic projections run all four modes, with 36 measured frames after 36 warm-up steps: **2,304 measured frames in the final repaired run**, plus separately recorded first reset/preparation frames. Every path records start/middle/end PNGs and a continuous WebM.

Hardware remains the physical Apple M1 Pro/16 GPU cores/32 GB/macOS 15.7.3/Chrome 155.0.8059.40, WebGPU `apple`/`metal-3` with timestamp queries, canvas 1280×720/DPR 1. Other team browser work was stopped during the coordinated GPU windows. Root performed offline file analysis; this small static experiment still does not establish full-game performance or an idle-machine benchmark. No provider calls were made. Additional cost, cumulative task provider cost and uncertain/reserved commitments are **$0** under the shared $10 ceiling.

### Actual findings, including the repaired slope failure

The initial surface-grid version reconstructed a face's plane offset from interpolated fragment coordinates. Close ramp inspection exposed tiny alternating speckle islands where rounding crossed the neutral stone material's internal sample thresholds. Ground-only point checks had passed and did **not** qualify that sloped face. The rejected first sweep remains at `/private/tmp/openlegend-texel-e07-stability-revisit-192/`; its failure is not erased by the repair.

The repair carries constant geometric normal/plane offset from each source triangle and reconstructs a cell center from only that plane and the integer lattice. The interpolated dominant coordinate is no longer used to recover the offset. The repeated full sweep removed the visible tiny speckle islands on the ramp. The fixed-capture source itself was unchanged between the two sweeps.

The ground point test samples cell centers at X `3.66–7.14`, Z `9.06–13.14`, Y `0`. Ramp samples use its real plane `Y=(13−Z)/2`, X `23.34–24.9`, Z `7.5–12.66`. Each point projects through the recorded start/end camera; its nearest final output pixel is compared, excluding black/outside samples. All 1,050/616 samples remained eligible in each repaired surface case. This finite material-interior method intentionally avoids source cell boundaries; it cannot prove absence of shimmer in the entire changing image. In the initial ground comparison, ordinary low-resolution raster changed 26.76–35.14% of these point colors by over 8 RGB; original splats 12.38–30.86%; fixed captures 8.67–12.86%; full-resolution surface control zero. The controls have different output resolutions/work, so the improvement cannot be attributed to sample anchoring alone rather than the combined resolution/grid/MSAA change.

Coverage percentages compare fixed black pixels (`max RGB < 4`) with the same output pixel in the surface reference (`max RGB > 24`). They include displaced/quantized edge coverage, not only mathematically empty holes; dark shadow/background pixels are excluded. They are diagnostic coverage counts, not artistic scores or a general quality metric.
