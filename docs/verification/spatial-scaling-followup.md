### Limits and adverse cases

A wall extended across the entire co-located layout exposes the remaining worst case. The baseline's first negative query takes about 2.18 seconds because it checks the whole graph even with an A\* expansion allowance of one. Revised code returns `budget-exceeded` after one expansion in about 32 ms; a subsequent full search takes about 1.09 seconds to prove no route across 5,852 expanded states, and the next identical query uses the closed-region proof in about 1.10 ms. The full search already had metadata and a few checks from the small-budget request, so it is not an entirely cold measurement. A first exhaustive no-route proof can still block the host; SW06.2a remains open before denser content or higher limits. Caching a partial search as impossible would hide this cost incorrectly and is forbidden.

The successful dense-route sample improves by about 97%, and isolated inert multi-step work can improve by more than 98%; neither establishes a 90% reduction in whole-game latency. Physical checks, first acquisition/event storage, observation serialization, commit/projection and rendering remain actual work. Candidate metadata still scales with admitted surface area, coarse surface grouping remains bounded pairwise work, and genuinely dense sensing does not become sublinear. No long-session memory, population maximum, GPU FPS or percentile guarantee follows from these short runs. A proposed `current(world.entities)` snapshot inside every encounter phase made a moving-bird diagnostic slower and was discarded rather than shipped.
