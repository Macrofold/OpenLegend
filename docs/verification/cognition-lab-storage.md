Saved work includes scenarios, checkpoints, runs and comparison groups. Pages display 50 rows with one cursor lookahead. A 3,600,000-byte Unicode artifact is read in 1 MiB chunks. Each caller runs 30 times. Node v22.23.2, Darwin arm64 and loopback PostgreSQL 14.17 (Homebrew) were used. Data was freshly seeded without manual `ANALYZE` or cache eviction; repeated calls warm caches. Raw diagnostic outputs are outside Git at `/tmp/openlegend-cognition-lab-storage-20261024-{a,b,c,d,e}.json`. Selecting keys in a subquery before hydration still sorted all matching keys (2.905 ms median at 10,000). These measurements did not satisfy bounded selected work.

The final query takes one ordered indexed identity at a time through a bounded recursive key selection, then hydrates those exact identities. Both sizes visit 51 identities and hydrate 51 bodies; the final sort covers only those 51 rows. At 10,000, its evidence plan uses the composite evidence page index and 306 shared buffer hits across key selection and exact hydration, with no shared reads. This trades a small fixed cost on tiny collections for predictable selected work despite fresh statistics. Actor and interval page plans also select 51 rows. ## Correctness and limits

Focused disposable-database tests exercise byte admission and terminal receipt reserve, duplicate commands, exact indexed reads and owner guards, retained-file leases/reference-safe deletion, paired native checkpoint/experiment snapshots, current-format streamed bundle validation, multi-page evidence, exact Unicode payloads and duplicate imports. Native import leaves the active world untouched until an explicit restore owner installs the validated pair.

Individual metadata owners are bounded by the native 1 MiB row limit, including their exported entry envelope. Exact long payloads use streamed artifacts. A saved scenario/checkpoint stores its complete experiment in a referenced JSON artifact; it does not impose that row limit on the aggregate settings, custom fields, holds or participant lists. Tests capture and restore multi-megabyte contexts, export/import a context with 401 custom fields, and preserve split Unicode, escaped text and valid JSON lone surrogates. Encoding chunks stay below 64 KiB; decoding validates UTF-8, unique object keys and the current snapshot schema without constructing a whole serialized text copy. Capture and restore still require the complete applied snapshot in memory; ordinary metadata pages do not hydrate it.

The current store keeps a single persistent 16 KiB recovery credit inside its reported reserved bytes. A bounded recovery receipt (at most 2 KiB) can claim that credit when ordinary admission is full, remove retained work, and replenish from genuinely freed space. Allowance increases can replenish it atomically before claiming the receipt. The credit is shared and durable, not a new reserve per command; a second pending recovery cannot reuse it. Tests verify the full-capacity deletion, duplicate/restart outcome and allowance-increase paths. An exhausted finite allowance cannot retain unlimited recovery receipts; if credit falls below the minimum, allowance must increase before another recovery command.

An exact durable replacement marker can preserve its pending operation’s terminal credit across startup; unrelated transient capture reservations are released and other pending commands become interrupted. Saved-work management separately requires current native creator authority. An owned record whose historical content is withheld exposes only its ID, kind and creation time. Deletion reads the reference graph and registered native checkpoint manifest, without reading its protected label, summary or context. Tests verify authority changes during reads, withheld-content cleanup and shared-checkpoint retention. The lab metadata layout has a separate current marker, so an earlier partial-index layout is refused before writes without changing the native checkpoint format or adding a migration.

Management search selects the same bounded indexed header page for every query, applies native disclosure, then matches only permitted names and summaries. Withheld rows never match historical text; otherwise a matching tombstone would disclose private-word membership. Its cursor depends only on the safe scanned ID/time, so an empty filtered page may still offer more pages. A focused test compares secret-name, secret-summary and absent queries, verifies identical empty pages/cursors, and reaches a permitted match on the next page. This security correction does not change the unfiltered caller measured above or hydrate whole experiment payloads.

This campaign does not qualify HTTP/browser latency, full-game responsiveness, operating-system cold reads, remote PostgreSQL, native checkpoint capture/restore latency or remote-model quality. Native save packaging has correctness coverage; complete native HTTP capture and repeated restore measurements have a [separate report](cognition-lab-runtime.md). No providers were invoked: additional and cumulative Jev cost for this storage campaign were $0. The parent task owns cumulative task-wide accounting.
