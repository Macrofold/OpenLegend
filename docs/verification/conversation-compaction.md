Both database adapters preserved a short exchange and its independent trigger without generation. A 182-turn, 120,470-byte permitted history became a 17,765-byte projection with 26 recent exact turns; downstream decision context was 39,621 bytes. Warm reuse made zero compactor calls. A cold 1,302-turn history requiring more than eight chunks rejected before any compactor dispatch. PostgreSQL initially hit its five-second statement timeout because cold statistics selected multiplying joins across complete conversation/source ranges. The final query restricts history by conversation and performs keyed actor eligibility/revision/correction lookups, without scanning unrelated personal recall or applying a lossy candidate limit. The final cold PostgreSQL observation was 67.2 ms; an earlier SQLite observation was 43.5 ms. These are local overflow observations, not throughput percentiles or a matched pre-change benchmark. Metadata selection/validation still grows with conversation history; the row limit bounds admitted results, not all database work.

This did not exercise scheduler timing or live reflection quality. The running production client exposed the authorized Conversation context card, byte allowance/usage, recent counts, coverage and keyboard-expandable exact projection. The inspector names compaction stages and measures object contexts as serialized text. These observations establish integration, not model quality.

### Conversation compaction review

The requested follow-up review refreshed the same `origin/design/conversation-compaction` base; it remains `33bbfde1e8f38480407f19f96dace25fb6719f8b`. Three native reproductions failed before fixes: a duplicate group represented by another conversation's ID reintroduced compacted raw speech (including through mandatory recent-memory coverage); an awareness edit committed while an older SQL validation result returned was accepted; a custom store could expose a retained row marked forgotten. The resulting changes distinguish genuinely required source evidence from recent-memory coverage, inspect all duplicate-group members, fence publication revisions around metadata reads, and validate custom-store forgetting/source edits. A normal append racing a validation read still passed after one additional native read. A separately supplied trigger retained its evidence binding even when absent from the coalesced evidence list; corrected sources also remained independently required.

Disposable SQLite and PostgreSQL scenarios passed corrected-source races, duplicate suppression, short/long preparation, failure/cancellation, competing publication, correction/forgetting, partial hearing, same-version restart and lazy restore. PostgreSQL reflection publication and stale-reflection rejection passed with injected output. A fresh `AiDirector.submitInteractive` run completed four fixture compactions and one native speech response. The 182-turn downstream decision fell from 39,621 to **34,021 bytes** after removing duplicate raw recall; its 17,765-byte conversation projection was unchanged. The cold 1,302-turn overflow still rejected before generation: review observations were 38.6 ms SQLite and 651.7 ms PostgreSQL, illustrating host/planner variability rather than a stable cold-latency improvement.

A matched alternating before/after comparison used the same disposable 182-turn world, cached fixture summary and 30 warm samples per implementation on each backend. Each sample prepared conversation context and performed three subsequent validations. Warm generation count was zero; projection bytes were identical. The saved pre-review context owner was compared with the revised owner using the same current repository query and data. Results therefore isolate context/validation changes, not a release-to-release whole-system comparison:

No history-independent, population-scale or model-latency improvement is claimed.

No prompt/model changes, paid calls or automated test suites were made for this review. The earlier live qualification remains scoped to those constructed examples, and the task's accounted provider total remains $1.27835743 including the unpriced-call hold.
