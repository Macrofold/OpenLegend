## Techniques implemented for actual comparison

- **One final reduction:** a `screen` character control captures at twice the actual displayed framebuffer dimensions, with linear color reconstruction and nearest depth. It retains the same body/label/pointer mapping, not a 96-row intermediate. Paired allocations round to 16 pixels, grow before undersampling and shrink after a factor-of-two drop. This control costs approximately four times the displayed area, with retained rounding/hysteresis overhead. It is separate from source texture resolution and all original fixed-row controls.
- **Deliberate surface art:** original connected leaf/bark/stone/ground clusters follow fixed object/metre coordinates, with mipmapped minification and contrast taper when source texels become subpixel. Foliage/bark use a two-metre repeat with 16 source texels per metre; broad ground fields retain quiet regions. Camera changes alter neither source artwork nor geometry. The first eight-metre weak tile failed visual inspection and was revised; ordinary faceted geometry alone is not accepted pixel artwork.
- **Final grids:** current half/third scene targets remain controls. Full-resolution scene rendering with 4×MSAA can instead feed a final two/three-display-pixel grid. A second variant anchors a five/seven-and-a-half-centimetre grid to an orthographic world point and integrates fractional cell-boundary coverage, retaining continuous camera movement. Perspective uses a screen grid because one global phase cannot stabilize all perspective depths. Orbit/zoom/newly visible surfaces remain separate risks.
- **Subject preservation:** an unused opaque HDR alpha channel marks prepared solid scenery while retaining real full-resolution depth. Existing people, animals, grass cutouts, fire and small sprite objects retain their detail in the full-resolution composition; generated crate solids follow scenery. At mixed boundaries, weighted scenery-color numerators are reconstructed continuously before normalization. The first hard threshold could pop a complete cell; interpolating normalized empty cells could create dark fringes; both were corrected before moving acceptance. Mixed foreground/background source pixels remain an approximation, not lossless layer separation. No second geometry/visibility pass or native collision change is added. RGBA16F and additional final samples increase cost.
- **Filtering and soft shadows:** imported character maps can use source/nearest/trilinear minification independently of Canvas sprite filtering. The source samplers restore exactly and late loads use the current selection. A fixed soft-shadow sample-pattern control removes the pinned PCSS shader's screen-position random rotation; the original screen pattern remains available. It is a comparison, not proof that all shadow-map movement is solved.

## Initial moving results and comparison limits

Five profiles traversed the same frozen-pose/daylight/wind-isolated slow orthographic pan, orbit, perspective pan/orbit and close zoom. Each still pair was byte-identical and each run had zero browser errors. These are still-view and finite-path findings, not proof of zero shimmer. Profiles were the rejected first candidate; full-detail character plus a common two-pixel final grid; fixed-96 character with orthographically anchored scenery and preserved subjects under each shadow setting; and painted surfaces without a coarse final grid. The surface-only run used the RGBA subject-preservation format even though its final grid was disabled; it is not the selected shared-format performance measurement.

The common final grid softens neighboring sprite faces and small props. Preserving subjects keeps those details sharper, but coarse scenery makes crate/structural details softer. Surface artwork without a coarse final grid retains leaf plates, plank seams, chest bands and fine ground marks more clearly. Conifer tiers/lobed crowns remain simple geometry, close leaf plates can read as camouflage, the noon palette is strongly yellow-green, and the mercenary’s sampled outfit/face remains grainier than the simpler sprites. Those are visible limitations, not accepted style decisions.

A matched close pair changes only character capture resolution before the same final two-pixel grid. The fixed target is 65×114; the full-detail target is 352×592 at that view, 28.12 times the capture area. Both retain the same 2.035 m height, 1.1 display scale and 294-display-pixel vertical rectangle. The higher-detail capture recovers facial/garment detail otherwise lost before final sampling; it does not establish stable permanent body pixels or justify enlarging the person. This comparison remains available rather than silently increasing default character density.

### Surface-point check and shadow-control correction

At 1,102 identical world positions before/after a 0.36 m orthographic pan, nearest-display-sample maximum-channel RGB differences have median/p95 0/1 for both full resolution and the anchored two-pixel control. Twelve full-resolution and sixteen anchored samples differ by more than eight levels. The rectangle crosses grass, the archery target and paint/shadow boundaries; these counts are not a shimmer score. All 885 common samples whose five-by-five image neighborhoods stay within six levels differ by at most one RGB level in both modes. This finite flat-interior result shows no decisive anchored-grid advantage and does not qualify moving silhouettes, occlusion or arbitrary surfaces.

Crucially, every initial screen/fixed-shadow pair was pixel-identical over the entire image. Review found the first control changed spot/omni PCSS while the directional sun uses a separate shader chunk. Local lights use PCF, so neither comparison reached an active PCSS path. The original shadow comparisons are **invalid as evidence of a fixed-sun benefit**. The repair targets the actual directional random seed as well, with one guarded uniform shared by both pinned chunks. The corrected control was then exercised in three fresh application recordings: painted/full-scene with original sun pattern, painted/full-scene with fixed sun pattern, and a full-detail mercenary with one final common grid. All three frozen still pairs were byte-identical, both camera projections/pan/orbit/zoom paths completed, and browser errors were zero. The matched initial screen/fixed PNGs now differ at 19,521 image pixels below the caption, 3,706 by more than eight RGB levels; this establishes that the repaired switch reaches visible sun shading, not that a changed image is more stable. The original screen-driven noise is removed by construction; filtered shadow-map edges, new silhouette coverage and the grainy fixed-row character remain separate limitations. Moving footage supports retaining the fixed-pattern trial, without a blanket no-shimmer claim.

The focused application check exercises actual pointer selection in both projections, a DPR 1.5 / 1,191×793 resize, full-detail/common-grid/preserved-subject control changes and return, read-through behind an opaque wall, pause, three model→sprite→model replacement cycles, and full destruction. All pass with zero browser errors. Read-through reaches 0.7 under the supported nearby preference and reaches zero/disabled after Off. The first probe incorrectly used an unsupported `all` preference and was rejected as fixture error; it is not a product regression or a pass.

The resized fixed capture stays 65×114; the framebuffer stays one pixel per CSS pixel under the existing device cap. Pause retains identical source/pose hashes and finite cloth. All three replacement cycles retain exactly the same assets, render passes, shared surface-texture IDs and reported buffer/texture totals. Destroyed owned color/depth plus all four surface textures have no live device; vertex/index/uniform bytes reach zero, with the same 150,232-byte residual engine texture bookkeeping seen in earlier lifecycle evidence. These counters are not total driver residency and do not measure multisample renderbuffer storage. Unchanged failed/late source-load and native route/content behavior reuse the earlier scoped evidence; no fresh broad gameplay qualification is claimed.

Earlier first-candidate timings and the initial ineffective-shadow run are historical measurements; they cannot qualify the corrected shadow result. The corrected-sun production run measured 600 frames each at requested 1×/8× after 180 warm frames on physical Apple M1 Pro / ANGLE Metal, Chrome 155, 1440×960/DPR1, Detailed shadows, one sun/one fire and 38 presented entities. Before the final surface-edge filtering trial, displayed median/p95/maximum intervals were 28.4/59.4/126.7 ms at 1× and 26.6/56.7/107.4 ms at 8×; application CPU median/p95 was 6.5/10.0 and 6.7/9.9 ms, full GPU 25.33/69.92 and 33.50/87.00 ms. This does not qualify smooth 60 Hz play. The world advanced during these sequential requested-speed cases and observed/drawn subjects changed, so differences are not a causal speed or rendering-technique comparison. An earlier ineffective-sun-control run was faster; its changed shading and workload cannot substitute for these results. Final edge-filter profile timing remains pending.

Actual WebGL allocation tracking, installed before scene construction and using weak references, exposed a pinned-engine lifecycle failure hidden by texture counters: its camera-frame target deletes MSAA color storage but omits deletion of unshared MSAA depth. A 1,440×960 four-sample depth/stencil attachment is 22,118,400 nominal bytes; startup plus one none→4→none cycle left two undeleted after scene destruction. Eventual browser/driver collection is unmeasured. The scene now wraps only its own camera frame’s update/target destruction to delete that unshared depth buffer; shared cache-owned depth remains with the engine. This also covers late engine layer rebuilds and resize, without a global dependency patch or extra depth pass. Fresh post-fix allocation/resize/format/teardown evidence is pending. API attachment bytes exclude textures, driver alignment/compression and total process VRAM.
