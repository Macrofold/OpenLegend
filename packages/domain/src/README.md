# Headless domain contract

## Spatial host boundary

World-root XYZ positions and support IDs are authoritative; contained and attached objects resolve through the placement owner. Hosts initialize the shape-query adapter before world creation/restoration. Pure domain transitions may emit a pending NavigationRequest; they never initialize WASM, generate meshes, await workers or call a provider. Completed routes re-enter through completeNavigation, and navigationBlocked is the required-data barrier for native steps. See the [runtime contract](../../../archive/07-technical-architecture/spatial-world-runtime.md).

## Spatial authority

The [spatial runtime](../../../archive/07-technical-architecture/spatial-world-runtime.md) owns exact coordinate/provider semantics. World roots use required XYZ plus explicit support and body profile. Native action transitions call shared support/sweep/reach logic; renderer/SDK objects never enter the domain, protocol or save. Static full-extent indexes and round-body queries serve the current public map. Nontrivial ground routes are prepared through the server Recast worker and admitted as plain native paths. Crowd dynamics and generic construction remain future family work. Incompatible development saves are rejected rather than read with optional Y.

`index.ts` is the package boundary. State and return values are plain JSON; the kernel imports no renderer, provider, transport, database or ambient clock. It uses persisted seeded RNG, stable IDs and structurally shared immutable state. The application binds actor/world authority before calling it and commits returned state, receipts and events together.

- `createActor(world, controller, fullness)`: creates an actor with three distinct described traits sampled from `worlds/base/config/traits.json` using saved RNG. Save the returned actor in the creating transition. Trait prose grants no mechanical powers. `initializeActorTraits` initializes missing traits for memory-capable actors from the bundled source and preserves existing descriptions; it is not an older-save reader.
- `spawnWorldEntity` and `reviveActor`: bounded owner-authorized transitions used by the server's god routes. Spawning accepts only the finite native catalogue on blank walkable ground. A person saves authored identity and selected bank traits, or uses `createActor`'s three-trait RNG default when none are selected. Revival restores a compatible dead actor to its installed body policy’s viable needs without advancing time and requires a clear supported stance. It clears any corpse/remains record, including after harvesting, while preserving already-created resources; it does not refund or undo those earlier effects. Request receipts and expected body revisions support retry/stale handling. Both emit committed god-labeled events; neither admits generated definitions or executable behavior.
- `createWorld(seed?)`: creates the primitive wilderness, people, native materials, finite resources, animals and dependable cooking fire. `recipes` starts empty. Generated recipes start empty; trusted installed family descriptors admit current-format candidates and compile their native components. Finished recipe compositions exist only in explicit fixtures, never production seeds.
- The current schema uses one actor lifecycle/body model with independent capabilities. `living.ts` owns body reconciliation and native effects; raw health has one body owner and installed numeric meters have one sparse-state owner. The exact installed body policy supplies lifecycle and survival services; animal components contain wandering/fleeing state only. Selected animals can gain cognition and speech without changing physical identity. See the [canonical actor model](../../../docs/architecture.md#actor-means-any-living-being).
- `conversations.ts` owns speech association, membership intervals, leave/closure and atomic merge redirects. Membership never grants event awareness. `social.ts` owns immutable objective kinship. `appraisals.ts` owns stable private appraisals with world-pinned lifetimes; directional relationship text is the actor’s existing subject knowledge document, edited only through `knowledge.ts`. Accepted About me remains self-understanding.
- `executeCommand(world, command)`: validates an action and returns `{world, events, outcome}`. An accepted command ID is reusable only with the same canonical body. Rejections leave input state unchanged. Keep receipts durable for the session's retry horizon.
- `advanceWorld(world, elapsedGameSeconds, { maxIntervals })`: accepts a bounded elapsed prefix without AI. Mechanical deadlines and explicit world fidelity bounds determine interval sizes; callers subtract actual `world.simTime` progress, not requested seconds or call counts. Paused or navigation-blocked worlds do not advance. The application owns presence, real-time speed/budgets and no-catch-up policy. See [simulation time](../../../docs/simulation-time.md).
- `admitDeclaration(world, draft, provenance)`: independently validates a current-format candidate against its exact installed trusted family, records provenance and dependency pins, compiles an immutable output definition and teaches its inventor. Family policy and descriptions belong to the authored world; saved compiled fields must reproduce the source candidate under the same pins. Admission does not craft an item or teach observers. Exact candidate retries deduplicate; semantic paraphrase retrieval belongs in application intent routing.
- `observeActor`, `queryMemories`: build actor-scoped evidence. Bind the requested actor ID to server authority. Never send a complete `WorldState` to a client or model. `remember` records application-validated private appraisal, requiring perceived event evidence for observed/heard sources.

`agency.ts` centralizes private operational goals and bounded native frontiers; `response.ts` admits optional repeated operations with independent outcomes. Continuation uses the existing kernel command/action lane. The [agency runtime](../../../archive/07-technical-architecture/agent-agency-runtime.md) owns the target contract; [Architecture](../../../docs/architecture.md#actor-agency-foundation) records the current boundary and [AG](../../../docs/maintainers/agent-agency.md) tracks remaining work.

Positions use continuous `{x,y,z}` with an explicit support identity; terrain lookup still uses `tiles[z][x]`. Actor IDs are opaque; resolve the controlled actor and default resident through saved bindings. The bundled human policy uses fullness and energy from 0–100; 100 fullness is full. Health maxima and applicable needs come from the installed body/world policy, not a universal human schema: current animals have species-specific health maxima and some bodies have no food or sleep need. Actors have a persisted birth time on the same simulation clock. The bundled NPC policy permits death; its player policy uses collapse and explicit camp recovery.

The bundled world composes native operations to prepare raw fiber into usable fiber, twist cord, gather, move, rest, shoot compatible projectiles, harvest finite remains, cook raw meat and consume edible food. Timed work consumes inputs when actual work starts. Cancelling does not refund inputs already consumed. Shots spend one projectile only after fresh target/range/tool/ammunition checks. Live animals flee from shots and can be missed. Navigation and line of sight use authoritative terrain.

Declaration roles reference material capabilities, rather than names granting powers. The supported launcher family accepts swing/stone and flex/arrow mechanisms. Arrows are separately generated and crafted ammunition. Drafts cannot contain scripts, arbitrary effects, new sources, nutrition, or unsupported properties. The validator certifies this small authored envelope; it does not establish arbitrary physical plausibility. An additional trusted world family may compose existing native operations without changing the kernel. Genuinely missing computation requires a narrow reviewed engine capability; names and generated prose never supply it.

Events freeze their eligible audience at commitment. Event names include `speech` (`data.text` is the raw utterance), `declaration-admitted` (`data.recipeId`), `crafted` (`data.recipeId`, `data.itemId`), `shot` (`data.hit`, `data.damage`, `data.ammunitionKind`), `body-effect`, `harvested`, `cooked`, `ate`, `taught` and `death`. Notable unseen events may be retained with no audience. Only memory-capable audience members receive awareness entries referencing the shared event; those entries are projected into actor recall without duplicating the event as a raw memory. Knowledge is separate from the world's recipe registry. An explicit nearby `teach` action conveys one known technique.

Native bodily simulation, genuine incapacity and already-admitted work continue independently of provider access. Bundled cognitive people choose feeding through ordinary agency; the kernel does not automatically gather or eat for them during provider delays. Separately configured native animal/reservoir responses remain explicit world/controller policy, not a generic promise that AI failure cannot lead to starvation. Private memories distinguish episode/belief/commitment/reflection and observed/heard/inferred sources. Ordinary memory retention is bounded; active commitments have a separate allowance. Hourly/daily experience consolidation and accepted reflection text are implemented through server scheduling and domain transitions; persistent and internal-source appraisal continuity uses the same accepted publication boundary; broader vocabularies and more elaborate embodied needs remain separate additions.

`kernel.test.ts` exercises an actual generated-declaration fixture → craft → hunt → harvest → cook/eat loop, a second launcher/ammunition composition, deterministic misses, wrong materials/ammunition, resource races, stale shots, cancellation, save/restore, pause, idempotency, scoped learning/memory, bodily progression without automatic feeding, and mortality. Fixture tests demonstrate the mechanical path, not live provider acceptance.

Transitions now use `draftWorld`/`finishWorld` (or `updateWorld`) from `draft.ts`. Published state is immutable by contract: unchanged branches retain identity for incremental persistence and public projection. Never mutate a transition result in place; create a new draft when composing transitions. Immer is isolated with auto-freezing disabled for owned initial-world construction. The server calls `freezeWorld` at ownership boundaries and after each native step so finalization can skip unchanged frozen branches; freezing transfers an owned snapshot to immutable use without cloning it. No draft may escape through events or observation DTOs.

Owner-editor additions, edits and deletions pass through `mutateExperience`; deletions apply authoritative forgetting, including dependent-summary removal, a durable forgetting ledger and derived mind invalidation. Unresolved commitments remain authoritative and cannot be deleted by the editor. See [current architecture](../../../docs/architecture.md#public-updates-and-owner-editors).

Draft finalization records append-only event lineage for persistence. Retained-event edits and incompatible forks cannot reuse that shortcut; routine appends compose until durable flush. Importance-only experience edits invalidate retrieval metadata without discarding dependent prose.
