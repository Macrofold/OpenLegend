# Headless domain contract

## Spatial host boundary

World-root XYZ positions and support IDs are authoritative; contained and attached objects resolve through the placement owner. Hosts initialize the shape-query adapter before world creation/restoration. Pure domain transitions may emit a pending NavigationRequest; they never initialize WASM, generate meshes, await workers or call a provider. Completed routes re-enter through completeNavigation, and navigationBlocked is the required-data barrier for native steps. See the [runtime contract](../../../archive/07-technical-architecture/spatial-world-runtime.md).

## Spatial authority

The [spatial runtime](../../../archive/07-technical-architecture/spatial-world-runtime.md) owns exact coordinate/provider semantics. World roots use required XYZ plus explicit support and body profile. Native action transitions call shared support/sweep/reach logic; renderer/SDK objects never enter the domain, protocol or save. Static full-extent indexes and round-body queries serve the current public map. Nontrivial ground routes are prepared through the server Recast worker and admitted as plain native paths. Crowd dynamics and generic construction remain future family work. Incompatible development saves are rejected rather than read with optional Y.

`index.ts` is the package boundary. State and return values are plain JSON; the kernel imports no renderer, provider, transport, database or ambient clock. It uses persisted seeded RNG, stable IDs and structurally shared immutable transition results. The application binds actor/world authority before calling it and commits returned state, receipts and events together.

- `createActor(world, controller, fullness, identity?)` is the bundled-world factory in `worlds/base/world.ts`, not a universal actor constitution. It preserves supplied traits, personality, backstory and initial goals; omitted traits use three distinct descriptions sampled from `worlds/base/config/traits.json` with saved RNG. Its fullness argument is a starting percentage of the installed world-defined meter range. Save the returned actor in the creating transition. Trait prose grants no mechanical powers. `initializeActorTraits` initializes missing traits for memory-capable actors from the bundled source while preserving existing descriptions and the shared RNG position; it is not an older-save reader.
- `spawnWorldEntity` and `reviveActor` are bounded transitions reached through owner-authorized creator actions. Spawning accepts the supported native catalogue on a clear walkable stance and saves authored identity; omitted traits use the bundled factory default, while explicitly supplied traits remain explicit. Revival requires a compatible dead actor, a current expected body revision when supplied, and a clear supported stance. It restores body health, applies the installed revival meter policy and clears remains without advancing time or clawing back previously harvested items. Request receipts retain retry/stale handling. Both emit committed god-labeled events; neither admits generated definitions or executable behavior. Ordinary player recovery and future ghost behavior retain their separate world-policy owners.
- `createWorld(...)` in `worlds/base/world.ts` assembles the bundled wilderness, people, native materials, finite resources, animals and cooking fire. Generated recipes start empty; installed family descriptors admit current family-scoped candidates and compile their native components. Finished recipe compositions exist in explicit fixtures, not production seeds. Other worlds may supply different content through the same supported mechanisms.
- The current schema uses one actor lifecycle/body model with independent capabilities. `living.ts` owns body reconciliation and native effects; raw health has one body owner and installed numeric meters have one sparse-state owner. The exact installed body policy supplies lifecycle and survival services; authored animal behavior does not own a second health or death model. Selected animals can gain cognition and speech without changing physical identity. See the [canonical actor model](../../../docs/architecture.md#actor-means-any-living-being).
- `conversations.ts` owns speech association, membership intervals, leave/closure and atomic merge redirects. Membership never grants event awareness. `worlds/base/family.ts` owns biological parent links, graph invariants and computed family descriptions. `appraisals.ts` owns stable private appraisals with world-pinned lifetimes; directional relationship text is the actor’s existing subject knowledge document, edited only through `knowledge.ts`. Accepted About me remains self-understanding.
- `executeCommand(world, command)`: validates an action and returns `{world, events, outcome}`. An accepted command ID is reusable only with the same canonical body. Rejections leave input state unchanged. Keep receipts durable for the session's retry horizon.
- `advanceWorld(world, elapsedGameSeconds, { maxIntervals })`: accepts a bounded elapsed prefix without AI. Mechanical deadlines and explicit world fidelity bounds determine interval sizes; callers subtract actual `world.simTime` progress, not requested seconds or call counts. Paused or navigation-blocked worlds do not advance. The application owns presence, real-time speed/budgets and no-catch-up policy. See [simulation time](../../../docs/simulation-time.md).
- `admitDeclaration(world, draft, provenance)`: independently validates the current candidate envelope against its exact installed trusted family, records provenance and dependency pins, compiles an immutable output definition and teaches its inventor. Family policy and descriptions belong to the authored world; saved compiled fields must reproduce the source candidate under the same pins. Admission does not craft an item or teach observers. Exact candidate retries deduplicate; semantic paraphrase retrieval belongs in application intent routing.
- `observeActor` and `queryMemories` build actor-scoped evidence from the supplied native snapshot. The latter is a bounded-result local helper, not the server’s complete retained-history recall path; production context preparation uses scoped repository queries and current privacy checks under [memory architecture](../../../docs/memory-architecture.md). Bind the requested actor ID to server authority. Never send a complete `WorldState` to a client or model. `remember` admits a bounded private memory proposal, requiring perceived event evidence for observed/heard sources; accepted appraisals use their own publication owner.

`agency.ts` centralizes private operational goals and bounded native frontiers; `response.ts` admits optional repeated operations with independent outcomes. Continuation uses the existing kernel command/action lane. The [agency runtime](../../../archive/07-technical-architecture/agent-agency-runtime.md) owns the target contract; [Architecture](../../../docs/architecture.md#actor-agency-foundation) records the current boundary and [AG](../../../docs/maintainers/agent-agency.md) tracks remaining work.

Positions use continuous `{x,y,z}` with an explicit support identity; terrain lookup still uses `tiles[z][x]`. Actor IDs are opaque; resolve the controlled actor and default resident through saved bindings. Installed attribute definitions own meter units and ranges; the body owns health. A bundled 0–100 tuning is not an engine-wide constraint. Birth time uses the same simulation clock. Mortality, incapacity, camp recovery and revival follow the installed body/world policy, not a universal rule inferred from player or NPC labels; [base-world lifecycle](../../../docs/worlds/base/lifecycle-and-protection.md) owns the selected game behavior.

Bundled-world actions include fiber preparation, cord manufacture, gathering, rest, compatible shooting, finite harvesting, cooking and eating; these are authored mechanics using shared execution, movement, item and resource owners, not laws every world must inherit. Timed work consumes inputs at its actual admitted start, and cancellation does not refund committed inputs. Shots spend one projectile only after fresh target/range/tool/ammunition checks; misses and animal flight use the installed world rules. Navigation and line of sight use authoritative spatial geometry, not artwork.

Declaration roles reference material capabilities, rather than names granting powers. The installed catalogue and each exact family schema determine the permitted parameters, material roles and compiled output. The bundled launcher examples support swing/stone and flex/arrow mechanisms, with arrows separately generated and crafted; [world-owned families](../../../docs/worlds/base/invention-families.md) also identify gathering tools, containers and manufactured cordage with their distinct admission rules. Drafts cannot supply scripts, arbitrary effects or unsupported fields; the former candidate-format envelope is not accepted. Validation certifies the selected trusted family, not arbitrary physical plausibility. Extend an existing family where its mechanism suffices; add a trusted native capability only when the required computation is genuinely missing.

Events freeze their eligible audience at commitment. Speech additionally retains listener-specific permitted words, identity and evidence: audience membership alone never authorizes the raw utterance. Consumers use the [hearing projection](../../../docs/hearing-and-speech.md), not `event.text` or `data.text` directly. Event names include `speech` (`data.text` is the raw source utterance), `declaration-admitted` (`data.recipeId`), `crafted` (`data.recipeId`, `data.itemId`), `shot` (`data.hit`, `data.damage`, `data.ammunitionKind`), `body-effect`, `harvested`, `cooked`, `ate`, `taught` and `death`. Notable unseen events may be retained with no audience. Only memory-capable audience members receive awareness entries referencing the shared event; those entries are projected into actor recall without duplicating the event as a raw memory. Knowledge is separate from the world's recipe registry. An explicit nearby `teach` action conveys one known technique.

The kernel advances already admitted actions and native plans without provider calls; it does not choose automatic eating, foraging or rest for bundled people when a provider is slow or unavailable. A separately installed numeric meter and compatible replenishment source can use the finite native replenishment controller; that is not a general survival autopilot. Private records distinguish episodes, beliefs, commitments, reflection and their evidence/source meanings. Bounded resident evidence and prompt windows do not cap or discard the complete retained history; older permitted sources remain in the existing PostgreSQL repository. Unresolved commitments retain separate admission and protection rules. Hourly/daily consolidation, accepted reflection and persistent/internal appraisal publication keep their existing server/domain owners; broader psychological behavior remains separately tracked.

`kernel.test.ts` exercises an actual generated-declaration fixture → craft → hunt → harvest → cook/eat loop, a second launcher/ammunition composition, deterministic misses, wrong materials/ammunition, resource races, stale shots, cancellation, save/restore, pause, idempotency, scoped learning/memory, native survival and mortality. Fixture tests demonstrate the mechanical path, not live provider acceptance.

Transitions now use `draftWorld`/`finishWorld` (or `updateWorld`) from `draft.ts`. Published state is immutable by contract: unchanged branches retain identity for incremental persistence and public projection. Never mutate a transition result in place; create a new draft when composing transitions. Immer is isolated with auto-freezing disabled for owned initial-world construction. The server calls `freezeWorld` at ownership boundaries and after each native step so finalization can skip unchanged frozen branches; freezing transfers an owned snapshot to immutable use without cloning it. No draft may escape through events or observation DTOs.

Owner-editor additions, edits and deletions pass through `mutateExperience`; deletions apply authoritative forgetting, including dependent-summary removal, a durable forgetting ledger and derived mind invalidation. Unresolved commitments remain authoritative and cannot be deleted by the editor. See [current architecture](../../../docs/architecture.md#public-updates-and-owner-editors).

Draft finalization records append-only event lineage for persistence. Retained-event edits and incompatible forks cannot reuse that shortcut; routine appends compose until durable flush. Importance-only experience edits invalidate retrieval metadata without discarding dependent prose.
