# Verification and paid execution

## Local verification only

Repository checks run locally, never through GitHub Actions. Do not dispatch, enable, retry or wait for GitHub checks, or add or restore GitHub CI workflows. A push, pull request, merge command, skill or project plan does not authorize hosted verification.

Reuse installed local dependencies and the running local PostgreSQL service when suitable; database checks still use their own disposable databases. Existing requirements to run CI mean the applicable local checks selected under this policy, not remote status checks or automatic full-suite reruns. Full validation still requires Mike's explicit request; ordinary work uses the focused checks below.

## Default delegated implementation

Write new automated tests only when Mike asks for them; a project document, acceptance criterion or skill does not by itself require them. Focused existing unit, integration or browser checks relevant to the change are permitted; select explicit files, test names or projects and inspect their fixtures, database and side effects before execution. `pnpm check`, unfiltered `pnpm test` and unfiltered `pnpm test:browser` remain full validation, run locally only when explicitly requested. Static checks and small manual/ad-hoc runtime scenarios are also permitted. Do not recreate a broad suite through many ad-hoc scripts, delete coverage, weaken required checks or waive acceptance criteria.

Exercise changed behavior through real downstream callers in a representative scenario and meaningful failure case where feasible, including review fixes. Group checks around a connected player journey, keeping immediate checks for permissions, privacy, current-format storage and committed effects. Prefer existing tools and retained checkpoints with their actual permissions/history; before copying a retained world into a diagnostic, read the [checkpoint capture contract](../../docs/save-and-load.md#current-history-capture-boundary) and check fixture compatibility. Repeated setup failures call for simplifying the scenario or repairing the shared fixture owner, not growing a parallel temporary suite. Distinguish fixture repair from product delivery. Reopen valid evidence only for a specific defect or changed dependency; static checks alone do not establish runtime behavior. Use disposable worlds, never replace someone's save. Native checks use `AI_BUDGET_USD=0` without unrelated credentials. UI work needs actual interaction/visual inspection when available. Findings-only reviews and design-only work do not require running the game merely because a skill mentions verification. Missing access is a gap, not a pass.

For disclosure checks, first establish that the underlying event or committed effect actually occurred. Confirm the owning participant's evidence when the installed disclosure policy permits it. An observer account omitting health after a missed attack does not demonstrate private-health filtering. Use a controlled positive case when needed, and distinguish that native/disclosure proof from natural hit rates, encounter balance or autonomous choice. [The shield checks](../../docs/verification/shield-defense.md#focused-checks-and-lookup-measurement) record this fixture pitfall.

For interruption, recovery or replacement guarantees, also exercise the state after the earlier action has stopped or been cleared. A busy-action refusal can mask a missing longer-lived constraint. Inspect the ordinary offers and actual admission at that point, and include the later permitted choice when the constraint ends. The [shield review](../../docs/verification/shield-defense.md#second-implementation-review--october-7-2026) only exposed refused resident attack offers after Stop removed the guard action while body recovery remained. Use focused existing checks or the evolving ad-hoc scenario; this adds no automatic test-writing mandate.

PostgreSQL is the only local and production database. Use disposable PostgreSQL databases for database-dependent verification; the shared fixture helper requires an explicit loopback administrative URL and creates/drops only its own databases. Do not run SQLite parity checks or recreate SQLite support unless explicitly requested. If PostgreSQL is unavailable, report the verification gap. Existing required local verification and merge gates remain required.

Choose checks by impact: pinned Prettier on changed files, `pnpm typecheck` for TypeScript, `pnpm build` for production/build/client integration, `pnpm config:check` for generated configuration, and `pnpm guidance:check` for guidance. Documentation-only work needs content/link review, not game stress. Avoid repository-wide formatting churn. Inspect script side effects before execution. Restore temporary settings and stop processes you started; for Macrofold shared with other agents, follow the [registered-use cleanup procedure](../../docs/live-ai-setup.md#local-macrofold-server-lifecycle). Do not stop another contributor's runtime.

Before costly checks, confirm their required service, storage headroom and execution capacity, including occupied paid slots; a healthy endpoint alone is insufficient. After an environmental failure, stop affected runs and resume only when that prerequisite observably changes; continue independent work. Avoid overlapping owned stress/browser observers with timing-sensitive checks. If a check fails, distinguish product, fixture and environmental failures from an existing baseline using the diff and available evidence. `pnpm typecheck` also checks test sources; stale tests can block it without proving the production build is broken. Report both outcomes where checked; never suppress diagnostics or claim the whole branch is green from a narrower pass. Required local checks remain merge gates; follow the local-only execution policy above.

Stress meaningful hot-path changes under the [performance skill](../skills/openlegend-performance/SKILL.md). Before interpreting timings, confirm the intended active caller path ran: presence, pause/recovery state and expected prepared results must match the workload. An expired session returning a cheap refusal does not measure active inventory preparation. Discard such samples; distinguish helper, complete service, HTTP and rendered-interaction costs. Record specific missing coverage, reproduction and expected behavior in its focused tracker, using [TODO](../../docs/maintainers/TODO.md) only without a focused owner. Consolidate related gaps and remove only clearly obsolete requirements, not unmet checks. Deferred verification is not acceptance.

## Rebase verification

A history-only or mechanically resolved rebase/merge does not require runtime requalification when [patch comparison and upstream-overlap review](../skills/openlegend-rebase/SKILL.md#review-and-verify-reconciliation) confirm unchanged behavior and valid prior assumptions. For semantic resolutions, select the smallest existing checks covering the affected behavior and a relevant failure condition. Use applicable static checks; formatting targets changed files. Reuse prior results for unchanged contracts rather than repeating lifecycle, performance or provider qualification. Broaden only for a specific invalidated assumption, introduced failure or explicit task requirement.

When integration changes database/checkpoint formats, current-format admission or the standard starting-world definitions, verify the destination checkout's actual configured development database and checkpoint directory before reporting it ready. A disposable database pass does not establish that the developer's next startup works. Inspect configuration without exposing secrets, check active writer ownership, and apply the [development save policy](../../AGENTS.md#development-save-policy) and [starting-world reconciliation](../../docs/save-and-load.md#starting-world-content-reconciliation) when replacement is needed. Preserve credentials, access controls, spending/uncertain operations and useful content; never bypass admission by editing a marker. Confirm native server initialization, persistence and same-format reopening with paid dispatch disabled, then stop only processes started for the check. This is a focused database readiness check, not browser qualification. If access or another writer prevents it, report the merge's local runtime readiness as unverified rather than complete.

**Do not run browser tests or browser playtests, or start a browser/server environment for them, during rebase/merge reconciliation, including UI conflicts.** Review the changed UI code and use relevant static checks; identify reused browser evidence and any remaining gap honestly. Required local checks and separately authorized implementation/player qualification remain separate and are not waived. A rebase alone does not close existing qualification gaps. Apply the [efficient reconciliation principles](../skills/openlegend-rebase/SKILL.md#keep-reconciliation-short) and [root stopping rule](../../AGENTS.md#completion-and-handoff--every-task) once the selected checks and requested reconciliation are complete.

## Spending

Mike's standing authorization covers up to $10 total for each task he assigns, using credentials he authorized for it. Spend within that limit without asking first; before the task would exceed it, stop and ask Mike to raise the limit. Contributors get no permission to charge his accounts. Other accounts need their owner's authorization; absent permission, stay native/no-cost. Documentation or a discovered key grants no authority.

Count settled cost plus outstanding/uncertain commitments across providers, actors, delegates, calls and compute against one task ceiling. Reserve conservatively before dispatch; application per-actor/monthly caps do not enforce this aggregate limit or create extra allowances. Use the smallest adequate bounded call and reuse evidence. Without a credible upper bound and accounting, do not dispatch. This ceiling covers the software/provider work launched for the task, not a claim to measure the coding assistant's own subscription or token billing. Cancellation, invalid output or missing usage do not prove zero cost. No automatic paid retry in experiments or adapters; the explicitly configured [server decision-escalation policy](../../docs/ai-providers.md#decision-escalation) is the narrow runtime exception. Its calls still share this task ceiling.

Automated checks use explicit fixtures, the selected disposable database when needed, and no provider or external-service requests; live-provider experiments are separate. Label static, fixture, native, live-provider and stress evidence distinctly. Keep keys, private prompts/saves and generated verification output out of commits; summarize relevant results under [verification report ownership](documentation.md#verification-reports). Before live gameplay or character-behavior experiments, read the [bounded live playtest protocol](../../docs/verification.md#bounded-live-playtest-protocol) and apply its relevant checklist; the protocol is never proof a check ran.

### Jev cost reporting

Whenever reporting on Jev calls or other Jev-related work, including progress updates, include the total USD cost for the reported scope and the cumulative task total. Preserve the available reported decimal precision; do not round to cents or present a nonzero cost as $0. Label provider-reported estimates, settled charges and reservations distinctly. If costs are missing or uncertain, report that explicitly rather than assuming zero. If no calls were made, state that the additional Jev cost is $0.
