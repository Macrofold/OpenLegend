# Standalone perspective stability experiment (E07)

This tool compares ordinary rasterization with Dylan Ebert's pinned MIT texel-splatting renderer using the **same exported static geometry from the existing starting scene**. It does not load another playable world or alter OpenLegend's graphics backend. All surfaces receive the upstream renderer's neutral stone material so material differences cannot be mistaken for stability differences. It cannot qualify face art, animation, fabric coverage or transparent effects.

Export only player-permitted static mesh data from a disposable copy of the current starting scene. The JSON input is `{ source: { commit, scene }, meshes: [{ name, positions, normals, indices }], camera: { position: [x,y,z], target: [x,y,z] } }`. Positions and unit normals are in world coordinates; indices are local to each mesh. The pinned renderer requires at most 65,535 merged vertices. Include suitable existing ground, shelter, raised surfaces and thin seams/poles; do not invent a replacement map.

```sh
node scripts/art/texel-splatting/run.mjs /private/tmp/starting-scene-geometry.json /private/tmp/e07-results 192
```

The tool uses installed Vite and Playwright, downloads source at `394d350f91842779ed4c45760bd4ea9a07ce5c4c` into a fresh temporary directory, retains its license and records source/input hashes. The adapter's initialization follows the upstream demo; its [MIT notice](UPSTREAM-LICENSE) is retained here too. No upstream source or assets are redistributed in the application. Inspect the recorded adapter and machine before claiming physical-device qualification; a software adapter can supply diagnostics only. `timestamp-query` supplies stage measurements when available. Run separately at 96, 192 or 384 texels per cubemap face. Only that temporary sampling constant is changed.

Both variants use the same camera/light paths and geometry and enlarge to 1280×720. Splatting draws to 640×360; the ordinary baseline uses approximately the central cubemap face's angular density at a 60° field of view (192×108 at a 192-texel probe). This matches apparent detail near the image center approximately; cubemap face angles, depth and zoom still change that comparison. The paths cover movement within a capture cell, crossing a cell boundary, orbit/disocclusion, zoom, thin deck seams and changed light. JSON outside the repository records 60 samples per path/variant, CPU encode time, complete submit/wait time, GPU capture/shading/edge/culling/drawing time, allocation descriptors and source settings. Capture probes and the ordinary renderer remain resident together; allocation snapshots distinguish their incremental costs. Texture bytes are descriptor estimates (four bytes per texel, including nominal depth24plus), not a driver VRAM measurement. GPU timing sums pass durations and also records the first-to-last timestamp span; neither includes presentation or readback. Complete CPU wait includes submission and synchronization. Compare the two clocks before accepting GPU timing on a backend; overlapping or inconsistent pass counters cannot qualify a device. Warm-up and screenshots are excluded from timing samples. The cold preparation measurement includes buffer upload, acceleration-tree construction and pipeline creation; download/browser startup are separate.

Probe time advances monotonically in controlled 1/60-second steps; each path first settles the preceding transition for 36 steps. Recorded motion waits for display frames, while performance samples exclude those waits and screenshot capture. Cold preparation ends before the first scene draw, so it is not time to first rendered image. On Metal, pass intervals can overlap: the sum of individual pass durations can exceed elapsed frame time. Grouped stage spans and the complete first-to-last timestamp span are recorded separately and must not be added together as independent costs.

Raw JSON/screenshots and WebM motion recordings stay outside Git. Visually review both variants at corresponding frames, especially thin geometry and newly revealed surfaces, before recommending integration, revision or deferral. Missing timestamp support or physical-device qualification stays explicit. See [the experiment contract](../../../docs/projects/3d-pixel-art-validation.md#first-scene-technique-experiments) and [research](../../../art-direction/research/3d-pixel-worlds/texel-splatting.md).

## Static stability revisit

```sh
node scripts/art/texel-splatting/run.mjs /private/tmp/starting-scene-geometry.json /private/tmp/e07-stable-results 192 stable
```

The optional `stable` profile preserves both original renderers and adds two explicitly different controls, on perspective and orthographic versions of the same paths plus a still view. It records 36 measured frames per path/projection/variant after 36 warm-up steps. Start/middle/end PNG hashes expose still-image changes; changing-camera images need geometric/visual interpretation, not a global difference score.

- **Fixed capture (`fixed`)** modifies a second temporary copy of the pinned splatter. One capture origin is set at the start of each path, with all six directions held thereafter. It disables eye/previous probes, grid transitions, camera-dependent edge expansion and the eye image behind the splats. Geometry capture is reused while lighting can change. Newly exposed surfaces and uncovered gaps stay visible instead of being concealed by changing eye samples. It retains the upstream 18-layer allocation to keep the code change bounded, despite using only one six-face capture. The original `splat` module stays untouched except its usual density constant.
- **Surface grid (`surface`)** is a separate ordinary raster alternative, **not cubemap splatting**. On these static planar meshes, it evaluates the same source stone material and lighting at 0.12-metre world-grid centers projected onto each face plane. Exact source triangles provide coverage/depth at 1280×720 with 4×MSAA. Camera movement changes neither source geometry nor sampling centers. It can expose existing fine geometry rather than preserving a low-resolution silhouette. MSAA filters triangle edges, not every internal texel edge; minification, shadow transitions, curved normals, seams and animated geometry still need qualification. This isolated neutral-material control is not authored game art or an application integration.

Both new controls use a black background so missing geometry remains obvious; the original controls retain the upstream sky. Color comparisons therefore concern visible geometry, not the backgrounds. The fixed origin resets **between** paths, never while traversing a path. The surface control pays full-resolution per-fragment lighting (including static-triangle shadow traces), while the splatter shades captured texels. Timing/memory comparisons must disclose those different resolutions and work rather than infer equal quality/cost. Allocation accounting now includes multisample storage. All controls remain resident together until explicit device destruction.
