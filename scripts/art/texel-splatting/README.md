# Standalone perspective stability experiment (E07)

This tool compares ordinary rasterization with Dylan Ebert's pinned MIT texel-splatting renderer using the **same exported static geometry from the existing starting scene**. It does not load another playable world or alter OpenLegend's graphics backend. All surfaces receive the upstream renderer's neutral stone material so material differences cannot be mistaken for stability differences. It cannot qualify face art, animation, fabric coverage or transparent effects.

Export only player-permitted static mesh data from a disposable copy of the current starting scene. The JSON input is `{ source: { commit, scene }, meshes: [{ name, positions, normals, indices }], camera: { position: [x,y,z], target: [x,y,z] } }`. Positions and unit normals are in world coordinates; indices are local to each mesh. The pinned renderer requires at most 65,535 merged vertices. Include suitable existing ground, shelter, raised surfaces and thin seams/poles; do not invent a replacement map.

```sh
node scripts/art/texel-splatting/run.mjs /private/tmp/starting-scene-geometry.json /private/tmp/e07-results 192
```

The tool uses installed Vite and Playwright, downloads source at `394d350f91842779ed4c45760bd4ea9a07ce5c4c` into a fresh temporary directory, retains its license and records source/input hashes. No upstream source or assets are redistributed in the application. Chrome must have a physical WebGPU adapter; `timestamp-query` supplies stage measurements when available. Run separately at 96, 192 or 384 texels per cubemap face. Only that temporary sampling constant is changed.

Both variants use the same camera/light paths and geometry and enlarge to 1280×720. Splatting draws to 640×360; the ordinary baseline uses approximately the central cubemap face's angular density at a 60° field of view (192×108 at a 192-texel probe). This matches apparent detail near the image center approximately; cubemap face angles, depth and zoom still change that comparison. The paths cover movement within a capture cell, crossing a cell boundary, orbit/disocclusion, zoom, thin deck seams and changed light. JSON outside the repository records 60 samples per path/variant, CPU encode time, complete submit/wait time, GPU capture/shading/edge/culling/drawing time, allocation descriptors and source settings. Capture probes and the ordinary renderer remain resident together; allocation snapshots distinguish their incremental costs. Texture bytes are descriptor estimates (four bytes per texel, including nominal depth24plus), not a driver VRAM measurement. GPU timing sums pass durations and also records the first-to-last timestamp span; neither includes presentation or readback. Complete CPU wait includes submission and synchronization. Compare the two clocks before accepting GPU timing on a backend; overlapping or inconsistent pass counters cannot qualify a device. Warm-up and screenshots are excluded from timing samples. The cold preparation measurement includes buffer upload, acceleration-tree construction and pipeline creation; download/browser startup are separate.

Raw JSON/screenshots stay outside Git. Visually review both variants at corresponding frames, especially thin geometry and newly revealed surfaces, before recommending integration, revision or deferral. Missing timestamp support or physical-device qualification stays explicit.
