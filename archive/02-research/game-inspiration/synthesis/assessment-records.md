## Record structure for future authorized work

Use one stable heading per pair, `<TOPIC>--<game_key>`, and retain dated revision notes beneath it. This is a schema, not a completed example.

| Field                  | Required content                                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Identity               | Stable game key and topic code; optional unambiguous roster label and edition scope                                                         |
| Assessment             | Date and reviewer; what was actually inspected, not merely located                                                                          |
| Source evidence        | Dossier/chapter/supplement paths; exact commit or blob revisions; section anchors or line ranges; underlying source links and access limits |
| Contribution           | Concrete interaction, relevant praise and criticism, counterexamples, possible explanation, confidence and applicability                    |
| Destination            | Owning guide and stable lesson/section anchors; explain how this game's evidence supports, qualifies or contradicts them                    |
| Exclusion or blocker   | Specific rationale for N, or exact missing evidence and next action for B/W/S                                                               |
| Review and publication | Source-to-destination and diff checks actually performed; incorporation commit when known, without inventing a future/self hash             |

Do not duplicate the current status here: coverage.csv owns it. A quoted dossier passage without a contribution to the topic's comparisons does not qualify as I. Candidate reading routes in shells are not evidence records.
