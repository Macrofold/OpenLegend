# Cross-game learning guides

**Created October 14, 2026.** [Game library](../README.md) · [Progress and tracking rules](progress.md) · [Game-by-topic matrix](coverage.csv) · [Source inventory](subjects.csv) · [Assessment evidence](assessment-records.md).

This is the missing bridge between **what each game does** and **what design choices we can learn from the collection**. It is not another list of proposed features and does not make research conclusions into accepted OpenLegend requirements. The existing [repertoire catalogues](../../../../docs/repertoires/README.md) own ideas; project specifications and runtime documents own decisions and implementation.

**Current state:** 26 new, intentionally unfilled topic shells. Their questions and candidate reading routes are planning, not synthesized findings. Four other topics reuse existing essays or reserve the work Mike says is ongoing on other branches. No existing essay, dossier or active research branch is overwritten.

## How the boundaries fit together

A sword can contribute to multiple guides without duplicating one lesson everywhere: finding it is LOOT; its uses and carrying tradeoffs are GEAR; making it is CRAFT; learning a sword build is GROWTH; fighting with it is COMBAT; selling it is ECON; losing it is LOSS. A lesson has one primary topic owner, with cross-links where needed.

Social play is deliberately separated into **players doing things together (MULTI)**, **relationships with characters and creatures (NPC)**, **factions and institutions (SOCIETY)**, and **trust and abuse prevention (TRUST)**. This avoids treating chat, simulated friendship, political allegiance and consent to PvP as one system.

For future authorized synthesis, I would start with ECON, CRAFT, LOOT, MULTI, NPC and LOSS: they connect useful invention, worthwhile discovery, people and consequences. No synthesis is started by this prioritization. A single selected topic can be completed independently; nobody needs all 30 guides before making a justified local design choice.

## Reuse earlier work before writing new conclusions

The [earlier cross-game essays](../essays/contents.md), [mechanics studies](../mechanics/README.md), [interaction lookup](../mechanics/interaction-lookup.md), game dossiers and the [repertoire design foundation](../../../../docs/repertoires/design-foundation.md) already contain relevant material. They are evidence and candidates for reconciliation, not empty predecessors to delete. Existing essays on fun, virality and production remain in their owners.

Future guides should compare decisions, patterns, contradictions and applicability rather than concatenate game summaries. A useful lesson explains a concrete interaction, what players valued or resisted, when it works, when it fails, and what would need to be true for an OpenLegend adaptation. Preserve uncertainty, differing audiences and useful negative cases. An idea catalogue entry is not independent evidence that its proposed behavior is fun.

## Coverage review and research-to-design handoff

The [30-topic critique](coverage-review.md) identifies under-explicit treatment of independent lives, peaceful play, stealth/conflict, bodily and generational life, and events becoming lore. The 26 original guides now include topic-specific questions for these dimensions and empty **Design subtopics** reference tables. Their substantive synthesis remains unwritten; no game coverage state was advanced.

Use the [adaptable main-topic template](main-topic-template.md) to develop a guide without imposing one rigid outline. When adding an actual design subtopic, use the existing [Future work needing design](../../../../docs/maintainers/needs-design.md) register and its ND identifiers: the same ID connects its source topic, feature specification, technical design and later implementation modules. Research coverage, design completion and implementation completion retain separate owners. No new design entries have been registered by this framework; the existing register is not empty or replaced.
