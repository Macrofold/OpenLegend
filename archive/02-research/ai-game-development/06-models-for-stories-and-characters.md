# Models for stories, characters, and remembered consequences

Research checked **17 October 2026**. This document records evidence and proposes evaluations; it does not change OpenLegend's model bindings, content policy, cognition architecture, or qualification status. General coding benchmarks are deliberately outside its scope. Image, geometry, animation, and audio models have a separate assessment in [07-image-3d-and-audio-models.md](07-image-3d-and-audio-models.md).

## Recommendation

**Audition Claude Opus 5.5 and Gemini 4 Argon for creative authoring against OpenLegend's actual configured OpenAI baseline. Select runtime character models through OpenLegend-specific, multi-turn tests.** Public evidence does not establish one provider as best at the combination this game needs: concise expressive dialogue, independent choices, permitted knowledge, persistent consequences, appropriate personal development, and reliable delivery under a budget.

The distinction matters. A model can write the most attractive scene while also inventing the player's actions, leaking another character's secrets, promising an impossible craft, or claiming an attack already succeeded. For OpenLegend those are different failures, and some disqualify an otherwise delightful answer. The project already gives deterministic world authority to native systems and uses generated language and proposals at bounded interfaces. That is the correct foundation for the comparison, rather than a reason to replace the architecture with a chatbot that narrates the entire world. [Project AI boundaries](../../../docs/ai-providers.md); [character authorship](https://github.com/Macrofold/OpenLegend/blob/main/docs/projects/compelling-characters-feature-spec.md); [memory architecture](https://github.com/Macrofold/OpenLegend/blob/main/docs/memory-architecture.md).

Confidence is **high** that the evaluation must separate these jobs, **moderate** that Claude and Gemini deserve the first authoring audition, and **low** in any untested claim that one current model should become every OpenLegend character. No paid comparative model calls were run for this research.

## 1. What the current names and modalities actually mean

The supplied material's references to **Claude Opus 5.5** are verifiable, not names to silently correct to an older release. Anthropic's current catalog lists Opus 5.5, Sonnet 5.5, Haiku 5.5, and Fable 5.1. The documented Claude models accept text and images and produce text. Their tools can operate creative applications; that does not make the language model a native image or mesh generator. Anthropic's own descriptions of more natural communication are vendor claims, useful for forming an audition hypothesis rather than deciding a game-writing contest. [Anthropic model overview](https://platform.claude.com/docs/en/models/overview); [Opus 5.5 release](https://www.anthropic.com/claude-opus-5-5).

OpenAI's current **GPT-6 Astra** model page documents text input/output and image input. It does not document native image, audio, or video output for that model. OpenAI separately supplies image and speech models. Thus “GPT made the inventory icons” may describe an agent calling a separate image model, generating drawing instructions, or assembling existing art. Those are materially different workflows. [GPT-6 Astra model documentation](https://developers.openai.com/api/docs/models/gpt-6-astra).

Google's catalog currently lists **Gemini 4 Argon**, Gemini 3.8 variants, separate Nano Banana image models, and separate TTS and Live models. Large context capacity is an input accommodation; it does not establish that every remembered event will be used faithfully or that irrelevant material will be ignored. The model and the product endpoint must be recorded together. [Google model catalog](https://ai.google.dev/gemini-api/docs/models).

An OpenLegend comparison must also record the **actual configured baseline**, not substitute a current flagship and call that today's game. The repository describes direct OpenAI generation, a separate Jev judgment interface, and configured Macrofold routes; the direct adapter's documented initial candidate is `gpt-5.6-luna`. Routing and receipts distinguish requested aliases, reported identities, reasoning settings, cancellation, and uncertain costs. Configuration examples are not proof of the particular deployment's effective model. [Current provider contract](../../../docs/ai-providers.md).

| Work being evaluated                             | Relevant model output                                | What success means for this game                                               |
| ------------------------------------------------ | ---------------------------------------------------- | ------------------------------------------------------------------------------ |
| Authoring a character or encounter               | Editable prose and structured proposals              | Interesting motives, usable conflict, discovery, consequences, minimal editing |
| Playing a character                              | Speech and permitted decision proposals              | Distinct voice, independence, appropriate restraint, faithful perspective      |
| Recalling experience                             | A bounded selection or wording of permitted evidence | Correct source and uncertainty; no new past events or hidden information       |
| Running combat, inventory, crafting, or recovery | Native state transitions                             | The world applies supported rules and records actual outcomes                  |

| Generating an icon, mesh, or voice               | Image bytes, geometry, motion, or audio              | An accepted asset, not merely a convincing description                         |

This is an evaluation decomposition, not a proposal for six additional autonomous agents or services.

One instructive exclusion is Braintrust's September **Opus 5.5 versus GPT-6** evaluation. Its “writing quality” dimension belongs to **MathTutorBench**, with tutoring tasks and a specified automated judge. It is useful evidence about that task, but would be misleading evidence for fantasy storytelling or NPC performance. [Braintrust's own evaluation](https://www.braintrust.dev/evals/opus-55-vs-gpt-6).

### Open models deserve a real test, not an assumption

Google publishes Gemma 4 model cards and weights with deployment-relevant variants. That gives a concrete base-model family to evaluate when control over serving, adaptation, or economics matters. It does not establish that a smaller local model will fit the available hardware at the required concurrency or outperform a hosted model at this game's character work. [Gemma 4 model card](https://ai.google.dev/gemma/docs/core/model_card_4).

A more informative roleplay-specific example is HiWaifu Research's **WaifuGemma4** report. The team trained from its own users' preference votes, then compared replies blindly inside real conversations. The card reports a 59.7% preference rate over its untuned base in 714 decided battles, but also explicitly reports verbosity effects, weaker relative coherence/restraint, population differences, and lower rankings after length adjustment. Most evaluation traffic was Spanish and Russian. Those disclosures make the method more useful than an unsupported claim of superior roleplay. They also explain why a companion-product preference objective should not be copied directly into OpenLegend. [HiWaifu's model card and comparisons](https://huggingface.co/hiwaifu-research/WaifuGemma4-26b-a4b-v1).

**Recommended transfer:** if a future open model trial is justified, compare a suitable base checkpoint and one transparently documented character adaptation using the same OpenLegend evidence, response budget, and policy. Retain examples where the adaptation became more interesting and examples where it became less coherent or appropriated the player's agency. Fine-tuning is a later response to a demonstrated recurring failure, after context and evaluation are working; it is not the first step in making the current game good.

## 3. The viral demo cannot isolate Claude's contribution

The supplied WoW-style demo transcript describes a substantial production setup: many curated visual references, prepared skills, Unity and Blender control, specialized image/3D generation, iterative inspection, parallel work, and sponsored Higgsfield credits. It also acknowledges remaining animation and gameplay work. These are observations from the **user-supplied transcript**, not an independently reproduced run or audited expense record.

Consequently, the strongest conclusion is that a creative agent can coordinate a productive toolchain when its operator supplies useful taste, references, feedback, and machinery. The demonstration does not isolate a Claude-versus-OpenAI effect. A fair comparison would have to hold the reference pack, asset access, task scope, allotted iteration, and review loop constant.

The UI question needs two comparisons. First, give different language agents the **same approved icon pack, border pieces, fonts, visual brief, and existing UI surface**. That tests composition and implementation judgment. Second, hold the UI implementation constant and vary the **asset generator and reference workflow**. That tests asset quality. Comparing an unstyled React inventory with a Unity screen containing hundreds of deliberately selected images conflates those questions. Browser presentation is not, by itself, evidence that the model cannot create game-like visual composition; the dedicated UI and engine analyses in this research should decide which actual constraints matter.

## 4. How OpenLegend changes the character-quality target

### Author conditions and motives; leave choices open

OpenLegend's character direction favors authored people with values, tendencies, history, and current concerns, capable of independent choices and meaningful development. It rejects turning a personality description into a fixed operational script. The world also needs an enjoyable survival-adventure loop with readable action and recovery, not unlimited conversational elaboration. [Character feature specification](https://github.com/Macrofold/OpenLegend/blob/main/docs/projects/compelling-characters-feature-spec.md); [gameplay priorities](../../../docs/repertoires/gameplay-priorities.md).

Therefore, an authoring model should help create **generative conflicts**. For example, a cautious herbalist might value a wounded stranger's life while fearing the raiders near the needed herbs. That creates a situation for independent choice. “At 80% supplies, stop gathering and stand beside the pond” creates a behavioral script. An audition should reward the former and reject the latter when it smuggles implementation instructions into personality.

At runtime, the same person can offer practical help, decline a reckless request, misunderstand something plausibly, or change their mind after evidence. A universal “friendly and helpful assistant” voice fails even if its language is pleasant. Equally, forced contrarianism is not independence. Judge whether the response follows the person's own concerns and the events they actually experienced.

### Preserve perspective and the difference between saying and doing

The test context should distinguish things a character observed, things another person claimed, remembered experiences, and current uncertainty. A character must not turn “someone told me the bridge collapsed” into direct eyewitness certainty. They must not recognize an unseen person through an internal identifier or know another actor's private memory. Recalled past events must not overwrite current world conditions. These are existing project requirements, not extra research-era architecture. [Memory architecture](https://github.com/Macrofold/OpenLegend/blob/main/docs/memory-architecture.md).

An example audition can present three separate facts: the herbalist last saw a gate open, a visitor says it is locked, and the player asks whether the herbs are reachable. A good response keeps those sources distinct and may suggest checking. A poetic but certain invented account is a worse game result. Another case can ask the character to hand over an item the native world does not currently make available. Good dialogue may express intent, but the model must not author a completed transfer.

The output schema helps reject malformed responses. It cannot prove truth, permission, or feasibility. Continue validating proposed operations against the current world, and only publish the actual outcome as history. Ordinary known actions continue through native machinery; this research does not recommend an LLM call for every movement, targeting update, or repeated craft. [AI provider contract](../../../docs/ai-providers.md).

### Measure development, not permanent sameness

A frightened person becoming more trusting after repeated help can be excellent continuity. A model forgetting the fear because the chat became long is not. Evaluation should ask for the cause of a changed disposition in the permitted evidence, without forcing the model to expose private reasoning. Human reviewers can inspect what events the context contains and whether the behavior is supported.

Use both a **no-reason-to-change** case and an **earned-change** case. Reward recognizable voice across them, appropriate flexibility, and the ability to hold conflicting feelings. Do not add a new psychological simulation simply to achieve this; first test whether the current authored context and memory interface suffice.

### Preserve the accepted storytelling scope

The current accepted policy supports mature, non-graphic storytelling and fictional characters with their own motives, including antagonistic roles. It also requires shared trusted service instructions, actor-specific perspective, and defined boundaries for companion behavior and content. Its implementation and live qualification are separate work. The research must neither narrow everyone into a generic service agent nor reward a model for violating that policy. [Agent content and companion safety, accepted October 2026](https://github.com/Macrofold/OpenLegend/blob/main/docs/agent-content-and-companion-safety.md).

Include permitted difficult scenes—grief, betrayal, menace, disagreement, romance within the accepted scope—so over-refusal is visible alongside boundary failures. The criterion is useful, in-world handling of the allowed scene. Benchmark “willingness” scores that reward explicit escalation are a poor proxy. Keep policy checks separate from literary preference so a fluent violation cannot win by averaging its score with good prose.

## 6. A reproducible, game-specific comparison

The research-wide experiment plan owns scheduling and approval. This document defines what a meaningful narrative comparison should contain.

**Use identical evidence snapshots.** Save the authored character, world-visible facts, recipient scope, memories, user message, output contract, model identifier, thinking settings, limits, and tool access. Withhold information the actor should not see. Do not give one candidate a carefully selected memory and another the raw entire world.

**Separate fixed-context and closed-loop tests.** Fixed-context tests compare candidates on exactly the same difficult moment. In a closed-loop session, each candidate changes what later conversation looks like; that tests the resulting experience, but the final transcripts are no longer identical inputs. Use both and label them. Save raw outcomes rather than retrospectively presenting only the best exchanges.

**Cover a small, discriminating scenario set.** Include a first meeting without name knowledge; a request conflicting with the person's values; a hearsay-versus-observation conflict; a failed native action; an unavailable item; a private secret belonging to another actor; a long absence with changed world state; an earned change of attitude; a return to an old concern after distracting conversation; and an allowed emotionally difficult scene. Add a few short authoring tasks whose usefulness can be judged by the project's actual playable loop.

**Use human blind preference after hard validity checks.** Reviewers should choose which valid answer they would put in the game, with reasons such as voice, economy, emotional specificity, plausible choice, and invitation to meaningful play. Track invalid operations, information leaks, fabricated memories, and policy failures separately. If an LLM judge helps triage, calibrate it on human labels, randomize position, use different judge families, and inspect disagreements. RP-Bench's disclosed judge sensitivity makes that precaution evidence-based, rather than merely procedural. [RP-Bench methodology](https://github.com/LeviTheWeasel/rp-benchmark/blob/main/docs/METHODOLOGY.md).

**Control length and effort without pretending APIs are identical.** Report the output ceiling and resulting words/tokens. Run a common response-length brief, then permit a bounded provider-appropriate tuning pass. A verbose answer should not win because it received five times the space. Record actual reasoning mode; a model's “high” setting is not a standardized amount of computation shared with another vendor.

**Measure time until an acceptable game response.** Capture queue time, first complete validated speech, final completion, failed requests, discarded generations, and editing time. Raw first-token speed does not tell us when a player can safely hear a reply. Report median and tail behavior across repeated calls, not a single impressive response. Record input, cached input, output, and any other separately billed work rather than treating cached tokens as fresh generation or subscription usage as an audited API bill.

**Test languages with speakers of those languages.** A multilingual model label is a candidate-selection fact. A localized character needs preserved register, humour, names, and emotional intent at a readable length. Evaluate important target languages separately; do not infer their ranking from English. Voice is a separate audition with pronunciation and acting checks, described in the asset/audio document.

**Accept an adoption only for the task demonstrated.** An authoring winner need not become the low-latency speech model. A good first-hour character need not be qualified for a long saved-world history. A smaller model that performs summaries well need not receive novel invention work. The outcome should be a short supported routing decision with representative failures and remaining limits, not one global score hiding incompatible requirements.

## 7. What we can confidently learn now

The current evidence supports a better selection process more strongly than a permanent brand ranking. Use language models where authorship, interpretation, and expressive choice help; let native systems preserve the world. Give candidates the same useful evidence and visual resources. Judge persistent characters across consequences and contradictions, not a single charming reply. Treat image, motion, geometry, and voice generators as independently selectable tools. Preserve the project's own vision of authored people who can change through experience.

The unresolved question is empirical and narrow enough to answer: **under OpenLegend's actual context, action boundaries, style, and budget, which candidate produces more accepted character moments with less correction and delay?** This research establishes credible candidates, exposes misleading comparisons, and supplies the tests needed to answer it. It does not claim those tests have already been run.
