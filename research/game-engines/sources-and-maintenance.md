## Evidence standard

External technical claims use official engine documentation, browser/API documentation, platform-holder requirements, vendor terms, first-party engineering guidance or primary research papers. Community interviews and panel reporting are identified as such. Detailed sources are linked beside the relevant claims; this register highlights decision-sensitive references rather than replacing inline citations.

Official documentation establishes supported mechanisms or restrictions in a described configuration. It does not prove Open Legend meets frame-time, population or production targets. Feature lists and demonstrations are not matched comparative benchmarks. There is no newly measured engine performance, hardware qualification, legal clearance or confidential console evidence in this collection.

The original capability sources were reviewed on **October 15, 2026**; the community/AI extension and priority reconciliation were reviewed on **October 17, 2026**. Moving stable/current URLs are not immutable evidence. Versioned links are used where available, and an implementation must pin compatible editor/package/renderer/platform versions. Access date is not publication, experiment or release date.

## Browser and hardware references

[MDN WebGPU](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API) and [Chrome's overview](https://developer.chrome.com/docs/web-platform/webgpu/overview) describe rendering/compute opportunities. [WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices) covers resource and synchronization concerns. [Adapter requests](https://developer.mozilla.org/en-US/docs/Web/API/GPU/requestAdapter) distinguish preferences from guarantees.

[Emscripten pthreads](https://emscripten.org/docs/porting/pthreads.html) supports the WebAssembly threading discussion. [Browser lifecycle](https://developer.chrome.com/docs/web-platform/page-lifecycle-api) and [storage quotas/eviction](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria) distinguish managed execution, persistent storage and RAM. No universal slowdown percentage, RAM ceiling, character count or polygon limit is inferred.

## Review findings and limitations

The original review corrected a Unity-version mismatch and retained distinctions between managed threads/Burst jobs, Nanite support/runtime importing, and native Godot/web export. The follow-up corrects the native-first recommendation and adds the missing community/AI evidence. It distinguishes tool documentation from execution and development assistance from player-facing World Agent authority.

Public documentation can contain stale paragraphs even on current pages. Narrow claims to the supported route/version instead of generalizing. Package-specific gamepad or audio restrictions are not universal browser impossibilities. A moving priority page or beta announcement is not shipping acceptance.

No comparative port, device/controller qualification, live generative-quality evaluation, legal review or closed-platform validation was completed. The Godot poll data retrieval gap remains explicit. Content/link review does not imply a passing pinned formatter or CI result; the formatter remains unavailable in this environment. The [benchmark plan](benchmark-plan.md) is conditional future work, not evidence already collected.
