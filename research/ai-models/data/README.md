# Structured inventory and evidence

These files contain the complete sourced model records represented in the human-readable tables. They are a research snapshot, not a runnable deployment manifest or a list of models approved for production.

| File                                               | Shape and purpose                                                                                                                                                                                                                                 |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [character-models.json](character-models.json)     | Array of character/roleplay records. Stable `RP` identifiers connect the three detailed tables; includes exact model IDs, behavioral evidence grades, sentiment provenance, published examples and deployment/cost/license notes.                 |
| [character-metadata.json](character-metadata.json) | Scope, evidence-grade definitions, priority meaning, targeted review date and six older reference models.                                                                                                                                         |
| [character-sources.json](character-sources.json)   | Character-source IDs, canonical URLs, retrieval dates, source type, supported scope and records using each source.                                                                                                                                |
| [decision-models.json](decision-models.json)       | Metadata plus `models` array. Includes dedicated decisions, ordinary generators, exact API/artifact identities, version status, use cases, example evidence, metering and limitations.                                                            |
| [decision-sources.json](decision-sources.json)     | Decision-source IDs, titles, dates, source types and supported claims.                                                                                                                                                                            |
| [voice-models.json](voice-models.json)             | Array of speech-model/service records. Includes TTS/recognition/conversion/conversation roles, exact IDs, streaming/expression properties, deployment, commercial terms, content-policy evidence and sample-inspection status.                    |
| [voice-sources.json](voice-sources.json)           | Voice-source IDs, canonical URLs, inspection dates, source type and supported claims.                                                                                                                                                             |
| [catalogue.json](catalogue.json)                   | A common selection index across all three inventories: role, interest, deployment/access, commercial terms, content evidence, sample status and cost basis; includes owning detail/source pointers. The domain records retain the complete facts. |
| [shared-sources.json](shared-sources.json)         | Additional primary sources used by the overview and deployment/cost interpretation.                                                                                                                                                               |

## Interpretation

### Runpod hosting records

Each domain record now has a `hosting` object, reviewed October 25. The domain JSON remains the complete model-specific owner; [hosting-matrix.md](../hosting-matrix.md) is its compact reading view. This adds deployment preparation without turning the catalogue into a tested hardware compatibility list.

| Field | Meaning |
| --- | --- |
| `reviewed_on`, `source_ids` | Date and primary-source references for the hosting review. Earlier sentiment/example dates remain distinct. |
| `runpod_disposition`, `reason` | `self_host_candidate`: a documented artifact/runtime route; `conditional_self_host`: access, contract, license or runtime prerequisites; `external_api_only`: no documented local route for this exact product; `unverified`: insufficient evidence. None means deployed or approved. |
| `profiles[]` | Separately identified artifact/runtime/precision combinations. A family may have many; an API-only entry has none. |
| Profile identity | `artifact_id`, nullable `artifact_revision`, format, precision, runtime/version and `api_protocol`. Missing revision means it still needs pinning; an image and model commit are distinct. |
| `context` | Native, extended, runtime-default and output lengths when supported by evidence; optional `config_max_position_embeddings_tokens` preserves config-only values. Scope/notes state exact-artifact versus parent evidence and recipe limitations. Optional `output_semantics` identifies native probability/head output without inventing a zero-token serialized-response cap. None is the actual deployed cap. |
| `request_limits` | Text characters and audio/reference/output seconds where known, plus original-unit/transport notes. Phonemes, UTF-16 units, bytes, training envelopes and recommendation ranges must not be silently treated as the same limit. |
| `memory` | Total parameters, raw weight arithmetic/file size, published VRAM/hardware, a clearly labeled GPU candidate, host RAM and cache notes. `*_basis` fields distinguish publisher requirements, estimates and missing evidence. Numeric GB fields use decimal GB; source GiB is retained in prose or explicitly converted. |
| `storage` | Exact `artifact_bytes` when established; optional `artifact_size_gb` for a rounded/published artifact footprint or explicitly labeled payload estimate; `disk_gb` only for an evidenced complete disk allocation. Repository-total bytes, selected quantization bytes and temporary working disk are different. The basis preserves component scope and units. |
| `requirements`, `source_ids` | Exact runtime/hardware/components/access conditions and supporting domain-ledger references for that profile. |
| `hosted_route_limits[]` | Optional separate limits for a provider API. These are not self-host profiles, Runpod settings or transferable hardware requirements. |
| `deployment_evidence` | Always `not_deployed_or_tested_by_this_research`, with configured caps and measurements null and `request_fit: unknown`. Published or historical outside evidence never fills these fields. |
| `blocking_unknowns` | The concrete information still needed for selecting or sizing that record's deployment. Unknown is not zero, unlimited or an implied successful fit. |

The common `catalogue.json` additionally exposes `runpod_disposition`, `hosting_profile_count` and `hosting_reviewed_on` as selection facets; read the domain profiles before treating a family-level match as applicable to an exact variant.

Additional platform files:

- [runpod-sources.json](runpod-sources.json): primary platform/runtime source ledger; source identifiers use `source_id` inside `sources`.
- [runpod-gpu-pricing.json](runpod-gpu-pricing.json): dated public Pod/Serverless prices, memory tiers, storage meters and retained source discrepancies. No account offer or resources were inspected/provisioned.
- [deployment-record-template.json](deployment-record-template.json): unfilled evidence worksheet for the existing MX06 owner, not executable configuration or authorization to run it.

### Existing discovery evidence

Research priority means interest in a possible comparison, not an instruction to run every highly rated model. The catalogue preserves each original `priority` and adds a coarse `research_interest`; the scales are not calibrated performance rankings. Access, commercial terms and comparison purpose remain separate. Every record is untested and unqualified for production by this research.

Release dates, model-file updates, service snapshots, article publication dates, crawl dates and retrieval dates are different. Records describe which one is known. The initial inspection date is October 23; October 24 review fields identify narrower checks and additions, not a claim that every source was fully refreshed again.

Specs and prices use model cards, official documentation, artifact licenses and provider listings. Community evidence identifies original discussions or firsthand use where found; exact-version uncertainty and publisher-selected testimonials are marked. Some source ledgers include discovery-only or supporting family evidence. Their presence does not turn a vendor claim into independent validation.

All model examples come from attributed public demonstrations, evaluation artifacts, documentation or brief excerpts. A usage snippet is labeled as such. Linked audio was not auditioned or synthesized. A missing published output is not replaced by a fictional example attributed to the model.

No account credentials, model weights, generated evaluation logs, benchmark results or voice assets are included. All models remain untested by this research. Reuse the detailed records and sources when preparing an explicitly authorized comparison; do not infer game integration support from the existence of a model card or an autogenerated hosting snippet.

## Catalogue fields and filtering

The catalogue adds common facets without rewriting the domain records or inventing a universal quality score. Lists can represent different variants, deployment routes or cumulative component obligations within a family. For example, Phonon’s standard-license 31M weights and noncommercial 40M weights coexist in one record; filtering for a standard license does not clear every family member. Likewise, Qwen Base, CustomVoice and VoiceDesign do not all expose the same controls, and a hosted route’s policy is separate from a downloadable checkpoint’s license.

| Field                                                                  | Meaning and boundaries                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`, `name`, `group`, `category`                                      | Existing record identity and original grouping. A family record is not a single deployable artifact.                                                                                                                                                                                                                                                                                                                                                                                                           |
| `priority`                                                             | Original authoring label, preserved unchanged, including policy/license/watch suffixes.                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `research_interest`                                                    | `high` for original P1/high; `medium` for P2/medium; `watchlist` for P3/watchlist; `reference` for baseline or general quality-control labels. `unranked` preserves license-only labels without inventing interest. `avoid_new_integration` preserves the retiring-service warning. These are coarse editorial buckets.                                                                                                                                                                                        |
| `comparison_role`                                                      | Functional roles: character dialogue, supplied-choice selection, general generation/planning, function translation, literal/scripted TTS, speech editing/continuation, speech recognition/alignment, voice conversion, scene authoring or speech interaction. Multiple roles are allowed and are leads from the recorded capability evidence, not verified game integrations.                                                                                                                                  |
| `comparison_purpose`                                                   | `candidate`, `quality_control`, `baseline` or `lifecycle_reference`. A current aligned control can be recent and still have a reference purpose.                                                                                                                                                                                                                                                                                                                                                               |
| `deployment_modes`                                                     | `self_host`, `on_device`, `hosted_api`, `hosted_demo`, `managed_deployment`, `enterprise_route` or `contract_deployment`, where the owning record documents that route. A managed deployment needs provisioning; an enterprise mention may still have unverified access. A native runtime alone does not prove a device/CPU route. Community ports and supported production serving are not automatically equivalent.                                                                                          |
| `availability`                                                         | Published weights/API access, gated access, unverified weight access, preview, promised weights, adapter plus required base, demonstration-only access, contract requirement, a deployment prerequisite, unresolved enterprise access or retirement. This is documentary evidence, not confirmation of account entitlement or a successful download/call.                                                                                                                                                      |
| `commercial_terms`                                                     | Standard weight license, custom weight terms, noncommercial weights, hosted service terms, unresolved weight terms or variant-specific terms. Lists preserve mixed cases and cumulative obligations; they are not necessarily a choice between licenses. A standard license is not a legal clearance for every dependency, reference voice, hosted service or intended use.                                                                                                                                    |
| `content_evidence`                                                     | Publisher measurement/claim, firsthand or related-model anecdote, documented safety training/refusal mechanism, published content restrictions, scoped fiction exception, configurable filters or no direct behavior evidence. `creative_intent_only` records RP/style tuning without a claim or measurement of permissive behavior. Types are not a ranking; restrictions and negative anecdotes are evidence too. None is an Open Legend refusal score.                                                      |
| `sample_status`                                                        | Attributable published output artifact, linked demo, illustrative response, request code, documentation only, usage report without output, or not found. No model output was generated; linked media was not auditioned.                                                                                                                                                                                                                                                                                       |
| `cost_basis`                                                           | Meter categories, including compute, input/text/audio tokens, characters, UTF-8 bytes, input/generated audio duration, connected session time, credits, voice-creation fees or quotes. `input_output_tokens` preserves separate input/output token billing without assuming all tokens are text or inferring a conversion to audio duration. Temporary offers and unverified units are explicit. Numerical rates stay in the detailed record; these categories cannot be converted into a shared cost ranking. |
| `selection_caveat`                                                     | One concise reason to inspect a variant, route, evidence limitation or eligibility condition before selecting it. Complete caveats remain in the owner record.                                                                                                                                                                                                                                                                                                                                                 |
| `qualification_status`, `tested_by_us`                                 | Always `not_evaluated` and `false` in this research snapshot. Interest and documented access do not change these fields.                                                                                                                                                                                                                                                                                                                                                                                       |
| `detail_file`, `structured_detail_file`, `source_ledger`, `source_ids` | Owning Markdown anchor, domain JSON file and source-ledger pointers. Within the domain JSON, select the record with matching `id`; decision records are inside the `models` array, while character/voice files are arrays.                                                                                                                                                                                                                                                                                     |

Useful filters are intersections. For example, select a role, then a documented deployment route, then inspect matching weight/service terms and sample status. An entry that matches `self_host` and `standard_weight_license` can still contain another variant with custom or noncommercial terms. Use `selection_caveat` and the detailed license field to resolve that case. Filtering for publisher measurements finds disclosed evaluations, not necessarily evaluations on comparable prompts or on fictional characters.

### Path and source conventions

All catalogue path fields are relative to the repository’s **`research/ai-models/` inventory root**, even though `catalogue.json` is stored in its `data/` subdirectory. They are not relative to the JSON file itself. Markdown detail anchors use the lowercase stable record ID, such as `character-models.md#rp01`, `decision-models.md#decision-jev-114` or `voice-models.md#voice-qwen3-tts`. Structured-detail paths remain `data/character-models.json`, `data/decision-models.json` and `data/voice-models.json`.

Source IDs are resolved in the listed ledger: the decision ledger uses the `id` key; character and voice ledgers use `source_id`. The full source entry provides its URL, source type, dates and supported claims. Catalogue facets summarize the existing record evidence as of the stated review date; they do not assert that every linked source was freshly re-retrieved.
